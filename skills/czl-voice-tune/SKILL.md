# 调音：人味体检与定向修改

## 职责边界

只做一件事：把"读着不对"变成"第几段第几句、哪个指标超了、怎么改"。

**不做**：不改设定、不改情节。发现情节问题，标出来交回 `czl-chapter-forge`。

## 输入

- 正文文件路径（md 或 txt，UTF-8）
- 可选：本章体裁（对话多/战斗多/心理多）——影响阈值取舍

## 步骤

### 第 1 步：跑脚本，先看数字

```bash
python skills/czl-voice-tune/scripts/voice_scan.py chapters/ch-001.md --json qc/ch-001.report.json
```

脚本给 14 项指标、一个 0—100 分、等级 A/B/C/D、判定 PASS/FAIL。

**分数只用于横向比较同一本书的不同章，不用于和别的书比。**

### 第 2 步：按状态处理

| 状态 | 处理 |
|---|---|
| FAIL | 必须改。改完重跑，直到 FAIL 清零 |
| WARN | 逐条看。结合语境决定改或豁免，豁免要写理由进 `qc/*.report.json` 的备注 |
| PASS | 不动。别为了改而改 |

**豁免规则**：只有三种情况可以豁免——
1. 体裁要求（战斗章短句多，R02 可放宽到连排 4）
2. 人物声线（某个角色说话就是短促，属对话不计入 R02）
3. 刻意的节奏（章节高潮处连续短句是设计，需在报告里写明是哪一段、为什么）

"我觉得这样写挺好"不是豁免理由。

### 第 3 步：改法（每条给两种）

改之前先看脚本给的 `where`（段号 + 原文片段），**只改指到的位置**，不顺手动全篇。

| 指标 | 保守改法 | 激进改法 |
|---|---|---|
| R02 连续短句 | 把其中两句用逗号并成一句 | 删掉其中一句，留最有力的那句 |
| R03 破折号 | 换成句号 | 整句重写，不用插入语 |
| R04 不是…而是 | 保留一处，其余改成直接陈述 | 全删，让动作自己说话 |
| R05 比喻 | 删掉后半个比喻 | 换成一个具体动作 |
| R06 情绪直述 | 换成身体反应（手、呼吸、动作） | 整段改成对话 |
| R07 万能词 | 换成具体物体或声音 | 删掉那一句 |
| R08/R12 总结句 | 删掉 | 删掉，并把前一句改成钩子 |
| R11 弱副词 | 删副词，动词留原样 | 换成更准的动词 |
| R14 同头排比 | 改掉后两句的开头 | 拆成一段对话 |

### 第 4 步：改完复跑

必须重跑，不许口头宣称"改好了"。对比两次的 report.json：
- 分数变化
- 哪些项从 FAIL 变 PASS
- 有没有新引入的 FAIL（改出新问题很常见）

### 第 5 步：落盘

- 正文原地改（用户要求保留原稿时，先另存 `chapters/ch-001.v1.md`）
- 报告：`qc/ch-001.report.json`
- 人读版摘要贴给用户：**只贴 FAIL 和 WARN 项，PASS 项一行带过**

## 判断条件

| 情况 | 处理 |
|---|---|
| 用户只想听意见不想改 | 只出报告，不给改后正文 |
| 用户要求"全部重写一遍" | 拒绝全篇重写。说明：全篇重写会丢人物声线，改为只改 FAIL 项 |
| 两轮后仍有 FAIL | 停手，如实报告哪几项改不动、为什么，不假装通过 |
| 文本不是中文 | 脚本的汉字统计会失真，明确告知"本脚本按中文设计，此文本仅作参考" |
| 用户贴的是大纲不是正文 | 直接说"这是大纲，不适用人味体检"，转 `czl-story-architect` |

## 输出

```
qc/ch-001.report.json     完整指标（含每项 where 定位）
（对话中）体检摘要         等级、分数、FAIL 清单、逐条改法
```

## 异常处理

- **脚本跑不了**（没有 Python / 权限不足）：明确说"未能执行体检"，改为人工逐段过，并在交付里标注"未经脚本核验"，不许说"已检查通过"。
- **编码不是 UTF-8**：脚本以 replace 读入，可能把字吃掉。发现乱码先转码再跑。
- **文本极短**（不足 300 字）：句长统计无意义，只看 R03/R04/R07 这类计数项。

## 依赖

`scripts/voice_scan.py`（纯标准库）。样本见 `samples/bad_sample.md`（应判 D/FAIL）与 `samples/good_sample.md`（应判 A/PASS），用于自检脚本是否正常。

## 与其他工作流的关系

下游：通过后交 `czl-continuity-keeper` 入档。
回边：`czl-data-doctor` 的工单回到本环节执行。

## 脚本

两个脚本，一个体检、一个校准。

### voice_scan.py —— 体检

```bash
python scripts/voice_scan.py chapters/ch-001.md --json qc/ch-001.report.json
python scripts/voice_scan.py chapters/ch-001.md --thresholds my.json   # 用自定义阈值
```

14 项指标、0—100 分、A/B/C/D 等级，四项阻断十项提示。同一份稿跑两次结果必须完全一致。

### calibrate.py —— 校准阈值

这是本产品唯一"别人没有"的能力：**阈值不是写死的，改完还能自证改对了。**

```bash
python scripts/calibrate.py --pos samples/pos --neg samples/neg
python scripts/calibrate.py --pos samples/pos --neg samples/neg --out my-thresholds.json
python scripts/calibrate.py --pos ... --neg ... --check my-thresholds.json   # 只评估不改
```

原理很土：已知"像人写"和"像机器写"两组样本各跑一遍，看当前阈值下两组分不分得开（负样本最高分 < 正样本最低分 = 完全分开）。分不开就逐项扫阈值，让间隔最大化。

当前样本集（正 3 负 3）实测：间隔 **+28**，准确率 **100%**，逐项扫描后间隔可提到 **+32**（把弱副词阈值从 5.0 收到 3.0）。

**样本规则**：每类少于 3 份时脚本拒绝给推荐值——两组各 1 份拟合出来的阈值没有统计意义。
