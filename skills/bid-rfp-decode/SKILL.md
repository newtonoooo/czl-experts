# 招标解码

## 什么时候用

- 用户给了招标文件（正文、评审办法、技术需求、资格条件任一章节）
- 用户问"这份标书有多少戏""分主要在哪"
- 后续任何环节需要评分表——没有分数地图，不要往下写

## 输入

必需：招标文件文本（或可读的 pdf/docx 转出的文字）。
可选：投标主体的资质现状（决定哪些客观分已经拿不到）。

## 步骤

1. **定位评审办法**。找"评标办法/评审标准/评分细则/综合评分法"章节。找不到就明确说找不到，不要用行业惯例代替。
2. **抽评分项**。逐条抄出评分项与分值。原文没写分值的，记为"未量化"，不许推算。
3. **分类**。三项判断：
   - 门槛分：不满足即否决（资格、资质、证书、社保）
   - 客观分：靠材料与报价（业绩、人员、报价、奖项）
   - 主观分：靠写作（理解、方案、措施、服务）
4. **打可争取度**。0-1 之间给一个数，必须写理由。写作完全动不了的给 0，不要给 0.3 假装有空间。
5. **扫红线**。否决投标条款、★/▲ 实质性条款、密封签章要求、工期与付款的实质性偏离。逐条抄原文 + 行号。
6. **推隐性偏好**。反复出现的词、被单独列出的场景、被强调的本地化/驻场/同类项目要求。每条标 [推断]。
7. **合计校验**。分值加起来应等于满分。不等就报差额，说明抓取不完整，请用户补原文。

## 判断

| 情况 | 处理 |
|---|---|
| 主观分占比 < 40% | 直接告诉用户：写作空间有限，重心应放到报价策略与材料完备 |
| 分值合计 ≠ 满分 | 停止后续推算，先要完整评分表 |
| 出现"综合评议""由评委酌情打分"且无分值 | 标为不可计算项，提示这是关系与印象分，写作只能保证不失分 |
| 文件是扫描件、抽不出文字 | 请用户给文字版或指定页码，不许凭标题猜内容 |

## 输出

`分数地图.md`：分值表（评分项 / 满分 / 类型 / 可争取度 / 依据 / 行号）+ 三段小结（总分、主观可写分、可争取分）。
`废标红线.md`：分级清单（阻断 / 实质性条款），每条带原文与行号。
`隐性偏好.md`：信号表 + 对应到方案哪个章节去接。

## 脚本

```bash
python scripts/rfp_decode.py 招标文件.txt --out ./out --total 100
```

输出 `分数地图.md` 与 `分数地图.json`。`--total` 用来校验抓取是否完整，不填也会提示差额。

脚本只做抽取与分类，不做价值判断。类型与可争取度是启发式结果，必须人工复核一遍再用于后续环节。

## 异常

- 编码乱码：脚本会依次试 UTF-8/GB18030；仍失败请用户另存为 UTF-8。
- 评分表跨页断裂：分页读取后手工合并，合并处注明页码。
- 同一评分项在正文与技术需求里分值不同：以评审办法为准，并在报告中标注冲突位置——这是要向招标方澄清的问题。

## 依赖与上下游

上游：无。下游：赢标主题锻造、三幕架构、评审模拟、交付体检全部以分数地图为输入。
