# G2 · 文案构建

## 职责

把分配表变成**可复制的文案块**。这一门唯一的验收标准是：每条卖点都能被追问"凭什么"并且答得出来。

## 输入参数

| 参数 | 必填 | 说明 |
|---|---|---|
| 关键词分配表 | 是 | G1 产物 |
| 输入卡 | 是 | G0 产物，取 attributes |
| 站点语言 | 是 | 文案必须用该语言写 |
| 站点字符上限 | 是 | 来自 `marketplace-rules.json` |

## 执行步骤

1. **选骨架**：按 `references/copy-patterns.md` 选 A（主词优先）/ B（场景优先）/ C（属性堆叠）。
2. **先写标题**，按骨架填，写完立刻数字符。超了就删，不要"等一下再删"。
3. **排五点顺序**：按决策权重排，不按写作顺序。默认序：核心问题 → 规格边界 → 证据 → 使用维护 → 包装售后。
4. **写每条五点**：锚点（2–4 词加粗）+ 利益 + 证据 + 场景。写完自查：这条的证据是什么？说不出来就重写。
5. **写描述**：四段（是什么 / 怎么用 / 不适合什么 / 包装与维护）。不重复五点。
6. **写后台搜索词**：只放没出现过的词，按字节算预算。
7. **跑 lint**：

   ```bash
   python scripts/listing_audit.py lint --listing x.json --market US
   ```

8. **按 lint 结果改**，直到没有 BLOCK。

## 判断条件

| 情况 | 动作 |
|---|---|
| 某条五点写不出证据 | 删掉这条，换一个能举证的卖点，不要用形容词撑 |
| 五点有两条讲同一件事 | 合并，腾出的位置写维护或包装 |
| 标题超限 | 按优先级删：装饰词 → 重复属性 → 次要场景词。主词不动 |
| 站点非英语 | 用目标语言写；不确定的表达标 `[待母语校对]` |
| 类目有固定标题模板 | 按模板字段顺序写，骨架让位于模板 |

## 输出格式

交付三块，缺一不算交付：

````markdown
### 成品

**标题**（77 / 200 字符）
```
NORDVIK Collapsible Coffee Cup 350 ml Leak-Proof Silicone Travel Mug with Lid
```

**五点**
```
1. **350 ml is one full cup**: …
2. **Silicone body, PP lid**: …
...
```

**描述**
```
…
```

**后台搜索词**（66 / 250 字节）
```
camping mug silicone cup pocket cup reusable cup outdoor drinkware
```

### 体检结论

lint：PASS｜标题 77/200｜五点 5 条｜描述 737 字符｜后台词 66 字节

### 下一步

先补属性栏的 weight 与 care，G4 的 D1 会直接加分。
````

## 异常处理

- **用户要求"写得更夸张一点"**：给一版更强的利益表达，但证据必须留。明确告诉他哪些词已经接近红线。
- **用户要求照抄竞品句式**：拒绝复用他人文案，改为拆解其结构（讲了哪几点、什么顺序），用自己产品的事实重写。
- **语言不确定**：宁可标 `[待母语校对]`，不要假装地道。机翻痕迹会直接拉低转化。
- **lint 报 BLOCK 但用户坚持不改**：交付时把 BLOCK 项单列，写明"未处理，提交有被压制风险"。不要因为用户坚持就把结论改成通过。
