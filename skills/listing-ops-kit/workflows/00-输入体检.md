# G0 · 输入体检

## 职责

把用户口述的"一款产品"变成一份结构化、可被后续五道门消费的输入卡。这一门不产出文案，只产出**约束**。

不做这一步的后果很具体：写到 G3 才发现没问资质，前面写的全要返工。

## 输入参数

| 参数 | 必填 | 说明 |
|---|---|---|
| 目标站点 | 是 | US / UK / DE / FR / IT / ES / JP / CA / AU |
| 类目 | 是 | 尽量到子类目，决定 G3 的类目门槛 |
| 产品本体 | 是 | 材质、尺寸、重量、颜色/规格、包装内含 |
| 主关键词 | 是 | 1–3 个，用户实际会搜的词 |
| 竞品参照 | 否 | ASIN 或竞品标题，用于 G1 扩词 |
| 已有资质 | 否 | 认证、检测报告、责任人、注册号 |
| 目标售价 / 是否 FBA | 否 | 影响五点里的价值表达与描述结构 |

## 执行步骤

1. **一次问完七项**。不要挤牙膏式追问，用户会烦，而且他往往一次能答完。
2. **对缺失项做显式假设**。格式固定：

   ```
   【假设】未提供材质，按食品级硅胶处理；如不符请纠正，会影响 G3 的食品接触材料判定。
   ```

   假设必须写"会影响哪道门"，否则用户不知道要不要纠正。
3. **判定类目键**。把用户说的类目映射到 `electronics` / `juvenile_products` / `food_contact` / `textiles` / `toys` / `battery_products` / `general` 之一。映射不了就用 `general`，并明确说"类目门槛未核对"。
4. **填输入卡**，输出 Markdown 表。
5. **列缺失项**。缺失项为空才允许进 G1。

## 判断条件

| 情况 | 动作 |
|---|---|
| 站点 + 类目 + 产品本体 + 主词齐备 | 进 G1 |
| 缺主关键词 | 用产品类目词兜底，标"主词待定"，仍可进 G1，但 G2 前必须补 |
| 缺站点 | 停止。站点决定字符预算与合规义务，不能猜 |
| 缺类目 | 用 `general` 继续，标"类目门槛未核对" |
| 用户只给了一句"帮我写个 listing" | 先给输入卡模板让他填，不要凭空生成 |

## 输出格式

```markdown
## 输入卡

| 项 | 值 | 来源 |
|---|---|---|
| 站点 | US | 用户提供 |
| 类目 | food_contact | 用户提供：厨房饮水 |
| 产品 | 折叠硅胶咖啡杯 | 用户提供 |
| 材质 | 硅胶杯身 + PP 杯盖 | 用户提供 |
| 尺寸/容量 | 350 ml，展开 8×12 cm | 用户提供 |
| 主关键词 | collapsible coffee cup | 用户提供 |
| 竞品 | 无 | 未提供 |
| 资质 | 无 | 用户提供 |
| 售价 / FBA | 21.99 USD / 是 | 用户提供 |

【假设】无
缺失项：无
```

## 异常处理

- **用户给了互相矛盾的信息**（如"食品级"但材质写"未知塑料"）：以更保守的一方为准，把矛盾点写进假设。
- **用户拒绝提供资质信息**：不追问第二次，直接在 G3 把对应项标为"未核对"，判定最多到 CONDITIONAL。
- **用户给的是别人的 Listing 链接要"改一改"**：先确认他是否有权使用该文案。照抄他人 Listing 属侵权，只能做结构分析，不能改写复用。

## 依赖

无前置。只依赖用户输入。

## 与其他工作流的关系

- 下游：G1（消费输入卡的主词与竞品）、G3（消费类目键与资质）、G4（消费 attributes）。
- 回退：G3 若发现类目判错，退回本门重判类目键。
