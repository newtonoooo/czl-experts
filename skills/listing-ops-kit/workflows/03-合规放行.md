# G3 · 合规放行

## 职责

给出一个**带清单的判定**，而不是一句"应该没问题"。判定只有三种：GO / CONDITIONAL / BLOCKED。

这一门是整条链上唯一可以说"不许提交"的门。

## 输入参数

| 参数 | 必填 | 说明 |
|---|---|---|
| 文案全文 | 是 | 标题 + 五点 + 描述 + 后台词 |
| 站点 | 是 | 决定市场层义务 |
| 类目键 | 是 | 决定类目层门槛 |
| 已有资质 | 否 | 决定 CONDITION 项能否转 GO |

## 执行步骤

1. **跑机器扫描**：

   ```bash
   python scripts/listing_audit.py compliance --listing x.json --market DE --category juvenile_products
   ```

2. **看 `category_known`**：为 `false` 时说明类目键没覆盖，此时判定只含词层 + 市场层，必须告诉用户"类目门槛未核对"。
3. **逐条过三层**：
   - 词层：绝对化、保证性、医疗功效、价格促销、竞品指名、未授权品牌词。
   - 类目层：该类目在该站点的准入（认证、检测、标签、说明书语言）。
   - 市场层：该站点的强制义务（责任人、包装注册、电子废弃物、能效）。
4. **对每条给四要素**：级别 + 命中原文 + 原因 + 改法。缺一不可。
5. **出判定**。
6. **写清"补什么才能 GO"**。

## 判断条件

| 情况 | 判定 | 说明 |
|---|---|---|
| 无 BLOCK，无未决 CONDITION | **GO** | 可以提交 |
| 无 BLOCK，有 CONDITION | **CONDITIONAL** | 可提交，但列清补齐项 |
| 有任一 BLOCK | **BLOCKED** | 必须先解决，不得提交 |
| 类目键未覆盖 | 最多 **CONDITIONAL** | 类目门槛未核对，不能给 GO |
| 用户无法提供任何资质 | 最多 **CONDITIONAL** | 相关项标"未核对" |

## 输出格式

```markdown
## 合规放行 · DE / juvenile_products

**判定：BLOCKED**（阻断 4 / 条件 2 / 提示 0）

### 阻断项（必须先解决）

| 命中 | 项 | 原因 | 改法 |
|---|---|---|---|
| `Beste` | 绝对化用语 | 无法举证的排名宣称 | 换成具体材质或结构 |
| `100% Sicher` | 保证性承诺 | 绝对百分比不可举证 | 删除百分比 |
| — | GPSR 欧盟责任人 | 法规要求欧盟境内责任人 | 指定责任人并写入后台 |
| — | LUCID 包装注册 | 德国包装生产者义务 | 取得 LUCID 号 |

### 条件项（补齐可转 GO）

| 项 | 原因 | 改法 |
|---|---|---|
| CE 标识提及 | 提及即承诺举证 | 确认报告在手，否则删除 |
| 德语说明书 | 面向德国消费者须德语 | 提供德语版 |

### 补齐后能否 GO

需同时满足：① 删除全部绝对化与保证性表述；② 取得 GPSR 责任人与 LUCID 注册号；③ 确认 CE 报告与型号对应。三项齐备后可重跑本门复核。

> 本判定基于配置规则与所提供文本，不构成法律意见，最终以亚马逊后台与当地法规为准。
```

## 异常处理

- **规则包与用户后台不一致**：以后台为准，记录差异，更新规则包。
- **用户说"别人都这么写"**：别人没被查到不代表合规。按判定给结论，不因为普遍性放宽。
- **用户要求"帮我过审"**：说明只能做合规改写，不能规避审核；规避行为会导致账号风险。
- **拿不准某条法规是否适用**：写"需核实"并说明核实路径（问谁、查什么），不要写"应该没问题"。
