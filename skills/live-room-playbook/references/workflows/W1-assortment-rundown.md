# W1 货盘排品与节奏表

## 一、职责

把一堆积压的货，排成一条**能接住每一波流量**的时间线。
排品的本质不是"哪个先讲哪个后讲"，而是：当系统把一批陌生人推进来的时候，屏幕上正好挂着一件他们此刻最可能下单的东西。

## 二、输入参数

| 参数 | 必填 | 说明 |
|---|---|---|
| 场次任务书（W0 产出） | 是 | 主目标、价格带、时长、验收口径 |
| 货盘清单 | 是 | SKU、售价、成本、库存、卖点、演示难度 |
| 库存与供应链约束 | 是 | 每个 SKU 可放量多少、能否补货 |
| 流量预判 | 否 | 是否有预热、是否投流、预计波峰时间 |
| 主播能力档位 | 是 | 见 W3 的评分；决定哪个品能讲、哪个品要换人讲 |

## 三、五类货位

| 货位 | 作用 | 价格定位 | 数量占比 | 时长占比 | 库存释放 |
|---|---|---|---|---|---|
| 引流款 | 把人留住、拉互动 | 全场最低价带 | 15% | 15% | 少放（20-30 件/次），制造稀缺 |
| 承接款 | 承接新进流量，转化门槛低 | 中低价，易决策 | 25% | 20% | 中量（可反复上） |
| 主力款 | 撑 GMV | 目标客单价附近 | 35% | 40% | 分批放（30%/40%/30%） |
| 利润款 | 赚钱 | 高于客单价 1.5 倍以上 | 15% | 15% | 少量（10-20 件） |
| 收尾款 | 收割+清尾货 | 中低价或打包 | 10% | 10% | 一次性放完 |

**价格带梯度原则：** 引流款 : 承接款 : 主力款 : 利润款 ≈ 1 : 2 : 3 : 5。
梯度断了（比如没有 100 元以下的品），新进流量没有低门槛入口，停留会在 30 秒内掉光。

## 四、执行步骤

**第 1 步：给每个 SKU 打三个标签。** 演示难度（一眼能看懂 / 需要讲解 / 需要上手）、决策成本（冲动 / 比较 / 慎重）、毛利档位（高 / 中 / 低）。三个标签决定它该放哪个货位。

**第 2 步：按 4 小时骨架铺时间线。** 骨架见 `references/rundown-blueprint.md`。核心是三段：

- **0-15 分钟 建模期**：不卖主力款。用引流款 + 一句"今晚有什么"建立预期，把停留和互动拉起来，让系统确认"这个直播间有人看"。
- **15 分钟-3 小时 成交循环**：每 20-25 分钟一个完整循环（引流款钩子 3 分钟 → 承接款 5 分钟 → 主力款 12 分钟 → 互动指令 2 分钟）。循环之间用福利或预告切换，防止节奏平掉。
- **最后 40 分钟 收割期**：放利润款和收尾款，用"最后一波""今天不再上"做时间稀缺，同时引导关注为下一场蓄水。

**第 3 步：把波峰对齐。**
如果 20:00-21:00 是投放或自然流量高峰，主力款必须**在这个时段内出现至少两次**，且第二次要有新信息（新赠品、新组合、降价），不能原样重念。

**第 4 步：定库存释放节奏。**
一个品一次放完，用户会觉得"反正还有"，逼单失效；放太少，讲完就卖光，后面的流量接不住。
标准做法：**首放 30% → 讲完核心卖点放 40% → 逼单前放 30%**。

**第 5 步：写进 Rundown 表。** 表头固定：`时间 | 货位 | 品名 | 价格 | 释放量 | 讲解要点（一句话）| 互动指令 | 责任人`。

## 五、判断条件（排完必须自检）

| 现象 | 判断 | 改法 |
|---|---|---|
| 成交集中在某 20 分钟 | 主力款太少或位置错 | 把主力款复制到第二个波峰，或补一个主力款 |
| 前 15 分钟就上主力款 | 建模期被跳过，新流量进来看到的是高价品 | 前 15 分钟改成引流款 + 预告 |
| 连续 30 分钟没有低价品 | 新进流量无低门槛入口 | 插入一个承接款 |
| 单品讲解超过 15 分钟 | 节奏断裂，掉人风险高 | 拆成"讲 8 分钟 → 上链接 → 5 分钟后补讲" |
| 利润款放在流量谷值 | 高毛利品没人看 | 利润款只在波峰后半段上 |
| 库存一次放完 | 逼单失效 | 按 30/40/30 分批 |
| 没有收尾款 | 最后 40 分钟空转 | 补一个打包清尾的收尾款 |

## 六、输出格式

1. **Rundown 表**（分钟级，见 `templates/rundown-4h.md`）
2. **价格带梯度图**（一行文字即可：`39 / 79 / 129 / 259 / 199打包`）
3. **库存释放表**（SKU / 总量 / 首放 / 二次 / 三次）
4. **波峰对齐说明**（把哪个主力款放在第几分钟、为什么）

## 七、异常处理

| 异常 | 处理 |
|---|---|
| 货盘凑不齐五类 | 缺什么补什么：缺引流款就把利润款拆出小规格；缺承接款就把主力款做成小份装 |
| 只有 3 个品 | 不排 4 小时，改 2 小时，每品拆成多个组合（单品 / 双件 / 三件套） |
| 库存极薄（每品 <50 件） | 排"多品少量"结构，缩短单次讲解，靠品数撑时长 |
| 主播只能讲 1-2 个品 | 排品向主播能力倾斜，其他品由副播或中控口播带过 |
| 用户坚持"把最好的放最后" | 告诉他流量峰值不在最后，放最后等于把最好的品给最少的人看 |

## 八、依赖

- W0 的主目标与价格带
- W3 的主播能力评分（决定谁能讲什么）
- `live-room-metrics breakeven`（毛利低的品不能当主力款）

## 九、与其他工作流的关系

- **上游**：W0。**下游**：W2（每个货位都要有对应脚本）、W4（库存释放节奏决定投放放量时点）。
- **回流**：W5 发现"点击高但成交低"，第一嫌疑就是本段的排品价格断层，需要回到本段重排。
