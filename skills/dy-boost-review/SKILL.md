# 投放测算与周期复盘

## 什么时候用

- 用户纠结"要不要投、投多少"。
- 投了钱，说不清是赚是亏。
- 视频自然流量还行，想放大。
- 到了周末/月末，要复盘但不知道看哪几个数。

## 必填输入

| 项 | 为什么要 | 缺了怎么办 |
|---|---|---|
| 客单价 | 换算订单数的分母 | 必填 |
| 毛利率 | 决定能拿出多少钱买流量 | 必填，只给"利润大概三成"就按 30% 并标注假设 |
| 退款率 | 直接吃掉毛利，很多人漏算 | 不知道就用类目常见区间并标注"假设值" |
| 计划消耗 | 分母 | 必填 |
| 点击成本（CPC）或千次曝光成本（CPM） | 反算获客成本 | 只有一个就给一个，另一个用实测替代 |
| 转化率（点击→成交 / 进入→成交） | 反算 CPA | 没有就先测，不许拍脑袋填 |

**只缺一个数时**：先把公式摆出来，把缺的那项留成变量，告诉他"这个数你自己查一下填进去，结论会变"。不许替他填。

## 第一步永远是算保本，不是算预算

```bash
python3 ${SKILL_DIR}/scripts/dy_boost.py ads \
  --aov 129 --margin 0.4 --refund 0.15 --cpc 0.8 --cvr 0.02 --spend 3000

python3 ${SKILL_DIR}/scripts/dy_boost.py plan \
  --aov 129 --margin 0.4 --refund 0.15 --budgets 1000,3000,5000
```

三个硬数（口径必须写清）：

- **单笔净毛利** = 客单价 × 毛利率 × (1 − 退款率)
- **保本 CPA** = 单笔净毛利（超过这个数，每单在亏）
- **保本 ROAS** = 1 ÷ (毛利率 × (1 − 退款率))

**判定规则**：
- 实际 CPA ≤ 保本 CPA × 0.8 → 有安全垫，可以小步放量。
- 落在 0.8—1.0 之间 → 没有容错，退款率一涨就亏，不许加预算。
- 超过保本 CPA → 跑不通。先改素材或提转化，加钱只会加速亏损。

## 两种付费工具怎么选（不编价格）

| 工具 | 本质 | 适合 | 不适合 |
|---|---|---|---|
| DOU+ | 给内容加热，买播放/互动 | 测钩子、测选题、给自然流量好的视频加一把火 | 直接冲成交（人群太泛） |
| 千川 | 买成交，按转化优化 | 有明确转化路径（小店/直播间）且素材已验证 | 内容本身还没跑通时投，等于给烂素材交学费 |

**顺序**：先用自然流量验证钩子和转化路径 → 再用 DOU+ 小预算测人群 → 跑得动再上千川。
反过来做，是拿钱买教训。

具体价格、起投门槛、审核规则以平台当时的实际报价和规则为准——不要在方案里写死数字，写死就会被平台改动作废。

## 素材衰减（判断什么时候换素材）

一条素材通常经历三段，判断信号如下：

| 阶段 | 信号 | 动作 |
|---|---|---|
| 起量期 | 消耗能跑出去，CPA 稳定在保本线以下 | 别动它。不要改价、不要改定向 |
| 衰减期 | CPA 连续 2 天上升 ≥ 30%，或消耗突然跑不动 | 复制素材换开头 3 秒，其他不动，做 A/B |
| 死亡期 | 点击率掉一半以上，或审核反复不过 | 停。硬撑只会拖高整体 CPA |

**换素材的纪律**：一次只换开头 3 秒。同时换开头 + 换音乐 + 换文案，测出来也不知道是哪个起的效。

## 周复盘固定表

每周填一张，**只填数，不填感受**：

| 指标 | 本周 | 上周 | 变化 | 归因（三选一：内容/投放/外部） | 下一步只改一件事 |
|---|---|---|---|---|---|
| 发布条数 |  |  |  |  |  |
| 总播放 |  |  |  |  |  |
| 均播放 |  |  |  |  |  |
| 3 秒留存 |  |  |  |  |  |
| 完播率 |  |  |  |  |  |
| 互动率 |  |  |  |  |  |
| 新增粉丝 |  |  |  |  |  |
| 消耗 / GMV / ROAS |  |  |  |  |  |
| 单均获客成本 |  |  |  |  |  |

**归因只许选一个主因**。三个都写等于没归因。

## 输出格式

1. **结论**：能投 / 不能投 / 只能小步试，附三个硬数。
2. **测算表**：单笔净毛利、实际 CPA、毛利−CPA、保本订单数、保本 GMV。
3. **预算建议**：分档压力测试（每档需要多少 GMV 和订单）。
4. **执行纪律**：小步、单变量、什么信号停。
5. **复盘表**（如用户是来复盘的）。

## 异常处理

| 情况 | 处理 |
|---|---|
| 用户没有成本数据，只想"投点试试" | 给最小测试方案（固定小额、固定时长、只测一件事），并说明这次不追 ROI，只买信息 |
| 用户要求"保证投出去就赚" | 拒绝。改为给保本线与止损线 |
| 用户已经亏了，情绪化要加投翻本 | 明确反对加投，先算出亏在哪一段（素材/人群/承接/货），再决定是否重开 |
| 数据口径不明（GMV 含不含退款） | 先统一口径再算，含退款和不含退款能差出一倍 |
| 用户想把站外成交算进 ROAS | 分开算。平台内 ROI 与全域 ROI 必须标清，不能混报 |

## 与其他技能的关系

- 上游：`dy-account-diagnosis` 的基线数据是复盘对照物。
- 保本 GPM 直接给 `dy-live-runbook` 排品用，两边口径必须一致。
- 素材要改开头 → 回 `dy-hook-script`；素材要改表述 → 过 `dy-compliance-lint`。
