# 账号体检

## 什么时候用

- 用户说"做了几个月没起量""播放总是卡在几百"。
- 用户贴了后台数据或截图，问"这算好还是差"。
- 用户问某一条视频为什么数据不好。
- 用户要投流，但连自己的基线都不清楚——先体检，再谈投放。

## 必填输入

| 项 | 为什么要 | 缺了怎么办 |
|---|---|---|
| 赛道与变现方式 | 决定看哪几个指标（卖货看完播+成交，做号看涨粉） | 必须问，不许猜 |
| 近 7—30 天每条视频的：播放量、时长、完播率、点赞、评论、收藏、分享、新增粉丝 | 算漏斗的唯一原料 | 缺哪项就标"待填"，不许用行业均值替代 |
| 目标观众的一句自我描述 | 判断选题是否跑偏 | 用评论区原话代替 |
| （选填）3 秒留存率、平均播放时长 | 能直接定位断点秒数 | 缺失时用完播率做粗判，并声明精度下降 |

**少于 3 条视频样本时**，先声明"样本不足，比率波动大"，结论只作方向参考，不许给精确阈值。

## 执行步骤

### S1 收数与清洗
1. 把每条视频的数据整理成一张表，缺失项写"待填"。
2. 剔除非正常样本：投过流且投流占比超过一半的、蹭过热点的、被限流后重发的——单独标注，不混入基线。
3. 确认口径：完播率是"完播次数/播放次数"还是"完播人数/播放人数"，两种不能混算。

### S2 计算
把数据写成 JSON 喂给脚本：

```bash
python3 ${SKILL_DIR}/scripts/dy_metrics.py --input data.json
python3 ${SKILL_DIR}/scripts/dy_metrics.py --input data.json --format json --out report.json
```

脚本会算：3 秒留存、完播（按视频时长分档）、互动率（赞评藏转/播放）、涨粉率（新增粉/播放）、平均播放时长占比，并给 0—100 分。

### S3 定断点（漏斗优先，只定一个）
按 `3秒留存 → 完播承接 → 互动密度 → 涨粉效率` 的顺序找**第一个低于及格线的环节**，那就是主断点。
前面的环节不过线时，后面的高分不算数——流量根本没走到那一步。

全部过线时，取得分最低者作为"最弱环节"，明确告诉用户"没有硬卡点，这是可优化项"。

### S4 归因（不许只给一个原因）
每个断点给 **3 个可能原因 + 各自的验证动作**，按可能性排序。参考下表：

| 主断点 | 常见原因 | 怎么验证 |
|---|---|---|
| 3秒留存低 | 开场是自我介绍/客套；首帧画面没有信息；标题与内容不符 | 同选题拍 3 版不同首句，其他不动，只比 3 秒留存 |
| 完播承接低 | 信息点后置；时长超出题材承载；中段有过渡废话 | 看平均播放时长落在第几秒，把最大信息点提到该秒前 3 秒 |
| 互动密度低 | 观点太正、没有可反驳处；结尾提问太开放 | 换成两个字能回答的提问，测下一批 3 条 |
| 涨粉效率低 | 没有可复用的身份标签；单条自洽但不成系列 | 加系列编号 + 固定结尾句，看主页关注转化 |

### S5 出排期
给 30 天修复排期，**一次只改一个变量**，每周只动一处：

| 周次 | 只改什么 | 观察指标 | 通过判据 |
|---|---|---|---|
| 第 1 周 | 首句钩子 | 3 秒留存 | 提升 ≥ 8 个百分点 |
| 第 2 周 | 信息前置 | 完播率 | 提升 ≥ 5 个百分点 |
| 第 3 周 | 结尾提问 | 互动率 | 提升 ≥ 1 个百分点 |
| 第 4 周 | 系列化与主页 | 涨粉率 | 单条 ≥ 3 个粉 |

## 输出格式

固定四段，顺序不许调：

1. **结论**：主断点是什么、实测多少、及格线多少、先改哪一处。
2. **漏斗表**：环节 / 实测 / 得分 / 判定。
3. **逐条表**：视频 / 播放 / 关键指标 / 本条判定。
4. **30 天排期**：周次 / 只改什么 / 观察指标 / 通过判据 / 没到怎么办。

每个数字必须能被用户自己核对，写清来源（后台哪个页面、哪个时间区间）。

## 异常处理

| 情况 | 处理 |
|---|---|
| 用户给的数据互相矛盾 | 先复算，把矛盾点单独列出来让他核对口径，不硬算 |
| 播放量普遍低于 500 | 声明样本过小，只做结构性判断，不给阈值结论 |
| 用户只想听"内容不够好" | 拒绝这种结论，追问具体哪一秒掉人，否则不给方案 |
| 用户要求预测"改了能涨多少" | 只给区间和条件，写明"不构成承诺" |
| 账号刚被处罚/限流 | 先确认处罚原因与恢复状态，再谈内容优化，否则一切优化无效 |

## 与其他技能的关系

体检出的主断点决定下一步：钩子类断点 → `dy-hook-script`；转化类断点 → `dy-live-runbook` 或 `dy-boost-review`；表述违规导致的限流 → `dy-compliance-lint`。
体检结论同时是下一轮复盘的基线，必须存档，否则复盘没有对照。
