# 01 受理与脱敏

这一阶段的唯一目的：**在动手算之前，把"算的是谁、算的是哪一段、算的是什么口径"钉死**。跳过它，后面所有数字都要返工。

## 一、任务卡（每单必填，五句话）

```
主体：______（名称可脱敏）  身份：□一般纳税人 □小规模 □个体户 □自然人 □不确定
行业：______            规模：月收入约____，员工____人
期间：______ 至 ______   数据形态：□报表 □明细账 □票据 □口述 □截图
要解决的问题：________________________________
本次交付：________________________________
```

第三行"要解决的问题"必须是一句能验收的话。

- 不合格：「帮我看看财务」——看完也不知道算不算看完了。
- 合格：「这个月毛利率比上月掉了 6 个点，想确认是采购价涨了还是低价单变多了」。

用户说不出具体问题时，你替他收窄：「你是想知道赚不赚钱、钱去哪了、还是税上有没有坑？」三选一，比让他自由描述有效得多。

## 二、资料清单矩阵（按任务类型取用）

只列**这次真正要用的**，一次要十几项会把用户吓走。第一轮最多要三项，其余标注"有则更好"。

| 任务类型 | 必需（不给就做不了） | 有则更好 | 没有时的降级方案 |
| --- | --- | --- | --- |
| 经营体检 | 利润表、资产负债表（同一期间） | 现金流量表、上期报表、预算数 | 只有利润表：只做盈利与费用结构，不做偿债与现金判断，并明确说明 |
| 现金与资金 | 现金流量表 + 银行流水月合计 | 应收应付账龄表 | 只有流水：做收付结构与集中度，不做权责口径分析 |
| 报税辅导 | 纳税人身份、期间、主要业务类型、开票情况 | 上期申报表、税负率、进项构成 | 无一手上数据：给判定树与清单，明确"金额需你自己代入" |
| 发票问题 | 发票类型、开票日期、金额税额、购买方信息 | 发票影像、业务合同、查验截图 | 只有描述：先给五要素核对表，让用户自行比对 |
| 预算编制 | 上年实际数（至少收入与三大费用） | 业务计划、人员编制、租金合同 | 无历史数：给零基预算骨架 + 需要用户填的空格，不编数字 |
| 差异分析 | 预算数 + 实际数（同科目同口径） | 量价明细、发生时间 | 只有总额：只能做科目级差异，不能拆量价，要说明 |
| 内控设计 | 业务环节、人员编制、现有审批方式 | 现有制度、历史差错记录 | 无制度：按最小可行控制给三个点，标明是"起步版" |
| 个体户/工作室 | 征收方式（查账/核定）、行业、月销售额 | 成本票据取得情况 | 征收方式不明：两种情形并列给，让用户先确认 |

## 三、脱敏规则

用户经常直接把真账贴进来。你要在第一次回复里主动说，不要等他问。

**替换，不删除**——保留结构，去掉身份：

| 原始信息 | 替换为 |
| --- | --- |
| 客户/供应商全称 | 客户A、客户B、供应商甲、供应商乙（同一主体前后必须一致） |
| 人名、身份证号、手机号 | 张某、员工1、139****0000 |
| 银行账号、开户行 | 账户1、基本户 |
| 具体地址 | 某区、仓库1 |

**金额处理**：允许整体乘以同一系数（如全部除以 10000）以隐藏真实规模，但必须满足两点——所有金额同比例缩放，且用户告知了缩放倍数。比例型指标不受影响，绝对额结论要换算回来。

**不允许的"脱敏"**：只删掉几笔大额交易。这会直接破坏勾稽关系，让 G1 永远对不上。要隐藏就整体缩放，不要挑着删。

**你自己也不索取**：密码、U 盾口令、网银登录信息、身份证原件照片、社保账号。用户主动发来也不要在回答里复述。

## 四、口径四问（决定后面所有算式）

问不全就假设，但假设要写进交付物的口径声明里。

1. **含税还是不含税？** 报表收入一般不含税；用户口述"这个月卖了一百万"多数是含税。两者差 13% 或 3%，足以改变毛利率结论。
2. **期末数还是平均数？** 算周转率、ROE 这类涉及存量的指标，严格口径用（期初＋期末）÷2。只有期末数时可以用期末值，但要在指标旁标注"按期末值计算，与平均值口径存在偏差"。
3. **单体还是合并？** 有子公司时，合并报表的收入含内部交易抵销，直接和单体比会得出错误结论。
4. **权责发生还是收付实现？** 报表是权责，流水是收付。用流水判断利润，会得出"账上赚钱但没钱"的错误归因。

这四问在中小企业场景里，第二和第四最容易出错，优先确认。

## 五、放行检查

进入 G1 前，逐条确认：

- [ ] 主体身份明确（不确定时，先按最可能的身份给方案，并列出身份变化会导致哪些结论改变）
- [ ] 期间明确到月，且起止一致（利润表 9 月，资产负债表 9 月末，不能一个是 8 月末）
- [ ] 金额单位明确（元／万元／千元）
- [ ] 至少一项可用数据
- [ ] 用户已知道你会怎么处理他的敏感信息

任一条不满足，输出《待补清单》而不是分析结论。待补清单格式：

```
为了回答"毛利率为什么掉了"，还差三样：
1. 上月同口径的营业成本 —— 用来分离是价变了还是量变了
2. 主要产品的单价与销量 —— 用来拆量差价差
3. 本期是否有一次性让利或返利 —— 用来排除非经营性因素
拿到 1 和 2 就能定位到主因；只有 1 只能判断趋势。
```

注意最后一句：**告诉用户补哪个最划算**。这比列一长串清单有用。
