# 三层验证清单

按项目类型取用。通用层必做，类型层按实际选。

---

## L1 通用（任何改动都要过）

| # | 项 | 用例 | 记录方式 |
|---|---|---|---|
| L1-1 | 空输入 | 空字符串 / 空数组 / null / 缺字段 | 返回 400 且提示可读，不 500 |
| L1-2 | 超长输入 | 文本框 1 万字符 / 超长 URL 参数 | 被拒或截断，不超时、不写爆库 |
| L1-3 | 类型错误 | 数字位置传字符串、布尔传 "yes" | 校验拦下 |
| L1-4 | 特殊字符 | 单引号、emoji、换行、`<script>` | 不报错、不被执行 |
| L1-5 | 重复提交 | 同一请求连发 2 次 | 只产生 1 条记录 |
| L1-6 | 边界数值 | 0、-1、极大值、小数位 | 符合业务定义，不静默截断 |

---

## L2 集成

| # | 项 | 怎么做 | 常见假通过 |
|---|---|---|---|
| L2-1 | 数据库真实连通 | 连真库跑一次迁移 + 读写 | 用内存库代替，结论不成立 |
| L2-2 | 迁移可回退 | 跑 up 再跑 down，再跑 up | 只跑 up |
| L2-3 | 第三方成功分支 | 沙箱真实调用一次 | 用 mock 返回写死结果 |
| L2-4 | 第三方失败分支 | 断网 / 错误密钥 / 超时 | 从未测过失败会怎样 |
| L2-5 | 文件写入位置 | 上传一个文件，确认落盘路径与权限 | 只看接口返回成功 |
| L2-6 | 队列/异步任务 | 投递一条，确认被消费 | 只看投递成功 |

---

## L3 端到端

按验收条目逐条走，每条填一行：

| 编号 | 操作路径 | 结果 | 证据 |
|---|---|---|---|
| A1 | | | |
| A2 | | | |

**必须额外走的三条路径：**

| 路径 | 目的 |
|---|---|
| 越权访问（改 id / 换账号） | 确认返回 403/404 而不是别人的数据 |
| 中途退出（提交前关页面、断开网络） | 确认不产生半条脏数据 |
| 权限最低的用户 | 确认不会因为"管理员能用"就以为功能正常 |

## Web 前端补充

| # | 项 |
|---|---|
| W1 | 控制台无报错、无 404 资源 |
| W2 | 窄屏（375px）不错位、不横向滚动 |
| W3 | 三态齐全：加载中、空数据、请求失败 |
| W4 | 表单提交期间按钮禁用，失败后恢复可点 |
| W5 | 刷新页面不丢关键状态；直达链接（深链接）不 404 |
| W6 | 接口地址来自配置，不是写死在页面里 |

## API 服务补充

| # | 项 |
|---|---|
| S1 | 未登录返回 401，无权限返回 403，不存在返回 404 |
| S2 | 错误响应体不含堆栈、SQL、路径、依赖版本 |
| S3 | 分页参数越界（第 0 页、负值、超大页码）行为一致 |
| S4 | 关键写接口幂等（连发两次结果一致） |
| S5 | 超时与限流存在，且限流命中返回 429 |
| S6 | 健康检查与就绪检查分别验证 |

## 数据迁移补充

| # | 项 |
|---|---|
| M1 | up / down 均执行成功 |
| M2 | 在接近生产数据量的副本上估算过耗时 |
| M3 | 不包含"删列 / 改类型"这类一步到位的破坏性操作 |
| M4 | 迁移完成后旧代码仍能运行（灰度期间新旧并存） |

## 记录模板

```
L1：6/6 通过
L2：数据库 ✓（迁移 up/down/up 通过）、第三方 ✓ 成功 ✓ 失败（错误密钥返回 401，符合预期）、文件 ✓
L3：A1 ✓ A2 ✓ A3 未验证（缺短信测试账号）
结论：L1 通过，L2 通过，L3 部分未验证 → 不可上线（A3 是主链路）
```

不允许写"基本都过了"。要么给编号，要么写未验证。
