# 一致性闸（Chain Consistency）

## 为什么需要这一步

五个人各写一份文档，最典型的事故不是写错，是**互相对不上**：

- 规格里 7 条需求，路线图里只有 5 条，另外 2 条不知去向
- 汇报里说"转化提升 15%"，口径表里的目标值是 8%
- 风险清单里的 RSK-03 在行动清单里没有对应动作
- 指标 MET-05 被引用三次，但口径表里没有这张卡

这些错误单看每份文档都发现不了，只有把编号抽出来对齐才看得见。

## 编号体系

| 前缀 | 含义 |
|------|------|
| GOAL-xx | 目标 |
| EVD-xx | 证据 |
| REQ-xx | 需求 |
| AC-xx.n | 验收标准 |
| MET-xx | 指标 |
| RM-xx | 路线图条目 |
| RSK-xx | 风险 |
| DEC-xx | 待决策 |

## 校验项

| 编号 | 检查 | 级别 |
|------|------|------|
| C1 | 每个 REQ 至少被一处 AC 覆盖 | error |
| C2 | 每个 AC 的父 REQ 存在 | error |
| C3 | 每个 active REQ 在排产表里有对应 RM（或被标 deferred/cut） | error |
| C4 | 每个 MET 被至少一个 REQ 或 GOAL 引用（孤儿指标） | warn |
| C5 | 每个被引用的 MET/EVD/RM 都有定义 | error |
| C6 | 每个 RSK 有缓解动作（同文档出现"缓解"或"应对"） | warn |
| C7 | 每个 committed RM 有止损线 | error |
| C8 | 同一指标的目标值在不同文档中出现时数值一致 | error |

## 脚本

```
python scripts/chain_check.py <交付目录> [--json]
```

输出：断链清单（按严重度排序）、孤儿编号、修复建议。退出码非 0 = 有 error。

## 修复原则

- 以**口径表**为准回改规格与汇报（口径是唯一事实源）
- 以**证据等级**裁决冲突结论，同级冲突登记 DEC-xx 交用户
- 被砍项不删除，标 `deferred` 并保留编号
- 修完后重跑脚本，把两次结果都留在 `99-一致性报告.md` 里

## 报告结构

```markdown
## 一致性报告
### 校验范围（文件清单 + 时间）
### 结果总览（error / warn 计数）
### 断链明细（编号 / 问题 / 修复动作 / 状态）
### 数字不一致明细（指标 / 文档 A 值 / 文档 B 值 / 采纳值 / 依据）
### 结论（可交付 / 不可交付）
```
