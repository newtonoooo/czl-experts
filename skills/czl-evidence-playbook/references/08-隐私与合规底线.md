# 08 · 隐私与合规底线

> 这一份讲的是：做数据分析时，哪些事不能做。不是法律意见，红线以现行法规与你所在机构的规定为准。

## 一、三条底线

1. **不处理可直接识别个人的明细**：身份证号、手机号、住址、银行卡、人脸、精确位置轨迹。
2. **不试图反匿名**：不通过组合字段把"已脱敏"的数据还原到个人。
3. **不外传**：不把用户数据发到任何外部服务、不上传、不粘贴到公开渠道。

违反其中任何一条，分析本身再有价值也不做。

## 二、什么算可用数据

| 可用 | 不可用 |
|---|---|
| 聚合到日/周/月、按维度汇总的表 | 含手机号、身份证的原始订单明细 |
| 用户 ID 已替换为随机编号 | 真实姓名 + 联系方式 |
| 金额、数量、状态、时间 | 聊天内容、评价原文中的个人信息 |
| 年龄段、城市级别（非精确地址） | 精确到门牌的发货地址 |

判断标准很简单：**这一行数据能不能对上某个具体的人**。能，就不要放进分析环境。

## 三、最小必要

只取分析需要的列。拿到 40 列的表，先删到 8 列再动手。

- 做销售归因：要日期、金额、渠道、品类、订单状态，不要收货地址与电话；
- 做留存：要用户编号与活跃时间，不要任何身份字段；
- 做分群：要行为与金额，不要人口属性中的敏感项。

## 四、小样本的再识别风险

按"城市 + 年龄 + 品类"分组后，某组只有 2 个人，这两人的信息实际上等于公开。

处理办法：

- 分组后样本 <5 的组，合并到"其他"；
- 极值（最高单笔、最大客户）在报告里改为区间表述，不写具体值；
- 涉及单一客户的分析，先确认内部授权。

## 五、报告里不能出现的东西

- 任何个人联系方式、证件号、精确地址；
- 能定位到个别客户的"最大客户贡献 32%"这类表述（除非客户同意或为内部授权场景）；
- 未脱敏的原始数据截图；
- 数据库连接串、账号口令、内网地址。

## 六、跨境与第三方

- 数据不出境：涉及境外工具的，先确认合规路径；
- 第三方 SDK、外部 API 处理用户数据前，确认授权与告知；
- 分析外包时，只给聚合数据，不给明细。

## 七、留痕与可追溯

- 分析用的数据文件、处理脚本、参数，全部留档；
- 谁在什么时候取过什么数据，可查；
- 分析结论对外发布前，确认不含个体信息。

## 八、遇到越界要求怎么办

用户要求"把某个客户的明细拉出来看看""这批手机号帮我匹配一下"——直接拒绝，并给替代方案：

> 这个需求涉及个人身份信息，我不处理明细。可以改成：按城市级别看这组客户的消费分布，或者你给我已脱敏的编号表，我按编号做分析。

拒绝要给替代，不然用户只会换个方式再问一次。
