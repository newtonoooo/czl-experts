# W2 · 数据体检

## 职责

在算任何指标之前，先判断这份数据**能不能支撑结论**。产出质量账、可用性评级，以及三条"这会怎么影响结论"的具体提示。

体检不是走过场。脏数据算出来的数，越精确越危险。

## 输入参数

| 参数 | 是否必需 | 说明 | 缺失时怎么办 |
|---|---|---|---|
| 数据文件 | 必需 | CSV/TSV（UTF-8 或 GBK） | 无文件则跳过本工序，转 W3 手算 |
| 关键字段 | 必需 | 至少一个日期列、一个金额或计数列 | 缺日期列 → 不能做趋势，只能截面 |
| 主体标识 | 建议 | 客户ID/订单ID/用户ID | 缺主体 → 无法去重、无法算留存，评级降一档 |
| 业务状态字段 | 建议 | 是否退款、是否取消、是否有效 | 缺 → 无法识别口径冲突，在质量账标注 |

## 执行步骤

1. **跑体检脚本。**

   ```bash
   python profile_table.py 订单.csv
   python profile_table.py 订单.csv --out 质量账.md
   ```

   输出：行列数、每列类型推断、缺失率、唯一值数、数值列的分位与极值、日期列的首末与断档、疑似重复行数。

2. **人工补三条脚本看不出来的东西。**
   - 状态字段与金额是否联动（有"已退款"行但金额未冲销）；
   - 是否存在同一主体多条记录的合并口径问题；
   - 单位是否统一（元/万元混用、件/箱混用）。

3. **评级。** 按下表打分，取最低项作为整体评级。

   | 维度 | A | B | C | D |
   |---|---|---|---|---|
   | 关键字段完整率 | ≥99% | 95–99% | 80–95% | <80% |
   | 时间连续性 | 连续无断档 | 断 1–2 天 | 断 3–7 天 | 断档 >7 天 |
   | 重复行 | 0 | <0.5% | 0.5–3% | >3% |
   | 口径一致性 | 完全一致 | 轻微不一致 | 需人工裁定 | 冲突严重 |
   | 样本量（关键分组） | 每组 ≥200 | ≥100 | ≥30 | <30 |

4. **写三条影响提示。** 每条格式：发现的问题 → 会让结论偏成什么样 → 处理办法。

   例：「金额列有 6.2% 的空值，且集中在『退货』状态。若直接求和，销售额会被低估约 4–7%。处理：按状态分别统计，退货单单独成表。」

## 判断条件

| 判断点 | 条件 | 动作 |
|---|---|---|
| 整体评级 | A / B | 正常进 W3 |
| 整体评级 | C | 进 W3，但结论最高只能 B 级；质量账必须随结论一起交付 |
| 整体评级 | D | **停下**。先问用户：补数据，还是降级继续（只做描述不做归因） |
| 缺关键字段 | 缺日期或缺金额 | 报告能做什么、不能做什么，不要硬算 |
| 疑似口径冲突 | 同一含义多列/多套值 | 不合并，分别统计，交用户裁定 |

## 输出格式

`T3-质量账.md` 一份，含：

- 数据基本信息（行数、列数、时间跨度、来源、提取日期）
- 逐列体检表（类型、缺失率、唯一值、异常值说明）
- 五维评级与整体评级
- 三条影响提示（问题 → 偏差方向 → 处理办法）
- 清洗留痕（做了什么处理、影响多少行）

## 异常处理

- **文件打不开或编码乱码**：先试 UTF-8，再试 GBK；都不行让用户导出一次标准 CSV。不猜内容。
- **空文件或只有表头**：直接判 D，不出任何数字。
- **列名含空格、特殊符号**：脚本会自动规整，报告里注一句"列名已规整"。
- **金额列混入「¥」「,」「万」**：脚本尝试清洗；清洗失败的样本贴出来给用户看，别静默丢弃。
- **行数超过脚本处理能力**（>50 万行）：先用表头抽样或让用户按时间切分，说明原因。

## 必要依赖

- `scripts/profile_table.py`
- `scripts/czl_core.py`（共享读取与统计，脚本内部调用，无需单独运行）

## 与其他工作流的关系

- **上游**：W1 产出任务书与口径账。
- **下游**：通过 → W3；判 D → 回 W1 与用户确认补数据或降级。
- **回流**：W5 反例验若发现"结论由异常值造成"，回本工序复核该列的异常处理是否恰当。
