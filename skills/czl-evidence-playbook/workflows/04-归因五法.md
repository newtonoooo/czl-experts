# W4 · 归因五法

## 职责

针对 W3 的假设，选择**一种**方法做归因。五种方法解决的问题不同，不能混着用，也不能用一种的结论去回答另一种问题。

选错方法比算错数更致命。

## 输入参数

| 参数 | 是否必需 | 说明 | 缺失时怎么办 |
|---|---|---|---|
| 假设清单 | 必需 | W3 产出 | 无 → 回 W3 |
| 目标指标与维度 | 必需 | 要拆的那个数 | 从任务书取 |
| 数量字段（可选） | 视方法 | 分解法需要量，如订单数 | 只有金额时，做"价×量"退化处理并注明 |
| 分组标识 | 视方法 | 渠道/地区/新老客/实验组 | 无分组 → 只能做整体分解 |

## 五种方法：什么时候用哪一个

| 方法 | 回答的问题 | 需要的条件 | 脚本 |
|---|---|---|---|
| **一 · 结构分解** | 总量变化里，多少来自量、多少来自价、多少来自结构 | 有金额与数量两列，或有分组的金额 | `period_compare.py` |
| **二 · 漏斗** | 转化链路里哪一步掉了 | 有序的步骤与对应人数 | `funnel_steps.py` |
| **三 · 同期群** | 留存变差是"新客质量差"还是"结构变了" | 主体ID + 时间，能按首次出现分组 | `cohort_retention.py` |
| **四 · 分群对比** | 整体结论在各组是否成立，是否出现方向相反 | 至少一个分组维度 | `segment_abc.py` + 手算 |
| **五 · 实验/准实验** | 改动是不是真的造成了变化 | 有对照组，或用断点/双重差分构造对照 | `ab_test.py` |

### 方法一 · 结构分解

1. 把总变化拆成三块：**量的变化 × 基期价**、**价的变化 × 基期量**、**结构和交互项**。
2. 逐组算贡献，按绝对值排序，取前 3 组讲，其余合并为"其他"。
3. 校验：各组贡献之和与总变化之差，应小于总变化的 1%，超过就说明漏了维度。

```bash
python period_compare.py 订单.csv --date 支付日期 --value 金额 --qty 件数 --period 2026-05:2026-06 --by 渠道
```

### 方法二 · 漏斗

1. 按业务真实顺序排步骤，不是按数据里出现顺序。
2. 算每步转化率与**环比跌幅**，找"跌幅明显大于相邻步"的那一步。
3. 换算成钱：这一步补齐到历史水平，能多带来多少单/多少钱。没有这一步，漏斗结论没有行动价值。

```bash
python funnel_steps.py 访问=10000,加购=3200,下单=1500,支付=980
```

### 方法三 · 同期群

1. 按首次出现时间分组（月或周）。
2. 算每组在后续第 N 期的留存率，形成矩阵。
3. 横向看：新群比老群差多少（质量变化）；纵向看：同一群随时间衰减是否异常（体验变化）。

```bash
python cohort_retention.py 用户事件.csv --user 用户ID --date 日期 --period month
```

### 方法四 · 分群对比

1. 对每个主要分组分别算指标变化。
2. 找"与整体方向相反"的组。找到就是辛普森悖论线索。
3. 判断该组的权重是否足以扭曲整体。权重够 → 结论要按组给，不能给整体。

```bash
python segment_abc.py 订单.csv --key 客户ID --value 金额
```

### 方法五 · 实验/准实验

1. 先确认对照是否可比（分流是否随机、样本是否同质、时间是否同期）。
2. 做检验：比例用两比例 z 检验，均值用 Welch t 检验；样本小或有偏时用 bootstrap 区间。
3. 报效应量与区间，不报"提升了 X%" 就完事——要报"提升了 X%，95% 区间 [a, b]"。
4. 若区间跨 0，结论是"没测出差异"，不是"没差异"。

```bash
python ab_test.py --control 512/10000 --treat 583/10000
python ab_test.py --control-file ab.csv --group 组别 --metric 是否转化
```

## 判断条件

| 判断点 | 条件 | 动作 |
|---|---|---|
| 有没有对照组 | 无 | 禁用方法五，改用同期基线并整篇降为 B 级 |
| 分组维度基数 | >50 组 | 先聚合，不做逐组检验（多重比较会制造假阳性） |
| 多组同时检验 | 检验次数 >5 | 报结果时说明未做多重比较校正，或改用更保守阈值 |
| 分解校验误差 | >1% | 补维度重算，不硬凑 |
| 漏斗步骤缺失 | 缺中间步 | 只报首末转化，说明缺失步 |

## 输出格式

每种方法产出一段固定结构：

```
方法：<名称>
输入：<文件/参数>
结果：<核心数字 3 行以内>
贡献排序：<前 3 项 + 其他>
局限：<这个方法测不到什么>
```

## 异常处理

- **分解项加起来不等于总变化**：说明维度没拆全或数据有重复，回 W2 查重复行。
- **漏斗某步人数反而上升**：通常是步骤定义有交叉（同一步重复计数），核查后再报。
- **同期群矩阵出现"越老留存越高"**：多半是数据回溯补录，标注后只用于组间比较，不做趋势。
- **实验组与对照组基线差异大**：不能直接比，改做分层对比或说明不可比，禁止硬下结论。
