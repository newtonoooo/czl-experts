# 能力接入（W3）

## 什么时候用

- 接登录、手机号、微信支付
- 接订阅消息、分享、小程序码、扫一扫、位置
- 提审因"收集用户信息未说明用途""强制授权"被拒
- 判断某个能力在 iOS 上能不能用

## 输入

| 输入 | 必需 | 说明 |
|---|---|---|
| 需要哪些能力 | 是 | 登录/支付/手机号/订阅消息/位置/分享/码 |
| 商户号与类目状态 | 支付必填 | 没有商户号只能写占位流程 |
| 后端形态 | 是 | 云开发 or 自建服务端（决定签名与回调写在哪） |

## 四道前置闸门（不过就别写代码）

1. **资质闸门**：支付要商户号 + 对应类目；直播、医疗、教育等要专项资质。缺了先补，代码写了也用不了。
2. **隐私闸门**：调任何采集类接口前，公众平台后台的「用户隐私保护指引」必须已配置且与实际采集项一一对应。
3. **域名闸门**：服务端域名要在后台配置白名单，且必须 https、已备案。
4. **iOS 闸门**：虚拟商品（会员、课程、虚拟币）在 iOS 端不能用微信支付。

## 步骤（按能力分四条线）

### 线 1：登录态

1. `wx.login` 拿 `code`（一次有效，5 分钟内用掉）。
2. `code` 送服务端，服务端调微信接口换 `openid` + `session_key`（**接口与参数以官方文档为准**）。
3. 服务端签发**自己的** token（含 openid、过期时间、必要的角色），前端只存 token。
4. 后续请求带 token，服务端校验；token 过期走静默续期。
5. 详见 `references/login-session.md`。

### 线 2：支付

1. 前端选好商品 → 请求服务端下单。
2. 服务端调统一下单，拿到 `prepay_id` 并**在服务端签名**。
3. 返回 `timeStamp / nonceStr / package / signType / paySign` 给前端。
4. 前端 `wx.requestPayment`。
5. 支付结果以**服务端收到的支付回调**为准，前端 `success` 只用于跳转提示，不能作为发货依据。
6. 详见 `references/pay-flow.md`。

### 线 3：手机号与其它授权

1. 手机号：`button open-type="getPhoneNumber"`，用户点击后拿加密数据 → 送服务端解密或换号（方式以官方文档为准）。
2. 位置：先在 `app.json` 声明 `requiredPrivateInfos` 与 `permission.scope.userLocation`，再调接口。
3. 图片/相册：`wx.chooseMedia` 这类接口属于采集，要在隐私指引里说明用途。
4. 所有授权都要有**拒绝分支**：拒绝后功能降级但不能让整个小程序不可用。

### 线 4：订阅消息与分享

1. 订阅消息：模板先在后台申请，前端在用户动作后调用 `wx.requestSubscribeMessage`，**一次授权对应一次下发**，不能反复弹。
2. 分享：`onShareAppMessage` 提供内容，分享按钮用 `button open-type="share"`。
3. **红线**：不得把分享作为功能前置条件，不得"分享得奖励"，不得强制关注。

## 判断条件

| 情况 | 动作 |
|---|---|
| 签名/密钥出现在前端代码 | 停，立即改服务端并轮换密钥 |
| `session_key` 下发到前端 | 停，这是登录态可伪造的根源 |
| iOS + 虚拟商品 + 微信支付 | 停，改方案 |
| 未配置隐私指引就调采集接口 | 停，先配 |
| 授权被拒后主流程不可用 | 改，必须有降级路径 |

## 输出

1. 前端调用代码（含拒绝分支）
2. 服务端/云函数代码（含签名、校验、幂等）
3. 配置清单：后台要开什么、`app.json` 要声明什么、域名要配什么
4. 官方文档路径（支付→微信支付商户平台文档；登录→小程序「登录态」文档；隐私→「用户隐私保护指引」文档）
5. 合规提示（主动给，不等用户问）

## 异常处理

| 异常 | 处理 |
|---|---|
| 无商户号 | 用沙箱或占位参数写完整链路，台账记"支付未开通" |
| 支付回调收不到 | 先查域名可达性与证书，再查是否配了回调地址；不要用前端轮询替代回调 |
| 手机号解密失败 | 多半是 `session_key` 已过期，重新走登录再解密 |
| 审核因隐私被拒 | 转 W6，按驳回原文逐条对照隐私指引与代码采集点 |
