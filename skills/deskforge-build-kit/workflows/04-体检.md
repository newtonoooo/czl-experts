# 工序 ④ 体检

## 名称

体检（Factory Inspection）——出厂前的量具检查，不许靠"看起来没问题"。

## 任务职责

用两个脚本 + 四项人工走查，证明这个文件真的能开、能用、不丢数据。产出《出厂单》，附脚本原始输出。

## 输入参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `file` | 是 | 待检的 `.html` 文件路径 |
| `prefix` | 是 | 存储键前缀，默认 `czl_desk_` |
| `strict` | 否 | 严格模式：warning 也算不通过（默认关闭） |
| `env` | 否 | 运行环境是否有 Python；无则走人工清单兜底 |

## 执行步骤

```
1  跑合规体检
     python scripts/blueprint_lint.py --file 台子.html --prefix czl_desk_
2  跑结构体检
     python scripts/dom_probe.py --file 台子.html
3  按输出逐条处理：error 必修；warning 修或写理由
4  人工走查四项（脚本查不出的）：
     ① 首屏非空：打开就看到内容，不是空白页
     ② 空数据不崩：清空数据后刷新，页面正常且提示清楚
     ③ 窄屏不横滚：375px 宽下没有横向滚动条，表格变卡片
     ④ 日期边界：月末最后一天加一天、年末最后一天加一天，都算对
5  修完重跑，直到 3、4 都干净
6  写《出厂单》：结论 + 两个脚本原始输出 + 人工四项结论 + 遗留 warning 理由
```

## 判断条件

**以下全部满足才算通过（G3 出厂闸）**

- [ ] `blueprint_lint.py` 退出码 0（或 1 且所有 warning 已解释）
- [ ] `dom_probe.py` 退出码 0（或 1 且所有 warning 已解释）
- [ ] 人工四项全部通过
- [ ] 交付文件能双击打开（不是靠本地服务器才显示）
- [ ] 导出 JSON 能重新导入（自己试一次）

任一项不过 → **不交付**，回工序 ③ 修。

## 异常处理

| 情况 | 处理 |
|---|---|
| 环境没有 Python | 转人工清单：按 `references/qc-checklist.md` 逐项手查，并在出厂单注明"未跑脚本检查" |
| 脚本报"文件不存在/编码错误" | 先确认路径与编码（统一 UTF-8），不要改脚本 |
| 脚本报的错确认是误判 | 在出厂单写明误判理由与位置，**不改阈值**；确实需要长期放宽的，改脚本时单独提版本 |
| 时间紧、用户催 | 明确告知"跳过体检的后果是手机端可能崩"，让他选；跳过要在交付里写清 |
| 体检在旧台子上跑（用户自带文件） | 只出体检结论与修复建议，不动原文件；用户要修再走 ③ |
