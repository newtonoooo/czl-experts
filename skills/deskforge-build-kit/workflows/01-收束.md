# 工序 ① 收束

## 名称

收束（Scope Compression）——把一句口语需求压成可以动手的尺寸。

## 任务职责

把"我想记一下每天的学习情况"这类模糊需求，转成**模块表 + 字段草案**，并且把规模压到 4 块以内。产出物是《收束卡》，它是后面所有工作的尺寸依据。

## 输入参数

| 参数 | 必需 | 说明 | 缺省处理 |
|---|---|---|---|
| `need` | 是 | 用户的一句话需求 | 没有就开口问，见"异常处理" |
| `user` | 建议 | 谁用（本人 / 孩子 / 老人 / 家里人共用） | 默认"本人"，标假设 |
| `device` | 建议 | 主要在手机还是电脑用 | 默认"两者都要"，按双端设计 |
| `fields` | 可选 | 用户自己列的要记的项 | 按同类场景的常规字段补全 |
| `style` | 可选 | 配色、页面名 | 用默认色板与默认名 |

## 执行步骤

```
1  判场景：从需求里抽出「记什么对象 + 多久一次 + 要看出什么」
2  列候选块：不设上限地先列 5–8 个可能的块（这一步不砍，砍了会漏）
3  三问过筛：对每个候选块问
     ① 往里填什么？
     ② 一眼看到什么？
     ③ 据此判断什么？
   三问有两问答不出 → 降级为展示块或砍掉
4  压规模：留 3–4 块。留的标准是「不做这块，台子还能用吗」
5  配卡片：每块指定主卡与辅卡（list / matrix / form / metric / time）
6  配字段：给每块列 3–8 个字段草案（正式定义留到工序 ②）
7  定顶栏：“今天要处理”由哪几块供料（逾期项、今日项、临期项）
8  写假设：把推断的部分列成一行一条
9  出卡：落盘《收束卡》，模块超过 4 个直接拒绝并改出分期表
```

## 判断条件

**必须全部为"是"，否则不许进入工序 ②**

- [ ] 模块数 ≤4
- [ ] 每一块都能填满"我在__填__，看到__，据此判断__"
- [ ] 每一块都指定了主卡原语，且没有出现第六种卡
- [ ] `form` 卡都有对应的 `list` 卡承接（填进去的东西有人看）
- [ ] 所有 `metric` 卡都写清了口径（求和 / 计数 / 近 N 天均值）
- [ ] 顶栏"今天要处理"的供料来源明确
- [ ] "本次假设"已列出

## 输出格式

```markdown
# 收束卡 · {台子名} · {日期}

**一句话**：给{谁}用的{什么}台，解决"{原话}"。
**本次假设**：（推断项，逐条一行）

## 一、模块表（{n} 块）

| # | 模块名 | 主卡 | 辅卡 | 填什么 | 看到什么 | 据此判断什么 |
|---|---|---|---|---|---|---|
| 1 | 今日待办 | list | — | 任务、截止日 | 今天/逾期两条泳道 | 先做哪一件 |
| 2 | … | | | | | |

## 二、顶栏「今天要处理」
供料：{模块 1 的逾期项} + {模块 3 的临期项}
规则：逾期标红、昨天未完成自动滚到今天、每条一个"完成"按钮。

## 三、字段草案
- 模块 1：`title` 文本、`due` 日期、`done` 布尔
- 模块 2：……

## 四、明确不做
（本期砍掉的块 + 一句话原因）

## 五、分期表（仅当原始需求 >4 块时出现）
| 期次 | 内容 | 为什么放这一期 |
|---|---|---|
| 本期 | 模块 1/2/3 | 缺了台子不成立 |
| 下期 | 模块 4 | 锦上添花，等本期用顺了再加 |
```

## 异常处理

| 情况 | 处理 |
|---|---|
| 用户只说"做一个工作台" | 最多问 2 个问题，且必须带候选：①给谁用？(自己/孩子/家人共用) ②最想记哪一类？(待办/打卡/收支/进度)。问完直接给一版收束卡 |
| 需求里含账号、协作、推送 | 说明超出范围，并给替代：账号→不需要；协作→导出 JSON 互相发；推送→首屏"今天要处理"代替 |
| 模块数 >4 | 不硬塞，出分期表；本期只做最不能缺的 3 块 |
| 用户要求"先做出来看看" | 可以，但收束卡照出（可只写模块表），并标"未收束，后续可能返工" |
| 同一需求有两种合理解读 | 两个解读都列在假设里，选更省事的一个先做，让用户一句话改 |

## 必要依赖

- `scripts/spec_card.py`（生成与校验，模块 >4 会拒绝）
- `references/card-primitives.md`（选卡与参数）

## 与其他工作流的关系

- **上游**：无（入口工序）
- **下游**：`02-建模.md`，把字段草案细化成数据账
- **回流**：工序 ③ 装配中发现某块做不到，回到本工序重压，不在装配阶段临时加块
