# 受众渲染：同一件事，四种说法

## 核心原则

**事实不变，密度和入口变。**

给高管的一页纸和给工程的详细说明，内容必须完全一致。变的是：
- 从哪一句开始（入口）
- 留多少证据（密度）
- 用什么词（术语层级）

**如果两个版本的说法互相矛盾，这不是渲染，是撒谎。** 检查方法：把两份材料并排看，"结论"那一段是否指向同一个动作。

## 五种受众

| 受众 | 他们真正想知道 | 长度 | 开头第一句 |
|---|---|---|---|
| 高管 | 要不要我做什么决定 | ≤300 字 | 结论或风险 |
| 工程 | 我要做什么、卡在哪 | 不限，结构化 | 变更或阻塞 |
| 跨部门 | 我要准备什么 | ≤200 字 | 对他们有影响的事 |
| 客户 | 我能多做什么 | ≤150 字 | 新增的能力 |
| 董事会/投资人 | 数字和风险 | ≤200 字 | 一个指标 + 一个风险 |

### 高管版

```
状态：黄
结论：批量导出能按 8 人周做完，但要砍掉筛选优化。
需要你定：是否接受筛选优化延后一个季度。
依据：3 条工单（B）+ 导出接口日均 412 次（A）。
风险：使用率可能低于 8%，止损点在上线第 30 天。
下一步：本周内给排期，9/30 出可用版本。
```

六行。**"需要你定"这一行必须有，否则这封更新没有意义。**

### 工程版

```
变更：
- 导出改为异步任务（原因：6000 条记录同步超时）
- 字段白名单从 12 个减到 9 个（法务要求，不可商量）

阻塞：
- 等待权限服务提供批量鉴权接口，承诺 9/22

待定（我还没想清楚，需要你判断）：
- 部分记录失败时，是整体回滚还是给失败清单
- 我的倾向：给失败清单，理由是重跑成本高

验收：AC-01 ~ AC-08，异常路径占 4 条，见规格书第 7 节
```

工程版最有价值的是"我还没想清楚"那一段。**假装什么都想清楚了，会在开发到一半以返工的形式还回来。**

### 跨部门版

```
对你们有影响的两件事：
1. 9/30 上线批量导出 —— 客服需要更新 FAQ（第 3 节），销售可以拿去谈续约
2. 筛选优化延后 —— 之前答应客户 B 的时间要改，需要销售先沟通

需要你们做：9/25 前给我 FAQ 初稿，我来补技术细节
```

### 客户版

```
现在可以批量导出了。
不用再逐条复制，选中时间范围后一次导出，完成后会收到通知。
单次最多 5000 条，超过会自动分批，7 天内可重复下载。
已知问题：暂不支持自定义字段，预计下个版本。
```

客户版不出现：内部代号、人周、验收标准、"优化调整"这类空话。

## 状态色纪律

| 色 | 定义 | 什么时候用 |
|---|---|---|
| 绿 | 按计划推进，无未缓解风险 | 真的顺利时，不是默认值 |
| 黄 | 有风险但已在处理，结果不确定 | **第一次看到风险信号就用** |
| 红 | 已落后，靠团队自己解决不了，需要决策 | 需要别人给资源或给决定时 |

三条硬规则：

1. **黄不是失败，黄是尽责。** 一直报绿的团队，最后一定报一次红，而且那次红会没人信。
2. **升级要有触发条件，不能靠感觉。** 例：关键路径延迟 ≥3 个工作日 → 黄；≥7 个工作日或影响对外承诺 → 红。
3. **降级要说原因。** "风险已解除，因为权限接口 9/20 提前交付"——不写原因就降级，等于把黄当装饰。

## 坏消息怎么说

顺序固定，不许调整：

1. **坏消息本身**（第一句，不加铺垫）
2. **影响范围**（谁受影响、多严重、有没有替代）
3. **已经做了什么**（不是"正在积极处理"）
4. **需要什么**（具体的人、决定、时间）
5. **什么时候再同步**

例：

> 批量导出赶不上 9/30，会延到 10/15。影响：已经答应客户 A 的销售需要重新沟通，其余客户无承诺。已做：把异步任务拆出来单独上线，9/30 能提供人工导出兜底。需要：你批准 9/30 先上兜底方案。10/8 再同步一次。

**禁止的五种写法**：

| 写法 | 问题 |
|---|---|
| "由于一些原因……" | 不说是哪些原因，等于没说 |
| "正在积极推进中" | 没有信息量，读者会认为你在掩盖 |
| "影响不大" | 由你判断影响大小，读者不会接受 |
| "争取在……之前完成" | 没有承诺，读者无法据此安排 |
| 先讲三条好消息再讲坏消息 | 读者会觉得你在稀释，信任度下降更快 |

## 索取要写成动作

| 愿望 | 动作 |
|---|---|
| 希望得到支持 | 需要你在 9/26 前批准 2 人支援两周 |
| 请领导关注 | 需要你在周会上明确这个需求排在下季度第一位 |
| 需要资源 | 需要 1 名后端，10 月起，最少 6 周 |
| 请尽快确认 | 需要你今天下班前回复 A 或 B |

**"支持""关注""重视"不是请求，是客套。** 客套在跨部门沟通里会被自动忽略。

## 决策记录（一页版）

重要决定留一页，半年后能看懂：

```
决定：批量导出采用异步任务，不做同步下载。
日期：2026-09-18     参与：产品、后端、测试
背景：6000 条记录同步导出超时率 23%，无法满足可用性要求。
考虑过的方案：同步加分页（改造成本 5 人周，仍未解决大客户场景）/ 异步（8 人周）/ 不做（工单持续上升）。
选择理由：异步在小数据量下体验损失可接受，大数据量下唯一可行。
代价：交互复杂度上升，需要通知机制。
什么情况下重议：若异步任务完成时长中位数超过 3 分钟。
```

最后一行是关键。**没有重议条件的决策，会变成没人敢碰的既成事实。**

## 长度纪律

- 高管：一屏内，超过就是没想清楚
- 客户：三段以内
- 董事会：一页，数字不超过 6 个
- 工程：不设上限，但必须有小标题，能跳读

**"内容太多放不下"通常意味着"还没决定讲哪件事"。** 先定那件事，再删其他。

## 异常

| 情况 | 处理 |
|---|---|
| 用户要求"写得积极一点" | 可以调语气，不能改事实和状态色。可以提供两版：事实版和语气缓和版，让用户自己选 |
| 用户要求"别提风险" | 拒绝。可以改成"风险已识别并有应对"，但不能不提 |
| 同一份材料要发给多个受众 | 拆成多份。合并版一定谁都不满意 |
| 用户不知道受众是谁 | 先问清是"要资源的人"还是"被影响的人"，两类写法完全不同 |
| 涉及对外承诺时间 | 一律给范围不给日期（"10 月中旬"），除非已确定 |
