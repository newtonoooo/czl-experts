# 取数适配层：能力 → 工具映射

本技能不绑定任何一家数据源。下面以通达信类 MCP 工具为例给出映射。
换数据源时只改这张表，评分与报告都不用动。

## 一、映射表

| 证据块 | 需要的数据 | 通达信类工具 | 备注 |
|---|---|---|---|
| 估值 | PE/PB/PS/股息率/历史分位 | `tdx_indicator_select` | 一次多指标多标的查询 |
| 财务报表 | 利润表、资产负债表、现金流量表 | `tdx_api_data` | 取 8 个季度可得同比与 TTM |
| 技术面 | 日/周 K 线 OHLCV | `tdx_kline` | 建议 250 根以上、前复权 |
| 行情盘口 | 现价、涨跌幅、换手、量比 | `tdx_quotes` | 盘中诊断必须带时间戳 |
| 资金 | 主力净流入、资金流向排序 | `tdx_screener` | 自然语言条件查询 |
| 事件 | 个股资讯 | `wenda_news_query` | 需要人工判定"正面/负面" |
| 公告 | 业绩预告、增减持、质押、重组 | `wenda_notice_query` | 优先取公告原文日期 |

## 二、调用顺序建议

1. **先 `tdx_quotes` 定时间戳**：所有数据都要能对齐到同一个"数据截止时刻"，否则技术与财务的时间错位会让结论自相矛盾。
2. **再 `tdx_kline`**：K 线是本地复算指标的输入，先拿到再谈技术面。
3. **然后 `tdx_indicator_select` + `tdx_api_data`**：估值与财务，注意报告期。
4. **最后 `tdx_screener` + 资讯/公告**：资金与事件属于短期因素，放最后，避免先入为主。

## 三、失败与降级

| 情况 | 处理 |
|---|---|
| 工具未授权 / 未连接 | 直接告知用户"取数通道不可用"，给出需要人工提供的字段清单（见 `templates/intake_form.md`），不要用记忆数据代替 |
| 返回空数组 | 视为"未取到"，在报告数据体检里记为 0 覆盖，不重试超过 1 次 |
| 字段名不一致 | 用 `check` 的 warnings 定位，按 `examples/sample_input.json` 的键名重排 |
| 只有不复权数据 | 可以算，但必须声明；除权日附近的技术结论标注"受除权影响" |
| 财务只有年报 | 用年报 TTM 近似并声明；不要拿年报同比当季度同比 |

## 四、不要做的事

- 不要把工具返回的原始 JSON 直接塞给用户当报告。
- 不要混用两个数据源的 PE 与 EPS（乘出来的数不成立）。
- 不要在盘中给出"今日主力净流入"却标成"20 日"。
- 不要为了凑满六维，把资讯标题当"事件"填进评分。
