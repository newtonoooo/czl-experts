# 五种骨架模式

> 选一种，用到底。混用会得到一篇"什么都有个开头"的稿子。

## 怎么选

先问一句：**这篇的证据主要是什么？**

| 证据来源 | 用哪个模式 |
|---|---|
| 我在现场看到的 | 现场递进 |
| 我看到的规律/判断 | 判断 + 三证 |
| 我自己做对/做错过的流程 | 流程拆解 |
| 两种做法我都见过 | 对比双轨 |
| 时间上发生了变化 | 时间线 |

---

## 模式一：现场递进

**适合**：观察、访谈、亲历。**不适合**：纯观点（会显得像流水账）。

```
01 场面：一个具体时刻，有人在做一件事
02 反常：这件事里有一处不合常理
03 追因：为什么？给出一个此前没想到的解释
04 另一面：有没有人不这么做，做成了什么样
05 收在一个动作：一个可以被验证的细节，不下结论
```

**承重要点**：第 2 个节点的"反常"必须是读者也能感到奇怪的，不能只有作者觉得奇怪。第 5 个节点禁止升华。

**常见失败**：第 3 个节点开始议论，一直议论到结尾，前两段白写了。

---

## 模式二：判断 + 三证

**适合**：观点文、评论文。**不适合**：需要手把手教方法的题。

```
01 判断：把结论放在最前面，一句话
02 证据一：可核对的事实
03 证据二：可核对的另一类事实（不同来源）
04 反例：什么情况下这个判断不成立
05 适用边界：谁能用、谁别用
```

**承重要点**：第 4 个节点的反例是这篇文章的可信度来源。没有反例的观点文，读者只信一半。

**常见失败**：三个证据其实是同一个证据换三种说法。

---

## 模式三：流程拆解

**适合**：方法、攻略、避坑。**不适合**：争议话题。

```
01 大家通常怎么做（并指出问题）
02 为什么这么做会失败（给出机制，不是态度）
03 换个做法（核心方法，一句话说得清）
04 具体步骤（3—5 步，每步可执行）
05 常见卡点（做到第几步会卡，怎么过）
```

**承重要点**：第 3 个节点必须能用一句话说清，说不清就是方法还没想明白。

**常见失败**：步骤写成"注意这几点""要重视"，这类不是步骤，是口号。

---

## 模式四：对比双轨

**适合**：选择困难类（要不要住校、补不补课、报不报班）。**不适合**：只有一个正确答案的题。

```
01 A 做法：谁在用，怎么用，效果如何
02 B 做法：同上，篇幅相当
03 分水岭：什么条件下 A 对，什么条件下 B 对
04 你属于哪种：给 2—3 条自测标准
05 试错成本：选错了要付什么代价，能不能退
```

**承重要点**：A 和 B 的篇幅必须相当。一边写得细一边写得糙，读者立刻知道你在推荐哪个（如果确实推荐，直接说，别装中立）。

**常见失败**：假装两方中立，最后一段突然全盘倒向一方。

---

## 模式五：时间线

**适合**：事件复盘、政策变化、行业变迁。**不适合**：常销类工具文。

```
01 起点：最早的那个状态（具体年份或时刻）
02 转折：什么变了，谁推动的
03 当下：现在是什么状态，和读者有什么关系
04 三种走向：可能往哪走，各自的信号是什么
05 现在该做什么：一个不依赖预测的动作
```

**承重要点**：第 4 个节点必须写"信号"，不写"预测"。写"如果看到 X 就说明往 Y 走了"，读者能自己验证。

**常见失败**：把时间线写成大事记，读者看完不知道跟自己有什么关系。

---

## 骨架自检四问

写完骨架，问自己四个问题，有一个答不上就改：

1. 第 2 个节点如果删掉，读者会损失什么？
2. 任意两个节点能不能互换位置而阅读不受影响？能，说明有一个是多余的。
3. 每个节点的"读者得到"，换到别的话题里还成立吗？成立就是空话。
4. 最后一个节点是在给动作/场面，还是在给总结？给总结就换掉。
