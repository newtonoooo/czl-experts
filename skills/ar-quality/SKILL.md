# 交付闸门

一份稿子的价值，取决于它最弱的那一段。这个流程的作用是**在用户看到之前找到那一段**。

## 职责

**做**：10 项检查、出问题清单、给修复建议、判定放行或打回。
**不做**：不重写文章（回 `ar-thesis`）、不补数据（回 `ar-evidence`）。

## 输入参数

| 参数 | 必填 | 说明 |
|---|---|---|
| 待检文件 | 是 | HTML 或 MD 路径 |
| 证据台账 | 是 | 用于核对数字出处 |
| 稿型 | 是 | 内部 / 对外（对外要求更严） |

## 十项检查

### 机器检查（`scripts/archeck.py` 自动跑）

**A1 · 禁用词**
扫"保证收益/稳赚/必涨/包赚/无风险/翻倍/买入建议/满仓/抄底/清仓"等。命中即打回。

**A2 · 免责声明**
末尾必须含固定文本。缺 → 打回。

**A3 · 七段完整性**
结论/证据/分歧/定价/情景/风险/来源，缺任意一段且无"不适用"说明 → 打回。

**A4 · 数字出处**
正文中每个带小数、带单位或 4 位以上的数值，须能匹配证据台账中的条目。匹配率 <75%（可用 `--threshold` 调整）→ 打回。**派生数字（区间上下限、增速、占比）也必须以 `estimated` 条目登记进台账**，否则会被算作无出处。

**A5 · 时间戳一致性**
报告中出现的"最新/今日/当前"须与实际数据日期一致；出现未来日期或跨年错误 → 打回。

**A6 · 涨跌停合规**
文中任何价格不得超出按板块幅度算出的涨跌停区间；越界 → 说明数据或结论有误，打回。

**A7 · 北向口径**
出现"今日北向净流入/净买入" → 打回（2024 年 8 月起无实时数据）。

### 人工检查（必须逐项过，不能跳）

**B1 · 结论可证伪**
第一段的判断，是否附了"什么情况下这句话算错"。没有 → 补。

**B2 · 分歧不是稻草人**
第三段的反方观点，是不是对方最强的版本。如果反驳的是一个弱化版的对手 → 重写。

**B3 · 定价假设可复算**
第四段的每个假设是否可被第三方代入复算。藏了隐含假设 → 补。

**B4 · 抽样复核三个数字**
随机抽 3 个关键数字，回台账核对。有 1 个对不上 → 全篇重核。

## 判定规则

| 结果 | 条件 | 动作 |
|---|---|---|
| 放行 | A 全过 + B 全过 | 交付，附一句"已过 10 项检查" |
| 有条件放行 | A 全过，B 有 1 项轻微（措辞类） | 交付但注明待改项 |
| 打回 | 任一 A 项失败，或 B 有实质项失败 | 不交付，列问题清单回 `ar-thesis` |

**打回时不解释"为什么严格要求"，直接给问题与改法。** 用户要的是能发的稿子，不是合规课。

## 输出

```markdown
## 闸门结果：打回 / 放行
| 项 | 结果 | 问题 | 改法 |
|---|---|---|---|
| A1 禁用词 | ✗ | 第 3 段出现"必然突破" | 改为"在 X 假设下，区间上限为 Y" |
| A4 数字出处 | ✗ | "毛利率 42%" 无对应台账条目 | 补来源或删除 |
...

## 必须改（阻塞）
1. …

## 建议改（不阻塞）
1. …
```

## 异常处理

- 文件不存在或为空 → 直接报错，不猜内容。
- 台账缺失 → 只跑 A1/A2/A3/A5/A7，明确说明"无台账，A4/A6 未执行"，不得标"全部通过"。
- 脚本报错 → 说明哪一项无法自动校验，转人工，并在报告中注明该项未机器验证。

## 依赖

- `scripts/archeck.py`（7 项机器检查）
- `references/checklist.md`（人工检查细则）
- `rules/ar-delivery-standard.md`（合规红线原文）

## 与其他工作流的关系

- 上游：`ar-thesis`（或任何产出稿件的流程）
- 下游：用户
- 回退：打回时回到 `ar-thesis` 或 `ar-evidence`，改完必须**重跑全部 10 项**，不允许只跑改动的那一项
