# 交付：投稿包与改编

## 职责边界

把散落的稿子变成一份能直接递出去的材料。

**不做**：不代投、不代签、不承诺过稿。

## 输入

- 已入档的作品（`czl-continuity-keeper`）
- 各章体检报告
- 目标平台与投稿要求（用户提供，或联网查现行要求）

## 步骤

### 第 1 步：投稿前自检（先查再写简介）

按顺序跑，任何一项不过，先修再继续：

```bash
nproj.py status --dir .                                   # 写到哪、欠什么
lint_project.py --dir . --json qc/lint.json               # 结构是否干净
voice_scan.py chapters/ch-001.md --json qc/ch-001.report.json   # 样章体检
```

人工核对五项（脚本查不了）：

| 项 | 不合格的表现 |
|---|---|
| 开篇三章分工 | 第一章在铺设定、交代身世 |
| 主线一句话 | 说不清主角要干什么 |
| 伏笔 | 有空埋不收的 |
| 章末钩子 | 连续三章以上是感慨结尾 |
| 敏感内容 | 涉政、涉黄、涉未成年人不当内容 |

### 第 2 步：简介三版

同一个故事写三个方向，让用户选，不要一稿定死：

| 版本 | 写法 | 用在 |
|---|---|---|
| 处境版 | 第一句就是读者能对号入座的具体场景 | 免费流量平台 |
| 反差版 | 先给一个读者以为成立的前提，第二句打碎它 | 需要钩子的位置 |
| 悬念版 | 只给一个异常，不给解释 | 付费/试读转化位 |

**硬规则**
- 每版不超过 200 字。
- 不列设定、不列境界、不列人物关系。
- 最后一句不写"他将如何"，写他在做什么。

### 第 3 步：标签

5—8 个，分三类各取几个：题材、主角类型、情绪/关系。
不写平台已废弃的旧标签；不确定就联网查当前可用标签，查不到就说"以平台后台可选标签为准"。

### 第 4 步：样章

选第一章 + 一个高潮章（通常是首个大爽点所在章）。两章都要是**已过体检的正式稿**，不许拿草稿凑。

### 第 5 步：导出

```bash
nproj.py export --dir . 
nproj.py words --dir .
```

导出后在文件头写清：书名、作者、字数、章节数、版本号。字数用脚本实数，不自报。

### 第 6 步：短剧/短篇改编（用户要求时）

改编不是压缩，是换载体。三件事必须重做：

1. **场景化**：每 1—2 分钟一个可拍的场景，每个场景有地点、有人物、有一个动作目标。
2. **对白承担信息**：小说里靠叙述交代的，全改成对白或可见动作。
3. **钩子前置**：每集结尾必须有一个反转或悬念，位置固定在最后 15 秒。

输出格式见 `references/short-drama-outline.md`。

## 判断条件

| 情况 | 处理 |
|---|---|
| 自检有阻断项 | 不写简介，先修。说明拦在哪 |
| 用户要求"帮我写得能过审" | 只做合规检查与修改建议，不承诺结果 |
| 用户要求按某平台模板 | 要用户提供模板或联网查现行要求，不凭记忆套旧模板 |
| 用户要求代投 | 拒绝，给投稿材料清单 |
| 样章体检不过 | 换一章，或先改这一章 |

## 输出

```
export/<书名>-vN.md        全本
03-简介.md                 三版简介 + 标签 + 样章说明
04-改编纲要.md             短剧/短篇纲要（可选）
qc/preflight.md            自检结果（逐项打勾或写不过的原因）
```

## 异常处理

- **字数与目标差太多**：如实报数并给差额，不四舍五入成"约十万字"。
- **平台要求查不到**：写明"未核实，以平台当前公示为准"，不编造条款。
- **导出缺章**：文内留空并提示，不假装完整。

## 依赖

`czl-continuity-keeper` 的 `nproj.py`（导出与字数）、`lint_project.py`、`czl-voice-tune` 的 `voice_scan.py`。

## 与其他工作流的关系

上游：`czl-continuity-keeper`（干净档案）、`czl-voice-tune`（过的稿）。
下游：无（终点）。用户拿到材料自行投稿。
