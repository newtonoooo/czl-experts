# 合规矩阵（compliance-matrix）

政务项目的合规不是附录，是评分项。这个技能把三张最容易写空话的表变成可勾选的清单：

- 等保控制项对照（按级别过滤）
- 密评检查点（SM2/SM3/SM4 用在哪）
- 信创适配清单（型号 + 验证要点 + 优先级）

## 一、什么时候用

| 用户说的 | 用哪条命令 |
|---|---|
| "要做等保三级方案" | `dengbao --level 3` |
| "密评怎么响应" | `miping` |
| "信创适配怎么写" | `xinchuang` |
| "三张表一起给我" | `all --level 3` |
| "我要填的表格（Excel 里改）" | 加 `--format csv` |

## 二、入口

```bash
python <技能目录>/scripts/matrix.py dengbao --level 3 --out 等保矩阵.md
python <技能目录>/scripts/matrix.py miping --format csv --out 密评.csv
python <技能目录>/scripts/matrix.py all --level 3 --out 合规三表.md
```

## 三、三张表的用法

### 等保矩阵

每行：安全域 → 控制点 → 落地要求 → 常见产品 → 证据材料 → 状态 → 责任人。

用法不是"填完就行"，而是**逐行问一句：测评时对方要什么材料，我们现在有没有**。没有的那一行就是方案里必须补的设计，也是答辩时最容易被问穿的地方。

级别的差别体现在控制项数量：二级偏基础防护与制度，三级加通信传输加密、集中管控、集中审计、剩余信息保护、第三方运维管理，四级再加更严格的准入与审计要求。

### 密评检查表

八个层面：物理和环境、网络和通信、设备和计算、应用和数据、管理制度、人员管理、建设运行、应急处置。

核心是回答三个问题：
1. 哪些环节用了国密算法（SM2 签名/鉴别、SM3 完整性、SM4 加密）。
2. 密钥怎么管（生成、分发、轮换、销毁，谁管）。
3. 上线前有没有做商用密码应用安全性评估，问题整改闭环没有。

写方案时最常见的失分是把"支持国密"当结论。评委会追问用在哪、怎么验。

### 信创适配清单

按层次列：芯片、整机、OS、数据库、中间件、办公、终端、密码模块。

优先级口径：
- **P0**：投标前必须完成验证，否则技术分拿不到，或者直接不满足实质性要求。
- **P1**：可以在方案里承诺迁移计划，合同中约定时间。
- **P2**：可分期，先做兼容性声明。

营销话术里的"全面支持国产化"在这张表里会被打回原形——型号、版本、验证方式，一个都不能少。

## 四、输出格式

markdown 表格（默认）或 csv（便于在 Excel/WPS 里分工填写）。
`all` 会把三张表拼成一份文档，并在等保表后附一行分布统计，方便看哪一块控制点最密集。

## 五、异常处理

- 用户没说级别 → 按三级生成，并提示"三级是政务系统最常见的定级，若定级为二级请重跑 `--level 2`"。
- 用户要求"按标准原文逐条列" → 说明本表是工作提纲、按类别归纳并用自有表述，条文以 GB/T 22239 现行版本原文为准；需要逐条引用时建议直接对照标准文本，避免转述误差。
- 项目涉及涉密网络 → 提示分保与等保是两套体系，涉密部分不适用本表，需按涉密规定另行设计。
- 信创替代型号与实际采购目录不符 → 以采购时最新信创目录为准，本表型号仅作示例。

## 六、边界

本表用于售前方案编写与内部自查，不替代测评机构的测评结论，也不构成合规承诺。
方案里写"满足等保三级要求"之前，必须有对应的设计与证据链，否则就是给自己埋雷。
