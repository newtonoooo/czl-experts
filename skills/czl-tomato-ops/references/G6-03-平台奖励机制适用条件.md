# 平台奖励机制适用条件

> 闸门：第六道 · 变现闸　｜　模块编号：G6-03　｜　适用：想知道自己能拿哪些奖励、要满足什么条件时

## 一、这个模块解决什么

奖励的本质是“条件达标”，不是“写得多”。本模块给的是核对方法，不是具体金额——金额与档位变动频繁，必须回后台核对。

## 二、判断标准

奖励类收入通常挂钩以下四类条件（以官方当月公告为准）：

| 条件类型 | 核对什么 |
|---|---|
| 更新条件 | 日更/月更数量、断更次数、单章最低字数 |
| 质量条件 | 是否入选某类评选，评选口径由平台定义 |
| 周期条件 | 按月/按季核算，跨周期不叠加 |
| 资格条件 | 是否完成签约、是否满足完本要求 |

**纪律**：本产品不提供任何具体金额，不承诺任何奖励可达。

## 三、操作步骤

1. 打开作者后台的奖励说明页，逐条抄下当前条件；
2. 对自己现状逐条打勾；
3. 只针对“差一点就能达到”的条件做动作；
4. 记录核对日期——条件会变，三个月前的口径可能已失效。

## 四、输出模板

```
核对日期：<YYYY-MM-DD>
条件清单（来源：作者后台）：
- <条件1>：达标 / 未达标
- <条件2>：...
差距项：<...>
可执行动作：<...>
```

## 五、三个常见误判

- **用旧口径规划**：政策变动频繁，必须回后台核对当月版本。
- **为凑条件牺牲内容**：凑出来的更新会拖垮留存，得不偿失。
- **把一次性奖励当长期收入**：一次性就是一次性。

## 六、关联模块

奖励与留存冲突时，优先保留存（G3 优先于 G6）。
