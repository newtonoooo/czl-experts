# 单章信息增量核算

> 闸门：第三道 · 留存闸　｜　模块编号：G3-02　｜　适用：感觉“写了很多但什么都没发生”时

## 一、这个模块解决什么

核算一章结束时读者比开章时多知道了什么。增量太低，读者会产生“这章可以不看”的判断，这种判断一旦形成就会连着跳章。

## 二、判断标准

每章至少要有 **2 项**增量，且不能全部同类：

| 类型 | 例子 |
|---|---|
| 事实增量 | 知道了某人的真实身份 |
| 关系增量 | 两人的立场发生了位移 |
| 能力增量 | 主角获得或失去了一种手段 |
| 处境增量 | 处境变好或变坏，且不可逆 |
| 认知增量 | 读者对某件事的理解被推翻 |

**判定**：一章只有“情绪增量”（爽了一下、气了一下）没有其他四类，视为低增量章。

## 三、操作步骤

1. 用一句话写出本章开头的状态与结尾的状态；
2. 若两句话几乎一样，说明本章没有增量；
3. 标出本章的增量类型；
4. 低增量章：压缩合并，或补一个不可逆的小变化。

## 四、输出模板

```
第 <N> 章
开章状态：<...>
收章状态：<...>
增量类型：<事实/关系/能力/处境/认知>
增量数：<N>
判定：有效 / 低增量
处理：保留 / 压缩 / 合并
```

## 五、三个常见误判

- **把“打了一场”当增量**：打完状态没变，等于没发生。
- **增量全是能力**：只涨本事不变处境的章，读者会觉得在刷副本。
- **用信息量代替增量**：塞了很多设定，但没有一条改变处境。

## 六、关联模块

低增量章往往同时是低钩子章，配合 G3-01 一起改。
