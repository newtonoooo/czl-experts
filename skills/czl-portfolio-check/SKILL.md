# 组合体检

单看每一只都没问题，合起来可能是同一个赌注。这个模块的价值是**把"N 个持仓"还原成"几个真实的赌注"**。

## 职责

**做**：敞口归集、集中度告警、隐性相关性识别、压力情景、持仓去重。
**不做**：不做单票估值（引用各自结论），不做单票仓位推导（`czl-position-plan`）。

## 输入参数

| 参数 | 必填 | 说明 | 缺失处理 |
|---|---|---|---|
| 持仓清单（代码 + 占比） | 是 | 体检的基础 | 缺占比 → 先索取，不得用等权代填 |
| 成本价 | 建议 | 判断浮盈浮亏与处置效应 | 缺则只做敞口分析，不做盈亏分析 |
| 组合总规模 | 建议 | 换算绝对金额 | 缺则全部用比例表述 |
| 基准 | 否 | 判断主动暴露 | 默认用宽基指数 |
| 杠杆与衍生品 | 建议 | 影响真实敞口 | 缺则提示"未含杠杆调整" |

## 依赖与关系

- **上游**：各持仓的 `czl-model-value` / `czl-decision-memo` 结论
- **下游**：`czl-position-plan`（调整个别仓位）、`czl-thesis-log`（记录处置决定）
- **横向**：标注约定见 `czl-evidence-standard.md`

## 执行步骤

### 第一步：核对数据，先防重复计数

体检结论最容易错在数据，不在分析：

1. 缺占比、成本、规模 → 先索取，**不以典型配置代填**
2. 用户口径与历史记录冲突 → 以最新口径算，并回确认所用口径
3. **防重复计数**：确认基数是否已包含近期买入、分红、拆分；重算结果与上一版差异无法被行情解释时，先查来源
4. 按持仓自身口径估值：基金用净值，不用关联标的价格近似

### 第二步：敞口归集（四个维度）

不要看名称看实质。把每个持仓拆到四个维度上：

| 维度 | 拆到什么 | 为什么 |
|---|---|---|
| 行业 | 主营收入来源行业，不是注册行业 | 同一行业才算同一风险 |
| 风格因子 | 价值 / 成长 / 小盘 / 高质量 / 高波动 | 因子暴露决定同涨同跌 |
| 地域与币种 | 收入来源地 + 记账币种 | 汇率是隐性共同因子 |
| 久期敏感度 | 对利率的敏感程度（尤其含地产、公用、高估值成长） | 利率变动会同时打击多只 |

输出一张归集表，按维度列示占比，标出**超过单一维度 30% 的集中项**。

### 第三步：识别"其实是同一个赌注"

找三类隐性重复：

1. **产业链重复**：上游 + 下游同时持有，看似分散实则同一景气度
2. **客户/供应商重叠**：A 的大客户是 B
3. **同一政策/同一技术路线暴露**：同受一条监管或一个技术标准影响

每找出一组，给出合并后的真实敞口占比。这是体检最有价值的部分。

### 第四步：集中度与流动性

- 单票上限、前五大合计占比、单行业上限
- 逐票算"全部退出需几个交易日"，标出超过 10 天的
- 指出"看起来分散但流动性都在同一档"的情形——压力时期会同时卖不掉

### 第五步：压力情景

不追求精确，只求量级。选一个统一冲击，算组合总影响：

| 情景 | 假设 | 组合影响 |
|---|---|---|
| 市场整体下跌 20% | 按各票 Beta 传导 | — |
| 利率上行 100bp | 按久期敏感度传导 | — |
| 本币升值 5% | 按外币收入占比传导 | — |
| 行业监管收紧 | 按行业敞口集中度传导 | — |

四个情景不必都做，选与当前持仓最相关的两到三个。

### 第六步：给出处置顺序

按"风险贡献 ÷ 信心强度"排序，指出最该处理的三个，而不是给一长串清单。

## 判断条件

| 判据 | 处置 |
|---|---|
| 单维度集中度 > 30% | 标为告警，说明具体是哪一维 |
| 找出产业链/客户重叠 | 合并计算，重排集中度 |
| 某票退出需 > 10 交易日 | 标为流动性风险，建议优先处理 |
| 持仓数据与用户口述冲突 | 以文件/最新口径为准，回确认 |
| 含杠杆或衍生品 | 折算为等效敞口后再算，未折算要明示 |

## 输出格式

```
一、体检结论三句话   最集中的是什么 / 最隐蔽的重复是什么 / 最该先处理哪只
二、数据口径声明    组合规模、成本是否齐全、是否含杠杆
三、四维敞口归集表  行业 / 因子 / 地域币种 / 久期
四、重复赌注识别    分组列示，给合并后真实占比
五、集中度与流动性  告警项
六、压力情景        两到三个情景的组合影响
七、处置建议        按优先级列前三，每项写清"为什么是它"
```

## 异常处理

- **只有持仓名称没有占比**：先索取；拿不到则做定性归集（指出重复赌注与集中方向），明确标注"未做定量，因缺占比"。
- **持仓含无法分类的品种**（私募、结构化产品）：单列"无法归类敞口"，并说明其底层不明会导致敞口低估。
- **数据与历史对不上**：先查是否有分红、拆分、新增申购未登记，再出结论。
- **用户只想听"没问题吧"**：仍然要先说最集中的那一项。体检的价值在发现问题。

## 质量红线

- 不按持仓名称做分散度判断，必须按实质敞口
- 不做压力情景就下"风险可控"的结论，视为未完成
- 处置建议必须排序并说明理由，罗列清单不算建议
- 缺占比时不得用等权或典型配置代填
