# 工序 ① 立项

## 名称

立项（Intake）——把"我想出海"压成一张能开工的卡。

## 任务职责

在花任何时间算账之前，先确定四件事：卖什么、卖到哪、走哪个渠道、谁在卖。产出《立项卡》。
这道工序不产出建议，只产出**边界**。边界不清，后面五道工序全部作废。

## 输入参数

| 参数 | 必需 | 说明 |
|---|---|---|
| 产品一句话 | 是 | 是什么、什么材质、给谁用、大概什么规格 |
| 目标国家 | 是 | 具体国家，不接受"欧洲""东南亚" |
| 渠道 | 是 | 亚马逊 / TikTok Shop / Shopee / Lazada / Temu / 独立站 |
| 出厂价与 MOQ | 否 | 缺则标 `[待填]`，不阻断开工 |
| 现有资质 | 否 | 有哪些证书、商标、税号 |
| 预算上限 | 否 | 首批能压多少钱在货上 |
| 本次要回答的问题 | 是 | 一句话，例如"这个价能不能做" |

## 执行步骤

```
1  补齐三个"清不清"（见判断条件），缺哪个问哪个，一次最多问三个问题
2  把产品归入品类 id（electronics / toy / baby / beauty / food_contact /
   textile / home / outdoor / pet / auto / medical / general），
   命中多个就都记下（如"带电池的儿童玩具" = toy + electronics）
3  确定币种与汇率取数日：如果中国侧成本用人民币，记下汇率与日期
4  写立项卡：产品、市场、渠道、预算、资质、待答问题、品类、本次假设
5  向用户复述边界，确认后进入工序 ②
```

## 判断条件

**三个"清不清"，任一不清就停在这道门**

1. **成本口径清**：出厂价含税吗、含包装吗、MOQ 多少、头程按公斤还是按方。
2. **目的地清**：具体到国家。同时要确认是"卖到该国"还是"从该国发货"（后者涉及进口商身份）。
3. **卖家身份清**：有没有公司主体、目标国税号、进口商（IOR）是谁、有没有商标。

**另外两条硬判断**

- 品类命中 `medical` → 直接提示"周期 6–18 个月起，先确认是否值得"，不进入常规测算。
- 用户要同时进 ≥3 个国家 → 先做分期表（本期做哪个、下期哪个、为什么这么切），确认后再走。

## 输出格式

```markdown
# 立项卡 · {产品} · {YYYY-MM-DD}

- 产品：{一句话}
- 品类：{id}（{命中多个则并列}）
- 目标市场：{国家}
- 渠道：{平台}
- 出厂价 / MOQ：{值或 [待填]}
- 现有资质：{证书/商标/税号 或 无}
- 首批预算：{值或 [待填]}
- 本次要回答：{一句话}
- 本次假设：{汇率与日期、退货率、广告占比，缺的标 [待填]}
```

## 异常处理

| 情况 | 处理 |
|---|---|
| 用户拒不给成本口径 | 用区间算（低/中/高三档），并在结论首行写"成本为假设区间，结论仅用于判断量级" |
| 用户说"先去试试，别问那么多" | 只做工序 ③ 与 ④ 的最小版：算保本价 + 列阻断项，其余标"未做" |
| 产品属平台禁售/限售类 | 在立项卡第一行写"该类目在 {平台} 属限售，需先确认准入"，再决定是否继续 |
| 用户描述前后矛盾（如说卖德国又提美国税号） | 指出矛盾，请其选一个市场，不替其选 |

## 依赖与上下游

- **前置**：无（这是第一道）
- **后置**：工序 ②（选品）、工序 ③（成本）、工序 ④（合规）都读这张卡的品类与市场字段
- **回退**：任何工序发现品类判错（如实际含电池），回到本工序改品类后重跑下游
