# 工序 ④ 合规

## 名称

合规（Compliance Release）——品类 × 国别出三态放行单。

## 任务职责

在发货和上架之前，把"要办什么、谁去办、要多久、缺哪项不能卖"写成一张单子。产出《合规放行单》。
这道工序的产出不是建议，是**放行结论**：GO / CONDITIONAL / BLOCKED。

## 输入参数

| 参数 | 必需 | 说明 |
|---|---|---|
| 品类 id | 是 | 来自立项卡，命中多个就都传 |
| 目标国家 | 是 | 具体国家代码，可多个 |
| 已具备项 | 否 | 已有的证书/税号/责任人编号（对应规则里的 id） |
| 阻断项办理路径 | 否 | 有明确服务商与预计完成日时，可判 CONDITIONAL |

## 执行步骤

```
1  列品类与国别，确认是否命中多个品类（带电池的玩具 = toy + electronics）
2  跑脚本：
     python scripts/compliance_gate.py --category baby --market DE --market FR
3  把用户已有的资质对应到规则 id，用 --have 传入重跑：
     python scripts/compliance_gate.py --category baby --market DE --have EU-RP,EU-VAT
4  读三态清单：阻断级 / 条件级 / 提示级
5  按判断条件给总判定，写《合规放行单》
6  若为 BLOCKED：只输出补齐清单（每项找谁办、常见周期），不出上架方案
```

## 判断条件

| 状态 | 条件 | 允许的下一步 |
|---|---|---|
| `GO` | 无阻断项 | 进入工序 ⑤ 页面 |
| `CONDITIONAL` | 阻断项已有明确办理路径与日期 | 可并行做页面与备货，但必须设补齐截止日，到期未补齐即停售 |
| `BLOCKED` | 有阻断项且无办理路径 | 不给上架方案，只给补齐清单 |

**三条不许越的线**

1. **不许把"平台没查"当成合规。** 平台未核验 ≠ 合法，事后追责照样成立。
2. **不许给"先发一批试试"的绿灯。** 有阻断项时，这句话必须替换成"补齐后再发"。
3. **不许承诺周期。** 认证周期按常见区间给，且注明"不含排队与补测"。

## 输出格式

```markdown
# 合规放行单 · {产品} · {市场} · {YYYY-MM-DD}

总判定：**GO / CONDITIONAL / BLOCKED**

## 已具备
| 编号 | 项 | 证据 | 有效期 |

## 阻断级（{n} 项）
| 编号 | 要求 | 需备证据 | 谁办 | 常见周期 |

## 条件级（{n} 项）
（同上表头）

## 提示级（{n} 项）
（同上表头）

## 补齐路径
- 编号 → 找谁 → 需要什么材料 → 预计完成日

## 风险提示
{若不按本单执行，具体会遇到什么：下架、扣货、罚款、禁入}
```

## 异常处理

| 情况 | 处理 |
|---|---|
| 目标国不在规则库 | 明说"该国未收录"，给通用四问（税号、进口商、认证、语言标签），建议找当地服务商确认 |
| 用户提供"朋友说不用办" | 指出这是口头信息，不可作为放行依据；写明"以官方或持牌方书面口径为准" |
| 用户已有证书但不确定是否覆盖本品 | 标注"证书覆盖范围需与检测机构核对型号与标准版本"，不替你判定有效 |
| 产品同时命中 medical | 单独提示周期与费用量级，劝其先做可行性判断再投入 |
| 平台侧另有要求（如亚马逊合规文件上传） | 单独列一节"平台侧要求"，说明与国别法规是两道关 |

## 依赖与上下游

- **前置**：工序 ①（品类、国别、卖家身份）、工序 ③（净利率过线才值得付合规成本）
- **后置**：工序 ⑤（GO/CONDITIONAL 才做页面）、工序 ⑥（阻断项影响首批发货时间）
- **回退**：BLOCKED 且补齐成本高于预期利润 → 回工序 ① 换市场或换品

> 定位说明：本工序输出的是**作业清单**，不是法律意见。涉及税务申报、产品责任、专利有效性，一律建议转持牌专业人士。
