# 机会关 · 投标取舍

## 什么时候用

- 客户问"这个标要不要投""值不值得跟""能不能中"。
- 两个标撞期，需要排优先级、分配人手。
- 已经决定投了但心里没底，想复核一遍。

## 什么时候不用

- 已经决定投、且截止只剩两三天：直接进 `rfp-decode`，别在判断上耗时间。
- 只想算钱：用 `price-story`。

## 输入

| 维度 | 要什么 | 没有时怎么办 |
|---|---|---|
| 资格匹配 | 资质、业绩、人员是否满足门槛 | 按"缺什么"扣分，不按"有没有"扣分 |
| 客户基础 | 是否合作过、谁认识谁、有没有被引荐 | 不知道就填 2 分，并注明"信息不足" |
| 方案差异 | 有没有对手不容易复制的做法 | 只有形容词没有做法，按 2 分 |
| 交付风险 | 工期、现网复杂度、验收条件 | 风险越高分越低（反向项） |
| 商务空间 | 还能让多少价、付款条件能否接受 | 毛利已到底线则 1 分 |

## 怎么打分

0 分＝完全不成立，3 分＝勉强够用，5 分＝明显占优。经验权重：资格 25%、客户 15%、方案 25%、交付 20%、商务 15%。权重可以按行业调，但必须和为 1。

两个常见打错：把"交付风险"当成"我们能扛"来打高分（它是反向项）；把"商务空间"理解成"报价高低"（它指还有多少让价余地）。

## 命令

```bash
python scripts/gate_score.py samples/case.json --md 机会关.md
```

脚本会校验权重和是否为 1、分值是否在 0–5 之间，不合规直接报错。

## 判据

| 总分 | 结论 | 下一步 |
|---|---|---|
| ≥70 | 全力投 | 锁资源，进读标关 |
| 50–69 | 条件投 | 列出三项必须项（事项/责任人/期限），拿不到就退出 |
| <50 | 不投或改联合体 | 说明哪个维度拖垮分数、联合体能补哪块 |

## 输出

先一句话结论，再给表格，最后给必须项。不要只给分数不给理由——分数是给人做决定用的，不是给人看的。

## 异常处理

- **权重加起来不是 1**：脚本报错，先改权重，不要改判据。
- **只有一个人打分**：建议两人独立打，差异超过 1.5 分的维度单独讨论，别取平均了事。
- **客户暗示"已经内定"**：不要在书面材料里写"内定"，改写为"客户基础评分低、信息不对称"，并提示客户评估投入产出。
- **分数在 68–72 之间**：不要纠结小数，回到"必须项能不能拿到"这个更硬的问题上。

## 与其他技能的关系

通过 → `rfp-decode`；条件投 → 先补必须项再回来复评一次，复评仍低于 50 就退出；不投 → 把评分表存档，下次同类项目直接引用。
