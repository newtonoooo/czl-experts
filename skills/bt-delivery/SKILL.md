# WF-05 交付与复现

交付物有两层：给人看的（回复 + 报告），给机器复算的（三件套 + 脚本 + 数据指纹）。两层都要齐。

## 一、文件契约

| 文件 | 内容 | 字段 |
|---|---|---|
| `<prefix>_equity.csv` | 评估区间内逐日净值 | `date, value` |
| `<prefix>_trades.csv` | 已平仓记录 | `symbol, side, entry_date, exit_date, shares, entry_price, exit_price, pnl, pnl_pct, holding_days, exit_reason` |
| `<prefix>_summary.json` | 元信息 + 指标 | `meta{strategy_name, universe, market, start, end, initial_cash, final_value, cost_model, lot_size, t_plus_1, engine}` + `metrics{…}` + `warnings` + `rejects` |

- 直接写在工作目录，不建子目录（除非用户指定）
- 事件研究没有净值三件套，改写成事件级 `trades.csv`（每行一个事件，`pnl_pct` 为核心字段）
- 数字保留两位小数即可，不要给 15 位有效数字

## 二、报告

```python
import btreport
payload = btreport.build_payload(res, "标题", "副标题", lang="zh",
                                 benchmark=bh, notes=notes)
btreport.render(payload, "out/index.html")
```

报告包含：KPI 六卡、净值曲线（含买入持有对照与成交标记）、回撤、单笔盈亏分布、月度热力表、成交明细、口径与说明、免责声明。

要点：
- `lang` 显式传 `"zh"` 或 `"en"`，跟随**用户最新提问的语言**，不跟随标的市场
- `notes` 至少写三块：成交口径、稳健性/成本压力、已知局限
- 事件研究用 `btreport.event_payload(...)`，成交表自动切换成"事件/买入日/卖出日/收益"列
- 生成后必跑 `node tools/check_report.js out/index.html`
- 交付时把**绝对路径**给用户

## 三、六段式回复（必须按这个骨架，不许写成文件清单）

```
【一句话结论】
这段历史里，策略累计 X%，同期买入持有 Y%，夏普 Z，最大回撤 -W%（日期）。
（先给结论，不给铺垫）

【口径】
标的 / 区间 / 信号 / 成交 / 仓位 / 费用 / 基准，一屏内读完，不要列表格超过 8 行。

【执行细节】
- 信号用哪个字段算（收盘/最高/成交量）
- 次日开盘成交还是当日收盘（如果不合规要说明用户的选择）
- 止损用收盘确认还是盘中近似
- 仓位怎么取整、留多少现金
- 样本末是否强平，末笔是否为强平记录

【结果】
挑 3—5 个最有信息量的角度，每个带数字：
- 收益归因：赚在几笔大单还是高频小胜
- 回撤：最深的一段发生在什么行情里，止损有没有起作用
- 频率：买入 X 次、卖出 Y 次、平均持有 Z 天
- 分段：哪一年最好/最差
- 稳健性：参数扫描 N 组里几组为正，成本翻 4 倍后收益变化多少

【局限】
只写这次最要紧的 2—3 条，不要抄教科书。

【复现】
脚本名、数据指纹、运行命令；报告路径。
```

**不要写**："已生成 xx 个文件""报告包含以下模块""如需进一步分析请告诉我"这类填充句。

## 四、语言跟随（硬规则）

| 用户提问 | 回复 | 报告 | 标的名 |
|---|---|---|---|
| 中文 | 中文 | 中文 | 有中文名就用中文名 |
| 英文 | 英文 | 英文 | 用 ticker（`600519.SH` / `0700.HK`） |

常见翻车：报告是中文、回复切成英文；或者英文报告里出现"沪深300"。交付前对一遍。

## 五、复现清单（repro.md）

```markdown
# 复现清单

- 脚本：run_ma_510300.py
- 数据：data/bars_510300.csv（sha256:9f2c…，区间 2019-01-02 ~ 2024-12-31，1456 行）
- 内核：kit/btcore.py v1.0.0
- 命令：python run_ma_510300.py
- 口径：spec.json（见下）

```

指纹一致 = 同一份输入；不一致就别拿两次结果直接对比。

## 六、免责声明（每份交付都要有）

中文：

> ⚠️ 以上内容由 AI 基于公开信息与历史数据计算生成，仅供研究与复核参考，不构成任何投资建议或个股推荐。历史回测结果不代表未来表现，实盘还受流动性、冲击成本与交易规则变化影响。投资有风险，决策需谨慎。

英文：

> ⚠️ Generated by AI from public information and historical data for research and verification only. It does not constitute investment advice or any recommendation to buy or sell specific securities. Past backtest performance does not predict future returns. Investing carries risk.

报告页脚已内置同一段，回复结尾再写一次。

## 七、异常处理

| 情况 | 处理 |
|---|---|
| 报告图表空白 / KPI 显示 `—` | 不交付。查 payload 是否为空、`check_report.js` 报了什么，修完重出 |
| 用户只想要结论不要文件 | 仍然生成报告（一句话说明路径），回复按六段式精简到前三段 |
| 用户要"再换一组参数" | 口径卡不变，回 WF-03，重跑 + 重出报告，不要手工改数字 |
| 用户质疑结果 | 拿审计单回应，逐项给证据；不要重复解释同一句话 |
| 数据源中途不可用 | 明说哪一段缺失，交付已完成的区间，并把区间写在标题里 |

字段与载荷细节见 `references/report-contract.md`，回复模板见 `references/readout-template.md`。
