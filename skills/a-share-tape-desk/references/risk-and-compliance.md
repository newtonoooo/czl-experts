# 仓位算法与合规边界

## 一、仓位算法（先定亏多少，再定买多少）

```
每股风险   = 入场价 − 止损价
单笔预算   = 总资金 × 单笔风险比例（默认 1%）
按风险股数 = floor(单笔预算 / 每股风险 / 100) × 100
按仓位股数 = floor(总资金 × 仓位上限 / 入场价 / 100) × 100
实际股数   = min(两者)
触发止损亏损 = 实际股数 × 每股风险
```

止损优先顺序：
1. 用户指定止损价（最优先，尊重用户的结构判断）；
2. ATR 止损：`入场 − 2 × ATR14`（默认，适应个股波动）；
3. 都没有时按 −7% 兜底，并**在输出里明确写"这是兜底估值"**。

止盈：按 R 倍数给 1.5R / 2.5R / 4.0R 三档，提示分批减仓。
超出当日涨停价的档位会标注"需分日实现"。

### 股数为 0 时的处理（重要）

小资金买高价股经常算不出整手。这时候不能只说"买不了"，要给最小可行规模：

- `1手成本`、`1手触发止损的亏损`、`占总资金比例`；
- 若 1 手风险 ≤ 预算的 1.5 倍 → 说明"接受这一手超配"或"把止损收窄到 X 元以内"；
- 若远超预算 → 说明"这只票的波动对当前资金体量太大"，建议换标的或用更紧的结构性止损。

### 组合层面

所有持仓同时触发止损的总亏损超过总资金 6%，说明押在同一个逻辑上太重，需要分散到不同驱动因素。
（`atd/risk.py: portfolio_risk`）

## 二、合规红线（写进产品行为，不是免责套话）

**必须做**

1. 每份涉及价格判断的输出，结尾都要有："以上为公开数据与规则化计算的结果，不构成投资建议；据此操作风险自担。"
2. 数据时间、来源、数据性质（实时/定格/上一交易日）必须写在报告里。
3. 用概率与条件表述："若放量站稳 X，则……"，不写"必涨""稳赚""一定反弹"。
4. 提到具体标的时，说清判断依据，让用户能自己复核。
5. 用户问"该不该买"时，把问题拆成条件：什么价位、什么信号、什么仓位、亏多少离场。

**必须拒绝**

1. 承诺收益、保证本金、宣称"内部消息"。
2. 代客理财、代客下单、索要账户与资金密码。
3. 帮助操纵股价、拉抬、坐庄、"喊单群"话术。
4. 对 ST、退市整理期、次新股首日给出"重仓"建议。
5. 把本工具输出包装成"投资顾问服务"对外售卖（涉牌涉证）。

**表述替换表**

| 不要写 | 改写成 |
|---|---|
| 必涨 / 稳赚 / 抄底 | 若…则上行概率偏高；上行需满足…条件 |
| 目标价 XX 元 | 第一压力位 XX 元，需放量突破才有效 |
| 建议满仓 / 梭哈 | 该标的波动对应仓位上限 XX%，单笔亏损不超过 X% |
| 主力在吸筹 / 洗盘 | 看到的是成交额与换手的变化，资金意图无法证实 |
| 明天会反弹 | 明天是否反弹取决于…，现在只能确认… |

## 三、这套算法的边界

- **不含滑点、佣金、印花税、过户费**：短线高频交易要把这些成本折进盈亏比，否则胜率再高也亏。
- **A 股 T+1**：当日买入当日不能卖，止损只能次日执行；隔夜跳空会让"止损价"失效。
- **涨跌停不可成交**：涨停板买不到、跌停板卖不掉，脚本已用 `is_limit_up` / `is_limit_down` 标出。
- **ATR 止损是波动适配，不是结构**：跌破前低、跌破平台这类结构性止损，往往比 ATR 更有效，用户指定时优先采用。
- **仓位上限来自情绪温度**：它是市场环境的函数，不是这只票的函数；个股风险要另外打折。
