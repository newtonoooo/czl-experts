# 岗位定制（jd-tailor）

## 这个技能解决什么

投同一个岗位的人，简历最后会被放到一起比。比的不是谁更优秀，是**谁更像这个岗位要的人**。定制做的不是往里塞关键词，是让招聘方在三秒内认为"这人干过我们这摊事"。

关键词硬塞是能看出来的：技能栏里突然多出一串没在经历里出现过的词，招聘方一眼就知道是抄 JD。

## 什么时候用

- 用户贴了 JD（或岗位链接）
- 用户问"我匹配这个岗位吗""为什么没面试"
- 同一份简历要投不同方向的岗位，需要判断改哪几处
- 用户想转行，需要知道差距在哪、能不能靠改写弥补

## 执行步骤

### 第 1 步：把 JD 拆成四栏

不要逐句读 JD，按四栏归类。归类标准见 `references/jd-decode.md`。

| 栏 | 内容 | 用途 |
|---|---|---|
| 硬门槛 | 学历、年限、证书、语言、地点 | 不满足就别浪费简历，先确认是否可破 |
| 职责动作 | "负责 XX""搭建 XX""推动 XX" | 决定你简历里该出现哪类动作 |
| 工具与方法 | 具体工具、方法论、行业术语 | 决定用词和技能栏 |
| 隐性信号 | 反复出现的词、职级暗示、汇报关系 | 决定语气和重点 |

**隐性信号最容易被忽略，但最有用**：JD 里三次提到"跨部门"，说明这个岗位的真实难点是推不动人，不是技术；写"独立完成"反而减分。

### 第 2 步：跑脚本拿覆盖底表

```bash
python skills/jd-tailor/scripts/jd_match.py --jd <JD文件> --resume <简历文件>
```

脚本给：必备/加分术语清单、每项的覆盖状态（已覆盖／可迁移／缺失）、综合匹配度、硬门槛对照。

脚本的局限要跟用户讲清：**它只能发现"写了没写"，判断不了"写得够不够深"。** 一个词写进去了但只是提了一嘴，脚本会算"已覆盖"，实际面试撑不住。

### 第 3 步：三类缺口分开处理

| 状态 | 含义 | 处理 |
|---|---|---|
| 已覆盖 | 简历里明确写过 | 检查深度够不够，必要时把这条提前 |
| 可迁移 | 有相邻经验，只是用词不同 | 换成 JD 的说法，不改事实 |
| 缺失 | 真没有 | 不要硬塞。要么在面试里准备学习路径，要么这个岗位先不投 |

**"可迁移"是最有价值的一栏。** 用户做过的事常常比他自己以为的更接近岗位要求，只是用了行业内的另一种叫法。

### 第 4 步：调整顺序和配比

定制不只是改词，更是改**版面权重**：

- 与 JD 最相关的经历放最前，哪怕它不是最近的。
- 与 JD 无关的经历压到一行，或者删掉。
- 技能栏按 JD 的出现顺序排，不要按自己熟悉程度排。
- 自我评价如果留着，第一句就要对上岗位。

### 第 5 步：给匹配度结论和投递建议

结论用三档，不用百分数糊人：

- **够格**：必备项覆盖 ≥80%，硬门槛满足 → 直接投，指出 1-2 处可加强。
- **差一点**：必备项覆盖 50-80% → 可投，但要在求职信或面试里主动补差距。
- **不建议投**：硬门槛不满足，或必备项覆盖 <50% 且差距无法短期弥补。

## 判断条件

- **JD 是英文、简历是中文**：先确认投递语言。跨语言投递要么全英文，要么全中文，不能混。
- **JD 写得极简（三五行）**：告诉用户信息不足，让他补充岗位链接或招聘方沟通记录，不要凭空推断要求。
- **JD 里要求明显超出岗位常理**（专员岗要求 8 年经验）：指出来，可能是招聘方写错或岗位虚挂，建议先问 HR。
- **用户想"先投了再说"**：尊重，但要告诉他哪些缺口在面试里一定会被问，并给出应答思路。

## 输出格式

按 `templates/gap-matrix.md`：JD 四栏拆解 → 覆盖矩阵 → 三类缺口清单 → 改写建议（3-5 条）→ 投递建议。

## 异常处理

- 脚本读不到 JD（用户只贴了正文）：先落成临时文件再跑。
- JD 是图片或截图：请用户提供文字版；无法提供就人工拆解，并在报告里注明"未做脚本匹配"。
- 用户提供的 JD 与简历岗位方向完全不搭：直接说"这份简历投这个岗位，改写的边际收益很低"，并给出更匹配的方向建议。

## 依赖

- `scripts/jd_match.py`（Python 3.8+，仅标准库，内置约 60 类技能词表）
- `references/jd-decode.md`（四栏拆解方法）
- `templates/gap-matrix.md`
- `samples/jd-sample.md`（虚构样例，可用于演示与回归测试）

## 与其他技能的关系

上游 `resume-audit`（先确保简历本身没硬伤），修改动作落在 `resume-rewrite`（定制本质是局部重写），交付走 `resume-export`。**一份简历只对一个岗位方向定制**；同时投多个方向，就出多个版本，文件名带岗位后缀。
