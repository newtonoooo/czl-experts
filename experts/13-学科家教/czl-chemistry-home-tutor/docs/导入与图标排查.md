# 导入后小图标变成文字：原因与排查

> 现象：专家导入新环境后，列表和对话输入区里的小图标不见了，显示成一个字（或一个字母）。
> 结论先说：**这不是平台故障，是这个专家的头像没被正确解析。** 界面拿不到头像地址时，会回退显示名称首字，所以看起来像"成字了"。

## 一、平台是怎么取头像的（按实际运行逻辑）

1. 读取专家根目录下的清单：`.codebuddy-plugin/plugin.json`，找不到再找 `.workbuddy-plugin/plugin.json`。
2. 取清单里的 `avatar` 字段，按"专家根目录 + 相对路径"拼出绝对路径。
3. 依次判断，任何一步不过关，头像地址就是**空字符串**：
   - 字段为空；
   - 路径里带 `..`，或拼接后跳出了专家目录；
   - **文件不存在**；
   - **文件大于 5 MB**（5 242 880 字节，超过会记一条警告然后返回空）。
4. 通过后转成 `local-file:` 地址给前端。
5. 前端组件拿到空地址、或图片解码失败时，就渲染名称首字作为占位。

所以"图标变字"= 第 3 步里某一条没通过，或第 5 步解码失败。

## 二、按概率从高到低排查

| 顺序 | 原因 | 怎么确认 | 怎么修 |
|---|---|---|---|
| 1 | **头像根本没打进包**。导出/打包时只复制了 `plugin.json` 和 `agents/`，`avatars/` 被漏掉 | 打开 zip 看有没有 `avatars/expert.png` | 重新打包，确认包含 `avatars/` |
| 2 | **路径与文件名不一致**。清单写 `avatars/expert.png`，实际是 `avatars/expert.png.png`、`expert-1.png`、`Expert.PNG`（Linux/打包工具区分大小写） | 逐字符比对清单字段与真实文件名 | 改文件名或改字段，二者完全一致 |
| 3 | **头像超过 5 MB**。AI 直出的 2048×2048 PNG 很容易到 2—6 MB | `dir avatars` 看字节数 | 用 `bin/make_avatar.py` 压到 512×512、≤500 KB |
| 4 | **路径越界或写成绝对路径**。如 `C:\Users\...\expert.png`、`../avatars/expert.png` | 看清单的 `avatar` 值 | 改成相对路径 `avatars/expert.png` |
| 5 | **图片本身坏了**。传输被截断、改了扩展名（JPEG 存成 .png） | 用系统看图打开；或跑 `bin/check_package.py` | 重新导出，统一存成 8 位 RGB PNG |
| 6 | **没注册或装错市场**。手动解压到 `experts/` 而不是 `my-experts/`，或 `marketplace.json` 里没有这条记录 | 看 `my-experts/.codebuddy-plugin/marketplace.json` 有没有该 name | 用平台"导入专家"，或跑注册脚本 |

补充一条容易被忽略的：**换头像后没刷新**。平台按 `plugin.json` 的修改时间缓存专家数据，只替换图片文件、不动清单时，可能仍然读到旧记录。改完头像顺手把 `version` 加一位，或重启应用。

## 三、一条命令自查

```bash
python bin/check_package.py <专家目录>
```

它会逐项检查：清单位置、`avatar` 字段、路径是否越界、文件是否存在、是否超过 5 MB、PNG 是否可解码、尺寸是否 512×512、CRC 是否完整、`agents`/`skills` 引用是否有效、是否已写进 `marketplace.json`。

输出示例（头像缺失时）：

```
[错误] 头像文件不存在：avatars/expert.png（这就是小图标变成文字的直接原因）
```

## 四、修好之后怎么验收

1. 跑 `check_package.py`，结论必须是"通过"。
2. 退出应用再启动（触发重新扫描）。
3. 在专家中心看到头像；进入对话后，输入区的小图标也应是头像。
4. 若列表有头像、对话区没有，多半是前端缓存：换一个会话再试。

## 五、给发布方的三条硬规矩

1. **头像只放一张**，命名 `expert.png`，512×512，8 位 RGB，≤500 KB，不带透明通道。
2. **清单里的相对路径必须与磁盘上的文件名逐字符一致**，不要依赖 Windows 的大小写不敏感。
3. **打包后自己解压一遍**，确认 `avatars/` 在里面——这一步能挡掉九成的"图标变字"。

## 六、实测记录（针对本次反馈）

对从市场下载的目标专家（`senior-chemistry-tutor`）头像做了逐项检测：

| 项 | 结果 |
|---|---|
| 文件路径 | `avatars/expert.png`，与清单字段一致 |
| 文件大小 | 412,519 字节（403 KB），未超过 5 MB |
| PNG 解码 | 通过，色彩类型 2（RGB） |
| 尺寸 | 512×512，正方形 |
| 分块 CRC | 全部通过，无截断 |

**结论：图片本身没有问题。** 那么"小图标变成文字"只可能出在前面的环节——最可能是导入的包里没有带 `avatars/` 目录，或导入时只复制了 `plugin.json` 与 `agents/`。

所以处理顺序应该是：**先确认包里有头像文件，再查路径，最后才怀疑图片。**

本产品（`czl-chemistry-home-tutor`）的头像已按同一套标准复检：512×512、RGB、372 KB、CRC 通过，且发布包内确实包含 `avatars/expert.png`（见压缩包文件列表）。
