## 四、"导入后图标变文字"的成因验证

这一节回答你的问题，也是本包新增自检脚本的原因。

### 4.1 客户端怎么取头像

在客户端代码里找到压缩包导入时的头像解析函数，逻辑等价于：

```js
function resolveAvatarFromExpertZip(zip, baseDir, avatar) {
  if (!avatar) return undefined;                       // 字段为空 → 没有图
  if (/^(https?|data):/i.test(avatar)) return avatar;   // 外链/内联
  const rel = avatar.replace(/^\.\//, '').replace(/^\//, '');
  for (const p of [baseDir + '/' + rel, rel]) {
    const e = zip.getEntry(p);
    if (e && !e.isDirectory) return 'data:image/png;base64,...';
  }
  return avatar;   // 找不到 → 原样返回相对路径
}
```

关键在最后一行：**zip 里找不到头像条目时，它不会报错，而是把 `avatars/expert.png` 这个相对路径原样交给渲染层**。这个路径在导入后的环境里取不到文件，图片加载失败，卡片就退回文字占位。卡片组件里确实存在 `_avatarFallback` 这一占位元素，并且有把名称取首字/首字母的函数。

### 4.2 三个实测试例

| 用例 | 构造 | 解析结果 | 是否显示头像 |
|---|---|---|---|
| 正向 | 本包 `dist/czl-chinese-home-tutor.zip` | 命中 `czl-chinese-home-tutor/avatars/expert.png` | 是 |
| 反向 1 | 删掉包内 `avatars/` 目录 | 未命中 → 原样返回相对路径 | **否，显示首字** |
| 反向 2 | 整体多套一层"外层目录/" | 命中 `外层目录/czl-chinese-home-tutor/avatars/expert.png` | 是 |

**结论**：

1. **主因是"清单在、图片不在"**，或 `avatar` 字段写错/为空。压缩包里 `.codebuddy-plugin/plugin.json`、`agents/`、`skills/` 都在，唯独漏了 `avatars/`，就会出现"名字有、图标是字"。
2. **多套一层目录不会导致丢图**，因为客户端按清单所在目录去找。此前把"嵌套"当成主因的判断不成立，特此更正。
3. 另有一条与包无关的路径：在客户端里"新建自定义专家"（不是导入包）时，记录里的 `avatar` 字段本来就是空字符串，这类专家在任何机器上都显示首字。这不是包的问题，只能通过导入专家包解决。
4. 旧卡片缓存也会造成同样现象：导入过同名专家后重导，卡片不会自动刷新，需要退出客户端或删旧目录。

### 4.3 已做的加固

- `bin/check_expert_package.py` 会在打包后直接检查 zip 内是否存在 `<清单目录>/<avatar>` 条目，缺失时给出与上述机制对应的提示；
- 头像文件名采用平台通用的 `avatars/expert.png`，字段值不带 `./` 前缀；
- 发布包已用该脚本复检通过。
