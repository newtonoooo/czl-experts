## 一、定位

**做家庭这一端的高中语文一对一。** 学校负责课程与班级教学，本产品负责孩子在家里的那一段：诊断卡点、设计辅导时段、面批作文、带读文言、安排一周节奏、四周复盘。

名称用"学习辅导"而不限于"家庭辅导"，是因为服务对象有三类（学生本人、陪读家长、家教老师）；但设计重心仍在家庭场景——客厅、餐桌、睡前二十分钟。

**不做的事**（写进提示词，作为边界）：

- 不做课堂教学设计、不写教案、不做单元整体教学——那是任课老师的工作；
- 不代写作文、不代做作业、不提供可誊抄的成段答案；
- 不承诺分数、不押题、不做"提分保证"式营销；
- 不评价、不贬低学校与任课老师；
- 不收集学生身份信息，不做排名与分层名单。

## 二、目标用户与实际场景

| 用户 | 具体场景 | 他现在怎么做 | 卡在哪 |
|---|---|---|---|
| 陪读家长（主） | 孩子高一，语文 90 分上下，问不出哪儿不会；周末请了家教但不知怎么配合 | 到处找方法、买练习册、加补习班 | 不知道问题类型，只能加量；不会判断老师好坏 |
| 学生本人（次） | 作文写不出、文言读不懂、阅读答不到点上 | 搜模板、背素材、抄答案 | 要的是"今晚怎么办"，得到的多是"多读多写" |
| 家教/机构老师（次） | 一对一或小班，需要备课、要向家长交代 | 凭经验排课，反馈靠感觉 | 缺可复用的时段结构与可量化的反馈话术 |

**典型使用时刻**：周日晚复盘后、月考出分后、家长会之后、请家教之前、寒暑假开始前。

从同类产品已覆盖的能力中提炼需求，再补上家庭场景的缺口。需求编号用于测试对照。

| 编号 | 需求 | 来源 | 本产品做法 |
|---|---|---|---|
| R1 | 从学生的原始材料判断问题类型，而不是凭分数猜 | 同类产品的学情诊断能力 | 五份证据 + 四类缺口（知识/方法/习惯/动力） |
| R2 | 把诊断结论转成一段可执行的时间安排 | 同类产品的教学设计能力 | 五段骨架 + 四种时长蓝图 + 讲练比 3:7 |
| R3 | 给作文具体、可改的反馈，而不是维度评分 | 同类产品的作文批改能力 | 十二型定位 + 只挑两个问题 + 一句示范 + 一段重写 |
| R4 | 文言与阅读的错因要分开，练法不能一样 | 同类产品的阅读教学能力 | 五因分类（词义/句法/语境/文化/题型）+ 每日 20 分钟 |
| R5 | 家长要知道自己该做什么、不该说什么 | 同类产品覆盖较弱 | 三句可说、三句禁说、六个高频场景话术 |
| R6 | 一周的时间要排得下，不能理想化 | 同类产品覆盖较弱 | 先算可用时间，再按 3-2-1 排；三种配置 |
| R7 | 四周后要知道有没有用 | 同类产品覆盖较弱 | 四个可数的指标，不记分数 |
| R8 | 材料要不到时也能给东西 | 同类产品覆盖较弱 | 最小诊断版 + 降级四问 |
| R9 | 孩子抗拒、亲子冲突时怎么办 | 同类产品覆盖较弱 | 降量 30%、关系优先、暂停学科任务 |
| R10 | 打包与导入不能出工程问题 | 同类产品未覆盖 | 包自检脚本，专查头像与路径 |

## 四、必要的输入与预期输出

### 输入（按工作流）

| 工作流 | 必填 | 选填 | 缺省时的处理 |
|---|---|---|---|
| W1 | 年级、分数或等第 | 试卷、作文、原始作答、学生三问、家长三问 | 出最小诊断版，标注待补 |
| W2 | 时长、年级、一个能力点 | W1 诊断卡、是否有家长旁听 | 用默认能力点（按年级），并说明是假设 |
| W3 | 作文原文、题目 | 年级、是否限时、平时分数 | 缺题目则先问一句，不猜题意 |
| W4 | 学段与文体 | 1—3 道原始错题、教材版本 | 用三题定位法替代 |
| W5 | 年级、每周可用时长、可陪读人力 | W1—W4 记录 | 按 200 分钟默认配置，标注需调整 |

| 工作流 | 交付物 | 篇幅上限 |
|---|---|---|
| W1 | 诊断卡（已会/卡住/待确认）+ 四类缺口表 + 四周优先级 + 今晚一个动作 | 900 字 |
| W2 | 时段表 + 示范脚本 + 问题链 + 当堂检测 + 家长反馈稿 | 1000 字 |
| W3 | 面批单（亮点/两个问题/示范/重写任务/检查点） | 800 字 |
| W4 | 错因表 + 7 天练法表 + 材料清单 | 800 字 |
| W5 | 周计划表 + 话术卡 + 四周指标 + 复盘流程 | 900 字 |

所有完整产出末尾带 AI 生成标识。

## 五、通用处理步骤

```
识别身份 → 收材料 → 判类型 → 定一个点 → 给动作 → 定检测 → 约复盘
```

七步在所有工作流中一致，差别只在"判类型"的依据和"给动作"的形态。

## 七、质量、速度、稳定性要求

| 维度 | 要求 | 检验方式 |
|---|---|---|
| 诊断有据 | 每条结论后跟一个可数事实 | 抽查 10 条结论，无事实者计不合格 |
| 建议可执行 | 每条建议含"做什么、多久、怎么检查" | 三要素缺一计不合格 |
| 不代写 | 示范不超过两句，无整段成文 | 全文检索成段范文 |
| 篇幅 | 首轮 ≤1200 字，单工作流 ≤1000 字 | 字数统计 |
| 出处 | 事实性内容有 K/R 标注；无出处则删 | 人工核对 |
| 响应 | 单轮常规请求 ≤60 秒（模型侧） | 实测记录，不含网络波动 |
| 稳定 | 缺材料、材料矛盾、用户催促均不崩 | 异常用例测试 |

## 八、对同类产品能力缺口的补充

以下为产品设计判断，不是对任何具体产品的评价：

1. **面向教师 → 面向家庭。** 教师需要"一节课怎么上"，家长需要"今晚这四十分钟做什么"。同一套诊断，交付物必须换。
2. **以课为单位 → 以周为单位。** 家庭没有 45 分钟课时，只有碎片时间。因此引入 3-2-1 周节奏与"先算时间再排计划"。
3. **维度齐全 → 取舍明确。** 诊断维度多，家长反而不知道先做哪个。本产品加了一条硬规则：先拿回"会但丢"的分。
4. **全面批改 → 只改两处。** 一次指出十个问题等于零。面批单强制只留两个，其余进"下次再说"。
5. **只谈方法 → 也谈关系。** 孩子抗拒时，方法无效。因此把"降量""暂停""家长退出陪读"写进流程。
6. **理想计划 → 现实计划。** 计划按可用时间排，不按应该的时间排；完成率低于 60% 不加量。
7. **只做内容 → 也做工程。** 加包自检脚本，把"导入后图标变文字"这类问题在交付前挡住。

## 九、非功能要求

- **隐私**：不存姓名、学校、班级、成绩；输出统一用"学生A"。
- **价值导向**：涉及党史国史与领袖人物的篇目正常讲解，只用统编教材与权威官方来源。
- **心理安全**：危机信号优先于学业，给 12356 与当天转介建议。
- **可维护**：五个技能独立，改一个不影响其余；版本号与变更日志分离。
- **可移植**：无第三方依赖，Windows/macOS 均可运行脚本。
