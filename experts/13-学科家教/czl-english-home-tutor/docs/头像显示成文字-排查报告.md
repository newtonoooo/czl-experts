# 排查报告：专家导入新环境后，选中时头像变成文字

- 排查对象：`senior-english-tutor`（老吴私塾·高中英语家教 / 艾薇）
- 排查环境：WorkBuddy 5.9.3（本机 `app.asar`，2026-10-27 构建）
- 结论时间：2026-10-31

## 一、结论先说

**这个包的图片文件本身没有问题。** 静态检查全部通过：`avatars/expert.png` 存在、512×512、PNG、412.8 KB、IEND 完整、`avatar` 字段为 `avatars/expert.png`。

界面之所以退回成文字，是因为**头像解析链路的某一环没拿到可用的图片地址**，前端就退化成"姓名首字"的字母块。链路上有四个明确的失败点，按可能性排序见第四节。

## 二、界面是怎么把头像变成文字的

从 5.9.3 的前端代码看，专家头像组件是 `Avatar`，`src` 取 `expert.avatarUrl`，`children` 取专家名首字：

```js
ExpertAvatar = ({expert}) => <Avatar size={16} src={avatarUrl} ...>{firstCharOf(expert.name)}</Avatar>
```

**`src` 为空或加载失败时，显示的就是 `children`**——也就是你看到的"成字了"。

## 三、`avatarUrl` 是怎么来的（主进程解析规则）

主进程 `ExpertPluginService.resolveAvatarUrl(avatar, expertRoot)` 的实际逻辑：

```js
if (!avatar) return '';
if (/^(https?|data):/.test(avatar)) return avatar;      // 远程/内联，直接放行
const rel = avatar.replace(/^\.\//, '');
const target = path.resolve(expertRoot, rel);
if (!target.startsWith(expertRoot + sep)) return '';    // 越出专家目录 → 空
if (!fs.existsSync(target)) return '';                  // 文件不存在 → 空
if ((await fs.stat(target)).size > 5 * 1024 * 1024) return ''; // 超 5MB → 空
return toLocalFileUrl(target);                          // local-file://...
```

也就是说，**只有同时满足"相对路径、在专家目录内、文件真实存在、≤5MB"这四个条件，头像才有地址。**

返回空字符串后，前端还有一次兜底：拿原始的 `avatar` 字段（`avatars/expert.png`）去拼 CDN 前缀 `https://acc-1258344699.cos.accelerate.myqcloud.com/workbuddy/expert-marketplace/avatars/expert.png`。这个地址当然不存在，于是最终落到字母块。

## 四、四个失败点，按可能性排序

| 排序 | 失败点 | 为什么会发生 | 怎么验证 | 怎么修 |
|---|---|---|---|---|
| 1 | **zip 里没有 `avatars/` 目录** | 导出时只选了"看得见的文件"；或用了只打包 `agents/`、`.codebuddy-plugin/` 的工具；或复制时漏了整个目录 | 在新环境打开专家目录，看 `avatars/expert.png` 在不在；或跑 `python bin/check_avatar.py .` | 重新用整目录打包（官方 `package_expert.py` 会保留 `.codebuddy-plugin` 与 `avatars/`） |
| 2 | **zip 多套了一层目录** | 压缩时把上级文件夹也打进去，导入后 `plugin.json` 与 `avatars/` 的相对位置仍在，但部分工具解压后层级错位 | 解压 zip，确认第一层就是专家目录（含 `.codebuddy-plugin`） | 压缩时进入专家目录再压，或确认第一层目录名＝专家名 |
| 3 | **`avatar` 被改写成外链/CDN 地址** | 走开放平台上传时，平台会把头像转存为 CDN 地址；换环境后该地址需要登录态或已过期，图片 403/404 | 打开 `plugin.json` 看 `avatar` 是不是 `https://...` | 改回本地相对路径 `avatars/expert.png` |
| 4 | **文件名/大小写与声明不一致** | Windows 不区分大小写，`Expert.PNG` 本地能读到，换到区分大小写的环境就找不到 | 对比 `plugin.json` 的 `avatar` 与 `avatars/` 里的实际文件名 | 统一小写，重命名文件 |

另有一个非头像原因：**专家没有注册进 `marketplace.json`**，元数据不完整时列表能扫到、但详情缺字段，也可能退化显示。本机就存在这种情况（见第五节）。

## 五、本机额外发现（同一类问题的旁证）

排查时比对"专家目录 vs `my-experts/marketplace.json`"：

- 目录 37 个，注册条目 33 个；
- 未注册的 4 个：`czl-ashare-research-writer`、`czl-chinese-home-tutor`、`czl-deskforge`、`serial-watch`；
- 其中 `czl-chinese-home-tutor`（高中语文家庭辅导）就是头像/元数据可能显示不全的典型：目录齐全、头像文件也在（406 KB / 512×512），但当时没有市场条目。

排查过程中，`czl-chinese-home-tutor` 被应用自动补进了 `marketplace.json`（条目数由 33 变 34，我注册新产品后为 35）。说明**应用会做目录扫描补偿，但补偿时机不确定**——刚导入时如果没等到补偿，就会出现"能选中、但图标是字"的中间状态。这一条可以解释"只有新导入的那一个不对"。

## 六、本产品（卓识教育-高中英语学习辅导专家）怎么规避

1. **头像规范**：`avatars/expert.png`，512×512，PNG，427.7 KB，全小写 ASCII 文件名，相对路径 `avatars/expert.png`，无外链。
2. **打包校验**：`bin/package_expert.py` 在压缩前断言三个必需文件存在（`plugin.json`、`agents/<name>.md`、`avatars/expert.png`），缺一个就中止，不会产出"少文件"的包。
3. **zip 结构**：第一层即专家目录 `czl-english-home-tutor/`，保留 `.codebuddy-plugin/`，跳过 `.created-by-session` 等隐藏文件。
4. **自带诊断脚本**：`bin/check_avatar.py` 按上文的四条规则逐项检查，并额外检查反斜杠路径、绝对路径、大小写一致性与 PNG 尺寸。
5. **注册**：已通过官方 `register_expert.py` 注册进 `marketplace.json`，条目含 `name / source / description / version`。

## 八、这不是"图片坏了"

补充一句避免误判：把同一张 `expert.png` 拖进浏览器能正常显示，说明图片编码没问题；用看图软件打开也正常。问题只在"路径解析 → 是否拿到 local-file 地址"这一环。所以**重做一张头像不会解决问题，改路径/补文件才会。**
