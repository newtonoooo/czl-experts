## 一、开发方式

本次为**独立重写**，不是改名分发。全过程分四步：

1. **功能分析**：只读取目标专家的三个文件（`plugin.json`、`agents/senior-english-tutor.md`、`README.md`），提取"能做什么、给谁做、怎么组织"，形成功能清单。
2. **需求重构**：把功能清单转成七条可执行工作流，并为每条定义输入、步骤、判断、输出、异常、依赖、关系（见 `docs/工作流规格.md`）。
3. **独立撰写**：所有提示词、知识库、模板、说明文档从零撰写；语法规则、题型结构、分值分布属于公共知识，按自己的口径重新表述并配自造例句。
4. **工程化交付**：初始化官方目录 → 写元数据 → 生成头像 → 静态校验 → 注册 → 打包 → 测试 → 文档。

## 三、关键设计决定

### 1. 为什么先诊断再讲题

家庭辅导最常见的浪费是"哪科都补一点"。诊断的作用不是分类，是**排序**：只允许一个主攻点占用新时间，其余进"暂缓清单"。所以 W1 的输出强制包含"暂缓清单"，这一栏是给家长安心用的。

### 2. 为什么"可动的分"要乘见效速度

只按丢分多少排序，会永远先修阅读（占分最大、提分最慢），家庭辅导最缺的正反馈就永远不来。加入"见效速度"和"依赖成本"两个维度后，语法填空、七选五、应用文会排到前面，两周能看到变化。

### 3. 为什么写作只改两句

整篇重写会让孩子认为"我写的不算"，下次还是不会。只改两句 + 说明"为什么更好" + 给三个可迁移句型，才能留下可复用的能力。这条写进了红线。

### 4. 为什么错因只打一个主码

打多个码等于没分类。强制单选会逼出判断："这题到底是词不认识，还是没定位？"判定问句按顺序问，先命中先定。

### 5. 为什么不用"下载资料打包"

原计划包含"下载高中英语资料作为专家材料"。评估后放弃，原因：

- 教材、真题、教辅的著作权归属明确（出版社/考试院），商业分发需要授权，无法确认；
- 语法规则、题型结构属于公共事实，可以自己写；
- 打包他人资料会把整个产品置于侵权风险，且无法通过平台原创性审核。

替代方案：把"资料"做成**自写的知识库**——语法十二讲、十类句式、五类错因码、六类应用文清单、升格句库、家长话术。信息密度不低于教辅摘编，且权利清晰。

## 六、已知取舍

1. **卷型只内置新高考全国卷**。地方卷（上海概要写作、北京、天津）差异大且会变，内置反而容易过时；改为"先问地区、再给方案、不确定就声明以本省说明为准"。
2. **语法只讲考点边界**。学术争议用法不进产品，避免误导。
3. **不做听力音频**。没有音频播放能力，听力只给动作与文本分析，写进了已知限制。
4. **分类用 `15-Education`**。官方市场十余个学科家教均用此值，但本地 `validate_expert.py` 的白名单未收录（只有 01—12），导致本地校验报 1 项 error、官方打包脚本中止。判断：以平台实际分类为准，自写打包脚本，差异记录在案。
