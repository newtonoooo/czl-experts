## 四、发布包解压回归（在最终 zip 上做，不在源码目录做）

这一步是为了排除"源码目录能跑、打出来的包跑不了"这种典型情况。

```
解压 dist/czl-math-home-tutor-1.0.0.zip 到独立目录
  → python tools/check_package.py --verbose  →  0 failed, 0 warnings, 38 passed
  → python tools/run_tests.py --no-write      →  26 passed, 0 failed
```

同时校验归档结构：

```
top-level entries: czl-math-home-tutor      ← 只有一个顶层目录，名字与包名一致
  ok  czl-math-home-tutor/.codebuddy-plugin/plugin.json
  ok  czl-math-home-tutor/agents/czl-math-home-tutor.md
  ok  czl-math-home-tutor/avatars/expert.png
```

**为什么专门查这一条**：归档多套一层目录时，专家仍能导入、名字也对，但 `avatars/expert.png` 会差一级解析不到，头像退回成名字首字。`tools/package.py` 内置了这个断言。

## 六、测试过程中发现并修复的缺陷

这些不是"设计如此"，是真的写错了然后改掉的，保留记录以便回溯：

| # | 缺陷 | 发现方式 | 修复 |
|---|---|---|---|
| 1 | `verify.py` 无法解析 `--on -1,1`（负号被当成选项） | 手跑单调性用例时报 `expected one argument` | 增加 argv 归一化 |
| 2 | `diagnose.py` 主码与"性质"自相矛盾 | 读输出时发现"主码 M / 性质：基础缺口" | 由码决定性质 |
| 3 | `diagnose.py` 验收标准过软 | 18% 得分率的断点验收写"≥38%" | 改绝对档位（60/80/90） |
| 4 | `ledger.py` 新增条目后崩溃 | 连续 add 两条时 `'int' object has no attribute 'isdigit'` | id 统一存字符串 |
| 5 | `drill.py` 计划超预算 | 不变量用例报"45 分钟排了 54 分钟" | 重写配额分配 + 断点数按分钟裁剪 |
| 6 | `drill.py` 低时长下仍排 3 个断点 | 不变量用例报"20 分钟要 32 分钟" | 每断点最少 12 分钟，不足则减少断点数 |
| 7 | `scoreplan.py` 多选时间分配过高 | 人工审表：3 道多选 20 分钟 | 调权重 + 加单题硬上限 |
| 8 | `scoreplan.py` 缺少"目标不现实"提示 | 用例"150 分 / 当前 40"时无任何警告 | 增加 ≥95% 得分率的"不现实"分支 |
| 9 | `package.py` 读版本号崩溃 | 同一文件句柄 `json.load` 调了两次，第二次读到 EOF | 只读一次存变量 |
| 10 | 头像 528 KB 超上限 | 生成后测体积 | 量化 + 真彩回写，降到 214 KB |
| 11 | `run_tests.py` 用例表没被加载 | 首次运行时只跑了 2 项 | `build_cases` 改为逐条 append |
