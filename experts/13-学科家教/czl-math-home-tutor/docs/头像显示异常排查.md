# 头像显示异常排查："小图标变成一个字的"到底是什么原因

> 现象：专家导入到新的 WorkBuddy 后，选中它，对话区左侧的小图标不显示，只剩一个字（通常是 `displayName` 的首字，如"陆"）。
> 结论先给：**这不是图片坏了，是头像的 URL 没解析出来。** 客户端拿不到图片地址时，就会退回用名字首字渲染。

## 一、先排除"图片本身不合格"这条

我对参考专家 `senior-math-tutor` 的头像做了实际检测：

```
senior-math-tutor/avatars/expert.png
  512×512, 8-bit, colour type 2 (RGB), non-interlaced, 395 KB
```

对照规范（PNG、512×512、≤500 KB），**它完全合格**。所以"图片格式不对"不是这次的原因。

顺带发现一个反例：同目录下 `wechat-miniprogram-expert/avatars/expert.png` 的真实编码是 **JPEG**（只是扩展名写成了 .png）。这种才是真的会挂——解码器按 PNG 读会直接失败。**判断方法：看文件头前 8 个字节是不是 `89 50 4E 47 0D 0A 1A 0A`。** 本包的 `tools/check_package.py` 内置了这个检查。

## 二、真正的机制：本地专家的头像是**绝对路径**绑定的

WorkBuddy 把头像地址记在会话的显示快照里（`~/.workbuddy/assistant-display/<会话id>.json`）。我读了本机的实际记录，两种来源写法完全不同：

| 专家来源 | 记录下来的 avatarUrl |
|---|---|
| 市场安装的官方专家 | `https://openplatform-cdn.codebuddy.cn/.../ex_xxx/xxxx.png`（CDN 地址） |
| 本地安装的专家 | `local-file://local/C%3A/Users/丛自龙/.workbuddy/plugins/marketplaces/my-experts/plugins/czl-draft-qc/avatars/expert.png` |

第二行是关键：**它是一个带盘符的绝对路径**，指向
`<用户目录>/.workbuddy/plugins/marketplaces/my-experts/plugins/<包名>/avatars/expert.png`。

由此可以推出三种会让它变成"一个字"的情况：

### 成因 1：导入后落点不是这个目录（最常见）

换一台电脑、换一个 Windows 用户，"丛自龙"这一段就不存在了。如果导入时包没有落到
`.../my-experts/plugins/<包名>/`，那么 `local-file://` 指向的路径就是空的 → 回落成字。

**判断方法**：在目标机器上按上面的路径去找 `avatars/expert.png`。找不到就是这一条。

### 成因 2：包名与目录名不一致

加载器是按**目录名**建索引、按 `plugin.json` 的 `avatar` 字段拼路径的。如果 zip 解压后多套了一层
（`czl-math-home-tutor/czl-math-home-tutor/...`），或者解压时目录被改名，拼出来的路径就会差一级。

**判断方法**：确认 `<包名>/avatars/expert.png` 的层级正好是"包名目录 → avatars → 文件"，中间不多不少一层。

### 成因 3：图片能读但解码失败

- 扩展名与真实编码不符（JPEG 改名成 .png）；
- 尺寸不是 512×512（过大的图在某些渲染路径上会被拒绝）；
- 带透明通道且整块透明，视觉上"没有图标"。

**判断方法**：跑 `python tools/check_package.py`，它会报 `avatar.format` / `avatar.dimensions`。

## 三、为什么"选择后"才出问题

专家卡片列表读的是 `plugin.json`（有路径就能拼），而**选中后**注入会话的那份显示信息，走的是另一条链路：把头像解析成 `local-file://` 再交给渲染层。两条链路的容错不一样，所以会出现"列表里好像有、选中后变字"这种看起来矛盾的现象。

这也解释了另一个现象：同一个包在同一台机器上重装一次可能就好了——因为重装让它重新落到了正确目录。

## 四、这个包怎么规避

1. **图片按最保守的规格做**：512×512、8-bit、colour type 2（RGB 真彩）、非隔行、214 KB。没有用调色板 PNG，也没有用 WEBP 改名。
2. **路径写成规范形式**：`"avatar": "avatars/expert.png"`，不加 `./`，不加盘符。
3. **一键安装到正确位置**：`python tools/install.py` 会把包复制到
   `%USERPROFILE%\.workbuddy\plugins\marketplaces\my-experts\plugins\czl-math-home-tutor\`，
   写入 `marketplace.json`，然后**回读一遍**打印出解析后的 `local-file://` 地址，确认文件真的在那儿。
4. **发布前自检**：`python tools/check_package.py --verbose` 会检查路径、真实编码、尺寸、体积四项。
5. **另存一份备用图**：如果平台侧仍然不显示，把 `avatars/expert.png` 复制成同目录下的 `avatars/expert.jpg` 不会有用（编码不符反而更糟）；正确做法是保持 PNG 不动，检查落点。

## 五、如果在新机器上还是不显示，按这个顺序查

1. 打开 `%USERPROFILE%\.workbuddy\plugins\marketplaces\my-experts\plugins\`，确认有 `czl-math-home-tutor` 目录。
2. 确认 `czl-math-home-tutor\avatars\expert.png` 存在，右键属性看大小是不是 214 KB 左右。
3. 打开 `...\czl-math-home-tutor\.codebuddy-plugin\plugin.json`，确认 `"avatar": "avatars/expert.png"` 一字不差。
4. 打开 `...\my-experts\.codebuddy-plugin\marketplace.json`，确认有 `"name": "czl-math-home-tutor"` 且 `"source": "./plugins/czl-math-home-tutor"`。
5. 重启 WorkBuddy（不是关窗口，是退出进程再开）。
6. 仍不显示：查看 `%USERPROFILE%\.workbuddy\logs\renderer.log`，搜 `local-file`，看它请求的路径和你实际文件的路径差在哪一段。差在哪一段，就是哪一段的问题。

## 六、置信度说明

| 结论 | 置信度 | 依据 |
|---|---|---|
| 参考专家头像文件本身合格 | 已确认 | 直接读取文件头与 IHDR |
| 本地专家头像走 `local-file://` 绝对路径 | 已确认 | 本机 `assistant-display` 快照记录 |
| 换机器/换目录会导致回落成字 | 高置信 | 路径机制直接推出，且与"重装后恢复"的现象一致 |
| 具体是哪一条导致了你那次的现象 | **待验证** | 需要按第五节在出问题的那台机器上核对落点 |

我没有在出问题的那台机器上取证，所以最后一条标"待验证"，不写成定论。
