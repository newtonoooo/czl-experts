## 一、目标用户与真实场景

### 用户画像

| 用户 | 占比估计 | 他们真实说的话 | 他们缺什么 |
|---|---|---|---|
| 高中生本人 | 45% | "这题没思路""明天考试了" | 拆题路径、即时反馈 |
| 陪读家长 | 40% | "90 分上不去""要不要报班" | 判断依据、可执行的家庭动作 |
| 家教/机构老师 | 15% | "帮我给这个学生出套题" | 定位工具、训练配比 |

### 四个高频场景

1. **考完试的当晚**：卷子发下来，家长想知道分丢在哪，孩子只想知道这次能不能别再被说。
2. **作业卡住**：一道题耗了 40 分钟，讲一遍听懂，下次同类还是不会。
3. **错题本无效**：抄了两大本，考试遇到同类型还是错。
4. **考前两周**：时间不够，后面大题从来没见过，不知道该放弃哪块。

### 场景对产品的硬约束

- 家长在手机上问，**输出必须能直接照着做**，不能是要再消化的长篇分析。
- 孩子问的时候**不能一次倒完**，说完一步要停。
- 考完当晚情绪敏感，**话术不能评判孩子**。

## 二、要解决的问题（按优先级）

| 优先级 | 问题 | 现状（市面产品） | 本产品的解法 |
|---|---|---|---|
| P0 | 不知道分丢在哪，只能归因为"不努力/粗心" | 给分数分析报告，但落不到动作 | 错因五码 + 断点排序 + 每条断点配动作和时长 |
| P0 | 讲过的题下次还错，没有复现机制 | 错题本 App 只做归档 | 1/3/7/21/45 天阶梯 + 到期清单 + 卡三次自动转概念重讲 |
| P1 | 练习量堆上去了，迁移没发生 | 题海 + 同类题推荐 | 同型/换皮/换轴三档，只有换轴能预测考场表现 |
| P1 | 考场时间不够，不会取舍 | 建议"先易后难" | 目标分倒推 → 分题型目标 → 每题时间上限 → 放弃线 |
| P2 | 家长想帮但一帮就吵架 | 泛化的"多鼓励" | 给具体话术 + 五条禁做清单 |

## 三、必要的输入

| 输入 | 必需性 | 形态 | 缺失时的降级 |
|---|---|---|---|
| 一道题 / 一张卷 / 一批错题 | 必需（任一） | 文字、图片、手写 | 用三问法缩小范围，产出"待验证假设" |
| 年级 | 建议 | 一句话 | 按高二处理并声明 |
| 卷型 | 建议 | 新高考Ⅰ/Ⅱ、地方卷 | 默认 19 题结构并声明 |
| 当前分数段 | 建议 | 数字或档位 | 按 90–110 假设并声明 |
| 每周可用时间 | 可选 | 分钟数 | 默认 45 分钟 × 3 次 |

**输入不足时的原则**：不猜。明确说"缺什么"，给一个基于假设的临时版本，并标注假设。

## 四、预期输出（五类交付物）

| 交付物 | 触发 | 结构 | 判据 |
|---|---|---|---|
| 解题卡 | 一道具体的题 | 题目/要什么/条件编号/挑武器+淘汰理由/关键一步/完整过程/三验/变式 | 学生能复述关键一步 |
| 诊断表 | 成绩问题 | 样本/断点排序/错因码分布/处方/这周三件事 | 每条断点能指回具体题号 |
| 练习卷 | 要练 | 三档变式 + 答案分离 + 停止条件 | 时间不超预算 |
| 错题台账 + 周报 | 整理错题 | CSV + 到期清单 + 五段周报 | 到期项可执行、卡三次能被识别 |
| 考场计划 | 时间/取舍 | 目标/分题型表/按题上限/三条硬规矩 | 目标分加总能对上 |

## 五、通用处理步骤（四环）

```
① 定位：建表 → 定错因码 → 按失分排序 → 出处方 → 写验收
② 拆解：划条件 → 换说法 → 挑武器（含淘汰） → 摆式子（找缺口） → 三验
③ 训练：定配比（按主码） → 出三档题 → 配答案 → 写停止条件
④ 复盘：入账 → 排期 → 到期复现 → 周报 → 回炉
```

跨环必须按顺序。**没有定位直接给训练计划，视为猜。**

## 六、需要的工具能力

| 能力 | 用途 | 本产品实现 |
|---|---|---|
| 文件读写 | 台账、诊断 CSV、报告落盘 | Python 标准库 |
| 计算校验 | 三验（代值/零点/单调/极值） | `verify.py`，白名单 AST，不用 eval |
| 表格处理 | 卷面得分表解析 | `diagnose.py`，CSV 自动嗅探 + 中英文表头 |
| 日期排期 | 1/3/7/21/45 阶梯 | `ledger.py`，ISO 日期 |
| 图像处理 | 头像裁剪压缩 | `png_resize.py`，纯 zlib 手写编解码 |
| 自检 | 发布前合规检查 | `check_package.py`，38 项 |

**不依赖**：联网、第三方库、外部题库、数据库。

## 七、质量、速度、稳定性要求

| 维度 | 要求 | 本版达标情况 |
|---|---|---|
| 准确性 | 解题结论必须可验证；不确定要标注 | 每个结论要求指回证据；`verify.py` 提供数值兜底 |
| 一致性 | 同一错因码在诊断/训练/台账三处含义相同 | 码定义集中在 `error-taxonomy.md`，脚本内嵌同一套 |
| 可执行 | 每份交付物必须带"下一步动作 + 时长" | 输出规范强制 |
| 速度 | 单次诊断 ≤ 3 轮对话；脚本 ≤ 2 秒 | 脚本均为毫秒级，最慢的量化脚本约 3 秒 |
| 稳定性 | 输入缺失不崩溃，给降级结果 | 每个工作流写了异常处理表 |
| 可维护 | 版本号、变更记录、文件指纹 | semver + CHANGELOG + 文件清单 |

## 八、明确不做

- 不代写作业、不代做整卷、不押题。
- 不承诺提分数字、不评价孩子能力。
- 不收录教材原文与真题原文。
- 不接入题库、不做院校志愿咨询（超出数学辅导范围）。

## 九、验收标准（本版）

1. `check_package.py` 零 FAIL。
2. 五个脚本各自有可复现的用例，输出与预期一致（见 `测试报告.md`）。
3. 五个 SKILL.md 均包含：职责边界、输入参数、执行步骤、判断条件、输出格式、异常处理、依赖、与其他工作流关系。
4. 头像 512×512、RGB、≤500 KB、无第三方水印。
5. 主提示词不含任何参考专家的原句（已逐段比对，见 `开发记录.md`）。
