# 使用说明 · 桌匠（czl-deskforge v1.0.0）

写给两类人：**审核人员**（这个包做了什么、会不会乱来）与**使用者**（怎么用、能出什么、出不来什么）。

---

## 一、安装

### 方式 A · 客户端导入（推荐）

1. WorkBuddy →【专家·技能·连接器】→【专家】；
2. 搜索「桌匠」，或导入本地 `czl-deskforge.zip`；
3. 选中「桌匠」开始对话。

### 方式 B · 放入专家目录

```
%USERPROFILE%\.workbuddy\plugins\marketplaces\my-experts\plugins\czl-deskforge\
```

macOS / Linux 为 `~/.workbuddy/plugins/marketplaces/my-experts/plugins/czl-deskforge/`。重启客户端后可见。

> 目录名、`plugin.json` 的 `name`、`agentName`、`agents/` 下的文件名，四者必须一致（均为 `czl-deskforge`）。改动会导致识别失败。

### 卸载

删除该目录即可。不写注册表、不改系统目录、不动其他专家。

## 二、配置

| 项 | 需要 | 说明 |
|---|---|---|

## 三、输入：最少说什么

| 说法 | 会发生什么 |
|---|---|
| 「做一个工作台」 | 它最多问两个问题（给谁用 / 最想记什么），且带候选选项，问完就出收束卡 |
| 「做一个备考打卡台」 | 直接开工，字段按常规补，补的会标"本次假设" |
| 「做个记账的，要能在手机上用，还要发给老婆」 | 收束 + 装配 + 上线（给链接） |
| 「这是上次那个文件，体检一下」 | 直接进体检工序，只出结论与修复建议，不动原文件 |

**推荐写法**：给谁用 + 记什么 + 要看出什么。三样齐了最省时间。

**不要给**：真实金额、真实姓名、身份证、健康档案等隐私数据。示例数据一律由它编造。

## 四、它会给你什么（交付四件套）

| # | 文件 | 里面有什么 |
|---|---|---|
| 1 | `收束卡-{台子名}-{日期}.md` | 模块表（≤4 块）、每块的填/看/判、字段草案、明确不做、分期表（如超限） |
| 2 | `数据账-{台子名}-{日期}.md` | 实体与字段（名/类型/单位/必填/示例）、存储键、种子数据、导出导入与迁移 |
| 3 | `{台子名}.html` | 单文件工作台，双击即开 |
| 4 | `出厂单-{台子名}-{日期}.md` | 两个脚本的原始输出 + 人工四项结论 + 遗留 warning 理由 |

对话里只放：做了什么、几块、体检结论、文件路径、下一步。**不会在对话里贴整段 HTML。**

## 五、工作流（五道工序）

| 工序 | 它做什么 | 你能看到什么 | 卡在哪 |
|---|---|---|---|
| ① 收束 | 把你的话压成模块表和字段表 | 收束卡 | 模块 >4 会先给分期表 |
| ② 建模 | 定字段、键名、种子数据、备份方式 | 数据账 | 有字段没类型就退回 |
| ③ 装配 | 先骨架后模块，一块一存档 | 可运行的 HTML 中间态 | 骨架不通不许填模块 |
| ④ 体检 | 两个脚本 + 人工四项 | 出厂单（附原始输出） | 有 error 不交付 |
| ⑤ 上线 | 给链接或给文件 + 备份说明 | 链接 / 文件 | 未体检通过不给链接 |

## 六、输出文件怎么用

### 打开

- 电脑：双击 `台子.html`，默认浏览器打开；
- 手机：把文件传到手机（微信文件传输助手 / 微信收藏 / 云盘），用浏览器打开；或让它部署成链接后直接访问；
- 加到桌面：浏览器菜单 →「添加到主屏幕」，之后像 App 一样打开。

### 数据在哪

在本机浏览器的 `localStorage` 里，键名以 `czl_desk_` 开头。**不上传、不联网、不进服务器。**

- 换设备 / 换浏览器 / 清理浏览数据 → 数据不会自己过去；
- 备份：点页面里的"导出 JSON"，得到 `{app}_{日期}.json`；
- 恢复：点"导入 JSON"，选那个文件；
- 清空：需要输入"清空"两个字二次确认。

### 部署成链接（要分享时才做）

运行环境有发布能力时，它会直接给链接；没有时会给文件 + 一段通用静态托管说明，**不会假装有链接**。

## 七、三个检查工具怎么用

```bash
cd skills/deskforge-build-kit

# 合规体检：外链、字号、点击尺寸、键名前缀、模块数、体积、viewport、安全区、TODO
python scripts/blueprint_lint.py --file 台子.html --prefix czl_desk_

# 结构体检：缺失 id、渲染函数成环、初始化入口、未定义调用
python scripts/dom_probe.py --file 台子.html

# 收束卡：模块超 4 个直接拒绝
python scripts/spec_card.py --input 需求.json --out 收束卡.md
```

参数补充：`--json` 输出机器可读结果；`--strict` 让 warning 也算不通过；`--allow a,b` 给 `dom_probe` 加白名单；`--init x.json` 生成需求模板。

**退出码**：`0` 通过 ｜ `1` 有警告 ｜ `2` 有错误（含模块超限）。

## 八、限制与已知问题

| 项 | 现状 | 影响 |
|---|---|---|
| 检查脚本是静态分析 | 不认识 JS 语义，正则/模板字符串做了跳过处理，仍有极小概率误判 | 误判时看输出里的原文定位，人工确认 |
| 浏览器 API 白名单 | 未列入白名单的 API 会以 warning 报"疑似未定义" | 用 `--allow` 加白名单，不影响结论 |
| localStorage 容量 | 约 5MB，因浏览器而异 | 大量文本记录会写满，脚本不检测容量 |
| 数据同步 | 不做 | 换设备必须手动导出导入；如需云同步要另外接入服务 |
| 部署能力 | 取决于运行环境 | 无发布能力时只给文件 |
| 儿童向尺寸 | 提供 50px 规则，但脚本只校验 44px 下限 | 儿童场景需人工确认 |
| 体检覆盖 | 不检查视觉美观、不检查业务正确性 | 只保证"能开、能点、不丢"，不保证"好看、算得对" |

## 九、常见问题

**Q：它会不会一次给我 8 个模块？**
不会。超过 4 个它会先给分期表，本期只做 3 块，你点头才继续。

**Q：能不能不要体检，直接给我文件？**
能，但它会先告诉你代价（手机点不中、断网白屏、换设备丢数据），并在交付里写明"未体检"。

**Q：我想加一个模块怎么办？**
直接说加什么。它会当作新一轮收束处理，只加不改：旧数据不动、新键名带新版本号。

**Q：它做的台子会联网吗？**
不会。零外链、零请求。你可以拔网线验证。

**Q：数据会不会被别人看到？**
数据在你本机浏览器里。但如果部署成公开链接，**任何人都能打开这个页面**——只是看到的是他自己浏览器里的空数据，看不到你的记录。

**Q：能改成中文以外的界面吗？**
可以，生成时说明语言即可；脚本的中文检查项只针对代码结构，与界面语言无关。
