# 工序 ⑤ 上线

## 名称

上线（Release）——给链接或给文件，两句话讲清怎么用。

## 任务职责

把体检通过的文件交到用户手上，并且让他知道：怎么打开、数据在哪、怎么备份、以后怎么加块。

## 输入参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `file` | 是 | 体检通过的单文件 |
| `ship_sheet` | 是 | 出厂单（证明体检过了） |
| `need_link` | 否 | 用户是否要"能在手机上用 / 要发给别人"，默认否 |
| `platform` | 否 | 目标平台（微信 / 手机浏览器 / 电脑） |

## 执行步骤

```
1  判断交付形态
     need_link = 是 → 走部署，拿 URL
     need_link = 否 → 直接给文件 + 打开方式
2  若部署：部署后自己打开一次，确认移动端布局正常，再给链接
3  写交付说明（三条，不多写）：
     ① 怎么打开（双击 / 浏览器打开 / 加桌面）
     ② 数据在哪（本机浏览器，换设备要导出）
     ③ 怎么备份（导出 JSON，建议每周一次）
4  交代迭代方式：以后加块走"报需求 → 收束 → 装配 → 体检"，
   一次只加一块，旧数据不动，新键名带新版本号
5  附上出厂单与文件名，结束
```

## 判断条件

**给链接前**

- [ ] 出厂单结论为"通过"或"有条件通过"且条件已满足
- [ ] 自己在手机上打开过一次，首屏正常
- [ ] 链接能复制、能重新打开

**给文件前**

- [ ] 文件名不含空格与特殊字符（建议英文或拼音）
- [ ] 用户明确知道"这是一个 HTML 文件，用浏览器打开"

## 输出格式

对话里三句话 + 文件，模板：

```markdown
做好了。{n} 块：{模块名简列}。体检 `error 0 / warning {n}`，出厂单在附件。

打开方式：双击 `{filename}.html`，或手机浏览器打开同一个文件。
数据在你自己的浏览器里；换设备前点一次"导出 JSON"，到新设备再"导入"。
要加到手机桌面：浏览器菜单 → 添加到主屏幕。

以后想加一块，直接说加什么；旧数据不会动。
```

## 异常处理

| 情况 | 处理 |
|---|---|
| 运行环境不支持部署 | 给文件 + 一段通用部署说明（任选静态托管），不假装有链接 |
| 用户要求"发到群里给同事用" | 提醒：链接公开可访问，页面本身不含数据；各自填各自的数据，互不可见 |
| 用户想放到微信里直接打开 | 说明微信不打开本地 HTML，必须用链接；给部署路线 |
| 部署后移动端出问题 | 回工序 ③ 修，重新部署；不要把"电脑上正常"当交付标准 |
| 用户问"数据会不会被看到" | 明确：数据在本机浏览器，不进服务器；但公开链接任何人都能打开这个页面 |

## 必要依赖

- 运行环境的网页发布能力（可选）
- 工序 ④ 的出厂单

## 与其他工作流的关系

- **上游**：`04-体检.md`
- **下游**：迭代时回到 `01-收束.md`（新增需求当作新一轮收束处理）
- **不做**：不在本工序改代码；不改需求；不承诺效果
