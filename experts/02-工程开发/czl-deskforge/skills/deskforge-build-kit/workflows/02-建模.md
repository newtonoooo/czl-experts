# 工序 ② 建模

## 名称

建模（Data Ledger）——先给数据定规矩，再动手画界面。

## 任务职责

把收束卡里的字段草案，定成一张可执行的数据账：实体、字段、类型、键名、种子数据、读写路径、迁移方式。数据定不死，界面一定会返工。

## 输入参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `scope_card` | 是 | 工序 ① 的《收束卡》（至少要有字段草案） |
| `prefix` | 是 | 存储键前缀，本产品固定 `czl_desk_` |
| `seed_policy` | 否 | 种子数据条数，默认 4 条（含 1 条逾期/异常） |
| `migrate_from` | 否 | 若已有旧版本数据结构，给出旧键名与字段 |

## 执行步骤

```
1  拆实体：一个模块通常 1 张表；出现「一对多」才拆第二张（如 分类 ← 明细）
2  定字段：每个字段给 名字 / 类型 / 示例 / 是否必填
     类型只有五种：文本 text、数字 number、日期 date、枚举 enum、布尔 bool
     枚举必须列出全部取值
3  定键名：czl_desk_{台子名}_{实体}_{版本}，版本从 v1 起
4  定种子：3–5 条假数据，其中 1 条处于逾期/超支/断签状态；日期用相对今天的偏移，
     不许写死具体日期（写死会让示例半年后全部失效）
5  定备份：导出 JSON（含版本号与导出时间）/ 导入 JSON（校验版本，失败要给提示，不许静默覆盖）/ 清空（二次确认）
6  定迁移：键名带版本号；读到旧版本时按字段映射升级，升不动的字段丢弃并提示
7  出账：落盘《数据账》
```

## 判断条件

**必须全部为"是"**

- [ ] 每个字段都有类型与示例值
- [ ] 枚举字段的取值已列全
- [ ] 所有键名都带 `czl_desk_` 前缀与版本号
- [ ] 种子数据 3–5 条，含 1 条逾期/异常；日期为相对偏移
- [ ] 导出 / 导入 / 清空三条路径都存在，且清空有二次确认
- [ ] 数字字段的精度与单位写明（元 / 分钟 / 次 / 千克）
- [ ] 排序键写明（按日期倒序 / 按创建时间正序）

## 输出格式

```markdown
# 数据账 · {台子名} · {日期}

**存储键**：`czl_desk_{name}_tasks_v1`（主表）、`czl_desk_{name}_budget_v1`（配置）

## 一、实体与字段

### 实体 1：task（待办）
| 字段 | 类型 | 单位/取值 | 必填 | 示例 |
|---|---|---|---|---|
| id | text | 时间戳+随机 | 是 | `t_1758361200_81` |
| title | text | ≤40 字 | 是 | 整理错题本 |
| due | date | YYYY-MM-DD | 否 | 今天-1 |
| done | bool | true/false | 是 | false |
| priority | enum | P0/P1/P2 | 是 | P1 |

**排序**：done 升序 → priority 升序 → due 升序
**索引**：按 due 取"今天/逾期"两组

## 二、种子数据（4 条，含 1 条逾期）
1. 整理错题本 / 昨天 / 未完成 / P0 ← 逾期
2. 完成数学卷一套 / 今天 / 未完成 / P0
3. 背单词 30 个 / 今天 / 已完成 / P1
4. 复盘周计划 / 明天 / 未完成 / P2

## 三、备份与迁移
- 导出：`{app}_{YYYYMMDD}.json`，结构 `{version, exported_at, data:{...}}`
- 导入：校验 `version`；不匹配走迁移；失败提示"文件格式不对"，不覆盖现有数据
- 清空：二次确认（需输入"清空"两个字）
- 迁移：v1 → v2 时 `priority` 缺失按 P1 补齐
```

## 异常处理

| 情况 | 处理 |
|---|---|
| 字段超过 12 个 | 拆表：主表存核心、明细表存扩展，避免一行太长难维护 |
| 用户要存图片 | 说明超出本产品范围（localStorage 容量与体积风险），改为存文字备注或外部链接文本 |
| 已有旧数据 | 先写迁移映射，再改结构；迁移失败要回滚到旧键，不许半途丢数据 |
| 两个模块共用一张表 | 允许，但要在账里写明"共享"，并在渲染时按模块过滤，避免互相污染 |
| 金额涉及小数 | 统一存"分"（整数），显示时除 100，避免浮点误差 |
