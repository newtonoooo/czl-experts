### 二、设计要点

1. **模块不再靠清单**：把"二十多个模块"改成"五种卡片原语 + 参数"，用组合覆盖场景；好处是可解释、可校验、不会越做越乱。
2. **质量可执行**：把规范条目落成三个脚本，出厂单必须附脚本原始输出，避免"我觉得没问题"式交付。
3. **规模有闸门**：模块 ≤4 写进脚本（`spec_card.py` 直接拒绝），不靠自觉。
4. **数据先定账**：字段、键名、种子、迁移在写页面前定死，减少返工。
5. **可回滚装配**：骨架先行 + 一块一存档，坏了回滚而不是边坏边修。

### 三、已知限制（首发版本）

| 限制 | 说明 |
|---|---|
| 静态分析有边界 | 脚本不做 JS 语义分析，极少数写法可能误判（已在 USAGE 第八节列明） |
| 不检查视觉与业务正确性 | 只保证能开、能点、不丢，不保证好看与口径正确 |
| 无云同步 | 换设备需手动导出导入 |
| 儿童向尺寸只做提醒 | 脚本校验 44px 下限，50px 规则靠人工确认 |
