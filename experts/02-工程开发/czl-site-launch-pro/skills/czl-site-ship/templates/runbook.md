## 三、上线步骤

| # | 动作 | 命令 / 操作 | 怎么确认成功 | 失败怎么办 |
|---|---|---|---|---|
| 1 | 构建 | `npm run build` 或 无需构建 | 产物目录文件数 > 0 | 看构建日志，不要重试第二次 |
| 2 | 备份上一版 | | 上一版可访问 | 停止上线 |
| 3 | 上传/发布 | | 首页 200 | 执行第五节回滚 |
| 4 | 静态资源校验 | `curl -I https://域名/assets/...` | 全部 200，content-type 正确 | 查路径与 MIME |
| 5 | 404 校验 | `curl -I https://域名/不存在` | 返回 404 且是自定义页 | 查 `try_files` / 托管配置 |
| 6 | 索引资料校验 | `curl -I /robots.txt`、`/sitemap.xml` | 200 且内容正确 | 补文件 |
| 7 | 表单/联系入口 | 实际提交一次 | 能收到 | 先挂备用联系方式 |
| 8 | 手机实机抽查 | 真机打开首页与一个内页 | 不错位、按钮可点 | 记录，不回滚 |

## 四、回滚

**触发条件（任一即回滚，不需要请示）：**

- 首页或关键页返回 5xx
- 静态资源大面积 404
- 表单完全收不到且无备用通道
- 证书报错导致浏览器拦截

**回滚命令（可直接复制）：**

```bash
# 方式一：平台回滚
<平台控制台路径 或 CLI 命令>

# 方式二：服务器软链回退
ssh user@host 'ln -sfn /srv/site/releases/<上一版> /srv/site/current && nginx -s reload'

# 方式三：对象存储覆盖
<上传上一版产物的命令>
```

- 回滚后验证：首页 200、关键页 200、资源 200

## 六、出事时的顺序

止血 → 恢复 → 查因 → 防复发。

不要在用户访问不了的时候研究根因；不要在生产上直接改代码试；不要在没回滚的情况下"再改一版看看"。
