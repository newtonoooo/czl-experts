# 闸门 W1–W3：立项、选型、骨架

这三道闸只解决一件事：**在写第一行代码之前，把"做什么"和"用什么做"钉死。**

钉不死的结果每个做过外包的人都见过：改了七版还在改首页文案，因为一开始没人问"这页看完要让人干什么"。

---

## 何时用

- 用户只有一句话的想法（"我想做个官网"）
- 用户在两个技术方案之间犹豫，或者根本没意识到这是个选择
- 要开项目，需要一份能让人接手不被骂的目录结构
- 老项目要重做，先得知道哪些东西必须原样保留

---

## W1 · 立项单七问

七个问题，答不上来的先记"待定"，但**不许跳过**。跳过的问题会在 W4 变成返工。

| # | 问题 | 为什么问 | 答不上来的后果 |
|---|---|---|---|
| 1 | 谁来看？（一个人还是一群人，他什么身份） | 决定信息层级和语气 | 首页写成公司简介合集 |
| 2 | 他来看什么？（三秒内要看到的那句话） | 决定首屏放什么 | 首屏放轮播图，没人看第二张 |
| 3 | 看完要做什么？（打电话/下单/加微信/投简历） | 决定行动按钮的位置和数量 | 页面很漂亮，没人联系你 |
| 4 | 他从哪来？（搜索/朋友圈/名片二维码/线下物料） | 决定 SEO 权重和落地页数量 | 一个页面扛所有渠道 |
| 5 | 主要在什么设备上看？（手机占比多少） | 决定断点优先级 | 桌面端精美，手机端错位 |
| 6 | 什么时候要？（有没有硬期限） | 决定做几页、砍什么 | 交期前三天才发现素材没给 |
| 7 | **不做什么？** | 划范围，防蔓延 | 无限加页、无限改稿 |

第 7 问是这份单子最值钱的一问。写不下"不做"的项目，一定会失控。

**素材清单同时确认**：文案谁写、图片哪来、Logo 有没有矢量文件、域名和备案在谁名下。这四项缺任何一项，W4 一定卡住。

立项单落到 `templates/brief.md`，一页写完，给用户确认后才进 W2。

---

## W2 · 选型三问

不问"你想用什么框架"，问三个和用户有关的问题。技术偏好排在能力之后。

| 问题 | 若答案是 | 选 |
|---|---|---|
| 内容是固定几页，还是经常新增文章/产品？ | 固定 3–8 页 | 纯静态 HTML/CSS/JS，或轻量 SSG |
| | 持续新增内容 | SSG（Astro / Hugo / Eleventy）；要后台就上 CMS |
| 有没有登录、支付、实时数据？ | 没有 | 静态托管（对象存储 + CDN） |
| | 有 | 需要服务端：Next.js / Nuxt / 后端 API |
| 以后谁维护？会改代码吗？ | 不会改代码，只改文字 | SSG + Markdown，或接 CMS |
| | 会改代码 | 常规前端框架 + 组件化 |

判据细节与反例见 `references/stack-matrix.md`。**默认倾向静态**：能静态就不上框架，能少依赖就不少装。原因不是保守，是静态站几乎不会因为版本升级而坏。

选型结论必须写成三句话：选了哪个、为什么、放弃的另一个方案会多付出什么代价。

## W3 · 骨架

骨架不是"空文件夹"，是一份能让人一眼看懂职责的结构。

```
site/
├── index.html            # 首页：首屏承诺 + 三个证据 + 一个行动
├── about.html            # 关于：谁在做、凭什么信
├── contact.html          # 联系：表单 + 备用联系方式
├── 404.html              # 找不到时的出口
├── assets/
│   ├── css/site.css      # 全站样式，一个文件起步
│   ├── js/site.js        # 全站交互，无框架
│   └── img/              # 图片，按用途命名
├── robots.txt            # 爬虫规则
├── sitemap.xml           # 站点地图（W5 生成）
└── README.md             # 怎么改、怎么发、改坏了怎么退
```

骨架阶段的四条判据：

1. 每个页面有唯一职责，一句话能说清
2. 每个文件有唯一职责，不出现 `utils2.js`
3. 导航从任意页能回到任意页，不出现死路
4. 空壳能跑起来（本地起服务能看到页面），先跑通再加内容

---

## 判断条件

| 情形 | 判断 | 动作 |
|---|---|---|
| 七问里 3 个以上"待定" | 立项未完成 | 只做单页试用版，别承诺全站 |
| 用户坚持要"高端大气"但不给参考 | 需求空转 | 要 3 个他喜欢的站，指着说喜欢哪一块 |
| 用户要的功能需要后端（登录/支付） | 超出静态范围 | 明说成本变化，给两条路：先做展示版 / 直接上带服务端的方案 |
| 素材（文案/图/Logo）没有 | 阻塞 W4 | 用占位内容先跑结构，明确标注哪些是占位 |
| 老站重做 | 保留清单优先 | 先列出"必须原样保留的 URL"，避免掉收录 |

## 输出格式

```
立项结论
七问：1 … 2 … 3 … 4 … 5 … 6 … 7 不做什么：…
素材：文案 <有/无> 图片 <有/无> Logo <有/无> 域名 <有/无> 备案 <有/无>
范围：必做 <页面清单> ｜ 本期不做 <清单>

选型
选定：<方案>　理由：<三句以内>
放弃：<方案>　代价：<一句>

骨架
<目录树>
第一个可运行命令：<命令>
```

---

## 异常处理

- **用户答不上七问**：不要替他编。给三个选项让他选（"来看的人主要是找工作的人、还是来采购的人？"），选完再落单。
- **用户中途加页面**：回到立项单，把新页面写进"本期不做"，说明加进去要延后什么。不在群里口头答应。
- **用户给的是竞品站**："照着这个做"要拆成三件事：结构像不像、内容像不像、视觉像不像。通常只有结构可以像，视觉照搬有版权风险。
- **立项后才发现技术不可行**：立刻停下回到 W2，不要在 W4 硬扛。硬扛的成本是重写。
