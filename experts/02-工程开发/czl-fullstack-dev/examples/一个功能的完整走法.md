# 示例：一个功能的完整走法

用一个虚构需求把六段线走一遍，看清每一步的产出物长什么样。

---

## 起点：用户的一句话

> 我想给客户加个"报价单"功能，销售填几个数，系统生成一份能下载的 PDF。

这句话里没有一条能验收。按 G0 定桩处理。

---

## G0 定桩

**先问四件事：**

- 谁用：销售（内部，约 10 人）
- 场景：电话沟通后当场生成发给客户
- 做完能看到什么：填完表单点生成，10 秒内下到一份带公司抬头的 PDF
- 什么情况下不能这么做：不能让客户看到成本价；金额不能让销售随意改单价

**改成条目（摘录）：**

```
A1 生成报价单
   操作：填客户名、3 个明细项（名称/数量/单价），点生成
   预期：10 秒内下载到 PDF，含公司抬头、报价单号、日期、明细与合计
   反例：明细为空 → 提示"至少填一项"，不生成文件
   证据：一次成功生成的 PDF 首页截图 + 响应耗时

A2 成本价不可见
   操作：销售账号打开报价单页面
   预期：页面与 PDF 中均不出现成本价字段
   反例：直接在接口返回里查 cost 字段 → 不存在
   证据：接口响应体片段

A3 单价只读
   操作：修改单价输入框的 value 后提交
   预期：服务端以产品库价格为准，提交的单价被忽略
   反例：构造请求把单价改成 0.01 → 生成的合计仍按库价
   证据：两次请求的返回金额对比

A4 重复生成
   操作：连点两次生成按钮 / 超时重发同一请求
   预期：只产生一个报价单号
   反例：同一请求连发两次 → 返回同一单号
   证据：两次响应的订单号
```

四条够了。数量少是因为这次只做"生成"，不做"修改/作废"。

**一页方案（要点）：**

- 选型：现有 Node 服务 + `pdfkit` 生成，不引新框架
- 数据：`quotes` 表（id, no, customer, items jsonb, total, created_by, created_at）
- 接口：`POST /api/quotes` 生成、`GET /api/quotes/:id/pdf` 下载
- 风险：**中文字体在 PDF 里的嵌入**——这是最不确定的一点，先做
- 第一片：只做"能生成一份带中文的 PDF"，不含业务字段

**闸门：** 把四条条目 + 方案交给用户，问"第 3 条我理解成服务端以库价为准，对吗"。用户确认后开工。

---

## G1 切片

| 切片 | 内容 | 覆盖 | 风险 |
|---|---|---|---|
| S1 | 中文字体 PDF 最小生成（固定内容） | — | 高：字体嵌入 |
| S2 | 表单 + 生成接口 + 落库 | A1 A4 | 中 |
| S3 | 成本价隔离 + 单价以库为准 | A2 A3 | 中：涉及权限与数据来源 |

S1 不覆盖任何验收条目，这很正常——它是技术探路片。**探路片允许不销号，但必须半天内出结论。**

---

## G2 实现（S1 的汇报示例）

```
完成：S1 中文 PDF 最小生成｜无验收编号（探路片）
改动：src/pdf/render.ts — 注册中文字体并渲染一行中文；assets/fonts/ 放入思源黑体子集
证据：生成 output.pdf 后打开截图，中文正常；文件 38KB（含字体子集）
下一步：S2 表单与接口
```

S1 出了问题（字体全变方框），处理方式：

1. 读第一处错误：`Font doesn't support this character`
2. 定位：用了仅含拉丁字符的内置字体
3. 一次性解决：换带中文的字体子集，并在 `render.ts` 里加一条注释说明为什么不能用默认字体
4. 回归：再生成一次，中文正常

这就是"先定位再改"，而不是反复换字体试运气。

---

## G3 验证

| 层 | 做了什么 | 结果 |
|---|---|---|
| L1 | 明细为空、数量为负、单价为 0、超长客户名 | 4/4 符合预期 |
| L2 | 连真实 Postgres 跑迁移 up/down/up；生成后查库核对 items 与 total | 通过 |
| L3 | A1 生成并下载（截图）、A2 查接口无 cost 字段、A3 构造 0.01 请求金额未变、A4 连发两次同单号 | 4/4 通过 |

## G4 上线

| 项 | 状态 |
|---|---|
| 迁移可回退 | ✅ 建表可 down |
| 备份可恢复 | ✅ 上线前全量导出，核对行数 |
| 健康检查 | ✅ /health 200 |
| 错误可查 | ✅ requestId 已接入 |
| 回滚可执行 | ✅ 回滚命令实际执行过一次 |
| 指标阈值 | ⚠️ 暂无告警，临时人工盯 24 小时 |

结论：**有条件上线**，条件是 24 小时内人工盯错误日志，一周内补告警。

---

## G5 交接

一页纸里写清：`pdfkit` 的字体子集怎么重新生成（这是最容易忘的一步）、报价单号的生成规则、PDF 模板在哪个文件、已知限制（暂不支持自定义抬头）。

---

## 这条线体现的三件事

1. **条目先行**：没有 A1—A4，S1 的字体问题会在上线前一天才被发现。
2. **风险前置**：最不确定的字体问题放在第一片，半天出结论，而不是放在最后。
3. **闸门是硬的**：告警没做就写"有条件上线"，不写"基本没问题"。
