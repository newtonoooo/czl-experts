# 体检与提审预检（W5 / W6）

## 什么时候用

- 页面写完，要确认四件套齐全、组件引用能解析
- 主包快满了，要定位是哪个文件在吃体积
- 提审前要一份"我现在到底缺什么"的清单
- 提审被拒，要逐条定位到代码
- 交接给别人前，要一份客观现状

## 输入

| 输入 | 必需 | 说明 |
|---|---|---|
| 工程目录 | 是 | 含 `app.json` 的那一层，或含 `project.config.json` 的上一层 |
| 驳回原文 | 整改时必填 | 照抄，不转述 |
| 上一版体检报告 | 否 | 用于对比"改了什么" |

## 四个命令怎么用

```bash
# 1. 静态体检：页面、分包、tabBar、组件引用、隐私接口、密钥、外链
python scripts/wx_doctor.py scan <项目>

# 2. 体积预算：主包/分包字节、占比、大文件排行
python scripts/wx_doctor.py budget <项目>

# 3. 提审预检：汇总 + 提审材料清单 + 采集接口清单
python scripts/wx_doctor.py preflight <项目>

# 4. 生成骨架（W1 用）
python scripts/wx_doctor.py scaffold --spec spec.json --out ./miniprogram
```

常用参数：`--root <子目录>` 手动指定根目录；`--out <目录>` 改报告输出位置（默认 `docs/体检`）；`--json` 额外存一份机器可读结果。

退出码：`0` 无阻断项 / `1` 有 P0 / `2` 参数或结构错误。可以直接接在 CI 或交付脚本后面。

## 判读规则（怎么读这份报告）

| 级别 | 含义 | 处理 |
|---|---|---|
| **P0** | 阻断：功能跑不通、安全有洞、体积传不上去 | 必须改完才能提审，一条都不许留 |
| **P1** | 应修：明显影响体验或大概率被问 | 本次迭代内改掉，改不掉的写进风险表并说明 |
| **P2** | 建议：优化项或需人工判断的提示 | 记录，排期处理 |

**三条硬规矩：**

1. **P0 不清零不提审。** 不存在"这个应该没事"。
2. **报告里出现的"未发现"，不等于"一定没有"。** 静态扫描盲区见 `references/checks-catalog.md`，拿不准的写成"需人工确认"。
3. **体积两个数都要看。** 本工具算磁盘字节，开发者工具算压缩后上传体积，差 10%-30% 正常；上线前以开发者工具为准。

## 步骤（提审前标准流程）

1. 跑 `scan`，把 P0 全部改掉。
2. 跑 `budget`，确认主包占比 < 85%；超了就回 W1 重新切分包。
3. 跑 `preflight`，照输出的材料清单逐项准备。
4. 人工补三件脚本管不了的事：
   - 真机走一遍主流程（不同机型至少两台，一台小屏一台大屏）
   - 视觉检查（错位、遮挡、安全区）
   - 审核口径判断（类目是否选对、功能描述是否与实际一致）
5. 把报告存进 `docs/体检/`，两次对比看改了什么。

## 输出

1. `docs/体检/scan-*.md` / `budget-*.md` / `preflight-*.md`
2. 报告里的 P0/P1/P2 表（可直接贴进交付说明）
3. 提审材料清单（preflight 输出）
4. 残留风险表（脚本覆盖不到的，人写的）

## 异常处理

| 异常 | 处理 |
|---|---|
| 报"没找到 app.json" | 用 `--root` 指定；跨端框架要指到编译产物目录 |
| 工程是 uni-app/Taro 源码目录 | 扫描意义有限，改扫编译产物（`dist/` 或 `unpackage/`），并说明降级 |
| 报告写入失败 | 控制台输出仍然完整，可手工另存 |
| 检查项误报 | 在报告里标注"误报 + 原因"，不要为了好看去改代码 |
| 用户要求"帮我把报告改好看点" | 拒绝：报告是证据，不是宣传材料 |

## 依赖

- `scripts/wx_doctor.py`
- `references/checks-catalog.md`（每条检查的判读与盲区）
- `references/preflight-materials.md`（提审材料与常见驳回对照）
- `references/troubleshooting.md`（白屏/卡顿/报错的排查树）

## 与其它工作流的关系

- 上游：W2 页面、W3 能力、W4 数据层都完成
- 下游：提审；被拒回 W6，用同一套检查定位
- 回流：`scan` 报的结构性问题（如目录混乱）要回 W1 修

## 自检

- [ ] P0 = 0，且每条都有整改记录
- [ ] 体积有真实数字，不是"差不多"
- [ ] 报告存档，前后两版能对比
- [ ] 脚本管不了的三件事（真机/视觉/口径）已人工过
- [ ] 残留风险单列，没有藏在正文里
