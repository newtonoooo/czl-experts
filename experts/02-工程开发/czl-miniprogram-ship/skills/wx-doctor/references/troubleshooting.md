# 排查树：白屏、卡顿、报错、数据不渲染

> 脚本能查结构问题，查不了运行时问题。这份排查树是补那一块的。原则：**先看第一行错，再猜原因。**

## 一、白屏

按这个顺序走，不跳步：

```
白屏
├─ ① 开发者工具 console 有没有红色报错？
│   ├─ 有 → 按报错信息定位（见第三节）
│   └─ 没有 → ②
├─ ② 页面路径是否正确注册？
│   ├─ app.json 的 pages 里有没有这个页面 → scan SCAN-002
│   └─ 分包页面是否在对应 subpackages.pages 里 → scan
├─ ③ 页面 .wxml 是否为空或有语法错？
│   ├─ 标签没闭合 → 编译器应该会报，但偶发不报
│   └─ 根节点用了 wx:if 且条件恒假 → 表现为白屏
├─ ④ 是否有 JS 异常中断了 onLoad？
│   ├─ onLoad 里第一行就 throw → 后面全不执行
│   └─ 常见：this 指向错误、解构 undefined
├─ ⑤ 样式问题导致的"假白屏"
│   ├─ 内容被 position: fixed 的遮罩盖住
│   ├─ 父级 height: 0 或 overflow: hidden
│   └─ 字体色 = 背景色
└─ ⑥ 真机才白屏、工具正常
    ├─ 接口域名未配置（工具可关 urlCheck，真机不行）
    ├─ 用了工具支持但基础库不支持的能力
    └─ 自定义组件路径大小写不一致（Windows 不敏感，iOS 敏感）
```

## 二、卡顿 / 掉帧

| 现象 | 先查这个 | 处理 |
|---|---|---|
| 列表滚动卡 | `setData` 频率与数据量 | 只传变化字段；分页；用局部路径更新 |
| 首次进入慢 | 主包体积、首屏请求数 | 分包 + 预下载；请求合并；骨架屏 |
| 点按钮反应慢 | 是否在点击里做了重计算 | 计算挪到 `onLoad` 或后端 |
| 图片加载慢 | 图片尺寸与数量 | 缩略图 + `lazy-load` + CDN |
| 反复进出页面越来越卡 | 定时器/监听未清理 | `onUnload` 清 `setInterval`、`wx.offXxx`（scan SCAN-071） |
| 长列表滚动白块 | 一次渲染太多节点 | 分页或虚拟列表 |

## 三、常见报错对照

| 报错关键词 | 含义 | 处理 |
|---|---|---|
| `Failed to load local image resource` | 图片路径错或文件不存在 | 检查相对路径基准（是页面目录还是根目录） |
| `Component is not found in path` | 组件路径解析不到 | 查 `usingComponents`（scan SCAN-030） |
| `request:fail url not in domain list` | 域名未配白名单 | 后台配置；工具里可关 urlCheck 但真机必配 |
| `setData 数据传输长度`相关 | 一次 setData 数据太大 | 拆批、只传必要字段 |
| `Cannot read property 'xxx' of undefined` | 数据未就绪就渲染 | 加默认值、用 `&&` 保护 |
| `thirdScriptError` | 第三方脚本错误 | 看完整堆栈，定位到具体库 |
| `subpackage xxx not found` | 分包路径与声明不一致 | 查 `root` 与 `pages` 拼接 |

## 四、数据不渲染（最常被误判为"接口没返回"）

按这个顺序查，别一上来就怪后端：

1. **`setData` 的键名与 WXML 绑定名是否一致**（`list` vs `lists`，这类错占一半）
2. **`setData` 是否在 `this` 正确的作用域里调用**（回调里 `this` 丢失，用箭头函数）
3. **数据是否在渲染时还没到**（首帧 undefined，后续到了但没触发重渲染）
4. **`wx:for` 是否漏了 `wx:key` 或 item 名称写错**（`wx:for-item` 自定义后仍用默认名）
5. **条件渲染是否把内容挡住了**（`wx:if` 恒假，最隐蔽）

## 五、样式不生效

1. 组件样式隔离：默认 `isolated`，外部样式进不去 → 用 `externalClasses` 或 `styleIsolation`
2. `rpx` 与 `px` 混用导致尺寸不对（不是"不生效"，是"看着不对"）
3. 选择器优先级被覆盖（尤其用了 UI 库）
4. 自定义组件根节点没有样式承载（组件内最外层 view 没写样式类）
5. 真机与工具差异：某些 CSS 属性在低版本基础库不支持

## 六、真机与工具不一致时的通用套路

```
1. 真机打开调试（vConsole），看 console
2. 对比：工具关掉 urlCheck 后正常 / 真机不正常 → 域名问题
3. 对比：新机型正常 / 旧机型不正常 → 基础库或 CSS 支持问题
4. 对比：iOS 不正常 / Android 正常 → 多为日期解析（'2026-01-01' 在 iOS 上要 '2026/01/01'）
5. 仍不定 → 二分法：注释掉一半逻辑，看是否恢复
```

## 七、写在最后

排查出来的每个问题，**都要回写台账**（新条目或风险项）。同一个坑踩两次，通常是第一次没记。
