# 检查项目录（含盲区）

> 每条检查都写明：查什么、怎么判、什么情况下会误报或漏报。**漏报的部分一律标注为"需人工确认"，不许当成通过。**

## scan

| 编号 | 级别 | 检查内容 | 判定 | 盲区 / 可能误报 |
|---|---|---|---|---|
| SCAN-001 | P0 | `app.json` 的 `pages` 是否为空 | 空数组或缺失 | 无 |
| SCAN-002 | P0 | 页面四件套是否齐全 | `pages` 与分包页面逐个查 `.js`（或 `.ts`）与 `.wxml` | `.json`/`.wxss` 缺了不报（微信允许缺省）；跨端框架的源码目录不适用 |
| SCAN-010 | P1 | tabBar 项数 | 少于 2 或多于 5 | 官方建议值可能调整，以 `app.json` 文档为准 |
| SCAN-011 | P0 | tabBar 页面是否在 pages 里 | `pagePath` 不在 `pages` 中 | 无 |
| SCAN-012 | P1 | tabBar 图标文件是否存在 | 拼根目录后文件不存在 | 图标用网络地址时无法判断 |
| SCAN-013 | P2 | tabBar 图标体积 | 超过 40KB | 官方建议值需核实，仅供参考 |
| SCAN-020 | P1 | 分包 root 目录是否存在 | 磁盘上没有该目录 | 分包代码来自 npm 构建产物时情况不同 |
| SCAN-021 | P1 | 独立分包是否有页面 | `independent` 为真但 `pages` 为空 | 无 |
| SCAN-022 | P1 | 是否有未声明的分包目录 | 一级目录下存在 `.wxml` 但不在 `subpackages` 里 | 组件目录、静态资源目录会被排除，仍可能误报，需人看一眼 |
| SCAN-023 | P2 | `preloadRule` 的键是否为真实页面 | 键不在 `pages` 中 | 无 |
| SCAN-024 | P2 | `preloadRule` 引用的分包是否存在 | 值与分包 root/name 都不匹配 | `__DEFAULT__` 已排除 |
| SCAN-030 | P1 | `usingComponents` 路径能否解析 | 绝对/相对路径拼出的 `.js` 不存在 | npm 包与 `plugin://` 已跳过；大小写敏感问题在 Windows 上可能漏报 |
| SCAN-040 | P0 | 隐私接口是否已在 `requiredPrivateInfos` 声明 | 代码里出现 `wx.getLocation` 等但未声明 | 动态调用（`wx['get'+'Location']`）识别不到 → 需人工确认 |
| SCAN-041 | P1 | 定位是否有权限用途说明 | 缺 `permission.scope.userLocation` | 无 |
| SCAN-042 | P2 | 采集类接口清单 | 列出 `chooseImage`/`getPhoneNumber` 等 | 只做清单，不做合规裁决；按钮写法与 API 写法都已覆盖但可能新增接口 |
| SCAN-050 | P0 | 前端是否出现密钥明文 | 匹配 AppSecret / 商户密钥 / 私钥特征 | 混淆过的密钥、Base64 编码的密钥识别不到 → 需人工确认 |
| SCAN-060 | P2 | 外部域名清单 | 抓取源码中的 http(s) 地址 | 域名由接口返回或拼接时不完整 |
| SCAN-061 | P1 | 是否有 http 明文域名 | 出现 `http://` | 注释里的地址也会被算进去，可能误报 |
| SCAN-070 | P1 | `setData` 整包刷新 | 出现 `setData(this.data)` 或展开整个 data | 变量间接传递识别不到 |
| SCAN-071 | P1 | 定时器/监听是否未清理 | 有 `setInterval` 但无 `clearInterval`；有 `wx.onXxx` 但无 `wx.offXxx` | 清理写在别的文件里时会误报 |
| SCAN-072 | P2 | console 输出数量 | 超过 10 处 | 无 |
| SCAN-073 | P2 | 是否开启按需注入 | 缺 `lazyCodeLoading` | 无 |
| SCAN-080 | P2 | `sitemap.json` 是否缺失 | 声明了 `sitemapLocation` 但文件不存在 | 无 |

## budget

| 编号 | 级别 | 检查内容 | 判定 |
|---|---|---|---|
| BUD-001 | P0 | 主包超限 | 主包字节 > 2MB |
| BUD-002 | P1 | 主包余量不足 | 主包 > 上限 85% |
| BUD-003 | P0 | 分包超限 | 某分包 > 2MB |
| BUD-004 | P0 | 总体积超限 | 全部合计 > 20MB |
| BUD-005 | P1 | 大文件 | 单文件 > 200KB |
| BUD-006 | P1 | 图片占用过高 | 图片合计 > 单包上限 40% |

**预算的盲区**：按磁盘字节累加，不含开发者工具压缩与 tree-shaking；`packOptions.ignore` 排除的文件本工具仍会算进去，可能高估。若高估很多，先核对忽略配置。

## preflight

除复用 scan 的隐私/密钥/域名/页面检查与 budget 的主包检查外，额外产出：

- **提审材料清单**（固定 7 项，见 `preflight-materials.md`）
- **类目与合规提示**：按代码里出现的能力（支付、手机号、位置、上传、直播、web-view）给出提示
- **采集接口清单**：接口 + 出现位置，用于逐条填隐私指引
- **域名清单**：用于后台配置白名单

**不做的判断**：类目选得对不对、资质够不够、内容是否违规、视觉是否合格。这些必须人工与官方后台核对。

## 覆盖不到的三件事（永远人工）

1. **真机表现**：不同机型、不同系统版本的渲染与性能差异
2. **视觉质量**：错位、遮挡、字号、对比度
3. **审核口径**：审核员对"功能与描述是否一致"的主观判断

这三件写进交付说明的"人工核实项"，不要用脚本结论冒充。
