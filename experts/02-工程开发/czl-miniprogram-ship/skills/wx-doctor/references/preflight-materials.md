# 提审材料与驳回对照

> 平台审核规范、类目与资质要求以微信公众平台后台与官方运营规范为准，且会更新。本文是**准备清单**与**常见驳回的定位思路**，不是规则原文。

## 一、提审七件材料

| # | 材料 | 准备要点 | 缺失的后果 |
|---|---|---|---|
| 1 | 名称 / 简介 / 头像 | 与实际功能一致；不含违禁词；不蹭知名品牌 | 名称被拒，整包退回 |
| 2 | 服务类目与资质 | 按实际功能选，不选"最容易过"的类目 | 类目不符是最常见驳回原因之一 |
| 3 | 用户隐私保护指引 | 逐项填写采集目的，与代码里的采集接口一一对应 | 采集接口直接失败 |
| 4 | 功能演示路径说明 | 写清"从哪进、点什么、看到什么" | 审核员找不到功能 → 判为"功能不完整" |
| 5 | 测试账号 | 若必须登录才能用，必须提供可用账号 | 无法验证功能 → 驳回 |
| 6 | 服务器域名 | request / uploadFile / downloadFile / socket 分别配置 | 真机请求被拦 |
| 7 | 版本号与更新说明 | 每次改动写清，便于审核比对 | 审核时间变长 |

## 二、常见驳回原因 → 定位方向

| 驳回表述（大意） | 大概率问题在哪 | 怎么定位 |
|---|---|---|
| 收集用户信息未说明用途 | 隐私指引缺项，或 `permission.desc` 写成了接口名 | `preflight` 拉采集清单，逐条对指引 |
| 存在强制授权 / 强制登录 | 首次进入就弹授权，或核心功能必须登录 | 搜 `onLaunch`/`onShow` 里的授权调用 |
| 功能不完整 / 无法体验 | 有页面但主流程走不通，或缺测试账号 | 自己按"演示路径"走一遍，不带登录态 |
| 存在诱导分享 | "分享得奖励""分享后解锁""关注才能用" | 搜 `onShareAppMessage` 周边逻辑与文案 |
| 类目与功能不符 | 选了不匹配的类目 | 对照类目说明与实际功能重新选 |
| 涉及虚拟支付 | iOS 端虚拟商品用了微信支付 | 查支付入口是否对 iOS 隐藏 |
| 页面空白 / 报错 | 接口域名未配、页面路径写错 | `scan` 看四件套与域名；真机看 console |
| 内容含违规信息 | UGC 无审核机制 | 查是否有内容安全检测与举报入口 |
| 使用了未开放的能力 | 用了需要资质或未开放的接口 | 查接口文档的开放条件 |

## 三、复审时的写法

驳回后重新提交，建议在审核备注里写三段：

1. **改了什么**：逐条对应驳回意见，一句话一条。
2. **在哪改的**：页面路径或功能入口，让审核员能直接点到。
3. **怎么验**：操作步骤 1-2-3。

不要写"已按贵平台要求整改完毕"这种空话，审核员看不到你改了什么。

## 四、提审前 10 分钟自检

- [ ] `wx_doctor.py preflight` 的 P0 为 0
- [ ] `app.json` 里 `requiredPrivateInfos` 与代码实际调用一致
- [ ] `project.config.json` 的 `appid` 是正式 AppID，不是测试号
- [ ] `setting.urlCheck` 已打开
- [ ] 后端环境指向正式环境，不是测试环境
- [ ] 首次进入不弹授权、不强制登录
- [ ] 主流程在真机上从冷启动走一遍能通
- [ ] 没有 `console.log` 打印用户敏感信息
- [ ] 版本号已更新，更新说明写了
- [ ] 测试账号（如需）可用
