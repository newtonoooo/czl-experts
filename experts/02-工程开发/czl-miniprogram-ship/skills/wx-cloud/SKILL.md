# 云开发数据层（W4）

## 什么时候用

- 用云开发做后端，要建集合
- 要写云函数（登录、下单、内容审核、定时任务）
- 担心权限：普通用户能不能读到别人的数据
- 查询慢，要加索引

## 输入

| 输入 | 必需 | 说明 |
|---|---|---|
| 数据契约 | 是 | 从 W2 页面契约来，字段要对得上 |
| 接口约定 | 是 | 从 W3 来，哪些操作要服务端做 |
| 权限要求 | 是 | 哪些数据谁能读、谁能写 |

## 步骤

1. **集合建模**：一个集合一个职责。字段写清类型、是否必填、是否索引。见 `references/data-model-and-rules.md`。

2. **定权限**：默认不是"所有用户可读写"。四条基本盘：
   - 用户私有数据 → 仅创建者可读写
   - 公开内容（商品、文章）→ 所有人可读，仅管理端可写
   - 有关联关系的（订单）→ 创建者可读，写入一律走云函数
   - 后台配置类 → 所有人可读、无人可写（只能控制台改）

3. **写云函数**：入参校验 → 身份校验 → 业务 → 统一返回结构。见 `references/cloudfunction-patterns.md`。

4. **建索引**：按实际 `where` + `orderBy` 字段建组合索引。列表页最常见的组合是「状态 + 创建时间倒序」。

5. **跑 `scan`**：确认云函数目录有入口文件、前端调用名与云函数名对得上。

## 判断条件

| 情况 | 动作 |
|---|---|
| 集合规则是"所有用户可读写"且含用户数据 | 拒绝，改规则 |
| 云函数不校验调用者身份 | 拒绝，加 openid 校验 |
| 前端直接写订单/余额/库存 | 拒绝，改云函数 |
| 查询没走索引 | 补索引或改查询条件 |
| 云函数把错误堆栈返回前端 | 改成统一错误码 |

## 输出

1. 集合设计表（字段/类型/必填/索引/权限）
2. 安全规则 JSON
3. 云函数代码（含校验与统一返回）
4. 索引清单
5. 越权自测用例（至少三条：读别人数据、改别人数据、伪造身份）

## 异常处理

| 异常 | 处理 |
|---|---|
| 未开通云开发环境 | 先出设计与代码，落地步骤写成待办，不假装已跑通 |
| 已有数据要迁移 | 先出字段映射表，再写迁移脚本，脚本要可重跑（幂等） |
| 云函数超时 | 拆小任务或改异步触发；不要在云函数里做长循环 |
| 权限规则写太复杂 | 简化：把复杂判断挪进云函数，规则只做粗粒度 |

## 与其它工作流的关系

- 上游：W3 的能力接口（登录态、支付回调）
- 下游：W5 体检（前端调用与云函数名一致性）
- 回流：数据模型变了要回 W2 改契约，不能只改后端

## 自检

- [ ] 每个集合都写了权限，没有默认开放
- [ ] 写操作都过云函数（除纯用户私有数据）
- [ ] 云函数校验了调用者身份
- [ ] 查询字段有索引
- [ ] 三条越权用例都试过
- [ ] 错误返回不含堆栈与内部字段名
