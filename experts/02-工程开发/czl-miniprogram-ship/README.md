# 码上线 · 专业级微信小程序交付专家

> 作者：虫志龙（47190078@qq.com）｜ 版本：1.0.0 ｜ 专家标识：`czl-miniprogram-ship`

## 这是什么

一个**把小程序当交付物做**的专家。它不满足于"帮你写几个页面"，而是从一句模糊需求一路推到能提审、能上线、能接手，中途每道闸门都留下证据。

和常见"小程序开发助手"的差别只有一条，但很关键：**它自带一套能跑的体检工具**。包体积、页面四件套、隐私接口声明、密钥泄露、外链域名——这些不是靠"我记得要检查"，而是靠脚本读你的真实工程文件给出结论。

## 它解决的问题

| 你现在的状态 | 它给你的东西 |
|---|---|
| 只有一句想法 | 一页方案 + 编号验收条目 + 可运行骨架 + 体积预算表 |
| 页面写到一半 | 缺失项补齐计划 + 数据契约 + 体检报告 + 剩余风险表 |
| 主包快满了 | 分包切分方案 + 真实字节核算 + 大文件定位 |
| 提审被拒 | 驳回原文逐条对照 + 整改代码 + 复检输出 + 复审说明 |
| 要交给别人 | 交付台账 + 目录地图 + 未完成项 + 环境清单 |

## 三条它坚持的规矩

1. **没有编号条目，不写代码**——"做得好看点"这种需求会被打回重写成可验收的动作。
2. **没有脚本输出，不说"通过"**——脚本覆盖不到的，明写"需人工核实"，不混着说。
3. **不编造 API 与版本**——接口名、基础库版本、平台规则，要么给官方文档路径，要么标注待核实。

## 快速上手

```
1. 描述你的小程序（做不做都行，它先帮你收口需求）
2. 它会产出 docs/一页方案.md 与 docs/acceptance.json（条目台账）
3. 定完骨架跑 python scripts/wx_doctor.py budget <项目>
4. 页面按条目推进，每条绑文件、绑验收动作
5. 提审前跑 preflight，拿到材料清单与 P0 清单
```

详细用法见 [`USAGE.md`](USAGE.md)。

## 七个工作流

| 阶段 | 名称 | 干什么 | 出口物 |
|---|---|---|---|
| W0 | 立项收口 | 需求变条目、定技术栈、扫资质红线 | 一页方案 + acceptance.json |
| W1 | 骨架与预算 | 分包切分、生成骨架、核真实体积 | 可运行骨架 + 预算表 |
| W2 | 页面与组件 | 数据契约 → 四件套 → 三态 | 代码 + 组件接口表 |
| W3 | 能力接入 | 登录/支付/隐私/订阅消息/分享 | 前后端代码 + 配置清单 |
| W4 | 云开发数据层 | 集合建模、权限规则、云函数 | 设计表 + 规则 + 云函数 |
| W5 | 体检与提审预检 | 跑脚本、清 P0、备材料 | 体检报告 + 材料清单 |
| W6 | 驳回整改 | 驳回原文逐条对照整改 | 整改表 + 复检输出 |

## 自带工具（纯 Python 标准库，无需安装依赖）

| 命令 | 作用 |
|---|---|
| `wx_doctor.py scan <项目>` | 静态体检：页面四件套、分包声明、tabBar、组件引用、隐私接口、密钥、外链域名、代码坏味 |
| `wx_doctor.py budget <项目>` | 体积预算：主包/分包字节、占比、超限定位、大文件排行 |
| `wx_doctor.py preflight <项目>` | 提审预检：汇总 + 提审材料清单 + 采集接口清单 + 类目提示 |
| `wx_doctor.py scaffold --spec <json>` | 按规格生成可运行骨架（含三态页面） |
| `ledger.py add/next/report` | 条目台账：状态四态，没绑文件的条目不许标"已完成" |

退出码可以直接接 CI：`0` 无阻断 / `1` 有 P0 / `2` 参数错误。

## 边界（必须说清）

- **不做真机测试**：它给方案与脚本，真机还得你自己点。
- **不连微信后台**：类目、资质、审核口径以公众平台后台为准，它只提醒。
- **不做视觉设计**：给布局建议，不给设计稿。
- **平台规则会变**：涉及规则与上限的地方都标了"以官方文档为准"，动手前请核实。

## 支持的工程形态

| 形态 | 支持程度 |
|---|---|
| 微信原生小程序 | 完整（四个脚本全部适用） |
| uni-app / Taro 源码目录 | 部分（结构检查需指向编译产物） |
| 云开发 / 自建后端 | 都支持（接入方案不同） |
