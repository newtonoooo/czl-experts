# 口播脚本工坊

## 什么时候用

- 用户给一个选题，要成稿脚本。
- 用户说"开头不抓人""完播低"，要改钩子。
- 用户要多个版本做 A/B。
- 用户要带货口播、需要把卖点讲成能听下去的话。

## 必填输入

| 项 | 说明 | 缺了怎么办 |
|---|---|---|
| 选题（一句话） | 这条到底讲什么 | 必须问，不许替用户编选题 |
| 这条的目标 | 涨粉 / 成交 / 立人设，三选一 | 必须问；不同目标结构完全不同 |
| 时长目标 | 15s / 30s / 45s / 60s | 默认按选题复杂度给建议，并说明理由 |
| 出镜条件 | 有没有人出镜、能不能拍手部特写、有没有产品实物 | 缺了就走无人物流（字幕+空镜+手部） |
| 受众的一句自我描述 | 决定用什么词、什么场景 | 用"目标观众是谁、他为什么刷到你"追问 |

## 钩子机制（7 选 1，不要混着用）

| 机制 | 长什么样 | 适合 | 常见误用 |
|---|---|---|---|
| 反常识断言 | "越省越穷" | 观点、认知类 | 断言太温和，等于没说 |
| 具体数字 | "月薪五千，两年存十万" | 方法、经验类 | 数字是编的，评论区一戳就塌 |
| 损失预警 | "这三样东西正在偷你的钱" | 避坑、测评 | 只喊损失不给证据，像标题党 |
| 身份点名 | "三十岁还在还花呗的，看这条" | 垂类、共鸣 | 点得太宽，谁都不觉得在说自己 |
| 场景切片 | "早上七点，孩子在门口哭" | 故事、情感 | 场景太长，三秒还没进正题 |
| 对比冲突 | "同款杯子，一个 39 一个 129" | 测评、带货 | 只对比价格，不比差异 |
| 悬念缺口 | "我删了三十条视频才明白这件事" | 复盘、成长 | 悬念吊太久不兑现，完播反而更低 |

**选择规则**：先看主断点。3 秒留存低 → 用身份点名或损失预警（最直接）；互动低 → 用反常识断言（留可反驳处）；涨粉低 → 用悬念缺口 + 系列化。

## 四种结构（按目标选，不要四段都塞满）

1. **教学型**（涨粉）：问题一句 → 方法三步 → 证据一个 → 关注理由一句。
2. **体验型**（信任）：场景 → 翻车 → 改法 → 结果，四段都必须是具体的事。
3. **观点型**（互动）：断言 → 反例 → 我的解释 → 留一个可反驳的口。
4. **带货型**（成交）：痛点 → 产品出现 → 差异点演示 → 价格锚点 → 低门槛动作。

## 写口播的六条硬规矩

这六条是口播稿"像人说话"的最低线，逐条对照，不合格就重写：

1. **不许连续三句同样长度的短句。** 念出来像机器打点。
2. **"不是……而是……"一条稿子最多出现一次。**
3. **必须留一两句"没用的话"**——一句口语、一次重复、一个小抱怨。全是干货反而假。
4. **不解释情绪。** "我当时特别崩溃"是解释，"我把手机扣在桌上，扣了三次没扣准"是画面。
5. **删掉所有过渡句**："接下来""那么""下面我们来看""话不多说"。
6. **结尾不升华。** 不给"希望我们都能……"这类总结，直接给动作或提问。

## 执行步骤

### S1 定策略
确认目标 → 选钩子机制 → 选结构。三个决定写在一行里，让用户先确认再写，避免白写。

### S2 写三版钩子
同一个选题，三种不同机制，各写 1—2 句。让用户选，不替他选。

### S3 成稿
按下表填六列，一句一行：

| 秒段 | 口播原文 | 画面·分镜 | 字幕重点 | 这一段的目的 | 备选钩子 |
|---|---|---|---|---|---|

模板见 `templates/script-card.md`。

### S4 核时长（必须做，不许估）
把稿子存成 `script.txt`（每句一行）或 `script.json`（带分镜字段），跑：

```bash
python3 ${SKILL_DIR}/scripts/dy_timing.py --file script.txt --rate 270 --target 45
```

脚本会给：每句起止秒数、总时长、首句落点是否在 3 秒内、钩子强度分（5 项信号）、要砍多少字。
**警告项必须在交付前处理掉**，尤其是"首句超过 3 秒"。

### S5 出发布包
标题 3 个（不同钩子角度）、封面文案 1 句（≤12 字）、话题 3—5 个（1 个大词 + 2 个精准词）、置顶评论 1 条（补信息或起争议）、发布时间建议（结合受众活跃时段，说明依据）。

## 输出格式

1. **策略一行**：目标 / 钩子机制 / 结构。
2. **三版钩子对照**：版本 / 原文 / 机制 / 适用判断。
3. **六列时间轴脚本**（选定版本）。
4. **时长核算结果**：总秒数、钩子落点、要砍的字数。
5. **发布包**：标题 3 个 / 封面 / 话题 / 置顶评论 / 发布建议。

## 异常处理

| 情况 | 处理 |
|---|---|
| 用户要"保证 10 万赞" | 拒绝承诺，改为"给 3 版做 A/B，用 3 条视频的数据判断哪版机制有效" |
| 用户没有任何拍摄条件 | 走无人物流：字幕卡 + 空镜 + 手部操作，脚本里把"分镜"全部改成拍摄成本最低的方案 |
| 用户要抄某个爆款 | 拆它的钩子类型、信息节奏、转化路径，换内容重写，不复制原句 |
| 选题本身违规或有风险 | 直接指出，并转 `dy-compliance-lint`，不写"擦边版" |
| 稿子念出来超时 20% 以上 | 先砍信息点，不砍句子。砍句子会把逻辑砍断 |
| 用户嫌"太口语，不够高级" | 说明口播的高级感来自信息密度和具体度，不来自书面词；给一版对照让他听 |

## 与其他技能的关系

- 上游：`dy-account-diagnosis` 给出的主断点决定钩子机制。
- 下游：成稿必须过 `dy-compliance-lint`，未过不交付。
- 带货脚本要进直播间复用时，交给 `dy-live-runbook` 改成话术卡。
