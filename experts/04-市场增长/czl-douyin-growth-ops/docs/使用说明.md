# 使用说明

## 一、第一次用，先给它三样东西

不用写长需求，把这三句说清就能开工：

1. **你卖什么 / 靠什么赚钱**：带货、团购、私域咨询、接广告、纯做号。
2. **你现在手上有哪些数**：近 7—30 天每条视频的播放、时长、完播、赞、评、藏、转、涨粉；或者直接说"没有数"。
3. **这次想解决什么**：起量、涨粉、成交、测选题、过审。

示例：

> 我做家居收纳，主要靠小店卖收纳盒，客单 89，毛利四成。近 30 天发了 12 条，播放最高 1.2 万最低 300，没投过流。想让账号先起量。

## 二、数据从哪拿

抖音创作者服务中心 → 数据中心 → 作品数据，单条视频可看到：播放量、完播率、平均播放时长、点赞、评论、分享、收藏、粉丝增量。把这几项抄下来就行。

**没有 3 秒留存和平均播放时长也可以**，用完播率做粗判，专家会告诉你精度下降。

## 三、怎么跟它对话（按场景）

### 场景 1：账号没起量

> 把上面那段数据给我，让它体检。它会先算分，再指出漏斗上第一个掉人的环节，最后给 30 天排期（每周只改一件事）。

要点：它一定会追问"变现方式"和"有没有投过流"，别嫌烦——这两项不明确，结论会跑偏。

### 场景 2：写脚本

> 选题：租的房子怎么在不打孔的情况下收纳。
> 目标：涨粉。时长 30 秒左右。我出镜，能拍手部特写。观众是刚毕业租房的人。

它会先给你三版不同机制的钩子让你选，再出六列时间轴脚本，最后跑工具算时长，告诉你"实际 41 秒，要砍 18 个字"。

**不要跳过"先选钩子"这步**。直接要成稿，它只会给你一个平庸版本。

### 场景 3：直播前

> 下周六晚 8 点播 2 小时，卖家居小件，客单 89，毛利 40%，退款率大概 15%，固定成本 3000（两个人加样品），打算投 2000 流量。预计场观 3 万。

它会先算保本 GPM，再排货盘和 15 分钟节奏环。如果保本 GPM 算出来偏高，它会直接告诉你"这个货盘撑不住，先提客单或压成本"，而不是硬排一张好看的表。

### 场景 4：要不要投流

> 客单 129，毛利 40%，退款 15%，现在 CPC 0.8，点击到成交 2%。想投 3000 试试。

它会算单笔净毛利、保本 CPA、保本 ROAS，然后给三种判定之一：可以小步放量 / 刚好过线没有容错 / 跑不通别加钱。

### 场景 5：稿子能不能发

> 帮我看这段能不能发：<粘贴全文>

它会跑词表扫描，给等级、依据、替换建议和改后稿。**高等级命中不为 0 时它不会说"可以发"**，会告诉你必须改哪几句。

## 四、四个常见误区

1. **别一次问五件事。** "帮我起号、写脚本、排直播、投流、复盘"——这种需求会被拆成多轮，反而慢。一次一个断点。
2. **别让它保证结果。** 它不会说"这条必爆"。要承诺的地方，它给的是概率区间和验证方案。
3. **别给模糊数据。** "播放几百"没法算。宁可说"最高 1200，最低 300，中位数 600"。
4. **别跳过合规。** 改完的稿子看起来更"软"，但那是因为删掉了会让你被限流的词。

## 五、脚本单独用（不进对话也能跑）

```bash
python skills/dy-account-diagnosis/scripts/dy_metrics.py --demo        # 看样例输出
python skills/dy-hook-script/scripts/dy_timing.py --demo --target 45   # 口播时长
python skills/dy-boost-review/scripts/dy_boost.py --demo               # 三种测算
python skills/dy-compliance-lint/scripts/dy_lint.py --demo             # 合规扫描
```

输入数据格式见各技能目录下 `SKILL.md`。所有脚本 `--help` 都有参数说明。

## 六、出错时怎么办

| 现象 | 原因 | 处理 |
|---|---|---|
| 脚本报"缺少必填字段" | JSON 少了字段 | 按提示补字段，不要填 0 糊弄 |
| 脚本退出码 1 | 合规检出高等级风险 | 正常行为，按报告改稿 |
| 中文乱码 | 控制台编码 | 脚本已强制 UTF-8；若仍乱码，用 `--out` 输出到文件再看 |
| 结论和你的直觉相反 | 通常是你漏看某个环节 | 要求它把计算过程摊开，逐项核对 |
