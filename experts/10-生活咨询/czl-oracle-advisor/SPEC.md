# 产品规格说明 · 司南 v1.0.0

本文件记录"为什么这样设计"，是开发依据，不是使用手册（使用看 `USAGE.md`）。

---

## 一、目标用户与场景

| 用户 | 场景 | 真实诉求 |
|---|---|---|
| 25–45 岁、对传统术数有兴趣的普通人 | 想认真看一次自己的结构 | 别给我模板话术，说清"为什么" |
| 卡在决定上的人（换工作、要不要签、搬不搬） | 需要第二个视角做交叉验证 | 不是求神谕，是求一个能自己想明白的框架 |
| 要办红白事/开业/搬家的家庭 | 挑日子、排时辰 | 要有理由，不要只说"黄历宜" |
| 术数爱好者 | 想核对盘面 | 排盘要能对上公开黄历与历表 |

**共同点**：要判断、要依据、要被当成年人对待。不要神棍腔，不要恐吓，不要付费化解。

## 二、要解决的问题

1. **排盘易错**：干支、节气、农历闰月、命宫定位凭记忆推，错一项整盘偏。→ 用算法解决。
2. **解读无依据**：市面上多是"七杀坐命→命硬"这类贴标签，用户无法核对也学不到东西。→ 用"结构→表现→建议"三段式。
3. **结论不可推翻**：说"必离""必破财"，用户只能信或不信。→ 强制给可观察的复核条件。
4. **越界伤人**：疾病、寿命、投资、未成年人。→ 设硬闸口。
5. **交付不可用**：一堆术语堆在聊天框里，用户没法转给别人。→ 单文件 HTML 成品。

## 三、输入规格

### 八项字段（详见 `rules/czl-input-standard.md`）

公历年月日、出生时刻、性别、出生地（经度）、历法口径、时辰来源、是否闰月、时区。

### 完整度分级

| 级 | 条件 | 允许的产出 |
|---|---|---|
| S | 八项齐，或提供现成命盘 | 全量 + 多体系 + HTML |
| A | 缺出生地 | 标准解读 + 声明未校正 |
| B | 缺时辰/时辰存疑 | 三柱或双盘并列，不下判断句 |
| C | 只有问题 | 起卦（不需生辰） |

## 四、输出规格

### 六段式

`总断 → 盘面依据 → 分领域 → 时间节奏 → 可做的事 → 复核时点`

### 三条可核对性要求

1. 盘面依据段至少引三处硬信息（四柱/命宫/卦名/干支）。
2. 每条领域结论走"结构→表现→建议"。
3. 不确定处显式标注（缺项 / 流派分歧 / 置信度低）。

### 交付形态

| 场景 | 形态 |
|---|---|
| 单点查询 | 对话直答 |
| 完整盘 + 解读 | 对话六段式 + 可选 HTML |
| 要对外交付 | 单文件 HTML（可选 JSON 存档） |

## 五、处理步骤（通用流程）

```
1 识别体系与问题      → 决定走哪条路径
2 立输入（intake）    → 规范化 + 定级 + 真太阳时
3 出盘（engine）      → 结构化 JSON，可复核
4 读盘（read）        → 六段式解读
5 过闸（boundary）    → 拦越界内容
6 装配（atlas）       → 需要成品时出 HTML
7 收口（composite）   → 多体系分歧时给决策备忘
```

## 六、技术接口

### 引擎 CLI

`oracle.py` 提供 10 个子命令：`today` `day` `pick` `bazi` `ziwei` `meihua` `liuyao` `tarot` `solar` `lunar`。

通用开关：`--json` / `--out-json` / `--html` / `--notes`。

### 解读 JSON 契约

```json
{"summary":"", "sections":[{"title":"","body":"","items":[]}], "actions":[], "one_line":""}
```

### 渲染器

`render.py` 提供 6 个渲染函数，共用一套排版骨架，各自独立配色 token。

## 七、质量指标

| 指标 | 要求 | 实测 |
|---|---|---|
| 节气时刻误差 | ≤ 60 秒 | ≤ 21 秒 |
| 农历（1900–2100） | 春节/闰月全对 | 2020–2035 16/16，含 2033 边界 |
| 日柱 | 与公开黄历一致 | 一致（2026-10-26 癸酉） |
| 盘面可复核 | 100% 由脚本产出 | 100% |
| CLI 响应 | < 1 秒（排盘） | 约 0.2–0.6 秒 |
| 离线可用 | 必须 | 是（无第三方依赖） |

## 九、设计取舍

**为什么权重不写成百分比概率**
把"八字 45% + 紫微 40%"算成"78% 会成功"是伪精确，会诱导用户把参考当结论。权重只用于决定"谁说了算"。

**为什么坚持"允许说看不出来"**
术数能答的问题有边界。承认边界比编答案更可信，也降低越界风险。

**为什么每个流派单独配色**
混排会让读者以为是一套体系，也会掩盖体例差异。视觉分离是认知分离的一部分。
