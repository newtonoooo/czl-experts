# 商业发布风险清单 · 算卦台 v1.0.0

本清单只写**真实存在、需要发布者决策**的风险。已通过技术手段消除的风险不再列入。每项给出：风险等级、具体表现、当前处置、需要你决定的事。

---

## 一、必须由你决定的三件事

### 1）平台对"占卜/命理"类目的政策是否允许上架 🔴 高

**风险**：术数/占卜类产品在部分平台被归入"封建迷信"而限制上架，或要求显著标注"娱乐"。各国监管口径不同（国内平台普遍要求此类内容限于传统文化与娱乐定位，禁止宣扬迷信、禁止付费改运）。

**当前处置**：
- 全链路定位为"传统文化研究与娱乐参考"
- 所有输出（含 HTML）强制附免责声明
- 硬闸口禁止疾病/寿命/官司/收益判断、禁止收费化解
- 产品内无任何付费改运、法器、法事相关内容

**需要你决定**：目标平台是否接受该品类；若要求更保守，可进一步弱化"运势""预测"字样，改为"结构参考""决策备忘"。

### 2）头像水印的处理 🔴 高

**风险**：`avatars/expert.png` 由 ImageGen 生成，原图右下角带"AI生成 WORKBUDDY"水印，成品裁切时已去边去水印。若平台要求生成内容必须保留水印，或被认定为规避标识，可能引发合规争议。

**当前处置**：原图完整保留为 `avatars/expert-raw.png`。

**需要你决定**：是否改用 raw 版本（保留水印、需重新裁 512 但会带上水印），或另请设计师绘制独立头像。本产品代码与文档均不依赖该图片，替换成本极低。

### 3）MIT 许可证是否就是你想要的授权方式 🟡 中

**风险**：`plugin.json` 声明 `license: MIT`，包内附 `LICENSE`（版权归虫志龙）。MIT 允许他人自由使用、修改、再分发甚至商用，只要求保留版权声明。若你希望保留商业独占或采用更严格的许可，需要改。

**当前处置**：已按 MIT 提供。

**需要你决定**：保持 MIT，还是改为专有许可（此时需同时删掉 LICENSE、改 plugin.json 的 license 字段）。

## 二、内容与法务风险

### 4）星历与历法数据的准确性 🟢 低

**风险**：节气与农历由本产品自算。数值误差已实测（节气 ≤ 21 秒，农历 2020–2035 与公认历表 16/16 一致）。

**残留风险**：1900 年以前、2100 年以后未做大范围交叉验证；极端边界（朔或节气恰好落在午夜前后数秒）理论上可能出现一天的差异。

**处置**：已在使用说明中提示"若与本人出生记录冲突，以记录为准"。

### 5）流派差异被误认为"算错" 🟡 中

**风险**：紫微庚干四化存在"太阴科/天同忌"与"天同科/天相忌"两说；羊刃在阴干上的取法各家不同；宿的吉凶各家略有出入。用户拿别家软件对比时可能认为本产品算错。

**当前处置**：本产品明确取一说（庚干取"太阳禄、武曲权、太阴科、天同忌"；羊刃仅列阳干）。`czl-ziwei-read` 中已写明"不一致时说明流派差异，不争对错"。

**建议**：在详情页加一句"流派差异说明"，减少售后争议。

### 6）术数内容被用于重大决策 🔴 高

**风险**：用户可能据本产品结论做医疗、法律、投资决策，造成实际损失。这是本类产品的**核心伦理风险**，不是技术风险。

**当前处置**：
- `czl-boundary-guard` 设四道硬线 + 改写银行（每个拒绝都配替代说法）
- 解读规范禁止"必"字断言，强制给可推翻条件
- 择日明确"手术以医生排期为准，绝不因择日推迟必要治疗"
- 每次交付附免责声明

**残留风险**：模型仍可能在措辞上软化边界。建议上线后抽查实际对话记录。

### 7）未成年人相关内容 🟡 中

**风险**：家长会拿孩子的生辰来问"读书行不行""以后怎么样"。

**当前处置**：`czl-boundary-guard` 明确禁止给未成年人贴宿命标签，只允许讲"气质倾向 + 家长可配合的方式"。

### 8）第三方隐私 🟡 中

**风险**：用户可能提供他人（伴侣、同事、子女）生辰而不告知对方。

**当前处置**：`czl-composite-verdict` 要求"提醒需对方知情同意，或改用不含对方生辰的方式"。

## 三、技术风险

### 9）运行环境依赖 Python 🟡 中

**风险**：引擎需要本机有 Python 3.8+。若用户环境无 Python 或 PATH 未配置，排盘不可用。

**当前处置**：纯标准库、无网络依赖；CLI 在 Windows/POSIX 均可运行。`czl-oracle-engine` 中写明"`python` 不可用时依次尝试 `python3`、`py`"。

**残留风险**：完全无 Python 的环境会退化到"仅能对话、不能排盘"。此时按铁律应**拒绝凭记忆排盘**，如实说明——即功能降级，不是错误输出。

### 10）HTML 视觉未做像素级验收 🟡 中

**风险**：页面结构校验通过，但未取得截图级验收（本环境浏览器截图接口超限）。存在排版细节问题的可能（如超长星曜名换行、窄屏挤压）。

**当前处置**：已内置 720px 断点、徽章内联（禁止绝对定位浮层）、标签配对校验。

**建议**：上线前人工打开 6 个流派页面各一次，重点看紫微十二宫格与六爻表格。

### 11）大规模并发未测试 🟢 低

**风险**：单次排盘 0.2–0.6 秒，未做并发压测。作为本地工具型专家，并发压力有限。

### 12）随机性来源 🟢 低

**风险**：塔罗与摇卦使用 `secrets`（系统熵源）。若运行环境熵源受限，随机性会下降。

**当前处置**：未使用伪随机固定种子，避免"同一秒重复同一副牌"。

## 四、原创性与平台审核

### 13）原创性举证 🟢 低

**现状**：
- 所有代码、提示词、文档为本包新写，`DEVLOG.md` 逐项记录来源与开发过程
- 术数规则属公有领域传统知识，规则本身不是著作权客体；具体实现与表达为本产品自有
- 未复制任何既有专家包的文件；未使用常见农历压缩表（改用自算）
- 头像为本次生成，原图保留

**建议留存**：`DEVLOG.md`、`TEST-REPORT.md`、本次会话的开发过程，可作为创作记录。

### 14）宣传文案与实际功能一致性 🟢 低

**现状**：
- README 与 plugin.json 中的能力描述均对应当前真实实现
- **未做**的能力（奇门、紫微辅星、完整黄历）在 SPEC 第八节与 README 中明确标注为"不做/未实现"
- 未声称"祖传""秘传""独家算法""与某机构合作"
- 未虚构用户量、准确率、专家背书

### 15）文件格式与导入要求 🟢 低

**现状**：`validate_expert.py` 校验通过（0 error / 0 warning）。包含：`.codebuddy-plugin/plugin.json`、`agents/`、`skills/`（均含 SKILL.md）、`avatars/`、README。无禁用目录（hooks/commands）。

3. 人工打开 6 个 HTML 页面验收一次
4. 抽查 10 段实际对话，确认边界话术没被软化
5. 详情页补一句"流派差异说明"
