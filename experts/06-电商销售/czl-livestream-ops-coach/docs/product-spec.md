## 一、目标用户与使用场景

### 1.1 目标用户

| 用户 | 典型处境 | 最痛的事 |
|---|---|---|
| 品牌自播负责人 | 有预算、有货、有场地，但每场数据都靠猜 | 不知道钱花得值不值，复盘说不出所以然 |
| 中小商家老板 | 自己上阵或雇了 1-2 个主播，播了几个月不见起色 | 不知道该改货、改话术还是改主播 |
| 新手主播 | 会说话，但一讲产品就冷场 | 没有可念的话，也不知道该怎么练 |
| 直播运营/中控 | 负责执行，被要求"把数据做上去" | 缺工具，缺标准，缺可执行的动作清单 |
| 代运营/MCN 新人策划 | 要独立出一场方案 | 方案像模板，客户一问细节就露馅 |

### 1.2 使用场景

| 场景 | 触发时机 | 期望结果 |
|---|---|---|
| 新号首播 | 开播前 1-7 天 | 有任务书、排品表、脚本卡，敢开播 |
| 日常场次迭代 | 每场播完当晚或次日 | 知道漏在哪一层，明天改哪一件事 |
| 大场/大促筹备 | 活动前 2-4 周 | 排品节奏、库存释放、投放预算能对得上 |
| 主播换人/带新人 | 人员变动时 | 有评分、有纠偏、有彩排流程 |
| 要不要投流 | 每次决定花钱前 | 有保本线、有止损条件、有预算上限 |
| 数据突然变差 | 限流、掉量、退货暴涨 | 有排查顺序，不靠猜 |

### 1.3 明确排除的场景

账号定位与人设策划、供应链选品采购、短视频/短剧内容创作、品牌 VI 设计、代投代运营执行、GMV 结果承诺。

## 二、要解决的问题

按用户原话归纳为六类：

| # | 问题 | 现有解法为什么不管用 | 本产品的解法 |
|---|---|---|---|
| P1 | "不知道该改什么" | 通用建议不落到动作，听完无法执行 | 五层漏斗定位第一个漏点，只改一层 |
| P2 | "话术写出来念不出来" | 书面语、长句、无节奏标注 | 25 字内短句 + 【念】【做】【看】【停】标注 |
| P3 | "货不知道怎么排" | 只说"要有引流款"，不说几点上、放多少 | 分钟级 Rundown + 五类货位 + 30/40/30 库存释放 |
| P4 | "主播带不出来" | 用形容词评价（不够自信、不够有感染力） | 五项行为评分 + 逐句纠偏 + 三轮彩排 |
| P5 | "钱花得心里没底" | 先投再看 ROI，亏了才知道 | 先算单件净毛利与保本 ROI，再定预算与止损 |
| P6 | "复盘写成流水账" | 报数 + 感慨，没有动作 | 指标表 → 漏点 → 归因 → 真实盈亏 → 三件动作 |

## 三、输入与输出

### 3.1 必需输入（七项）

平台与账号阶段 / 类目与主推品 / 价格带与客单价 / 毛利与履约成本 / 团队编制 / 历史场次数据 / 本场目标。

### 3.2 缺项降级规则

| 缺什么 | 降级方式 | 对输出的影响 |
|---|---|---|
| 毛利与成本 | 给类目区间假设并标注 | 不出投放预算与出价 |
| 历史数据 | 定义为"基线场" | 验收只看过程指标，不看 GMV |
| 团队编制 | 默认主播+中控两人 | 场控与投手的活合并给中控 |
| 本场目标 | 追问一次，仍不明则给双版本 | 两版排品并列，让用户选 |
| 平台 | 追问；仍不明则按通用逻辑 + 标注平台差异 | 指标参考线与合规提示按最严平台处理 |

### 3.3 标准输出物

| 输出 | 形态 | 使用者 |
|---|---|---|
| 场次任务书 | Markdown 表 | 老板 / 负责人 |
| 分钟级 Rundown | 表格（24 行左右） | 中控 / 场控 |
| 单品脚本卡 | 六段表格，可打印 | 主播 |
| 带教单 | 评分 + 纠偏 + 彩排计划 | 主播 / 培训者 |
| 投放与流量计划 | 闸门表 + 节奏表 | 投手 / 老板 |
| 复盘报告 | 指标 + 诊断 + 盈亏 + 动作单 | 全员 |

所有输出为 Markdown，可直接复制进文档或打印。

## 四、通用处理步骤（六段流水线）

```
W0 场次立项  → 定目标、验收口径、资源瓶颈、风险
W1 货盘排品  → 五类货位、价格带梯度、分钟级节奏、库存释放
W2 话术脚本  → 整场三段结构 + 单品六段卡 + 互动指令表
W3 主播带教  → 五项评分 + 逐句纠偏 + 三轮彩排 + 30 天路径
W4 流量闸门  → 保本测算 + 预算上限 + 放量/止损条件 + 节奏表
（播出）
W5 场次复盘  → 漏斗诊断 + 四类归因 + 真实盈亏 + 三件动作 → 回灌下一场
```

判断逻辑：

- 五层漏斗（进房→停留→互动→点击→付款）取**第一个**低于参考线的层作为唯一修改目标
- 归因分四类（货 / 人 / 节奏 / 流量），每类给验证方法，不凭感觉
- 下一场只改一个主变量，否则无法归因

## 五、所需的工具能力与技术接口

| 能力 | 用途 | 实现 |
|---|---|---|
| 本地脚本执行 | 指标计算、保本测算、目标反推 | `skills/live-room-metrics/scripts/live_metrics.py`，Python 3.8+ 标准库 |

**不依赖**：任何平台 API、数据库、网络请求、第三方 Python 包。

## 六、质量、速度与稳定性要求

| 维度 | 要求 | 落地方式 |
|---|---|---|
| 准确性 | 所有数字可复算，误差为 0（纯算术） | 脚本计算 + 公式文档 + 自检 |
| 可执行性 | 每条动作含时间点、责任人、验收标准 | 输出规范第 4 条强制约束 |
| 口径一致性 | 同一输出中同一指标只有一种口径 | 参数名强制区分人次/人数、下单/付款 |
| 合规性 | 不出现绝对化用语、功效承诺、假比价 | 红线清单 + 词表 + 脚本自检三问 |
| 响应速度 | 单段工作流一次对话内可完成；全链不超过 6 轮 | 每段输入清单明确，不反复追问 |
| 稳定性 | 缺输入时不崩、不编造，给带假设的降级版本 | 五条降级规则 |
| 可追溯 | 每个结论能指回数据或规则 | 区分事实/推断/建议 |

## 七、功能需求清单（验收用）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-01 | 能识别用户问题属于六段中的哪一段 | 八类典型问法路由正确 |
| FR-02 | 能在信息不足时列出缺项并降级 | 缺毛利时不出投放方案 |
| FR-03 | 能输出分钟级 Rundown | 4 小时场 ≥20 行，含货位、释放量、中控动作 |
| FR-04 | 能输出可念的脚本卡 | 句子 ≤25 字，含四种标注，含合规自检 |
| FR-05 | 能给主播打分 | 五项 1-5 分，每项带行为证据 |
| FR-06 | 能算保本 ROI | 与脚本输出一致，误差 0 |
| FR-07 | 能给漏斗诊断 | 指出第一个漏点并给三条对应动作 |
| FR-08 | 能算真实盈亏 | 含退款、广告费、固定成本三项 |
| FR-09 | 能输出三件次日动作 | 每件含责任人、时间、验收标准 |
| FR-10 | 能拒绝违规请求 | 刷单、绝对化用语、假比价一律拒绝并给替代方案 |
