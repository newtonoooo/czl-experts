python skills/live-room-metrics/scripts/live_metrics.py selftest

### T02 场次诊断 —— 通过（实测）

输入（一场冷启动场）：曝光 180,000 / 进房 12,600 / 停留 41 秒 / 点赞 3,200 / 评论 640 / 关注 180 / 点击 880 / 下单 42 / 付款 31 / 成交 3,069 / 退款 210 / 花费 1,800 / 广告进房 6,300

输出要点：
- 进房率 7.00%、停留 41.0 秒、互动率 30.48%、评论率 5.08%、点击率 6.98%、支付转化率 3.52%、GPM 243.57、UV 价值 0.24、退款率 6.84%、ROI 1.71、CPA 58.06、自然进房 50%
- 漏斗命中两个漏点：**平均停留 41.0 秒（参考线 45 秒）**、**商品点击率 6.98%（参考线 8%）**
- 结论锁定第一个漏点为"进房→停留"，并输出三条对应动作

判定：逻辑正确（停留与点击确实低于冷启动参考线，进房率 7% 达标）。

### T03 保本测算 —— 通过（实测，含手算核对）

命令：
```bash
python skills/live-room-metrics/scripts/live_metrics.py breakeven --price 129 --cost 41 \
  --fulfillment 7 --return-rate 0.22 --commission 0.05 --payment-fee 0.006 \
  --return-logistics 9 --fixed-cost 1200
```
输出：单件净毛利 54.03、净利率 41.9%、保本 ROI 2.39、保本 CPA 54.03、单场保本销量 22 件、单场保本 GMV 2,865.33

手算核对：129×0.78 − 41×0.78 − 7 − 129×0.05×0.78 − 129×0.006×0.78 − 9×0.22 = 54.025 → 保本 ROI = 129/54.025 = 2.3878。与脚本一致。

退货率敏感性另测：退货率 40% 时单件净毛利 37.87、保本 ROI 3.41，与文档中"提升 43%"的表述一致。

### T04 目标反推 —— 通过（实测）

命令：`plan --target-gmv 50000 --aov 99 --pay-rate 0.03 --click-rate 0.10 --entry-rate 0.08 --target-roi 2.5 --entries-per-hour 3200`
输出：需付款 505 单 / 需点击 16,835 次 / 需进房 168,350 人 / 需曝光 2,104,377 次 / 广告预算 20,000 元 / 需播 52.6 小时，并触发"单场时长不现实"提示。

### T05 JSON 输出 —— 通过（实测）

`--json` 参数输出合法 JSON（含 price、return_rate、unit_net_margin、breakeven_roi 等字段），可被上游流程消费。

### T06 空输入处理 —— 通过（实测）

`session --entries 0`：向 stderr 输出"没有足够参数计算任何指标"，退出码 2，不产生错误的空表。

### T07 负毛利拦截 —— 通过（实测）

`--price 50 --cost 48 --fulfillment 5 --return-rate 0.1`：单件毛利 −3.00、单件净毛利 −6.52，**不输出保本 ROI**，并给出"卖一件亏一件，先改成本结构"的提示。符合"保本线为负时不得给投放建议"的设计。

### T08 口径冲突提醒 —— 通过（实测）

输入"下单 5 单 / 付款 9 单 / 成交 100 / 广告费 500"：触发两条告警（下单小于付款、广告费高于成交额）。数据仍照常算出，但告警随结果输出，符合"先提醒再计算"的要求。
