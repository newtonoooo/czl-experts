# W5 场次复盘

## 一、职责

把一场直播的结果，变成**下一场只改一个地方**的明确指令。
复盘的产物不是报告，是动作单。写不出动作的复盘等于没做。

## 二、输入参数

| 参数 | 必填 | 说明 |
|---|---|---|
| 场次原始数据 | 是 | 曝光、进房、停留、点赞、评论、关注、点击、下单、付款、GMV、退款、花费、广告进房 |
| W1 Rundown 实际执行版 | 是 | 哪些货位按计划上了、哪些没上、为什么 |
| 现场记录 | 强烈建议 | 中控记录：几点掉人、几点放量、主播状态异常时点 |
| 上一场的动作单 | 否 | 用来检查"上次说要改的改了没有" |

## 三、执行步骤

**第 1 步：跑数。**
`live-room-metrics session` 一次算完，不要手工算。数据口径不明的（下单 vs 付款、人次 vs 人数）先问清再算。

**第 2 步：找第一个漏点。**
脚本按 进房 → 停留 → 互动 → 点击 → 付款 的顺序找第一个低于参考线的层。
**只修第一个。** 上层漏了，下层的数据是被污染的，改下层是白改。

**第 3 步：归因到四类原因。**
同一个漏点，可能是四种原因之一。用下面的矩阵交叉验证，不要凭感觉。

| 漏点 | 最可能的四类原因 | 怎么验证 |
|---|---|---|
| 进房率低 | 流量：投放人群不对 / 货：封面货品无吸引力 / 节奏：开播时间撞车 / 人：第一帧画面差 | 换封面或换开播时段，看下一场进房率 |
| 停留低 | 节奏：前 15 秒没钩子 / 人：开口慢、语速平 / 货：前 15 分钟上了高价品 / 流量：投放带来的人群与货不符 | 把前 15 分钟换成引流款+福利预告再测一场 |
| 互动低 | 人：指令太开放 / 节奏：钩子间隔太长 / 货：没有可讨论的点 | 把开放提问改二选一，测一场 |
| 点击低 | 人：讲解不动人、没报链接序号 / 货：价格断层、规格复杂 / 节奏：讲完才提链接 | 讲解与报序号同步，测一场 |
| 付款低 | 货：价格锚定不足、赠品不诱人 / 人：逼单无力 / 节奏：库存一次放完 / 平台：支付路径有障碍 | 先自查支付路径，再改锚定顺序 |
| 退款高 | 人：话术预期管理过头（最常见） / 货：尺码色差 / 平台：物流时效 | 抽查 10 条退款原因，看话术有没有说过头 |

**第 4 步：算出净 ROI 与真实盈亏。**
用净成交额（扣退款）重算 ROI。同时算：本场净毛利总额 − 广告花费 − 固定成本 = 真实盈亏。
这一栏很多复盘会跳过，跳过就等于不知道这场到底赚没赚。

**第 5 步：写次日动作单（三件）。**
每条必须含：动作、责任人、完成时间、验收标准。

```
例：
1. 把主力款从第 6 位提到第 3 位        / 中控阿明 / 明日 18:00 前改完 Rundown / 第 3 位有主力款
2. 前 15 分钟加一个 9.9 元引流款       / 主播小周 / 明日开播前练熟 / 能不看稿讲完六段
3. 抽查 20 条退款原因并归类            / 运营小李 / 明日 12:00 前出结论 / 有归类表
```

**第 6 步：留一条"下一场只改这一个变量"。**
如果三件动作里有互相冲突的（既改排品又改话术），必须指定唯一主变量，其他保持不动。否则下一场数据变了，你仍然不知道是什么起作用。

## 四、判断条件

| 条件 | 处理 |
|---|---|
| 付款单量 <20 | 样本不足，只给方向，不给结论；下一场作为验证场 |
| 数据缺 3 项以上 | 不出归因，只出数据补录清单 |
| 五层全部达标但 GMV 不理想 | 问题在流量规模或客单价，不在漏斗；建议扩流量或提客单 |
| 上一场动作单未执行 | 先追执行，不复盘；连续两场不执行则停止出方案 |
| 有平台处罚记录 | 处罚优先于一切优化，先处理违规内容 |
| 退款率 >类目常态 1.5 倍 | 暂停放量，先查预期管理 |

## 五、输出格式

1. **指标表**（本场 / 上场 / 变化 / 参考线，四列）
2. **漏斗诊断**（第一个漏点 + 实测值 vs 参考线）
3. **归因结论**（原因类型 + 证据 + 置信度：高/中/低）
4. **真实盈亏**（净成交额、净毛利、广告花费、固定成本、盈亏）
5. **次日动作单**（三件，责任到人）
6. **下一场唯一主变量**

## 六、异常处理

| 异常 | 处理 |
|---|---|
| 用户只有 GMV 一个数 | 只做盈亏判断，不做漏斗归因；给数据补录清单 |
| 用户想一次改五件事 | 拒绝，说明改了五件就不知道哪件有用；排优先级，一次一件 |
| 数据前后矛盾（下单 < 付款） | 标为口径错误，不用于归因，要求重新导出 |
| 老板只看 GMV 不看过程指标 | 用净 ROI 和真实盈亏对话，这是老板听得懂的语言 |
| 连续三场同一层漏 | 说明修的方向错了，换归因假设（参考归因矩阵换一行） |

## 七、依赖

- `live-room-metrics session`（全部指标与诊断）
- `live-room-metrics breakeven`（算真实盈亏）
- W1 的执行版 Rundown、现场记录

## 八、与其他工作流的关系

- **上游**：实际播出的场次。
- **下游**：直接决定下一场 W0 的主目标与 W1 的排品调整。
- **闭环**：本段的三件动作，下一场复盘时第一件事就是检查执行情况。
