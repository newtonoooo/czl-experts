# W0 场次立项

## 一、职责

把"我们想播一场"这句模糊的意愿，变成一份**开播前能被别人拿去执行、播完能被别人拿去验收**的任务书。
这一段不产出任何创意，只产出约束。约束定不下来，后面五段全是白做。

## 二、输入参数

| 参数 | 必填 | 说明 | 缺失时处理 |
|---|---|---|---|
| 平台 | 是 | 抖音 / 快手 / 视频号 / 淘宝 / 小红书 | 追问，平台不同整套逻辑不同 |
| 账号阶段 | 是 | 冷启动（<30 场）/ 成长期 / 成熟期 | 追问；问不到按冷启动处理并标注 |
| 类目与主推品 | 是 | 计划讲的 3-10 个品 | 追问 |
| 价格带 | 是 | 最低价 / 最高价 / 目标客单价 | 用货盘价推测并让用户确认 |
| 毛利与成本 | 是 | 售价、成本、履约、退货率、佣金 | 缺则给类目区间假设，明确标注 |
| 团队编制 | 是 | 主播 / 中控 / 场控 / 投手 各几人 | 默认"主播+中控"两人 |
| 历史数据 | 否 | 最近 3-5 场核心指标 | 无则本场定义为"基线场" |
| 本场目标 | 是 | 成交 / 涨粉 / 测品 / 清库存 | 追问一句"这场是想赚钱还是想让系统认你" |
| 时长与时段 | 是 | 计划播几小时、几点开播 | 默认 4 小时、类目高峰时段 |

## 三、执行步骤

**第 1 步：锁定唯一主目标。**
四种目标互斥，只能选一个当主目标，其余降为次要：

| 主目标 | 货盘特征 | 验收指标 | 明确放弃的东西 |
|---|---|---|---|
| 打成交 | 主力款+利润款为主，引流款少 | GMV、GPM、支付转化率 | 涨粉 |
| 打涨粉 | 引流款多、福利品钩子密 | 转粉率、平均停留 | 单场 GMV |
| 测品 | 新品多、每品讲解时间短且均等 | 每个品的点击率与支付转化率 | 整场 GMV |
| 清库存 | 尾货为主、价格下探 | 售罄率、件数 | 毛利 |

一句话判定：**要成交就不能指望涨粉，要测品就不能心疼 GMV。** 目标混着定，最后每一项都不达标，且找不到原因。

**第 2 步：盘点四类资源，找出真正的瓶颈。**
人（几个岗位）、货（几个能讲的品）、场（场景与设备）、钱（投放预算）。四项里最弱的那一项就是本场的上限。方案要围绕瓶颈做，不要平均用力。

**第 3 步：用 `live-room-metrics plan` 反推目标是否现实。**
把目标 GMV 和当前转化水平丢进脚本，看需要的进房人次和时长。超出常识范围就回头调目标，而不是把目标写进任务书然后播崩。

**第 4 步：定验收口径。**
写 4-6 个指标，每个指标给：口径、目标值、最低可接受值。

```
例：
GPM            付款口径成交额/千进房    目标 600   地板 450
平均停留        秒                     目标 55    地板 45
商品点击率      点击/进房              目标 9%    地板 7%
支付转化率      已付款/点击            目标 3%    地板 2.2%
自然进房占比    自然进房/总进房        目标 40%   地板 25%
```

**第 5 步：列三到五条风险，每条给触发条件和应对。**
只列真实存在的风险，不要写"市场竞争激烈"这种正确的废话。合格的写法：**"主力款只有 80 件库存，若前 40 分钟卖超 50 件，后半场无货可讲 → 预案：把主力款拆成两波放，第一波限 40 件。"**

## 四、判断条件

| 条件 | 分支 |
|---|---|
| 用户说不出毛利与成本 | 不进 W4，投放方案一律不出；先给"不投流版本"的排品与话术 |
| 历史数据 <3 场 | 本场定义为基线场，验收只看四项过程指标，不看 GMV |
| 团队只有 1 人（无中控） | 所有方案降级为"单人可执行版"：脚本里自带提词节奏，互动靠预置话术轮播 |
| 主推品 <3 个 | 不能排 4 小时，改成 2 小时或先测品 |
| 目标是清库存但价格无法下探 | 回到目标，改成"打成交"，否则必然失败 |
| 目标 GMV 反推所需进房 > 50 万 | 目标定高，拆场或先做涨粉场 |

## 五、输出格式

按 `templates/session-brief.md` 填，必须包含：

1. 一句话任务书（"X 月 X 日 X 点，在 X 平台，用 X 个品，播 X 小时，主目标是 X"）
2. 目标与验收表（指标 / 口径 / 目标值 / 地板值）
3. 资源与瓶颈（一句话指出瓶颈）
4. 风险与预案表
5. 明确放弃项（这一场不追什么）

## 六、异常处理

| 异常 | 处理 |
|---|---|
| 用户反复改目标 | 让他二选一，把两个目标的排品差异摊开给他看，逼他选 |
| 用户要求承诺 GMV | 拒绝，说明承诺 GMV 的方案一定是骗人的，改承诺"过程指标可达" |
| 数据显示老号已长期低流量 | 先做 3 场基线场，不做大场，把 W5 的诊断当主任务 |
| 老板与主播目标不一致 | 写进任务书的风险栏，明确"以老板目标为准，主播需知情" |

## 七、依赖

- `live-room-metrics` 的 `plan` 与 `breakeven`（第 3 步、第 4 步的数值来源）
- `references/category-playbooks.md`（类目常识与合规边界）

## 八、与其他工作流的关系

- **下游**：W1 排品直接吃本段的主目标与价格带；W4 直接吃本段的毛利与预算。
- **上游**：W5 的复盘结论回灌本段——上一场的漏点决定这一场的主目标。
- **禁止**：本段未完成就进 W1，会导致排品无的放矢。
