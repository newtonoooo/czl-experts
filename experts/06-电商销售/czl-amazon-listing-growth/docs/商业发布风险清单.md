## 二、逐项说明

### R1 · 新内容来源与创作记录（低）

**情况**：本产品的提示词、工作流、规则包、脚本、文档、头像全部为本项目内新写，无一处复制自其他专家包。

**证据**：
- `docs/开发记录.md` 记录了从功能拆解到成品的完整时间线与决策。
- 头像由 `build/render_avatar.py`（纯标准库 SDF 渲染）生成，源图与成品均在，可复现。
- 规则包内容依据公开的平台规则常识整理，表述为本项目自撰。

**残留风险**：无法提供"独立创作"的第三方公证，只能提供过程证据。这是所有原创声明的共同局限，如实说明。

### R2 · 第三方依赖的商用与再分发（低）

**情况**：脚本只用 Python 标准库（`argparse` / `json` / `os` / `re` / `sys`）。无 pip 包、无前端库、无图标字体、无图片素材。

**结论**：不存在第三方许可证的商用与再分发问题。

**注意**：运行环境需 Python 3.8+。WorkBuddy 自带运行时，用户无需另装。

### R3 · 头像版权（低）

**情况**：`avatars/expert.png` 由本项目代码绘制——背景渐变、三根圆角柱、描边框全部由有向距离场（SDF）解析计算，再用盒式滤波降采样。

**为什么不走图像生成模型**：本次图像生成服务网络不可用（两次调用均返回 TLS 连接中断）。改用代码自绘后，反而消除了"生成内容能否商用"的条款不确定性。**这是当前状态下更干净的方案，不是退而求其次。**

**残留风险**：构图（递增柱状）是通用图形语言，不排除与某些商标视觉近似。已避免：不使用任何企业标志、不使用亚马逊的笑脸箭头元素、不使用人物形象。

### R4 · 商标使用（中，需你决策）

**情况**：产品名、文案、规则包中大量出现 "Amazon"、"亚马逊"、"Rufus"、"A+"、"FBA"、"ASIN" 等词。

**判断**：这些属于**描述性/指示性使用**（说明产品适用于该平台），不是将他人商标作为自身品牌使用。行业惯例普遍如此。但存在两点不确定：

1. 专家市场对"标题含第三方平台名"是否有额外限制，未核实。
2. "增长官"一词可能被理解为效果承诺，虽然文档已明确不承诺。

**可选处置**：
- 方案 A（当前）：保留，接受描述性使用的常规风险。
- 方案 B：标题改为「专业跨境电商 Listing 增长官」，把平台名放到标签与描述里，风险更低但搜索命中变差。
- 方案 C：标题改为「专业 Listing 增长官（亚马逊/多平台）」。

**需要你定**：选 A / B / C。我默认按 A 打包。

### R5 · 合规规则内容准确性（中，需你决策）

**情况**：`compliance-matrix.json` 与 `marketplace-rules.json` 中的字符上限、认证要求、市场义务，依据公开信息与行业通行认知整理，**未逐条与官方原文比对**。

**已做的处置**：
- 两个规则文件顶部都有 `disclaimer` 字段，声明为配置基线。
- 每次 `compliance` 输出末尾固定打印免责句。
- 提示词中写死"不确定就写需核实，不写应该没问题"。

**残留风险**：若用户把判定当成权威结论，可能做出错误的上架决策。特别是：
- 字符上限会随类目模板变化；
- GPSR / EPR / LUCID 等义务的适用范围有细则；
- 认证要求按产品细分差异很大。

**需要你定**：是否在发布前请一位熟悉欧美合规的人复核规则包。若不复核，建议在展示文案中加一句"规则包为自查基线，具体以官方为准"（当前已有类似表述）。

### R6 · 平台原创性与商业分成要求（中，需你决策）

**情况**：未获取到 WorkBuddy 专家市场关于"原创性认定标准"和"商业分成比例"的正式条款文本。本清单不对这两项作任何断言。

**你需要做的**：
1. 在提交页或开发者协议中确认原创性认定方式（是否要求代码/提示词查重、是否要求提供创作说明）。
2. 确认分成比例、结算周期、退款责任归属。

**我能提供的**：`docs/开发记录.md` 可作为原创性说明材料提交。

### R7 · 与既有专家产品的功能重叠（低，需你决策）

**情况**：本机已有一个同类产品 `czl-crossborder-landing-pro`（专业出海落地官），覆盖选品→成本→合规→页面→补货全链路，其中"页面"一段与本产品有交集。

**差异**：本产品不做选品、成本、补货，只做 Listing 且做到可执行细节（关键词预算、五点结构、AI 就绪度七维、申诉框架）。

**风险**：同一作者名下两个产品功能部分重叠，若同平台销售，可能被用户认为重复购买。

**需要你定**：是否在展示文案中显式写明"与出海落地官的分工"（当前在 `平台展示文案.md` 名称查重一节已有说明，但未写进市场卡片）。

### R8 · 专家包格式与导入要求（中，需你决策）

**情况**：按本机已安装专家包的结构对齐（`.codebuddy-plugin/plugin.json` + `agents/*.md` + `avatars/*.png` + `skills/*/SKILL.md`）。

**已做的静态校验**：
- `avatar` 使用 `avatars/expert.png`（无 `./` 前缀）。
- zip 打包时**不套外层目录**，`.codebuddy-plugin` 位于 zip 根部。
- 已核对平台导入逻辑：清单文件按后缀查找，头像按精确路径查找——两者不对称，套外层目录会导致"专家导入成功但头像变成首字"。

**未验证**：真实导入后的界面渲染。见 `docs/功能测试报告.md` 第五节。

**需要你定**：导入后请确认头像显示正常。若仍显示首字，按 `docs/开发记录.md` 第二节的排查顺序处理。

### R9 · 名称查重（低）

查重范围：本机 29 个专家包。无「亚马逊」「Listing」字样，`专业亚马逊Listing专家` 未重复。

**局限**：只查了本机，未查线上市场全量。提交前建议在市场中再搜一次「Listing」。

### R10 · 免责与责任边界（中）

**已做的处置**：
- 提示词末段写明"不构成法律意见、不构成官方解释、不构成销售结果承诺"。
- 脚本输出固定带免责句。
- 展示文案第七节独立声明"与亚马逊公司无隶属或合作关系"。

**残留风险**：用户可能忽略免责声明，把合规判定当权威。这是工具类产品的固有风险，只能靠文案反复提示，无法根除。
