## 二、头像不显示（显示为首字）的根因分析

> 这一节回答你在任务里提到的问题：专家导入新环境后，选中时小图标不见了，变成一个汉字。

### 2.1 现象

专家列表卡片上，本该显示头像的位置渲染成一个带渐变底色的首字圆形。专家名称、职业、简介都正常。

### 2.2 从代码里找到的判定链

**第一处：渲染层只认两种头像来源**

专家卡片的渲染逻辑（`renderer/assets/src-0FGg1seX.js` 中 `ExpertOption`）本质是：

```js
const { avatarUrl: s, name: u, id: p } = t;
if (s) return <div class={avatar}><img src={s} alt={u} class={avatarImage}/></div>;
// 否则：渐变圆 + 首字
const E = t.initial || getExpertInitial(u);
return <div class={avatar} style={background: gradient}><span>{E}</span></div>;
```

即：**`avatarUrl` 有值就渲染图片，没有就渲染首字**。

**第二处：`avatarUrl` 的来源有正则过滤**

`toSelectedExpert()`（`renderer/assets/project-detail-page-*.js`）：

```js
function toSelectedExpert(e){
  const t = e.avatar && /^(https?:\/\/|data:image\/)/i.test(e.avatar) ? e.avatar : undefined;
  return { ..., avatarUrl: t, initial: e.name.slice(0,1) };
}
```

关键在 `/^(https?:\/\/|data:image\/)/i`：**只接受 `http(s)://` 开头的 URL 或 `data:image/` 开头的 data URI**。

`avatars/expert.png` 这种相对路径、`./avatars/expert.png` 这种带点路径，**都过不了这个正则**，于是 `avatarUrl` 为 `undefined`，走首字分支。

**第三处：zip 导入时头像本该被转成 data URI**

`resolveAvatarFromExpertZip(zip, metadataDir, avatar)`（主进程）：

```js
function resolveAvatarFromExpertZip(e, t, n) {
  if (typeof n !== 'string' || !n) return;
  if (/^(https?|data):/i.test(n)) return n;           // 已是 URL 直接返回
  const r = n.replace(/^\.\//, '').replace(/^\//, ''); // 去掉 ./ 和前导 /
  const i = t ? [`${t}/${r}`, r] : [r];                // 候选：<元数据目录>/<路径> 或 <路径>
  for (const p of i) {
    const entry = e.getEntry(p);                       // ← 精确匹配
    if (entry && !entry.isDirectory) return `data:${getMimeType(p)};base64,${...}`;
  }
  return n;                                            // ← 找不到就原样返回相对路径
}
```

注意最后一行：**找不到头像文件时，它不报错，直接把相对路径原样返回**。这个值同样过不了第一处的正则，于是变成首字。

**第四处：清单文件的查找方式与头像不一致**

```js
function findZipEntryBySuffix(e, t) {          // 后缀匹配
  return e.getEntries().find(x => !x.isDirectory && x.entryName.endsWith(t));
}
// 用 `${'.codebuddy-plugin'}/plugin.json` 去匹配后缀
```

清单用**后缀匹配**，头像用**精确路径匹配**。

### 2.3 结论

**根因：zip 里套了一层外层目录（或头像路径与 zip 内的实际条目名不一致）。**

后果链条：

```
zip 内容：czl-amazon-listing-growth/.codebuddy-plugin/plugin.json
          czl-amazon-listing-growth/avatars/expert.png
   ↓ 清单：后缀匹配命中 → 专家导入成功，名称/简介/职业都正常
   ↓ 头像：getEntry('avatars/expert.png') 精确匹配失败 → 返回相对路径
   ↓ 渲染：相对路径过不了 /^(https?|data:image)/ → avatarUrl 为空
   ↓ 结果：渐变圆 + 首字
```

这也解释了为什么"专家能用，只是图标没了"——两者走的是不同的查找策略。

### 2.4 次要诱因（同样会导致首字）

| 诱因 | 说明 |
|---|---|
| `avatar` 写成 `./avatars/expert.png` | zip 路径会被剥掉 `./` 所以导入没问题；但本地文件夹导入路径 `buildExpertFromCustom` 原样透传，`resolveExpertAvatarUrl` 会拼成 `baseUrl + '/./avatars/...'`，可能 404 |
| 本地文件夹导入且文件不存在 | 同上，原样透传 → 首字 |
| 图片体积过大或格式不被支持 | 请求失败 → 图片裂图或回退 |

### 2.5 本产品采用的规避规则

1. `avatar` 写 `avatars/expert.png`——**不带 `./`、不带前导 `/`、不写绝对路径**。
2. 打包时**不套外层目录**，`.codebuddy-plugin/` 位于 zip 根部。
3. 打包后跑校验脚本，模拟平台的两次查找（清单后缀 + 头像精确），确认头像能解析成 data URI。
4. 头像 512×512、PNG、35.5 KB，远低于体积上限。

### 2.5.1 反向验证：真的能复现这个现象

只讲道理不够，我构造了一个**故意套外层目录**的包（`build/negative-test-wrapped.zip`）跑校验，结果与现象完全对上：

```
[2] 清单查找（后缀匹配）
    命中：czl-amazon-listing-growth/.codebuddy-plugin/plugin.json   ← 专家照样导入成功
[5] 头像解析（精确匹配）
    未命中任何候选：.codebuddy-plugin/avatars/expert.png / avatars/expert.png
    FAIL 未解析为 data URI，实际值：avatars/expert.png
    结论：导入后头像会退化为首字
```

同一个包的正常版本（无外层目录）校验为 PASS，头像解析为长度 48,514 的 data URI。

**这就是完整因果链**：套一层目录 → 清单靠后缀仍能找到 → 头像靠精确路径找不到 → 回退成相对路径 → 渲染层正则不认 → 首字。

### 2.6 你可以怎么自行排查

拿到任何专家包，按这个顺序看：

1. 解压 zip，看根目录下是不是直接有 `.codebuddy-plugin/`。如果只有一个同名文件夹，就是套层了——**重新打包，选中里面的文件再压缩**。
2. 打开 `plugin.json`，看 `avatar` 值是否以 `./` 或 `/` 开头。有就删掉。
3. 确认 `avatars/` 里文件名与 `avatar` 值的大小写、扩展名完全一致。
4. 重新导入，删除旧专家再导入一次（同名可能命中缓存）。

## 三、相对目标专家的补强点

目标专家是一个 28 行的角色说明 + 一个外部服务导流。它的能力描述是"撰写 / 合规 / 评分 / 申诉"四件事，但**没有任何一步是可执行的**：没有字符规则、没有判定口径、没有可运行的检查、没有输出格式约束，且能力依赖一个未挂载的外部连接器。

本产品在这四件事上逐一补成可执行：

| 能力 | 目标实现 | 本产品实现 |
|---|---|---|
| 撰写 | 提示"生成高转化率文案" | 六道闸门 + 三套标题骨架 + 五点「锚点/利益/证据/场景」结构 + 字符预算先算后写 |
| 合规 | 提示"三级风险" | 词层/类目层/市场层三层扫描，10 类宣称规则 + 7 类目门槛 + 9 站点义务，输出四要素与 GO/CONDITIONAL/BLOCKED |
| 评分 | 提示"评估概率" | 七维加权 0–100，每维可观测、每项扣分带改写动作、附问答缺口清单 |
| 申诉 | 提示"给框架" | 四段式（根因/纠正/预防/证据）+ 提交前自查表 + 拒绝编造理由的边界 |
| 可执行性 | 依赖外部连接器 | 零依赖本地脚本，离线可跑，退出码可串流程 |

另外补了目标专家没有的两件事：**关键词预算分配**（G1）和**输入体检**（G0）——这两处是实际返工最集中的地方。

## 五、实现过程中修掉的 4 个缺陷

记录在此，因为它们说明测试确实在起作用：

| # | 缺陷 | 现象 | 修法 |
|---|---|---|---|
| 1 | 品牌名被误判为全大写滥用 | NORDVIK 触发 `TITLE_ALL_CAPS` | 全大写检测加入品牌豁免 |
| 2 | 关键词正常落位被误判为重复 | 主词在标题/五点/描述各一次（共 3 次）触发 `COPY_DUPLICATE` | 3-gram 重复阈值从 2 提到 4 |
| 3 | `verdict` 与 `exit_code` 口径不一致 | 只有 INFO 时 verdict 显示 WARN 但退出码 0 | verdict 改为三态：有 BLOCK→FAIL、有 WARN→WARN、否则 PASS |
| 4 | 同一义务重复列出 | 德语儿童品同时命中类目层与市场层的 GPSR，出现两条 | 合规条目加 `dedupe` 键去重 |
