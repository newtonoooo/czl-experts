# G1 · 关键词预算

## 职责

把散落的词变成**有归属、有预算的分配表**。核心不是"找更多词"，而是**先算清每个位置能放多少字符，再决定放哪些词**。

写完之后再砍字，是最常见的返工来源。

## 输入参数

| 参数 | 必填 | 说明 |
|---|---|---|
| 主关键词 | 是 | 1–3 个 |
| 次级词 / 长尾词 | 否 | 用户提供的词库 |
| 竞品标题 | 否 | 用于扩词 |
| 站点 | 是 | 决定标题字符预算 |
| 品牌名 | 否 | 占标题预算 |

## 执行步骤

1. **建词池**：主词 + 次级词 + 长尾词 + 竞品标题切词 + 类目常用词。
2. **归一化去重**：小写、去标点、单复数归一、连字符归一。
3. **跑机器分组**：

   ```bash
   python scripts/listing_audit.py keywords --listing x.json --market US
   ```

   脚本按 token 重叠聚类，输出组与建议位置。
4. **人工判噪**：脚本不认识业务。逐组判断：
   - 这组词是买家真会搜的，还是竞品堆的？
   - 有没有词指向了不属于本品类的东西（会把流量带偏）？
   - 有没有他人品牌词（必须剔除）。
5. **算标题预算**：`站点上限 − 品牌长度 − 2`。把预算写在分配表最上面。
6. **分配位置**，输出表。

## 判断条件

| 情况 | 动作 |
|---|---|
| 标题预算不足以容纳主词 | 缩短品牌展示或改用骨架 B（场景优先），不能砍主词 |
| 两个词高度同义（cup / tumbler） | 只留搜索量更高的那个进标题，另一个进后台词 |
| 出现他人品牌词 | 直接剔除，不解释、不折中 |
| 出现类目外词（如杯子 listing 里放"phone case"） | 剔除，会拉低相关性 |
| 长尾词 ≥3 个词 | 一律进后台搜索词，不塞标题 |

## 输出格式

```markdown
## 关键词预算（US，标题上限 200，品牌 NORDVIK，可用 191）

| 词 | 类型 | 归属位置 | 占用字符 | 理由 |
|---|---|---|---|---|
| collapsible coffee cup | 主词 | 标题前段 | 23 | 主词必须在前 5 词内 |
| 350 ml | 属性 | 标题 | 6 | 买家最关心的规格 |
| leak proof | 属性 | 标题 | 10 | 与竞品的主要差异点 |
| camping mug | 场景 | 五点 | - | 做具体场景句 |
| collapsible cup with lid for travel | 长尾 | 后台词 | - | 3 词以上，标题放不下 |

标题已用 39 / 191 字符，余 152。
```

## 异常处理

- **用户词库只有 2 个词**：不硬凑。用竞品标题和类目词扩，扩不出来就说明"词池偏小，标题后段用属性词补位"，并建议用户去后台搜索词报告取真实词。
- **用户坚持要塞 6 个同义词进标题**：给出具体后果（稀释主词权重、触发堆砌判定），给一版合规写法，让他选。不要默默照做。
- **站点上限与后台不一致**：以后台为准，更新 `marketplace-rules.json` 的对应值并记一笔。

## 依赖

- G0 的输入卡（主词、站点、品牌）。
- `references/marketplace-rules.json` 的字符基线。
- `scripts/listing_audit.py keywords`。

## 与其他工作流的关系

- 上游：G0。
- 下游：G2（按分配表写）、G3（后台词也要过合规扫描）。
- 回退：G2 写完发现某词放不下，退回本门重排，不要在现场硬塞。
