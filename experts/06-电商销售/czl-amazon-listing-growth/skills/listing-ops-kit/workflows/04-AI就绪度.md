# G4 · AI 推荐就绪度

## 职责

回答一个问题：**买家在问答式购物助手里问的那些问题，这份 Listing 答得上来吗。**

分数只是坐标，真正有用的是后面的"问答缺口"清单。

## 输入参数

| 参数 | 必填 | 说明 |
|---|---|---|
| 文案全文 | 是 | 标题 + 五点 + 描述 |
| attributes | 是 | 八槽位，缺项会直接扣 D1 |
| 主关键词 | 否 | 缺了 D7 不计入扣分 |

## 执行步骤

1. **跑评分**：

   ```bash
   python scripts/listing_audit.py score --listing x.json
   ```

2. **读七维得分**，按 `references/score-rubric.md` 的口径核对每个扣分项是否成立（脚本按词面判定，可能有误判）。
3. **人工复核误判**：脚本把"clean"当清洁探针命中，但文案里可能是"clean design"。这类要人工改判并说明。
4. **补问答缺口**：脚本给出未答问题清单，逐条写一句补写建议。
5. **给分数区间与动作**：85+ 保持 / 70–84 按项补 / 50–69 重写五点 / <50 整体重写。

## 判断条件

| 情况 | 动作 |
|---|---|
| 分数 < 70 | 不给"微调"建议，直接指向结构重写 |
| 未答问题 ≥ 4 条 | 优先补问答，收益高于调关键词 |
| D1 扣分最多 | 先补 attributes，这是最容易也最有效的一项 |
| 文案本身违规（G3 BLOCKED） | 不评分。先解决合规，再谈就绪度 |
| 脚本判定与人工判断冲突 | 以人工为准，但要在交付里说明为什么改判 |

## 输出格式

```markdown
## AI 推荐就绪度：72 / 100 — 有明确缺口

| 维度 | 得分 | 权重 |
|---|---|---|
| D1 属性完整度 | 12.5 | 20 |
| D2 场景与人群覆盖 | 10 | 15 |
| D3 问答覆盖 | 10.5 | 15 |
| D4 实体一致性 | 15 | 15 |
| D5 结构化程度 | 15 | 15 |
| D6 差异化证据 | 6 | 10 |
| D7 关键词自然度 | 10 | 10 |

### 扣分明细与改写动作

- `D1` 属性缺 3 项：weight、care、style → 后台补齐，或在五点写一句带数值的话覆盖
- `D3` 未回答：怎么清洁、耐用吗、兼容什么 → 在第五条补一句维护与适配边界
- `D6` 五点中带单位数字 2 个 → 每条卖点至少给一个数字

### 问答缺口（这一节比分数有用）

| 买家会问 | 现状 | 补写建议 |
|---|---|---|
| 能不能放洗碗机 | 未答 | 加一句"top rack dishwasher safe" |
| 折叠后多厚 | 已答 | — |
| 装热水会不会烫手 | 半答 | 补"双层壁，外壁不烫手" |

### 下一步

先补 attributes 的 weight 与 care，再补两条问答，重跑应能到 85。
```

## 异常处理

- **文案太短无法评分**（如只有标题）：明确说"信息量不足以评分"，先走 G2。
- **用户把分数当销量预测**：纠正。分数衡量信息结构完整度，与销量无因果关系。
- **分数很高但转化差**：说明问题不在文案结构，可能在主图、价格、评论或流量，给出排查顺序。

## 依赖

- G2 的文案、G0 的 attributes。
- `references/score-rubric.md`。
- `scripts/listing_audit.py score`。

## 与其他工作流的关系

- 上游：G3 判定非 BLOCKED。
- 下游：无强制下游。分数低于 70 时回退 G2。
- 与 G1 的关系：D7 依赖主词落位，主词分配错会直接扣分，可退回 G1。
