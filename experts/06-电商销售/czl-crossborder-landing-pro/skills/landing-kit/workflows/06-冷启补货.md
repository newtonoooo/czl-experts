# 工序 ⑥ 冷启补货

## 名称

冷启补货（Cold Start & Replenishment）——投放带止损线，补货带断货日。

## 任务职责

把"上架之后怎么办"写成两件可执行的事：一张带止损条件的投放表，一张带日期与金额的补货表。产出《冷启补货》。
没有止损线的投放表不算完成；没算过现金占用的补货表也不算完成。

## 输入参数

| 参数 | 必需 | 说明 |
|---|---|---|
| 保本 ACOS | 是 | 来自工序 ③，广告止损线就是它 |
| 售价与净利率 | 是 | 来自工序 ③ |
| 日均销量预估 | 是 | 冷启动期用保守值（类目均值 × 0.5） |
| 海运/空运时效 | 是 | 含排产、报关、末端，不只是航行天数 |
| MOQ | 是 | 工厂起订量 |
| 在库与在途 | 是 | 当前数量 |
| 现金预算 | 否 | 首批能压多少钱 |
| 单件落地成本 | 是 | 来自工序 ③，用于算占用资金 |

## 执行步骤

```
1  定投放结构：自动 / 手动广泛 / 手动精准 / 品牌或展示，四层各自的预算与目标
2  给每层写止损条件：连续 7 天 ACOS > 保本 ACOS → 降价或关停；点击 >X 无单 → 否词
3  定预算节奏：第 1–2 周只跑自动与手动广泛（收词），第 3 周起把出单词提到精准
4  跑补货脚本：
     python scripts/replenish_plan.py --input case.json
5  读四组数：补货点、在库耗尽日、最晚下单日、海空切分与占用资金
6  定首单策略：先 30–45 天量试水，跑通后按 60–90 天补
7  写复盘节点：第 7 / 30 / 60 / 90 天各看转化率、ACOS/TACOS、库存周转
8  出《冷启补货》：投放表 + 补货表 + 现金表 + 复盘节点
```

## 判断条件

| 项 | 通过条件 |
|---|---|
| 止损线 | 每个广告活动都有明确的 ACOS 上限与动作 |
| 首单量 | ≤ 45 天覆盖量；一次铺满 90 天以上的方案不予通过 |
| 补货点 | 已算出，且最晚下单日不晚于今天 +（可售天数 − 海运时效） |
| 现金 | 占用资金 ≤ 预算；超出时给分批到货方案 |
| 空运判断 | 只有在"含在途可售天数 < 海运时效 + 安全天数"时才用空运，且只补缺口 |
| 复盘节点 | 四个节点各自有明确的触发动作，不是"到时候看看" |

## 异常处理

| 情况 | 处理 |
|---|---|
| 无历史销量数据 | 用类目均值 × 0.5 做保守预估，并在表头写"预估，首周后用实际数据替换" |
| 现金不足首批量 | 给三档方案：减 SKU 变体 / 减颜色 / 先空运小批量验证 |
| 海运时效波动大 | 用区间（如 35–50 天）并按下限算最晚下单日，宁可早订 |
| 平台大促临近 | 安全天数上调 7–14 天，补货点同步上移，重跑脚本 |
| 用户只想投广告不谈补货 | 明确说：断货一次，排名恢复成本通常高于省下的库存成本 |

## 依赖与上下游

- **前置**：工序 ③（保本 ACOS、净利率、落地成本）、工序 ⑤（页面转化率决定预算效率）
- **后置**：无（这是最后一道），但 90 天复盘结果回喂工序 ② 与 ③
- **回退**：90 天净利率不达标 → 回工序 ③ 重算成本结构，或回工序 ② 换切口

> 铁律：没有止损线的投放方案不交付；首单一次铺满的补货方案不交付。
