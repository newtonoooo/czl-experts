# 工序 ② 选品

## 名称

选品（Market Screen）——判断这个 SKU 是"进"、"换切口"还是"不进"。

## 任务职责

用四条可核对的判据，把"我感觉能卖"变成"有数据支撑的判断"。产出《选品判定》。
这道工序的价值不在于找到爆款，而在于**用最低成本否掉不该做的品**。

## 输入参数

| 参数 | 必需 | 说明 |
|---|---|---|
| 品类与产品 | 是 | 来自立项卡 |
| 目标市场与平台 | 是 | 来自立项卡 |
| 主关键词 | 是 | 3–5 个，用于查搜索量与竞品 |
| 数据来源 | 是 | 卖家精灵 / Jungle Scout / Helium 10 / 平台前台，注明工具与取数日期 |
| 到岸成本（估） | 否 | 工序 ③ 的产出；没有则本工序只做定性判断并标注 |

## 执行步骤

```
1  定主关键词：品牌词剔除，只留功能词与品类词
2  查需求：主词月搜索量、近 12 个月趋势（上升/平稳/下滑）
3  查竞争：首页自然位评论数（取中位数）、头部是否被 ≤2 个品牌占据、
   近 90 天是否有新品冲进首页（有则说明还有机会）
4  查价格带：首页成交价分布，算出主流价带的上下限
5  查合规预判：品类是否属认证/许可类目（儿童、医疗、食品接触、电子、化妆品）
6  四条判据各自打分，按判断条件给结论
7  写判定文件：结论 + 四条依据 + 数据来源与日期 + 若为"换切口"给三个具体方向
```

## 判断条件

| 维度 | 判据 | 不满足时 |
|---|---|---|
| 需求 | 月搜索量 ≥ 3,000 且趋势非下滑 | 低于 3,000 且无上升趋势 → **缓**（不是不做，是别现在做） |
| 竞争 | 首页评论中位数 ≤ 800，且头部未垄断 | > 800 且前 10 个 listing 有 ≥6 个属同两品牌 → **换切口** |
| 价格带 | 主流价带 ≥ 到岸成本 × 3 | 低于 3 倍 → **不进**（毛利结构撑不住广告与退货） |
| 合规 | 无"无法补齐"的阻断项 | 有阻断项且无办理路径 → **不进** |

**结论只有三个，必须落在其中一个**

- `进`：四条全过，进入工序 ③。
- `换切口`：需求在但竞争过密，给三个具体方向（改规格 / 改人群 / 改捆绑），回本工序重判一次。**最多两轮。**
- `不进`：写明是哪条判据否掉的，并给一个替代方向（相邻品类、相邻价格带、相邻市场）。

## 输出格式

```markdown
# 选品判定 · {产品} · {YYYY-MM-DD}

结论：**进 / 换切口 / 不进**

| 维度 | 实测值 | 判据 | 结论 |
|---|---|---|---|
| 需求 | 月搜索 x,xxx（趋势 ↑/→/↓） | ≥3,000 且非下滑 | 过 / 不过 |
| 竞争 | 首页评论中位数 xxx（头部品牌 n 个） | ≤800 且未垄断 | 过 / 不过 |
| 价格带 | 主流 xx–xx {币种} | ≥ 到岸成本 ×3 | 过 / 不过 |
| 合规 | {命中的认证类目} | 无不可补齐阻断项 | 过 / 不过 |

数据来源：{工具} · 取数 {YYYY-MM-DD}
若换切口：① … ② … ③ …
```

## 异常处理

| 情况 | 处理 |
|---|---|
| 拿不到搜索量数据 | 明说"无工具数据"，改用前台信号（首页评论增速、新品出现频率、BSR 分布）做定性判断，并在结论标"定性" |
| 数据与我方判断冲突 | 以数据为准，把冲突写出来，不改判据迁就直觉 |
| 用户坚持要做被否的品 | 不阻拦，但把否掉的那条判据写成第一行警示，并把结论改成"条件性进入：需接受 X 风险" |
| 品类属季节性 | 加一行"旺季窗口：{月份}，倒推备货需在 {月份} 前下单" |

## 依赖与上下游

- **前置**：工序 ①（品类、市场）
- **后置**：工序 ③（拿"进"的结论才开始算账）、工序 ④（合规预判用于判断是否值得继续）
- **回退**：`换切口` 回本工序；`不进` 回工序 ① 换品或换市场

> 提醒：本工序不给"爆款预测"。任何声称能预测爆款的说法都不成立，能做的只有排除明显不成立的品。
