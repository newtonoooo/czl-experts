## 一、需求是怎么来的

### 1.1 起点

用户希望获得一个能覆盖"跨境电商出海"全流程的专家。市面同类产品（本机已装的跨境类专家）覆盖了平台运营、物流、合规、Listing、广告、品牌等**话题范围**，但呈现出三个共同短板：

| 短板 | 表现 | 后果 |
|---|---|---|
| 给判断不给算式 | "佣金约 15%，广告控制在 25% 以内" | 用户拿不到可复算的数，无法验证结论 |
| 合规给清单不给结论 | 罗列"需要 CE、需要 VAT、需要 EPR" | 用户不知道哪一项不办就不能发货 |
| 无工具 | 全部输出为自然语言 | 同类问题每次回答口径不一致，无法沉淀 |

### 1.2 因此本产品的定位

不是"更全的跨境知识库"，而是**把跨境决策里能算的部分算清楚，把能判的部分判出结论**。

一句话规格：

> 输入一个 SKU + 一个目标市场 + 一个渠道，输出三条保本线、一张合规放行单、一套过检的页面底稿、一张带止损与断货日的补货表；每个数字可复算，每个结论有放行条件。

### 1.3 明确不做的

见第七节"非目标"。

## 二、目标用户与使用场景

### 2.1 用户画像

| 画像 | 特征 | 最常问的问题 |
|---|---|---|
| 工厂型卖家 | 有产能、有成本优势，不懂海外规则 | "我这个品能不能卖到美国？能赚多少？" |
| 贸易型卖家 | 选品能力强，供应链弱 | "这个价卖得动吗？备多少货不压死？" |
| 转型中的国内电商卖家 | 熟悉国内平台，误以为规则通用 | "国内这套打法搬到亚马逊行不行？" |
| 小团队操盘手 | 一人管多店，时间极碎 | "别讲原理，直接给我能不能做、缺什么" |

### 2.2 典型场景（按频次）

1. **定价前算账**（最高频）：拿到报价，判断这个价能不能做。
2. **上架前合规自查**：准备发第一批货，确认缺什么证。
3. **文案交付前体检**：写完标题五点，担心被拦或转化差。
4. **补货决策**：销量起来了，什么时候下单、备多少。
5. **新品全流程**：从零开始，需要一条完整路径。

### 2.3 使用环境

- 对话式使用（WorkBuddy 专家中心）
- 需要本机有 Python 3（脚本为纯标准库，无需安装依赖）
- 无需联网即可完成测算（但费率与规则需用户提供或提前核实）

## 三、需要解决的问题（按优先级）

| # | 问题 | 判定"解决了"的标准 |
|---|---|---|
| P0 | 这个价能不能做 | 给出净利率、保本价、保本 ACOS，且能复算 |
| P0 | 能不能合法卖到这个国家 | 给出 GO / CONDITIONAL / BLOCKED，并列出阻断项 |
| P1 | 第一批备多少、什么时候下单 | 给出补货点、最晚下单日、海空切分、占用资金 |
| P1 | 页面会不会被平台拦、会不会转化差 | 给出 error 级问题清单与逐条改法 |
| P2 | 该进哪个市场 / 该不该换品 | 给出四条判据与三态结论 |
| P2 | 投多少、什么时候停 | 每个广告活动带保本线与止损条件 |

## 四、必要的输入与预期输出

### 4.1 输入（按闸门）

| 闸门 | 必需输入 | 可选输入 |
|---|---|---|
| G0 立项 | 产品一句话、目标国家、渠道 | 出厂价、MOQ、现有资质、预算 |
| G1 选品 | 主关键词、数据来源 | 到岸成本估值 |
| G2 成本 | 售价、出厂价、头程、关税率、佣金率、配送费、退货率、广告占比 | 收款费率、仓储、固定费用、目标净利率、汇率 |
| G3 合规 | 品类、国别 | 已具备的证书/税号编号 |
| G4 页面 | 平台、产品事实、卖点证据、目标词 | 品牌名、竞品页面 |
| G5 冷启补货 | 保本 ACOS、日均销量、海运空运时效、MOQ、在库与在途、单件落地成本 | 现金预算、单件毛利 |

**输入不完整时的规则**：缺的参数标 `[待填]`，并说明这个数会影响哪一行结论；不设默认值假装算过。

### 4.2 输出

| 输出 | 形态 | 必含内容 |
|---|---|---|
| 立项卡 | Markdown | 产品、市场、渠道、预算、资质、待答问题、本次假设 |
| 选品判定 | Markdown | 四条判据实测值 + 三态结论 + 数据来源与日期 |
| 成本定价 | Markdown + 脚本原始输出 | 成本瀑布、三条保本线、价格阶梯、敏感性、未计科目 |
| 合规放行单 | Markdown | 总判定 + 三级清单（编号/证据/谁办/周期）+ 风险提示 |
| Listing 文案包 | Markdown | 标题五点描述 + 关键词覆盖 + 体检结果 + 三处待审校 |
| 冷启补货 | Markdown | 投放结构 + 止损条件 + 补货点与断货日 + 现金占用 + 四节点复盘 |

**命名规范**：`{类型}-{产品}-{市场/平台}-{YYYY-MM-DD}.md`

## 五、通用处理步骤（六道闸门）

```
G0 立项 ──▶ G1 选品 ──▶ G2 成本 ──▶ G3 合规 ──▶ G4 页面 ──▶ G5 冷启补货
   │            │            │            │            │            │
 立项卡      选品判定      成本定价     合规放行单   Listing包    冷启补货表
```

| 闸门 | 核心动作 | 不过怎么办 |
|---|---|---|
| G0 | 三清检查（成本口径/目的国/卖家身份） | 缺哪问哪，一次最多三问 |
| G1 | 四条判据（需求/竞争/价格带/合规预判） | 缓 / 换切口（最多两轮）/ 不进 |
| G2 | 脚本算到每成交一单 | 净利率 <10% 只给成立条件 |
| G3 | 品类 × 国别三态判定 | BLOCKED 只给补齐清单 |
| G4 | 文案 + lint 前移 | error 不为 0 不交付 |
| G5 | 投放止损 + 补货模型 | 无止损线 / 首单超 45 天 → 不通过 |

**单点直通**：用户只问一个维度时，可只走对应闸门，但必须带前置假设并声明"以此为限"。

## 七、非目标（明确不做）

| 不做 | 原因 |
|---|---|
| 国内平台（淘宝/天猫/京东/拼多多/抖音小店）运营 | 属另一套流量与规则体系 |
| 货代订舱、报关代理、实时运价 | 需实时舱位与资质 |
| 代办税号、代办认证、代持责任人 | 需持牌资质 |
| 刷单、测评操纵、改差评、跟卖抄图 | 账号封停与法律责任 |
| 保证排名、保证爆单、保证 ROI | 平台流量分配不可控 |
| 专利有效性与侵权判定 | 需 FTO 检索与法律判断 |
| 独立站从零开发 | 属开发工程 |
| 汇率预测 | 只做敏感性提示 |

## 八、质量、速度与稳定性要求

### 8.1 质量

| 指标 | 要求 | 验证方式 |
|---|---|---|
| 数字可复算 | 交付里每个金额都能追到一次脚本运行 | 测试报告附原始输出 |
| 费率不虚构 | 缺参数一律标"待填" | 人工检查 4 份样例输出 |
| 合规有结论 | 必须落 GO / CONDITIONAL / BLOCKED 之一 | 脚本判定 + 人工复核 |
| 文案可交付 | error 为 0 才交付 | 退出码检查 |
| 假设透明 | 交付含"本次假设"与"未计科目" | 模板强制字段 |

### 8.2 速度

| 动作 | 目标 |
|---|---|
| 单脚本运行 | < 1 秒（512 项以内规则匹配、千级字符 lint） |
| 单道闸门交付 | 3–8 轮对话内完成 |
| 全流程（G0–G5） | 交付 6 份文件，分阶段推进，不一次倾倒 |

### 8.3 稳定性

| 要求 | 实现方式 |
|---|---|
| 模型公式不被误改 | 每个脚本内置 7 项 `--selftest` 断言，改动后必须全绿 |
| 非法输入有明确报错 | 退货率 ≥100%、缺汇率、缺销量、未知品类/市场/平台均返回 2 并说明 |
| 规则可维护 | 规则外置 JSON，带 `meta.as_of` 与免责声明 |
| 结果可追溯 | 输出带币种、汇率与取数日、规则版本 |
