## 一、开发前的边界确认

### 1.1 只做了功能层面的分析

对参考对象（本机市场中的跨境类专家）只做了三类观察，均属**功能与结构层面**：

1. 覆盖的话题范围（平台运营、物流仓配、合规、Listing、广告、收款、选品、品牌、客服）；
2. 它的产品形态（单角色 Agent 型、无脚本、无规则数据文件）；
3. 它的明显短板（给判断不给算式、合规罗列不给结论、无工具、无法复算）。

**没有做**：复制其提示词原文、复制其文件结构、复制其目录命名、复制其头像或宣传文案。参考包中的 `README.md`、`agents/*.md`、`skills/browser-use/**` 均未进入本项目。

### 1.2 关于许可链的判断

参考对象的 agent 提示词标注"改编自 agency-agents（MIT）"，技能为 `browser-use`（MIT）。理论上 MIT 允许商业使用与再分发（需保留版权声明）。本项目仍选择**独立实现**，原因：

- MIT 声明只覆盖 agency-agents 仓库本身，无法确认其上游是否含其他来源内容；
- 该专家包未说明其自身对下游的授权条款；
- 独立实现可彻底消除授权链不确定性，且产品形态本就不同（工程化 vs 顾问式）。

该判断已写入 `docs/发布风险清单.md` R1、R2。

## 三、头像的制作过程

| 步骤 | 做法 |
|---|---|
| 生成 | 用 WorkBuddy 内置图像生成，prompt 按角色特征构造：年轻、干练、白衬衫 + 深灰技术马甲 + 工牌挂绳、一手小纸箱一手平板（屏上是成本柱状图）、背景金色渐变 + 地球轮廓 + 航线弧 + 集装箱船与货机图标、无文字无字母 |
| 首轮问题 | ① 输出 1024×1024、1.6 MB；② 右下角带生成工具水印 |
| 处理 1 | 环境无 Pillow、无 PyPI 通道、PowerShell `Add-Type` 被安全策略拦截 → **用纯标准库自写 PNG 解码 + 面积平均缩放**（`build_tools/avatar_prep.py`），裁掉水印区（crop 40,0,944,944）并缩放到 512×512 |
| 处理 2 | 缩放后仍 602 KB，超 500 KB 上限 → **自写中位切分调色板量化**（`build_tools/quantize_png.py`，5 位分箱 + 256 色 + 8 位索引 PNG），降到 135,608 字节 |
| 验证 | `struct` 解析 IHDR：512×512、depth 8、colortype 3；目视检查水印已消失、无可见色带 |

两个构建脚本留在 `build_tools/`，不进专家包（不是产品功能的一部分），但保留以便后续换图复用。

## 四、关键设计决策与理由

| 决策 | 备选 | 为什么这么定 |
|---|---|---|
| 按"每成交一单"建模 | 按"每发一单" | 退货率 20% 时两者差 25% 的发货量；按发货算会让退货率越高账面越好看，这是行业里最常见的错误 |
| 合规做成三态判定 | 罗列"要办哪些证" | 用户真正需要的不是清单，是"哪一项不办就不能发货"。三态可执行、可放行、可阻断 |
| 净利率双阈值（15% / 10%） | 单一阈值 | 15% 是警戒（低于则广告无试错空间），10% 是否决（低于则不给"可以做"）。单阈值会让 11% 的方案看起来"过线" |
| 缺参数标"待填"而非填默认值 | 填行业均值 | 行业均值会让结论看起来完整但失真，且用户无法察觉。宁可表里有空格 |
| 规则外置 JSON | 写死在代码 | 平台字数与合规要求每季度都在变；外置后用户可自行维护，不必改代码 |
| 文案 lint 前移到交付前 | 交付后建议自查 | "建议自查"等于没做。放进脚本并用退出码卡住，才有约束力 |
| 单脚本而非一个大脚本 | 一个 `tool.py` 带子命令 | 四个问题域彼此独立，分开后每个都能独立 `--selftest`、独立被调用、独立维护 |
| Agent 型而非 Team 型 | 多角色专家团 | 六道闸门本身是串行依赖，不是并行分工；做成团队会引入调度开销却换不来并行收益。多人协作的收益点在"并行分析"，此处不成立 |

## 五、开发中修复的问题（9 项）

详见 `docs/功能测试报告.md` 第三节。其中三项属**模型错误**而非编码错误：

1. `--cost-in-cny` 把目的国侧费用（配送费/仓储/退货处理）也按汇率折算了 —— 这三项本来就是目标币计价，折算会让配送费虚高；
2. 补货"最晚下单日"从在库耗尽日倒推，忽略在途，导致日期偏早、误判"已过触发日"；
3. 敏感性网格递归调用主函数导致 RecursionError —— 说明主函数职责过重，加 `deep` 开关分离。
