## 二、逐项说明

### R1 商标风险（高，需你决定）

"净利操盘手"是本次新造的名称，未做商标检索。风险有两层：一是他人在先注册导致无法作为品牌使用；二是被认定为与在先商标近似。

**替代方案**：若检索不通过，可换为"毛利操盘手""账盘""单品账本"等，包名 `czl-ecom-profit-ops` 不必改动（包名是标识符，不是品牌）。

### R2 合规内容的责任边界（高，需你决定）

包内 `banned-claims.md` 与 `category-licenses.md` 是**自查工具**，覆盖常见高风险表达，但不构成法律意见，也不保证穷尽。

已做的隔离：
- 词表每条给"替换写法"而非"违法结论"
- 文件开头明确写"不是法律意见"
- LICENSE 第三条免责
- 主提示词硬规则第 7 条要求"指出并给替换写法，不帮用户绕过"

仍存在的风险：用户可能把输出当成法律结论。**建议在详情页加一句"合规内容为自查参考，正式发布前请自行核验或咨询律师"。**

### R3 会过期的平台数字（中）

本次刻意**不写死**任何平台费率、佣金比例、报名门槛、标题字数上限。原因：检索时发现不同来源对同一平台的标题字数给出互相矛盾的说法（30 汉字 / 60 字符 / 60 汉字并存），无法确证，因此工具改为 `--limit` 参数传入，由用户填当期值。

参考卡中出现的具体数字（如示例成本、示例折扣）均为**演示用**，不是行业标准。建议在详情页说明这一点，避免用户误当基准。

### R4 输入质量（中）

账本的可信度上限等于输入数据的可信度。已在三处设防：
1. 主提示词要求"三数不全就先要数，不替用户假设"
2. 输出每个数字带口径
3. 敏感性表让用户看到"参数错一点，结论差多少"

### R5 头像授权（中）

头像由 WorkBuddy 内置图像模型生成，成品已去除平台水印并重制为 512×512。

**需要你确认**：所用图像模型服务的商用条款是否允许将生成结果用于商业产品。这一步我无法代为确认，属于你与服务提供方之间的协议问题。

**替代方案**：若条款不允许，可改用自行绘制的矢量图标（几何 + 图表符号），我可以重做。

### R6 原创性证明（中）

本包为独立开发，未复制目标专家的任何句子或代码。开发记录里保留了"读了哪些文件、提取了什么、没用什么、为什么"。这份记录是原创性的最好证据，建议随包保留、不要删。

需要注意：方法论层面（成本瀑布、保本点、逐项替换）属于通用技术，任何同类产品都会用，**不构成独创性主张**。宣传时不要声称"独创方法"。

### R7 客户端表现（中）

已完成：`validate_expert.py` 通过、`register_expert.py` 注册成功。
未完成：在专家中心界面对话、观察实际路由是否按预期加载技能。

**建议**：重启客户端 → 专家中心 → 我的专家 → 用第三条推荐问法（合规场景）测一次，再用第一条（账本场景）测一次。若技能未被加载，检查 `skills` 字段路径。

### R9 平台商业条款（未知）

我不知道你计划上架的具体平台及其分成规则、独家条款、定价限制。这些需要你查阅对应协议。**不要在没有确认条款的情况下承诺独家或排他。**

### R10 用户数据敏感性（中）

用户会把拿货价、毛利率、投放数据输进对话，这些属于商业秘密。建议在详情页加一句："请勿输入可识别具体客户身份的订单明细；建议使用汇总数据。"
