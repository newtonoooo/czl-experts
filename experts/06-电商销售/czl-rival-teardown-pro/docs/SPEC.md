## 1. 背景与目标

### 1.1 目标用户

| 用户角色 | 典型规模 | 使用频率 | 核心诉求 |
|---|---|---|---|
| 亚马逊精品卖家 / 品牌方运营 | 1-5 人小团队 | 每周 1-3 次 | 找出对手弱点，决定这一轮改什么 |
| 跨境代运营 / 服务商 | 5-50 人 | 每天 | 快速产出可交付给客户的竞品报告 |
| 新卖家 / 选品阶段 | 个人 | 不定期 | 判断这个类目还值不值得进 |
| 独立站 / 多平台卖家 | 个人 | 每月 | 借用亚马逊竞品的打法迁移到其他平台 |

共同特征：**懂业务但缺时间，能看结论但没耐心看过程，需要能直接拿去开会的东西。**

### 1.2 使用场景

1. **对手突然超过我**：排名被反超，需要 24 小时内说清对手做对了什么。
2. **上新品前的对标**：选定 1 个标杆竞品，反推自己的 listing 该怎么写。
3. **投放前的卖点排序**：不确定主图第一句该讲什么，用评论与 QA 反推。
4. **客户提案**：代运营需要一份看起来专业、结论站得住的竞品报告。
5. **选品决策**：判断某个价格带是否已被锁死、还有没有空位。

### 1.3 要解决的问题

| 问题 | 表现 | 本产品的解法 |
|---|---|---|
| 看不懂 | 对手 listing 平淡但排名高 | 五层拆解，把「平淡」拆成具体的选择与取舍 |
| 说不清 | 知道对手强，说不出哪一层 | 分层结论 + 证据编号 + 强度评分 |
| 落不下 | 报告很厚，不知道先做什么 | 单一主攻方向 + 带验证指标的动作清单 |
| 不敢信 | 分析里混着猜测与事实 | 四级证据体系 + 数据缺口表 + 能力边界声明 |
| 不合规 | 抄了对手文案或用了绝对化表述 | 文案种子强制合规自查 + 合规红线小节 |

## 2. 输入规范

### 2.1 输入形态

| 形态 | 示例 | 处理方式 |
|---|---|---|
| ASIN | `B08N5WRWNW` | 默认按 US 站点构造链接，并提示确认 |
| 商品链接 | `https://www.amazon.com/dp/B08N5WRWNW` | 提取 ASIN 与站点 |
| 短链 | `https://amzn.to/xxxx` | 标记需展开，请用户提供展开后的链接 |
| 粘贴文本 | 标题/五点/评论/QA 原文 | 按「用户供给」通道处理 |
| 截图 | 页面截图 | 先转文字描述，再进入分析 |

### 2.2 最小输入与理想输入

- **最小可用**：竞品 ASIN 或链接（其余由抓取补齐）。
- **理想输入**：竞品标识 + 我方产品信息（品类、价格、现有优势）+ 本次想解决的问题。
- **降级可用**：仅粘贴 listing 文案与 10 条以上评论，可完成 L1/L2/L4，L3/L5 标注低置信。

### 2.3 输入校验规则

1. ASIN 必须为 10 位字母数字，否则提示用户确认。
2. 未识别站点时按 US 处理，并在报告中标注该假设。
3. 评论样本少于 10 条时，口碑层结论一律降级为「推断」。
4. 未提供我方产品信息时，不输出「我方胜率」。

## 3. 输出规范

### 3.1 交付物

| 文件 | 必须 | 结构 | 用途 |
|---|---|---|---|
| `竞品拆解-{ASIN}-{date}.md` | 是 | 15 章固定顺序 | 完整分析 |
| `打法卡-{ASIN}-{date}.md` | 是 | 一页纸 ≤400 字 | 决策与对齐 |
| `文案种子-{ASIN}-{date}.md` | 是 | 3 个角度 × (标题+五点+主打词+适用前提) | 文案执行 |
| `证据台账-{ASIN}-{date}.csv` | 是 | 6 列固定表头 | 复核与存档 |
| `视觉brief-{ASIN}-{date}.md` | 否 | 按需 | 视觉执行 |

### 3.2 质量要求

| 维度 | 要求 | 验收方式 |
|---|---|---|
| 结构完整 | 15 章齐全，无占位符 | `check` 命令 |
| 可追溯 | 结论带证据编号，≥3 个不同编号 | `check` 命令 |
| 样本透明 | 口碑层写明样本量与抽样方式 | `check` 命令 |
| 缺口透明 | 数据缺口表非空 | `check` 命令 |

### 3.3 报告章节（固定）

0 一页速览 / 1 分析概览 / 2 竞品基本信息 / 3 证据台账摘要 / 4 L1 需求定位 / 5 L2 表达 /
6 L3 视觉 / 7 L4 口碑 / 8 L5 竞争格局 / 9 强度评分卡 / 10 差异化打法 / 11 行动清单 /
12 数据缺口 / 13 本报告不能回答什么 / 14 合规红线 / 15 证据索引

## 4. 处理流程（通用步骤）

```
输入体检 → 证据采集 → 五层拆解 → 强度评分 → 打法生成 → 交付质检
   P0         P1          P2          P3          P4          P5
```

| 阶段 | 判断条件 | 输出 | 失败处理 |
|---|---|---|---|
| P0 输入体检 | 有 ASIN/链接 → 继续；只有文本 → 转供给通道；什么都没有 → 问 3 个问题 | 受理回执（3 行） | 一次问完，不反复确认 |
| P1 证据采集 | 五层关键字段是否够用 | 证据台账 + 缺口清单 | 抓取失败即切用户供给，给 6 项清单 |
| P2 五层拆解 | 每层三问是否答全 | 五层结论（带编号与置信度） | 某层无证据 → 降级为推断，不跳层 |
| P3 强度评分 | 五层是否都有分 | 加权总分 + 档位 + 建议打法 | 缺分则该层按 50 分中性处理并标注 |
| P4 打法生成 | 是否有 3 个候选且写明淘汰理由 | 主攻 1 + 备选 1 + 动作清单 | 候选不足 → 回到 P2 补盲区扫描 |
| P5 交付质检 | `check` 是否通过 | 四件套文件 | 未通过 → 修复后重跑 |

## 6. 非功能要求

| 维度 | 要求 | 实现方式 |
|---|---|---|
| 速度 | 单竞品完整报告在 1 次会话内完成 | 阶段化流程 + 骨架模板，避免重复组织语言 |
| 稳定性 | 任一数据源失败不阻断整体 | 错误隔离：缺哪层降哪层置信度 |
| 一致性 | 不同竞品分数可比 | 权重固定，不允许临时改权重 |
| 可复核 | 结论可追溯 | 证据编号 + 台账 + 证据索引 |
| 可移植 | 无外部服务也能跑 | 零依赖 CLI，纯文本交付物 |
| 合规 | 不产出高风险话术 | 合规红线小节 + 绝对化用语自动扫描 |

## 7. 相对通用竞品分析做法的补充

本产品在通用四维分析（文案/视觉/评论/市场）的基础上补充了以下机制，这些是本产品的
设计增量，不是对任何现有产品的复制：

1. **输入体检（P0）**：先判断输入够不够、缺什么，再决定走抓取还是用户供给，避免「拿到半份数据就开写」。
2. **证据分级与台账**：把「事实 / 可核数据 / 推断 / 待验证」分开，报告内可追溯到行号。
3. **分层三问**：每层必须回答「做了什么选择 / 服务谁 / 代价是什么」，强制产出机会点而非描述。
4. **可复算评分**：权重固定、结果由脚本计算，避免不同报告口径不一。
5. **候选切口筛选**：3 个候选 → 二维打分（可验证性 × 资源匹配）→ 主攻 1 个，并写明淘汰理由。
6. **动作可验收**：每条动作带类型、负责角色、工作量、验证指标、验证周期。
7. **能力边界声明**：报告必须写「不能回答什么」，防止结论被过度使用。
8. **结构质检**：交付前自动检查 7 项，未通过不算完成。
9. **合规红线**：主动识别医疗功效、绝对化用语、未证实背书、比较贬低等风险。

## 8. 不做什么

- 不做多竞品打包浅扫（用户要求时按优先级逐个深拆）。
- 不做销量预测模型，不承诺精度。
- 不做广告投放结构反推（数据不可得）。
- 不做侵权文案代写。
- 不做店铺整体诊断（超出竞品拆解范围，建议另开任务）。
