## 00 起点：需求分析

**输入**：一个已有的亚马逊竞品分析专家包，作为功能参考对象。

**分析方法**：只读取其文件结构与功能描述，提炼「它解决什么问题」，不提取其文本表达。
具体看的是：包结构（plugin.json / agents / skills / prompts）、工作流的阶段划分、
输出报告包含哪些章节。

**明确不做的事**：

- 不复制其 `analysis-prompt-base.md` 的任何段落
- 不沿用其四维命名（The Brain / The Face / The Voice / The Pulse）
- 不沿用其报告章节顺序
- 不复制其 Skill 描述、README 文案、公众号推广语
- 不修改其原包（原包保持原样，未删除任何版权声明）

**理由**：目标包是 MIT 许可，技术上允许复用并要求保留版权声明。但本产品要作为独立商品
商业化，混入他人文本会导致权属不清与后续维护困难，因此选择完全独立撰写。

## 01 需求重写：从「它做什么」到「我要做成什么」

把目标功能翻译成需求，再补上它没做的事：

| 维度 | 目标包的做法 | 本产品的处理 |

| 分析框架 | 四维（文案/视觉/评论/市场） | 五层（需求定位/表达/视觉/口碑/格局），把「市场」拆成「口碑反馈」与「货架格局」，并新增需求定位层 |

## 02 命名与定位

**候选**：最强竞品拆解专家 / 专业竞品拆解官 / 拆敌

**决策**：

- 产品名 `czl-rival-teardown-pro`（czl 前缀 + 功能 + pro），符合「包名以 czl- 开头」的要求。
- 中文职业头衔「专业亚马逊竞品拆解专家」，不用「最强」——理由见 RISK-REGISTER R4（广告法绝对化用语）。
- 花名「拆敌」：两字，动词化，便于记忆；对应英文 Rival。

**查重**：本地已有 29 个专家包，逐一比对包名，`czl-rival-teardown-pro` 无重复；
功能上与 `czl-ecom-profit-ops`（利润）、`czl-amazon-listing-growth`（listing 撰写）、
`czl-product-decision-audit`（选品决策）均不重叠。

## 03 框架设计过程

先写「层」，再写「每层问什么」，最后写「怎么从层结论收敛到动作」。

**关键取舍**：把目标包的「评论分析」和「市场分析」拆开重组，原因是这两件事的证据类型
完全不同（评论是用户语言，市场是平台数据），混在一层会导致结论口径混乱。
新拆出的 L4 只谈用户为什么买/退，L5 只谈货架位置与盲区。

**每层三问的来源**：来自一个判断——「描述对手做了什么」是信息，「指出这个选择的代价」
才是洞察。三问中的第三问强制产出机会点，避免报告变成竞品说明书。

**评分权重 20/20/20/25/15 的依据**：口碑层权重最高（25%），因为在亚马逊上评论是
最难被短期复制的资产；格局层最低（15%），因为它变化最快、最容易被外部因素干扰。

## 04 工程实现

### teardown_toolkit.py

设计原则：零依赖、可离线、可被 Agent 直接调用。

- `parse`：先按路径正则提取，再按参数正则，最后按 B0 前缀兜底；站点用最长域名匹配
  （避免 `amazon.com` 误匹配 `amazon.com.au`）。
- `score`：权重写成常量字典，拒绝运行时改权重（保证跨报告可比）。
- `scaffold`：章节与 `references/output-contract.md` 严格对齐，改一处要同时改两处。
- `check`：7 项检查，其中「绝对化用语」需排除合规小节（该节会引用违禁词）。

### package_qa.py

把官方 `validate_expert.py` 没覆盖的部分补上：i18n 完整性、字数区间、
头像尺寸与体积、ASCII 路径、依赖纯净度、禁用目录。
额外提供 `--portable`，把头像转成 data URI 重新打包，用于规避本地路径解析失败。
