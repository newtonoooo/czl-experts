# 输出契约

定义交付什么文件、什么结构、什么算合格。任何一项不满足，都算未完成。

---

## 一、文件清单与命名

| 序号 | 文件名 | 必须 | 说明 |
|---|---|---|---|
| 1 | `竞品拆解-{ASIN}-{YYYY-MM-DD}.md` | 是 | 主报告 |
| 2 | `打法卡-{ASIN}-{YYYY-MM-DD}.md` | 是 | 一页纸决策卡 |
| 3 | `文案种子-{ASIN}-{YYYY-MM-DD}.md` | 是 | 3 个角度的标题/五点草稿 |
| 4 | `证据台账-{ASIN}-{YYYY-MM-DD}.csv` | 是 | 字段级来源 |
| 5 | `视觉brief-{ASIN}-{YYYY-MM-DD}.md` | 否 | 用户需要视觉执行时追加 |

规则：

- ASIN 用大写原值；无 ASIN（纯文本分析）用 `TEXT-{4位摘要}` 代替。
- 日期用分析当天日期，不用文件名里的其他日期。
- 所有文件写在同一目录，便于打包。

## 二、主报告章节顺序（固定）

```
# 竞品拆解报告：{产品简称}

## 0 一页速览
## 1 分析概览
## 2 竞品基本信息
## 3 证据台账摘要
## 4 L1 需求定位层
## 5 L2 表达层
## 6 L3 视觉层
## 7 L4 口碑层
## 8 L5 竞争格局层
## 9 强度评分卡
## 10 差异化打法
## 11 行动清单
## 12 数据缺口
## 13 本报告不能回答什么
## 14 合规红线
## 15 证据索引
```

不增删章节。某一层无数据时，保留章节标题，正文写「无有效证据，本层结论降级为推断」并给推断结论。

### 各章要求

**0 一页速览**：5 行以内。竞品是谁、最强的一处、最弱的一处、主攻方向、下一步验证什么。

**1 分析概览**：分析对象、站点、分析日期、数据通道（抓取/用户供给/数据工具）、采集耗时。

**2 竞品基本信息**：标题、价格、评分与评论数、变体数、类目与排名、优惠形式。缺失写「未获取」。

**3 证据台账摘要**：E1/E2/E3/U 各多少条，覆盖了哪几层，缺口几项。

**4-8 五层**：每层固定三个小节 —— `做了什么选择` / `服务谁` / `代价与机会`，结尾一行 `本层结论`（带证据编号与置信度）。

**9 强度评分卡**：五层分数表 + 加权总分 + 强度档位 + 建议打法。分数必须来自 `score` 命令输出。

**10 差异化打法**：3 个候选切口（含淘汰理由）+ 1 个主攻 + 1 个备选 + 为什么对手不做这件事。

**11 行动清单**：表格，列固定 `# / 动作 / 类型 / 负责角色 / 工作量 / 验证指标 / 验证周期`。类型只能是 文案/视觉/产品/定价/评论运营。

**12 数据缺口**：四列表格，至少 1 行。

**13 本报告不能回答什么**：3-5 条，明确划出能力边界（如无法判断广告投放结构、无法验证真实销量）。

**14 合规红线**：存在风险逐条列；无风险写固定句。

**15 证据索引**：编号 → 台账行号 → 一句话说明。

## 三、打法卡结构（一页纸）

```
# 打法卡：{产品简称}（{ASIN}）

一句话战场：{在什么场景，用什么东西，抢谁的人}

对手最强：{一处} → 我们不硬碰
对手最弱：{一处} → 我们从这里进

主攻切口：{一句话}
为什么成立：{三条，各一句}
为什么对手不做：{一句}

本周动作（≤5 条）
1. {动作} → 验证：{指标}（{周期}）
...

不做什么（同样重要）
- {明确放弃的方向 + 一句理由}
```

限制：全文 ≤ 1 屏（约 400 字）。超了就删，不是缩字号。

## 四、文案种子结构

三个角度各一组：

```
### 角度 A：{切口名}
标题（≤200 字符，含核心场景词）：...
五点：
1. ...
2. ...
3. ...
4. ...
5. ...
主打词：{3-5 个}
适用前提：{什么情况下用这个角度}
```

要求：

- 每条五点前 6 个字必须是完整卖点，不能是铺垫。
- 全部标注「草稿，需合规复核」。
- 不得出现绝对化用语、未证实背书。
- 不得与对手原文有连续 8 个词以上的重合。

## 五、质检命令与判定

```bash
python3 scripts/teardown_toolkit.py check <主报告路径>
```

检查项与失败含义：

| 检查项 | 失败含义 | 修法 |
|---|---|---|
| 章节完整性 | 缺章节或标题被改写 | 用 `scaffold` 重新生成骨架后迁移内容 |
| 占位符残留 | 有 `<!-- FILL -->` 或 `[TODO]` | 逐处填充 |
| 证据编号 | 结论段无 `E1-`/`E2-`/`E3-` 编号 | 补编号或降级为待验证 |
| 样本量披露 | 口碑层没写样本条数 | 补「样本量：N 条」 |
| 缺口表 | 无「数据缺口」表或表格为空 | 补缺口 |
| 合规小节 | 缺「合规红线」 | 补小节 |
| 绝对化用语 | 出现「最好/第一/唯一/永久」等 | 改为可验证表述 |

退出码 0 = 通过；1 = 有失败项，需修复。

## 六、语言与格式

- 中文为主，用户用英文提问则全篇英文。
- 表格优先于长段落；每段不超过 5 行。
- 数字带单位与时间点（「$29.99，采集于 2026-10-28 10:20」）。
- 不使用 emoji 装饰结论。
- 引用评论原文时加引号并标注星级与日期。
