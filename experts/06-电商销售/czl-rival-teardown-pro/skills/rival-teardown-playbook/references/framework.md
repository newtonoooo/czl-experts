# 五层拆解框架

这套框架的设计原则：**每一层都必须产出「对手的选择」和「选择的代价」，只描述现象不出结论的内容不算完成。**

层与层之间是递进关系：L1 决定他在服务谁，L2/L3 是他对这群人的说服方式，L4 是说服结果的真实反馈，L5 是他在整个货架上的位置。跳层会得出漂亮但没用的结论。

---

## L1 需求定位层：他在服务谁

### 要看什么

| 观察点 | 具体看什么 | 说明什么 |
|---|---|---|
| 标题主语 | 主语是品牌、品类词还是场景词 | 主语是场景词 → 打的是明确需求；主语是品牌 → 打的是信任 |
| 变体结构 | 颜色/尺寸/套装/数量的组合方式 | 变体多而杂 → 铺流量；变体少而准 → 押单一场景 |
| 首图出现的人/场景 | 有人物、有使用场景、纯产品 | 有人物场景 → 卖解决方案；纯产品 → 卖参数与质感 |
| QA 提问方式 | 用户问的是「能不能…」还是「哪个更…」 | 「能不能」→ 需求未被满足；「哪个更」→ 已进入比价 |
| 五点第一条 | 第一句承诺什么 | 第一句通常是他们判断的最高优先痛点 |

### 必答三问

1. **他服务的是哪类人在哪个场景下的哪个瞬间？** 写成一句人话，例如「租房党在搬家当天发现旧收纳箱塌了的那一刻」。
2. **他放弃了谁？** 任何定位都有代价：主打便携就牺牲容量，主打专业就牺牲小白。找出他明确不服务的人群。
3. **被放弃的那群人去哪了？** 这批人就是最容易被截流的池子，直接对应 L5 的机会。

### 常见错误

- 把品类当场景：「他卖收纳箱」不是定位，「他卖搬家场景下的抗压收纳」才是。
- 把人群当标签：「25-35 岁女性」不是定位，是画像，落不到动作。
- 忽略变体语言：变体命名方式往往比标题更诚实地暴露主打场景。

## L2 表达层：他怎么说服人

### 拆解四步

**第一步 拆叙事骨架**

把标题 + 五点 + A+ 首屏的第一句全部摘出来，判断属于哪种骨架：

| 骨架 | 特征 | 适用前提 |
|---|---|---|
| 痛点触发 | 先描述糟糕现状，再给解法 | 品类存在明确、高频、可感知的痛点 |
| 场景驱动 | 用一天/一次使用流程串卖点 | 产品价值需要「用起来」才成立 |
| 参数压制 | 开门见山堆规格与对比数字 | 品类已进入参数比拼，用户会主动比 |
| 身份认同 | 强调「和你一样的人在用」 | 复购与社群属性强的品类 |
| 反常识 | 先否定行业惯例，再给新标准 | 有真实技术或结构差异可支撑 |

一个 listing 通常是 1 主 + 1 辅，找出主骨架，辅骨架用于补信任。

**第二步 看卖点排序的经济学**

五点顺序 = 对手对转化阻力的排序判断。把五点各压缩成 6 个字，排成一列，问三个问题：

- 第一条解决的是「不买的原因」还是「买的理由」？解决不买原因的排第一，说明该品类决策阻力大。
- 有没有一条在讲「你可能担心…」？有，说明他们在主动处理异议。
- 最后一条是不是售后/保障？是，说明他们在收口风险。

**第三步 数关键词，但看位置**

统计高频词只是起点，真正有用的是**位置权重**：

- 标题前 80 字符出现的词 → 权重最高（移动端可见范围）
- 五点每条的第一句 → 权重次高
- A+ 首屏文案 → 影响停留，不影响搜索
- 后台/search term 不可见，不做推断

把关键词分成三类：**品类词**（必须覆盖）、**场景词**（差异化所在）、**问题词**（痛点原话）。对手在场景词和问题词上的覆盖密度，直接反映他的定位精度。

**第四步 找语言指纹**

摘出对手反复使用的 3-5 个表达（不是关键词，是句式），例如「不用再…」「专为…设计」「比…更…」。这些句式是他们验证过的说服模板，属于可借鉴的**结构**（不是文案本身）。

### 必答三问

1. 主骨架是什么，为什么这个骨架在这个品类成立？
2. 五点排序暴露了他们认为的最大转化阻力是什么？
3. 他们在哪些场景词/问题词上覆盖不足？（这就是 L2 的机会点）

## L3 视觉层：第一眼赢在哪

### 拆解路径

**主图（决定点击）**

| 维度 | 判断标准 |
|---|---|
| 主体占比 | 产品占画面比例，过大显廉价，过小显不自信 |
| 背景策略 | 纯白 / 场景 / 渐变 / 色块，反映价格带与定位 |
| 光影方向 | 硬光显工业感，柔光显家用感 |
| 是否有「一图说清」的信息 | 主图上直接给尺寸、对比、使用状态 |

**副图序列（决定停留与信任）**

按顺序记录每张图回答的问题，形成「视觉问答链」：

1. 第 1 张通常回答「它是什么」
2. 第 2-3 张回答「它凭什么更好」
3. 中间回答「怎么用/多大/适配什么」
4. 靠后回答「别人怎么说/售后保障」

如果对手的序列里缺了某一环，那就是他留给你的空位。

**A+ 与视频**

- A+ 的分段逻辑：是「功能罗列」还是「场景叙事」
- 是否有对比模块：有对比 = 主动定义战场；无对比 = 回避比较
- 视频前 3 秒给的是什么画面：产品特写 / 使用痛点 / 结果展示

### 必答三问

1. 主图在 0.5 秒内传达了什么？（如果说不清，说明对手也没说清，这是机会）
2. 副图序列缺了哪一环？
3. 视觉上的「钩子」是什么——是构图、色彩、还是信息密度？

### 无法读取图片时的降级方案

用文案反推：五点里描述得最具体的那一条，通常对应视觉上最用力的一张图。据此推断视觉重点，并在报告里标注「视觉层为文案反推，置信度低」。

## L4 口碑层：用户替他说话

### 定量部分

| 指标 | 算法 | 用途 |
|---|---|---|
| 样本量 | 实际读取的评论条数 | 一切结论的前提，必须披露 |
| 好评率 | 4-5 星条数 / 样本量 | 判断口碑健康度 |
| 差评率 | 1-3 星条数 / 样本量 | 判断风险敞口 |
| 评分-样本背离 | 高评分 + 高差评率 | 说明评分被稀释或有刷评嫌疑，需谨慎引用 |

**注意**：样本是「最新 + 最有帮助 + 差评」三个切片的合集，不是全量随机抽样，报告里要写清抽样方式，避免被当成总体比例。

### 定性部分

**好评聚类**：把好评里的购买理由归成 3-5 类，每类给一个「触发场景」。
判断标准：如果一条好评只说「很好用」，归入「无信息」类，不计入聚类。

**差评穿透**：把差评分成三类，处理方式完全不同：

| 类型 | 特征 | 对我们的意义 |
|---|---|---|
| 产品缺陷 | 同一问题反复出现 | 供应链机会，也是最硬的差异化 |
| 描述不符 | 「和图片不一样」「尺寸不对」 | 表达机会：把预期管理做对就能赢 |
| 体验落差 | 物流、包装、客服 | 运营机会：低成本可抢 |

**QA 挖掘**：QA 是下单前的最后一道心理防线。把问题按「能不能/适不适合/会不会」分类，能直接产出文案里的异议处理段落。

### 必答三问

1. 用户真正买的是什么？（不是产品，是结果）
2. 差评里哪一类占比最高，我们能不能在产品和表达上同时解决？
3. QA 里出现频率最高的问题，我们的 listing 有没有正面回答？

## L5 竞争格局层：他在货架上的位置

### 看四个位置

| 位置 | 观察点 |
|---|---|
| 价格位置 | 价格带内的分位、是否有中间价位空缺 |
| 变体位置 | 是否用变体占了多个价格点 |
| 流量位置 | 类目排名区间、是否出现在相邻类目的推荐位 |
| 促销位置 | 优惠形式（券/秒杀/订阅省）、频率、深度 |

### 盲区扫描

盲区 = 对手没做、但用户需要的事。按四个方向扫：

1. **人群盲区**：他放弃了谁（回看 L1 的答案）
2. **场景盲区**：他的图片/文案没覆盖的使用场景
3. **服务盲区**：他没有承诺的保障（试用、终身保修、配件补寄）
4. **组合盲区**：他没有做的套装/耗材绑定

### 必答三问

1. 价格带上有没有明显空缺，空缺是因为没人做还是因为做不了？
2. 他的流量结构是单一依赖还是多点分布？（单一依赖 = 可被单点突破）
3. 四个盲区里，哪一个是我们现有资源能最快补上的？

## 从五层到打法：转换规则

五层拆完后，按下面的顺序收敛，不要跳：

```
L1 被放弃的人群  ┐
L2 覆盖不足的词  ├→ 候选切口（至少 3 个）→ 可验证性 × 资源匹配 → 主攻 1 个
L3 缺失的视觉环  │
L4 未被解决的差评┤
L5 价格/服务空缺 ┘
```

每个候选切口必须能回答：**为什么对手不做这件事？** 如果答不上来，说明这个切口要么不成立，要么对手已经在做只是没写在页面上。

三种典型答案与对应判断：

- 「他做不了」→ 供应链/资质壁垒，最硬的差异化，优先
- 「他不想做」→ 定位取舍，可以做，但要接受同样的取舍
- 「他还没做」→ 时间窗口，快打快验证，窗口期通常 3-6 个月

---

## 框架使用纪律

1. 五层都要写，但可以标注「低置信」；不允许整层跳过。
2. 每层结论必须有证据编号，推断必须写「推断」。
3. 每层至少指出一个「对手的代价」，没有代价的拆解等于没拆。
4. 报告里的动作必须能追溯到某一层的某条结论，不能凭空出现。
