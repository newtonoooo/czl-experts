# 使用说明

## 一、快速开始

装上专家后，直接说人话就行，不需要记命令。四种最常见的开口方式：

**要合同**
> 帮我起草一份办公用品采购合同，我方是甲方（采购方），供应商是乙方，含税总价 20 万，验收后 30 天付款。

**要审查**
> 帮我审一下这份租房合同，我是租客，重点看押金退还和提前解约，有问题的条款直接告诉我怎么改。

**要比对**
> 对方回传了修改版，帮我比一下和原版差在哪，哪些是必须谈的。

**要依据**
> 劳动合同期限 1 年，最多可以约定多长试用期？给我条号和要点。

如果需要精确控制，可以显式说明站位（甲方/乙方）、合同类型、关注点、金额与期限。

## 二、五条工作流怎么用

### W1 起草台

**必须给的三样**：合同类型、双方主体、标的。金额与期限没说也能出稿，会用行业默认值并单独标注。

**能说清就更准**：付款节奏、验收期限、质保月数、违约责任比例、管辖地。

**交付物**：`.docx` 合同文件、`.md` 预览、`.meta.json`（记录用了哪些默认值 + 履约节点）。

**改稿**：直接说"把违约金改成每日万分之三""加一条数据合规""删掉保密条款"，会只改该条重新出文件，不重排全篇。

命令行等价操作：

```bash
python skills/contract-counsel-toolkit/scripts/cc.py draft \
  --type purchase --a "成都甲科技有限公司" --b "成都乙商贸有限公司" \
  --amount 200000 --subject "办公电脑 100 台" --delivery-days 20 --payment-days 30 \
  --stance a --out .contract-workspace
```

### W2 审查台

**支持格式**：`.docx`、`.txt`、`.md`。PDF、图片、`.doc` 需先转换（本产品不带 PDF/OCR 依赖，会明确告知，不会假装读过）。

**站位很重要**：同一份合同，站在租客和站在房东，结论相反。没说就默认"提出需求的一方即己方"，并在结论里写明。

**报告结构**：结论 → 风险表（等级/位置/问题/证据）→ 必改 Top3（含可直接粘贴的替换文本）→ 其余改法速查 → 缺失要素。

**风险 > 10 条时**：高风险全展开，中低风险折叠统计，可要求展开某几条。

```bash
python .../cc.py review ./房屋租赁合同.docx --type lease --stance b
```

### W3 比对台

按传参顺序：A = 原版，B = 新版。报告开头会写明，说错了可以一句话调换。

**只报实质变更**：纯排版、标点、空白差异会被过滤。分级为重大 / 一般 / 轻微，谈判清单最多 3 条。

**特别识别两类隐蔽改动**：数值变动（金额、比例、天数、月数）与甲乙方指向翻转（如管辖地从甲方所在地改成乙方所在地）。

```bash
python .../cc.py compare ./v1.docx ./v2.docx
```

### W4 依据核查

**本地优先**：先查本地法条索引（4 部法律 44 条导航），命中即给条号 + 要点 + 适用场景。

**要原文必须核对**：要求"法条原文"时，会去国家法律法规数据库等官方来源核对；未核对前只给要点，并注明"条号请复核"。

**不给假条号**：拿不准时用口径化表述（"按《民法典》合同编关于违约金调整的规定"），绝不硬凑条号。

```bash
python .../cc.py laws --q 违约金
python .../cc.py laws --q 试用期 --limit 8
```

### W5 履约跟踪

两条路：从起草产物导入，或手工添加。

```bash
# 从起草产物导入（基准日 = 合同起始日，按节点偏移天数自动算截止日）
python .../cc.py ledger import --draft .contract-workspace/purchase_20261026.meta.json --start 2026-11-01

# 手工加节点（可一次加多个）
python .../cc.py ledger add --contract "采购合同" --item "首批到货" --item "验收" --obligor 乙方 --due 2026-11-30

# 查看与提醒
python .../cc.py ledger list --state open
python .../cc.py ledger due --days 15
python .../cc.py ledger done --id L0003
python .../cc.py ledger report
```

节点状态按当天日期实时算：正常 / 临近（≤7 天）/ 逾期 N 天 / 已完成 / 无截止日。逾期项在报告里单独点名。

## 三、常见组合

**今天就要回签**：审（W2）→ 查争议条款依据（W4）→ 改稿出文件（W1）→ 与对方原版比对确认改动（W3）。

**模板化一批合同**：起草母版（W1）→ 自查一遍确认无风险（W2，作为基线）→ 只替换主体与金额 → 批量导入节点（W5）。

**个人租房**：审查（W2，站位选租客）→ 要法条支撑（W4）→ 把押金退还、租期届满、续租确认写进台账（W5）。

## 四、文件与数据放在哪

- 产物默认写到当前目录下的 `.contract-workspace/`，与你的合同原件分开，便于整体归档。
- 台账文件默认 `.contract-workspace/ledger.json`，纯本地 JSON，可直接编辑或纳入版本管理。
- 合同正文不上传任何服务器；仅在核验法条时检索公开法规，不传合同内容。

## 五、自检与排错

```bash
python .../cc.py doctor
```

六项检查：Python 版本、条款库、风险规则表、法条索引、金额大写转换、DOCX 写入与结构校验。全绿才说明环境正常。

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示"暂不支持直接解析 .pdf" | 无 PDF/OCR 依赖 | 用 Word/WPS 另存为 `.docx`，或粘贴正文 |
| 审查定位不准（条号都是"段N"） | 合同没写"第X条"，按段落切分了 | 在合同里补条号，或直接按段落理解风险项位置 |
| 类型识别错了 | 要素特征不典型 | 显式指定类型：`--type lease` 或在对话中说"这是租赁合同" |
| 生成的合同有 `＿＿` | 该字段没提供且无默认值 | 看交付里的"建议确认项"，补一句话即可 |
| 台账报"文件损坏" | JSON 被手工改坏 | 先备份，再删除重建 |
| 金额大写不对 | 输入含非数字字符 | 只填数字，如 `200000` 或 `200000.50` |

## 六、注意事项

- 起草产出的合同是**参考文本**，签署前请核对主体名称、金额、账户、附件清单。
- 审查报告只覆盖规则库能识别的模式，不能替代对交易背景、行业监管、对方资信的判断。
- 引用条号标注"请复核"的，务必以国家法律法规数据库的现行文本为准。
- 涉及股权、担保、涉外、建设工程、金融产品的交易，请交执业律师出具意见。
