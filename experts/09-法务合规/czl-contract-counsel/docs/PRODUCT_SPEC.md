## 一、目标用户

| 用户 | 特征 | 核心诉求 |
|---|---|---|
| 中小企业主 / 个体经营者 | 没有专职法务，合同靠网上下载的模板改 | 别踩坑、能签、出问题知道找谁 |
| 采购 / 销售 / 行政岗 | 手上有一份对方发来的合同，当天要回签 | 快速判断"能不能签、改哪几处" |
| 个人用户 | 租房、装修、借款、兼职、培训 | 条款看不懂，怕押金不退、怕概不负责 |
| 法务新人 | 需要结构完整的初稿再精修 | 条款齐备、格式规范、可直接进流程 |

## 二、使用场景

1. **对方发来合同，要在今天回签**：需要在半小时内得到"改哪几条、怎么改"的清单。
2. **公司要把某类合同模板化**：先出母版，再批量替换主体与金额。
3. **两版合同来回拉扯**：需要看清对方悄悄改了哪些数字、把义务换到了谁头上。
4. **条款争议需要依据**：要给老板/客户一个"哪一条这么规定"的说法。
5. **签完就忘**：付款、验收、质保、续租节点没人盯，逾期才发现。

## 三、要解决的问题

| 问题 | 现状 | 本产品的处理 |
|---|---|---|
| 不知道缺什么条款 | 模板东拼西凑，缺验收、缺解除、缺送达 | 按合同类型做要素覆盖检查，缺哪项直接点名 |
| 看不出条款里的坑 | "概不负责""最终解释权""视为验收合格"看不懂 | 31 条规则逐条命中并给替换文本 |
| 改完不知道怎么谈 | 只会说"这条我不同意" | 每条给后果与让步边界，按优先级排序 |
| 引用法条靠记忆 | 条号经常记错、版本过时 | 条号+要点+置信度分级，需复核的明确标注 |
| 隐私顾虑 | 不敢把合同传到在线服务 | 全程本地处理，不上传正文 |
| 依赖第三方服务 | 在线审查/签署要账号、要额度、要网络 | 零外部服务，装上就能用 |

## 四、输入与输出

### 输入

- 起草：合同类型 + 双方主体 + 标的 + 金额 + 关键商务条款（付款/交付/验收/质保）。
- 审查：合同文件（`.docx` / `.txt` / `.md`）+ 用户站位（甲方/乙方）+ 关注点。
- 比对：原版 + 新版两份文件。
- 法条：关键词、法名或具体场景描述。
- 台账：合同名称、节点、义务方、截止日，或起草产出的 `.meta.json`。

### 输出

| 工作流 | 主产物 | 附带 |
|---|---|---|
| W1 | `.docx` 合同正文 | `.md` 预览、`.meta.json`（默认值清单 + 履约节点） |
| W2 | 风险报告 `.md` | `.json`（结构化风险项，可二次处理） |
| W3 | 变更分级报告 `.md` | `.json`（变更项 + 谈判清单） |
| W4 | 条号 + 要点 + 适用条件 | 置信度标注与复核提示 |
| W5 | 台账报告 `.md` | `ledger.json`（本地持久化） |

## 五、通用处理步骤

1. **识别意图**：起草 / 审查 / 比对 / 依据 / 台账，五选一或串联。
2. **确认站位与类型**：站位决定"对谁不利"；类型决定条款结构与必备要素。
3. **检查输入完整性**：区分"影响结论的关键要素"（必须问）与"可用行业默认"（先出稿再说）。
4. **执行**：能脚本化的交给 `cc.py`（切条、规则扫描、数值比对、docx 渲染、日期推算），判断与措辞交给模型。
5. **自检**：产物存在性、结构合法性、结论与证据是否对应。
6. **交付**：结论 → 主体内容 → 依据与假设 → 下一步选项。

## 六、需要的工具能力

| 能力 | 实现方式 |
|---|---|
| 读取合同正文 | 自研 OOXML 解析（zipfile + 正则），不依赖第三方库 |
| 条款切分 | 三级退化：第X条 → 序号标题 → 空行段落 |
| 风险识别 | 5 类检测器：regex / numeric / absent / mutual / conditional_absent |
| 数值比对 | "数值+单位"集合比对（金额/比例/天数/月数/年数） |
| 文档生成 | 自研 DOCX 写入器（OOXML 最小子集） |
| 日期推算 | 起始日 + 偏移天数 → 履约节点 |
| 法条检索 | 本地索引 + 必要时联网核对官方来源 |

## 七、质量、速度、稳定性要求

| 维度 | 要求 | 现状 |
|---|---|---|
| 质量 | 起草必须条款齐备、无占位符残留、金额大小写一致；审查每条结论必须有位置+后果+改法 | 已实现，见 `docs/TEST_REPORT.md` |
| 质量 | 规则误报要低：合规文本不应报出风险 | 已用自称起草件回归验证（0 条误报） |
| 速度 | 起草/审查单份合同脚本耗时 < 2 秒；对话交付 < 1 分钟 | 实测 0.2–0.6 秒 |
| 稳定性 | 规则写错只跳过单条，不中断整份报告；台账损坏不静默覆盖 | 已实现 |
| 可维护 | 条款、规则、法条全部数据化，改 JSON 不改代码 | 已实现 |
| 可移植 | 无第三方依赖，Windows/macOS/Linux 通用 | 已实现（仅需 Python 3.8+） |

## 八、功能边界（不做的事）

- 不提供在线签署、电子签章、存证服务（不接第三方签署 API，也不宣称具备该能力）。
- 不解析 PDF、扫描件、图片（不带 OCR/PDF 依赖），要求用户转格式。
- 不做对方资信调查、不做合同效力认定、不承诺胜诉。
- 不生成规避法律强制性规定的条款。

## 九、与同类产品的差异化

| 维度 | 常见在线合同工具 | 契约守门人 |
|---|---|---|
| 数据流向 | 合同上传到云端 | 全程本地，正文不出机器 |
| 依赖 | 需要账号、额度、网络 | 装上即用，无需注册 |
| 结论可解释性 | 给一个风险等级 | 给"哪条、为什么、怎么改、依据哪一条" |
| 交付物 | 在线页面 | 可直接签署的 `.docx` + 可归档的报告 |
| 履约闭环 | 通常止于"审完" | 延伸到签后节点台账 |
