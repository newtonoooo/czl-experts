# 使用说明 · 专业级产品战略作战室

本说明面向两类人：**安装者**（把它装进 WorkBuddy）和**使用者**（用它出决策包）。

---

## 一、安装

### 方式 A：本地专家市场（推荐）

1. 把整个 `czl-product-strategy-warroom` 目录复制到：

```
~/.workbuddy-ai/plugins/marketplaces/my-experts/plugins/
```

Windows 下即 `C:\Users\<你的用户名>\.workbuddy-ai\plugins\marketplaces\my-experts\plugins\`。

2. 编辑 `~/.workbuddy-ai/plugins/marketplaces/my-experts/.codebuddy-plugin/marketplace.json`，在 `plugins` 数组里追加一项：

```json
{
  "name": "czl-product-strategy-warroom",
  "source": "./plugins/czl-product-strategy-warroom",
  "description": "Five-seat product strategy war room: intake, evidence, spec, capacity, metrics, alignment, with a cross-document consistency gate."
}
```

3. 重启 WorkBuddy，在专家列表中搜索「产品战略作战室」。

### 方式 B：直接指定本地目录

在 WorkBuddy 的自定义专家入口选择"从本地目录导入"，指向本包根目录（包含 `.codebuddy-plugin/plugin.json` 的那一层）。

### 安装后自检

在包目录执行：

```
python tests/run_tests.py -v
```

全部通过说明包结构、头像、脚本、文档均完整。若某项失败，输出里会直接给出原因。

## 二、第一次使用

选中「专业级产品战略作战室」后，直接说你的事。**不需要写提示词**，但要给它三个东西：**要解决什么、给谁用、手头有什么**。

三句可以直接用：

> 老板说要做 AI 助手，但没说给谁用、解决什么。我手上只有 8 条客户抱怨和一份竞品截图，帮我把它变成能立项的方案。

> 下季度 11 个候选需求，团队 6 个人 13 周。帮我定出真能做完的，并写清楚砍掉什么、砍了怎么跟老板交代。

> 上个季度 MAU 涨了 9%，付费转化掉了 12%。先把口径和分母查清楚，再告诉我会上该怎么回答。

### 它会先问你什么

大多数情况下，主理人会先跑**立案卡**，最多问你 3 个问题，每个问题都带选项。例如：

- 「这个功能上线后，哪个数字会变？现在是 3% 还是 30%？」
- 「第一批必须用上的是哪类用户？他们现在用什么凑合？」
- 「如果只做一半，哪一半先做？」

答不出来也可以，它会写成假设并标注，但会告诉你"取证后需要重算"。

## 三、你会拿到什么

一次完整任务会落盘到：

```
deliverables/warroom/<日期>-<任务简称>/
```

| 文件 | 什么时候看 |
|------|------------|
| `00-决策简报.md` | 只有 5 分钟，看这份 |
| `05-汇报包.md` | 要开会了，按受众取对应版本 |
| `02-需求规格.md` | 交给工程/设计前 |
| `03-产能排产.md` | 跟老板对齐排期时 |
| `01-证据台账.md` | 有人质疑"这数据哪来的" |
| `04-指标口径表.md` | 定成功指标、做数据看板前 |
| `99-一致性报告.md` | 交付前自查 |

对话里只给：一句话结论 + 结论卡 + 3–5 条行动。细节都在文件里。

## 四、五个校验脚本怎么单独用

脚本都在 `skills/<技能名>/scripts/` 下，纯标准库，`python xxx.py -h` 可看参数。

### 1. 证据台账校验

```
python skills/evidence-ledger/scripts/evidence_grade.py --csv 01-证据台账.csv --today 2026-10-28
```

输出 A/B/C/D/X 分布与可用比例，抓四类问题：无出处、比例缺分母、绝对化措辞配弱证据、日期越界。

### 2. 规格校验

```
python skills/spec-architect/scripts/spec_lint.py 02-需求规格.md
```

九节是否齐全、每条 REQ 是否有 AC、AC 是否可测、P0 是否过多、有没有残留占位符。

### 3. 产能装箱

```
python skills/capacity-packing/scripts/capacity_pack.py \
  --backlog backlog.csv --people 6 --weeks 13 --focus 0.65
```

`backlog.csv` 字段：`id,req_id,title,pw,priority,depends_on,stop_loss`。
加 `--out plan.csv` 输出排产表，加 `--json` 输出机器可读结果。

### 4. 指标口径检查

```
python skills/metric-guard/scripts/metric_check.py --cards 口径卡.csv
python skills/metric-guard/scripts/metric_check.py --segments 分层.csv
```

分层文件字段：`segment,exposed_n,exposed_k,control_n,control_k`。第二项能识别辛普森反转。

### 5. 一致性校验

```
python skills/chain-consistency/scripts/chain_check.py deliverables/warroom/2026-10-28-xxx
```

扫描目录下所有 md/csv，报 C1–C8 八类问题：缺验收、悬空 AC、需求没进排产、孤儿指标、悬空引用、风险没措施、承诺没止损线、同一指标两个值。

**退出码约定**：0 = 通过；1 = 有阻断项。可以直接接进 CI。

## 五、常见问题

### Q1：专家列表里图标显示成一个字（比如"产"）

这是**团队型专家**的已知显示问题，不是图片损坏。原因与修复见 `docs/头像图标显示问题排查报告.md`，一句话版本：

> 团队型专家的列表图标取自主理人成员的头像（`members[]` 里 `role: lead` 的那位），而不是包级 `avatar`；如果包是从远端市场目录安装的、且头像写的是相对路径，加载器可能把它拼成 CDN 地址而 404，UI 就回退成名字首字。

本包的处理：6 张头像全部为 384×384 PNG、单文件 < 250KB、显式提供 `assistantAvatarUrl`、成员头像与包级头像同时配置。若仍出现文字图标，按排查报告第 4 节的三个检查点逐项核对。

### Q2：它一直追问我，能不能直接给结果？

可以，但要接受代价。回一句「按假设模式跑，别问了」，它会：全部结论标 D 级、第一页写明"基于假设，取证后需重算"、给 3 条最低成本取证动作。**这种情况下它不会假装结论可靠。**

### Q3：能不能不写 Non-goals？

不行。Non-goals 是防范围蔓延的唯一闸。如果确实没有，说明范围还没想清楚。

### Q4：排产结果装不下我的 P0 怎么办？

它会阻断并给三选一：砍范围 / 加人 / 延期，各自带代价。它不会把 3 人周的活压成 1.5 人周。

### Q5：能处理英文材料吗？

能读能写，但模板、话术、汇报结构是中文优先。英文输出质量低于中文。

### Q6：需要联网吗？

不需要。五个脚本纯离线。竞品取证若需要联网，由运行环境提供检索能力，本包不硬依赖。

### Q7：数据会上传吗？

不会。所有计算在本地脚本完成，包内无任何网络调用代码。你提供的 CSV 只在你本机被读取。

## 六、卸载

1. 删除 `~/.workbuddy-ai/plugins/marketplaces/my-experts/plugins/czl-product-strategy-warroom` 目录
2. 从 `marketplace.json` 的 `plugins` 数组里删除对应条目
3. 重启 WorkBuddy

已生成的 `deliverables/warroom/` 下的文件不会自动删除，需要你自己清理。
