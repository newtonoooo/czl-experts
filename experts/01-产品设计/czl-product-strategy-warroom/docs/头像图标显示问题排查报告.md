# 头像图标显示问题排查报告

**问题描述**：专家团导入到新的 WorkBuddy 后，在专家列表中选择该专家，小图标不显示，位置显示为一个汉字（名字首字）。

**结论摘要**：不是图片损坏，也不是尺寸超限。根因是**团队型专家的图标取的是主理人成员的头像，而不是包级 `avatar`；当这个相对路径没有被本地解析时，加载器会把它拼成远端 CDN 地址，请求 404 后 UI 回退成名字首字。**

**证据等级**：A 级（直接读取本机 WorkBuddy 应用包内的解析代码，见第 2 节）。第 3 节关于"哪个安装路径会走到哪段代码"的判断为 B 级（代码可读，但未能对目标安装环境做运行时验证）。

---

## 1. 排查过程

| 步骤 | 动作 | 结果 |
|------|------|------|
| 1 | 检查 `product-strategy-team/avatars/*.png` | 7 张均为合法 PNG，512×512，RGB，255–328KB，无损坏 |
| 2 | 检查 `plugin.json` 中 `avatar` 与 `members[].avatar` 路径 | 均指向存在的文件，路径写法与其他正常显示的包一致 |
| 3 | 对比正常显示的包（`huashu-data-pro`、`czl-*`） | 正常包的 `agents` 是**文件路径数组**，问题包是目录字符串 `"./agents/"`；正常包有 README.md、`plugin`、`tags`、`quickPrompts`，问题包没有 |
| 4 | 读取应用包内头像解析代码 | 发现两条不同的解析路径，其中一条会把相对路径拼成 CDN 地址（见第 2 节） |
| 5 | 检查头像体积上限 | 硬上限 5MB（`5242880`），255–328KB 远未触限，排除体积原因 |

## 2. 代码证据

以下片段来自本机 `WorkBuddyAI/resources/app.asar` 中的应用代码（已压缩混淆，此处保留原样并标注含义）。

### 2.1 团队图标取自 lead 成员的头像

```js
function readTeamMembers(e){
  return t.expertType !== 'team' || !Array.isArray(t.members) ? [] : t.members.filter(...)
}
function pickTeamLeaderMember(e){
  let t = readTeamMembers(e);
  if (t.length === 0) return;
  let n = readTrimmedString$1(e.leader);
  return t.find(e => e.role === 'lead') ?? (n ? t.find(e => readMemberId(e) === n) : void 0) ?? t[0];
}
function attachExpertAssistantIdentity(e){
  let t = pickTeamLeaderMember(e);
  if (t) {
    ...
    let i = resolveExpertAvatarUrl(t.avatar);      // ← 取的是成员头像
    return { ...e, ...(i ? { assistantAvatarUrl: i } : {}) };
  }
  let i = resolveExpertAvatarUrl(e.avatarUrl ?? e.avatar);
  ...
}
```

含义：**团队型专家**的会话身份头像 = `members[]` 中 `role === "lead"` 的那位成员的 `avatar`。包级 `avatar` 在这条路径上不参与。

### 2.2 团队场景下包级头像被显式丢弃

```js
assistantAvatarUrl: d.avatarUrl ?? (f === 'team' ? void 0 : s)
//                    ↑成员头像      ↑团队类型时不要包级头像 s
```

含义：即使包级 `avatar` 是有效的本地文件，只要 `expertType === "team"`，这条 DTO 也不会用它兜底。**这解释了为什么"包级头像是好的，但图标还是没了"。**

### 2.3 相对路径会被拼成远端 CDN 地址

```js
function resolveExpertAvatarUrl(e){
  if (typeof e !== 'string') return;
  let t = e.trim();
  if (!t) return;
  let n = t.indexOf('data:image/');
  if (n === 0 || (n > 0 && t[n-1] === '/')) return t.slice(n);   // data URI 直接用
  let r = t.replace(/^\/+/, '');
  if (/^(https?|file|data|blob|local-file):/i.test(r)) return r;  // 绝对协议直接用
  return buildExpertUrl(t.startsWith('/') ? t : '/' + t);         // 其余 → 拼 CDN
}
// buildExpertUrl = https://acc-1258344699.cos.accelerate.myqcloud.com/workbuddy/expert-marketplace + path
```

含义：`avatars/lead.png` 这种相对路径，如果没有先被转成 `local-file:` 之类的本地 URL，就会变成
`https://acc-…/workbuddy/expert-marketplace/avatars/lead.png`。
这个地址在 CDN 上不存在（本地包的文件不可能在 CDN 上），请求失败 → 无图 → UI 回退成名字首字。

### 2.4 只有"自定义专家"路径会做本地解析

```js
async resolveAvatarUrl(e, t){          // t = 包根目录
  if (!e) return '';
  if (/^(https?|data):/.test(e)) return e;
  let r = path.resolve(t, e.replace(/^\.\//, ''));
  if (!r.startsWith(path.resolve(t) + path.sep)) return '';     // 防目录穿越
  if (await pathExists(r)) {
    let st = await stat(r);
    return st.size > 5242880 ? (warn('avatar file is too large'), '') : toLocalFileUrl(r);
  }
  return '';
}
// 调用点：readCustomExpertFromDir()  —— 仅用于 isCustomExpert: true、marketplace: 'my-experts'
```

含义：**只有走"本地自定义专家"读取路径时**，`avatar` 和 `members[].avatar` 才会被逐个解析成本地文件 URL。这条路径还会：
- 校验路径不越出包目录（`..` 会被拒绝）
- 校验文件存在
- 校验体积 ≤ 5MB（`5242880`），超限时打日志 `resolveAvatarUrl: avatar file is too large` 并返回空串

**这就是为什么用户自己放在 `my-experts` 里的 `czl-*` 包图标一直正常，而从远端市场安装/手工塞进 `experts` 市场目录的团队包图标会变成字。**

## 3. 失效链路还原

```
plugin.json: expertType = "team"
        │
        ├─ 平台取图标 ──> pickTeamLeaderMember() ──> members[role=lead].avatar = "avatars/team-lead.png"
        │                                              │
        │                                              ├─ 若已本地解析（my-experts 自定义专家路径）
        │                                              │      → local-file://… → 显示正常
        │                                              │
        │                                              └─ 若未本地解析（远端市场/缓存目录路径）
        │                                                     → https://acc-…/expert-marketplace/avatars/team-lead.png
        │                                                     → 404
        │                                                     → 无图
        │
        └─ 包级 avatar 被 `f === 'team' ? void 0 : s` 丢弃，无法兜底
                                                        ↓
                                            UI 回退：显示名字首字
```

补充因素（不直接导致失效，但会让包"看起来不完整"、影响加载与审核）：

| 现象 | 说明 |
|------|------|
| `"agents": "./agents/"` | 正常包写的是文件路径数组（`["./agents/a.md", …]`）。目录字符串依赖加载器的额外兼容处理，属于非标准写法 |
| `members[]` 只有 `id`，没有 `agent` | 加载器会用 `agent` 字段回填 `id`；缺 `agent` 时容错能力下降 |
| 缺 `plugin` / `license` / `tags` / `quickPrompts` | 不影响图标，但影响市场卡片完整度与审核印象 |
| 缺 `README.md` | 与同目录其他包不一致，安装后无说明可看 |

## 4. 本产品的规避措施

已在 `czl-product-strategy-warroom` 中落实以下 5 条，逐条对应上面的失效点：

| # | 措施 | 对应失效点 |
|---|------|------------|
| 1 | 安装到 `my-experts` 本地市场（走 `readCustomExpertFromDir`，头像会被本地解析） | 2.4 |
| 2 | 同时配置包级 `avatar` 与 `assistantAvatarUrl`（后者直接指向 `avatars/lead.png`） | 2.2 的丢弃逻辑 |
| 3 | 每个成员都配置 `avatar`，且 lead 成员 `role: "lead"` 明确标注 | 2.1 |
| 4 | 头像统一 384×384 PNG，单文件 136–239KB，远低于 5MB 上限，且避免大图拖慢列表 | 2.4 体积校验 |
| 5 | `members[]` 同时写 `id` 与 `agent`，`agents` 写完整文件路径数组 | 第 3 节补充因素 |

### 验证方式

```
python tests/run_tests.py -v
```

其中 `头像合规：avatars/xxx.png` 与 `assistantAvatarUrl 指向存在的文件` 两项即为该问题的回归测试，任一头像缺失、非正方形或超过 512KB 都会 FAIL。

## 5. 如果你在新环境里仍然看到文字图标

按顺序查这三处，基本能定位：

1. **包放在哪个市场目录**
   必须是 `plugins/marketplaces/my-experts/plugins/<包名>/`，并在 `marketplaces/my-experts/.codebuddy-plugin/marketplace.json` 里有条目。
   放在 `marketplaces/experts/plugins/` 下（那是远端市场的落地目录）不会走本地解析。

2. **`members[]` 里是否有 `role: "lead"`**
   团队图标只认 `role === "lead"` 的成员；没有 lead 时会退回 `members[0]`，再没有就完全无图。

3. **头像文件是否真的在包内**
   用 `python tests/run_tests.py` 直接验，比肉眼确认可靠。检查项会报出具体是哪个文件缺失或不合规。

如果三处都正常但仍显示文字，请把 `~/.workbuddy-ai/logs/` 下当天日志里含 `resolveAvatarUrl` 的行发出来——代码里有 `avatar file is too large` 这类显式告警，能直接指向原因。

## 6. 一句话给用户

**图没坏，是"团队头像取成员、成员头像没被本地解析、包级头像又被丢弃"三件事叠在一起。** 把包放进本地 `my-experts` 市场、给 lead 成员配好头像、再补一个 `assistantAvatarUrl` 兜底，问题就不会再出现。本包已按这个结论做好，并通过了自动化回归检查。
