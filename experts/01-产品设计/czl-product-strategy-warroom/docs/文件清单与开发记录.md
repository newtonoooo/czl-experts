## 二、目录结构

```
czl-product-strategy-warroom/
├── .codebuddy-plugin/
│   └── plugin.json                 ← 平台唯一入口
├── agents/                         ← 5 份席位提示词（文件名 = agent id）
├── avatars/                        ← 6 张 384×384 原创头像
├── skills/                         ← 7 个技能
│   ├── strategy-intake/
│   ├── evidence-ledger/            ← SKILL.md + scripts + fixtures
│   ├── spec-architect/             ← SKILL.md + scripts + fixtures
│   ├── capacity-packing/           ← SKILL.md + scripts + fixtures
│   ├── metric-guard/               ← SKILL.md + scripts + fixtures
│   ├── chain-consistency/          ← SKILL.md + scripts + fixtures
│   └── stakeholder-render/
├── docs/                           ← 7 份文档
├── tests/run_tests.py              ← 包自检
├── README.md  LICENSE  NOTICE.md  CHANGELOG.md
```

**命名约定**：

- `agents/<id>.md` 的文件名必须与 `plugin.json` 中 `agentName`、`teamInfo.leadAgent`、`teamInfo.memberAgents`、`members[].id` 完全一致，否则加载器找不到对应提示词。
- `skills/<name>/SKILL.md` 的 frontmatter `name` 必须与目录名一致。
- 头像统一放 `avatars/`，文件名用英文短横线小写，避免路径解析问题。

## 四、开发过程中修正的缺陷

这些缺陷都是脚本自测跑出来的，记录在此以说明"测试确实执行过"。

| # | 缺陷 | 表现 | 修正 |
|---|------|------|------|
| 1 | 证据台账跳过缺字段行 | 缺 `source_ref` 的行被 `continue` 跳过，导致 X 级判定与重复编号检查失效 | 改为先判级后报缺字段，不再跳过 |
| 2 | 规格校验把所有需求行当表头 | `table_rows` 用 `REQ` 关键字过滤，把 `REQ-01` 数据行误判为表头，需求数恒为 0 | 改为只过滤 `编号/序号/ID/项目` 等纯表头文本 |
| 3 | 章节匹配不到带序号的标题 | `## 2. 目标` 因前缀 `2.` 匹配失败，九节检查误报 | `find_section` 先剥离前导序号再匹配 |
| 4 | 装箱允许小项挤掉 P0 | P0 因放不下被延后，P1 却因体积小被装进去 | 引入 `capacity_broken` 标记，一旦有项装不下，后续项不再填缝 |
| 5 | 一致性检查把"出现过"当"进了排产" | REQ-04 只在规格里出现也被算作已排产，C3 检查失效 | 单独维护 `roadmap_reqs`，只从排产 CSV 的 `req_id` 收集 |

## 五、设计决策

| 决策 | 选择 | 理由 | 被否方案 |
|------|------|------|----------|
| 排序方法 | 人周装箱 | 分数不占用人周，回答不了"装得下几个" | RICE / ICE 评分排序 |
| 团队图标 | 几何徽标 | 40px 列表尺寸下多人合影会糊成一团，徽标辨识度更高 | 五人合影、lead 单人照 |
| 席位数量 | 1 + 4 | 五个角色各有不可替代的判断；再多会让编排成本超过收益 | 1 + 3（合并证据与指标）、1 + 6（拆出 GTM） |
| 头脑风暴 | 不设独立工作流 | 发散完没人收敛是常见失败模式，收敛进 S1/S3 更实际 | 独立 brainstorm 工作流 |
| 校验方式 | 脚本 + 退出码 | 只有机器能保证"每次都查"，人做不到 | 仅靠提示词约束 |
| 头像体积 | 384×384 / ≤250KB | 列表显示够用，加载快，远离 5MB 上限 | 1024×1024（单张 1MB+） |
| 文档语言 | 中文优先 | 目标用户是中国产品经理，术语与场景更贴近 | 中英双语模板 |

## 六、来源与独立性说明

- 本包全部提示词、文档、脚本、夹具为本次独立编写，未复制任何其他专家包或开源项目的文本与代码。
- 目标专家包仅用于**功能分析**（有哪些角色、覆盖哪些任务、输出什么），其提示词结构、文案、模板、工作流定义均未被采用。
- 本包的角色名（祁略/柯证/简文/权衡/验数）、编号体系、四道闸、六段链、C1–C8 检查项、人周算法参数均为本次设计。
- 方法论层面使用了公共领域概念（用户故事、Given/When/Then、辛普森悖论、AARRR），未复制具体表述，详见 `NOTICE.md` 第二节。
- 无第三方代码依赖，无第三方字体、图标、CDN 资源。

## 七、复现方式

从零重建本包的可验证路径：

1. 目录结构按第二节创建
2. `python tests/run_tests.py -v` 全绿
3. 用 `docs/使用说明.md` 第四节命令逐个运行 5 个脚本，对照 `docs/测试报告.md` 的输出

任何一步对不上，说明包被改动过。
