# 更新日志

本文件记录 `czl-product-strategy-warroom` 的版本变更。版本号遵循语义化版本：主版本号变更表示工作流或输出结构不兼容，次版本号变更表示新增能力，修订号变更表示修正与优化。

---

## [1.0.0] — 2026-10-28

首个发布版本。

### 新增

- **专家团结构**：1 名主理人（战略总参）+ 4 名专业席位（证据官 / 需求架构师 / 产能与优先级规划师 / 指标口径师），共 5 个 Agent。
- **六段链工作流**：立案 → 取据 → 成文 → 排产 → 度量 → 汇报，每段定义输入契约、判断条件、产出文件与异常处理。
- **四道闸机制**：G1 立案闸、G2 证据闸、G3 一致闸、G4 交付闸，闸门记录写入 `meta.json`。
- **编号贯通体系**：GOAL / EVD / REQ / AC / MET / RM / RSK / DEC 八类编号，跨文档可追溯。
- **7 个技能模块**：
  - `strategy-intake` 立案卡（五要素 + A/B/C 档位判定）
  - `evidence-ledger` 证据分级（A/B/C/D/X 五级 + 降级规则）
  - `spec-architect` 需求规格（九节结构 + 验收写法）
  - `capacity-packing` 产能装箱（人周算法 + 砍单清单 + 止损线）
  - `metric-guard` 指标口径（口径卡 + 护栏指标 + 辛普森检查）
  - `chain-consistency` 一致性闸（C1–C8 八项跨文档检查）
  - `stakeholder-render` 汇报改写（高管/工程/设计三版）
- **5 个校验脚本**（纯 Python 标准库，离线可运行）：
  - `evidence_grade.py` 证据等级复算与合规检查
  - `spec_lint.py` 规格结构校验
  - `capacity_pack.py` 产能装箱与超载检测
  - `metric_check.py` 口径卡校验与辛普森反转识别
  - `chain_check.py` 跨文档断链与数字冲突检测
- **测试体系**：`tests/run_tests.py` 覆盖 11 个脚本行为用例 + 包结构完整性检查，每个脚本均配置通过/不通过双向夹具。
- **原创视觉**：6 张 384×384 PNG 头像（团队徽标 + 5 位席位），统一深青底金色点缀风格。
- **文档**：产品规格说明、使用说明、平台展示文案、文件清单与开发记录、测试报告、商业发布风险清单、头像显示问题排查报告。

### 修正（上架解析失败后修复）

平台导入时报「解析失败」，三条错误已全部修复：

| 错误 | 原因 | 修复 |
|------|------|------|
| `tags` 须固定 3 个，当前 5 个 | 写了 5 个标签 | 收敛为 3 个：产品战略 / 需求规格 / 产能排产 |
| `defaultInitPrompt.zh` 必须与 `quickPrompts[0].zh` 一致 | 默认提示是"季度排产"，但 quickPrompts 首条是"从零立项"，两者文本不同 | 把默认提示原文放到 `quickPrompts[0]`，其余两条顺延 |
| `defaultInitPrompt.en` 必须与 `quickPrompts[0].en` 一致 | 同上 | 同上（英文同步） |

**回归防护**：`tests/run_tests.py` 新增 5 项断言（tags 恰好 3 个、tags 每项含 zh/en、quickPrompts 非空、中英文默认提示与首条一致），此类错误不会再流出去。

### 设计决策

- **不用 RICE 分数作为主排序手段**：分数不占用人周，无法回答"装得下几个"。改用产能装箱 + 砍单清单。
- **团队头像使用几何徽标而非人物合影**：在 40px 列表尺寸下，徽标比多人合影更易辨识；人物形象由 5 个席位头像承担。
- **显式提供 `assistantAvatarUrl`**：规避团队型专家在部分安装路径下头像相对路径未被本地解析的问题（详见 `docs/头像图标显示问题排查报告.md`）。

### 已知限制

- 不包含联网检索能力，竞品取证需由运行环境提供检索工具。
- 一致性脚本只做结构校验，不判断业务判断的正确性。
- 中文优先，英文模板尚未本地化。
