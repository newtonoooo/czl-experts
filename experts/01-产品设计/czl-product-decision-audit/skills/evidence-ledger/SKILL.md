# G2 证据：这句话能撑多重

## 什么时候用

- 分诊通过，要把请求变成可检验的论证
- 用户给出访谈纪要、工单、反馈群聊天记录，要提炼结论
- 用户说"竞品都有这个功能"
- 用户给出一个数字但不知道能信到什么程度
- 要判断一个已有结论该不该被采信

## 核心方法：拆断言

一段话里通常混着事实、判断和愿望。先把它们拆开，拆不开就没法核。

例：
> "客户反馈很多，都在说导出太麻烦，竞品上周也上了批量导出，我们不做就落后了。"

拆成四条断言：

| # | 断言 | 类型 | 等级 | 依据 | 缺什么 |
|---|---|---|---|---|---|
| 1 | 有很多客户反馈导出麻烦 | 事实（数量） | D | "很多"无来源 | 工单数、客户数、时间窗 |
| 2 | 客户认为导出麻烦 | 事实（内容） | B | 有 3 条工单原文 | 是否代表多数 |
| 3 | 竞品上周上了批量导出 | 事实（外部） | C 待核 | 需检索核实 | 链接、日期 |
| 4 | 不做就落后 | 判断 | X | 无 | 需转化为可测命题 |

四条拆完，结论就变了：真正能站住的是第 2 条，第 1 条要补，第 3 条要核，第 4 条根本不是事实。

**"不做就落后"这类话必须转化。** 转化成"如果竞品的批量导出能让他们在 X 场景下比我们快 Y，我们会在 Z 类客户上丢单"。这样才有办法验证。

## 等级评定细则

主等级定义见主 Agent 的表格。这里给判定边界，避免同级争论。

### 判 A 的条件（全部满足）

- 数据是产品自己的系统产出（埋点、订单、日志、实验分流）
- 定义可复述（能说清分子分母、时间窗、去重规则）
- 别人能重跑出同一个数

不满足任何一条，降到 B 或以下。典型降级：日报里截图出来的数（不知定义）→ B；别人口头给的数 → D。

### 判 B 的条件

- 有原文可查（不是摘要、不是转述）
- 能指认是谁在什么场景下说的
- 场外信息足够判断他是不是目标用户

**注意**：截图里的客户原话算 B；你听同事说客户这么说算 D。这个区别在评审会上很致命——B 可以引用，D 只能作为线索。

### 判 C 的条件

- 公开可访问，用户点开就能看到
- 有日期
- 不是厂商的自证宣传（"行业领先"不算 C，"支持 200 人同时在线"且文档可查算 C，但要注意它是厂商给的参数，涉及能力上限时降为 D）

### 判 D 的条件

转述、二手汇总、他人整理的结论、报告摘要、销售口述、会议上的概括。

**D 级的正确用法**：作为找证据的线索，不能作为结论依据。写"销售反馈有客户提过（D，待核）"是可以的；写"客户普遍需要（D）"不成立。

### 判 X 的条件

印象、直觉、类比（"别家都这么做"）、你的推测、模型输出。

**X 级唯一合法形态**是假设加证伪方式：
> 假设：导出慢是流失原因之一。证伪方式：看流失用户在流失前 14 天是否使用过导出（A 级数据可查）。

## 找反例

这是本技能最重要的一步，也是最容易被跳过的一步。

找反例不是"再找几个支持结论的例子"，而是去找**如果存在就说明结论错**的东西：

| 结论 | 该去找的反例 |
|---|---|
| 客户需要批量导出 | 有批量导出权限但从不使用的客户；用过一次就再也不用的记录 |
| 新用户卡在引导流程 | 跳过引导但依然留存下来的用户比例 |
| 竞品靠这个功能赢单 | 丢了单但客户没用过该功能的案例 |
| 提价会流失 | 上次提价后实际流失率；对价格不敏感的客户分层 |
| 这个功能没人用 | 有没有一批高频用户是例外（可能是最值钱的用户） |

找不到反例时，写"**未找到反例（检索范围：___，时间：___）**"。不要写"没有反例"——这两个说法在评审会上含义完全不同。

## 研究材料综合

用户给访谈、工单、群聊、问卷时，按这个顺序处理。

### 1. 先建频次表

| 主题 | 提到的人数 | 总样本 | 行为证据 | 原话（一条） |
|---|---|---|---|---|
| 导出要手工整理 | 6 | 11 | 其中 4 人有自建表格 | "每次导完还得再改一遍格式" |

**人数和样本必须同时写。** 只写"6 人提到"没有意义，6/11 和 6/60 是两件事。

样本小于 8 时，不写百分比，只写人数，并注明"样本小，仅作方向"。

### 2. 分"说的"和"做的"

访谈里说的需求可信度低于行为记录。优先级：

1. 他现在为了绕过这个问题花了多少时间/钱（行为）——最强
2. 他已经自己搭了什么替代方案（行为）
3. 他明确说愿意为此付费或换产品（陈述，但要看他有没有真的换过）
4. 他说"这个功能不错"（最弱，几乎不算证据）

**自建替代方案（Excel 模板、手工流程、脚本）是最好的证据**——它证明痛点真实到让人愿意付出额外劳动。

### 3. 处理矛盾

矛盾不要抹平，要写出来。矛盾通常意味着存在两个不同人群：

> 矛盾：5 人希望流程更短，3 人希望加审批环节。
> 解释：前者是一线执行者，后者是管理者。这不是需求冲突，是两个角色的目标冲突，需要分别定义。

**同一句原话出现三次以上要警惕**：可能是同一个人在不同场次重复说，也可能是访谈者引导出来的。

### 4. 提炼结论的上限

样本 11 人的定性访谈，能支持的结论上限是"存在这类需求，方向可信"。不能支持"占比 X%"、"多数用户"、"市场需要"。要占比就必须有量的数据。

## 竞品取证

竞品信息的最大问题是**时效**和**来源层级**。按下面处理。

### 来源分级

| 来源 | 等级 | 可信度说明 |
|---|---|---|
| 自己注册试用并截图 | A（自测） | 最强。注日期、注版本、注套餐 |
| 官方定价页、更新日志、帮助文档 | C | 可核，但含厂商表述 |
| 应用商店评论、社区讨论 | C | 未经筛选，样本偏斜（生气的人更爱写） |
| 官方博客、发布会、新闻稿 | C（事实部分）/ D（评价部分） | 日期必须写 |
| 第三方分析报告摘要 | D | 常滞后 6–12 个月 |
| 销售听来的、行业群里传的 | D/X | 只能当线索 |

### 必写字段

每条竞品事实必须带：**来源类型 + 链接或截图位置 + 核实日期 + 套餐/版本**。

不带这四项的竞品事实，在评审会上会被一句"你从哪看的"打掉。

### 常见错误

- **把竞品的功能清单当能力**：清单说有，实际用起来是半成品。有能力判断时注明"仅见文档，未实测"。
- **把竞品宣传语当定位事实**："AI 驱动"不是事实，是宣称。
- **忘记比价格口径**：按席位、按用量、按模块，三种计费方式不能直接比单价。要换算到同一个使用场景下的年化成本。
- **用竞品有/没有来论证该不该做**：竞品做不代表对，不做不代表错。竞品信息只能改变"优先级"和"差异化角度"，不能替代你自己的用户证据。


## 用脚本核对台账

台账条目多的时候，用 `scripts/evidence_check.py` 做机械核对：

```bash
python scripts/evidence_check.py ledger.csv
```

它检查：等级是否合法、是否有结论等级高于其证据（越级）、是否用了"多数/普遍/显著"这类词却只有 D/X 级证据、反例检索是否填写。规则细节见 `references/evidence-grades.md`。

## 异常

| 情况 | 处理 |
|---|---|
| 用户给的是别人的结论，不是原始材料 | 要求原始材料。拿不到就把等级压到 D，并写明"结论来源为转述" |
| 用户材料里有明显编造迹象（数字太整齐、原话像文案） | 直接指出可疑点，请用户确认来源。不要基于可疑材料往下推 |
| 只有支持证据，没有反例 | 主动去构造反例场景，或明确写"未做反例检索" |
| 用户要求"帮我论证这个结论" | 说明会先做压力测试。如果测完站得住，再帮他写论证 |
| 涉及用户个人信息（手机号、住址、健康、未成年人） | 停止落个人粒度，改聚合；提示最小必要原则 |

## 与其他技能的关系

- 上游：`decision-triage`
- 下游：`metric-integrity`（证据是数字时）、`adversarial-review`（拿反例做压力测试）
- 竞品部分通常与 `adversarial-review` 配合：先取证，再问"所以我们要不要跟"
