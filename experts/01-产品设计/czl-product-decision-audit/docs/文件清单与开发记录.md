## 二、开发记录

### 2.1 需求分析阶段（做了什么判断）

分析对象仅为功能与结构，目的是找出可继承的经验和原有做法的缺口，不复制其表达。

识别到的功能范围：需求规格与 PRD、路线图与优先级、利益相关者沟通、用户研究综合、竞品分析、指标追踪。

识别到的缺口（本产品针对这些缺口设计，构成本产品差异）：

| # | 缺口 | 本产品的处理 |
|---|---|---|
| 1 | 有置信度要求，但没有可操作的定级规则 | 建立 A/B/C/D/X 五级标尺 + 八条争议判例 + 三条降级规则 + 越级用词禁用清单 |
| 2 | 有"找反例"的意识，但没有反例检索纪律 | 规定找不到时只能写"未找到反例（范围/时间）"，禁止写"没有反例" |
| 3 | 指标部分讲层级与看板，统计护栏不足 | 引入波动带（MAD）、样本充分性、口径漂移、辛普森反转，并落成可执行脚本 |
| 4 | 有风险意识，但没有失效条件与止损线的强制要求 | 五区块输出契约中，"反方与失效条件""止损线"为必填，缺一不许交付 |
| 5 | 排期只到评分，不校验产能是否装得下 | 改为装箱算法 + 吞吐比对 + 敏感性分析（脆弱项） |
| 6 | 规格与实际交接之间缺少强制项 | 补 DoR 八项、AC→TC 一对一映射、异常路径比例要求、变更成本账簿 |
| 7 | 输出以对话文本为主，缺少可交付物的形态约束 | 定义决策包五区块 + 附件独立性要求 + 格式纪律（数字带口径、表格只用于对比） |
| 8 | 未覆盖"该不该继续投 / 该不该下线" | 新增续投四档判定与下线四步前置动作 |
| 9 | 场景偏英文语境（G2/Capterra 等） | 中文本土表达，公开法规与方法按中国语境表述，去掉了不适用的市场工具默认值 |

### 2.2 架构设计（为什么是七个技能）

按"一道闸一个技能"切分，而不是按"一种文档一个技能"。理由：闸门有强制顺序，文档类型没有。按闸切分才能让主提示词用路由表把八类问法收束到同一条流水线上。

设计时排除的方案：

- **按文档类型切**（PRD/路线图/汇报/研究/竞品/指标）：与原产品的切法过近，且无法表达"先过证据再谈结论"的顺序要求。
- **单一巨型技能**：内容过长，模型加载后容易只取局部。
- **按行业切**：v1.0 无足够场景验证，先不做。

### 2.4 开发过程中的实际修正

记录真实发生的问题与处理，便于后续维护：

1. **`metric_guard.py ab` 结论自相矛盾**：初版对"显著但效应小于 MDE"的情况同时输出"可以上"和"样本可能不足"。改为：仅在不显著时提示样本不足；显著但处于功效边缘时，给出"延长一期再决定是否放大投入"的独立提示。
2. **`portfolio_fit.py` 砍单原因不够精确**：初版写"只剩 0.1 人周"，容易被读成"当时只剩这么多"。改为"装不进剩余容量（需 X，排完已排入项后只剩 Y）"。
3. **`portfolio_fit.py` 缺少关键洞察**：初版只给砍单清单，没说明"某项因体积被砍但其实产出更高"。补充该提示，并建议拆分。
4. **头像水印**：生成原图右下角带生成服务水印，直接用作商用头像不合适。裁去底部区域并以 1:1 裁切（1024→940 方形）后再降采样，保留构图主体。
5. **无 Pillow 环境**：本机无图像库且无法联网安装，为此另写一个仅用标准库的 PNG 解码/裁剪/面积降采样/重编码脚本（开发工具，不入包），保证头像处理可复现。
