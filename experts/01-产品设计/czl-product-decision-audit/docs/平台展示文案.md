## 详细介绍（详情页版）

### 它是做什么的

一个产品决策的**审校**工具。你在会前把想法和材料交给它，它做三件事：判断这件事值不值得做，找出你论证里最弱的一环，把它变成能被人执行、能被追问、能被叫停的东西。

判断标准只有一条：这份产出拿到会上，会不会被一个认真的人一句话问倒。

### 五道闸

- **分诊**：这是哪类决策？值不值得写文档？很多请求到这一步就该停。
- **证据**：每条断言标 A/B/C/D/X。结论的等级不能高于支撑它的最强证据，五条转述拼不成一条数据。
- **口径**：先查定义、波动带、口径是否改过、是否存在辛普森反转，**再**讨论"为什么"。
- **对抗**：写失效条件、做事前验尸、构造反方最强论点、定止损线。没写止损线的方案不许交付。
- **交付**：DoR、八节规格书、验收标准一对一映射测试、DoD、变更成本账簿。

### 交付物

默认一个决策包，五个区块顺序固定：结论 → 证据等级与最弱环节 → 反方与失效条件 → 下一步与止损线 → 待确认。

按需附：规格书、排序表、指标体检单、证据台账、竞争取证表、多受众版简报。

### 可执行的工具

三个纯标准库 Python 工具，不联网、不装依赖：

- 证据台账体检：越级措辞、小样本百分比、结论越级、单一来源依赖
- 指标护栏：口径卡校验、稳健波动带、两比例检验、辛普森反转检查
- 组合容量校准：真实产能、装箱排期、吞吐比对、脆弱项、砍单原因

### 适合谁

10–200 人团队的产品经理、产品负责人、创始人、技术转产品的负责人，以及一个人干完发现—定义—交付的独立开发者。

### 不适合谁

需要纯执行排期、需要法律或财务专业意见、需要为已定结论做支持性包装的场景。这三种情况它会说明原因并给替代方向，而不是硬套流程。

### 它不会做什么

不编造用户访谈和竞品数据；不写"零风险"方案；不替你对上级论证一个已经定下的结论（会转成压力测试）；不用框架名词代替判断。
