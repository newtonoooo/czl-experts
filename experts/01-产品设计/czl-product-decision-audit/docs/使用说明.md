# 使用说明

## 一、先理解它的态度

它会说"这个结论撑不住"、"你的证据只有 D 级"、"这份材料写不成 PRD"。

这不是故障，是它的功能。它的价值在于**在开会之前**把这些话说出来，而不是在会后。

如果你需要的是"帮我把我已经想好的方案写漂亮"，它不适合——它会先做压力测试，测试完可能给出反对意见。

## 二、五种典型用法

### 用法一：需求该不该做

**怎么问**

> 这个需求销售催了三次，老板问我要不要排进下个版本。我手上有 6 条客户反馈和一张竞品截图，帮我判断该不该做、做了怎么算成功。

**它会做什么**

1. 判门型（可逆补丁 / 单向门 / 赌注 / 合规 / 缺陷）
2. 把你手上的材料逐条评等级（客户反馈是原文还是转述，差别很大）
3. 走四问检验：谁的行为会变 / 影响哪个指标 / 不做会怎样 / 现在比三个月后多做得到什么
4. 给出口：做、补材料、或不做

**怎么把材料给得更好**

- 客户反馈贴原文，不要贴你的总结。原话能评 B 级，总结只能评 D 级。
- 竞品截图配上链接和日期。没有日期的竞品信息在评审会上会被一句话打掉。
- 说明是谁在催、催的人是不是使用者。销售催和市场催，是两件不同的事。

### 用法二：明天要开的复盘会

**怎么问**

> 季度复盘会明天开，MAU 涨了 8% 但付费转化掉了 12%，会上肯定有人问为什么。帮我把口径和归因先捋清楚。

**它会做什么**

1. 先要口径卡（定义、分子分母、时间窗、系统、去重与排除）
2. 算波动带，判断 8% 和 12% 是真变化还是噪声
3. 查口径是否改过（换埋点、换系统、换去重规则）
4. 查辛普森反转（合计方向对了不代表每个分组都对）
5. 给归因候选，每条写"若要成立应看到什么"
6. 给"可以说"和"不能说"两栏

**注意顺序**：口径 → 波动 → 归因。反过来做，会上一定被问倒。

**如果它要口径你给不出**，它会按你的描述反推一个定义让你确认。确认不了，所有结论会降为"参考"——这是诚实的处理，不是它偷懒。

### 用法三：排不下的季度计划

**怎么问**

> 我手上有 11 个候选需求要排下季度，团队就 5 个人。别再给我 RICE 分数了，帮我算清楚按现在的吞吐到底能做几个、剩下的怎么跟老板交代。

**它会做什么**

1. 算真实产能：5 人 × 12 周 × 0.65 ≈ 39 人周，**不是 60**
2. 扣掉必做项（合规、合同、缺陷）
3. 按产出密度装箱（不是排序——装不进去就跳过下一项）
4. 给出：做几个、砍哪些、每个砍掉的原因
5. 标记脆弱项（产能缩 20% 时会掉的项，不要对外承诺）
6. 给三选一的上行方案（砍范围 / 加人 / 改周期），每个都有代价

**最有价值的一栏**：如果某个被砍项的产出其实高于某个已排入项，只是体积太大塞不进去，它会单独点出来，并建议拆分。

**需要你提供**：候选清单的 reach / impact / confidence / effort。给不出精确值就填估算，但请标一句"估算"，它会在结论里注明排序依赖估算。

### 用法四：PRD 被工程打回

**怎么问**

> 我这份 PRD 工程说"这不是需求，是想法"。帮我看看缺什么，按能开工的标准重写。

**它会做什么**

1. 先过 DoR 八项（场景 / 现状 / 范围 / 成功标准 / 验收 / 依赖 / 埋点 / 设计）
2. 按八节结构重写，每节标注精度要求
3. 把验收标准一对一映射到测试用例
4. 检查异常路径是否不少于正常路径的 1/3
5. 给 DoD 和变更成本账簿

**它的强项在第五节"规则与逻辑"**。"系统自动匹配最优"会被改成判断表：匹配哪些字段、冲突怎么排序、匹配不到怎么办、用户能不能改。

### 用法五：对外怎么说

**怎么问**

> 批量导出下周上线，但自定义字段没做。要跟老板、工程、销售、客户各说一遍。帮我写四个版本。

**它会做什么**

给你四份长度不同、入口不同、但事实完全一致的材料。检查方法是把四份并排看，"结论"那一段是否指向同一个动作。

**坏消息**按固定五段说：坏消息本身 → 影响范围 → 已经做了什么 → 需要什么 → 什么时候再同步。不允许"由于一些原因""正在积极推进中""影响不大"。

## 三、怎么读它的输出

决策包五个区块，读法：

| 区块 | 你该看什么 |
|---|---|
| 1 结论 | 有没有具体动作和时间。出现"建议进一步评估"就是没结论 |
| 2 证据等级 | 哪些标 B 以上（能用），哪些标 D/X（只能当线索） |
| 3 反方与失效条件 | **这一块最该看**。失效条件写不出来，说明方案本身没想清 |
| 4 下一步与止损线 | 有没有人、有没有时间、有没有停止条件 |
| 5 待确认 | 谁该去问谁。这三条通常就是开会前需要补的洞 |

## 四、常见误用

| 误用 | 后果 | 改法 |
|---|---|---|
| 只给结论不给材料 | 它只能反复问，或给一个空决策包 | 至少给一条原文或一个数字 |
| 要求"写积极一点""别提风险" | 会被拒绝，或给两版让你选 | 说清受众和目的，语气它可以调，事实不能改 |
| 把它当文案工具 | 得到的是审校意见，不是文案 | 文案另找工具，这里只保证内容站得住 |
| 跳过 G1 直接要 PRD | 会在规格阶段发现需求本身不成立，白写 | 先说"要不要做"，再说"怎么做" |
| 材料是二手总结 | 全部结论降到 D 级，可用性大幅下降 | 尽量给原话、原文、原始数据 |
| 一次问十件事 | 每件都浅 | 一次一件，或明确说"先做哪件" |

## 五、三种你可能会不喜欢的回答

提前说清，免得误会：

1. **"这份材料撑不起一个版本"**
   它不是拒绝帮忙，是在告诉你：现在写 PRD 会写出一堆虚构细节。它会给你最小取证清单（三项以内，带成本）。

2. **"这个结论最高只能到 D 级"**
   因为你的证据是转述。它不会因此不给你做，但会在决策包里标明等级，让会上的人知道该信到什么程度。

3. **"你其实已经决定了，我把工作改成帮你找最强反对意见"**
   这在你说"帮我论证这个方案"时会出现。它不做支持性包装，因为包装过的论证在会上更容易崩。

## 六、配合脚本使用

材料多的时候（证据超过 15 条、候选超过 10 项、指标序列超过 12 期），建议直接用脚本，避免人工遗漏：

```bash
# 证据台账
python skills/evidence-ledger/scripts/evidence_check.py 台账.csv --conclusion-grade B --purpose invest

# 指标
python skills/metric-integrity/scripts/metric_guard.py card 口径卡.csv
python skills/metric-integrity/scripts/metric_guard.py ab --control 10000 512 --treat 10000 583
python skills/metric-integrity/scripts/metric_guard.py simpson 分群.csv

# 组合
python skills/portfolio-fit/scripts/portfolio_fit.py 候选.csv --headcount 5 --weeks 12 --history 6
```

脚本的 CSV 列名要求，见各技能目录下的 `SKILL.md` 与 `references/`。
夹具示例见各 `scripts/fixtures/` 目录，照着改最快。

## 七、一句话建议

**在你会前 24 小时用它，不要在会后。**

它的全部价值在于把"这个结论站不住"这句话提前说出来。会后再说这句，只是复盘；会前说，能改。
