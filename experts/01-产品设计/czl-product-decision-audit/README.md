> 把需求、优先级、指标和汇报过五道闸：证据、口径、反方、验收、止损。输出能直接开会的决策包。

## 它是什么

一个**决策审校**工具，不是文档代笔工具。

你带着一个已经有点成型、但在会上会被问倒的想法来，它做三件事：

1. 判断这件事**值不值得做**（很多请求到这一步就该停）
2. 找出你的论证里**最弱的那一环**（不是夸你，是拆你）
3. 把它变成**能被人执行、能被追问、能被叫停**的东西

判断标准只有一条：这份产出拿到会上，会不会被一个认真的人一句话问倒。会被问倒，就还没做完。

## 它和通用产品助手有什么不同

| 常见做法 | 这里的做法 |
|---|---|
| 给一套 PRD 模板让你填 | 先问你四句话，答不出就不写 PRD |
| 每条结论都写得很肯定 | 每条结论后面标证据等级 A/B/C/D/X，X 级只能写成假设 |
| 排完 RICE 分数就交差 | 算真实产能（人周），按装箱而非排序，给砍单清单和被挤掉的是什么 |
| 指标掉了就给归因 | 先查口径、查波动带、查辛普森反转，**再说**可能是为什么 |
| 方案列出风险就算尽责 | 必须写失效条件和止损线，没写不许交付 |
| 输出一堆框架名词 | 输出决策包五区块：结论 / 证据 / 反方 / 下一步与止损 / 待确认 |

## 五道闸

```
G1 分诊  → G2 证据 → G3 口径 → G4 对抗 → G5 交付
```

| 闸 | 回答的问题 | 不过怎么办 |
|---|---|---|
| **G1 分诊** | 这是什么类型的决策？值不值得写文档？ | 补最小证据清单，或劝退 |
| **G2 证据** | 每条断言最多能撑多重？最弱一环在哪？ | 降级结论，或标注为假设 |
| **G3 口径** | 这个数字在两个时间点是不是同一个东西？ | 断开趋势线，只做定性描述 |
| **G4 对抗** | 什么事实一旦出现，这个结论就作废？ | 加失效条件，或改方案 |
| **G5 交付** | 一个没参会的人能不能照着做事？ | 补 DoR / 验收映射 / 变更账簿 |

## 七个工作流技能

| 技能 | 职责 | 主要产出 |
|---|---|---|
| `decision-triage` | 定门型（可逆补丁/单向门/赌注/合规/缺陷）、清点材料、四问检验 | 决策简报，或最小取证清单，或劝退理由 |
| `evidence-ledger` | 拆断言、评等级、找反例；调研综合与竞品取证也在这一闸 | 证据台账 + 频次表 + 未找到反例的说明 |
| `metric-integrity` | 口径卡、波动带、样本充分性、口径漂移、辛普森检查 | 指标体检单 + 归因候选 + "可以说与不能说" |
| `adversarial-review` | 失效条件、事前验尸、反方最强论点、止损线、续投判定 | 对抗报告 + 续投/止损结论 |
| `spec-handoff` | DoR、八节规格书、验收映射到测试、DoD、变更成本账簿 | 规格书（评审版 + 工程版） |
| `portfolio-fit` | 产能校准、必做项预留、装箱式排期、吞吐比对、脆弱项 | 排序表 + 砍单清单 + 对上的三选一 |
| `audience-rendering` | 同一事实的五种写法、状态色纪律、坏消息结构、决策记录 | 高管版 / 工程版 / 跨部门版 / 客户版 |

## 三个可执行工具

纯 Python 标准库，无第三方依赖，无网络调用，不写文件。

```bash
# 证据台账体检：越级措辞、小样本百分比、结论越级、单一来源依赖
python skills/evidence-ledger/scripts/evidence_check.py ledger.csv \
       --conclusion-grade B --purpose invest

# 指标护栏：口径卡 / 波动带 / 两比例检验 / 辛普森反转
python skills/metric-integrity/scripts/metric_guard.py card cards.csv
python skills/metric-integrity/scripts/metric_guard.py baseline 412,401,398,420,405,410
python skills/metric-integrity/scripts/metric_guard.py ab --control 10000 512 --treat 10000 583
python skills/metric-integrity/scripts/metric_guard.py simpson segments.csv

# 组合容量校准：真实产能、装箱排期、吞吐比对、脆弱项
python skills/portfolio-fit/scripts/portfolio_fit.py backlog.csv \
       --headcount 5 --weeks 12 --utilization 0.65 --history 6
```

## 三个真实场景

**场景一：销售催了三次的需求**

> 「这个需求销售催了三次，老板问我要不要排进下个版本。我手上有 6 条客户反馈和一张竞品截图。」

它会先判门型，再拆断言。6 条反馈里如果只有 3 条是原文（B），另 3 条是销售转述（D），结论最高只能到 B；竞品截图必须标日期和来源类型。然后它会给一个「如果一定要做」的最小版本和止损线——因为决定权往往不在你手上。

**场景二：明天要开的复盘会**

> 「MAU 涨了 8% 但付费转化掉了 12%，会上肯定有人问为什么。」

它会先要口径卡，再算波动带，再查是不是口径改过、是不是辛普森反转。**顺序不能反**——在排除埋点漏报和定义变更之前，讨论「为什么」是浪费会议时间。最后给「可以说」和「不能说」两栏，你拿着去开会，被追问时知道边界。

**场景三：排不下的季度计划**

> 「11 个候选需求，团队 5 个人。别再给我 RICE 分数了。」

它算真实产能（5×12×0.65≈39 人周，不是 60），扣掉必做项，按产出密度装箱。会告诉你做几个、砍哪些、每个砍掉的原因（是排名低，还是体积太大塞不进剩余容量），以及**产能缩 20% 时哪几项会掉**——那几项不要对外承诺。

## 交付物

默认一个**决策包**，五个区块，顺序固定：

1. **结论** —— 一句话，不超过 40 字，含动作、范围、时间
2. **证据等级与最弱环节** —— 挂在什么等级上，补强要什么
3. **反方与失效条件** —— "如果 ___ 成立，此结论作废"
4. **下一步与止损线** —— 做什么、谁做、什么时候看、什么条件下停
5. **待确认** —— 最多 3 条，每条写明该谁回答

按需附：规格书、排序表、指标体检单、证据台账、受众版简报。附件可单独拿走使用，不依赖正文。

## 适用范围与边界

**适合**：10–200 人团队的产品经理、产品负责人、创始人、技术转产品的负责人，以及一个人干完发现—定义—交付的独立开发者。高频场景是周一的一页纸、需求评审会、季度复盘、排期会议、上线后的续投判断。

**不适合**：

- 纯执行排期（人力已定，只算日子）→ 给排期方法，不写决策包
- 法律意见、财务审计、人事绩效 → 只做产品侧影响分析
- 要求为已定结论做支持性包装 → 会改成压力测试，可能给出反对意见

## 已知限制

1. **不替代真实用户研究。** 没有访谈数据时它会明确说"缺"，并给最小取证清单，不会编造用户声音。
2. **竞品信息有时效。** 所有竞品事实必须带来源与日期；检索不到时会写"未找到公开来源"。
3. **统计方法有前提。** 两比例检验假设独立同分布、无中途偷看；埋点漏报、样本污染不在模型内，需要人来判断。
4. **产能模型是估算。** 利用率取 0.65 是起点，不是真理，需要按团队历史数据校准。
5. **建议不等于决策。** 它给的是能在会上站住的材料，最终判断和责任在用户。
