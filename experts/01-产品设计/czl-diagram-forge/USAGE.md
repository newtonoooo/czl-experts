# 使用说明

## 一、三种用法

### 1. 直接对话（推荐）

选定制图宗师后，用自然语言描述要画什么：

- 「画一张用户登录认证流程图，输出 SVG 和 HTML 预览」
- 「把订单状态机画成状态图，用深色主题」
- 「用四象限图评估这 6 个需求的优先级」

专家会自动完成：分诊 → 建模 → 体检 → 渲染 → 交付，并把文件给你。

### 2. 命令行（可控）

适合已经有结构描述、想自己掌控每一步的场景。

```bash
cd <专家包根目录>
node skills/diagram-forge/scripts/dg.mjs render my.json --out out --theme midnight
```

### 3. 只做体检

手上已有一段 Mermaid 源码，只想确认它有没有语法问题：

```bash
node skills/diagram-forge/scripts/dg.mjs check diagram.mmd
```

输出精确到行号，例如：

```
✖ 发现 2 处错误
   第 3 行：括号未闭合："["
   第 7 行：有 1 个块未闭合（缺少 end）
```

## 二、五个典型场景

### 场景 1：把口述流程变成审批图

**你说**：画一个报销审批流程，员工提交、系统校验、超过 5000 要主管审批、然后财务复核、通过就打款。

**专家做的事**：

1. 判定为 `flow`，有 1 个判断节点，链条约 8 层 → 自动选横排
2. 建 10 个节点、3 个分组（员工端 / 审批端 / 财务端）
3. 判断节点补「是 / 否」两条带标签出边
4. 退回路径用虚线区分
5. 体检 96 分（A），渲染 SVG + HTML + Mermaid

**你会拿到**：`费用报销审批流程.svg`、`.html`、`.mmd`、`.txt`

### 场景 2：把接口链路画成时序图

**你说**：下单接口，客户端调网关，网关转订单服务，订单服务查库存、调支付、写库，最后返回。

**注意点**：时序图最容易犯的错是"消息没有说明文字"。体检会对每条空消息扣 3 分。所以每步都要写清"做了什么"，而不是只画箭头。

### 场景 3：把表结构画成 ER 图

**你说**：我有会员、订单、订单明细、商品、支付、发货六张表。

**注意点**：

- 主键标 `pk`、外键标 `fk`，图上会有 PK/FK 角标
- 字段类型照抄真实 DDL，`decimal(12,2)` 这类带括号的类型在导出 Mermaid 时会自动规范化
- 关系基数写清 `1-1` / `1-n` / `n-n`，图上用鸦爪符号表示

### 场景 4：做一页 PPT 用的架构图

**关键差异**：PPT 是"远看"的，节点要少、字要大、对比要强。

- 主题选 `midnight` 或 `plum`
- 方向选 `LR`
- 节点压到 10 个以内，细节放 `note`
- 导出 SVG，插入 PPT 后仍是矢量，投影不糊

### 场景 5：检查别人给的 Mermaid

```bash
node dg.mjs check someone-else.mmd
```

体检能查出：括号未闭合、块未配对、空标签、箭头缺目标、标签含特殊字符未加引号。

查不出的是"画得对不对"——那是语义问题，需要人判断。

## 三、改图怎么改

改图 = 改 `model.json`，然后重跑 `render`。常用改动对照：

| 想改什么 | 改哪里 |
|---|---|
| 换配色 | 命令行 `--theme`，或模型里 `theme` |
| 横排改竖排 | `direction`: `LR` ↔ `TB` |
| 节点文字 | `nodes[].label` |
| 加一个分支 | 加一个 `diamond` 节点 + 两条带 `label` 的边 |
| 异常路径 | 边上加 `"style": "dashed"` |
| 圈一个责任域 | 加 `groups` 一项，`members` 填节点 id |
| 强调某个节点 | 节点加 `"emphasis": true` |
| 补一句口径说明 | 加 `footnote` |

改完一定要重跑 `check`，确认没引入新错误。

## 四、输出格式怎么选

| 用途 | 格式 | 理由 |
|---|---|---|
| Word / PPT / 网页 | `.svg` | 矢量，放大不糊，体积小 |
| 发给同事看 | `.html` | 单文件，离线可开，能切主题 |
| 平台里继续编辑 | `.mmd` | 标准 Mermaid，兼容面广 |
| 代码注释 / 终端 | `.txt` | 等宽对齐，无依赖 |
| 进版本库 | `.model.json` | 结构化，diff 可读 |

## 五、常见问题

**Q：图太宽/太高怎么办？**
改 `direction`。链条长（层数多、每层窄）用 `LR`；扇形宽（层少、每层宽）用 `TB`。不填则引擎按结构自动选。

**Q：节点文字被挤成好几行？**
标签压到 12 字以内，细节写进 `note` 或 `footnote`。

**Q：为什么体检说我有孤立节点？**
有节点没连任何边。要么补连线，要么删掉——孤立节点在图上会让人误以为它属于某个流程。

**Q：判断节点为什么被扣分？**
菱形必须至少 2 条出边，且每条都要写条件（是/否、通过/拒绝）。这是流程图最容易被省略、也最容易让读者困惑的地方。

**Q：能画成公司品牌色吗？**
可以。编辑 `skills/diagram-forge/scripts/lib/themes.mjs`，复制一份主题改 `accent` 与 `palette` 即可，方法见 `references/themes.md`。

**Q：能在离线环境用吗？**
能。引擎只用 Node.js 标准库，不联网、不装包。

**Q：头像图标显示成文字了怎么办？**
跑一次体检：

```bash
python skills/diagram-forge/scripts/tools/avatar_check.py check <专家目录>
```

它会检查头像是否存在、格式、尺寸（须 512×512）、体积（须 ≤500KB）。不合规时用 `fix` 子命令规范化。
