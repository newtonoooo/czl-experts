# 「专家头像变成文字」问题排查报告

- 排查日期：2026-10-28
- 现象：专家导入到新的 WorkBuddy 后，选中该专家时左上角小图标不显示，退化成了一个字
- 结论：**头像文件不合规导致客户端解析失败，前端按设计降级为首字文字头像**

---

## 一、机制：为什么会"变成字"

客户端渲染专家头像的流程（`ExpertPluginService.resolveAvatarUrl`）：

```
读 plugin.json 的 avatar 字段
  → 拼成绝对路径
  → 文件不存在？         → 返回 ''
  → 文件体积 > 5MB？      → 返回 ''（同时打一条 warn 日志）
  → 都不是？             → 返回 file:// URL，交给 <img> 渲染
```

只要返回空字符串，前端拿不到图片地址，就退化成用专家名首字渲染的占位头像——**看起来就是"图标没了，变成一个汉字"**。

这条链路上有三处会**静默失败**，都不会弹错误提示：

1. `resolveAvatarUrl` 遇到文件缺失或超大 → 返回空串，只写日志
2. zip 导入时 `resolveAvatarFromExpertZip` 把头像内联成 base64 data URL，找不到对应 zip 条目就原样返回相对路径
3. `<img>` 拿到 data URL 但 MIME 与实际字节不符 → 解码失败 → 空白

所以"图标变文字"不是 UI bug，而是**头像资源在某一环没被正确解析**的最终表现。

## 二、实测证据

### 2.1 对比同环境下能正常显示的专家

| 专家 | 头像尺寸 | 体积 | 显示 |
|---|---|---|---|
| czl-a-share-trading-desk | 512×512 | 228 KB | 正常 |
| czl-deskforge | 512×512 | 457 KB | 正常 |
| czl-contract-counsel | 512×512 | 415 KB | 正常 |
| ……（共 21 个自建专家） | 全部 512×512 | 105–486 KB | 全部正常 |
| **mermaid-diagram-expert**（出问题的那个） | **1024×1024** | **1194 KB** | **异常** |

21 个正常显示的自建专家，头像清一色 512×512、全部小于 500KB；唯一出问题的那个是 1024×1024、1194KB。

### 2.2 官方规范

`expert-manager` 技能的 `references/avatar-spec.md` 明确要求：

| 项目 | 要求 |
|---|---|
| 格式 | PNG（推荐）或 JPG |
| 尺寸 | 512×512 px（正方形） |
| 大小 | 单张不超过 500KB |

出问题的头像**同时违反两条**：尺寸不是 512×512，体积超出上限 2.4 倍。

### 2.3 客户端代码中的体积阈值

反查客户端代码，`resolveAvatarUrl` 里的体积阈值是 `5242880`（5MB），不是 500KB。也就是说：

- **1.2MB 的文件不会触发客户端的 5MB 拦截**
- 但在 **zip 导入**路径下，头像会被转成 base64 内联进专家记录：1.2MB → 约 1.6MB 的 data URL 字符串。这个字符串要经过 IPC 传递并落盘，是最容易出问题的一环

由此可以判断：**这个头像在"下载自市场"和"手工 zip 导入"两条路径下的表现可能不同**，而用户遇到问题的场景正是"导入到新 WorkBuddy"。

## 三、五个可能原因（按可能性排序）

| # | 原因 | 表现 | 30 秒确认方法 |
|---|---|---|---|
| 1 | 头像尺寸/体积不符合规范 | 图标缺失 | `avatar_check.py check` 直接报出尺寸与体积 |
| 2 | 文件扩展名与实际格式不符（如 JPG 改名成 .png） | 图标缺失 | 同上，会报「扩展名与内容不符」 |
| 3 | zip 包结构不对：顶层目录名 ≠ `name` 字段，或漏打包 `avatars/` | 图标缺失 | 解压后看是否只有一层同名目录、里面是否有 avatars |
| 4 | `plugin.json` 的 `avatar` 路径写错（大小写、多余层级） | 图标缺失 | `check` 会报「头像文件不存在」 |
| 5 | 导入时专家记录被截断（超大 data URL 撑爆序列化） | 图标缺失，其他字段可能也不全 | 对比导入前后专家名/简介是否完整 |

本次这个包，第 1 条已经确认成立；第 2–5 条需要用工具逐项排除。

## 四、修复步骤

### 4.1 一键体检

```bash
python skills/diagram-forge/scripts/tools/avatar_check.py check <专家目录>
```

输出示例（真实运行结果）：

```
专家：mermaid-diagram-expert
配置：avatar = avatars/expert.png
文件：PNG 1024×1024  1194.4 KB
⚠ 发现以下问题：
   • 尺寸不是 512×512（规范要求）
   • 体积 1194 KB 超过 500KB 上限
```

### 4.2 一键规范化

```bash
python skills/diagram-forge/scripts/tools/avatar_check.py fix avatars/expert.png avatars/expert.png --size 512
```

会做四件事：居中裁成正方形 → 双线性区域平均降采样到 512×512 → 重新编码 PNG（最优压缩）→ 若仍超 500KB 自动继续降采样。

纯 Python 标准库实现，不需要装 Pillow。

### 4.3 重新打包

```bash
python scripts/package_expert.py <专家目录>
```

打包脚本会跳过 `.DS_Store`、`__pycache__` 等垃圾文件，并保持单一顶层目录。

### 4.4 重新导入并验证

删掉旧专家 → 重新导入 zip → 重新选择该专家 → 看小图标是否恢复。

## 五、给这个新专家的预防措施

`czl-diagram-forge` 在设计上直接规避了同类问题：

1. 头像从生成开始就按规范处理：1024×1024 生成 → 裁掉生成工具水印 → 居中裁正方形 → 降采样 512×512 → 重编码 PNG，最终 **472 KB**
2. 头像体检脚本随包分发，任何人改头像后都能自查
3. 打包前跑一遍 `validate_expert.py`（0 error / 0 warning）
4. 测试报告里把头像合规性列为独立验收项

## 六、本次排查的边界

- **已确认**：出问题的头像为 1024×1024 / 1194KB，违反官方 512×512 / ≤500KB 规范；同环境 21 个合规头像均正常显示
- **已确认**：客户端在头像解析失败时返回空字符串，前端降级为文字头像；体积硬阈值是 5MB
- **未能确认**：无法在客户端 UI 内复现，因此不能断言"就是体积导致的"。第 2–5 条原因需要按第四节逐项排除
- **建议**：先按 4.1 跑一次体检。如果体检只报尺寸/体积问题，按 4.2 修复后重导入基本可解决；若体检全部通过但图标仍缺失，则问题在 zip 结构或导入环节，需要检查包内目录层级
