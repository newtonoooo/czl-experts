## 一、需求来源

### 1.1 功能分析（仅分析能力，不复制实现）

对目标专家 `mermaid-diagram-expert` 做了完整的功能面分析，归纳出这类产品必须解决的六件事：

1. 把自然语言转成图表结构
2. 生成可编辑的图表源码
3. 渲染成可视化文件
4. 提供主题配色
5. 支持多种图表类型
6. 支持多种输出格式

### 1.2 发现的不足（这些成为新产品的设计输入）

| 不足 | 后果 | 本产品的应对 |
|---|---|---|
| 渲染依赖第三方库 `beautiful-mermaid` | 需 `npm install`，离线环境不可用；库行为变化不可控 | 自研渲染引擎，零依赖 |
| 以 Mermaid 源码为唯一中间产物 | 源码有语法错时只能靠渲染失败发现 | 引入模型层 + 渲染前静态体检 |
| 无质量评估 | 图"能出来"不等于"读得懂" | 100 分制质量评分，12 组规则 |
| 图表类型 6 种 | 缺甘特、思维导图、时间轴、饼图、四象限、柱线图 | 扩展到 11 种 |
| 无跨层边避让 | 复杂流程连线穿越节点 | 侧向通道 + 画布范围纳入 |
| 中文断行未处理 | 中英混排时换行位置生硬 | 全角计量 + 中西文分别断行 |
| 头像 1024×1024 / 1.2MB | 不合规，导致图标不显示 | 512×512 / 472KB，并随包提供体检工具 |

**没有复制的部分**：原专家的提示词结构、文案、主题命名、渲染脚本、头像、README 均未使用。仅参考了"这类产品需要具备哪些能力"这一层信息。

## 二、架构决策

### D1 模型优先，而非源码优先

**决策**：定义 `model.json` 作为唯一事实来源，Mermaid 源码降级为一种导出格式。

**理由**：
- 源码作为中间层时，语法错误只能靠渲染失败暴露；模型层可以在渲染前做结构校验
- 同一结构要导出 4 种格式时，从模型派生比从源码转换更可靠
- 用户可以只改 JSON 局部重渲染，不必重写提示词

**代价**：不支持从 `.mmd` 反向重建模型（已在文档中明确列为限制）。

### D2 场景图（Scene）作为渲染中间层

**决策**：布局层只产出绘制指令数组（rect / text / path / polygon / circle），序列化层负责转 SVG / HTML / ASCII。

**理由**：换输出格式不需要重写任何布局代码。ASCII 输出就是复用同一份场景数据做的降级映射。

### D3 自研分层布局

**决策**：不引入 ELK / dagre，自己实现「环检测 → 最长路径分层 → 重心法排序 → 正交路由」。

**理由**：
- 零依赖是核心卖点（离线可用）
- 需要的图规模有限（≤30 节点），完整 ELK 的能力过剩
- 需要针对中文排版做定制（节点宽度按全角计量）

**代价**：布局质量不如成熟库，跨层边需要手工通道策略。

### D4 语义角色 + 7 色板

**决策**：节点颜色不直接指定，而是由 `role` 映射到主题的 7 色板；填充色 = 底色与角色色按 11% 混合。

**理由**：保证 12 套主题下节点都是"克制的强调"而不是"刺眼的色块"；同时让"异常=红、成功=绿"这类语义在不同主题下保持一致。

### D5 质量评分而非"看起来不错"

**决策**：12 组规则、每条扣分对应一句可解释的理由，等级 A/B/C/D，硬性门槛 78 分。

**理由**：让"能不能交付"从主观判断变成可复现的检查，也让用户知道该改哪里。

### 3.2 迭代中修复的问题

开发过程用无头浏览器把 SVG 渲染成位图逐张核对，共发现并修复 7 类问题：

1. **LR 布局下文字被挤成多行** — 根因：方向变换时节点宽高互换，但布局阶段仍用原始宽高计算列宽，导致节点实际宽度变成它的高度（46px）。修复：方向为 LR/RL 时先用交换后的尺寸参与布局。
2. **边标签被节点填充盖住** — 根因：绘制顺序是「分组 → 连线 → 节点」，标签画在节点之前。修复：标签延迟到最后绘制。
3. **跨层边压住标题** — 根因：侧向通道放在画布左侧外部，转置到 LR 后变成顶部。修复：通道改到右侧，并把连线点纳入画布包围盒计算。
4. **类图构造型压线** — 根因：表头固定 34px，构造型文字画在表头外。修复：表头高度随构造型自适应。
5. **四象限纵轴标注颠倒** — 根因：把 y 轴高值画在了中线位置。修复：改为顶部高值、底部低值，并加箭头轴。
6. **柱线图图例压副标题** — 根因：图例 y 坐标与副标题重叠。修复：多系列时下移绘图区，图例右上对齐。
7. **甘特图条纹错位** — 根因：用绝对坐标奇偶判断隔行底色。修复：改用行号。

另有 2 项未完全消除，作为已知限制记录在测试报告里。

### 3.3 ASCII 输出返工

第一版把所有节点画进了同一个方框（误用「一个框装多行文字」的写法）。重写为「每层并排多个独立方框 + 竖直连接线」，并解决了跨层连线列号在目标层尚未计算导致箭头丢失的问题（改为先预计算全部列的坐标，再绘制）。

### 3.4 自检脚本

`selftest.mjs` 从最初的「能跑通就算过」演进为 86 项断言，覆盖：生成标记、标签平衡、NaN 检测、导出源码回检、非法输入、全主题矩阵。开发后期每次改动都先跑它，避免回归。
