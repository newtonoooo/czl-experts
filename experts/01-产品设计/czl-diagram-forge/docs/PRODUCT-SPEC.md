## 一、需求分析

### 1.1 目标用户

| 用户 | 典型身份 | 他们画什么 |
|---|---|---|
| 技术文档作者 | 后端 / 架构师 / 技术写手 | 系统架构、调用链路、表结构 |
| 产品与项目角色 | 产品经理 / 项目经理 | 业务流程、状态机、排期、优先级 |
| 咨询与汇报角色 | 顾问 / 分析师 | 汇报用示意图、时间轴、对比图 |
| 教学与内容创作 | 讲师 / 自媒体 | 概念拆解、知识结构图 |

共同点：**他们不是设计师**，也不想为了画一张图去学一个工具。

### 1.2 使用场景

1. **写文档时临时要一张图**：需求已经想清楚，只差把它画出来。
2. **开会时口头描述流程**：需要快速变成可确认的图，边讨论边改。
3. **接手别人的项目**：手上只有一段 Mermaid 源码或一堆表名，需要整理成图。
4. **做汇报材料**：需要同一份结构在不同配色/尺寸下复用（文档版 + 投影版）。
5. **审阅别人画的图**：需要判断这张图有没有结构硬伤。

### 1.3 要解决的问题

| 问题 | 现状 | 本产品的解法 |
|---|---|---|
| 生成的 Mermaid 有语法错 | 复制到平台才发现渲染失败 | 渲染前静态体检，精确到行号 |
| 节点一多就糊 | 布局交叉、文字换行、比例失衡 | 分层布局 + 结构画像自动选方向 + 质量评分拦截 |
| 配色靠猜 | 深浅底对比不足、语义色滥用 | 12 套预设主题 + 语义角色色板 |
| 只给代码不给图 | 用户还得自己找渲染器 | 直接产出 SVG / HTML 文件 |
| 改一处要重画 | 结构散落在提示词里 | 模型与渲染分离，改 JSON 即可重出图 |
| 不同场合要不同版本 | 手工调尺寸配色 | 一次建模，多主题多格式导出 |

### 1.4 必要输入

- 自然语言描述（最少：要表达什么关系）
- 或结构化材料：文档、表格、DDL、代码、已有 `.mmd`
- 可选：目标场景（文档/PPT/代码仓库）、品牌色、尺寸约束

### 1.5 预期输出

| 产物 | 格式 | 用途 |
|---|---|---|
| 矢量图 | `.svg` | 文档、PPT、网页 |
| 交互预览 | `.html` | 单文件分享，可切主题、缩放 |
| 源码 | `.mmd` | 跨平台二次编辑 |
| 文本图 | `.txt` | 终端、代码注释 |
| 模型 | `.model.json` | 版本管理、程序化生成 |
| 说明 | 交付说明 | 结构假设、文件清单、修改指引 |

### 1.6 通用处理步骤

```
分诊（定类型/方向/主题/格式）
  → 建模（抽实体、定关系、定角色、分组、压文案）
  → 体检（结构校验 + 质量评分，不达标返工）
  → 渲染（一次生成全部格式）
  → 复核（比例、标签、连线、分组、对比度）
  → 交付（文件 + 说明 + 修改指引）
```

### 1.7 工具能力要求

| 能力 | 要求 |
|---|---|
| 布局 | 有向图分层布局，支持环、跨层边、分组 |
| 排版 | 中日韩全角计量，中英混排正确断行 |
| 绘制 | 至少 10 种节点形状、4 种线型、箭头 |
| 主题 | ≥ 10 套，深浅各半，切换不重排 |
| 输出 | SVG / HTML / Mermaid / ASCII 四种 |
| 校验 | 结构校验 + 语法体检 + 质量评分 |
| 环境 | 离线可用，无第三方运行时依赖 |

### 1.8 质量、速度、稳定性要求

| 维度 | 指标 | 实测 |
|---|---|---|
| 质量 | 质量分 ≥ 78 才允许交付，无 high 级遗留 | 11 份模板平均 99.6 分 |
| 速度 | 单图渲染 < 300ms | 单图 30–120ms（含进程启动） |
| 稳定性 | 全类型 × 全主题渲染无异常 | 132 次组合渲染全部通过 |
| 可复现 | 同输入同输出（除生成时间戳） | 是 |

## 二、产品定位

**一句话**：把结构描述编译成交付级图表的离线工具型专家。

**与通用大模型画图的差异**：

| 维度 | 通用做法 | 本产品 |
|---|---|---|
| 产出 | 一段代码 + 建议 | 文件 + 说明 |
| 校验 | 无 | 结构校验 + 语法体检 + 质量评分 |
| 结构 | 直接写代码 | 先建模再渲染 |
| 一致性 | 每次风格不同 | 主题令牌化，同主题必然一致 |
| 可修改 | 改提示词重来 | 改 JSON 局部重渲染 |

**与在线图表工具的差异**：无需注册、无需联网、无需上传数据；适合有数据合规要求的环境。

## 三、功能规格

### 3.1 图表类型矩阵

| kind | 布局内核 | 关键能力 | 主要限制 |
|---|---|---|---|
| flow | 分层图 | 10 形状 / 3 线型 / 分组 / 四向 | 单图建议 ≤30 节点 |
| state | 分层图 | 起止伪状态 / 迁移标签 | 不支持复合状态 |
| class | 分层图（盒模型） | 5 种关系 / 构造型 / 成员分栏 | 不支持泛型嵌套展示 |
| er | 分层图（盒模型） | PK/FK 角标 / 鸦爪基数 | 不支持复合主键分组 |
| sequence | 时序内核 | 3 类消息 / 注释 / 4 种逻辑块 | 无激活条、无嵌套 fragment |
| gantt | 时间轴内核 | 分段 / 里程碑 / 关键路径 / 日期或偏移 | 无依赖连线 |
| mindmap | 树形内核 | 自动配色 / 备注 | 仅横向布局 |
| timeline | 轴内核 | 上下交错卡片 | 事件 >10 建议合并 |
| pie | 极坐标内核 | 环形 + 图例百分比 | ≤8 项 |
| quadrant | 笛卡尔内核 | 四区标注 / 散点标签避让 | x/y 需归一到 0~1 |
| xy | 笛卡尔内核 | 柱/线/面积混合 | 系列 ≤4 |

### 3.2 输出规格

| 格式 | 规格 |
|---|---|
| SVG | 含生成标记注释、`<title>`、`viewBox`；字体栈含中英文回退；不引用外部资源 |
| HTML | 单文件；内联 SVG；主题按钮切换；Ctrl+滚轮缩放；拖拽平移；无 CDN |
| Mermaid | 首行为类型声明；节点 id 已规范化；可通过 `dg check` 自检 |
| ASCII | 等宽对齐；CJK 按双宽处理；框线用 Unicode 制表符 |
| model.json | 规范化后的模型，字段顺序稳定，便于 diff |

### 3.3 质检规格

- 结构校验：11 类必检项（类型、id 唯一性、悬空引用、分组冲突、块闭合、长度一致、数值合法性等）
- 语法体检：括号/引号平衡、块配对、空标签、箭头缺目标、特殊字符未加引号
- 质量评分：100 分制，12 组规则，每条扣分对应具体可读性问题，等级 A/B/C/D

### 3.4 环境规格

- Node.js ≥ 18，仅标准库
- Python 3.8+（仅头像体检工具，可选）
- 无网络请求、无 npm install、无外部二进制

## 四、非功能需求

| 项 | 要求 | 实现 |
|---|---|---|
| 可维护性 | 渲染器分层，新增图表类型不改动既有模块 | `lib/` 13 模块，paint 层按类型隔离 |
| 可测试性 | 每类图表有可运行模板与自动化自检 | `templates/` 11 份 + `selftest.mjs` 86 项 |
| 可移植性 | 不依赖平台 API | 纯标准库，Windows/macOS/Linux 一致 |
| 可解释性 | 扣分理由可读 | 每条规则附一句话原因 |
| 失败可见 | 出错不静默 | 校验错误带字段路径，语法错误带行号 |

## 五、明确不做的事

1. 不做位图精修与照片级插画
2. 不做在线协作与云端存储
3. 不解析 `.mmd` 反向重建模型
4. 不替用户编造业务事实与数值
5. 不宣称任何平台官方认证或合作关系
