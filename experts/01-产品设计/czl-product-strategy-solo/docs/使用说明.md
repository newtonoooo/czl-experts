# 使用说明 · 专业级产品战略参谋

面向两类人：**安装者**（装进 WorkBuddy）与**使用者**（用它出决策包）。

---

## 一、安装

### 方式 A：本地专家市场（推荐）

1. 复制整个 `czl-product-strategy-solo` 目录到：

```
~/.workbuddy-ai/plugins/marketplaces/my-experts/plugins/
```

Windows 即 `C:\Users\<用户名>\.workbuddy-ai\plugins\marketplaces\my-experts\plugins\`。

2. 编辑 `~/.workbuddy-ai/plugins/marketplaces/my-experts/.codebuddy-plugin/marketplace.json`，在 `plugins` 数组里追加：

```json
{
  "name": "czl-product-strategy-solo",
  "source": "./plugins/czl-product-strategy-solo",
  "description": "Single-expert product strategy workbench: five hats, six stages, four gates, with a cross-document consistency check."
}
```

3. 重启 WorkBuddy，专家列表搜索「产品战略参谋」。

### 方式 B：本地目录导入

在自定义专家入口选择"从本地目录导入"，指向包根目录（含 `.codebuddy-plugin/plugin.json` 那一层）。

### 安装后自检

```
python tests/run_tests.py -v
```

全绿说明结构、头像、脚本、文档完整。

## 二、第一次使用

选中「专业级产品战略参谋」后，直接说事。**不用写提示词**，但要给三个东西：**解决什么、给谁用、手头有什么**。

三句可直接用：

> 老板说要做 AI 助手，但没说给谁用、解决什么。我手上只有 8 条客户抱怨和一份竞品截图，帮我把它变成能立项的方案。

> 下季度 11 个候选需求，团队 6 个人 13 周。帮我定出真能做完的，并写清楚砍掉什么、砍了怎么跟老板交代。

> 上个季度 MAU 涨了 9%，付费转化掉了 12%。先把口径和分母查清楚，再告诉我会上该怎么回答。

### 它会先问你什么

多数情况下先跑**立案卡**，最多 3 个问题，每个带选项：

- 「这个功能上线后，哪个数字会变？现在是 3% 还是 30%？」
- 「第一批必须用上的是哪类用户？他们现在用什么凑合？」
- 「如果只做一半，哪一半先做？」

答不出也行，它会写成假设并标注，同时告诉你"取证后需要重算"。

## 三、五顶帽子是怎么轮换的

你会看到它按顺序推进，每推进一步落一个文件：

```
帽 A 立案  → 00-立案卡.md
帽 B 取据  → 01-证据台账.csv/.md
帽 C 成文  → 02-需求规格.md
帽 D 排产  → 03-产能排产.csv/.md
帽 E 度量  → 04-指标口径表.md
帽 F 汇报  → 05-汇报包.md + 00-决策简报.md + 99-一致性报告.md + meta.json
```

**换帽的关键规矩**：上一顶帽子的产出先落盘，下一顶帽子只读文件。所以你看到的不是"一个 AI 想到哪写到哪"，而是"五个人依次进场，各自只看材料不看人"。

### 你可以随时打断

- 「先只做立案卡，我看完再往下」→ 它会在帽 A 结束后停
- 「证据太弱，帮我把取证动作列细」→ 回到帽 B
- 「排产重算，人数改成 4 人」→ 回到帽 D，后续自动重跑

### 它会主动说的局限

如果事情金额大、不可逆、或你手上结论"太一致没人反对"，它会告诉你"这件事更适合多人交叉审"，并建议换用团队版。这是设计好的行为，不是推诿。

## 五、五个脚本单独用

都在 `skills/<技能名>/scripts/`，`python xxx.py -h` 看参数。

### 1. 证据台账

```
python skills/evidence-ledger/scripts/evidence_grade.py --csv 01-证据台账.csv --today 2026-10-28
```

### 2. 规格

```
python skills/spec-architect/scripts/spec_lint.py 02-需求规格.md
```

### 3. 产能装箱

```
python skills/capacity-packing/scripts/capacity_pack.py --backlog backlog.csv --people 6 --weeks 13 --focus 0.65
```

`backlog.csv` 字段：`id,req_id,title,pw,priority,depends_on,stop_loss`

### 4. 指标口径

```
python skills/metric-guard/scripts/metric_check.py --cards 口径卡.csv
python skills/metric-guard/scripts/metric_check.py --segments 分层.csv
```

分层字段：`segment,exposed_n,exposed_k,control_n,control_k`

### 5. 一致性

```
python skills/chain-consistency/scripts/chain_check.py deliverables/warroom-solo/2026-10-28-xxx
```

**退出码约定**：0 通过，1 有阻断项。可直接接 CI。

## 六、常见问题

### Q1：和团队版（作战室）什么区别，我该用哪个？

同一套方法论，两种形态：

- **单人版（本包）**：快，无编排开销，适合日常立项、季度规划、你一个人负责的事。
- **团队版**：5 个 AI 分工，别人审你的证据，对抗性强，适合金额大、不可逆、需要交叉验证的决策。

两个都装了不冲突，按场景换。

### Q2：一个人怎么保证不是自己骗自己？

三条硬机制：每条 A/B 级结论必须写"反证候选"（写不出降级）、汇报前必须写"三条最强否决理由"、自评冲突以脚本为准。这是单人形态的最低成本对冲，但它不等于真的有人审你。

### Q3：它一直追问，能不能直接给结果？

回「按假设模式跑，别问了」。它会：结论全标 D 级、首页写明"基于假设需重算"、给 3 条最低成本取证动作。**不会假装结论可靠。**

### Q4：能不能不写 Non-goals？

不行。Non-goals 是防范围蔓延的唯一闸。没有就说明范围没想清楚。

### Q5：排产装不下我的 P0 怎么办？

阻断并给三选一：砍范围 / 加人 / 延期，各带代价。不会把 3 人周压成 1.5 人周。

### Q6：需要联网吗？

不需要。5 个脚本纯离线。竞品取证若要联网，由运行环境提供检索能力。

### Q7：数据会上传吗？

不会。脚本纯本地，包内无网络调用代码。

## 七、卸载

1. 删除 `.../my-experts/plugins/czl-product-strategy-solo` 目录

3. 重启 WorkBuddy
