# 更新日志

本文件记录 `czl-product-strategy-solo` 的版本变更。版本号遵循语义化版本：主版本号变更表示工作流或输出结构不兼容，次版本号变更表示新增能力，修订号变更表示修正与优化。

---

## [1.0.0] — 2026-10-28

首个发布版本。由同系列团队版（`czl-product-strategy-warroom`）的编排逻辑重构为单专家形态，功能等价。

### 新增

- **单专家五帽协议**：一个 Agent 顺序轮换立案 / 取据 / 成文 / 排产 / 度量 / 汇报五顶帽子，每顶帽子职责排他，产出独立落盘。
- **换帽铁律（5 条）**：文件隔离、换帽标记、反证义务、数字双录、脚本裁决。这是单人形态能顶住"自己审自己"的核心机制。
- **六段链与四道闸**：与团队版同一套 G1 立案闸 / G2 证据闸 / G3 一致闸 / G4 交付闸。
- **编号贯通体系**：GOAL / EVD / REQ / AC / MET / RM / RSK / DEC。
- **7 个技能模块**：strategy-intake、evidence-ledger、spec-architect、capacity-packing、metric-guard、chain-consistency、stakeholder-render。
- **5 个校验脚本**（纯标准库）：evidence_grade、spec_lint、capacity_pack、metric_check、chain_check。
- **单人自审三对冲**：红队段落（三条最强否决理由）、数字对账表、假设暴露清单。
- **形态切换建议**：提示词内置"什么时候该换用团队版"的三条判断（金额大/不可逆、无人反对、需三路独立取证）。
- **测试体系**：`tests/run_tests.py`，11 项脚本行为用例 + 结构完整性检查。
- **原创头像**：`avatars/expert.png`，384×384 PNG，与团队版不同形象，避免列表混淆。

### 与团队版的差异

| 维度 | 团队版 | 本包 |
|------|--------|------|
| Agent 数量 | 5（1 主理人 + 4 席位） | 1 |
| 编排方式 | Agent Team 消息中转 | 单上下文顺序换帽 |
| 交付目录 | `deliverables/warroom/` | `deliverables/warroom-solo/` |
| 技能与脚本 | 7 + 5 | 完全相同（同一份自研内容） |
| 对抗性 | 强 | 中，靠三对冲补足 |

### 修正（上架解析失败后修复）

平台导入时报「解析失败」，三条错误已全部修复：

| 错误 | 原因 | 修复 |
|------|------|------|
| `tags` 须固定 3 个，当前 5 个 | 写了 5 个标签（含"单人可跑"） | 收敛为 3 个：产品战略 / 需求规格 / 产能排产；"单人"特性改由产品名与描述承载 |
| `defaultInitPrompt.zh` 必须与 `quickPrompts[0].zh` 一致 | 默认提示是"季度排产"，quickPrompts 首条是"从零立项" | 把默认提示原文放到 `quickPrompts[0]`，其余两条顺延 |
| `defaultInitPrompt.en` 必须与 `quickPrompts[0].en` 一致 | 同上 | 同上（英文同步） |

**回归防护**：`tests/run_tests.py` 新增 5 项断言，覆盖上述三条平台规则。

### 设计决策

- **保留同一套技能与脚本**：不为了"看起来不同"而重写已经过测试的校验逻辑。两版差异应体现在编排形态，而不是把同一件事做出两种质量。
- **强制反证义务**：单人形态最容易把"我猜的"写成"数据显示"，因此把"每条 A/B 级结论必须写反证候选"写成硬约束，写不出就降级。
- **不隐瞒局限**：提示词第十二节要求主动告知用户单人版的对抗性弱点，不许为了留住任务而隐瞒。

### 已知限制

- 不包含联网检索能力，竞品取证需由运行环境提供检索工具。
- 一致性脚本只做结构校验，不判断业务判断的正确性。
- 单人版无跨 Agent 交叉验证，重大不可逆决策建议使用团队版。
- 中文优先，英文模板尚未本地化。
