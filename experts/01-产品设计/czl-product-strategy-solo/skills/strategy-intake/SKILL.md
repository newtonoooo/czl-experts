# 立案（Intake）

## 什么时候用

- 用户说"我想做个 X""老板要我们上 Y""竞品有了我们也要有"
- 需求方催得紧，但没人说得清给谁用、解决什么
- 你自己也拿不准这事该不该做

## 为什么先做这一步

产品链路里最贵的错误不是做错功能，是**做错题**。做错题的返工成本是做错功能的十倍，而且没人会怪你——因为从头到尾没人写清楚目标是什么。

立案卡的作用：让"做错题"在第一天就暴露。

## 五要素

| 要素 | 合格标准 | 不合格的样子 |
|------|----------|--------------|
| **目标** | 一句话，含对象+变化+期限 | "提升用户体验" |
| **谁的问题** | 具体角色 + 规模（人数/占比） | "所有用户" |
| **现状证据** | 至少 1 条可指出来源的事实 | "大家都知道很痛" |
| **成功定义** | 一个可测指标 + 基线 + 目标值 | "做好了会上线" |
| **不做什么** | ≥3 条明确排除项 | 空白 |

## 执行步骤

1. **复述**：用一句话把用户诉求改写成"给 <谁> 在 <场景> 下解决 <什么问题>"，请用户确认或纠正。
2. **填空**：五要素逐项填。能填的填，不能填的标 `待确认`。
3. **计数**：`待确认` 达到 2 项以上 → 不要往下跑，直接问。
4. **提问**：最多问 3 个问题，每个问题给选项（不要开放式提问，用户答不出来）。
5. **定级**：给出本次任务的档位
   - **A 档（可立项）**：五要素齐全，有 A/B 级证据 → 走完整六段链
   - **B 档（可探路）**：缺 1 项，证据为 C/D 级 → 走 S1→S2→S3 后停下复核
   - **C 档（不该做）**：目标不成立，或问题规模不足以支撑投入 → 直接建议不做，并给出替代动作

## 提问模板（照抄可用）

- 「这个功能上线后，哪个数字会变？现在是 3% 还是 30%？」（逼出基线）
- 「第一批必须用上的是哪类用户？他们现在用什么凑合？」（逼出人群与替代方案）
- 「如果只做一半，哪一半先做？另一半什么时候做？」（逼出边界）

## 输出

`00-立案卡.md`：

```markdown
# 立案卡：<名称>

| 要素 | 内容 | 状态 |
|------|------|------|
| 目标 | ... | 确认 / 待确认 |
| 谁的问题 | ... | |
| 现状证据 | EVD-xx / 无 | |
| 成功定义 | MET-xx：基线 X → 目标 Y，口径见 | |
| 不做什么 | 1. 2. 3. | |

## 档位判定
A / B / C —— 理由一句话

## 下一步
- 若 A：进入取据（S2）
- 若 B：先补 <哪项>，成本 <多久>
- 若 C：建议不做，替代动作是 <...>
```

## 判断规则

- 目标里出现"提升/优化/加强"但没有对象和数字 → 不合格。
- "谁的问题"写成"用户" → 不合格，必须到角色级（例：月结期间的财务专员）。
- 成功定义只写"上线" → 不合格，上线不是成功。
- 不做什么少于 3 条 → 说明范围没想清楚。

## 反模式

- 把立案卡写成需求文档（那是 S3 的事）
- 用行业平均值代替自家基线
- 用户答不出就自己编一个基线继续跑（这是最危险的一种"帮忙"）
