# 头像显示成汉字：原因与排查

现象：专家导入到新的 WorkBuddy 后，列表/详情里本该显示图片的位置，变成一个汉字（例如「财」「税」）。

结论先说：**不是头像图片坏了，是打包时图片没被装进 zip，或者清单里的路径与 zip 内的实际条目对不上。** 平台读不到图片，就退回到用名称的第一个字占位。

---

## 一、平台是怎么处理的

从应用安装包中可读到的两段逻辑（压缩变量名已还原含义）：

**第一段，导入时解析头像**（`resolveAvatarFromExpertZip`）：

```
输入：zip 对象、清单所在目录前缀 prefix、清单里的 avatar 字段值

1. 若 avatar 是 http(s): 或 data: 开头 → 原样返回
2. 去掉开头的 "./" 和 "/"
3. 依次尝试查找 zip 条目： `${prefix}/${avatar}`，再 `avatar`
4. 找到 → 读取字节，转成 `data:image/png;base64,...` 返回
5. 找不到 → 原样返回那个相对路径字符串（注意：不是返回空）
```

**第二段，渲染**（`ExpertDetailAvatar`）：

```
fallback 显示条件：解析结果为空，或 img 加载失败（onError）
fallback 的内容：expertName.charAt(0)   ← 名称的第一个字符
```

两段连起来就是现象的全部解释：第 5 步返回了一个 `avatars/expert.png` 这样的字符串当 `src`，浏览器当然加载不出来，`onError` 触发，于是显示了名称首字。**所以你看到的那个汉字，本身就是"图片没找到"的错误提示。**

---

## 二、四种成因，按出现频率排序

### 1. 打包时把图片漏了（最常见）

用不同工具打包时，排除规则不一样。常见漏法：

- 只压缩了 `.md` 和 `.json`；
- 用 `zip -r ... -x "*.png"` 之类误排；
- 手动拖动时只拖了 `agents`、`skills`、`.codebuddy-plugin` 三个目录，忘了 `avatars`。

**验证**：

```bash
unzip -l your-package.zip | grep -i avatar
```

没有任何输出，就是漏了。

### 2. zip 里套了两层同名目录

正确结构只有一层包名目录：

```
czl-taxops-advisor/                 ← 只有这一层
├─ .codebuddy-plugin/plugin.json
└─ avatars/avatar-512.png
```

错误结构（先解压再压一次容易出现）：

```
czl-taxops-advisor/
└─ czl-taxops-advisor/             ← 多了一层
   ├─ .codebuddy-plugin/plugin.json
   └─ avatars/avatar-512.png
```

平台的 prefix 是从 `*/plugin.json` 反推出来的，会指向**内层**目录，于是去找 `czl-taxops-advisor/avatars/...`（内层路径），而文件实际在外层，找不到。

**验证**：上面那条 `unzip -l` 命令，看路径是不是以两层包名开头。

### 3. 文件名大小写不一致

清单写 `avatars/Avatar-512.png`，实际文件是 `avatars/avatar-512.png`。

Windows 本地不区分大小写，目录里看着没问题；但 zip 条目名是**字符串精确匹配**，差一个字母就找不到。这是"本机正常、换台机器就变字"最典型的原因。

**验证**：逐字符比对清单里的字符串和 zip 条目名。

### 4. 路径写法不规范

- 用了反斜杠：`"avatar": "avatars\\avatar-512.png"` —— 解析只处理 `/`，反斜杠无法匹配任何 zip 条目；
- 用了绝对路径：`"avatar": "C:/xxx/avatar.png"`；
- 改了图片文件名但忘了同步清单（改名后剩下的旧引用）。

---

## 三、本包怎么规避的

`czl-taxops-advisor` 在打包前会跑一遍结构自检，专门针对上面四类问题：

| 检查项 | 对应成因 |
| --- | --- |
| C2 头像文件按声明路径存在（大小写敏感） | 2、3、4 |
| C7 头像目录只有一个文件（避免引用歧义） | 4 |
| C4 头像是正方形、C6 小于 1MB | 图片本身不合规 |
| 包内校验：模拟平台解析规则定位头像条目 | 1、2 |

另外三个设计选择：

- **路径用正斜杠、相对路径、不带 `./`**：`"avatar": "avatars/avatar-512.png"`。
- **文件名全小写、无空格、无中文**：`avatar-512.png`。
- **`avatars/` 目录下只放一张图**：防止打包时选错文件。

自检命令（在包目录外执行）：

```bash
python czl-taxops-advisor/dev/validate_package.py czl-taxops-advisor
python czl-taxops-advisor/dev/build_package.py czl-taxops-advisor dist
```

第二条会重新读一遍 zip，按平台规则把头像解析一次，输出 `头像可按平台规则解析 avatars/avatar-512.png → czl-taxops-advisor/avatars/avatar-512.png` 才算通过。

## 四、导入后仍显示汉字，按这四步查

1. **看 zip 里有没有图**：`unzip -l 包.zip | grep -i avatar`。没有 → 重新打包。
2. **看路径层级**：条目应该是 `包名/avatars/xxx.png`，只有一层包名。
3. **看大小写**：清单字符串与条目名逐字符一致。
4. **看清单字段**：必须是 `avatar`，值用 `/` 分隔的相对路径。

四步都对还是显示文字，可能是平台缓存了旧的专家卡片信息：移除该专家后重新导入，或重启客户端再看。

---

## 五、顺带说明：为什么不用别的格式

- 平台支持 `.png` `.jpg` `.webp` `.gif` `.svg`。
- 头像会被压到很小尺寸显示（详情页约 48px 逻辑像素），矢量理论上更清晰，但 svg 在部分渲染环境下有兼容差异。
- 512×512 的 png 在 48px 下足够清晰，兼容性最好，故选它。
