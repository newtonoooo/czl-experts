# 交付标准

## 一、先选形态，再动笔

| 内容体量 | 形态 | 判断依据 |
|---|---|---|
| 单一指标、快速判断 | 对话直答 | 不需要留存 |
| 结构化分析、跟踪记录、简报 | Markdown | 需要被引用但不需排版 |
| 对外或对上交付的研究 | 自包含 HTML | 需要给别人看，双击能开 |
| 需要走审批、盖章、存档 | DOCX | 流程要求 |
| 财务模型 | XLSX | 一切涉及计算的交付 |

**不许用截图代替模型，不许用 Markdown 冒充正式报告**（用户明确要求 Markdown 除外）。

### HTML 交付要求

- CSS 内联，无外部依赖，离线可开
- 响应式，手机能读
- 含 `@media print` 样式
- 数字右对齐，表格有表头底色

### DOCX 交付要求

- 正文宋体、标题黑体（中文）；英文用 Times New Roman
- 页眉含报告名，页脚含页码与数据截止日
- 目录可跳转，超链接可点

## 二、交付物通用骨架

```
1  结论页     方向 / 目标价区间 / 当前价 / 隐含空间 / 一句话逻辑
2  依据       三到五条，每条带数字
3  正文       按模块展开，先结论后论证
4  风险       上行 / 下行 / 假设风险，三类分开
5  推翻条件   与复核时点
6  附录       数据表 / 来源清单
7  声明       免责 + 数据截止日
```

**第一页必须能在 30 秒内读懂。** 读不懂说明结构错了，不是读者水平问题。

## 三、数字与表格规范

| 项目 | 规范 |
|---|---|
| 小数位 | 全文统一，一般 1–2 位 |
| 货币 | 必标单位；跨币种须写汇率与换算日期 |
| 百分比 | 标明基期（同比 / 环比 / 占收入比） |
| 涨跌配色 | 上涨用红，下跌用绿 |
| 大数 | 统一用「亿」「万」，不混用 |
| 空值 | 写 `[MISSING]`，不留空、不写 0、不写"—"了事 |

## 四、密度规则（反注水）

- 一段话删掉形容词后若不剩信息，整段删除
- 同一结论不得在三个章节重复表述
- 禁止"综上所述""总的来说"后接前文复述
- 长报告中每 200–300 字应有一处图表或表格支撑
- 篇幅不足时**增加有信息量的维度**（如单位经济、分部拆解、竞争对照），不增加字数

## 五、语言规范

- 中文正文用简体中文，术语保留英文原词（DCF、EBITDA、EV/EBITDA）
- 不用"我们认为该公司具备较强的竞争优势"这类空句
- 判断句必须带依据：「毛利率 38%，高于同业中位数 6 个百分点」
- 避免绝对化表述：不用"必然""一定""毫无疑问"

## 六、交付前检查

- [ ] 形态与场景匹配
- [ ] 结论页 30 秒可读
- [ ] 六件套齐全（方向/区间/置信/推翻/复核/截止）
- [ ] 每个关键数字有来源与日期
- [ ] 风险分三类，非免责套话
- [ ] 表格精度、单位、基期、配色统一
- [ ] 无注水段落
- [ ] 免责声明与数据截止日已附

任何一项未过，不得交付。
