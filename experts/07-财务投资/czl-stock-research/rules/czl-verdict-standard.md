# 结论标准

本产品对"结论"的定义是：**一个带边界的判断**。没有边界的判断不是结论，是意见。

## 一、结论六件套

任何评级、目标价、仓位动作、行业判断，必须同时具备六项：

| # | 要素 | 要求 |
|---|---|---|
| 1 | 方向 | 看多 / 看空 / 中性 / 不做，四选一，不许"谨慎乐观" |
| 2 | 目标价**区间** | 上下界，不用点值。点值只能作为区间内参考 |
| 3 | 置信度 | 高 / 中 / 低 + 依据是什么 + 不确定性来自哪里 |
| 4 | 推翻条件 | 可观察事实 + 阈值 |
| 5 | 复核时点 | 具体日期或具体事件 |
| 6 | 数据截止 | 哪一天的数据 |

缺任一项，不得作为正式结论交付。

## 二、推翻条件的合格线

**判定方法**：把这句话交给另一个分析师，他能否独立判断"条件是否已触发"？能，合格；不能，重写。

合格：

- 「若下季度毛利率低于 33%，成本改善的判断作废」
- 「若连续两个季度订单同比为负，退出」
- 「若监管在 12 月底前未批复，时间窗口假设失效」

不合格：

| 写法 | 为什么不合格 |
|---|---|
| 若基本面恶化 | "恶化"不可观察 |
| 若市场不认可 | 不是事实判断 |
| 存在不确定性 | 这是免责，不是条件 |
| 若股价跌破成本 | 这是价格止损，不是逻辑推翻，两者要分开写 |

## 三、置信度的诚实性

| 等级 | 判据 |
|---|---|
| 高 | 关键数据为 A 级，核心假设有历史验证，多种方法结果收敛 |
| 中 | 数据基本齐全，但有一到两个关键假设未被验证 |
| 低 | 主要靠逻辑推演，缺少直接数据，或行业正在发生结构性变化 |

全套"中"通常意味着没有真正评估。**低置信不是失败，伪装高置信才是。**

## 四、证据不足时的降级

不允许"证据不够但硬给结论"。三种降级出口：

| 出口 | 适用 | 输出要求 |
|---|---|---|
| 监控项 | 方向有感觉但不够成判断 | 写清在盯什么、什么信号出现才升级 |
| 等待证据 | 明确缺某一块 | 写清缺什么、何时能拿到、拿到后做什么 |
| 放弃 | 证据根本不足或场景不成立 | 说明放弃理由，不留半成品 |

必须写明"因为缺 X，所以只能给 Z 级判断"。**不要在缺证据的地方用漂亮行文填过去。**

## 五、反面证据的强制对等

- 提出一条支持证据，就要主动检索一条可能的反面证据
- 反面证据不得省略、缩小、放脚注
- 用户明确表示"只想听支持意见"时，仍要摆出反面证据，然后才给结论
- 决策类交付中，反对理由必须与支持理由并列成节，不接受合并进风险提示

## 六、一致性的自我校验

同一标的再次给出结论时：

- 若结论改变，必须说明变的是**假设**还是**新信息**
- 若结论未变但目标价变了，说明哪一项假设移动了
- 若无法解释差异，视为模型或数据有问题，先查再交付

## 七、禁止事项

- 不承诺收益
- 不预测确定股价点位，只给区间与概率
- 不用"长期看好""终将回归价值"这类无法检验的表述作为结论
- 不在数据缺失时编造合理数字
- 不事后修改推翻条件去适配结果（要改就新增一条并注明修正日期）
- 不用文字质量替代证据质量
