# 仓位计划

观点是免费的，仓位是有代价的。这个模块只干一件事：**把"看好"翻译成一个不会让你出局的数字**。

## 职责

**做**：仓位推导、退出规则、对冲评估、监控清单。
**不做**：不重新论证观点（引用 `czl-decision-memo` 或 `czl-model-value` 的结论），不做组合整体体检（`czl-portfolio-check`）。

## 输入参数

| 参数 | 必填 | 说明 | 缺失处理 |
|---|---|---|---|
| 方向与目标价 | 是 | 来自上游结论 | 缺则先完成上游 |
| 组合总规模 | **仓位百分比必需** | 决定绝对金额 | 缺 → 只给公式与档位，不给百分比 |
| 单笔风险预算 | **仓位百分比必需** | 如"单笔最大亏损不超过组合 2%" | 缺 → 给 1% / 2% 两档对比 |
| 现有持仓与成本 | 加减仓必需 | 判断边际变化 | 缺 → 先索取，**不得代填** |
| 个股波动率或预期最大回撤 | 是 | 换算股数 | 缺 → 用历史最大回撤替代并标注 |
| 日均成交额 | 建议 | 判断能否退出 | 缺 → 提示流动性未评估 |
| 相关敞口 | 建议 | 避免隐性集中 | 缺 → 提示未做相关性调整 |

## 依赖与关系

- **上游**：`czl-decision-memo`（观点与目标价）、`czl-model-value`（估值区间）
- **下游**：`czl-thesis-log`（记录执行与后续复盘）、`czl-portfolio-check`（汇总敞口）
- **横向**：结论标准见 `czl-verdict-standard.md`

## 执行步骤

### 第一道：先定这笔最多亏多少

不要先想买多少，先想**错了亏多少还能接受**。

```
可承受亏损金额 = 组合规模 × 单笔风险预算
```

这一步定了，后面所有数字都是它的函数。

### 第二道：换算成仓位上限

```
仓位金额 = 可承受亏损金额 ÷ 预期最大跌幅
仓位比例 = 仓位金额 ÷ 组合规模
```

**关键在"预期最大跌幅"取哪个数**。三种取法，越保守越要靠前：

| 取法 | 含义 | 适用 |
|---|---|---|
| 止损位到入场价的距离 | 你打算在哪认错 | 有明确技术位或估值底时首选 |
| 历史最大回撤 | 这只股票真跌过多少 | 无明确止损位时 |
| 压力情景跌幅 | 极端情况下会跌多少 | 高杠杆、高波动标的 |

### 第三道：三把尺子往下砍

上面算出的是**理论上限**，还要被三把尺子砍：

| 尺子 | 判断 | 砍法 |
|---|---|---|
| 流动性 | 全部退出需要几个交易日 | 超过 10 个交易日 → 仓位压到"日均成交额 × 参与率 × 可接受天数" |
| 集中度 | 单票占总仓位多少 | 超过预设上限（常见 10–15%）→ 硬压到上限 |
| 相关性 | 与已有持仓是否同因子 | 同行业/同风格敞口合计超限 → 合并计算后再压 |

**最终仓位 = 三道闸里最窄的那个。** 必须写出是哪一道卡住了，那是你后续要盯的地方。

### 第四道：定退出规则

三条线，建仓前就写死：

| 类型 | 触发 | 动作 |
|---|---|---|
| 逻辑止损 | 推翻条件成立 | 3 个交易日内清仓，不看价格 |
| 价格止损 | 跌破预定位置 | 减到剩余仓位或清仓 |
| 时间止损 | 超过 X 个月逻辑未兑现 | 减半或退出，释放机会成本 |

再加两条纪律线：达到目标区间上沿分批减、催化剂落地后重估。

### 第五道：对冲要不要做

先问"要对冲什么"：市场 Beta、行业因子、事件尾部、汇率。四种工具：指数期货、行业 ETF 做空、期权保护、配对做空。

判断标准：**对冲年化成本 > 缩小同等风险所需放弃的预期收益**，就不对冲，直接压仓位。多数情况下"小仓位裸持"优于"大仓位加昂贵对冲"，若结论相反要给出定量理由。

还要算对冲自身带来的风险：基差、保证金、展期成本、流动性。

### 第六道：监控清单

写成"如果 X 则 Y"的规则表，不要写成注意事项。

| 触发 | 动作 | 优先级 |
|---|---|---|
| 跌破止损位 | 减至 X% 或清 | 强制 |
| 推翻条件成立 | 清仓 | 强制 |
| 达到目标区间上沿 | 减至 X% | 纪律 |
| 波动率骤升 | 复检仓位 | 审视 |
| 流动性恶化 | 提前退出 | 审视 |

## 判断条件

| 判据 | 处置 |
|---|---|
| 组合数据不全 | 只给推导公式 + 待填项，**不给百分比** |
| 流动性退出需 > 10 个交易日 | 仓位由流动性决定，不由信心决定 |
| 相关性无法测算 | 明示"未做相关性调整"，建议按同行业合计口径人工折算 |
| 空头标的无法融券 | 直接写"不可执行"，观点再对也不构成机会 |
| 用户要求满仓单票 | 算出最差情景损失给用户看，决定权归用户，风险必须写明 |

## 输出格式

```
一、结论       建议仓位 X%（或"待定 + 需要的输入项"）| 最窄的那道闸是 [什么]
二、推导      风险预算 → 可承受亏损 → 仓位金额 → 三道闸逐层结果
三、入场      方式（一次/分批）+ 价格区间
四、退出      逻辑止损 / 价格止损 / 时间止损，三条都写
五、对冲      做不做、为什么、成本与净敞口（若做）
六、监控表    如果 X 则 Y
七、风险提示  最差情景下的损失额
```

## 异常处理

- **波动率数据缺失**：改用历史最大回撤；仍无则给"按 1%/2% 风险预算的两档示例"并标注为示例不是建议。
- **组合规模已知但持仓结构未知**：给单票上限，提示集中度未做合并计算。
- **加仓请求但无成本价**：无法判断边际风险，先索取；拿不到则不给定加仓量。
- **用户不接受推导结果**：把"若按你的想法执行，最差情景亏多少"算出来给用户，不争论。

## 质量红线

- 没有组合数据就给百分比，视为编造
- 不给退出规则的仓位建议，视为未完成
- 止损是纪律不是预测——不许论证"会不会跌到止损位"
- 正常时期的流动性不等于压力时期的流动性
