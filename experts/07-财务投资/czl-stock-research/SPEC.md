## 1. 需求来源与推导方式

本产品面向"股票研究与定价"这一通用业务场景独立开发。功能范围由下述需求分析推导，不取自任何现有专家包的实现文件。

推导路径：

```
使用场景 → 用户要做的决定 → 决定所需的判断 → 判断所需的输入与步骤 → 工作流划分
```

即：先定"用户要下什么决定"，再定"支撑这个决定最少需要什么"，最后才切分模块。模块边界由**决定类型**决定，而非由资料类型决定。

## 2. 目标用户

| 用户类型 | 典型处境 | 最需要的东西 |
|---|---|---|
| 买方研究员 | 覆盖 20–40 只股票，被要求给组合经理明确建议 | 能站得住的评级与目标价，以及"错了怎么办" |
| 卖方研究岗 | 要出深度报告、路演材料、晨会观点 | 成体系的报告结构 + 可追溯的数据 |
| 私募/家族办公室投资经理 | 自己看案子，无人复核 | 一套防自我欺骗的检查流程 |
| 投研支持/风控岗 | 要评估别人递上来的研究是否可靠 | 快速识别论证漏洞的方法 |
| 个人投资者（进阶） | 有财务基础，缺流程 | 从想法到仓位的完整链条 |

**不面向**：需要实时行情下单执行、需要投顾牌照业务、寻求确定性涨跌预测的用户。

## 3. 使用场景与要解决的核心问题

### 场景清单

1. 第一次接触一家公司，要在 10 分钟内判断是否值得投入时间。
2. 需要给一家公司定价，给出评级和目标价。
3. 公司发了财报，要判断这次业绩改变了什么。
4. 要写一份能对外/对上交付的深度报告。
5. 要在若干标的之间排序，决定先研究谁。
6. 要理解一个行业，判断哪一环节赚钱。
7. 面临一个可预见的事件（审批、并购、议息），要评估影响。
8. 已经看好了，要决定买多少、什么时候加、什么时候认错。
9. 手里有多个持仓，要体检风险敞口。
10. 要定期复盘"当初的逻辑还成立吗"。
11. 要把研究整理成能过会的决策材料。

### 核心问题（按痛点强度排序）

- **P1｜结论不可检验**：报告写得很长，但没有一句能判断对错。三年后回看，无法知道自己当时错在哪。
- **P2｜估值是黑箱**：给了一个目标价，但假设藏在模型里，别人无法质问，自己换一天也算不出同一个数。
- **P3｜证据与观点混淆**：把券商研报的转述当事实，把管理层说法当数据，把期望当预测。
- **P4｜仓位与观点脱节**：看好就满仓，没有风险预算概念，一个错误判断毁掉半年收益。
- **P5｜没有记忆**：每次都从零开始，同一只股票一年内被推翻三次却无人记录。
- **P6｜输出形态不对**：给基金经理的应该是三句话结论，却递了 40 页 PDF。

## 4. 功能需求

### 4.1 必须具备（P0）

| 编号 | 功能 | 验收标准 |
|---|---|---|
| F1 | 公司快速画像 | 输出一页纸，含商业模式、收入结构、单位经济、竞争位势、数据报告期 |
| F2 | 三法估值 | 至少两种方法交叉，给出目标价**区间**而非点值，附关键假设表 |
| F3 | 财务建模 | 三表联动闭合，可做敏感性矩阵，说明终值占比 |
| F4 | 财报事件解读 | 区分"质量型超预期"与"账面型"，给出估计修正与新目标价 |
| F5 | 研究报告撰写 | 结构完整、数据可溯、含图表要求与交付前质量闸口 |
| F6 | 仓位与风险方案 | 由约束反推仓位，含退出规则；缺组合数据时只给框架 |
| F7 | 论点记录与复盘 | 支柱式记分卡 + 反面证据栏，可跨会话复用 |
| F8 | 事件情景评估 | 概率分布 + 双变量敏感性 + 反推当前价格隐含假设 |
| F9 | 行业结构分析 | 落到"利润池在哪一环"与"这个行业只交易哪一两个变量" |
| F10 | 决策备忘 | 平衡呈现多空，允许结论是"不做" |

### 4.2 应当具备（P1）

| 编号 | 功能 | 说明 |
|---|---|---|
| F11 | 标的筛选 | 把条件翻译为可复核阈值，输出带"下一步验证动作"的候选表 |
| F12 | 组合体检 | 敞口归集、相关性提示、集中度告警 |
| F13 | 跟踪简报 | 一页纸，有观点，带时间戳 |
| F14 | 证据分级 | 对来源分 A/B/C 级，C 级必须经 A 级核对才进结论 |

### 4.3 明确不做（Out of Scope）

- 实时行情推送与自动交易执行
- 保证收益、预测确定点位
- 处理内幕信息或未公开重大信息
- 替代持牌投顾的法定义务

## 5. 输入与输出规范

### 5.1 必要输入

| 输入 | 必填性 | 缺省策略 |
|---|---|---|
| 标的（名称/代码）或行业口径 | 必需 | 缺失则先问，不猜 |
| 市场（A股/港股/美股/其他） | 强烈建议 | 由上下文推断，并在输出中声明所用口径 |
| 交付形态（对话/文档/模型/报告） | 可选 | 按内容体量自动选择，并在开头说明 |
| 组合规模、现有持仓、成本、风险预算 | 仅仓位类任务必需 | 缺失时**只给推导框架，不给百分比** |

### 5.2 输出形态判定

| 内容体量 | 形态 |
|---|---|
| 单一指标、快速判断 | 对话直答，不落文件 |
| 结构化分析、跟踪记录 | Markdown |
| 对外/对上交付的研究 | 自包含 HTML 或 DOCX |
| 财务模型 | XLSX |

### 5.3 每条结论必须携带的字段

1. 方向（看多 / 看空 / 中性 / 不做）
2. 目标价**区间**与当前价对比
3. 置信度（高/中/低）及依据强度
4. **推翻条件**（什么可观察事实出现即判定为错）
5. 复核时点
6. 数据截止日 + 免责声明

## 6. 通用处理步骤（跨场景的稳定方法）

无论哪个场景，处理都遵循同一骨架，这是产品的方法内核：

```
第 1 步 定义问题      —— 用户要下的到底是哪个决定？
第 2 步 盘点已知      —— 现有证据是什么等级？缺哪一块？
第 3 步 写出可检验假设 —— 一句话，含可观察的判断
第 4 步 量化          —— 假设落到数字上：收入、利润率、倍数、折现率
第 5 步 定价          —— 至少两种方法，给区间
第 6 步 定推翻条件     —— 写在结论前面
第 7 步 落动作        —— 评级、仓位、时点、退出规则
第 8 步 留记录        —— 写进台账，供下次复盘
```

**判断条件（何时中止）**：第 3 步写不出可检验假设 → 中止并降级为"观察"；第 4 步关键数据缺失且无法替代 → 只给方向性判断，不给目标价。

## 7. 所需工具能力

| 能力 | 用途 | 不可用时的降级 |
|---|---|---|
| 联网检索 | 取财报、公告、行情、共识 | 只用用户提供的数据，标 `[MISSING]` |
| 金融数据连接器 | 结构化行情与财务 | 降到公开检索；再不行则声明缺口 |
| 文档生成（DOCX/XLSX） | 报告与模型交付 | 降级 Markdown + 表格，并说明未生成正式文档 |
| 图表绘制 | 报告配图 | 交付数据表 + 绘图脚本，**不以文字描述冒充图表** |
| 文件读写 | 台账持久化 | 在对话内维护，提示用户自行存档 |

## 8. 质量、速度与稳定性要求

| 维度 | 要求 |
|---|---|
| 可追溯性 | 每个数字带来源与日期；三类标注 `[MISSING]` `[STALE]` `[假设]` 必须使用 |
| 可检验性 | 所有结论附推翻条件，且该条件能被第三方独立判定 |
| 一致性 | 同一标的两次估值，若结论不同，必须解释差异来源 |
| 响应速度 | 单点问答 ≤ 1 轮交互给结论；深度报告按阶段交付，每阶段结束报进展 |
| 稳定性 | 前置不满足时**明确中止并说明缺什么**，不用占位内容续写 |
| 诚实性 | 未执行的检查不得声称通过；缺证据时降低结论等级 |

## 9. 模块划分（作业台架构）

模块边界按**研究对象的作用范围**划分，而非按研究流程的时间顺序。理由是：用户从来不是按流程提问的，而是按"对象"提问的（这家公司 / 我的组合 / 这个事件 / 这个行业）。

| 作业台 | 模块 | 承接的功能 |
|---|---|---|
| 单票 | `czl-company-map` 公司画像 | F1 |
| 单票 | `czl-model-value` 建模与定价 | F2 F3 |
| 单票 | `czl-earnings-read` 财报解读 | F4 |
| 单票 | `czl-report-build` 报告构建 | F5 |
| 组合 | `czl-position-plan` 仓位计划 | F6 |
| 组合 | `czl-portfolio-check` 组合体检 | F12 |
| 事件 | `czl-event-scenario` 事件情景 | F8 |
| 行业 | `czl-sector-scan` 行业扫描 | F9 F11 |
| 横向 | `czl-thesis-log` 论点台账 | F7 F13 |
| 横向 | `czl-decision-memo` 决策备忘 | F10 |

横向模块不属任何单一作业台，任何作业台的结论都要流入台账与备忘。

## 10. 验收测试设计

| 用例 | 输入 | 期望行为 |
|---|---|---|
| T1 正常单票 | "看一下某某公司" | 触发 `czl-company-map`，输出一页纸并声明报告期 |
| T2 缺数据定价 | 只给公司名，无财务数据 | 先索取财报；拿不到则只给方法不给目标价，标 `[MISSING]` |
| T3 仓位但无组合数据 | "这家我该买多少" | 给约束推导框架与待填项，**不给百分比** |
| T4 结论审查 | 递上一份现成观点 | 逐条指出哪句不可检验，补出推翻条件 |
| T5 越界请求 | 要求预测明天涨跌 | 拒绝给点位，改为给区间与概率 |
| T6 内幕信息 | 涉及未公开重大信息 | 明确拒绝并说明原因 |
| T7 前置不足的深度报告 | 只有公司名要 40 页报告 | 说明数据不足，建议缩短或先补数据，不凑页数 |

## 11. 与原目标专家的关系说明

- 本产品的**功能范围**与市面上的股票研究类专家存在重叠，这是同一业务场景的必然结果，不构成对特定作品的复制。
- 本产品的模块划分、提示词、输出模板、目录结构、文档、头像均为本次独立编写/生成。
- 所使用的 DCF、可比估值、仓位约束等属于公开的行业通用方法与财务常识，不属可受保护的独创表达。
