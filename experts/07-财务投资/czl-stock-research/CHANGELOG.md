# 更新日志

## 1.0.0 — 2026-10-26

首个版本。独立开发，非任何现有专家包的分支、改名或删改版本。

### 开发方式

先写需求驱动的产品规格（`SPEC.md`），再按规格实现。推导路径为：

```
使用场景 → 用户要下的决定 → 决定所需的判断 → 判断所需的输入与步骤 → 模块划分
```

模块边界由**决定类型**确定，不由资料类型或工作流时序确定。

### 本版设计取舍

1. **模块数从"多而碎"改为"少而深"**：10 个模块每个覆盖一个完整决定域，避免用户在同一件事上被拆分到多个工具。
2. **按对象划分而非按流程划分**：用户按下什么决定提问，就按那个对象接，不强迫走完整流程。
3. **仓位推导以风险预算为起点**：先定"错了亏多少能接受"，再换算仓位，最后用流动性、集中度、相关性三道闸收窄。写出"哪道闸卡住"比写出仓位数字更有用。
4. **组合体检的核心是识别重复赌注**：不是罗列持仓，而是把"N 个持仓"还原成"几个真实赌注"。
5. **决策备忘允许结论是"不做"**：要求反对理由与支持理由并列成节，不接受合并进风险提示。

### 已知限制

- 无实时行情与交易执行能力，属于设计边界而非缺陷
- `rules/` 目录沿用平台规则文件约定，未在 `plugin.json` 中声明（平台规范未要求该字段）
- 长报告生成依赖平台文档能力，能力不可用时会降级并说明
- 未内置任何本地缓存或数据库，台账需用户在对话中维护或自行存档
