# 持仓体检与观点台账

两个功能，一个目的：**让判断有账可查。** 没有台账的投资者，永远在同一只股票上犯同一个错，且不记得。

## 职责

**做**：敞口分析、相关性识别、事件撞车检测、流动性评估；观点落账、到期复核、对错记分。
**不做**：不给买卖建议、不计算最优仓位（只给风险暴露事实）、不做个股诊断（调 `ar-autopsy`）。

## 输入参数

### 体检模式

| 参数 | 必填 | 说明 | 缺失处理 |
|---|---|---|---|
| 持仓列表 | 是 | 代码 + 数量（+成本价可选） | 缺代码无法做 |
| 成本价 | 否 | 有则算盈亏 | 无则只算敞口与集中度 |
| 总资产 | 否 | 有则算仓位比例 | 无则只算相对占比 |
| 关注维度 | 否 | 集中度/相关性/事件/流动性 | 默认全查 |

### 台账模式

| 参数 | 必填 | 说明 |
|---|---|---|
| 标的与判断 | 是 | 看好/看空/中性 + 理由 |
| 证伪条件 | 是 | 什么情况下这个判断算错 |
| 复核日期 | 是 | 具体日期，不写"以后" |

## 一、体检五查

### 1. 集中度

- 单一标的占比、前三大合计占比
- 单一级行业占比（按申万一级归类，**同一行业不同股票不算分散**）
- 单一风格暴露：大盘/小盘、价值/成长、周期/防御

判据：单票 >30% 或单行业 >50% → 明确提示集中风险。这是事实陈述，不是建议。

### 2. 相关性

不看行业名，看**驱动因子**：是不是同一个上游、同一个下游、同一套政策、同一类资金。

典型伪分散：三只新能源股票（同一政策周期）、两只银行 + 一只保险（同一利率因子）、上下游各一只（同一景气度）。

输出一张两两相关性判断表（高/中/低 + 依据），有历史收益率序列时用实际相关系数。

### 3. 事件撞车

把所有持仓未来 6 个月的事件排到一条时间轴上：财报日、解禁日、股东大会、限售上市。

判据：同一周内有 3 个以上财报 → 提示"业绩期集中暴露"；两只股票同月大额解禁 → 提示流动性同时受压。

### 4. 流动性

- 各标的日均成交额
- 持仓市值占日均成交额比例（>10% 意味着退出需要多日）
- 是否含停牌、ST、退市整理期标的

### 5. 尾部暴露

找出组合里"最坏情况会同时发生"的那一组：高质押 + 高商誉 + 解禁临近 + 成交额小。这类标的单看都不致命，凑在一起是尾部风险。

## 二、台账机制

### 记账格式

每条判断一行，写入 `data/ar-thesis-log.json`：

```json
{
  "id": "T20261029-600519",
  "code": "600519.SH",
  "date": "2026-10-29",
  "view": "中长期看好",
  "thesis": "一句话核心逻辑",
  "key_evidence": ["证据1[事实]", "证据2[推算]"],
  "falsify_if": ["若批价连续两季下滑", "若预收款同比转负"],
  "confidence": "中",
  "review_date": "2027-01-31",
  "price_at_call": 1500.00,
  "status": "open"
}
```

### 复核流程

到复核日或被证伪条件触发时：

1. 读台账原条目，**先不看当前价格**，只看证伪条件是否发生
2. 发生 → 判"错"，记录错在哪一环（证据错/推理错/运气）
3. 未发生且逻辑仍成立 → 判"暂对"，更新证据
4. 未发生但逻辑已变 → 判"需改"，重写 thesis

### 记分口径

只记三档：**对 / 错 / 未了结**。不记"部分对"——那是最容易自欺的一档。

统计口径：胜率 = 对 ÷（对 + 错），未了结不计入。样本 <10 条不出胜率。

## 输出

### 体检

```markdown
## 组合画像
标的数 {}｜前三大占比 {}%｜最大行业 {} 占 {}%

## 集中度
| 标的 | 占比 | 行业 | 风格 | 日均成交额 |

## 相关性
| 组合 | 相关性 | 共同驱动 |

## 事件时间轴
| 日期 | 标的 | 事件 | 影响 |

## 尾部暴露
{一组可能同时恶化的标的，说明为什么它们会一起坏}
```

### 台账复核

```markdown
## 复核：{标的}（{原判断日期}）
原判断：{}　置信度：{}
证伪条件：{}
现状：{} 已发生 / 未发生
判定：对 / 错 / 需改
错在哪：证据 / 推理 / 运气
```

## 判断条件

| 情形 | 动作 |
|---|---|
| 只给代码不给数量 | 只做相关性与事件分析，不做集中度 |
| 持仓含港股/美股 | 单独成段，注明汇率与交易规则差异，不混入 A 股统计 |
| 持仓含已退市/长期停牌 | 单列为"无法处置"，不参与占比计算但必须提示 |
| 用户要求"帮我决定减哪个" | 拒绝给指令，改为列出各标的的风险暴露与情景影响 |
| 台账为空 | 说明这是第一次记录，先建账再谈胜率 |

## 异常处理

- 数量与市值对不上（如填了股数但市值差 10 倍）→ 反问确认单位（股/手/万元）。
- 相关性样本不足（上市 <1 年）→ 用行业与驱动因子定性判断，标注"无足够历史序列"。
- 台账文件损坏 → 备份原文件，重建，不覆盖。

## 依赖

- `scripts/arposition.py`（集中度、相关性、事件轴计算）
- `data/ar-thesis-log.json`（台账，首次使用时创建）
- `rules/ar-market-rules.md`（解禁、减持、退市规则）
- `references/ledger-schema.md`（台账字段与判定口径）

## 与其他工作流的关系

- 上游：`ar-evidence`、`ar-intake`（回读台账，检查该标的是否有未了结判断）
- 下游：`ar-autopsy`（对风险最高的标的做深入诊断）
- 闭环：台账 → 下次 `ar-intake` 回读 → 复核 → 更新台账
