# 观点台账结构

台账是一个 JSON 文件，默认路径 `data/ar-thesis-log.json`。首次使用时创建，之后只追加与改状态，不删除旧条目——**被推翻的判断比正确的判断更有价值**。

## 文件结构

```json
{
  "version": 1,
  "updated_at": "2026-10-29",
  "entries": [
    {
      "id": "T20261029-600519",
      "code": "600519.SH",
      "name": "贵州茅台",
      "date": "2026-10-29",
      "view": "中性偏谨慎",
      "thesis": "增速换挡，当前估值隐含增长高于可实现水平",
      "key_evidence": [
        "前三季度营收 1234.5 亿元，同比 +9.8%[事实]",
        "预收款同比下降 12%[事实]"
      ],
      "falsify_if": [
        "三季报预收款同比转正",
        "飞天批价连续两季站稳 2200 元以上"
      ],
      "confidence": "中",
      "review_date": "2027-01-31",
      "price_at_call": 1349.47,
      "status": "open",
      "outcome": null,
      "closed_at": null,
      "note": ""
    }
  ]
}
```

## 字段约束

| 字段 | 必填 | 约束 |
|---|---|---|
| `id` | 是 | `T` + 日期 + `-` + 6 位代码，全局唯一 |
| `view` | 是 | 只能取：看好 / 中性偏乐观 / 中性 / 中性偏谨慎 / 看空 / 不值得看 |
| `thesis` | 是 | 一句话，不超过 40 字 |
| `key_evidence` | 是 | ≥2 条，每条带证据等级标记 |
| `falsify_if` | 是 | ≥1 条，必须可观察（价格/指标/事件/日期） |
| `review_date` | 是 | 具体日期，不写"以后" |
| `status` | 是 | `open` / `closed` |
| `outcome` | 关闭时必填 | 只能取 `对` / `错` / `未了结` |

## 三档判定，不用"部分对"

"部分对"是最容易自欺的一档：涨了说是逻辑兑现，跌了说是外部扰动。只留三档，强制做选择。

| 判定 | 定义 |
|---|---|
| 对 | 证伪条件未发生，且复核时逻辑仍成立，或价格朝判断方向移动且原因与 thesis 一致 |
| 错 | 任一证伪条件发生，不论价格涨跌 |
| 未了结 | 复核日已到但证伪条件未触发、逻辑也未验证（如事件推迟） |

## 胜率口径

```
胜率 = 对 ÷（对 + 错）
```

- 未了结核不算入分母。
- 样本 <10 条不出胜率，只列明细。
- 分维度统计更有用：按"看多/看空"分别算，按行业分别算。总体上"看多胜率高"往往只说明赶上了牛市。

## 复核流程（不可跳步）

1. 读原条目，**先只看 `falsify_if`**，逐条核对是否发生。
2. 未看当前价格先做判定，避免被结果倒推理由。
3. 判定后，再记录价格变化，用于事后区分"判断对"与"运气好"。
4. 更新 `status` / `outcome` / `closed_at`，写一句 `note` 说明错在哪一环（证据错 / 推理错 / 运气）。

## 与体检的联动

- `ar-intake` 收到某标的请求时，先查台账是否有 `open` 条目；有则提示"此前对该标的的判断是 X，复核日 Y"。
- `ar-position` 在体检时列出所有 `open` 条目的到期日，避免判断过期无人管。
