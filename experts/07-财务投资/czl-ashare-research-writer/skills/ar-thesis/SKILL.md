# 成稿与交付

研究和稿子之间隔着一道工序：**把判断链翻译成读者能跟着走的顺序。** 这道工序不做，前面所有工作都留在聊天框里。

## 职责

**做**：结构编排、语言加工、HTML+MD 双产出、图表内联、来源表生成。
**不做**：不产生新结论（结论来自 `ar-autopsy`/`ar-value`/`ar-tape`）、不做质检（交 `ar-quality`）。

## 输入参数

| 参数 | 必填 | 说明 | 缺失处理 |
|---|---|---|---|
| 上游结论 | 是 | 诊断/估值/复盘的结构化结果 | 无则回到对应工作流 |
| 证据台账 | 是 | `ar-evidence` 产出 | 无则不能写来源段 |
| 稿型 | 是 | 内部研究 / 对外发布 | 默认内部研究 |
| 篇幅 | 否 | 短（1200）/ 中（2500）/ 长（5000+） | 按稿型默认 |
| 署名与渠道 | 否 | 发布平台 | 对外稿必问 |

## 七段结构（顺序固定）

| 段 | 写什么 | 长度占比 | 判据 |
|---|---|---|---|
| 1 结论 | 判断 + 置信度 + 证伪条件 | 8% | 读完这段，读者已知答案 |
| 2 证据 | 支撑结论的关键事实，逐条带源 | 25% | 每条能追到出处 |
| 3 分歧 | 共识是什么、我不同意什么、为什么 | 15% | 有具体的对立面，不是稻草人 |
| 4 定价 | 方法、假设、区间、隐含预期 | 20% | 假设可被复算 |
| 5 情景 | 乐观/中性/悲观 + 触发条件 + 权重 | 15% | 三档触发条件都可观察 |
| 6 风险 | 会让结论失效的具体事件 | 10% | 不是"市场有风险" |
| 7 来源 | 数据源表 + 质量 + 时间 + 免责 | 7% | 完整可查 |

**为什么是这个顺序**：读者先判断"要不要信你"（结论），再判断"你说的对不对"（证据与分歧），最后才关心"那值多少钱"（定价）。倒过来写，读者读不到定价段就关了。

## 两种稿型的差异

| 维度 | 内部研究稿 | 对外发布稿 |
|---|---|---|
| 标题 | 直接写标的与判断 | 留悬念，不给结论 |
| 第一段 | 结论先行 | 一个具体场景或数字切入 |
| 术语 | 可用行业术语 | 术语首次出现须一句解释 |
| 数据密度 | 高，表格多 | 中，每段不超过 2 个数字 |
| 免责 | 文末固定文本 | 文首或文末均需，不可省 |
| 长度 | 2500-6000 字 | 1500-3000 字 |

## 语言纪律

写的时候逐句自查，触犯即改：

- 第一段必须有判断。没有判断的开头是拖延。
- 一句话一个意思。出现"并且""同时""此外"连缀三个分句，拆开。
- 删掉：综上所述、值得关注、或将迎来、有望、显著、大幅、强劲、赋能、闭环
- 不写"一方面…另一方面…"。有方向才有对错。
- 数字后面跟单位和口径：`营收 32.1 亿元（同比 +12.3%，前三季度）`
- 允许"我不知道"。不确定就明写不确定在哪，这比假装确定可信。
- 不用感叹号。不用"！"。不用 `**非常**` 强调。
- 一段不超过 5 行，手机屏幕上超过一屏的段落没人读。

## 成稿步骤

1. **定骨架**：把上游结论映射到七段，每段先写一句主旨句。
2. **填证据**：从台账里取数，每个数字标注来源编号 `[S1]`，末尾统一列表。
3. **写分歧**：找出最强的反方论点，用它的最强版本反驳，不用稻草人。
4. **算定价**：直接引 `ar-value` 的区间与假设表，不改数字。
5. **排情景**：三档触发条件必须可观察（价格、事件、日期），不写"如果市场转好"。
6. **写风险**：列 3-5 条具体事件与影响路径。
7. **生成文件**：调用渲染脚本。

```bash
python skills/ar-thesis/scripts/arreport.py \
  --input draft.json \
  --out 600519-diagnosis-20261029.html
```

`draft.json` 结构见 `skills/ar-thesis/references/draft-schema.md`。脚本会同时输出同名 `.md`。

## 输出

| 文件 | 内容 | 校验点 |
|---|---|---|
| `{code}-{type}-{date}.html` | 自包含 HTML，内联 CSS + SVG，含打印样式 | 断网可开、A4 打印不串版 |
| `{code}-{type}-{date}.md` | 同内容 Markdown，可复制进编辑器 | 标题层级正确、表格可渲染 |
| 对话摘要 | 3-5 句 + 一条最该警惕的事 | 不开文件也能用 |

## 判断条件

| 情形 | 动作 |
|---|---|
| 上游结论置信度为"低" | 只出情景段，不出定价段，明确写"证据不足，不定价" |
| 用户要求"写得乐观一点" | 拒绝调整事实与假设，只能调整语气；说明理由 |
| 用户要求删免责声明 | 拒绝，说明这是发布前提 |
| 对外稿涉及具体买卖 | 全部改为条件化表述 |
| 篇幅要求与内容量不匹配 | 内容不够就缩短，不注水；明确告知"按现有证据只能写到 X 字" |

## 异常处理

- 渲染脚本报错 → 检查 `draft.json` 字段完整性，缺字段报出具体键名，不生成半成品。
- 中文字体缺失 → HTML 使用系统字体栈（`-apple-system, "Microsoft YaHei", sans-serif`），不嵌外部字体。
- 数字与台账不一致 → 以台账为准，改稿，不不改台账。

## 依赖

- `scripts/arreport.py`：HTML/MD 渲染（CSS 与模板内置于脚本，无外部模板文件）
- `references/draft-schema.md`：输入数据结构
- `rules/ar-delivery-standard.md`：命名、结构、文风

## 与其他工作流的关系

- 上游：`ar-autopsy` / `ar-value` / `ar-tape`
- 下游：`ar-quality`（强制）
- 输出文件路径必须传给 `ar-quality` 做校验
