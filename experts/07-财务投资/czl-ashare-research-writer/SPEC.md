## 1. 这份规格是怎么推导出来的

推导路径只有一条，从下往上：

```
用户要交出去的东西 → 交出去之前必须想清楚的事 → 支撑判断所需的最小证据 → 证据怎么拿到 → 工作流怎么切
```

注意起点是「要交出去的东西」，不是「手上有什么数据」。这是本产品与既有同类工具最根本的分岔。

绝大多数股票分析工具的组织逻辑是：数据维度 → 分析模块 → 拼成报告。
它的组织逻辑是：**交付物形态 → 判断链条 → 证据 → 数据**。

所以工作流的切分依据是「一次判断的完整闭环」，而不是「一类数据的处理方式」。个股诊断、板块复盘、持仓体检之所以是三个独立流程，不是因为它们用不同的表，而是因为它们支撑三个不同的决定，且失败方式不同。

## 2. 参考对象的实测分析

开发前完整读取了本机 6 个 A股/投研方向专家包的全部文件（agent 提示词、skill、reference、脚本、清单）。下面是能力盘点与缺口判断，仅作需求推导依据，不作为实现来源。

| 参考对象 | 它真正解决的问题 | 实测短板 |
|---|---|---|
| 鹏城信息AI专家（A股交易分析） | 用公开行情接口（新浪/东财）拿到实时价，做情绪与短线方向判断 | 无 skill 文件、无历史数据、无回测、无质检；行情口径只有"当前"，没有"过去与分布"；预警写死成本地 md 文件，跨会话不可靠 |
| 星辰（多市场分析） | 15+ 策略库 + HTML 决策仪表盘 + 0-100 评分收敛规则 | 数据源清单（TickFlow/Tushare/AkShare）多数用户实际没有 key，等于纸面能力；HTML 模板只给色彩规范没给可运行文件；覆盖 6 个市场导致每个都不深 |
| 通达信诊断师（个股诊断） | 六模块诊断骨架（基本面/技术面/资金面/事件/同业/结论） | 强绑定通达信 MCP，未装即全部失效；六模块只有目录没有方法细则，实际靠模型自由发挥；无证据分级 |
| 通达信选股猎手（智能选股） | 自然语言 → 筛选条件的映射；5 维打分 | 同上强绑定 MCP；"模糊→精确"只有一句原则，没有映射词典；无筛选结果可复现机制 |
| 回测明算（策略回测） | 自然语言策略 → 可运行 Python 回测 + 指标 + 仪表盘 + 自检链 | 交付纪律最严，但只覆盖"验证过去"，不产出研究内容；依赖 westock CLI 与专有数据通道 |
| 严估深（股票研究） | 15 个卖方研究技能：首次覆盖、DCF、可比、多空推介、组合风险 | 体系最完整，但按美股/卖方范式写：A股的涨跌停、T+1、ST、停牌、北向口径、解禁、龙虎榜基本缺失；交付物偏英文投行格式，本土内容场景（公众号/内部过会）适配弱 |

### 汇总出的六个共性缺口

1. **能力与数据可得性错配**：宣称的能力依赖普通用户拿不到的数据通道；通道失效时整套流程没有降级路径。
2. **只有分析，没有成品**：输出是聊天里的段落，不是可直接交付、可直接发布、可打印的文件。
3. **A股本土规则缺位**：涨跌停、ST、停牌、T+1、除权、北向口径变化，这些直接决定结论对错，却普遍只在"注意事项"里提一句。
4. **证据不分级**：公司公告、管理层口径、券商转述、模型推算、自己判断混在一段话里，读者无法评估可信度。
5. **没有交付闸门**：写完就交，不检查数字是否可追溯、日期是否最新、评级与建议是否自相矛盾。
6. **没有记忆**：同一标的三个月内被推翻两次，没有任何台账记录当初为什么这么判断。

## 3. 目标用户

| 用户 | 真实处境 | 他缺的不是数据 |
|---|---|---|
| 财经内容创作者 / 公众号作者 | 每周要出 A股方向的稿子，既要有观点又不能踩合规红线 | 缺"把数据变成能发出去的稿"的流水线，以及一条不会出事的边界 |
| 券商/基金研究员（初、中级） | 要交个股深度、板块综述、晨会观点，被要求结论明确 | 缺可追溯的证据链和能过复核的结构，不缺 Wind 权限 |
| 私募/资管投资经理 | 自己看案子，没人复核，容易自我说服 | 缺一套防自欺的检查顺序 |
| 企业投关 / 战略岗 | 要判断同业与产业链，写内部材料 | 缺把公开信息组织成判断的方法，不缺搜索 |
| 有财务基础的个人投资者 | 看得懂报表，但结论常常前后矛盾 | 缺纪律，不缺信息 |

**明确不服务**：要下单执行、要投顾牌照业务、要"明天涨不涨"式确定性预测、要内幕信息的用户。

## 4. 使用场景（触发即工作）

1. 给我看一只票，我要知道它现在值不值得花时间看下去。
2. 我要写一篇关于某只股票/某个板块的稿子，得有数据、有观点、能发。
3. 出了财报/重大公告，我要判断这改变了什么。
4. 我要给这只票定个价，说清楚贵还是便宜，以及贵在哪。
5. 今天大盘这样，我要一份能直接用的复盘。
6. 我手里这几只，帮我看看风险是不是堆在一处。
7. 我三个月前看好它的理由，现在还算不算数。
8. 这份稿子/报告发出去之前，帮我挑错。

## 5. 要解决的问题（按痛感排序）

- **P1 结论不可检验**：通篇分析，没有一句能被后来的事实判定对错。
- **P2 证据混装**：公告数字、管理层说法、券商观点、自己推算写在同一段，读者无法分辨哪句能信。
- **P3 规则性错误**：拿涨跌停价当理论价、用 T+0 口径算收益、把停牌股当正常交易、北向数据用了已停更的口径。
- **P4 成品不可用**：结论在聊天框里，转成稿件要重写一遍，格式还得自己排。
- **P5 合规擦边**：脱口而出"可以买""目标价必到""稳赚"，一句话把内容号送走。
- **P6 判断无记忆**：说过的话没有落账，无法复盘自己错在哪。

## 6. 功能需求

### 6.1 必须做到（P0）

| 编号 | 需求 | 可验证标准 |
|---|---|---|
| F1 | 标的识别与任务分型 | 输入"茅台/600519/沪市股王"均能锁定 600519.SH；识别出用户要的是诊断/成稿/复盘/体检中的哪一种 |
| F2 | 取数可降级 | 主通道失败自动降级，至少 3 级；全失败时明确说"拿不到什么"，不编造 |
| F3 | 数据带源与时间 | 每个关键数字可追到来源与日期，缺失标 `[MISSING]` |
| F4 | A股规则校验 | 涨跌停价、ST 幅度、停牌、T+1、除权、代码归属六项机器可校验 |
| F5 | 个股六维诊断 | 基本面/技术面/资金面/事件/筹码/同业，每维必须有数字支撑 |
| F6 | 估值定锚 | 至少两种方法交叉，假设显式列出，给出隐含预期反推 |
| F7 | 内容成稿 | 产出可直接使用的 HTML（可打印）+ Markdown 双格式 |
| F8 | 交付质检 | 10 项机器+人工检查，未过闸不得交付 |
| F9 | 证据分级 | 六类标注：事实/披露/共识/推算/假设/判断 |
| F10 | 观点台账 | 每次判断落账，含证伪条件与复核日期 |

### 6.2 明确不做（划清边界，避免能力虚标）

- 不做分钟级/tick 级回测，不做期权、可转债定价。
- 不接券商交易接口，不代替用户下单。
- 不给"买入/卖出"操作指令，只给研究结论与条件化情景。
- 不做全市场多因子 IC 检验这类需要完整因子库的工作。

## 7. 输入规范

| 输入 | 必需 | 缺省处理 |
|---|---|---|
| 标的（代码/名称/简称） | 是（诊断、估值、成稿类） | 缺失时反问，一次只问一个最关键的问题 |
| 任务类型 | 否 | 由动词推断；推断置信度低时给两个选项让用户选 |
| 时间口径 | 否 | 默认最近交易日收盘；盘中任务标注"盘中快照" |
| 输出形态 | 否 | 默认 HTML + 对话摘要；用户说"发公众号"则切公众号稿模式 |
| 持仓（体检类） | 是 | 缺成本价时不计算盈亏，只算敞口 |

## 8. 输出规范

统一三层交付：

1. **对话层**：3-5 句结论 + 一个"这意味着什么" + 一条最该警惕的事。
2. **文件层**：`{代码}-{任务}-{YYYYMMDD}.html`（自包含、可打印）+ 同名 `.md`（可复制进编辑器）。
3. **证据层**：报告末尾来源表 + 数据质量标记 + 免责声明。

报告骨架固定为七段：结论 → 证据 → 分歧 → 定价 → 情景 → 风险 → 来源。顺序不可改，因为读者是按"先信不信、再对不对"的顺序读的。

## 9. 工作流架构

八个工作流，两条主线（研究线、内容线）共用一条证据底座。

```
                    ┌──────────────┐
                    │  ar-intake   │  受理与分型
                    └──────┬───────┘
                           │
                    ┌──────▼───────┐
                    │ ar-evidence  │  取数与证据台账（所有下游共用）
                    └──┬───┬───┬───┘
             ┌─────────┘   │   └─────────┐
      ┌──────▼──────┐ ┌────▼─────┐ ┌─────▼──────┐
      │ ar-autopsy  │ │ ar-value │ │  ar-tape   │
      │  六维诊断   │ │  估值定锚│ │  大盘复盘  │
      └──────┬──────┘ └────┬─────┘ └─────┬──────┘
             └──────┬──────┘             │
              ┌─────▼──────┐             │
              │ ar-thesis  │◄────────────┘
              │  成稿交付  │
              └─────┬──────┘
              ┌─────▼──────┐      ┌──────────────┐
              │ ar-quality │      │ ar-position  │
              │  交付闸门  │      │ 持仓体检/台账│
              └────────────┘      └──────────────┘
```

| 工作流 | 职责 | 上游 | 下游 |
|---|---|---|---|
| `ar-intake` | 锁标的、定任务、问清缺失 | 用户 | 全部 |
| `ar-evidence` | 取数、降级、登记来源、打质量标 | intake | autopsy/value/tape/position |
| `ar-autopsy` | 六维诊断，出"值不值得继续看" | evidence | thesis/quality |
| `ar-value` | 双法交叉定价，反推隐含预期 | evidence/autopsy | thesis/quality |
| `ar-tape` | 大盘与板块复盘，定市场背景 | evidence | thesis/autopsy（背景修正） |
| `ar-thesis` | 成稿，HTML+MD 双产出 | autopsy/value/tape | quality |
| `ar-quality` | 10 项闸门，不过不放行 | thesis | 用户 |
| `ar-position` | 持仓敞口体检、观点台账维护 | evidence | 用户（下次 intake 回读） |

## 10. 工具与技术约束

- **运行时**：Python 3.9+ 标准库。**不引入任何第三方包**（无 numpy/pandas/requests/PIL）。理由：专家包要能在未配置环境的机器上直接跑，装不上就等于没有。
- **取数**：公开 HTTP 接口优先，`urllib` 实现；三级降级（公开接口 → 用户已连金融 MCP → 联网检索）。失败必须显式回报，不许静默补数。
- **渲染**：纯字符串模板生成自包含 HTML，图表用内联 SVG 手绘，不引 CDN（离线可开、无外部依赖）。
- **质检**：正则 + 结构断言，纯标准库。

## 11. 质量、速度、稳定性要求

| 维度 | 要求 |
|---|---|
| 质量 | 关键数字 100% 可追溯；报告七段不缺；证据六类标注覆盖所有主张 |
| 速度 | 单标的诊断常规 60-120 秒内出稿；取数单源超时 8 秒即降级，总取数预算 30 秒 |
| 稳定性 | 任一数据源失败不阻断流程；行情完全拿不到时拒绝出结论，只出"缺什么"清单 |
| 可复现 | 同一输入同一数据日期，报告结论应一致；随机性只允许出现在措辞，不允许出现在数字 |

## 12. 合规约束

- 全文不得出现"保证收益""必涨""稳赚""抄底信号确认"等确定性表述。
- 不得给出具体买卖操作指令；只能给条件化情景（"若 X 成立则 Y，若 X 被推翻则 Z"）。
- 不接触、不推测内幕信息；用户提供未公开信息时明确拒绝并说明原因。
- 每份交付物末尾固定免责声明，不可由用户要求删除。
- 涉及具体标的的内容成品，默认加"本文仅为研究记录，不构成投资建议"。
