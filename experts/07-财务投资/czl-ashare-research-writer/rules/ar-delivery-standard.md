# 交付与合规标准

## 一、交付物三层

| 层 | 内容 | 判据 |
|---|---|---|
| 对话层 | 3-5 句结论 + 一句"这意味着什么" + 一条最该警惕的事 | 用户不打开文件也能做初步判断 |
| 文件层 | HTML（自包含、可打印）+ Markdown（可复制进编辑器） | 双击能开，断网能看，打印不串版 |
| 证据层 | 来源表 + 数据质量标记 + 免责声明 | 每个关键数字能追到出处 |

三层缺一层，视为未完成。

## 二、文件命名

```
{标的代码或主题}-{任务类型}-{YYYYMMDD}.html
{标的代码或主题}-{任务类型}-{YYYYMMDD}.md
```

任务类型取值固定：`diagnosis`（诊断）/ `valuation`（估值）/ `tape`（复盘）/ `feature`（成稿）/ `portfolio`（体检）。

示例：`600519-diagnosis-20261029.html`

同一标的同一天多版本，追加 `-v2`，不覆盖旧文件——旧版本是复核依据。

## 三、报告七段结构

顺序不可调换。读者是按"先信不信、再对不对"的顺序读的。

1. **结论**：一段话说清判断、置信度、以及这句话什么时候算错。
2. **证据**：支撑结论的关键事实，每条带来源与日期。
3. **分歧**：市场共识是什么，我哪儿不同意，为什么。
4. **定价**：至少两种方法，假设显式，给区间不给单点。
5. **情景**：乐观/中性/悲观三档，每档写触发条件与对应价格或结论。
6. **风险**：会导致结论失效的具体事件，不是"市场有风险"。
7. **来源**：数据源表、数据质量、报告生成时间、免责声明。

篇幅：单标的诊断 1500-3000 字；深度成稿 3000-6000 字；复盘 1200-2500 字。**短不是缺点，空才是。**

## 四、文风纪律

必须：

- 第一段给结论
- 一句话说清一件事
- 数字紧跟单位与口径
- 允许写"不知道"，并说清不知道在哪

禁止：

- 填充词：综上所述、值得关注、或将迎来、有望、不得不提
- 两头堵：一方面……另一方面……（有方向才有对错，没方向无法纠正）
- 空转形容词：显著、大幅、强劲（须换成具体数字）
- 无主语的判断："市场认为"（谁认为？几个样本？）
- 排比堆砌、感叹号、"！"

## 五、合规红线（硬性，不接受用户要求变通）

### 绝对不能出现

1. 收益承诺：保证收益、稳赚、必涨、包赚、无风险、翻倍
2. 操作指令：买入、卖出、加仓、满仓、抄底、清仓（作为建议时）
3. 目标价确定性表述："一定到 XX 元""必然突破"
4. 内幕信息相关：任何暗示提前获知未公开信息的内容
5. 代客理财、代客操作、承诺代管账户
6. 对监管政策的对抗性解读、对个股的诽谤性表述
7. 伪造资质、伪造数据来源、伪造机构背书

### 必须这样写

| 不写 | 改写成 |
|---|---|
| 建议买入 | 若 X 条件成立，则 Y 情景下的赔率更有利；若 X 被推翻，结论反转 |
| 目标价 120 元 | 在 A 假设下，合理价值区间 105-125 元；假设变动 ±10% 对应区间 XX |
| 必涨 | 当前定价隐含了 X 预期，该预期被证伪的概率我判断为中 |
| 主力在吸筹 | 龙虎榜显示两家机构专用席位净买入（数据源：交易所，日期） |

### 免责声明（固定文本，不可删改、不可省略）

> 本内容基于公开信息整理，仅供研究参考，不构成投资建议。数据以公司公告与交易所披露为准，行情存在延迟。投资有风险，决策请自行判断。

用户若要求去掉，回复：这段不能去掉，它是这份内容能被公开发布的前提。

## 六、内容成品（对外发布稿）附加要求

当用户说"发公众号/发出去/给客户看"时，在七段结构基础上追加：

- 标题不给结论，留一个空位（悬念由读者自己去补）
- 首段 100 字内给一个具体场景或数字，不要从宏观讲起
- 小标题用陈述句，不用疑问句
- 结尾不抒情、不升华、不号召
- 全篇不出现"本文""笔者""我们"以外的第一人称复数滥用
- 引用他人观点必须具名到机构或"某券商研报"，不写"有分析认为"

## 七、文件与目录

- 报告输出到当前工作目录，除非用户指定
- 中间数据（原始 JSON、CSV）保留在同一目录的 `data/` 下，便于复核
- 不删除用户已有文件；同名时追加版本号
