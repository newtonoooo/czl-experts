## 五、开发过程中发现并修复的缺陷

测试不是走过场，以下 5 个问题均为实际运行暴露后修复：

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | `check` 子命令抛 KeyError: 'exchange' | `limit_prices()` 返回值缺 `exchange` 与 `currency` 字段 | 补齐字段 |
| 2 | 新浪行情自检"日期解析"失败 | 测试夹具多写了一个 `2026` 字段，导致索引偏移 | 修正夹具为真实 32 字段格式 |
| 3 | 闸门 A3 对合法报告报"缺失结论段" | HTML 版结论区只有文字，没有"结论"二字，而 MD 版有标题 | HTML 结论区补 `<h2>结论</h2>` |
| 4 | 请求 260 根 K 线却返回 6031 根 | 东财接口在 `beg=0` 时忽略 `lmt` 参数 | 取回后按 `days` 从尾部截断 |
| 5 | 几乎所有报告 A4 匹配率偏低 | 股票代码（600519）与年份（2026）被当作数据数字计入分母 | 抽取时排除 6 位纯数字与 19xx/20xx |

第 5 项是设计层面的问题：如果不修，闸门会对每一份正常报告误判，最终使用者会习惯性忽略闸门，整个质量机制失效。

## 六、未验证事项（不计入通过）

以下内容**没有实测**，不得视为可用：

1. **非 Windows 平台**：脚本只用标准库，理论上跨平台，但未在 macOS / Linux 上实际运行过。
2. **客户端内加载与 skill 路由**：本包按 WorkBuddy 专家包结构组织（`plugin.json` + `agents` + `skills`），但未在客户端中实际导入并触发 skill 调用。此项需上架前由人工在客户端内验证。
3. **多轮对话中的上下文保持**：未测试长会话（>40 轮）后提示词约束是否衰减。
4. **多标的批量处理**：`ar-intake` 规定超过 5 只标的先问优先顺序，该分支未构造用例。
5. **财务与资金面数据通道**：包内无财务数据库，`ar-autopsy` 的财务维、资金维依赖外部工具或联网检索，本次未接入真实财务源验证。
6. **情绪温度的校准**：`ar-tape` 的四项映射曲线为经验值，未用历史数据回归验证其区分度。
7. **极端行情**：未测试涨跌停开盘、停牌、退市整理期、熔断等异常场景下的完整流程。
8. **大文件性能**：未测试 5000+ 标的批量筛选时的耗时。
9. **平台审核**：未提交平台实际审核，审核口径未知。
