# 来源、原创性与第三方依赖说明

本文件回答三个问题：这个东西是怎么来的、哪些部分是我独立写的、里面有没有别人的东西。

## 一、开发方式

本产品为**独立开发**，开发过程分三步：

1. **需求分析**：阅读本机已安装的 6 个 A股/投研方向专家包，记录它们能解决什么问题、在什么条件下失效，据此归纳出产品需求（见 `SPEC.md` 第 2 节）。这一步只做功能分析与能力盘点。
2. **规格设计**：由需求推导工作流划分、输入输出规范、质量与合规约束，先写成 `SPEC.md`，再据此实现。
3. **实现**：agent 提示词、8 个工作流、3 份规则、6 个脚本、渲染器、测试，全部按规格新写。

以下包仅用于功能分析，**未复制其任何提示词、代码、模板、文档或图像**：

## 三、借鉴的通用方法与独立实现

**属于公开通用方法、可自由使用**（这些是行业共同知识，不构成他人专有表达）：

- 两阶段 DCF 的标准公式、WACC 的构成
- MA / EMA / MACD / KDJ / RSI / BOLL / ATR 的计算式
- 杜邦分解、PE/PB 分位、隐含增长反推的思路
- 六类证据分级的做法（来源可追溯原则）
- A股交易规则（涨跌停、T+1、ST、复权等，属公开规范）

**本产品独立设计的部分**：

| 组件 | 独立设计点 |
|---|---|
| 判断链 | 「交付物 → 问题 → 证据 → 可得性 → 表达」的五步顺序，与"数据维度→模块→报告"的常规组织方式相反 |
| 工作流划分 | 按"一次判断的闭环"切分，而非按数据类型；8 个流程的上下游与回退关系为自行设计 |
| 六维诊断 | 维度定义、权重、一票否决项、打分档位 |
| 交付闸门 | A1-A7 机器检查项与 B1-B4 人工判据、放行/打回规则 |
| 证据台账 | 六类标注（事实/披露/共识/推算/假设/判断）字段化 + 质量标记体系 |
| 脚本 | `arrules.py` / `arfetch.py` / `arindicators.py` / `arvalue.py` / `arreport.py` / `archeck.py` / `arposition.py` 全部为本次新写，标准库实现 |
| 报告版式 | 七段结构、CSS、内联 SVG 走势、打印样式 |
| 头像 | `tools/make_avatar.py` 生成，纯几何绘制 |

## 四、第三方依赖

**运行时依赖：无。**

所有脚本仅使用 Python 3 标准库（`argparse`、`json`、`re`、`urllib`、`zlib`、`struct`、`decimal`、`math`、`csv`、`subprocess` 等）。不引入 numpy、pandas、requests、Pillow 或任何需要额外安装的包。

因此本产品**不包含任何第三方开源代码**，不涉及 GPL/MIT/Apache 等许可证的传染性或署名义务。

**使用者注意**：若将产出物用于商业发布，行情数据的转载与展示条件需自行向数据提供方确认。本产品建议在产出物中标注数据来源与获取时间，这既是学术规范，也是降低风险的做法。
