# WF-04 对抗式自检

这一步的心态很关键：**不是去证明结果对，而是去证明结果错**。找不到错，也要写出"我怀疑过什么、怎么排除的"。

## 一、12 项审计清单

逐项给 PASS / FAIL + 证据（命令输出、行号、数字），不要写"已检查"。

| # | 检查项 | 怎么查 | 典型 FAIL 症状 |
|---|---|---|---|
| 1 | 可运行性 | `python run_xxx.py` 干净退出（无异常、无静默跳过） | 报错、只跑了一半、靠 try/except 吞掉 |
| 2 | 三件套完整 | 三个文件都存在且非空；`summary.json` 能被 `json.load` | 空文件、只有表头 |
| 3 | 成交时点 | 抽 1 笔：`entry_price` 是否等于**次日**开盘价（含滑点） | 等于信号日收盘价 → 未来函数 |
| 4 | 预热隔离 | `equity[0].value == initial_cash`；首笔 `entry_date >= eval_start` | 预热段就开仓 |
| 5 | 手数约束 | 所有 `shares % lot_size == 0`；无 0 股成交 | 出现 150 股 |
| 6 | T+1 约束 | 无 `entry_date == exit_date` 的记录（A 股） | 当日买当日卖 |
| 7 | 费用计提 | `total_fees > 0`；把费用置 0 重跑，收益应变好 | 费用恒为 0 |
| 8 | 强平记录 | 末笔 `exit_reason == "eod_close"`（若末笔有持仓） | 留浮盈不结算 |
| 9 | 账户恒等式 | 末期 `equity ≈ cash`（清仓后）；中途抽一天手算 | 差出几千块 |
| 10 | 记录配对 | `buy_fills` 与 `sell_fills` 逻辑一致；笔数 = 平仓次数 | 买卖次数乱配 |
| 11 | 首末 5 笔人眼过 | 价格量级、持有天数分布、`side`、日期是否在区间内 | 3 元 ETF 出现 300 元成交价 |
| 12 | 基准对照 | 与买入持有比，收益同量级；差异能用策略特征解释 | 差 10 倍且说不清 |

## 二、数值红线（越线先当 bug，不要先讲故事）

| 指标 | 红线 | 常见根因 |
|---|---|---|
| 夏普 | > 3（单标的日线） | 未来函数、漏费用、样本太短 |
| 年化收益 | > 50% 且回撤 < 10% | 同上，或用了不复权价算收益 |
| 胜率 | > 70% 且盈亏比 > 1 | 出场逻辑把亏损单藏起来了（如只统计盈利单） |
| 最大回撤 | 恰为 0 | 净值曲线几乎是平的 / 从没真正持仓 |
| 年交易次数 | < 3 或 > 252 | 指标全是 NaN / 把状态当事件 |
| 平均单笔盈亏 | 恰好等于 ±止损比例 | 用触发价直接成交、没有滑点分布 |
| 收益 / 买入持有 | > 10 倍或 < 1/10 | 口径不同（复权、区间、费用） |

越线不等于一定错，但**必须先排除实现错误，再讨论策略特性**。

## 三、四个对抗问题（逐行读代码时问自己）

1. **时点**：这一行用到的数据，在"明天开盘做决定"的那一刻真的知道吗？
2. **边界**：当变量是 `None` / `0` / `NaN` / 负数 / 空列表时，这一行会静默跳过还是炸掉？静默跳过的地方最危险。
3. **手算**：这笔交易的 `pnl` 能不能用「卖出价 × 数量 − 费用 − 买入价 × 数量」反算出来？差在哪里？
4. **换词**：把用户原话里的一个词换掉（"开盘"→"收盘"、"每天"→"每周"、"清仓"→"减半"），这行代码还成立吗？不成立说明硬编码了假设。

## 四、硬性要求：至少列出 3 个"怀疑过并排除"的点

审计单末尾必须有这一段。写不出来说明没真审。示例：

```
- 怀疑手数取整导致资金闲置过多 → 查 rejects 为空、exposure 96%，排除
- 怀疑止损价用了触发价而非成交价 → 查 trades 里 pnl_pct 分布连续（无 -8.00 聚集），排除
- 怀疑预热段污染 → equity[0] == 1,000,000，排除
```

## 五、审计单格式（audit.md）

```markdown
# 审计单 · <策略名> · <日期>

## 结论
可信 / 有条件可信 / 不可信（一句话 + 主要原因）

## 清单
| # | 项目 | 结果 | 证据 |
|---|---|---|---|
| 1 | 可运行性 | PASS | 退出码 0，耗时 1.2s |
…

## 数值体检
夏普 X｜年化 X%｜回撤 X%｜笔数 X｜费用 X 元｜在场 X%
（与红线表逐项对照，越线的写处理意见）

## 手算复核
第 3 笔：买入 2022-05-06 开盘 3.62 × 260000 股 + 费用 235.3 = 941,435.3
       卖出 2022-06-15 开盘 3.71 × 260000 股 − 费用 482.3 = 963,117.7
       pnl = 21,682.4（记录值 21,682.4，一致）

## 怀疑并排除
1. …
2. …
3. …

## 回退去向
无 / 回 WF-01（口径）/ WF-02（数据）/ WF-03（实现，需重跑全链）
```

## 六、失败怎么处理

| 发现 | 回退到 | 是否重跑全链 |
|---|---|---|
| 口径卡与实际实现不一致 | WF-01 | 是 |
| 数据缺口、复权错、单位错 | WF-02 | 是 |
| 撮合、费用、手数、强平、指标算错 | WF-03 | 是（三件套 + 报告全部重出） |
| 只是报告排版/文案问题 | WF-05 | 否 |

**改代码后必须重跑整条链**：不许只改报告不改数据，那会让用户看到"新结论 + 旧数字"。

## 七、复核别人的回测（专项）

用户丢来一份别人的脚本或结果时，按这个顺序看：

1. 有没有 `shift(-n)` / `iloc[i+1]` / 未来日期切片
2. 信号与成交是不是同一个价格
3. 费用是不是 0，或只在买入时收
4. 样本区间是不是精心挑过的（刚好避开大熊市）
5. 有没有对照组；只有一条曲线的基本不可信
6. 参数是不是只有一个最优点
7. 股票池是不是今天的成分股（幸存者偏差）

审计单照上面格式写，结论可以很直接："按目前实现，这个年化 80% 的结果主要来自未来函数，修正后约 X%。"

详细查法见 `references/audit-playbook.md`，历史翻车案例见 `references/failure-cases.md`。
