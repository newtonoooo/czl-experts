# 产品规格 · 专业回测台 v1.0.0

编写日期：2026-10-28　编写人：虫志龙

---

## 1. 目标用户与真实场景

| 用户 | 场景 | 现在怎么做 | 痛在哪 |
|---|---|---|---|
| 有交易想法的个人投资者 | 刷到一条"均线金叉""量价突破"，想验证 | 找代码、改参数、跑通就信 | 未来函数、漏费用、只看一个参数 |
| 投顾 / 研究者 | 给客户或同事解释一套规则的历史表现 | 手工记在 Excel | 口径说不清，别人复算不出来 |
| 内容创作者 | 写策略复盘文章，需要可信数字 | 抄别人的回测结果 | 无法核对来源与假设 |
| 被交付方 | 收到一份"年化 80%"的回测，要判断真假 | 凭经验看 | 不知道从哪查起 |
| 学生 / 转行者 | 学量化，需要完整的示范工程 | 啃框架文档 | backtrader/vectorbt 门槛高，跑不通就放弃 |

共同点：**要的不是"能跑"，是"能信"**。

## 2. 要解决的问题（按发生频率排序）

1. **口径不可复现**：同一句话，两个人跑出两个结果，且都说不清差在哪。
2. **未来函数**：收盘决策 + 收盘成交；用本期涨幅选股；用整段样本极值当基准。
3. **只报单点结果**：一个参数、一次成本假设，没有稳健性与成本压力。
4. **数据带病**：缺预热段、复权混用、成交量单位错、停牌日补 0。
5. **自检缺失**：脚本跑通即交付，不查账户恒等式、不查首末笔记录。
6. **交付不可读**：只有一堆 CSV，没有结论，也没有局限说明。
7. **复核成本高**：拿到别人的回测，没有系统化的检查顺序。

## 3. 输入与输出

### 输入（最小集 → 完整集）

| 层级 | 内容 |
|---|---|
| 最小 | 一句话策略描述（标的 + 买卖条件 + 区间） |
| 常用 | 再加：成交时点、仓位、费用、止损、基准 |
| 完整 | 再加：参数扫描网格、成本压力倍数、输出语言、是否要报告 |
| 可选附件 | 用户自有 CSV、别人的回测脚本 / 结果文件 |

### 输出（每次交付固定）

| 输出 | 形态 | 说明 |
|---|---|---|
| 口径卡 | 对话内表格 + `spec.json` | 唯一事实来源 |
| 数据清单 | `data_manifest.json` | 来源、区间、行数、缺口、指纹 |
| 回测脚本 | `run_xxx.py` | 自包含、可单独复跑 |
| 三件套 | `*_equity.csv` / `*_trades.csv` / `*_summary.json` | 事件研究改为事件级 `trades.csv` |
| 审计单 | `audit.md` | 12 项 + 数值体检 + 手算 + 排除项 |
| 报告 | `index.html` | 自包含，含 KPI/曲线/回撤/月度/成交/口径 |
| 结论 | 六段式回复 | 结论→口径→执行→结果→局限→复现 |
| 复现清单 | `repro.md` | 命令 + 数据指纹 + 版本 |

## 4. 处理步骤（工作流）

| ID | 名称 | 输入 | 输出 | 关键判断 | 失败去向 |
|---|---|---|---|---|---|
| WF-01 | 立项与口径锁定 | 需求文本 | 口径卡 | 时点/状态、复合出场、生命周期、多策略优先级 | 需求超范围 → 说明并给替代 |
| WF-02 | 取数与体检 | 口径卡 | CSV + 清单 | 缺数据是停牌还是截断、复权是否一致、单位 | 数据不足 → 缩区间并标注 |
| WF-03 | 引擎构建与运行 | 卡 + 数据 | 脚本 + 三件套 | 模式选择、成本参数化、强平 | 0 笔交易 → 查 NaN 与条件方向 |
| WF-04 | 对抗式自检 | 脚本 + 产物 | 审计单 | 是否越红线、账户恒等式、配对 | 回 WF-01/02/03 并重跑全链 |
| WF-05 | 交付与复现 | 三件套 + 审计单 | 报告 + 回复 + 复现清单 | 语言跟随、局限取舍 | 图表空白 → 重出，不交付 |

依赖关系：01 → 02 → 03 → 04 →（04 打回）→ 05。**禁止跳步**。

## 5. 工具能力与技术接口

| 能力 | 实现 | 约束 |
|---|---|---|
| 行情获取 | 外部命令行（若已装）/ 用户 CSV / 公开源 | 来源必须在回复中披露；缺数据不许编 |
| 格式转换 | `tools/bars_from_table.py` | 认中英文表头、Markdown/TSV/CSV |
| 撮合与账户 | `kit/btcore.py` | 次日开盘成交、手数、T+1、费用、强平 |
| 指标 | `kit/btcore.py:compute_metrics` | 收益/年化/波动/夏普/索提诺/卡玛/回撤/胜率/盈亏比/在场时间 |
| 事件研究 | `event_study / event_stats` | 事件级统计，不报组合指标 |
| 稳健性 | `param_sweep` + `CostModel` 倍数 | 参数网格 ≥ 3×3，成本 ≥ 3 档 |
| 报告 | `kit/btreport.py` + 模板 | 自包含 HTML，无 CDN，无字体依赖 |
| 自检 | `tools/selftest.py`、`tools/check_report.js`、`tools/verify_avatar.py` | 交付前必须全绿 |

## 6. 质量、速度、稳定性要求

| 维度 | 要求 | 现状 |
|---|---|---|
| 正确性 | 13 例内核单测全过；审计 12 项全 PASS | 通过（见 `docs/功能测试报告.md`） |
| 可复现 | 同输入 + 同代码 → 同输出；数据带指纹 | 通过（示例两次运行结果一致） |
| 速度 | 1000 根 bar、单标的 < 2 秒 | 实测 0.012 秒（Python 3.13，1045 根 bar，32 笔交易） |
| 稳定性 | 缺数据/坏 CSV/空结果都有明确报错，不静默 | 通过（有反例测试） |
| 可读性 | 报告在 1280px 下无需横向滚动；手机端两列折叠 | 通过（响应式断点 900px） |
| 依赖 | 零第三方 Python 包 | 通过 |
| 语言 | 中英双语，跟随提问语言 | 通过 |

## 7. 与同类做法的差异（产品定位）

| 常见做法 | 本产品 |
|---|---|
| 给一段模板代码让用户自己改 | 按口径卡生成脚本，脚本可直接复跑 |
| 只报一个参数下的收益 | 默认做参数扫描 + 成本压力 |
| 只要跑通就算交付 | 审计是独立工作流，未过不得交付 |
| 依赖 pandas / matplotlib | 零依赖，报告自绘 SVG |
| 只接新需求 | 支持复核别人的回测 |

## 8. 不在范围内

- 分钟 / Tick 级撮合
- 期权、可转债、期货展期与保证金
- 完整多因子截面流水线（IC、因子正交、组合优化）
- 任何形式的买卖建议
