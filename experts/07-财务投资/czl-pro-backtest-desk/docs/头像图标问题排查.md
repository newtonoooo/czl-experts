# 排查记录：专家导入新 WorkBuddy 后，小图标变成文字

日期：2026-10-28　排查人：虫志龙（借助本机 WorkBuddy 客户端代码与缓存）

## 一、现象

专家包在自己的机器上正常显示头像；打包成 zip 导入另一台（或新装的）WorkBuddy 后，
专家能选中、能对话，但列表里的小图标变成「名字首字 + 色块」。

## 二、结论（一句话）

**头像地址没有被解析成可用 URL，界面于是回退成"首字色块"。**
WorkBuddy 只接受三种头像写法，其余一律被静默置空；而被置空之后，前端**不会报错**，只会画一个字。

## 三、代码依据

### 1. 本地自定义专家的头像解析（决定性的一段）

客户端主进程里读取自定义专家目录时，会调用 `resolveAvatarUrl(avatar, expertDir)`：

```js
async resolveAvatarUrl(e, t) {                 // e = plugin.json 的 avatar 字段，t = 专家目录
  if (!e) return '';
  if (/^(https?|data):/.test(e)) return e;     // 只放行 http(s) 与 data:
  let n = e.replace(/^\.\//, '');
  let r = path.resolve(t, n);                  // 相对包根解析
  let i = path.resolve(t);
  if (!r.startsWith(i + path.sep) && r !== i) return '';   // 越界即作废
  try { if (await pathExists(r)) return toLocalFileUrl(r); } catch {}
  return '';                                   // 文件不存在 → 空字符串
}
```

三个硬条件：**只能是 http(s)/data: 开头的地址，或包内真实存在的相对路径；绝对路径、`file://`、`local-file://` 全部会被判为越界并返回空串。**

### 2. 空字符串 → 首字色块

专家卡片处的解析是：

```js
function resolveAvatarUrl(i) { return /^(https?|file|data|local-file):/.test(i) ? i : '' }
function getAvatarFallbackBackground(i) { return `var(--ec-avatar-fallback-bg-${(i?.charCodeAt(0)||0)%8+1})` }
```

头像为空 → 走 fallback，用名字第一个字的字符码算背景色。这就是「成字了」。

### 3. 展示快照会缓存**绝对路径**

客户端把专家展示信息缓存到 `~/.workbuddy/assistant-display/<会话>.json`，其中的头像形如：

```json
{"source":"expert","name":"…","avatarUrl":"local-file://local/C%3A/Users/…/marketplaces/my-experts/plugins/czl-draft-qc/avatars/expert.png"}
```

官方/云端专家缓存的是 `https://…png`，本地专家缓存的是 `local-file://local/<本机绝对路径>`。

**换机器、换用户名、换安装目录后，这条地址就指向空气**；如果界面沿用了旧快照，图标同样是字。

### 4. 本机实测（存在真实坏样本）

扫描本机 `assistant-display/*.json`，发现同一批自定义专家里已经有一条失效记录：

| 专家 | 缓存里的头像真实路径 | 文件是否存在 |
|---|---|---|
| czl-draft-qc | `…/plugins/czl-draft-qc/avatars/expert.png` | 存在 |
| czl-guatai | `…/plugins/czl-guatai/avatars/expert.png` | 存在 |
| gaochi-content-ops | `…/plugins/gaochi-content-ops/avatars/expert.png` | **不存在** |

说明机制成立：路径一旦对不上，就只剩首字色块。

## 四、触发条件清单（按发生概率排序）

1. **zip 里没带 `avatars/` 目录**，或带的是另一张图（`plugin.json` 写 `avatars/expert.png`，实际文件叫 `czl-xxx.png`）。
2. **`avatar` 字段写成了绝对路径**（`C:/Users/…/avatar.png`）或 `file://`、`local-file://` 开头的地址——换机器必挂。
3. **路径大小写不一致**：`Expert.PNG` vs `expert.png`，Windows 上能读，macOS/Linux 上读不到。
4. **导入后没重启**：展示快照仍是旧路径（尤其从别的机器迁移过来的数据）。
5. 头像放进 `skills/` 或 `.codebuddy-plugin/` 子目录（解析器以包根为基准，子目录里的相对路径会越界）。
6. 文件名含空格、`#`、`?`、中文：URL 编码不一致时可能解析失败。

## 五、本产品的处置

1. `plugin.json` 使用**最短的相对路径**：`"avatar": "avatars/avatar.png"`，不带 `./`、不带盘符、全小写 ASCII。
2. 新增体检脚本 `tools/verify_avatar.py`：把 `avatar` 解析成绝对路径，检查是否越界、是否存在、是否 PNG、尺寸与体积是否达标，并在有问题时直接指出"导入后会显示成文字头像"。
3. `README.md` / `USAGE.md` 里写明导入后重启一次；若仍是字，先跑体检脚本。
4. 打包后再次校验 zip 内确实包含 `czl-pro-backtest-desk/avatars/avatar.png`（见 `docs/功能测试报告.md` 的 T-08）。

## 六、给平台侧的建议（非投诉，仅记录）

- 头像解析失败时，建议在开发者工具控制台打印一条 warning，而不是静默返回空串——这个错误目前完全不可见，只能靠猜。
- 展示快照里的 `local-file://` 地址建议带一个「来源目录指纹」，目录变了就重建，而不是沿用。

## 七、复现与自查命令

```bash
# 1) 检查当前包的 avatar 配置是否可用
python tools/verify_avatar.py .

# 2) 检查本机缓存里是否存在失效的本地头像路径
python - <<'EOF'
import json, glob, os, urllib.parse
for fp in glob.glob(os.path.expanduser("~/.workbuddy/assistant-display/*.json")):
    for s in json.load(open(fp, encoding="utf-8")).get("snapshots", []):
        a = s.get("assistantDisplay", {})
        u = a.get("avatarUrl") or ""
        if u.startswith("local-file://local/"):
            p = urllib.parse.unquote(u[len("local-file://local/"):])
            if not os.path.exists(p):
                print("失效:", a.get("expertId"), p)
EOF
```
