# 开发记录

日期：2026-10-28　开发者：虫志龙

本记录写下"为什么这么做"，方便后续维护时判断哪些是可以改的，哪些是踩过坑才定下来的。

## 0. 起点

目标是一个「量化策略回测师」类专家：用户说一句交易规则，专家把它跑成回测，给出指标、图表和结论。

我先把它拆成功能需求（见 `SPEC.md` 第 1—4 节），再决定不照搬任何现成实现，从头写一套。原因有两条：

1. 权利状态不明的内容不能直接打包进商业产品；
2. 现成实现普遍有两个结构性问题——**只报单点结果**、**没有独立的审计环节**。这两点恰好是回测最容易骗人的地方，值得作为差异点重做。

## 1. 关键决策与理由

### 决策一：不用 pandas，重新实现撮合

**为什么**：pandas 在用户机器上经常是"没装/版本冲突/装不上"。一个回测专家如果第一句话是"请先 pip install pandas"，体验直接崩。标准库的 `csv` + 列表足够处理日线级别的数据量（千根 bar）。

**代价**：向量化指标要自己写（`sum/len` 求均线，`statistics` 求波动），代码比 pandas 长，速度慢一个量级——但 1000 根 bar 实测 0.012 秒，用户感知不到。

**验证**：`tools/selftest.py` 13 例全部针对内核行为写，其中 5 例直接针对撮合边界（次日开盘、T+1、手数、恒等式、强平）。

### 决策二：信号与成交强制分离

**为什么**：这是回测里第一大 bug 源。用户说"金叉买入"，最自然的写法是"今天算金叉、今天买"，等于用当日收盘价买入——而收盘价只有收盘才知道。

**做法**：引擎内部维护 pending 队列，`run()` 在 t 日收盘后调用策略，t+1 日开盘执行。策略回调拿不到未来的 bar（`ctx.history` 只到当天）。

**代价**：策略作者不能"立即成交"，需要理解延迟一天；但这正是真实世界的样子。

### 决策三：预热段只喂历史，不下单

**为什么**：第一版写完发现 `equity[0]` 不等于初始资金——预热期已经交易了。这是典型的"指标预热污染"。

**做法**：只在 `[eval_start, eval_end]` 内调用 `strategy()`；预热数据照常累积进 `history`。自检里专门有一条 `test_warmup_does_not_trade` 守着。

### 决策四：报告不用 matplotlib

**为什么**：matplotlib 在 Windows 上中文标题经常是方块，用户还得装字体；而且生成的 PNG 散落一地，转给别人要打包。

**做法**：`btreport.py` 把结果转成 JSON 载荷，塞进自包含 HTML 模板，图表用内联 SVG 由前端脚本画。好处是单文件可转发、可打印、可离线。

**代价**：模板 JS 要自己维护；用 `tools/check_report.js` 在 Node 的极简 DOM 桩里跑一遍，避免每次都要开浏览器。

### 决策五：审计独立成第五条工作流

**为什么**：如果审计只是"交付前顺手看一眼"，它一定会被跳过。做成独立工作流、要求输出带证据的审计单、要求"至少列出 3 个怀疑过并排除的点"，才有约束力。

**做法**：12 项清单 + 数值红线表 + 手算复核 + 首末笔人眼过 + 基准对照；失败按类型回退到 WF-01/02/03，并强制重跑全链。

### 决策六：默认做参数扫描与成本压力

**为什么**：单点最优是回测最常见的骗人方式。与其等用户问"是不是过拟合"，不如默认给。

**做法**：`param_sweep` 支持任意网格，示例里跑 3×3 参数 + 1×/2×/4× 成本。报告"9 组里几组为正"。

### 决策七：加"复核模式"

**为什么**：市面上回测工具都在"生产结果"，没人管"判断别人结果真假"。而这恰恰是用户拿着"年化 80%"截图来问的高频场景。

**做法**：审计技能里写了 7 条复核顺序（未来数据切片 → 信号成交同价 → 费用为 0 → 挑区间 → 无对照 → 单点参数 → 幸存者偏差）。

## 2. 踩过的坑（都修了）

| 现象 | 根因 | 修法 |
|---|---|---|
| `equity[0]` 不等于初始资金 | 预热段也在调用策略 | 加 `eval_start` 门禁 + 单测 |
| 止损参数加了但结果没变 | 死叉先触发，止损路径从未走到 | 示例里打印止损触发次数（本次 0 次），不再假装它起作用 |
| `buy_fills` 与 `sell_fills` 意义不明 | 只统计了平仓笔数 | Broker 分别计数，指标里分开给 |
| 强平后净值仍用旧值 | 直接写了 `cash`，没算残留持仓 | 改为 `broker.equity(marks)` |
| 事件研究报告出现月度热力表空白 | 事件模式没有月度数据，模板仍渲染该卡片 | 模板里空数组直接隐藏卡片 |
| 事件研究成交表列名是"标的/买入价" | 与策略回测共用表格 | 加 `table_mode="event"` 切换列名 |
| 示例里的结论文字是硬编码的 | 参数扫描结果变了文案没变 | 改为从扫描结果计算后再拼文字 |

## 3. 测试与验证

见 `docs/功能测试报告.md`。核心结论：内核 13 例全过，三个示例全部跑通，三份报告渲染自检全过，两次运行结果哈希一致。
