# W2 分录编制

分录不是把金额凑平就完事。真正决定这张凭证对不对的，是四件事：业务实质定没定、科目落没落对、价税分没分开、期间卡没卡准。

## 工作流卡片

| 字段 | 内容 |
|------|------|
| **工作流名称** | W2 分录编制（journal-builder） |
| **任务职责** | 把一笔业务翻译成合规、可复核、可过账的记账凭证，并给出计算依据 |
| **输入参数** | 业务描述；金额（含税/不含税要说明）；税率与发票类型；业务发生日期与所属期间；往来对象；结算方式；原始单据号；部门/项目（用于费用归集） |
| **执行步骤** | ① 定性：这笔业务的经济实质是什么 → ② 定科目：落到一级/明细科目（附映射） → ③ 定价税：含税拆分，确认能否抵扣 → ④ 定期间：按权责发生制判断归属期 → ⑤ 定证据：列出所需单据 → ⑥ 出分录表 → ⑦ 跑 `entry-check` 校验 → ⑧ 附复核要点 |
| **判断条件** | 业务实质无法判断（如"付了一笔钱"）→ 只能给候选方案并标注各自前提，不替你选；跨期 → 标 R0 并给调整期方案；含税口径不明 → 默认按不含税报价处理并显著提示；单笔 ≥ 实际执行重要性 → 强制复核提示 |
| **输出格式** | 分录表（凭证号/日期/摘要/科目/借贷/部门/单据号）+ 计算过程 + 价税拆分表 + 复核要点清单 + 校验结论 |
| **异常处理** | 多税率混合（如货物+服务）→ 分行按税率拆，不允许加权平均；代垫费用 → 走往来不走费用；红字冲销 → 必须写原凭证号；无法取得单据 → 出 R0 草稿并写明缺哪张 |
| **必要依赖** | `bin/ledgerkit.py entry-check`（批量校验）、`depreciation`（折旧）、`amortize`（摊销） |
| **与其他工作流关系** | 承接 W1 的任务单与风险级别；被 W3 调用（对账差异出调账分录）；被 W4 依赖（分录是报表的原料）；被 W6 按日历调度 |

## 编制五步

**第一步 定性。** 一句话说清：这笔钱换来什么？资产、费用、负债减少、权益变动，还是几者混合。定不了性，后面的科目全是猜。

**第二步 定科目。** 用用户的科目表；没有科目表时按 CAS 常用编码出映射，并在底稿附映射表。一级科目决定报表取数位置，明细科目决定管理口径，两者都不能凑。

**第三步 价税分离。** 中国账务最常错的地方。规则：

```
不含税金额 = 含税金额 ÷ (1 + 税率)
税额       = 含税金额 − 不含税金额
```

- 取得**增值税专用发票**且用于应税项目 → 进项税额可抵扣，单独计入 `222101 应交税费—应交增值税（进项税额）`。
- 取得**普通发票**，或用于简易计税、免税、集体福利、个人消费 → 不得抵扣，价税合计全额计入成本费用。
- 金额精度：不含税与税额分别四舍五入到分，二者相加必须等于含税总额；差 1 分时把差额调在税额上，并在底稿注明。

**第四步 定期间。** 权责发生制，不看付款日。判断依据依次是：服务/货物实际提供时点 → 合同约定的履约进度 → 结算单据日期。跨期入账一律 R0。

**第五步 定证据。** 分录后面必须能挂上单据：发票、合同、回单、签收单、审批单。缺一张，这张凭证就是草稿。

## 常用业务分录库（CAS 口径）

| 业务 | 借方 | 贷方 | 关键点 |
|------|------|------|--------|
| 采购存货（专票） | 1405 库存商品、222101 进项税 | 2202 应付账款 / 1002 银行存款 | 运费计入存货成本；普票不拆税 |
| 购入固定资产（专票） | 1601 固定资产、222101 进项税 | 2202 / 1002 | 投用次月起计提折旧 |
| 预付一年房租（专票） | 1123 预付账款、222101 进项税 | 1002 银行存款 | 按月摊入费用，不得一次性进费用 |
| 计提工资 | 6602/5101 应付职工薪酬—工资 | 2211 应付职工薪酬—工资 | 按部门归集；当月计提次月发放 |
| 计提社保（单位部分） | 6602 管理费用—社保 | 2211 应付职工薪酬—社保 | 个人部分从工资中代扣，走其他应付款 |
| 计提折旧 | 6602/5101 制造费用等 | 1602 累计折旧 | 当月增加下月提，当月减少当月照提 |
| 摊销待摊费用 | 6602 管理费用等 | 1123/1801 | 末期倒挤尾差 |
| 确认收入（专票） | 1122 应收账款 / 1002 | 6001 主营业务收入、222101 销项税 | 以控制权转移为时点 |
| 结转成本 | 6401 主营业务成本 | 1405 库存商品 | 与收入同期同口径 |
| 计提城建税及附加 | 6403 税金及附加 | 2221 应交税费—城建税/教育费附加 | 以实缴增值税为基数 |
| 银行手续费 | 6603 财务费用 | 1002 银行存款 | 取得专票可抵进项 |
| 期末汇兑调整 | 6603 财务费用 / 1002 等 | 1002 等 / 6603 | 统一汇率来源，逐户调整 |
| 政府补助（与收益相关） | 1002 银行存款 | 6117 其他收益 | 与资产相关走递延收益分期结转 |
| 研发支出（费用化） | 5301 研发支出—费用化 | 2211/1002 等 | 期末转 6602 管理费用 |

> 编码以《企业会计准则——应用指南》常用科目为准；用户科目表不同则按映射表替换，编码本身不是重点，落到正确的报表项目才是。

## 折旧与摊销

- **折旧方法**：直线法（默认）、双倍余额递减法（后两年转直线）、年数总和法、工作量法。
- **中国口径关键差异**：**当月增加的固定资产，当月不提折旧，从下月起计提；当月减少的，当月照提。** 工具里 `rule: "cas"` 就是这个口径，`rule: "immediate"` 是当月即提（部分外资账套用）。
- **残值率**：内资常见 5%，由企业政策定，不一致时必须写明依据。
- **摊销**：按受益期直线摊，末期倒挤尾差保证合计等于原额。

命令行示例：

```bash
python bin/ledgerkit.py depreciation -f 折旧输入.json
python bin/ledgerkit.py amortize -f 摊销输入.json
```

## 复核要点（过账前自查）

- [ ] 借贷合计相等，差额为 0
- [ ] 记账日期落在所属期间内
- [ ] 科目存在且方向正确（资产/费用在借，负债/收入/权益在贷）
- [ ] 价税分离正确，税率与发票一致，不得抵扣的已全额进成本
- [ ] 摘要能让人只看摘要就懂业务（禁止"调整""结转""其他"这类词单独出现）
- [ ] 附单据编号已填
- [ ] 与上期同类业务处理一致，不一致有说明
- [ ] 计提类分录已设反转（或已注明冲回期间）
- [ ] 金额未超过编制人权限；超限已走审批
- [ ] 与关联方的业务已单独标识

## 校验命令

```bash
python bin/ledgerkit.py entry-check -f 分录批次.json
```

判定口径：出现任何 R0 → 不得入账；只有 R1 → 补复核说明后可入账；无问题 → 可入账。

## 异常处理

| 情形 | 处理 |
|------|------|
| 只说"付了一笔钱" | 给 2—3 个候选方案（预付/费用/借款/投资），列各自前提，让用户选，不替他定 |
| 含税与不含税口径不明 | 默认按不含税理解并加粗提示；金额大时追问一次 |
| 一笔业务跨两个期间 | 按履约进度拆两期，两期分录都出，禁止一期吞掉 |
| 发票未到但货已到 | 月末暂估入账，次月红冲；标注暂估依据（入库单/合同） |
| 红字冲销 | 必须引用原凭证号与冲销原因，不得直接改原凭证 |
| 发现前期差错 | 区分重要性：重大走以前年度损益调整，非重大在本期调整，两者都要留下判断依据 |

## 底稿编号建议

`JE-期间-序号`（凭证）、`CAL-期间-序号`（计算表）、`MAP-科目映射`（映射表）。W3 产出的调账分录沿用同一编号体系并加 `ADJ-` 前缀。
