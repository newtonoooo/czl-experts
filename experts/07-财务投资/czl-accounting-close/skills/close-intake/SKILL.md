# W1 接单与任务单

任何账务任务的第一道门。跳过这道门直接做账，是返工的主要来源：科目口径不一致、期间理解错、拿到的数据少一行少一列，最后全部要重来。

## 工作流卡片

| 字段 | 内容 |
|------|------|
| **工作流名称** | W1 接单与任务单（intake） |
| **任务职责** | 把模糊需求转成可执行任务：确认口径、清点数据、判定风险、分流到 W2—W6 |
| **输入参数** | 用户描述；账套主体；期间；准则；币种与金额单位；科目表（可选）；数据文件或粘贴内容；交付对象与时限 |
| **执行步骤** | ① 填任务单六要素 → ② 逐项做完整性检查 → ③ 出缺件清单（必须/建议两档，写明缺了会导致什么） → ④ 定风险级别 → ⑤ 按路由表指定下游工作流与工具命令 → ⑥ 回执用户确认后才开工 |
| **判断条件** | 六要素缺 ≥3 项或期间不明 → 只做问答，不出任何数字；缺 1—2 项非致命 → 给临时口径并在结论标注"待补"；发现期间已关账 → 暂停并确认反结账路径 |
| **输出格式** | 任务单（表格）+ 缺件清单（表格，含影响说明）+ 风险汇总 + 分流结论 + 一句开工确认 |
| **异常处理** | 主体不清（多账套）→ 列出各账套差异点让用户选；币种/单位不明 → 一律先按"元、人民币"处理并在结论标注；科目表非标 → 按业务性质映射并附映射表，不擅自改用户科目 |
| **必要依赖** | 无外部依赖。可选调用 `ledgerkit.py materiality` 先算重要性门槛 |
| **与其他工作流关系** | 是 W2—W6 的共同前置；风险分级结果贯穿全部下游；缺件清单未清则下游不得出具正式结论 |

## 六要素任务单

| # | 字段 | 问法 | 为什么必须要 |
|---|------|------|-------------|
| 1 | 账套主体 | "哪个公司/哪个账套？有无分公司、合并层？" | 同一笔业务在单体与合并层处理不同，关联交易要抵销 |
| 2 | 会计期间 | "做哪个月？期间是否已关账？" | 跨期是最高频的错误来源，也最难事后补救 |
| 3 | 准则与口径 | "CAS / IFRS / US GAAP？金额单位是元还是万元？" | 决定科目、列报、减值与收入处理 |
| 4 | 科目体系 | "给一份科目表，或告诉我一级科目编码规则" | 决定分录落到哪个科目，也决定报表取数 |
| 5 | 数据来源 | "余额表哪来的？对账单是银行原件还是截图？" | 决定数据可信等级（A/B/C/D） |
| 6 | 交付物与复核人 | "交给谁？什么时候要？谁复核？" | 决定详略程度与底稿编号规则 |

> 六项里第 1、2、3 项是硬性项。这三项不清，任何数字都不该往外发。

## 完整性检查与缺件清单

按下表逐项打勾。**缺项必须写清"没有它会怎样"**，否则用户不知道优先级。

| 数据项 | 档位 | 缺了会怎样 |
|--------|------|-----------|
| 科目余额表（试算平衡表） | 必须 | 无法确认期初，所有滚算失去基准 |
| 期间内全部凭证或分录流水 | 必须 | 无法校验借贷、无法查重、无法定位异常 |
| 上期已审/已结报表 | 必须 | 无法做期初衔接与跨期比较 |
| 银行对账单（含期末余额与流水） | 做资金科目时必须 | 账实无法核对，未达账项无法识别 |
| 往来明细账（按客户/供应商） | 做往来时必须 | 无法做账龄，无法识别单边挂账 |
| 固定资产卡片（原值/投用日期/年限/方法） | 做折旧时必须 | 折旧只能估，属于 D 级数据 |
| 合同与发票（含税率） | 做收入/采购时建议 | 价税分离口径可能错，影响增值税申报 |
| 工资表与社保公积金基数 | 做薪酬时建议 | 只能按上月数推算 |
| 预算或上期实际 | 做差异分析时建议 | 只能做期间对比，做不了预实对比 |
| 关联方清单 | 有集团时必须 | 关联交易可能漏披露 |

## 数据来源等级

| 等级 | 含义 | 能否进正式报表 |
|------|------|---------------|
| A | 原始单据：发票、合同、回单、签收单、盘点表 | 可以 |
| B | 系统导出：ERP 余额表、银行网银流水、 payroll 系统报表 | 可以，需注明导出时间与操作人 |
| C | 用户口述、聊天记录、手写便条 | 仅作草稿，需回补 A/B 级证据 |
| D | 我的推算：按比例估、按上期延展、按行业均值补 | 不可以，只能作为待确认金额 |

## 风险分级

| 级别 | 触发条件（任一命中即算） | 处置 |
|------|------------------------|------|
| R0 | 无原始单据；记账日期不在本期间；借贷不平；调节表两侧不齐；勾稽关系不成立；红字冲销无原凭证号；关联方交易未识别 | 未清除不得结账、不得出表 |
| R1 | 单笔整额且 ≥10 万；金额超 2 位小数；同科目同方向重复行；往来账龄 >90 天；期间费用环比波动 >30%；新增大额科目余额 | 底稿写明依据与复核人，可过账 |
| R2 | 其余常规业务 | 留档 |

## 任务分流路由表

| 用户说的话 | 走哪条 | 先跑什么命令 |
|-----------|--------|-------------|
| "这笔业务怎么做分录" | W2 | `ledgerkit.py entry-check`（做完后校验） |
| "月末要结账，帮我排一下" | W6 → 循环调 W2/W3/W4 | `ledgerkit.py materiality` |
| "银行对不上" / "往来差 8 万" | W3 | `ledgerkit.py bank-rec` / `rollforward` |
| "帮我出三大表" | W4 | `ledgerkit.py tieout` |
| "这个月费用怎么多了这么多" | W5 | `ledgerkit.py variance` |
| "审计要资料" / "准备函证" | W6（审计交接段） | 无 |
| "折旧怎么算" / "摊销表" | W2 | `ledgerkit.py depreciation` / `amortize` |

## 交付包（四件，缺一件算未完成）

1. **主表**：分录表 / 调节表 / 三表 / 差异表（按任务类型）
2. **底稿**：计算过程、取数来源、假设清单，编号如 `R-2026-09-03`
3. **校验单**：勾稽或平衡校验的结果，含通过/不通过与差额
4. **未决事项与下一步**：编号、卡点、责任人、时限

## 异常处理细则

- **期间已关账**：不要自作主张反结账。先问三件事：是否允许反结账、上一期是否已对外报出、是否有跨期调整审批单。
- **多账套**：先做单体，再做合并；合并层必须单独列抵销分录，不得在单体凭证上直接冲。
- **科目表非标**：出一张"你的科目 → 准则对应科目"映射表，附在底稿里，后续所有输出沿用同一映射。
- **外币业务**：确认记账汇率来源（当月 1 日中间价 / 业务发生日 / 月末），三选一并全期统一；期末必须做汇兑调整。
- **只给截图**：可以处理，但标注为 B− 级，并在交付时提示"建议用系统导出复核一次合计数"。

## 与其他工作流的关系

```
W1 接单
 ├─ 单笔业务 ──────────────→ W2 分录 ──(校验)──→ 交付
 ├─ 账目不平 ──────────────→ W3 对账 ──(调账)──→ W2
 ├─ 要出报表 ──────────────→ W4 报表 ──(勾稽不过)──→ W3
 ├─ 要解释波动 ────────────→ W5 差异 ──(原因落在账上)──→ W2/W3
 └─ 要排结账/备审计 ───────→ W6 排程 ─→ 逐日调 W2/W3/W4/W5
```

W1 的风险分级会随任务流转一路带下去；下游任何一步发现新的 R0，都要回到 W1 更新任务单，不允许"先出表再说"。
