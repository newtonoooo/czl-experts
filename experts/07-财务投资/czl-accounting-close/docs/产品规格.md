## 一、目标用户与使用场景

### 1.1 目标用户

| 用户 | 具体身份 | 真实痛点 |
|------|---------|---------|
| 主用户 | 中小企业总账会计 / 财务主管（1—5 人财务团队） | 一个人干全流程，月末集中爆发；没人复核，错了也不知道 |
| 次用户 | 代账机构会计（一人管多套账） | 账套切换频繁、口径不统一、重复劳动多 |
| 次用户 | 内审 / 财务分析岗 | 要查别人做的账，缺一套"该查哪里"的清单 |
| 外围用户 | 创业公司创始人 / 非财务管理者 | 看不懂报表、不知道结账卡在哪，需要有人把话说清楚 |

### 1.2 典型场景

1. **月末结账**：T+1 开始，5 天内出表。任务多、依赖多、天天被问进度。
2. **单笔业务判断**：一笔付款/收款/预付款，不确定记哪个科目、要不要拆税、算哪一期。
3. **对账差异**：银行差 2.6 万、往来差 15 万，找不到原因，也不敢挂"其他"。
4. **出报表前的最后一道关**：三表出来了，勾稽差几千块，倒查不出。
5. **解释波动**：老板问"这个月费用怎么涨了 30%"，需要一份有数字、能站住的说明。
6. **审计进场前**：审计要 12 类资料，不知道从哪翻起，也不知道函证该怎么发。

### 1.3 不在目标内

不做合并报表全流程、不做税务申报表填制、不做 ERP 实施、不做投资与估值分析、不出审计意见。

## 二、需要解决的问题

按发生频率与损失程度排序：

| # | 问题 | 现状 | 后果 |
|---|------|------|------|
| 1 | 数据缺项，做到一半才发现 | 靠微信来回问 | 结账拖 2—3 天，返工 |
| 2 | 凭证借贷不平 / 金额口径含税不含税混用 | 靠手工核 | 报表整层错，需重做 |
| 3 | 账面对不上，差异归因错（时间性当永久性） | 靠经验猜 | 下月再错一次，长期挂账 |
| 4 | 三表勾稽不过，用调平分录糊过去 | 行业陋习 | 埋雷，审计/融资时暴露 |
| 5 | 差异分析写成空话 | 没有可验证标准 | 管理层拿不到信息，分析白做 |
| 6 | 结账无排程，关键路径不清 | 靠催 | 天天加班，仍超期 |
| 7 | 审计资料临时找 | 无清单 | 现场效率低，问题被放大 |
| 8 | 准则口径混乱（CAS/IFRS 混着用） | 无统一说明 | 同一业务两种处理 |

核心判断：**这 8 个问题里，只有 1 个是"懂不懂准则"的问题，其余 7 个是规则与算术问题。** 所以产品重心必须放在流程门禁与可执行校验上，而不是再写一遍准则讲解。

## 三、必要输入与预期输出

### 3.1 输入（六要素 + 数据）

| 要素 | 是否必须 | 缺了会怎样 |
|------|---------|-----------|
| 账套主体 | 必须 | 单体/合并处理不同，关联交易无法识别 |
| 会计期间 | 必须 | 跨期风险，无法判断截止 |
| 准则与金额单位 | 必须 | 科目与列报口径不确定，元/万元混用 |
| 科目体系 | 建议 | 只能按 CAS 常用编码映射，需事后调整 |
| 数据来源 | 必须 | 无法评定可信等级（A/B/C/D） |
| 交付对象与时限 | 建议 | 详略失当，节奏失控 |

数据形态：Excel / CSV / PDF / 图片 / 直接粘贴 / 结构化 JSON。不要求连接任何系统。

### 3.2 输出（固定四件套）

1. **主表**：分录表 / 调节表 / 三表 / 差异表
2. **底稿**：计算过程 + 取数来源 + 假设清单，带编号
3. **校验单**：平衡或勾稽结果，含逐项差额
4. **未决事项与下一步**：编号、卡点、责任人、时限

## 四、通用处理步骤（产品工作法）

```
接单（门禁） → 做平（三平） → 校表（五勾稽） → 归档（留痕）
```

| 阶段 | 动作 | 完成判据 | 未完成时的处理 |
|------|------|---------|--------------|
| 接单 | 填六要素、点数据、定风险、分流 | 六要素齐、缺件清单已出 | 只问答不出数 |
| 做平 | 凭证平、账账平、账实平 | 借贷差为 0、滚算闭合、两侧调平 | 标 R0，不结账 |
| 校表 | 五条勾稽逐条跑 | 全部差额为 0 | 倒查，不许调平 |
| 归档 | 编号、挂来源、列未决 | 第二人能独立复核 | 视为未完成 |

## 五、必要的工具能力与技术接口

### 5.1 能力清单

| 能力 | 为什么必要 | 实现方式 |
|------|-----------|---------|
| 金额精确计算 | 浮点尾差会让借贷差 1 分，直接被判不平 | Decimal + ROUND_HALF_UP，2 位小数 |
| 借贷平衡校验 | 最高频错误 | 按凭证逐张核，差额输出 |
| 单据与期间校验 | "无据不入账"必须可执行 | 字段级规则 + 风险等级 |
| 四柱滚算 | 判断账内是否自洽 | 期初 + 增 − 减 = 期末 |
| 银行余额调节 | 四类调节项方向易错 | 固定四桶 + 两侧调平 |
| 折旧/摊销计算 | 中国口径"当月增加下月计提"细节多 | 四种方法 + 口径开关 |
| 量价结构分解 | 差异分析要有可闭合的加法 | 三因分解，残差必须为 0 |
| 三表勾稽 | 报表发布前的最后一道关 | 五条关系逐条核 |
| 重要性测算 | 无门槛则差异分析无重点 | 五种基准 + 三档比例 |
| 机器可读输出 | 结果要能进底稿、能被复核 | `--json` + `--out` |
| 自检 | 发布前验证工具本身没坏 | 内置 8 个断言用例 |

### 5.2 技术约束

- **零第三方依赖**：只用 Python 3 标准库，避免许可证与分发风险，也避免用户装不上。
- **跨平台**：Windows / macOS / Linux 均可运行；Windows 控制台强制 UTF-8 输出。
- **三档退出码**：0 通过、1 有阻断问题、2 输入非法，便于脚本串联。
- **无网络**：不上传数据、不调用外部 API，账务数据不出本机。

## 六、质量、速度、稳定性要求

| 维度 | 要求 | 本版达成方式 |
|------|------|-------------|
| 正确性 | 金额计算无尾差；平衡判断零容差 | Decimal 全链路；`selftest` 8 用例 |
| 可复核 | 每条结论可追到数据来源 | A/B/C/D 四级来源标注 |
| 完整性 | 缺件必须显性化，不许静默假设 | 缺件清单 + D 级数据禁入报表 |
| 响应 | 常规分录/调节秒级给结果 | 工具本地执行，无网络往返 |
| 稳定性 | 输入异常不崩溃、给出可读错误 | 三档退出码 + 中文错误信息 |
| 一致性 | 同一业务每次给同样的科目与口径 | 科目映射表 + 固定模板 |

## 七、功能规格与架构

### 7.1 模块划分

| 模块 | 文件 | 职责 | 关键设计 |
|------|------|------|---------|
| 主控 | `agents/czl-accounting-close.md` | 工作法、硬规矩、边界、输出规范 | 四段闭环作为唯一主线，六技能挂在主线节点上 |
| W1 接单 | `skills/close-intake/` | 任务单、缺件、风险分级、路由 | 缺件必须写"缺了会怎样"，否则用户不知道优先级 |
| W2 分录 | `skills/journal-builder/` | 业务定性、价税分离、分录库、折旧摊销 | 中国口径细节（当月增加下月计提、专普票）显式写死 |
| W3 对账 | `skills/recon-balance/` | 三类对账顺序、调节表、归因矩阵 | 先账证再账账后账实，顺序反了必乱 |
| W4 报表 | `skills/statement-tieout/` | 编制顺序、五勾稽、列报、附注 | 勾稽不过不出表；给倒查顺序而非"想办法调平" |
| W5 差异 | `skills/variance-drill/` | 三因分解、说明规范、证据分级 | 设"空话黑名单"，解释必须可证伪 |
| W6 排程 | `skills/close-runbook/` | 日历、依赖、看板、审计交接 | 只给关键路径与真实压缩手段，不给鸡汤 |
| 工具 | `bin/ledgerkit.py` | 9 个命令的计算与校验 | 单一入口多子命令，输出双形态 |

### 7.2 数据流

```
用户输入 ──→ W1 任务单/缺件/风险
                 │
     ┌───────────┼────────────┬──────────────┐
     ▼           ▼            ▼              ▼
   W2 分录     W3 对账      W5 差异        W6 排程
     │           │            │              │
     └─────┬─────┴──────┬─────┘              │
           ▼            ▼                    │

```

### 7.3 与原目标专家（通用财务会计类能力）的关系

本产品在需求阶段研究了一类通用"企业财务会计专家"的能力构成：凭证、对账、报表、差异、结账、审计六条线，以及七个子技能的组织方式。研究结论用于界定功能边界，实现全部重写。

| 维度 | 通用财务会计类产品常见做法 | 本产品做法 |
|------|--------------------------|-----------|
| 准则重心 | 以 US GAAP / ASC 606 / SOX 为主 | **CAS 为一等公民**，IFRS/US GAAP 只标差异点 |
| 能力载体 | 以提示词模板与英文表格模板为主 | **提示词 + 可执行工具**，算术与校验交给脚本 |
| 输入处理 | 缺数据时按模板补位 | **接单门禁**，缺件清单前置，D 级数据禁入报表 |
| 风险控制 | 无统一分级 | **R0/R1/R2 三级**，R0 未清不得结账 |
| 对账方法 | 给调节表模板 | 给**顺序**（账证→账账→账实）+ 归因矩阵 + 四柱滚算 |
| 差异表述 | 给叙述模板 | 给**可证伪标准**（空话黑名单 + 证据分级） |
| 结账 | 给 checklist | 给**依赖分层与关键路径**，指出真正能压缩的只有三点 |
| 交付形态 | 单点回答 | **四件套**（主表/底稿/校验单/未决） |
| 语言 | 英文模板为主 | 中文为主，科目、发票、税种按中国实务 |

**继承的是问题域的划分方式**（哪些事归会计做），**不继承任何具体文案、提示词表述、代码或表格样式**。

### 7.4 非目标

- 不做准则全文检索或条款释义库（避免版本过时风险）。
- 不做税务申报表生成（税率与优惠地方差异大，且需资质）。
- 不做自动化记账机器人（无 ERP 接口，且无人复核的自动入账风险过高）。
