# 使用说明

面向使用者（会计、财务主管、代账会计）的操作手册。工具部分需要本机有 Python 3.8+。

---

## 一、先弄清它怎么工作

专家不会一上来就给你数字。它会先问六件事：**哪个账套、哪个月、什么准则和单位、科目怎么编、数据哪来的、交给谁**。这不是流程繁琐，是因为这六项里任何一项错，后面全是返工。

问完你会拿到一张任务单和一张缺件清单，缺件清单会写明"没有它会怎样"。确认之后才开工。

四段闭环对应四类产出：

| 阶段 | 你会拿到 | 什么时候算完成 |
|------|---------|--------------|
| 接单 | 任务单 + 缺件清单 + 风险预判 | 你说"可以开始" |
| 做平 | 分录 / 调节表 / 计算表 | 差额为 0 |
| 校表 | 三表 + 勾稽校验单 | 五条关系全通过 |
| 归档 | 底稿编号 + 未决事项 | 第二个人能独立复核 |

## 二、五个常用流程

### 流程 1：月末结账

**你这样说**：「9 月要结账了，10 月 5 号要出表，财务就我和出纳两个人。余额表和对账单我传上来了。」

**它会做**：
1. 出任务单，确认六要素；缺固定资产卡片、往来明细时列进缺件清单并说明影响。
2. 按 T-2 至 T+5 排日历，标出你和出纳各自的任务与前置关系，指出关键路径。
3. 逐日推进：先折旧摊销 → 再收入成本 → 再往来核对 → 再科目对账 → 最后出表。
4. 每天给状态看板，卡在哪一环、卡在谁那里写清楚。
5. 锁期前跑 11 项关账前置检查，有一项不过就不锁。

**你要给的**：科目余额表、期间全部凭证、上期报表、银行对账单（每户）、固定资产卡片、往来明细账、工资表。

---

### 流程 2：一笔业务怎么做分录

**你这样说**：「9 月一次付了 12 个月房租 24 万，收到专票，税率 9%，租期从 10 月开始。」

**它会做**：
1. 定性：这笔钱换来的是"未来 12 个月的场地使用权"，属预付，不是当期费用。
2. 价税分离：240,000 ÷ 1.09 = 220,183.49；进项税 19,816.51。
3. 出分录：借 预付账款 220,183.49 + 应交税费—进项 19,816.51，贷 银行存款 240,000.00。
4. 给后续摊销计划：10 月起每月 18,348.62，共 12 期，末期倒挤。
5. 列复核要点：合同、发票、回单三张单据是否齐全；跨年部分是否影响所得税。

**你要给的**：含税还是不含税、税率、发票类型（专票/普票）、租期起止、付款日期、单据编号。

> 关键区别：**专票且用于应税项目才能抵扣**；拿去发福利、做免税项目、或只拿到普票，价税合计全额进成本，不能拆。

---

### 流程 3：对账

**你这样说**：「银行账面对不上。账面 117.4 万，对账单 120 万，还有一笔 9 月 28 日付出去的 2.3 万支票没兑付。」

**它会做**：
1. 先跑四柱滚算，确认账面自身闭合（不平说明是过账问题，不是未达账）。
2. 按四类调节项入桶，跑余额调节表。
3. 两侧调平后，逐项给出账龄与处置建议。
4. 若属永久性差异（如银行代扣手续费未入账），出调账分录；时间性差异只挂账不调。

**你可以直接跑工具**：

```bash
cd czl-accounting-close
python bin/ledgerkit.py bank-rec -f bin/samples/bank_rec_demo.json
```

输出示例（节选）：

```
企业账面余额            1,174,000.00
加：银行已收、企业未收      3,000.00
调节后企业存款余额      1,177,000.00
银行对账单余额          1,200,000.00
减：企业已付、银行未付     23,000.00
调节后银行对账单余额    1,177,000.00
差额                            0.00
```

**方向别记反**：企业已付、银行未付 → 从**银行**侧扣；银行已收、企业未收 → 加到**账面**侧。

---

### 流程 4：出三表并检查勾稽

**你这样说**：「余额表给你，帮我出 9 月三表，先检查能不能对上。」

**它会做**：
1. 校验试算平衡（不平直接退回对账环节）。
2. 按"试算平衡 → 结转损益 → 资产负债表 → 利润表 → 现金流量表"的顺序出。
3. 跑五条勾稽，逐条给差额：

```bash
python bin/ledgerkit.py tieout -f bin/samples/tieout_demo.json
```

| 校验项 | 差额 | 结果 |
|--------|------|------|
| 资产 = 负债 + 所有者权益 | 0.00 | 通过 |
| 未分配利润期末 = 期初 + 净利润 − 分配 | 0.00 | 通过 |
| 现金流量表期末现金 = 货币资金 | 0.00 | 通过 |
| 期初 + 经营 + 投资 + 筹资 = 期末现金 | 0.00 | 通过 |
| 间接法起点净利润 = 利润表净利润 | 0.00 | 通过 |

4. 勾稽不过时给倒查顺序：先查账本身（第 1 条）→ 再查净利润衔接（第 2 条）→ 再查现金口径（第 3、4 条）→ 最后查版本一致性（第 5 条）。

> 明确禁止：用调平分录把差额塞平。它会直接告诉你"不许"，并把差额写进未决事项。

---

### 流程 5：解释波动

**你这样说**：「9 月销售费用比 8 月多了 42.6 万，老板问为什么。」

**它会做**：
1. 先定门槛（默认取收入的 0.5% 或税前利润的 5%），低于明显微小临界值的只列数不解释。
2. 拆驱动，加法必须闭合（残差为 0）：

```bash
python bin/ledgerkit.py variance -f bin/samples/variance_demo.json
```

3. 每个驱动写一句结论 + 一到两个可核对事实 + 走势判断，超三句就删。
4. 每条解释标证据等级（A 单据 / B 书面说明 / C 口述 / D 推理），C 和 D 必须进待查清单。

**空话会被打回**：「受市场环境影响」「属正常波动」「符合经营计划」——这些一律重写。

## 三、工具命令与输入契约

统一用法：

```bash
python bin/ledgerkit.py <命令> -f <输入.json> [--json] [--out 输出路径]
```

所有命令均支持 `--json`（机器可读）与 `--out`（写入底稿）。
退出码：`0` 通过 / `1` 有阻断问题 / `2` 输入非法。

### 3.1 entry-check 分录校验

```json
{
  "period": "2026-09",
  "round_amount_threshold": 100000,
  "entries": [
    {
      "id": "JE-2026-09-001",
      "date": "2026-09-30",
      "memo": "计提9月房租",
      "attachment": "INV-20260912-0087",
      "lines": [
        { "account": "660203", "debit": "18348.62", "credit": "0" },
        { "account": "222101", "debit": "1651.38", "credit": "0" },
        { "account": "224101", "debit": "0", "credit": "20000.00" }
      ]
    }
  ]
}
```

检查项：借贷平衡、无明细行、同科目双边金额、负数（红字）、超 2 位小数、缺摘要、缺单据、跨期、整额估数、科目码格式、同科目重复行。

### 3.2 rollforward 四柱滚算

```json
{
  "subject": "应收账款",
  "period": "2026-09",
  "opening": 4820000,
  "additions": [{ "label": "确认收入", "amount": 3260000 }],
  "reductions": [{ "label": "收回货款", "amount": 2980000 }],
  "closing": 5100000
}
```

### 3.3 bank-rec 银行余额调节

```json
{
  "account": "100201 银行存款-工行",
  "period": "2026-09",
  "book_balance": 1174000,
  "bank_balance": 1200000,
  "book_received_bank_not": [],
  "book_paid_bank_not": [{ "label": "支票未兑付", "amount": 23000, "aging_days": 3 }],
  "bank_received_book_not": [{ "label": "银行结息", "amount": 3000, "aging_days": 1 }],
  "bank_paid_book_not": []
}
```

### 3.4 depreciation 折旧

```json
{
  "period": "2026-09",
  "rule": "cas",
  "assets": [
    { "id": "FA-001", "name": "服务器", "cost": 120000, "salvage_rate": 0.05,
      "life_months": 36, "method": "straight_line", "in_service": "2026-07-15" }
  ]
}
```

- `rule`：`cas` = 当月增加下月计提（中国口径）；`immediate` = 当月即提。
- `method`：`straight_line` / `double_declining` / `sum_of_years` / `units_of_production`（后者需 `total_usage` 与 `usage_by_period`）。

### 3.5 amortize 摊销

```json
{ "subject": "预付保险费", "start_period": "2026-09", "total": 240000, "months": 12 }
```

### 3.6 variance 差异分解

单项：

```json
{ "area": "A产品收入", "period_current": "2026-09", "period_prior": "2026-08",
  "price_current": 105, "qty_current": 9000, "price_prior": 100, "qty_prior": 10000 }
```

多项（可拆出结构效应）：

```json
{ "area": "主营业务收入", "period_current": "2026-09", "period_prior": "2026-08",
  "materiality_pct": 5,
  "items": [
    { "name": "A产品", "price_current": 105, "qty_current": 9000,
      "price_prior": 100, "qty_prior": 10000 },
    { "name": "B产品", "price_current": 60, "qty_current": 12000,
      "price_prior": 60, "qty_prior": 8000 }
  ] }
```

输出：价差 / 纯数量差 / 结构差，三者相加必须等于总差异（残差非 0 会报错）。

### 3.7 tieout 三表勾稽

```json
{
  "period": "2026-09",
  "balance_sheet": { "total_assets": 86421000, "total_liabilities": 38214000,
                     "total_equity": 48207000, "cash": 1180000,
                     "retained_earnings_begin": 12400000, "retained_earnings_end": 13860000,
                     "dividends": 0 },
  "income_statement": { "net_income": 1460000 },
  "cash_flow": { "begin_cash": 960000, "net_operating": 486000, "net_investing": -320000,
                 "net_financing": 54000, "ending_cash": 1180000, "net_income_in_cf": 1460000 }
}
```

字段缺哪项就跳过哪条校验，不会报错；给全了才跑五条。

### 3.8 materiality 重要性

```json
{ "benchmark": "revenue", "amount": 500000000, "performance_rate": 0.6, "clearly_trivial_rate": 0.05 }
```

基准可选：`revenue`（0.5%）、`total_assets`（0.5%）、`profit_before_tax`（5%）、`equity`（2%）、`expenses`（1%）。比例可覆盖。

### 3.9 selftest 自检

```bash
python bin/ledgerkit.py selftest
```

8 个用例，全 PASS 才说明工具本身没坏。装完先跑这个。

## 四、常见问题

**Q：我的科目编码不是六位，能用吗？**
能。编码只是标签，校验只检查"4—10 位数字 + 可选分隔符"。真正要紧的是科目落到哪个报表项目，专家会先出一张映射表。

**Q：金额单位是万元，要换算吗？**
不用预换算，但要告诉专家单位。工具内部按元计算，喂数据时统一成元最省事；用万元时所有输入输出都是万元，别混。

**Q：只有截图，没有 Excel？**
可以。但要标为 B− 级来源，并建议用系统导出复核一次合计数。

**Q：差异就是查不出来怎么办？**
如实写"未查明"，附金额与已排除原因。这是合规做法；硬编一个原因才是问题。

**Q：能不能让它直接出审计意见？**
不能，也不会。它只把资料准备到能交给 CPA 的程度。

**Q：外币怎么处理？**
先定汇率来源（当月 1 日中间价 / 业务发生日 / 月末），全期统一；期末必须做汇兑调整，差额进财务费用（筹建期另有规定）。

**Q：能处理合并报表吗？**
能出单体，能给抵销分录框架，但不做完整合并流程（持股比例变动、商誉减值、少数股东权益逐项计算需人工判断）。
