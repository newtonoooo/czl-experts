## 一、起点与边界

需求：做一个"沪深A股盘中交易参谋"类型的专家，可公开上架与商业运营。

已有的同类产品（下称"参考产品"）只用于**功能分析**。它的目录结构是：

```
a-stock-trading-assistant/
├── .codebuddy-plugin/plugin.json
├── README.md
├── agents/a-stock-trading-assistant.md
└── avatars/a-stock-trading-assistant.png
```

阅读后确认的事实：

1. 该产品**没有 Skill 目录、没有脚本、没有任何可执行代码**，全部能力以自然语言提示词描述。
2. 它的数据获取方式是"让模型自己用 curl 拼接口"，包括 URL、字段位置、`iconv` 转码都写在提示词里。
3. 提示词中的接口示例（`hq.sinajs.cn`、`push2.eastmoney.com`）是公开行情服务地址，**属于通用的技术事实，不是该产品的独创表达**。
4. 该产品的名称、作者、头像、README 文案属于其所有者的表述，**未在本产品中复用任何一句**。

**据此划定的处理原则**：

| 内容类型 | 处理方式 |
|---|---|
| "做A股行情查询/个股分析/情绪判断"这类通用功能思路 | 允许作为需求来源，独立实现 |
| 公开行情接口的地址与字段含义 | 通用技术事实，实测后写入自己的参考文档 |
| 该产品的提示词原文、README 文案、头像、名称 | 不复用，全部重写 / 重画 |
| 该产品的文件结构 | 不复制，本产品新增了 Skill、脚本、测试、文档等该产品完全没有的部分 |

## 二、做了什么（按时间顺序）

### 阶段 1 · 功能拆解（约 20 分钟）

把"盘中交易参谋"拆成可执行的能力项，并逐项问三个问题：
**用户真正要什么？没有数据能不能回答？模型自己算会不会算错？**

拆解结果：

| 能力 | 用户真实需求 | 模型能否自己完成 | 结论 |
|---|---|---|---|
| 实时行情 | 现在什么价 | 可以联网取，但字段易错 | 写脚本，自己解析 |
| 技术指标 | 结构强不强 | 会算，但经常算错、编数 | **必须**写脚本 |
| 大盘情绪 | 今天能不能做 | 无法凭记忆知道今天涨跌家数 | **必须**扫全市场 |
| 板块龙头 | 钱往哪去 | 只能给"常识"，给不出当日数据 | 写脚本 |
| 仓位止损 | 买多少、亏多少走 | 会编出看似专业的数字 | **必须**写脚本 |
| 预警 | 到点提醒我 | 只能写在 markdown 里 | 改成结构化 JSON |

这一步确定了本产品的核心差异：**把"应该算的"从模型手里拿走，交给代码。**

### 阶段 2 · 数据源实测（约 40 分钟）

不凭记忆写接口，逐个用 curl 实测，记录真实的返回内容。

实测发现并解决的问题：

1. **东方财富有频率限制**。连续几次请求后返回 0 字节，且换主机（`push2` / `82.push2` / `push2delay`）无效。
   → 决定不把东方财富放主源，并给 HTTP 层加"主机连续失败 2 次冷却 90 秒"。
2. **腾讯行情字段非常全**，含涨跌停价、量比、PE/PB、市值，且一次可批量多只。
   → 定为快照主源。实测 600519 的涨停价 `1484.98 = 1349.98 × 1.1`，300750 的 `285.60 = 238.00 × 1.2`，
   反证了主板 10% / 创业板 20% 的规则计算是对的。
3. **新浪全市场分页可全量取**。`getHQNodeStockCount` 给出 5576 只，56 页 × 100 条，
   10 线程并发实测 **2.07 秒**取完。
   → 情绪扫描不依赖任何第三方"情绪值"，全部自己数。
4. **新浪板块聚合一次返回全部板块**（行业 49 个、概念 175 个），带领涨股。
   → 龙头识别的主数据来源。
5. **编码坑**：新浪与腾讯都是 GBK，新浪 `hq.sinajs.cn` 不带 Referer 返回空。
   → 写进 `references/data-sources.md`，代码里固定带上。

### 阶段 3 · 数据引擎（约 2 小时）

按"一个模块只做一件事"划分，共 11 个模块 + 1 个命令行入口，只用标准库：

```
atd/codes.py       代码解析、板块归属、涨跌幅限制、涨跌停价
atd/clock.py       交易时段、已走完分钟数、数据性质
atd/net.py         请求、退避重试、主机冷却、双层缓存、缓存清理
atd/quotes.py      快照（腾讯主 + 新浪备），派生字段重算与交叉校验
atd/history.py     前复权日线（腾讯主 + 东财备）
atd/indicators.py  MA/EMA/MACD/KDJ/RSI/BOLL/ATR + 分形支撑压力 + 趋势分
atd/market.py      全市场扫描 + 六项加权情绪评分 + 风险等级 + 仓位上限
atd/sectors.py     板块排行 + 龙头评分 + 板块历史累积
atd/risk.py        仓位、止损、R/T 止盈、最小可行规模、组合敞口
atd/watch.py       结构化预警清单（8 种条件）
tapedesk.py        8 个子命令 + --json
```

几个刻意的设计决定：

- **涨跌幅自己重算**。厂商字段与重算值偏差 >0.05 个百分点时以重算为准，并在 `flags` 里标注。
  这样即使厂商改了字段顺序，核心数值也不会错。
- **成交额取字段 35 的第三段**（`价/量/额`），精确到元，而不是字段 37 的"万元"。
  这条是被测试用例逼出来的：最初用字段 37，断言失败差了 1076 元。
- **情绪分不用"涨停数×系数"**。实测 47 家涨停时线性公式直接顶满，失去区分度。
  改成 `50 + 16×ln(1+涨停) − 22×ln(1+跌停)`，同样 47/5 的数据得 60.7 分而不是 100 分。
- **量能样本不足就说不足**。历史基准靠本地逐日累积，前 3 天按中性 50 计并写明原因，
  而不是编一个"较昨日放量 12%"。
- **0 股要给最小可行规模**。小资金买高价股必然算不出整手，只说"买不了"是没用的。
  现在会算 1 手成本、1 手亏损、占资金比例，并判断是"勉强可接受"还是"波动太大"。

### 阶段 4 · 提示词与工作流（约 1 小时）

七条工作流，每条都写全了：职责、输入、步骤、判断条件、输出、异常、依赖、被谁使用。

写作时刻意避开三样东西：
- 不写"你是一位资深的……"这类无信息量的角色铺垫；
- 不写"注意风险"这类没有具体动作的空话，改成"止损距离 >10% 时提示 X"；
- 不复述脚本已经做过的事（比如不要再教模型怎么解析逗号分隔字符串）。

### 阶段 5 · 头像（约 15 分钟）

用图像生成模型按自拟提示词生成，人物设定为三十出头的年轻分析师（衬衫+马甲，短袖挽起，
神态克制），背景深海军蓝 + 一条金色价格线 + 极简 K 线剪影，避免"老登感"。

生成结果右下角带平台水印，为满足商用与平台规范，自己写了 `tools/png_crop.py`
（零依赖 PNG 解码/裁剪/缩放/量化），裁掉底部 80px、缩放至 512×512、量化到每通道 6 位，
最终 234 KB（＜500 KB）。原始 1024 图另存于 `build/avatar_raw/`，不进发布包。

### 阶段 6 · 测试与修正（约 40 分钟）

- 25 个离线用例：第一次跑 24 通过 1 失败（成交额精度），修完后 25/25。
- 集成测试发现并修掉的问题：
  1. `%` 出现在非格式化位置导致 `ValueError`（"涨超5% / 跌超5%"）；
  2. 指数解析用错了 key（`000001` vs `sh000001`），三大指数一直是空的；
  3. 涨跌分布把"涨 9.8% 以上"标成"涨停"，与实际的"已封板家数"概念混淆；
  4. `watch` 默认路径跟着 cwd 走，换个工作目录就找不到上次的清单；
  5. MA60/MA120 在样本不足时直接打印 `None`；
  6. 全部代码被拒时退出码仍是 0，调用方无法感知失败。

## 三、原创性说明

**完全原创**（从零编写，无参考副本）：
- 全部 12 个 Python 文件（数据引擎 11 + 命令行 1）、测试、构建工具
- 七条工作流的定义与全部提示词文字
- 情绪评分规则、龙头评分规则、趋势评分权重、最小可行规模算法
- README、使用说明、平台文案、变更日志、本文件
- 头像提示词与后期处理流程

**通用技术方法**（属于公开知识，非他人独创）：
- MACD/KDJ/RSI/BOLL/ATR 的数学公式
- A 股涨跌幅限制规则（10%/20%/5%）
- 风险预算法仓位管理（risk-based position sizing）
- 公开行情接口地址与字段含义

**未使用**：
- 任何第三方专家的提示词、代码、文档、头像
- 任何开源项目源码
- 任何付费数据
