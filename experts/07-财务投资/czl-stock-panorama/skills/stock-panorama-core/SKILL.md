# 个股全景诊断：标准作业流程

这套流程解决一个具体问题：**同一只股票，不同人给出的结论完全相反，而且都说得出理由。**
原因是口径不同、证据不成体系、缺失项被话术填满。本流程用固定顺序和固定规则把这三件事压住。

## 一、先判断用户要哪一档

| 档位 | 触发条件 | 交付物 | 大致工作量 |
|---|---|---|---|
| 速览 | 用户只问"这票怎么样""能不能拿" | 一页速览（结论 + 三条理由 + 三条风险） | 一轮取数 |
| 标准诊断 | 用户要"诊断/分析/评估"某一只 | 六维报告 + 关键价位 + 数据体检 | 六模块取数 |
| 全流程 | 用户要比多只、要看同业、要做决策依据 | 每只一份六维报告 + 横向对比矩阵 + 组合视角 | 分标的串行 |

判断依据只有一条：用户是想要一个判断，还是想要一套可复核的证据。**不要主动升级档位**，用户没要报告就别生成报告。

## 二、五个阶段（顺序不可颠倒）

### 阶段 1：对齐口径（30 秒，不做会毁掉后面全部结论）

必须先确认或明确假设这四项，并把结果写进报告头：

1. **标的**：代码 + 名称 + 交易所。名称与代码不一致时以代码为准，并提示用户。
2. **数据截止日**与**财务报告期**：两者不是一回事。行情到昨天、财报到中报，是很常见的组合。
3. **复权方式**：技术面用前复权还是不复权。除权日附近不复权会造出假跌破。
4. **单位口径**：ROE、增速这类字段是百分数还是小数。引擎能自动处理常见情形，但拿不准时要问。

用户没说、且无法从数据源确定时，按下面的默认值走，并在报告"数据体检"里标注：
- 复权：前复权（并注明"若用户视角为不复权，技术面结论需重算"）
- 财务口径：TTM 优先，无 TTM 用最新报告期并注明
- 单位：百分数

### 阶段 2：取证（六块，缺哪块记哪块）

按能力而不是按工具名思考。每一块取证时都要记录**数据来源 + 时间戳**，取不到就写"未取到"。

| 证据块 | 要拿到的最小集合 |
|---|---|
| 估值 | PE(TTM)、PB、行业 PE 中位、历史分位（有则更好）、股息率 |
| 盈利质量 | ROE(TTM)、毛利率、净利率、ROIC、经营现金流/净利 |
| 成长性 | 营收同比、净利同比、三年复合（有则更好）、单季同比 |
| 财务健康 | 资产负债率、流动比率、利息保障倍数、商誉/净资产 |
| 技术面 | 至少 250 根日 K（OHLCV），据此本地复算均线与指标 |
| 资金与事件 | 主力净流入、北向变化、融资余额变化、最近公告/业绩/增减持 |

**工具不可用时的降级规则（重要）：**

1. 首选已授权的通达信类行情/财务工具取数（映射见 `references/data_adapters.md`）。
2. 工具不可用或返回空 → 不要用记忆里的数字填空。改为：
   - 明确告诉用户"取数工具不可用"，列出缺哪几项；
   - 请用户提供截图/CSV/一段数据，收到后用引擎重算；
   - 若用户坚持要结论，只能给"基于你提供片段的有限判断"，并标注置信度=低。
3. 只有价格没有财务 → 只做技术面，明确说明"本次不含基本面结论"。

### 阶段 3：本地计算（把数据交给引擎，不让模型自己算）

把取证结果按 `examples/sample_input.json` 的结构写成 JSON，然后运行：

```bash
cd <skill>/scripts
python -m panorama.cli check  --input <work>/data.json     # 先体检：单位、缺失、时效
python -m panorama.cli report --input <work>/data.json --out <work>/report.md
```

为什么要跑脚本而不是心算：六个维度、三十多个分项，人工加权必然算错，而且算错了看不出来。引擎的输出同时给出每个分项的扣分理由，报告里可以直接引用。

- `check` 返回 `errors` 非空 → 先补数据，不要硬着头皮往下走。
- `check` 返回 `warnings` → 保留原样，这些提示要原封不动进报告，别删。
- 引擎报 `overall: null` → 说明覆盖率不足 60%，禁止自行"估一个分"，只能输出定性描述。

### 阶段 4：写判断（引擎给骨架，模型只做三件事）

引擎负责分数、价位、多空清单。模型在此之上只补充：

1. **把机械结论翻译成人话**：为什么这一维强/弱，和行业常识是否冲突（例如高 ROE 但高负债，要指出是杠杆推的）。
2. **补反方**：引擎列出的空头证据必须保留，并补一条"如果看多的人会怎么反驳"，再说明为什么这个反驳不成立或成立。
3. **给条件，不给预测**：写"若 X 发生则 Y 更可能成立"，不写"预计上涨到 Z 元"。

### 阶段 5：交付前自检（八条，任一条不过就回去改）

1. 报告里每个数字都能在输入数据或引擎输出里找到出处？
2. 有没有把"未取到"写成"约为/大致/预计"？
3. 结论有没有同时给出支持与反对的证据？
4. 有没有出现目标价、收益承诺、"必涨/稳赚/翻倍"这类表述？
5. 复权方式、数据截止日、报告期、置信度四项是否都在报告头？
6. 同业样本少于 3 家时，是否明确说了"不做排名结论"？
7. 亏损股（PE<0）是否明确说了"PE 无经济含义"？
8. 免责声明是否保留，且没有用"仅供参考"掩盖具体荐股？

## 三、输出规范

**语气**：像研究员跟同事过材料，不像券商研报写给客户看。少用形容词，多用数字和条件句。

**结构**（标准诊断）：见 `references/report_standard.md`。核心是七节：结论摘要 / 六维评分 / 关键价位 / 同业对标 / 多空证据 / 事件与治理 / 数据体检。

**来源标注**：行情、财务、资金三类数据分别注明来源与时间。同一张表里混用两个来源时，必须在表下注明。

**结论强度**必须与置信度匹配：
- 置信度高 → 可以给明确档位判断（"六维偏强，主要短板在成长性"）；
- 置信度中 → 只给条件式判断（"若下季度营收增速回到 10% 以上，成长性这一维才成立"）；
- 置信度低 → 只整理事实与分歧点，不给档位结论。

## 四、禁止事项

- 禁止承诺收益、给目标价、说"必涨/稳赚/翻倍/抄底"。
- 禁止在数据缺失时用行业均值、记忆中的历史数据替代。
- 禁止把评分说成"模型预测"。这是规则打分，不是预测模型。
- 禁止把亏损股的负 PE 说成"估值便宜"。
- 禁止在同一份报告里对不同标的用不同的权重或阈值而不声明。
- 禁止省略免责声明。

| `scripts/panorama/cli.py` | 命令行入口：check / score / report / levels |
