# 商业发布风险清单

版本：1.0.1　日期：2026-10-28
说明：以下是技术与产品视角的风险梳理，**不构成法律意见**。涉及持牌经营、广告合规、数据授权的事项，建议在正式收费前请专业人士过一遍。

分级：🔴 高（可能直接导致下架/处罚/索赔）　🟡 中（影响审核或商业合作）　🟢 低（可控）

---

## 一、合规类

### 🔴 R1 证券投资咨询资质

**风险**：在中国境内向不特定公众提供证券投资分析、预测或建议，属于证券投资咨询业务，需要持牌。本产品输出"个股诊断报告""档位判断""关键价位"，即便声明"不构成投资建议"，若表达方式接近荐股（例如给出买卖点、评级、目标价），仍可能被认定为实质荐股。

**现有处置**：
- 全部文案与提示词禁止目标价、买卖指令、收益承诺、评级推荐；
- 输出定位为"证据整理 + 状态描述"，结论用条件句（"若 X 则 Y 更可能成立"）；
- 关键价位命名为"支撑/压力/风险位"，并注明"技术参照，不构成买卖建议"；
- 报告固定附免责声明。

**残余风险**：免责声明不能免除实质违规。若产品形态是"付费给个股结论"，风险等级不降。

**建议**：收费模式优先做"工具/软件"而非"咨询服务"；不设"专家在线荐股"入口；不对接实盘跟单。正式收费前做一次合规评估。

### 🟡 R2 广告绝对化用语

**风险**：《广告法》第九条禁止"国家级""最高级""最佳"等用语。原需求提到用"最强"作前缀，属于同一类风险。

**现有处置**：名称改为"专业级"（描述定位，不构成效果承诺），`docs/平台展示文案.md` 第七节列出七条文案红线。

**残余风险**：推广素材、短视频口播、第三方分销文案不受本包控制，容易越线。

**建议**：把文案红线作为渠道投放的硬性约束；所有对外素材统一审一遍"最强/第一/稳赚/准确率"等词。

### 🟡 R3 数据来源与商用授权

**风险**：产品本身不含数据，但运行时依赖行情/财务类 MCP 工具。若这些数据源的用户协议仅允许个人研究使用，把它接进付费产品可能违反其条款。行情数据通常还有交易所授权要求。

**现有处置**：包内零数据内嵌；文档明确"数据由用户提供或经用户已授权的工具取得"；不声称与任何数据厂商合作。

**建议**：确认所用 MCP 服务的使用条款是否允许商业场景；面向企业客户时，优先用客户自有授权的数据源。

### 🟢 R4 商标与名称混淆

**风险**："通达信""WorkBuddy"等为他人商标。产品名若含这些字样易被认为存在关联。

**现有处置**：产品名不含任何厂商名；文档提及工具名仅用于说明接口映射，并在 NOTICE 声明无合作关系。

## 二、版权与原创类

### 🟢 R5 代码与提示词原创性

**现状**：全部代码、提示词、文档、模板为本包原创；头像为几何图形程序化绘制，无第三方素材、无生成式模型参与。运行时零第三方依赖。

**取证材料**（建议随发布留档）：
- `docs/开发记录.md`：设计决策与缺陷修复过程；
- `tools/make_avatar.py`：头像可复现的生成代码（任何人可重跑得到同一张图）；
- `skills/stock-panorama-core/tests/selftest.py`：54 项断言，能证明引擎是自建而非套壳；
- 文件创建时间线（Git 提交记录更佳）。

**注意**：不要对外宣称"已获得原创认证""平台官方认证"——本包没有此类认证。

### 🟡 R6 与参照产品的相似度

**风险**：功能定位与某个既有"个股诊断"专家包相近。功能相近本身不侵权，但如果名称、文案、报告结构高度相似，可能被投诉混淆。

**现有处置**：名称、六维命名（估值/盈利质量/成长/财务健康/技术结构/资金与事件）、七节报告结构、评分体系均为重新设计，与参照对象的"六模块"划分和输出结构不同；未复制其文本。

**建议**：若收到平台或权利人异议，保留开发记录作为独立创作证据；必要时调整名称。

## 三、平台类

### 🟡 R7 专家包格式与审核

**风险**：平台对专家包的目录结构、清单字段、内容合规有具体要求，且规则可能变化。本包按 `plugin.json` + `agents/` + `skills/` 的现行结构组织，已通过本地体检，但**未经过平台审核**。

**现有处置**：`tools/verify_package.py` 覆盖 39–40 项结构检查；zip 内单一顶层目录；已把平台反馈的两条硬规则（头像扩展名、初始提示词一致性）固化为本地检查。

**残余风险**：本次只收到两条错误提示，可能还有未触发的规则，例如描述字数上限、`tags` 用词限制、`categoryId` 枚举范围、`license` 是否要求 SPDX 标识、是否拒绝未登记字段（`keywords`）。这些无法从错误信息反推，只能再提交一次看结果。

**建议**：首次提交前用平台提供的校验工具（若有）再跑一遍；保留一版可回滚的包；若因未知字段被拒，先删 `keywords` 与 `license` 这两个非必需字段重试。

### 🟡 R8 头像显示机制

**风险**：平台渲染头像时把相对路径拼到官方 CDN 上，本地自建包会 404 并退化成文字图标。这是已经发生过的真实问题（详见开发记录第 4 节）。

**现有处置**：默认内联 data URI（约 75KB），任何环境导入即可显示；提供 `set_avatar_mode.py` 在上架场景切回相对路径。

**残余风险**：若平台后续禁止 `data:` 协议或对清单体积设限，需切回路径模式并配合 CDN 上传。

### 🟢 R9 商业分成与结算

**风险**：平台分成比例、结算周期、退款规则由平台决定，且可能调整。定价策略需据此测算。

**建议**：定价前先确认平台分成条款与实际到账口径，避免按售价估算毛利。

## 四、技术与运营类

### 🟡 R10 模型未必加载技能

**风险**：提示词要求"先加载 stock-panorama-core 技能"，但模型在简单问答时可能跳过，直接用语言给结论，导致分数来自心算。

**现有处置**：提示词里把"算分必须交给引擎"写成硬要求，并在自检闸门里要求数字可追溯。

**残余风险**：无法从包层面强制。建议在真实使用中抽查若干次对话，看是否出现"未跑脚本直接给分"。

### 🟡 R11 取数工具不可用时的体验

**风险**：用户未授权任何行情工具时，产品只能输出"取数不可用 + 缺数清单"，体验会显得"什么都做不了"。

**现有处置**：降级路径已在 `references/data_adapters.md` 写清，提示词要求明确告知并给出人工提供数据的入口。

**建议**：上架页明确写"需配合行情数据工具使用"，管理预期。

### 🟢 R12 评分被误读为概率

**风险**：用户把"63 分"理解成"63% 概率上涨"，进而产生投诉。

**现有处置**：报告与文案多处声明"规则打分，非预测"；`qa.py` 不输出任何胜率字段。

### 🟢 R13 版本维护

**风险**：阈值调整后未同步文档，导致报告与说明矛盾。

**现有处置**：`references/scoring_rules.md` 与代码一一对应，改阈值需同时改两处并跑自测；CHANGELOG 记录三个已修缺陷。
