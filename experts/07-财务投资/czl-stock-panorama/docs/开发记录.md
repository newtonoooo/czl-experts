## 1. 起点：从功能需求出发，不从代码出发

参照对象是一个"个股诊断"类专家包。我只把它当**功能样本**读：它做了哪几件事、按什么顺序、输出什么形态。

读完之后提取出的需求是六条（已写入 `SPEC.md`）：目标用户、要解决的问题、输入、输出、处理步骤、工具能力。

**没有做的事**：没有复制它的提示词文本、没有沿用它的工作流结构、没有复用它的头像或文案。评分权重、阈值、报告结构、代码全部重新设计。

## 2. 关键决策

### 决策 1：把"算分"从模型手里拿走

参照对象的流程是"调六个模块 → 综合评分 → 输出报告"，评分由模型自己完成。
问题很明显：三十多个分项加权，模型心算必定出错，而且错了看不出来——报告依然通顺。

所以做了本地引擎。模型负责取数和解释，引擎负责一切算术。这不是为了炫技，是因为**不可复核的分数等于没有分数**。

### 决策 2：缺失不补，只降置信度

行业里通行做法是用行业均值兜底。我拒绝了，理由是：一旦兜底，读者就无法区分"这家公司 ROE 是 12%"和"这家公司 ROE 没披露，我按行业均值填了 12%"，而这两件事在投资判断上完全不同。

代价是报告里会出现大量"未取到"。这是设计意图，不是缺陷。

### 决策 3：固定阈值 + 显式标注，而不是行业自适应

白酒和钢铁用同一套 PB 标准确实不合理。但行业自适应需要一份可靠的行业阈值表，而这份表本身没有公认来源，编一套出来只会把主观判断伪装成客观标准。

选择是：阈值固定、全部公开、分项带 `caveat` 字段提示"该阈值不适用于本行业"，再用同业对标提供相对位置。分歧因此落在"阈值定得对不对"，这是可以讨论的；而不是"你到底算了什么"，那是没法讨论的。

### 决策 4：引擎强制生成空头证据

`bear_case()` 从低分项反推，报告固定保留这一节。理由：模型天然倾向于给出平衡但偏正面的叙述，而投资场景里"漏掉风险"的代价远大于"多说了风险"。

### 决策 5：用规则而不是概率

评分 63 分不是"63% 概率上涨"。所有对外文案都避免把分数说成概率，`qa.py` 里也不输出任何"胜率"字段。

## 3. 缺陷发现与修复（三个真实 bug）

这三个都是自测和示例报告复核时抓到的，不是事后补写的。

### bug 1：0.9% 被放大成 90%

初版对所有百分数字段套同一个启发式：绝对值 ≤1.5 就当小数写法 ×100。
示例报告里出现了"20 日主力净流入占流通市值 90.0%"——一个荒谬的数。

根因：`main_net_inflow_20d_pct = 0.9` 本意是 0.9%，被当成 0.9 倍。

修复：只对"按百分数读明显不合理"的字段（ROE、毛利率、净利率、负债率、商誉占比、质押比例、第一大股东比例）自动换算；其余字段按原值使用，并输出"可能把百分数写成了小数，请确认"的提示。另加 `meta.units.percent_format = "decimal"` 让用户显式声明口径。

经验：**自动纠错比不纠错更危险**，因为它悄悄改数据且不留痕迹。

### bug 2："标准无保留意见"判成最差

审计意见的判断写成了"含'标准'且不含'保留' → 好"。但"标准无保留意见"里确实包含"保留意见"四个字，于是最健康的审计意见拿到 18 分，还被写进空头证据。

修复：先认"无保留"，再认"无法表示/否定意见/保留意见/拒绝表示"。

经验：中文短语匹配不能用否定式包含判断，语序本身就是语义。

### bug 3：227.0075 这种"精确的错觉"

支撑位直接输出均线原始值（四位小数）。对一个由 20 日均线推导出来的参考位，精确到小数点后四位是虚假的严谨。

修复：展示层统一两位小数。

### 附带修掉的两个小问题

- 覆盖率初版按 `FIELD_TYPES` 全部字段统计，导致"没填 EV/EBITDA"也扣覆盖率。改为只看评分真正用到的主字段（`PRIMARY_KEYS`）。
- RSI 原样输出 95.4952，改为一位小数。

## 4. 头像为什么在别人机器上变成一个字（根因分析）

用户反馈：专家包导入到新的 WorkBuddy 后，选中该专家，小图标不显示，变成一个汉字。

**排查过程**：

1. 先排除文件本身问题：`expert.png` 是合法 512×512 RGBA PNG，407KB（未超 500KB 限制），签名正常。同目录其他专家头像格式一致。
2. 查 `plugin.json`：`"avatar": "avatars/expert.png"`，相对路径。所有同类专家都这么写，包括官方市场的。
3. 反查应用渲染逻辑（解包 `app.asar` 的渲染层资源）：找到负责头像的函数，逻辑等价于：

```js
function resolveAvatarUrl(path, base = CDN_BASE) {
  if (!path) return '';
  // data:image/ 直接透传
  // http/https/file/data/local-file 协议直接透传
  // 其余一律拼到 CDN 前缀上
  return join(base, path);   // base = https://acc-.../workbuddy/expert-marketplace
}
```

4. 结论：相对路径不是"本地文件相对路径"，而是**CDN 相对路径**。官方市场专家的 `avatars/expert.png` 在 CDN 上真实存在，所以能显示；自建分发的包没往 CDN 传图，请求 404，头像组件回退到"渲染名字首字"。

**这解释了为什么"图标没了、变成字"——那不是图标丢了，是兜底占位符。**

**解法**：把头像内联成 data URI。渲染层的白名单里显式包含 `data:`，且已确认它会原样透传、不做二次拼接；`new URL(dataUri)` 在缩略图函数里会抛异常并被 catch 住，不会破坏图片。

本包默认用 data URI（`plugin.json` 约 78KB）。提交官方市场上架时可切回相对路径：

```bash
python tools/set_avatar_mode.py --mode path
```

**另一个可选方案**（未采用）：`local-file:///C:/...` 绝对路径。它确实能加载本地文件，但绑定单机路径，换机器就失效，对分发型包没有意义。

### 4.1 平台上架校验推翻了上面的默认值

1.0.0 把 data URI 直接写进了清单，结果提交平台时解析失败：

```
解析失败：
格式不支持：当前为 （无扩展名），请使用 png、jpg 或 webp
defaultInitPrompt.en 必须与 quickPrompts[0].en 一致
```

两条规则说明得很清楚：

1. **平台把 `avatar` 当文件路径解析**，检查扩展名。data URI 没有扩展名，无论内容多正确都过不了。
2. **`defaultInitPrompt` 被当作首条快捷词的镜像**，必须逐字一致。我写的时候为了英文更完整，给 en 版多加了 `(Kweichow Moutai)`，中英各自"更好"反而破坏了约束。

结论：**"本地能显示"和"平台能解析"是两个互斥的约束**，不存在一个字段同时满足。处理方式不是二选一，而是出两个包：

| 包 | avatar | 面向 |
|---|---|---|
| `1.0.1.zip` | `avatars/expert.png` | 平台提交，图随后由平台托管到 CDN |
| `1.0.1-local.zip` | 内联 data URI | 本地/私下分发，导入即显示图标 |

打包时在内存里替换清单字段，磁盘上的 `plugin.json` 保持平台口径，避免"忘了切回来"这类事故。

这次的教训值得记下：**规则的唯一权威在平台侧，本地没有等价校验就等于没测**。所以顺手把这两条写进了 `verify_package.py`，现在提交前就能拦住——B6、B7 两个缺陷因此不会再犯。

## 5. 命名与合规上的两个判断

**不用"最强"**。用户建议用"最强/专业"这类前缀。查了一下：《广告法》第九条禁止使用"国家级""最高级""最佳"等用语，"最强"属于同一类绝对化表述，在金融类产品上尤其敏感。改用"专业级"——它描述功能定位，不构成效果承诺。

**不在名称里蹭"通达信"**。参照对象叫"通达信诊断师"，这个名称既涉及商标，也暗示与厂商的关系。本产品叫"个股全景诊断官"，功能描述里只说明"可对接行情/财务类 MCP 工具"，不声称任何合作。

## 6. 做过但没保留的东西

| 尝试 | 结果 | 原因 |
|---|---|---|
| 行业自适应阈值表 | 放弃 | 无公认来源，等于把主观判断包装成标准 |
| 用 AI 生成头像 | 放弃 | 生成式图像的权利状态在商用场景下需要额外说明；改为程序化几何绘制，来源清晰、可复现 |
| 目标价推算（PE/PEG 反推） | 放弃 | 与"不给预测"的定位冲突，且容易被视为投资建议 |
| 组合相关性分析 | 推迟 | 需要多标的完整收益率序列，当前输入结构不支撑，列入后续计划 |
| 打分结果缓存 | 放弃 | 引擎单次 <0.1 秒，缓存只会引入一致性问题 |
