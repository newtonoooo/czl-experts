## 五、未验证事项（明确列出）

以下项目**没有测试**，不能视为通过：

1. **平台上架复测**：1.0.0 被平台拒绝的两项（头像无扩展名、初始提示词不一致）已修复，并在本地用等价规则做了检查，但**没有再次提交平台验证**。这是本文最重要的未验证项。
2. **真实数据端到端**：本次开发环境未接入行情/财务类 MCP，`tdx_*` 系列工具均不可调用。因此"取数→规范化→打分→报告"的完整链路只用合成数据验证过。真实数据的字段名、单位、缺失模式可能与本包假设不同。
   *建议*：用 3–5 只真实标的（1 只白马、1 只亏损、1 只次新、1 只周期股）跑一遍，人工核对每个分项。
3. **跨环境导入**：没有第二个 WorkBuddy 实例可测。`-local` 包用 data URI 是基于渲染层代码分析的结论（见开发记录第 4 节），逻辑上成立，但没有做"装到干净环境里看图标"的实测。
4. **多轮对话行为**：追问、被纠正、越界请求（"你就说涨不涨"）时的实际表现，无自动化测试手段，只能靠提示词约束。
5. **超长/异常输入**：例如 5000 根 K 线、含中文字段的财务表、NaN/Infinity 混入。引擎有 None 分支和类型过滤，但未做压力测试。
6. **并发与性能**：单次计算远低于 0.1 秒，未做并发压测（也不打算支持并发场景）。
7. **不同 Python 版本**：只在 3.13.12 上跑过。代码使用 `from __future__ import annotations`，理论兼容 3.9+，未逐一实测。
8. **平台其他隐藏校验**：本次只收到两条错误提示，可能还有未触发的规则（如描述字数上限、tags 用词、categoryId 枚举）。以平台最终审核结论为准。

## 六、缺陷记录

| 编号 | 现象 | 严重度 | 状态 |
|---|---|---|---|
| B1 | 0.9% 资金占比被读成 90%，导致资金面虚高 | 高（会误导结论） | 已修复，已加断言 |
| B2 | "标准无保留意见"被判为非标（18 分），并进入空头证据 | 高（结论反向） | 已修复，已加断言 |
| B3 | 支撑位显示 227.0075，虚假精度 | 低（观感） | 已修复 |
| B4 | 覆盖率按全部字段统计，可选字段缺失也扣分 | 中（低估数据完整性） | 已修复 |
| B5 | 包体检把自身文件里的正则字面量误判为绝对路径 | 低（工具误报） | 已修复（跳过自身） |
| B6 | 平台解析失败：`avatar` 为 data URI，被判"格式不支持：当前为（无扩展名）" | 高（阻断上架） | 已修复：清单改回 `avatars/expert.png`，data URI 版本单独打 `-local` 包 |
| B7 | 平台解析失败：`defaultInitPrompt.en` 与 `quickPrompts[0].en` 不一致 | 高（阻断上架） | 已修复：直接对齐首条快捷词，并在打包时强制同步 |

B6、B7 暴露的问题是：**规则只写在平台侧，本地没有等价校验**。修复时把这两条加进了 `verify_package.py`，现在本地就能拦住同类错误。
