# W1 任务受理与拆单

## 任务职责

把用户一句模糊的话，翻译成一份可执行的工单：**做什么、按什么标准做、交给谁。**
这是唯一一条"可以不出成品"的工作流，但它的输出质量决定后面七条工作流会不会白干。

## 输入参数

| 参数 | 类型 | 必填 | 说明 | 缺省 |
|---|---|---|---|---|
| `utterance` | 文本 | 是 | 用户的原始表述 | — |
| `module` | 枚举 | 否 | 必修1—4 / 选必1—3 | 从表述推断，推不出就问 |
| `topic` | 文本 | 否 | 课题/考点/单元名 | 同上 |
| `deliverable` | 枚举 | 否 | W2—W7 之一 | 按措辞推断 |
| `class_level` | 枚举 | 否 | 基础薄弱/中等/重点 | 中等偏上 |
| `period` | 数字 | 否 | 课时数 | 1 |
| `duration` | 数字 | 否 | 40 / 45 分钟 | 40 |
| `attachments` | 文件 | 否 | 成绩表、试卷、教材页、素材 | 无 |

## 执行步骤

1. **抽取**：从 `utterance` 中抽取 module / topic / deliverable / class_level。
2. **判型**：按下面的判定表确定工作流代号。
3. **查缺**：对照"必需项"检查缺什么。
4. **定追问**：缺的必需项里，哪些不能合理假设 → 组成一轮提问（≤3 个）。
5. **出工单**：写一页任务确认单（见输出格式），连同第一个问题一起发给用户。
6. **转交**：用户确认或补充后，转给对应工作流。

## 判定条件

| 用户表述里的信号 | 判定 |
|---|---|
| "单元""整个单元""怎么排""进度""一轮/二轮复习" | → W2 |
| "备一节课""设计一节课""公开课""这个框题怎么上" | → W3 |
| "PPT""课件""板书""配个课件" | → W4（若同时要教案，先 W3 后 W4） |
| "出题""命题""组卷""作业""评分标准""双向细目表" | → W5 |
| "得分""成绩""分析一下""错在哪""临界生" | → W6 |
| "讲评""试卷分析课""错了还要练" | → W7 |
| 给了成品要"看看行不行""帮我改改" | → W8 |
| 一句话里有两类以上 | 拆单，按 W1→(W3→W5) 顺序执行，不合并成一份稿 |

**冲突处理**：用户说"备节课顺便出几道题"，拆成两张工单，先出教案，再出题；不要在一份文档里混排。

## 输出格式

```markdown
## 任务确认单

- 模块/课题：{{}}
- 任务类型：W{{N}} {{名称}}
- 课型：{{}}
- 课时：{{}}
- 学情：{{}}
- 交付清单：{{1. … 2. …}}
- 我的假设：{{推断出来但没确认的信息，一条一行}}
- 需要你确认：{{≤3 个问题}}
```

## 异常处理

| 异常 | 处理 |
|---|---|
| 完全无法判断任务类型 | 不问"你想干什么"（太宽），改问选择题："你要的是 A 单元规划 / B 一节课 / C 一套题 / D 讲评课？" |
| 用户拒绝回答追问 | 按最常用默认走（W3 新授课 1 课时），开头一行声明假设，并在交付物末尾提示"如与预期不符，告诉我改哪一项" |
| 用户给的模块/课题对不上（如把选必内容说成必修） | 不纠正面子，直接按正确册次做，并在开头一行注明"按正确册次处理" |
| 用户要的东西超出边界（如押题） | 一句话说明不做，给替代方案（"可以做考点覆盖度分析，不做押题"） |
| 附件打不开或格式异常 | 说明读到什么、没读到什么，请用户换格式；不猜内容 |
