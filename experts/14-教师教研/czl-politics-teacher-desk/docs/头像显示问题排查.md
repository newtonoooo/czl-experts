# 头像显示问题排查记录（外部专家包导入后头像变文字）

**排查对象**：另一份政治备课专家包（`politics-lesson-prep`，非本产品）
**现象**：导入到另一台机器的 WorkBuddy 后，选中该专家，头像位置没有图片，显示成一个字。
**排查日期**：2026-11-01

---

## 一、结论先说

头像本身没坏，坏在"从包到客户端"这一跳。

客户端的头像渲染是二选一：**`avatarUrl` 有值就渲染图片；为空或图片加载失败，就渲染"渐变底 + 姓名首字"**。你看到的"一个字"，就是这个兜底样式。所以问题不是图片不好看，是客户端拿到的 `avatarUrl` 是空字符串。

## 二、证据（客户端代码）

### 2.1 渲染分支

客户端对专家头像的渲染逻辑（片段，来自 `renderer/assets/src-*.js`）：

```js
let { avatarUrl: s, name: u, id: p, gradientColorStart: h, gradientColorEnd: _ } = t;
if (s) return <div className={styles.avatar}><img src={s} alt={u} onError={()=>setFailed(true)} /></div>;
let T = h && _ ? { start: h, end: _ } : getExpertGradient(p);
return <div className={styles.avatar} style={{ background: `linear-gradient(135deg, ${T.start}, ${T.end})` }}>
         <span className={styles.avatarInitial}>{initial}</span>
       </div>;
```

也就是说：`avatarUrl` 为空 → 直接走渐变+首字；`avatarUrl` 有值但图片加载失败（`onError`）→ 同样退回渐变+首字。

### 2.2 `avatarUrl` 什么时候会为空

主进程解析本地专家头像的函数（来自 `main/module.app-server.js`）：

```js
async resolveAvatarUrl(avatar, expertRootDir) {
  if (!avatar) return '';
  if (/^(https?|data):/.test(avatar)) return avatar;
  const rel = avatar.replace(/^\.\//, '');
  const abs = path.resolve(expertRootDir, rel);
  const root = path.resolve(expertRootDir);
  if (!abs.startsWith(root + path.sep) && abs !== root) return '';   // ① 路径逃出专家目录
  try {
    if (await pathExists(abs)) {
      const st = await fs.stat(abs);
      return st.size > 5242880 ? (warn('avatar file is too large'), '') : toUrl(abs);  // ② 超过 5MB
    }
  } catch {}
  return '';                                                          // ③ 文件不存在
}
```

只有三种情况会返回空：

| 编号 | 条件 | 说明 |
|---|---|---|
| ① | 解析后的路径不在专家目录内 | 一般不会发生，除非 `avatar` 写成绝对路径或带 `../` |
| ② | 文件超过 5MB | 客户端硬上限，超过直接丢弃 |
| ③ | 文件不存在 | **最常见** |

### 2.3 导入链路

客户端导入 zip 时（`main/authority-snapshot.js`）：

```js
extractZipToDir(zip, tempDir);
manifest = findPluginManifestPath(tempDir);
if (!manifest) {
  const { dirName } = await resolveSingleTopLevelDir(tempDir);  // 必须恰好一个顶层目录
  ...
}
```

两个要点：
- zip **必须有且只有一个顶层目录**，否则报 `Expected single top-level directory`；
- 找到 `plugin.json` 后，安装时会**整体搬移**解压目录，理论上 `avatars/` 会一起过去。

## 四、最可能的四种实际原因

按概率排序：

1. **导入用的不是标准打包的 zip**。
   用资源管理器右键"压缩为 zip"时，若选中的是文件夹里的**文件**而不是文件夹本身，zip 顶层会散开成多个目录；若压了两层，顶层目录就不唯一。两种情况客户端都会走异常兜底，头像可能丢。官方打包器生成的是"单顶层目录 + 完整相对路径"，这份包用官方打包器重打是正常的。

2. **走的是分享链接而不是文件导入**。
   分享链路会把专家打成 zip 上传到服务端，接收端再下载安装。如果上传时头像字段没带上（或服务端对体积/格式有限制），接收端拿到的就是空 `avatarUrl`。

3. **新机器上的文件被"清理"了**。
   网盘同步、杀毒软件、企业管控工具，都可能把 `avatars/` 下的图片当缓存清掉；`plugin.json` 是文本，通常能留下，于是元数据正常、头像消失。

4. **客户端版本差异**。
   旧版只认 `.codebuddy-plugin`，新版同时认 `.codebuddy-plugin` 与 `.workbuddy-plugin`。若导入的包被某个工具重新生成过目录名，可能出现"专家能显示、头像读不到"的半失效状态。

## 五、怎么自查（三步）

在出问题的那台机器上执行：

```bash
# 1. 头像文件在不在、多大
ls -l <专家目录>/avatars/

# 2. plugin.json 里的 avatar 字段指向哪
python -c "import json;print(json.load(open('<专家目录>/.codebuddy-plugin/plugin.json',encoding='utf-8'))['avatar'])"

# 3. 两者是否对得上、是否超过 5MB
python -c "import os;print(os.path.getsize('<专家目录>/avatars/expert.png'))"
```

三项都对得上还没图，就重启客户端再看一次（客户端有内存缓存，第一次读失败后会一直显示兜底样式，直到 `avatarUrl` 变化）。

## 六、本产品做了什么来避免同样的问题

1. **头像按 512×512、≤500KB 出**，远低于客户端 5MB 硬上限，也低于规范建议值。
2. **自检脚本按客户端同规则校验**：路径在包内、文件存在、PNG/JPG magic 正确、尺寸与体积合规。这一项不过，打包直接中止。
3. **打包脚本强制单一顶层目录**，并在打包后复核 zip 内顶层目录数量，不合规直接报错。
4. **不使用生成模型的原始文件名**，统一重命名为 `expert.png` 并在 `plugin.json` 中声明，避免"文件名带时间戳、路径写死"这类不一致。

```bash
python tools/selfcheck.py        # 看 avatar 那一行
python tools/build_release.py . ./dist
```

## 七、给外部那个包的建议

不改它的内容，只做三件事即可：

1. 用官方 `package_expert.py` 重新打包（或本产品的 `tools/build_release.py`，逻辑一致）；
2. 把头像压到 512×512、≤500KB（它现在是 1024×1024、91KB，客户端能读，但平台侧推荐 200×200—512×512）；
3. 换机导入后，先 `ls avatars/` 确认文件落地，再打开客户端。
