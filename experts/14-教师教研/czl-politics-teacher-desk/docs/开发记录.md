## 一、开发方式

本产品为独立开发。开发过程分四步：

1. **功能分析**：阅读目标专家的公开结构（元数据字段、能力清单、流程描述、输出规范），提炼"高中政治老师需要哪些产出"这一层功能需求，形成 `docs/产品规格说明书.md`。
2. **独立设计**：重新设计产品定位、任务路由、工作流划分、知识底稿体系、质量闸与检查脚本。
3. **独立实现**：所有提示词、工作流、知识底稿、模板、脚本、文档、头像均重新编写/生成。
4. **验证**：自检脚本 + 正反例测试 + 打包结构复核（见 `docs/测试报告.md`）。

## 三、借鉴与独立实现的边界

**借鉴的是通用方法**（这些属于教学法与软件工程的公共知识，不专属于任何产品）：

- "议题—情境—活动—评价"的课堂结构，是高中政治议题式教学的通行框架；
- "目标—活动—评价一致性"来自通用教学设计原理；
- "分档评分 + 踩分点"是考试评价的常规做法；
- "单元—课时—作业—诊断—讲评"的链路是教研工作的常见分工；
- 专家包的字段规范、目录结构、头像规格来自 WorkBuddy 官方开发规范。

**独立实现的是具体表达与结构**：

- 八条工作流的划分方式、每条工作流的九个要素、判断条件与异常分支，为本次设计；
- 五道质量闸（事实/对齐/可教/可评/可核）的命名与判定标准，为本次设计；
- 40 组易混概念的"一句话区分 + 判断口诀 + 典型设问"写法，为本次撰写；
- 五类错因（A—E）的判据与"看答案文本判、不靠问学生"的操作方法，为本次设计；
- 两个检查脚本的检查项与实现，为本次编写；
- 全部文案、示例、模板字段，为本次撰写。

**明确未做的事**：未复制目标专家的提示词段落、未沿用其能力清单表述、未复用其目录结构命名、未使用其头像或任何图片素材、未保留其作者字段与版本信息。

## 四、对目标专家的功能缺口分析（只谈功能，不谈优劣）

分析目标专家时，识别出六处可以补强的地方，本产品逐条做了对应设计：

| 观察到的缺口 | 后果 | 本产品的处理 |
|---|---|---|
| 只有流程描述，没有输入契约 | 用户给的信息不全时，产出结构随对话漂移 | W1 定义最小输入集 + 缺省值 + 一轮三问上限 |
| 没有可复用资料 | 每次都要靠模型即兴生成，术语与判据不稳定 | 8 份知识底稿，把判据固化下来 |
| 输出规范是原则性的 | "试题必须成套"这类要求无法验收 | 五道闸把原则变成可勾选的检查项 |
| 所有课型共用一套结构 | 复习课上成"再讲一遍"，讲评课上成"对答案" | 五种课型分开，各给骨架 |
| 没有质量检查手段 | 占位符残留、时间加总超课时这类错误无人拦 | 两个脚本 + 打包前自检 |
| 没有区分"诊断"与"讲评" | 拿到分数只会说"均分偏低" | W6 出诊断，W7 出讲评，中间用错因分类衔接 |

## 五、构建工具链

| 工具 | 作用 | 依赖 |
|---|---|---|
| `tools/selfcheck.py` | 包合规自检（元数据、头像可解析性、引用完整性、占位符） | 仅标准库 |
| `tools/build_release.py` | 自检 + 打包 + SHA256 + 文件清单 | 仅标准库 |
| `tools/avatar_prep.py` | 头像裁剪、缩放、压缩（无水印处理需在生成阶段控制） | 仅标准库 |
| `skills/.../scripts/lesson_lint.py` | 教案类交付物结构检查 | 仅标准库 |
| `skills/.../scripts/item_lint.py` | 试题类交付物结构检查 | 仅标准库 |

全部脚本不依赖第三方包，避免用户环境缺库导致工具不可用。

## 六、头像制作过程

1. 用文生图模型生成 1024×1024 方图（提示词包含：五十岁上下的中国高中教师、方框眼镜、藏青西装、手持教案夹与红笔、背后黑板上有三步议题链示意图、无文字无旗帜无徽章）。
2. 生成结果右下角带平台水印，且体积 681KB 超过规范建议的 500KB。
3. 用 `tools/avatar_prep.py` 裁掉下边 84px（含右侧 42px 对称裁切）去除水印，再缩放至 512×512，体积降至 253.5KB。
4. 自检确认：PNG 有效、512×512、253.5KB，可被客户端解析。

## 八、可复现性

任何人拿到本包，执行以下三步即可验证与重建：

```bash
python tools/selfcheck.py                 # 应输出「自检通过」
python skills/czl-politics-core/scripts/lesson_lint.py docs/testdata/sample-lesson.md
python tools/build_release.py . ./dist    # 生成 zip 与 SHA256
```

测试用例固定在 `docs/testdata/`，包含一个正例教案、一个反例教案、一个正例题组，可复现测试报告中的全部结论。
