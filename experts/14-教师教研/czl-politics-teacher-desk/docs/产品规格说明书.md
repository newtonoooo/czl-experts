## 一、这份产品解决什么问题

高中政治老师的时间不花在"上课"上，花在上课之前和之后：排单元、写教案、配课件、出题、改卷、做讲评、准备复习。这七件事彼此咬合，但绝大多数工具只覆盖其中一件，结果是老师要在五六个软件之间搬运同一份内容。

本产品把这条链做成一条生产线：**同一套术语、同一套结构、同一个质量闸**，从单元规划一路做到讲评课。它不替代教师判断，它替代"从零开始搭结构"的那部分劳动。

## 二、目标用户与使用场景

| 用户 | 具体场景 | 最痛的点 |
|---|---|---|
| 教龄 1—5 年的青年教师 | 明天要上公开课；第一次独立命一套单元卷 | 不知道一份合格教案/试卷长什么样，写出来"看着像"但经不起推敲 |
| 骨干教师 | 带备课组，要统一进度与命题标准 | 组内产出质量参差，评课时说不出具体标准 |
| 高三把关教师 | 一轮/二轮复习排期、模考后讲评 | 复习课容易上成"再讲一遍"，讲评课容易上成"对答案" |
| 教研组长 | 组织磨课、统一评分细则 | 评分标准写不细，几位老师打出来的分对不上 |

**不适用**：小学/初中道德与法治、高校思政课、考研政治。这三类的内容结构与课标要求不同，本产品的知识底稿不覆盖。

## 三、需求拆解

### 3.1 必须解决的问题

1. **产出结构不标准**：同一个"教案"，十个人十个样，无法互评、无法传承。
2. **评分标准写不细**：大量"言之有理即可"，导致跨教师打分不一致。
3. **目标与活动脱节**：目标写"培养政治认同"，活动却是教师讲授 + 学生填空。
4. **时政素材不可靠**：用自媒体转述当事实、旧闻当新闻、数据口径不明。
5. **诊断停留在分数**：知道均分低，不知道低在哪一类错因，下一步做什么说不清。
6. **容量失控**：一节课塞三个议题，或一份卷子的答案超出材料可推范围。

### 3.2 输入与输出

**输入**（最小集）：模块/课题 + 任务类型 + 课时 + 学情。
**输入**（增强集）：指定素材、成绩数据、现有教案/试卷、备课组进度。

**输出**：五类成品——单元规划、课时教案、课件框架、题组与评分标准、诊断/讲评稿，另有质检单。

### 3.3 处理步骤（通用）

判定任务 → 定课型 → 取知识底稿 → 套模板 → 填内容 → 过五道闸 → 跑脚本 → 写教师备注。

### 3.4 工具能力要求

| 能力 | 用途 | 本产品怎么做 |
|---|---|---|
| 读写本地文件 | 落盘交付物、读取成绩表 | 使用宿主文件工具，产出写 `政治备课产出/` |
| 联网检索 | 核实时政素材 | 需要时检索，来源分级 + 五步核验 |
| 结构检查 | 拦住低级错误 | 两个纯标准库脚本，不依赖第三方包 |
| 打包分发 | 生成可导入的 zip | `tools/build_release.py`，保证单一顶层目录 |

### 3.5 质量、速度、稳定性要求

| 维度 | 要求 | 落地方式 |
|---|---|---|
| 质量 | 交付物能直接上课/直接印 | 五道闸 + 模板字段完整性 |
| 一致性 | 同一类产出结构一致 | 模板固定字段，不允许自由发挥 |
| 可核查 | 每个数字有出处 | G1 事实闸，核不实标"需核实" |
| 速度 | 单课时教案一次成型 | 默认值策略，最多追问一轮 |
| 稳定性 | 不因缺信息而停滞 | 缺省假设 + 开头声明 + 末尾可改提示 |

## 四、与同领域产品的差异

只列可验证的差异，不比较"谁更好"：

| 维度 | 常见做法 | 本产品 |
|---|---|---|
| 产出形态 | 给建议、给思路、给清单 | 给成品：教案、题组、评分标准、讲评稿 |
| 评分标准 | 给参考答案 + "酌情给分" | 三档 + 零分 + 踩分点 + 常见错答给分表 |
| 质量保障 | 无 | 五道闸 + 两个检查脚本，未过项如实标注 |
| 复习课 | 与新课同一套结构 | 五种课型分开，复习课走"诊断—重建—补漏—变式—收口" |
| 时政素材 | 直接引用 | 来源四级 + 五步核验 + 素材卡六字段 |
| 诊断 | 报均分、排名次 | 五类错因 + 临界生 + 四类教学归因，不出排名 |
| 知识底稿 | 无或很少 | 8 份：教材地图、40 组概念辨析、课型框架、命题蓝图、诊断量表、时政规范、交付规范、来源索引 |

## 五、非功能约束

1. **不虚构资历**：不使用"名师""专家""三十年经验""参与命题"等无法验证的表述。
2. **不编造事实**：文件名称、文号、会议名称、统计数据一律带出处；核不实标"需核实"。
3. **不替代判断**：脚本只做机械检查，教学设计的好坏仍由教师判断。
4. **保护学生信息**：成绩分析去标识，不评价学生个人特质。
5. **版权边界**：不整段复制教材、教辅、试卷；引用教材只引短句并标注。

## 六、验收标准

| 项 | 标准 | 验证方式 |
|---|---|---|
| 包结构 | 符合 WorkBuddy 专家包格式 | `tools/selfcheck.py` 全项通过 |
| 头像 | 客户端可解析，不回落为文字头像 | 自检按客户端规则校验路径/格式/尺寸/体积 |
| 元数据 | 字段齐全、命名合规、标签与推荐语各 3 条 | 自检 |
| 工作流 | W1—W8 齐全，每条含九个要素 | 自检 + 人工抽查 |
| 脚本 | 正例通过、反例报错 | `docs/testdata/` 两组用例 |
| 打包 | zip 只有一个顶层目录 | `build_release.py` 结构复核 |
| 可导入 | 导入后能正常识别并对话 | **需在目标环境实测**（见测试报告"未验证事项"） |
