## 附录：关于"导入后头像变成一个字"的排查记录

这是你提的具体问题，我把查到的东西列在这里，包括查到哪一步、哪一步没能证实。

### 结论（可确证的部分）

平台的专家服务在读取本地专家包的头像时，走这一段逻辑（摘自客户端主进程的专家插件服务，变量名为压缩后形态）：

```js
async resolveAvatarUrl(e, t) {
  if (!e) return ``;
  if (/^(https?|data):/.test(e)) return e;
  let n = e.replace(/^\.\//, ``), r = A.resolve(t, n), i = A.resolve(t);
  if (!r.startsWith(i + A.sep) && r !== i) return ``;
  try {
    if (await pathExists$2(r)) {
      let s = await z.stat(r);
      return s.size > Hn
        ? (Q.warn(`[ExpertPluginService] resolveAvatarUrl: avatar file is too large:`, e, s.size), ``)
        : E.i(r);            // → 转成 local-file:// 本地文件 URL
    }
  } catch {}
  return ``;
}
```

其中 `Hn = 5242880`（5 MB）。

**这段代码说明：头像解析会返回空字符串 `""` 的只有四种情况：**

1. `avatar` 字段为空；
2. 相对路径解析后的文件**不存在**（扩展名不符、大小写不符、目录没被复制过去，都算）；
3. 文件**超过 5 MB**；
4. 路径**逃出插件目录**（含 `..`）。

界面拿到空字符串，就退化成显示名称首字——也就是你看到的"成字了"。

**渲染层还有一层转换**（`resolveAvatarUrl` → `resolveAvatarThumbnailUrl`），它只对特定 CDN 域名做缩略图参数拼接，本地文件 URL 会原样透传，不会二次失败。

### 与观察吻合的部分

本机 82 个已安装专家中，**48 个用 `avatars/expert.png`，4 个用 `avatars/expert.jpg`**。4 个 JPEG 里包含你刚装的 `highschool-english-teacher` 与 `highschool-history-teacher`——正是显示成文字的那两个。

同时我实测了对应的 CDN 地址：

| 地址 | HTTP | Content-Type |
|---|---|---|
| `.../eza_58a6b4b4-768.jpg`（历史） | 200 | image/jpeg |
| `.../eza_f73da67e-f81.jpg`（英语） | 200 | image/jpeg |
| `.../eza_44f5d61d-a4b.png`（数学） | 200 | image/png |
| 加 `imageMogr2` 缩略参数后（jpg 与 png 各测） | 均 200 | image/webp |

**所以 CDN 上没有差别，JPEG 本身也能正常返回。** 这排除了"服务器端拒绝了 jpg"。

再查 JPEG 文件结构：该图为 512×512 基线 JPEG，标记序列为 `SOI → COM → DQT → DHT → SOF0 → SOS → EOI`，结尾有 EOI，可正常解码。COM 段内容为 `Lavc61.19.100`（FFmpeg 的 libavcodec 版本串），说明它是用 ffmpeg 转码生成的，且**没有 JFIF/Exif 的 APP0/APP1 段**。

### 没能证实的一步

我**无法确认**"没有 APP0 段"是否是导致显示失败的直接原因。理由：

- 我无法在本机加载这两个专家并观察界面；
- 也无法在客户端的渲染进程里抓取 `<img>` 的 onError 事件。

因此关于 JPEG 的部分，我只能说：**存在相关性（4 个 JPEG 中至少 2 个确认失效），但因果未证实。**

### 本产品采取的措施（不依赖上述因果）

不赌单一原因，三件事都做了：

1. **改成 PNG**，与 48 个正常工作的同批专家保持一致，避开 JPEG 的全部不确定性。
2. **控制体积**：512×512、434 KB，远低于 5 MB 阈值。
3. **提供绕开文件系统的方案**：`scripts/embed_avatar.py` 把图片 base64 内联进 `plugin.json`。渲染层的 `resolveAvatarUrl` 明确支持 `data:image/` 前缀，命中即直接返回该 data URI，不查文件、不判体积。这是根治"导入丢文件"的手段。

### 你可以自己验的三步

1. 导入带文件夹的那个 zip，看头像是否正常。
2. 若仍显示文字，运行 `python scripts/embed_avatar.py --apply`，重启客户端。
3. 仍不行，说明是平台侧缓存或清单未被重新读取，需清 `~/.workbuddy/plugins/cache/experts/<包名>/` 后重装。
