# 更新日志

本产品采用语义化版本号：`主版本.次版本.修订号`

- **主版本**：工作流结构或输出格式发生不兼容变化（旧的使用习惯需要重建）
- **次版本**：新增工作流、新增参考文件、编码本扩表
- **修订号**：修正史实错误、修正文案、修正排版、修 bug

**工作流（6 条）**
- W1 备课流水线：课题 → 教案 + 学案 + 课件骨架，含史料链与问题链设计
- W2 命题流水线：范围 → 双向细目表 → 试卷 + 评分细则 + 答题卡
- W3 批改流水线：作答 → 采分点比对 → 24 码错因表 → 讲评脚本

### 发布前修正（首次上传被驳回后修复，未对外发布，故不升版本号）

| 问题 | 现象 | 原因 | 处理 |
|---|---|---|---|
| `defaultInitPrompt` 与 `quickPrompts[0]` 不一致 | 上传时被服务端整体驳回：`defaultInitPrompt.zh 必须与 quickPrompts[0].zh 一致` | 平台对这两处做**严格字符串相等**校验，中英文各校验一次；此前把"备课"放进了 defaultInitPrompt、把"命题"放在了 quickPrompts 首位 | 把 quickPrompts 首项改为与 defaultInitPrompt 完全相同的"备课"提示，命题与批改顺延为第 2、3 项；两种语言同步 |

| `keywords` 超出实测区间 | 未被驳回，但存在被裁断或拒收的风险 | 已发布专家的 keywords 实测为 5–9 条，本包原写 12 条 | 压到 9 条，保留搜索价值最高的词 |

同时给自检工具补上这几条规则（`validate_package.py` 报错、`run_tests.py` T16 断言），避免以后再犯：

- `defaultInitPrompt` 与 `quickPrompts[0]` 必须逐字相等（中英文各一次）
- `tags` 必须正好 3 条
- `quickPrompts` 3–6 条
- `keywords` 5–9 条

**规则依据**：本机 77 个带 quickPrompts 的已发布专家，`defaultInitPrompt` 与 `quickPrompts[0]` 在 zh 与 en 上全部完全相等，无一例外。这说明它是硬性相等，不是"意思相近即可"。

### 设计取舍（记下来，因为以后会有人问为什么这样做）

1. **不打包教材正文与真题原文。** 教材与试题的著作权状态复杂，商业分发风险大于收益；改为只给"册·单元·课·子目"坐标与改造方法。详见 `references/SOURCES.md`。
2. **不写页码。** 不同印次页码不同，写页码等于制造错误坐标。
3. **分类归到 15-Education。** 教育类专家不应放在运营/人力类目下。
4. **每条工作流都配异常码。** 教师输入不全时不是卡住，而是降级出成品并声明假设。
5. **明确拒绝押题、保分、编造史料、代写作业。** 这是产品边界，不是能力不足。

### 已知限制

- 未能验证在 macOS / Linux 客户端的表现（本轮测试仅在 Windows 11 + WorkBuddy 桌面端进行）。
- 图片作答的识别质量取决于上传清晰度，字迹潦草时只能对可辨部分评分。
- 卷型结构与分值需教师按本省当年试卷核对，产品内只给常见结构。
