# 排查报告：导入新环境后，选中专家时图标变成文字

- 排查对象：本机 `my-experts` 下全部 49 个自建专家包
- 排查环境：WorkBuddy 5.9.3（`app.asar` 构建时间 2026-10-27），Windows 11
- 排查时间：2026-11-01
- 结论：**图片本身没有问题，是"头像地址解析"没拿到可用的本地路径，前端回退成了姓名首字。**

---

## 一、界面为什么是"字"而不是"图"

专家头像组件是一个兜底式组件：`src` 有值就画图，`src` 为空就画 `children`——而 `children` 正是**专家名称的第一个字**。

```
<Avatar src={avatarUrl}>{firstCharOf(displayName)}</Avatar>
```

所以"成字了"这句话翻译过来就是：**`avatarUrl` 是空字符串**。它不代表图片坏了，而代表"没找到可用的图片地址"。

## 二、`avatarUrl` 是怎么算出来的（反查 app.asar 得到的确切规则）

主进程在加载专家时调用 `resolveAvatarUrl(avatar, expertRoot)`，逻辑按顺序是：

| 步骤 | 判定 | 不满足时 |
|---|---|---|
| 1 | `avatar` 字段非空 | 返回 `''` → 成字 |
| 2 | 以 `http(s)://` 或 `data:` 开头 → 直接用 | — |
| 3 | 去掉开头的 `./`，拼成 `expertRoot + 相对路径` | — |
| 4 | 结果必须仍在 `expertRoot` 之内 | 越界 → `''` → 成字 |
| 5 | 文件必须真实存在 | 不存在 → `''` → **成字（最高频）** |
| 6 | 体积必须 ≤ `5242880` 字节（5MB） | 超出 → 记一条 warn 后返回 `''` → 成字 |
| 7 | 转成 `local-file://` 地址交给渲染层 | 渲染层加载失败 → `<img onError>` → 成字 |

第 6 步的常数是从包里直接读到的：`Hn=5242880, ExpertCustomRuntime=...`。**注意这个上限是 5MB，不是 500KB**——500KB 是开放平台上传侧的更保守要求，两者不是同一个限制。

第 7 步还有一层：`resolveAvatarThumbnailUrl` 只对两个 CDN 域名生效（`openplatform-cdn.codebuddy.cn`、`acc-1258344699.cos.accelerate.myqcloud.com`），本地文件会原样透传。所以**本地图标不走缩略图服务，不存在"缩略图生成失败"这个原因**。

## 三、本机实测：找到了那一个"成字"的包

对 49 个专家逐个比对 `plugin.json` 的 `avatar` 字段与磁盘实际文件：

```
总数 49    异常 1
! czl-politics-teacher-desk  声明 avatars/expert.png  →  文件不存在
```

进一步看目录：

```
czl-politics-teacher-desk/
├── .codebuddy-plugin/plugin.json      ← avatar 指向 avatars/expert.png
├── agents/czl-politics-teacher-desk.md
├── skills/czl-politics-core/SKILL.md
└── avatars/                            ← 目录在，但是空的
```

`avatars/` 目录存在、里面没有任何文件。按第二节第 5 条，解析结果必然是空字符串，界面必然是"卓"字。
这就是你看到的那个现象，**与图片质量、模型、缓存都无关**。

其余 48 个包的头像体积分布在 8KB–486KB 之间，全部低于 5MB，路径均为 `avatars/expert.png`（正斜杠、相对路径、全小写），所以它们不出现这个问题。

## 四、导入到"新 WorkBuddy"后特有的三个原因

本机自检通过、换台机器就成字，通常是下面三件事之一：

| 排序 | 原因 | 为什么会发生 | 验证方法 | 修法 |
|---|---|---|---|---|
| 1 | **zip 里没有 `avatars/`** | 手动压缩时只选了看得见的 `.md`，或用了只打 `agents/` 的脚本；空目录本身不会进 zip | 解压后看 `czl-xxx/avatars/expert.png` 在不在 | 用会做存在性断言的打包脚本，缺文件直接中止 |
| 2 | **多套了一层目录** | 压缩时把上级文件夹也打进去，解压后层级错位 | 解压后第一层必须直接是专家目录（含 `.codebuddy-plugin`） | 进入专家目录再压缩 |
| 3 | **没有注册进 `marketplace.json`** | 只拷了目录没跑注册脚本；应用会做目录扫描补偿，但补偿时机不确定 | 看 `my-experts/.codebuddy-plugin/marketplace.json` 有没有这个 name | 跑 `register_expert.py` |

补充两个较少见但确实会触发的：`avatar` 被改写成 CDN 外链（换环境后该地址 404）、文件名大小写与声明不一致（Windows 不区分、平台侧区分）。

## 五、为什么"重做一张头像"修不好这个问题

如果是第 5 条（文件不存在），换任何一张图都不会出现——因为根本没有文件可加载。
如果是第 6 条（超 5MB），把 486KB 的图重画一遍也没用。
只有"图片编码损坏"这一种情况，重做才有意义；而编码损坏的表现通常是裂图，不是首字。

**正确顺序是：先验路径与文件是否存在，再谈图片质量。**

## 六、本产品（卓识教育-高中数学老师助手）怎么规避

| 措施 | 具体做法 |
|---|---|
| 头像规格 | `avatars/expert.png`，512×512，PNG，**174.9 KB**，全小写 ASCII，相对路径，无外链 |
| 体积留余量 | 规范上限 500KB、运行时上限 5MB，实际压到 175KB，为开放平台上传链路留足空间 |
| 去水印 | AI 生成图右下角带平台水印，已裁切后再量化压缩，成品无第三方标识 |
| 打包断言 | 官方 `package_expert.py` 会先跑校验；本包另设 `bin/check_package.py` 逐条验头像 |
| 自带诊断 | `bin/check_package.py` 把上述 7 条规则全部实现，一条命令出结论 |
| 注册 | 通过官方 `register_expert.py` 写入 `marketplace.json`，条目含 name/source/description/version |

## 七、在任何一台机器上 60 秒自检

```bash
cd <专家目录>
python bin/check_package.py .
```

输出会逐条打 `[OK]` / `[警告]` / `[FAIL]`。看到下面这行就说明文件侧没问题：

```
[OK]   avatar 存在且不超 5MB：174.9 KB
[OK]   avatar 格式：png
[OK]   avatar 尺寸：512×512
```

如果脚本全绿但界面仍是文字，请给我三样东西，可以直接定位：

1. `%USERPROFILE%\.workbuddy\logs\` 下最新日志里带 `[ExpertPluginService]` 或 `resolveAvatarUrl` 的行；
2. 该专家目录的完整 `dir /s` 输出；
3. 界面截图（列表页 + 选中后的输入框）。

## 八、给你的那一个包的修法（czl-politics-teacher-desk）

三选一：

1. 补一张 512×512 PNG 到 `avatars/expert.png`，然后重跑 `bin/check_package.py`；
2. 临时方案：把 `plugin.json` 的 `avatar` 改成一个能访问的 https 地址（不推荐，离线会回落）；
3. 如果这个包本来就没有做完，直接删掉目录并执行一次注册脚本，避免它出现在列表里显示成字。

> 说明：以上结论基于对 `app.asar` 的反查与本机 49 个包的实际比对，**未修改**该包任何文件。
