## 一、目标用户与实际使用场景

### 1.1 目标用户

| 用户 | 占比估计 | 特征 | 最痛的点 |
|---|---|---|---|
| 高中数学任课教师（1–15 年教龄） | 主力 | 每周 12–16 节课，带 2 个班，兼班主任或备课组长 | 备课与命题挤占休息时间，出卷要找题改题，批完还要统计 |
| 备课组长 / 教研组长 | 次要 | 要统一进度、统一命题、统一评分标准 | 组里几个人的卷子难度不一致，评分细则各写各的 |
| 新入职教师（0–3 年） | 增量 | 知识没问题，缺课堂经验与命题经验 | 教案写不出来、时间分配没概念、压轴题不知道讲到哪一步停 |
| 教培 / 家教从业者 | 边缘 | 一对一或小班，需要快速出针对性材料 | 没有题库，出题靠翻书 |

**明确不服务的用户**：学生本人（本产品是教师工具，学生辅导由同品牌另一条产品线承担）、
学校行政（不做排课、不做成绩上报）。

### 1.2 典型场景

| 场景 | 时间点 | 用户动作 | 现在怎么做 | 期望 |
|---|---|---|---|---|
| S1 日常备课 | 前一晚 20:00–23:00 | 明天要上《函数的单调性》 | 翻教参、改旧教案、找例题 | 20 分钟拿到能照着上的稿子 |
| S2 单元测验命题 | 单元结束前 3 天 | 出一套 19 题单元卷 | 题库挑题、改数字、拼卷、写答案 | 先看细目表，确认后一次成型 |
| S3 月考后讲评 | 考后第 2 天 | 分析成绩、准备讲评课 | Excel 拉均分、凭感觉选题讲 | 算出得分率，按优先级给讲评顺序 |
| S4 批改与评语 | 考后 1–3 天 | 批 45 份卷子 | 逐份手批、写套话评语 | 按细则分步批注，评语指出一个具体动作 |
| S5 公开课准备 | 提前 2 周 | 一节课要打磨 | 反复改设计、找亮点 | 有设计逻辑、有卡点预案、有课件脚本 |
| S6 压轴题教学 | 高三复习 | 讲第 19 题 | 自己先做一遍再讲 | 拆成得分点阶梯，标清哪几分能拿 |
| S7 查错审校 | 印卷前 | 检查自己出的卷子 | 自己看两遍 | 系统检查答案、题号、分值、超纲 |

### 1.3 使用环境

- 桌面 WorkBuddy 客户端，Windows / macOS。
- 教师通常**没有编程环境**：所有脚本必须零依赖、双击或一条命令可跑。
- 打印是硬需求：最终产物默认要能直接打出来发给学生。

## 二、需要解决的问题

按"不做会怎样"排序：

1. **时间被切碎**。备课、命题、批改三件事各自 1–4 小时，且都要在晚上做。产品必须把单件产物压到 20 分钟以内。
2. **答案会错**。教师最怕的不是写得不好，是答案错。错一题，一个班跟着错。产品必须有强制校验环节，且校验结果要看得见。
3. **命题结构失衡**。凭手感出卷，容易某一章出成半张卷、难度忽高忽低。产品必须把"先摊细目表"变成硬流程。
4. **统计靠心算**。均分、得分率靠计算器或 Excel 手拉，慢且易错。产品必须用程序算，且结果可复算。
5. **讲评没有依据**。45 份卷子批完，讲哪几题靠印象。产品要给出可解释的排序依据。
6. **教案写成套路文**。"引导学生体会""激发学习兴趣"这些话放在任何一节课都成立，等于没写。产品必须能识别并清除这类空话。
7. **格式劳动**。写完了还要排版、调字号、加页眉页脚。产品要直接出可打印的 Word。

**不解决的问题**：不做题库检索（版权风险）、不做在线组卷平台、不做学生画像（隐私）、不做成绩上报。

## 三、必要的输入与预期输出

### 3.1 输入（按模块的最小集）

| 模块 | 必需输入 | 可选输入 | 缺失时的处理 |
|---|---|---|---|
| 教案 | 课题、年级、教材版本 | 课型、班级均分、课时长度 | 年级教材缺失→按课标通用口径；课型缺失→默认新授课；课时缺失→默认 45 分钟 |
| 命题 | 考试范围、卷型（单元/月考） | 总分、题量、难度目标、班级均分 | 总分默认 150，结构默认 8+3+3+5，难度默认中等班 |
| 批改 | 学生作答（图片或文字）、评分细则或标准答案 | 满分、班级均分 | 细则缺失→按题型反推；图片不清→请补拍，不臆造 |
| 学情 | 分题得分表（CSV/TSV 宽表或窄表）+ 每题满分 | 及格线、优秀线、题号-考点对照 | 满分缺失→拒绝计算并说明；缺考→不计入该题分母 |
| 讲解 | 知识点或题目 | 学生层次、已学范围 | 层次缺失→默认中等班 |
| 课件 | 课题、教材版本 | 场景（常态/公开）、比例 | 场景默认常态课，比例 16:9 |
| 审校 | 待查的卷子/教案 | 本省考试说明 | 无考试说明→按课标通用范围，并标注"未按本省细则核" |

### 3.2 输出（交付物清单）

| 模块 | 对话内输出 | 文件输出 |
|---|---|---|
| 教案 | 结构说明 + 需拍板三处 | `.docx` 教案（含板书图、作业表） |
| 命题 | 细目表 → 逐题 → 答案 | 试卷 `.docx`（题目卷 + 答案卷可分开打印） |
| 批改 | 逐题批注 + 错因汇总 + 评语 | 批改记录 `.docx`（一页一份） |
| 学情 | 统计表 + 失分点 Top3 + 讲评顺序 | 学情报告 `.docx` |
| 讲解 | 学案正文 | 学案 `.docx` |
| 课件 | 逐页脚本 | 脚本 `.docx`（或 `.pptx`，视环境） |
| 审校 | 问题清单（按严重度） | 可选 `.docx` |

**每条交付固定附**：校验回执（5 项）+ 需教师拍板的具体条目 + 一个延伸追问。

### 3.3 输出格式约束

- 正文中文，术语用教材表述，不用"我们"以外的第一人称。
- 公式用可读文本（`f'(x)=3x²-6x`），不默认 LaTeX。
- 表格不超过 6 列；超过则拆分或改为列表。
- 单份文档不超过 8 页（试卷按题量自然长度）。

## 四、实现目标所需的通用处理步骤

七步，所有模块共用，轻重可调但顺序不变：

1. **接单定档**：把一句话需求转成工单卡（课题/年级教材/用途/班级档位/硬约束），最多问 3 个问题。
2. **路由**：判定走哪条产线（教案/命题/批改/讲解/课件/审校），只加载对应 Skill。
3. **取证**（条件触发）：仅当任务涉及成绩或学生作答时执行，数据一律交脚本计算。
4. **制造**：按产线模板产出初稿，同时写出"需要教师拍板"的条目。
5. **校验**：五关（回代/边界/范围与符号/方法互证/题号对齐），生成校验回执。
6. **成稿**：Markdown → `.docx`（A4、宋体小四、1.5 倍行距、页脚页码）。
7. **交付**：四段话术（做了什么 / 结构 / 拍板项 / 回执 + 追问）。

**判定条件**（决定是否回退）：

- 校验任一关未过 → 回到第 4 步重做，不许"改答案让它对上"。
- 教师改了档位或考点范围 → 回到第 1 步重开工单。
- 产出被 `qa_gate.py` 判为有错 → 修完再交付。

- 不依赖特定字体文件（Word 用系统自带宋体/黑体）。

## 六、对结果质量、速度和稳定性的要求

### 6.1 质量

| 指标 | 要求 | 验证方式 |
|---|---|---|
| 数学正确性 | 交付物中每道题的答案经五关校验 | 校验回执逐项可查 |
| 结构完整性 | 教案含 5 个必备部分；试卷题号/答案/分值对齐 | `qa_gate.py` + `check_package.py` |
| 空话率 | 教案中"放之四海皆准"的句子为 0 | `qa_gate.py` 空话词表 |
| 可打印性 | `.docx` 打开无乱码、表格不超页宽、页脚有页码 | `md_to_docx.py` 自检 + 人工打开 |
| 命题合规 | 总分等于目标、单模块≤35%、无超纲 | `blueprint.py` 体检 |
| 统计准确 | 均分/得分率/标准差可复算 | 手工核对已知样本（见测试报告） |

### 6.2 速度

| 任务 | 目标 | 说明 |
|---|---|---|
| 教案 | ≤ 5 分钟 | 含读材料、写作、出 Word |
| 单元卷 | ≤ 15 分钟 | 细目表确认后的时间；确认环节不计 |
| 学情报告 | ≤ 3 分钟 | 脚本 1 秒出数，其余是解读 |
| 单份批改 | ≤ 2 分钟 | 不含 OCR 等待 |
| 课件脚本 | ≤ 6 分钟 | 16 页左右 |

**稳定性优先于速度**：宁可多花 2 分钟跑校验，不可省掉。

### 6.3 稳定性

| 风险 | 处理 |
|---|---|
| 模型算错 | 统计类全部交脚本；数学答案走五关校验 |
| 上下文过长 | 材料按需 `Read`，不预加载；Skill 分模块加载 |
| 输入缺失 | 按默认档产出 + 首页标注假设，不空转追问 |
| 输出格式漂移 | 模板固定章节顺序，`qa_gate.py` 兜底 |
| 文件写不出 | 先 XML 自检再写盘，失败明确报错不产出半成品 |

## 七、与原产品的功能关系（差异化说明）

本产品与同类"高中数学老师助手"覆盖同一岗位，但做了以下取舍：

| 维度 | 同类常见做法 | 本产品做法 | 为什么 |
|---|---|---|---|
| 流程 | 能力清单 + 通用五步 | 六段流水线，P0/P3 强制 | 没有校验环节的能力清单，等于把风险留给教师 |
| 统计 | 让模型直接算 | 交脚本算，报告里写明"可复算" | 模型算均分必错，这是硬伤 |
| 命题 | 直接写题 | 先摊表，表过体检才写题 | 结构失衡是出卷第一大问题，靠人眼看不住 |
| 讲评 | 按得分率排序 | 按"可挽回分×可教性"排序 | 压轴题得分率最低，但讲它在多数班是浪费 |
| 教案 | 教学目标 + 过程表 | 加时间预算、问题链、板书分区、卡点话术 | 教师真正照着上课时缺的是这些 |
| 校验 | 无 | 五关 + 回执 | 答案错是本类产品最大的信任风险 |
| 交付 | 对话内 Markdown | 默认出 `.docx` | 教师最终一定要打印 |
