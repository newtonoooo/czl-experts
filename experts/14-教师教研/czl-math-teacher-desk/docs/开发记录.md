## 一、开发起点：先明确"要解决什么"

开发前先做了一件事：确认同类"高中数学教学助手"这个岗位**实际要干的活有哪些**。为此通读了参考产品的目录结构、
Agent 描述、参考资料分类与工作流章节，从中提取**功能清单**（能做什么），而不是提取**表达**（怎么写）。

提取出的功能域（7 类）：教案设计、试题命制、作业批改、学情分析、知识点讲解、高考真题解析、课件制作。

这一步的产出是 `docs/产品规格说明.md` 的第一、二、三节——用户、场景、问题、输入输出。
规格定完才动笔写提示词，避免"先写文案再想功能"。

## 三、这次补了什么（相对同类产品的增量）

不是"把原来的做一遍"，是补了五个原来没有的东西：

### 1. 数学校验变成硬关卡

同类产品的规范是"关键计算用工具验证"——一句话，没有可执行的判定。本产品做成五道有通过条件的关卡
（回代 / 边界 / 范围与符号 / 方法互证 / 题号对齐），并要求输出**校验回执**附在交付消息末尾。
有未消除的不确定必须写明题号。这一条是产品信任度的地基。

### 2. 统计从"模型估"改成"程序算"

均分、得分率、标准差、分数段，全部交 `score_report.py` 算。报告首行写明"本报告全部数字由脚本计算，可复算"。
模型在这类计算上必错，这是硬伤，不能靠提示词约束解决。

### 3. 组卷强制先摊表

`blueprint.py` 把"总分对不对、模块占比是否失衡、难度系数预估多少"变成可执行的检查。
不通过就报错，不进入写题环节。这条把"凭手感出卷"的结构性风险挡在前面。

### 4. 讲评排序给了算法

不是按"得分率最低"排，按 `可挽回分 × 可教性` 排。压轴题得分率最低，但讲它在多数班是浪费——
这个判断原来靠教师经验，现在有可解释的算法。

### 5. 教案加了"能不能照着上"的字段

时间预算表（合计必须等于课时）、问题链（含预期错误回答与降档问法）、板书分区图、三处卡点话术。
判断标准很土：把"引导学生体会""激发兴趣"划掉，看还剩多少字。

## 四、关键技术决定

| 决定 | 理由 | 代价 |
|---|---|---|
| 工具全部零依赖（纯标准库） | 教师电脑不一定有 pip，装不上就废了 | `md_to_docx.py` 要手写 OOXML，代码量约 500 行 |
| 自己做 Word 生成而不依赖 python-docx | 同上；且能控制 A4/中文字体/页脚页码 | 只支持 Markdown 子集，复杂公式渲染为文本 |
| 学科材料放 `references/` 让 Agent 按需 Read | 避免启动时全量注入导致上下文膨胀 | 首轮响应略慢 |
| 不使用 `knowledge` 字段 | 该字段不在公开规范里，行为不确定 | 若平台后续支持，可再迁移 |
| `categoryId` 用 `15-Education` | 与同品牌教育系列一致 | 本地 `validate_expert.py` 分类表只有 12 类，会判错，已在测试报告中如实记录 |
| 头像压到 175KB | 规范上限 500KB、运行时上限 5MB，留足余量 | 需量化到 256 色，肉眼在列表尺寸下无差别 |

## 五、开发过程与验证

### 5.1 步骤

1. 建目录（官方 `init_expert.py`）→ 填元数据 → 写主提示词
2. 写 7 个 Skill（每个含触发条件、方法、边界）
3. 写 4 份学科材料
4. 写 6 个工具脚本（先写、先跑、先修）
5. 生成头像 → 裁水印 → 量化压缩 → 校验
6. 做三份真实样本（教案 / 细目表 / 学情报告）→ 过质检 → 出 Word → 用 python-docx 回读验证
7. 写 `self_test.py`（用已知答案的样本比对）→ 修到 25/25
8. 校验 → 注册 → 打包 → 验包

### 5.2 开发中真实修掉的缺陷

| 缺陷 | 怎么发现的 | 怎么修的 |
|---|---|---|
| 分数段分档在小分值卷上退化成"16-16""15-15" | 用 20 分制样本跑统计 | 低于 100 分改用等距六档 |
| 教案时间预算把正文举例的 ′ 也加进去，算出 311 分钟 | 用模板文件跑 `qa_gate` | 改为只读"时长"列求和，退化时才用全文正则并降级为警告 |
| 细目表测试样本单模块占比 46%，被判不合格 | `self_test` 第 7 条失败 | 调整样本分值到 31.8%，并在工具里加 `--unit` 单元卷模式 |
| 生成文档里带 ✓/⚠ 符号，Word 中可能变方块 | 回读 docx 时看到标题含 ⚠️ | 从生成的 Markdown 中去掉表情符号 |
| 包名与同系列不一致（`-teaching-desk` vs `-teacher-desk`） | 扫描本机 49 个专家时发现同系列命名 | 全量重命名并替换 5 个文件中的引用 |

以上都是**实际跑出来的**，不是预想。测试报告里能看到对应的通过项。
