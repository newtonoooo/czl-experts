# 工作流规格

六个工作流串成一条主链，另有两条支链。文档格式统一：名称 / 职责 / 输入 / 执行步骤 / 判断条件 / 输出 / 异常处理 / 依赖 / 与其他工作流的关系。

```
W1 接单定档 ──► W2 取证 ──► W3 制造 ──► W4 校验 ──► W5 成稿 ──► W6 归档
                   ▲            │            │
                   └──── 回退 ───┘◄───────────┘
```

---

## W1 接单定档

**职责**：把一句模糊需求固定成可执行工单，决定后续走哪条产线。不做任何内容生产。

**输入**
- 必需：用户的原始请求文本
- 可选：年级、教材版本、章节、用途、班级均分、课时长度

**执行步骤**
1. 从请求中抽取五要素：课题/考点、年级教材、用途、班级档位、硬约束。
2. 缺项按"改起来最贵"排序，最多追问 3 项：先问给谁用（年级+教材+章节），再问干什么用，再问什么水平。
3. 判产线：按关键词表映射到教案/命题/批改/讲解/课件/审校。
4. 复述档位给用户确认（一句话），不等确认也可开工，但必须复述。
5. 加载对应 Skill（只加载一条，不全读）。

**判断条件**
- 五要素缺 ≥3 项 → 追问；缺 ≤2 项 → 按默认档补，首页标注。
- 用户明确说"别问了直接做" → 立即按默认档开工，不再追问。
- 信息自相矛盾（如"高三复习课"却指定"必修一第一章"）→ 指出矛盾，请用户二选一，不自行圆场。
- 请求涉及造假（改分、代写作业）→ 拒绝并说明边界，转正常教学场景。

**输出**：工单卡（五要素 + 产线 + 默认档标注）

**异常处理**
- 完全没有课题 → 按知识模块给 6–8 个可选项让用户点。
- 教材版本未知 → 按课标通用口径，标注"可按你的版本调整"。

**依赖**：无（链路起点）

**与其他工作流的关系**：向 W2/W3 传工单卡；W3 收到用户改档后回到本工作流重开。

## W2 取证

**职责**：把成绩数据、学生作答转成可计算、可复算的结构化结果。**条件触发**，不涉及数据时整段跳过。

**输入**
- 必需：分题得分表（CSV/TSV）或学生作答（图片/文字）+ 每题满分
- 可选：及格线、优秀线、题号-考点对照表、评分细则

**执行步骤**
1. 判断数据形态：宽表（一行一学生）、窄表（三列长格式）、图片作答三种。
2. 表格类 → 直接调 `bin/score_report.py`，传入 `--full-marks`。
3. 图片类 → 先 OCR 识别，识别不清的逐处标出，请用户补拍或转文字。
4. 读取脚本输出的 JSON，把数字写进报告骨架，不自算任何统计量。
5. 按"可挽回分 × 可教性"取前 3 作为讲评重点。

**判断条件**
- 满分列缺失或与题号数量不一致 → 停止计算，说明缺什么，不猜。
- 某题得分率为 0 → 先怀疑数据错位或漏批，提示核对，再下结论。
- 缺考/空值 → 不计入该题分母；若用户要求按 0 分计，重跑并注明口径。
- 人数 < 10 → 统计意义有限，报告中注明。

**输出**：统计 JSON + Markdown 学情报告草稿

**异常处理**
- CSV 编码异常（GBK/UTF-8 混用）→ 用 `utf-8-sig` 重试，仍失败则提示另存为 CSV。
- 题号非数字（如"15(1)"）→ 按字符串处理，排序用数字前缀。

**依赖**：`bin/score_report.py`

**与其他工作流的关系**：为 W3（批改产线/讲评课）提供数据；结论作为 W3 的输入，不并行。

## W3 制造

**职责**：按产线产出初稿。本工作流内含五条并行支线，一次只走一条。

**输入**：W1 的工单卡（+ W2 的结论，若走批改线）

**执行步骤（按支线）**

| 支线 | 步骤 |
|---|---|
| 教案 | 判课型 → 排时间预算（合计=课时）→ 写 3–5 个问题链（含预期错误回答与降档问法）→ 选例题（按档位选起点）→ 设计板书分区 → 写三处卡点话术 → 分层作业 |
| 命题 | 摊细目表 → `blueprint.py` 体检 → 交用户确认 → 逐题写 → 写答案与步骤分 → 写干扰项对应错法 |
| 批改 | 取评分细则 → 逐题对步骤给分 → 打错因码（C/K/R/M/S）→ 写两句评语（一句夸动作、一句改一个动作）→ 列订正范围 |
| 讲解 | 五段式：困境 → 定义怎么长出来 → 例题 → 三个反例 → 变式 → 首步动作一句话 |
| 课件 | 定三件事（比例/场景/讲义）→ 按 8 段排页 → 每页写四要素（内容/讲述词/停留/板书同步）→ 标需补素材 |

**判断条件**
- 命题支线：细目表未确认 → 不写题。
- 教案支线：时间预算合计与课时差 >15% → 删例题，不压练习。
- 批改支线：评分细则缺失 → 先反推细则再批，不凭印象给分。
- 任一产线：用户给的是"改写已有材料" → 只改指定部分，不重写全篇。

**输出**：Markdown 初稿 + 「需要你拍板的三处」清单

**异常处理**
- 教材页码/例题编号不确定 → 写"教材本节例 2 位置"，不臆造页码。
- 用户在过程中改需求 → 回 W1 重开工单，不在半成品上叠改。

**依赖**：7 个 Skill（按支线加载）、`bin/blueprint.py`、`references/` 学科材料

**与其他工作流的关系**：初稿交 W4；W4 判不过则退回本工作流重做。

## W4 校验

**职责**：交付前的强制关卡。五关全过才允许进入 W5。

**输入**：W3 的初稿（含所有题目与答案）

**执行步骤**
1. ① 回代：把每个答案代回原式/原条件，写明回代过程。
2. ② 边界：对最易错的 2 处取极端值/端点/临界情形验证。
3. ③ 范围与符号：检查定义域、开闭区间、正负号、概率和是否为 1。
4. ④ 方法互证：对 1 道关键题用两种方法各算一遍，答案须一致。
5. ⑤ 题号-答案对齐：题干数=答案数，小问齐全，选项无重复漏项，总分用脚本加。
6. 生成校验回执（5 项 + 未消除的不确定）。

**判断条件**
- 任一关不过 → 退回 W3 重做，**禁止微调答案使其对上**。
- ④ 两解不一致 → 停下，说明两种方法各得什么，请用户判断题目本身是否有问题。
- 题目条件不足导致多解 → 指出缺什么条件，给两种补法让用户选。
- 无法消除的不确定 → 写进回执的"未消除"行，不隐藏。

**输出**：校验回执 + 修正后的终稿

**异常处理**
- 完全算不出 → 说清算到哪一步卡住，给下一步方向，不编答案。
- 用户催"先给我，别验了" → 说明风险，仍交付但回执标红"未校验"。

**依赖**：`skills/math-verify`、`bin/qa_gate.py`

**与其他工作流的关系**：把关 W3，放行 W5。

## W5 成稿

**职责**：把终稿转成可打印、可分发、格式稳定的文件。

**输入**：W4 放行的终稿 Markdown + 页脚信息（课题/年级/教材版本）

**执行步骤**
1. 按 `templates/` 校正章节顺序（不自创结构）。
2. 运行 `bin/md_to_docx.py`，指定 `--footer`。
3. 脚本内置 XML 自检；失败则修 Markdown 重跑，不产出半成品。
4. 用 `present_files` 交付。
5. 写交付话术四段（做了什么 / 结构 / 拍板三处 / 回执 + 一个追问）。

**判断条件**
- 纯口头答疑 → 不出文件（别为了交付而交付）。
- 文档超过 8 页 → 检查是否该拆成"题目卷 / 答案卷"两份。
- 表格列数 >6 → 拆表或改列表，避免超页宽。

**输出**：`.docx` 文件 + 交付话术

**异常处理**
- 环境无 Python → 退化为对话内 Markdown，并说明如何自行转 Word。
- Word 打不开（自检通过但用户环境异常）→ 提供 `.md` 原稿作为兜底。

**依赖**：`bin/md_to_docx.py`、`present_files`

**与其他工作流的关系**：链路终点（交付侧）。

---

## W6 归档

**职责**：把本次产出中可复用的部分抽成清单，供下次直接改。**可选，只在同一单元连续作业时提一次。**

**输入**：W5 的成稿

**执行步骤**
1. 抽取四类可复用件：问题链、原创题、易错点、板书/素材位。
2. 写成 6–10 行清单，标注各自适用场景。
3. 告诉用户存哪儿（建议按"教材版本/册/章"建目录）。
4. 不建库、不写系统、不要求用户维护。

**判断条件**
- 用户只做一次性任务 → 跳过，不打扰。
- 同一单元第二次作业 → 提一次，仅一次。

**输出**：复用清单（对话内，5–10 行）

**异常处理**
- 用户已有自己的归档方式 → 只给内容，不提建议。

**依赖**：无

**与其他工作流的关系**：链尾，不影响主链。

---

## 支链 A：审校模式

**触发**：用户提供现成材料并要求"看看有没有问题"。

**流程**：W1（确认审校范围）→ W4（五关 + 命题/教案专项检查）→ 输出问题清单（按严重度：致命/严重/一般/建议）→ 跳过 W3、W5（除非用户要求出修订稿）。

**关键判断**：只列问题，不擅自重写。用户说"顺手改了吧"才改，且标出改动处。

---

## 支链 B：复合任务

**触发**：一次给两件事（如"分析月考 + 备讲评课"）。

**流程**：W2（取证）→ W3 批改支线（定讲评顺序）→ W3 教案支线（写讲评课教案）→ W4 → W5。

**关键判断**：必须串行，前段结论是后段输入。并行产出等于两份互不相关的材料。

---

## 工作流之间的数据契约

| 从 | 到 | 传什么 | 格式 |
|---|---|---|---|
| W1 | W3 | 工单卡 | 五字段文本 |
| W2 | W3 | 统计结果 + 讲评重点 | JSON + 表格 |
| W3 | W4 | 初稿 | Markdown |
| W4 | W5 | 终稿 + 回执 | Markdown + 回执文本 |
| W5 | W6 | 成稿路径 | 文件路径 |
