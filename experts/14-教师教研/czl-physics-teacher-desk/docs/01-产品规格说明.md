## 0. 这份规格是怎么来的

先做功能分析，再写规格，最后写实现。分析对象是平台上已上架的一个高中物理教师助手类专家，方法是**逐文件阅读它的元数据、主提示词、输出模板与知识库结构**，提取"它能完成什么任务"，转成需求；再对照一线教师的真实工作流，找出它没覆盖的环节。

分析只用于理解**功能边界与问题域**。本产品没有复用它的文案、提示词、模板措辞、文件结构或头像；所有工作流定义、评分与错因体系、模板与脚本均为本次重新编写（见 `04-文件清单与开发记录.md` 的来源声明）。

## 1. 目标用户与实际场景

| 用户 | 场景 | 频率 |
|---|---|---|
| 高中物理任课教师（1–20 年教龄） | 备明天的课、出单元卷、考完分析、上讲评课 | 每天 |
| 备课组长 / 教研组长 | 统一进度、统一难度、组内共享学案 | 每周 |
| 新入职教师 | 需要"能照着上"的教案与规范作答示范 | 每周 |
| 教研员 | 命题说明、质量分析、区域对比 | 每月 |

不使用本产品的人：学生本人（走学习辅导类专家）、家长（走升学规划类专家）。

## 2. 要解决的问题

按"耗时程度 × 专业门槛"排序：

1. **备课耗时且质量不稳**：一节课要写目标、排环节、配例题、出作业，2–4 小时；新教师容易写成知识点罗列。
2. **命题缺少结构**：凭感觉挑题，考点重复、难度失控、没有评分细则，考完无法解释"为什么这么考"。
3. **批改口径不一**：同一道题不同老师给分不同；学生只知道对错，不知道丢分在哪一步。
4. **成绩分析停在平均分**：有数据但算不出难度、区分度，找不出共性错因。
5. **讲评课效率低**：按卷面顺序讲，讲完下次照错。
6. **教研沉淀缺失**：一次备课的经验留在个人电脑里，组内无法复用。

## 3. 必要的输入与预期输出

| 工作流 | 最小输入 | 预期输出 |
|---|---|---|
| W1 定标 | 课题、年级 | 目标表（四素养 + 检测话术）、重难点、起点假设 |
| W2 设计 | W1 + 课型 + 课时 | 教案、学案、分层作业、板书结构、课件大纲 |
| W3 命题 | 范围、用途、总分、时长 | 双向细目表、试卷、答案、评分细则 |
| W4 诊断 | 成绩表（学号 + 分题得分） | 难度/区分度、分数段、错因排序、分层名单 |
| W5 复盘 | W4 报告或错题清单 | 讲评课设计、变式题、当堂检测、跟踪表 |
| W6 沉淀 | 前序产出 + 用途 | 一页纸教研记录 |

通用输出要求：A4 打印版 .docx、文件命名规范、末尾「需您确认」三条。

## 4. 通用处理步骤（五段闭环）

```
W1 定标 → W2 设计 → W3 命题 → W4 诊断 → W5 复盘 → （回到 W1）
```

每个工作流的九要素（职责/输入/步骤/判断/输出/异常/依赖/关系）见 `skills/czl-physics-desk/references/09-工作流规范.md`。

设计原则：
- **先骨架后内容**：正式卷先给细目表，教案先给目标与时间轴，确认后再展开。
- **数据说话**：涉及数值必须过脚本，不靠心算。
- **交付即可用**：所有文档类产出同步给 A4 打印版。

## 5. 工具能力与技术接口

| 脚本 | 能力 | 依赖 |
|---|---|---|
| `blueprint.py` | 细目表生成 + 总分/难度/配比/用时校验 | 标准库 |
| `rubric_builder.py` | 步骤清单 → 分步评分细则 | 标准库 |
| `item_analysis.py` | 成绩表 → 三率一分、P/D、分数段、讲评建议 | 标准库 |
| `physics_calc.py` | 55 条常用公式计算与自检 | 标准库 |
| `docx_lite.py` | Markdown → A4 .docx（页眉页脚、表格、分页） | 标准库 |
| `self_test.py` | 全量冒烟测试 | 标准库 |

不依赖：网络、pip 安装、Office 组件、python-docx。
输出格式：Markdown（正文）+ CSV（数据交换）+ DOCX（打印）。

## 6. 质量、速度与稳定性要求

| 维度 | 要求 | 验证方式 |
|---|---|---|
| 学科正确性 | 公式带条件、答案可复算、单位与有效数字正确 | 脚本抽验 + 人工复核 |
| 结构完整性 | 试卷四件套齐全；教案含目标/时间轴/作业/板书 | 交付前清单 |
| 可打印性 | A4、边距 18mm、表格与题目不跨页 | docx 结构校验 + 人工翻页检查 |
| 响应速度 | 单次任务 1 轮内给骨架，2–3 轮内给成品 | 对话实测 |
| 稳定性 | 脚本零依赖、可在无网环境运行 | `self_test.py` 6/6 |
| 可追溯 | 真题标年份卷别；外部素材标许可 | 交付审查 |

## 7. 相对参考对象的改进（差异点）

| 参考对象的做法 | 本产品的做法 | 为什么改 |
|---|---|---|
| 7 个并列模块，任务之间无衔接 | 五段闭环 W1–W5 + 沉淀 W6，上游产出直接作为下游输入 | 教学本身是闭环，孤立模块会导致"备完课不知道怎么考" |
| 只给"注意公式适用条件"的原则 | 55 条公式表逐条写适用条件与高频错 | 原则无法执行，表可以 |
| 批改只到"错因分类" | 错因码 E01–E20 + 三步赋分 + 讲评优先级矩阵 | 分类不落到码，统计不了 |
| 学情分析靠人工统计 | 脚本算 P/D/分数段并给讲评建议 | 手算 45 人 × 12 题不现实 |
| 打印版描述为"用 python-docx" | 自带零依赖 docx 生成器（A4/页眉页脚/表格/分页） | 教师机器上通常没有 python-docx |
| 无命题校验 | 细目表脚本自动校验总分/难度/配比/用时 | 命题最常见的错是总分对不上 |
| 无版本对照与课时建议 | 四版教材内容块对照 + 课时区间 | 换教材/跨年级时最需要 |

## 8. 非功能要求

- **隐私**：只要学号与得分，不索取姓名；分析结果不写入公开目录。
- **版权**：不打包教材、教辅、真题原卷；引用标年份卷别；外部素材只用 CC0/CC BY/公有领域。
- **合规**：不代写学生作业、不押题卖题、不做超出教材的实验指导。
- **可维护**：知识条目与脚本分离；改教材版本只改 reference，不改提示词。

## 9. 验收标准

1. `self_test.py` 全部通过；
2. 专家包通过 `validate_expert.py` 校验（分类 ID 见风险清单说明）；
3. 用 3 个真实任务（备课/命题/学情）各跑一轮，产出可直接打印；
4. 打印版在 Word/WPS 中打开无错位、无跨页断裂；
5. 交付文档齐全（规格/说明/文案/清单/测试/风险）。
