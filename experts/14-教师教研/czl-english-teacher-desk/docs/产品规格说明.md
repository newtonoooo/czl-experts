## 一、目标用户

| 用户 | 特征 | 最常卡在哪 |
|---|---|---|
| 高中英语任课教师（主用户） | 教 1–2 个班，周课时 10–14，兼任班主任或备课组任务 | 备课时间被挤压；命题靠拼卷；批改量大且标准不稳 |
| 备课组长 / 教研组长 | 需要对全组交付物把关 | 组内标准不一，缺少可复用的模板与口径 |
| 新手教师（0–3 年） | 教材不熟，课堂节奏把握弱 | 目标写不具体，活动设计撑不满一节课 |
| 转岗/跨学段教师 | 不熟悉新高考题型与评分 | 命题不合规，写作批改没尺子 |

非目标用户：学生本人（本产品不做家教式答疑）、家长、教培销售。

## 二、真实使用场景

**场景 A：周日晚上的备课**
教师下周要上必修一 Unit 3 阅读课，手头只有教材和教参。她需要的不是"一份漂亮的教案"，而是"明天能照着上的流程 + 三层作业 + 一个能检查学生是否学会的评价点"。

**场景 B：月考后的两天**
成绩出来了，班里均分比上次低 4 分。教师要在两天内完成：分析失分点 → 出一节讲评课 → 布置针对性练习。她现在靠翻卷子凭印象找问题。

**场景 C：作文批改的深夜**
30 篇读后续写，每篇至少 3 分钟，批完两小时，评语高度雷同（"语言流畅，注意时态"），学生看完不知道改什么。

**场景 D：备课组要一套单元卷**
要求 100 分、覆盖本单元、难度适中、有答案和解析、能直接印。教师手上没有题库授权，只能拼凑。

## 三、需要解决的问题

1. **断链**：备课、命题、批改、讲评各自为战，上一环的结论传不到下一环。
2. **口径不齐**：同一份卷子，不同教师定的难度、评分尺度不同。
3. **不可执行**：目标和评语停留在"培养能力""语言流畅"，学生和教师都无法据此行动。
4. **重复劳动**：每次都要重新描述教材、班级、范围。
5. **合规焦虑**：想用现成语篇和真题，但不确定能不能复制分发。

## 四、必要输入与预期输出

| 场景 | 最小输入 | 预期输出 | 交付形态 |
|---|---|---|---|
| 备课 | 教材版本 + 单元 + 课型（+ 班级层次） | 单元设计 + 课时教案 + 分层作业 + 评价量表 | 对话版 + docx |
| 命题 | 范围 + 用途（+ 分值/难度） | 细目表 + 试卷 + 答案与解析 + 质检单 | docx（学生版/教师版分开） |
| 批改 | 题目要求 + 学生原文（+ 评分标准） | 批改单 + 班级错误台账 | 对话版 + docx（可批量） |
| 学情 | 成绩表（分板块） + 满分 | 统计表 + 得分率 + 失分点 + 下一步 | 对话版 + docx + JSON |
| 讲评 | 错题/台账（+ 课时） | 讲评课教案 + 变式题组 + 当堂检测 | 对话版 + 课件页纲 |
| 复盘 | 两次数据 + 教学动作 | 动作—结果对照 + 归因 + 三个决策 | 一页纸 docx |

## 五、通用处理步骤（所有场景共用）

1. **入口判断**：识别属于哪一段，用一句话说明判断结果。
2. **口径对齐**：确认范围、对象（层次）、用途三件事。
3. **最小输入**：只问缺了会做错的项，其余按默认档并在开头标注前提。
4. **调取知识**：读对应 workflow 与 reference，不凭记忆。
5. **产出**：按固定骨架（结论 → 证据 → 方案 → 质检单）。
6. **质检**：脚本自检 + 人工清单，未通过项写明原因。
7. **交付**：对话版 + 打印版（默认 docx）；文件用呈现方式打开。
8. **追问一个**：给出一个与本次内容直接相关的延伸问题。

## 六、工具与技术接口

| 能力 | 用途 | 实现 |
|---|---|---|
| 文件读取 | 读教材页图片、成绩表、学生作文 | 平台内置读文件/识图能力 |
| 文档生成 | docx 打印稿 | 文档技能（本地 Office 通道） |
| 课件生成 | pptx 或分页大纲 | 课件技能；不可用时降级为大纲 |
| 数据统计 | 成绩、得分率、失分点 | `scripts/item_stats.py` |
| 结构校验 | 细目表题量/分值/难度 | `scripts/blueprint.py` |
| 评分折算 | 写作四维 → 档次 | `scripts/essay_score.py` |
| 成品自检 | 题号/选项/分值/答案/隐私 | `scripts/qa_check.py` |

无网络依赖；不调用外部 API；不写入系统目录。

## 七、质量、速度与稳定性要求

| 维度 | 要求 | 现状 |
|---|---|---|
| 语言准确性 | 英文示例语法正确、搭配地道；不确定标注待核实 | 由 `references/language-qa.md` 清单约束，交付前自检 |
| 结构完整性 | 教案含目标/重难点/过程/作业/评价；试卷含细目表/答案/质检 | 固定骨架，缺项即视为未完成 |
| 一致性 | 答案数量=题目数量；分值合计=卷头满分 | 脚本可验证（qa_check.py） |
| 可解释性 | 难度、档次、失分点均给依据 | 每个结论附证据行 |
| 速度 | 单节课教案 1 轮对话内出稿；一套 100 分卷分 2–3 轮（细目表确认后出卷） | 受模型与教师确认节奏影响 |
| 稳定性 | 缺输入时按默认档产出，不空转；脚本失败时降级为手工计算并标注 | 异常矩阵覆盖 13 类情况 |
| 可复现 | 同一输入、同一默认档，结构一致 | 骨架与脚本保证结构稳定 |

## 八、与同领域通用助手的差异

| 维度 | 通用助手 | 本产品 |
|---|---|---|
| 组织方式 | 功能并列（教案/出题/批改各做各的） | 六段闭环，段间有数据依赖 |
| 输出 | 一次性文本 | 结论 + 证据 + 方案 + 质检单 |
| 可验证性 | 靠人看 | 4 个脚本可跑，13 个回归用例 |
| 口径 | 通用教育话语 | 卷面结构、评分维度、错因分类、统计定义均固定 |
| 合规 | 不涉及 | 素材边界单列，明确不可复制项与替代方案 |

## 九、不做清单

- 不做整卷真题复制、教材原文转录。
- 不做听力音频、视频生成。
- 不做学生个人排名公示、不收集身份信息。
- 不代替教师定等、不承诺提分。
- 不做代写论文、留学文书、成绩造假。

## 十、验收标准

1. 六个工作流文件齐备，每份含九要素（职责/输入/步骤/判断/输出/异常/依赖/关系 + 触发）。
2. 10 份知识库可被主提示词按需索引，路径正确。
3. 4 个脚本在干净环境（仅 Python 标准库）可运行，13 个回归用例全通过。
4. 头像 512×512、PNG、≤500KB、路径与配置一致。
5. 打包后解压可还原全部文件，`plugin.json` 无 `[TODO]`。
6. 文档齐备：规格、工作流、使用、开发记录、测试、风险、展示文案。
