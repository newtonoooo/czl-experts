# 专家图标不显示（显示成文字）问题诊断

- 现象：专家包导入到新的 WorkBuddy 后，在专家列表/选择器里**没有头像**，只显示一个带底色的**文字**（名称首字）。
- 诊断对象：`highschool-english-teacher`（1.0.0，作者 xtgxiso），安装位置
  `%USERPROFILE%\.workbuddy\plugins\marketplaces\experts\plugins\highschool-english-teacher\`
- 诊断日期：2026-11-01
- 方法：读取客户端渲染代码与主进程加载逻辑 + 比对包内文件（非官方文档，属逆向分析；结论可用第五节的方法自证）

---

## 一、结论

**主因：头像字段是"包内相对路径"，而该专家被当作"市场专家"加载，相对路径会被拼到云端 CDN 基址上，CDN 上没有这个文件，图片 404，组件回退成首字母。**

一句话：图片不是没打包，是**加载时找错了地方**。

次因（会加重问题，但不是本次主因）：头像用了 `.jpg`、文件名与同系列不一致、包内 `avatars/` 若被解压工具漏掉也会同样失败。

## 二、证据链

### 1. 组件在图片失败时会渲染"首字母"

专家选择器的样式表里同时存在三个类：

| 类名 | 作用 |
|---|---|
| `_expertAvatarSmall_…` | 容器，紫色渐变底（`linear-gradient(135deg,#6366f1,#8b5cf6)`） |
| `_expertAvatarImage_…` | `<img>`，`object-fit: cover` |
| `_expertAvatarInitial_…` | **文字回退**：白色、9px、`text-transform: uppercase` |

有 `Initial` 这个类，说明"图加载失败 → 显示首字"是设计好的降级路径。你看到的"成字了"就是这个回退态。

### 2. 相对路径会被拼到 CDN 基址

负责把 `avatar` 字段转成 URL 的函数（渲染层）：

```js
function resolveAvatarUrl(e, t = Xf) {
  if (!e) return ``;
  let n = e.trim();
  if (n.indexOf(`data:image/`) === 0) return n.slice(...);   // data URI 直接用
  let i = n.replace(/^\/+/, ``);
  if (/^(https?|file|data|local-file):/.test(i)) return resolveRendererStaticUrl(i) ?? i;
  return `${t}${...}`;                                        // 相对路径 → 拼基址
}
```

其中两个基址常量：

```
Yf = https://acc-1258344699.cos.accelerate.myqcloud.com/workbuddy/experts
Xf = https://acc-1258344699.cos.accelerate.myqcloud.com/workbuddy/expert-marketplace
```

也就是说，`"avatar": "avatars/expert.jpg"` 在**市场专家**路径下会变成
`https://…/workbuddy/expert-marketplace/avatars/expert.jpg`——这个地址只对"头像已随包上传到 CDN"的专家有效。

### 3. 本地自建专家走的是另一条路

主进程从本地目录加载自定义专家时，有一行关键代码：

```js
t.avatar &&= await this.resolveAvatarUrl(t.avatar, e);   // e = expertRootDir
```

即：**本地专家的头像会按"专家根目录 + 相对路径"解析成本地文件 URL**（客户端支持 `local-file://`，CSP 的 `img-src` 里也放行了 `local-file:`）。这条路不经过 CDN，只要文件在包里就能显示。

### 4. 这个包属于"市场专家"，不是"本地自建"

该专家目录下存在 `.downloaded_at` 文件，且位于 `marketplaces/experts/plugins/`（市场目录），而不是 `marketplaces/my-experts/plugins/`（我的专家）。它的 `plugin.json` 写的是：

```json
"avatar": "avatars/expert.jpg"
```

文件确实存在（86 KB，1024×1024 JPEG）。所以不是"缺文件"，而是**加载通道选错**：市场通道按 CDN 解析 → CDN 无此文件 → 404 → 首字母。

### 5. 为什么作者本地看着正常

作者在本地开发时，包在 `my-experts` 目录，走本地文件通道，头像正常；一旦以"市场包"分发，相对路径就失去了本地上下文。

## 三、影响面

- 只影响**市场渠道**分发的、且头像为相对路径的专家。
- 不影响功能：提示词、工作流、脚本照常工作，只是列表里不好看。
- 同一现象也会出现在：头像文件 >500 KB 被拒、扩展名大小写不一致（`.PNG` vs `.png`）、`avatars/` 在压缩包里被漏掉、路径写成 `./avatars/…` 且解析器未归一化。

## 四、本次新产品的处理

`czl-english-teacher-desk` 采用了四条规避措施：

1. **PNG**（不是 JPG），512×512，217.6 KB，远低于 500 KB 上限。
2. **纯 ASCII 文件名** `avatars/expert.png`，全小写，无空格无中文。
3. **路径写法与官方模板一致**：`"avatar": "avatars/expert.png"`，不加 `./`，不加前导斜杠。
4. **文件确实在包内**，打包脚本会把 `avatars/` 一起打进去（已用解压清单核对）。

即便如此，**如果将来走市场渠道上架，仍需确认平台在发布时把头像资源一并上传到 CDN**——这是平台侧动作，不是包内能解决的。

## 五、你可以怎么自证与修复

### 30 秒判定

1. 打开专家列表，看该专家卡片：是"图"还是"首字"？→ 首字即命中本问题。
2. 打开 `…\plugins\marketplaces\experts\plugins\highschool-english-teacher\avatars\`：文件在不在？在 → 说明是通道问题，不是丢文件。
3. 把同一个目录**整体复制**到 `…\plugins\marketplaces\my-experts\plugins\`，重启 WorkBuddy。若头像出现 → 证实"市场通道 CDN 解析"这一判断。

### 修复方案（按成本排序）

| 方案 | 做法 | 适用 |
|---|---|---|
| A 改走本地通道 | 把包放进 `my-experts/plugins/`，用注册脚本登记 | 自用、校内分发 |
| B 换成绝对地址 | 把头像传到可公开访问的 HTTPS 地址，`avatar` 写成完整 URL | 有图床/对象存储 |
| C 用 data URI | `avatar` 写成 `data:image/png;base64,…`（客户端显式支持 `data:image/`） | 不想依赖任何路径，但会让 `plugin.json` 变大 |
| D 平台侧上传 | 市场发布时在后台单独上传头像，确保 CDN 有对应资源 | 正式上架 |

### 给同系列产品的建议

本机 `my-experts` 下已有 40+ 个 `czl-*` 专家，若其中也有走市场渠道分发的，建议统一检查：

- `avatar` 是否为相对路径；
- 头像是否 PNG、512×512、≤500 KB；
- 打包后 `avatars/` 是否在 zip 内；
- 市场后台是否已上传头像资源。

## 六、本次诊断的局限

- 结论基于客户端打包代码的静态分析，未在"全新安装 + 导入"环境中做对照实验。
- 平台后续版本可能改变头像解析策略（例如统一改为本地通道），届时以实测为准。
- 若按第五节第 3 步复制到 `my-experts` 后**仍然**显示首字，则说明是图片本身解码失败（可用系统看图软件打开确认），而非通道问题。
