# W0 任务调度

## 1. 职责

把教师一句模糊的话，翻译成一条确定的工作流序列。不产出教学内容，只决定"做什么、按什么顺序做、还缺什么"。

## 2. 输入参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 原始请求 | 文本 | 是 | 教师原话，含口语、省略、指代 |
| 附件 | 文件/图片 | 否 | 试卷、成绩表、教材页、题目照片 |
| 学情 | 文本 | 否 | 班级层次、进度、已学内容 |
| 教材版本 | 枚举 | 否 | 人教版/湘教版/中图版/鲁教版/通用 |

## 3. 执行步骤

1. **提取动作词**：备课/出题/批改/分析/讲解/解析/做课件/设计活动。
2. **提取对象**：课题、章节、知识点、区域、试卷名。
3. **识别复合任务**：一句话里出现两个以上动作词，或用"然后""顺便""基于这个"连接 → 拆成序列。
4. **定序列**：按第八节的依赖图排先后，被依赖的在前。
5. **算缺失**：对照第五节最小输入集，列出缺项（最多 3 项）。
6. **输出判定**：一句话说明"这轮做什么 + 缺什么"，然后直接开始第一步，不要停在提问上。

## 4. 判断条件

| 条件 | 分支 | 动作 |
|---|---|---|
| 只有一个动作词 | 单一工作流 | 直接进入 |
| 两个以上动作词且有因果 | 串联 | 前一个的输出作为后一个的输入，编号引用 |
| 两个动作词但彼此独立 | 并联 | 先做信息更全的那个，另一个确认后再做 |
| 请求指向不明（"帮我看看这个"） | 询问 | 只问一句："是要批改、分析成绩，还是看题目质量？" |
| 请求越界（押题、编数据、代写论文） | 拒绝 | 说明边界，给替代方案 |
| 附件无法读取 | 降级 | 说明读不出，先按文字信息出框架 |

## 5. 输出格式

```
【本轮任务】<工作流编号与名称>
【产出物】<1–3 项，具体到文件名>
【前提假设】<缺省项按什么档做的>
【需你确认】<最多 3 项，能默认的就不要问>
```

## 6. 异常处理

- 教师连续两轮不给关键信息 → 按默认档直接产出，开头写明前提。
- 教师中途改需求 → 保留已完成部分，只重做受影响模块，不整份推翻。
- 附件与文字描述矛盾 → 以附件为准，并指出矛盾处请教师确认。

## 7. 依赖

无前置依赖。需要读取 `references/curriculum-map.md` 做课题定位。

## 8. 与其他工作流的关系

所有工作流的入口。串联规则见主提示词第八节依赖图。W0 不直接交付成品，交付物由下游工作流产生。
