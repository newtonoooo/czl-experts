# 头像图标不显示、变成文字：根因诊断与处置

> 诊断对象：WorkBuddy 桌面端本地专家（`my-experts` / `experts` 市场）在专家列表与对话头像处的显示异常。
> 诊断方式：读取客户端安装包实现（`resources/app.asar`）中的头像解析逻辑，并对本机 131 个本地专家包做全量扫描。
> 诊断时间：2026-11-01。

## 一、现象

专家导入新环境后，在专家列表/对话身份区选中该专家，头像位置没有图片，显示为该专家名称的第一个字。

这不是图片损坏，而是客户端的**兜底显示**：当头像 URL 解析结果为空时，组件退化为文字首字。

## 二、代码链路（定位结论）

客户端在读取本地自定义专家时，会做一次头像路径解析。关键实现（`readCustomExpertFromDir` → `resolveAvatarUrl`，见 `app.asar`）：

```js
async resolveAvatarUrl(avatar, pluginDir) {
  if (!avatar) return "";                       // ① 没有 avatar 字段 → 空
  if (/^(https?|data):/.test(avatar)) return avatar;
  const rel = avatar.replace(/^\.\//, "");
  const target = path.resolve(pluginDir, rel);
  const root = path.resolve(pluginDir);
  if (!target.startsWith(root + path.sep) && target !== root) return "";  // ② 路径跳出包目录 → 空
  try {
    if (await pathExists(target)) {
      const st = await fs.stat(target);
      return st.size > 5 * 1024 * 1024
        ? (console.warn("[ExpertPluginService] resolveAvatarUrl: avatar file is too large:", avatar, st.size), "")
        : toLocalFileUrl(target);               // ③ 超过 5MB → 空
    }
  } catch {}
  return "";                                    // ④ 文件不存在 → 空
}
```

返回空字符串后，前端 `resolveExpertAvatarUrl("")` 返回 `undefined`，头像组件渲染文字首字。**四条路径都指向同一个结果：图片没被取到。**

## 三、四种真实原因与自查

| # | 原因 | 判定方法 | 出现频率 |
|---|---|---|---|
| 1 | `plugin.json` 的 `avatar` 指向的文件不存在（最常见） | 看包内 `avatars/` 是否只有 `.gitkeep` | 高 |
| 2 | 根本没有 `avatar` 字段 | `grep avatar plugin.json` 无输出 | 中 |
| 3 | 头像文件超过 5MB | 文件大小 > 5242880 字节 | 低（但 1024px 大图易超） |
| 4 | 路径写法跳出包目录，如 `../shared/a.png` | 路径含 `..` | 低 |

**本机实测（2026-11-01 10:47）**：131 个本地专家包中，

- 4 个缺 `avatar` 字段：`deep-research`、`finance`、`product-management`、`software-company`；
- 1 个声明了 `avatars/expert.png` 但文件不存在：`czl-politics-teacher-desk`（`avatars/` 内只有 `.gitkeep`）。

这 5 个包必然显示为文字首字，与导入环境无关——**在本机也一样**。

## 四、第五种情况：补了图还是不出

客户端对自定义专家 DTO 有按 `plugin.json` 修改时间（mtime）的缓存（`readCustomExpertFromDirCached`）。若先导入、后补头像，而未改动 `plugin.json`，缓存里的旧 DTO（avatar 为空）会继续生效。

**处置**：补完头像后刷新 `plugin.json` 的 mtime，或重启客户端。本项目 `tools/sync_install.py` 在同步末尾显式 `os.utime(plugin.json)`，就是为了踩掉这个缓存。

## 五、第六种情况：打包时把图弄丢了

- 手动压缩时排除了隐藏文件/图片，或用 `.gitignore` 过滤了 `*.png`；
- zip 内多套了一层目录，导入后实际安装路径与 `avatar` 相对路径不再对应；
- 直接把 `avatars/` 放在 `.codebuddy-plugin/` 里面（规范要求放包根目录）。

## 六、本产品的处置与预防

1. **交付即合规**：`avatars/expert.png` 为 512×512 PNG、336KB，远低于 5MB 上限；`plugin.json` 中 `avatar` 为 `avatars/expert.png`，文件位于包根 `avatars/` 下。
2. **打包前拦截**：`tools/verify_package.py` 增加 7 项头像检查——字段存在、文件存在、PNG/JPEG 合法、正方形、<5MB、≤500KB、路径在包内、`avatars/` 无多余文件。任一不过即 FAIL，不进入打包。
3. **导入后自检**：`tools/verify_package.py dist/xxx.zip` 会解压后重跑同一套检查，等价于模拟一次导入。
4. **安装刷新缓存**：`sync_install.py` 同步后 touch `plugin.json`。

## 七、复查方法（给使用者）

```bash
# 解压后校验（等价于模拟导入）
python tools/verify_package.py dist/czl-geo-teacher-desk-1.0.0.zip

# 检查已安装副本的头像是否就位
ls -l ~/.workbuddy/plugins/marketplaces/my-experts/plugins/czl-geo-teacher-desk/avatars/
```

若列表中仍显示文字首字：先确认 `avatars/expert.png` 存在且 <5MB，再重启客户端（刷新 mtime 缓存），最后才怀疑导入包本身。

## 八、给同类产品的通用建议

1. 头像放包根 `avatars/`，用相对路径，不加 `./` 也能解析，加了也可以。
2. 控制体积：512×512、PNG（`optimize=True`）通常 150–350KB，一眼能看清就够，不要直接放 1024px 原图。
3. 把"头像存在性"写进打包脚本，而不是靠人记。
4. 换图后记得动一下 `plugin.json`，否则缓存会让你以为换失败了。
