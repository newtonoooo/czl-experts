# 07　为什么导入后小图标变成了文字

> 这一篇是给"导入专家后，选中时图标没显示、只显示一个字"这个具体问题写的。结论来自对 WorkBuddy 桌面端 `app.asar` 的实际阅读，不是猜测。

## 一、一句话结论

**不是图片坏了，是"相对路径头像"在某些入口不会被解析成图片。**

WorkBuddy 客户端对同一个 `avatar` 字段有**四条不同的解析路径**，它们对"相对路径"的处理方式不一致：

| 入口 | 解析方式 | 相对路径的结果 |
|---|---|---|
| 市场 / 插件列表渲染 | `resolveAvatarUrl()`：不是 `http/file/data/local-file` 开头就拼成 CDN 地址 `…/workbuddy/experts/<路径>` | 私有包没有对应 CDN 对象 → **404 → 回退成名字首字** |
| 专家详情卡 / 成员卡 | 只接受 `^(https?\|file\|data\|local-file):`，否则返回空串 | **空 → 名字首字** |
| "我的专家"（my-experts）读取 | 后端 `readCustomExpertFromDir()` 会把相对路径读成文件，转成 `data:image/png;base64,…` | **能显示**（前提：文件存在且 ≤5 MB） |
| 会话召唤（summon） | `buildExpertFromManifest()` 把 `avatar` 置空，靠"最近使用记录 / 已购记录"里的 `avatarUrl` 补 | 无记录时 **空 → 名字首字** |

所以出现这个现象需要同时满足：**① 头像写的是相对路径；② 这个包不在 `my-experts` 目录下（或不在"我的专家"链路上）；③ 没有云端记录给它补一个绝对 URL。**

## 二、用你的旧包验证

把旧包（`highschool-chemistry-teacher`）交给本产品的诊断器，输出是：

```
[INFO] avatar 字段类型：相对路径
[INFO] 安装位置 marketplace：experts
[WARN] 不在 my-experts 下：市场/插件列表渲染会把相对路径拼成 CDN 地址，
       私有包没有对应的 CDN 对象，图片 404 → 回退成名字首字。
[WARN] 显示名「老师助手」与另外 7 个已安装专家重复
```

三条事实正好凑齐上面三个条件：

1. `plugin.json` 里是 `"avatar": "avatars/expert.png"`（相对路径，402 KB，512×512，文件本身没问题）；
2. 它装在 `plugins/marketplaces/experts/plugins/` 下，不是 `my-experts`；
3. 显示名"老师助手"在本机有 8 个同名专家，列表里连"靠名字认人"这条退路都没有。

文件没坏、路径没写错，**是解析路径不匹配**。

## 三、另外四个高频原因（自查顺序）

| 顺序 | 检查项 | 现象 | 怎么查 |
|---|---|---|---|
| 1 | zip 里到底有没有 `avatars/` 目录 | 整个目录都在，就是没图 | 解压后 `ls avatars/`；或 `python tools/doctor_avatar.py <目录>` |
| 2 | 路径大小写 / 反斜杠 | Windows 能读、客户端读不到 | 清单里写 `avatars/expert.png`，文件名必须一模一样 |
| 3 | 文件超过 5 MB | 客户端 `resolveAvatarUrl` 直接返回空串 | `stat` 看字节数；建议 ≤200 KB |
| 4 | 头像不是正方形 / 不是 PNG | 部分界面裁切变形或不解码 | 用 512×512 PNG；JPG 虽可但 MIME 判断更严格 |

## 四、本产品怎么处理（1.0.1 起：两种形态，按用途选）

| 形态 | 写法 | 用在哪 | 结果 |
|---|---|---|---|
| **提交态（默认）** | `avatars/expert-512.png`（512×512 PNG，334 KB） | 市场上架、正式分发 | 平台校验通过（认扩展名）；上架后头像由平台上传 CDN，市场内正常显示 |
| **本地测试态** | `data:image/png;base64,…`（256×256，46.6 KB → 清单 63.6 KB） | 自己机器上试装、演示 | 四条渲染路径都直接采用，私有包也不会变文字 |

**为什么要分两种**：平台校验按**扩展名**判断头像格式，`data:` 开头会被判为"（无扩展名）"直接驳回（1.0.0 已因此被退稿一次）；而私有包用相对路径时，客户端又可能拼成 CDN 地址而 404。两个约束方向相反，只能分场景用。

```bash
python tools/avatar_mode.py --status            # 看当前形态
python tools/avatar_mode.py --mode relative     # 提交前（默认就是这个）
python tools/avatar_mode.py --mode embed        # 本地试装前，用完切回
```
4. **自带诊断器**：`python tools/doctor_avatar.py <任意专家目录>`，直接告诉你这个包会不会变成文字、卡在哪一条。
5. **显示名不重复**：叫「卓识化学」，本机 82 个已安装专家中唯一，不会和"老师助手"们混在一起。

## 五、三步验证（导入后自测）

1. 打开专家列表 → 找到「卓识化学」→ 看头像是不是那张戴圆框眼镜的教员插画。
2. 选中它、发一句 `帮我备《氧化还原反应》` → 看对话区顶部的助手小图标。
3. 若仍是文字：先分清是"从市场安装"还是"本地 zip 导入"——
   - 市场安装：属平台 CDN 侧问题，把截图与包名反馈给平台；
   - 本地导入：这是本文第一条已知差异，在该包目录运行 `python tools/doctor_avatar.py .`，需要看图就临时切 `--mode embed`。

## 六、给平台的一条建议（可选反馈）

相对路径头像在"列表渲染"与"自定义专家后端"两条路径上语义不一致，是这类问题的根源。建议平台统一：**读取清单时就把相对路径解析成 data URL 或 local-file URL 再下发给渲染层**；同时上架校验改为"解析后判断 MIME"，而不是只看扩展名。这两条可以提交给 WorkBuddy 反馈渠道。
