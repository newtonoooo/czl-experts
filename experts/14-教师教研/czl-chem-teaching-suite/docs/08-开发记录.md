## 二、需求分析：从"能力清单"到"产品需求"

既有专家包列出 8 项能力（教案、命题、批改、学情、讲解、真题、化学特色、课件）。这只回答了"能做什么"，没回答"做成什么样才算完成"。本次补了六项：

| 需求要素 | 结论（本产品的答案） |
|---|---|
| 目标用户与场景 | 一线高中化学教师，8 个高频高压场景（见 `docs/01` 第 2 节） |
| 要解决的问题 | 产物不可直接用 / 错误无法归因 / 学科严谨性缺失 / 重复劳动 / 口径不统一 |
| 必要输入 | 每流的最小输入集 + 6 个默认档（缺参数不断流） |
| 通用步骤 | 受理 → 取知识 → 生成 → 过五闸 → 交付 → 给下一步 |
| 工具能力 | 图片/文档读取、文件写入、计算、本地脚本、可选联网；**零外部依赖** |
| 质量/速度/稳定 | 五条契约 + 五道闸门 + 默认档降级 + 模板固化 |

## 三、关键设计决策（以及为什么）

### 1. 用"工作流卡"而不是把全部规则塞进一个提示词

- **问题**：单文件提示词超过 ~6000 字后，模型对中段规则的遵守度下降。
- **决策**：主提示词只保留路由表、五条契约、七条红线、异常表（约 5000 字符）；每条流的执行细节放独立卡，命中才读。
- **代价**：多一次文件读取；换来长对话中的稳定性。

### 2. 自建错因码 E01–E14，而不是用文字描述错误

- **问题**：文字描述无法跨次汇总，"这次错得多"永远说不清结构。
- **决策**：14 个码，每码固定"判定信号 + 典型表现 + 补救动作"，并给"码 × 知识点"交叉表。
- **收益**：W3 与 W4 共用一套码，批改完直接能出班级错因分布。

### 3. 方程式强制三行校验

- **问题**：化学最容易被"看起来对"骗过；通用 AI 常给配平系数却不给依据。
- **决策**：任何方程式交付必须附"原子 / 电荷 / 电子"校验行，写进 W7 与 G1 闸。
- **代价**：输出变长；换来教师敢让学生抄。

### 4. 头像默认内嵌 data URL

- **问题**：客户端四条头像解析路径对相对路径处理不一致，私有包导入后图标会变成文字（已用旧包复现）。
- **决策**：清单里写 256px 的 `data:image/png;base64,…`（46.6 KB 图 → 63.6 KB 字符串），四条路径都直接采用；另留 512 母版供投稿，并提供切换脚本。
- **代价**：清单从 3 KB 变 68 KB（可接受）。

### 5. 不打包教材与真题

- **问题**：打包教材能显著"看起来资料丰富"，但版权风险不可控。
- **决策**：只打包自编的对照表、速查表、卷结构、资源索引；教材与真题由教师用官方渠道自备。
- **代价**：资料包体积小（约 12 KB）；换来权属清晰。

### 6. 从既有专家包只取"需求"，不取"表达"

- **决策**：目录结构改为 `playbooks/ + knowledge/ + materials/ + tools/`；提示词改为"路由 + 契约 + 红线"；知识库重写为 11 个文件，新增错因码、四维蓝图、方程式协议、流程四段式、质检闸门等原包没有的内容；名称、职称、头像、文案全部新定。
