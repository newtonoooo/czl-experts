### 脚本开发中的真实返工记录

保留这段是因为它能说明"测试确实跑过"，而不是事后补的报告：

1. `rfp_decode.py` 第一版把"评分标准（满分 100 分）"这行标题也当成了 100 分的评分项，导致合计 200 分。加入行首编号剥离与标题词黑名单后修复。
2. `theme_stress.py` 第一版因中文引号与 ASCII 引号混用导致语法错误（3 处），改为中文引号后通过编译。
3. `summary_audit.py` 第一版把带客户名、带数字的合格摘要判成 48 分（丢"处境"段）。原因是处境关键词只有"面临/当前"一类，补入"现有/去年/纳入/考核"后，同一份稿子得 89 分，与差稿的 30 分形成区分。
4. `score_sim.py` 第一版把"投标报价"排到追分第一位——报价分靠决策不靠写作，属误导。改为报价类不参与排序，单列提示。
5. `qc_check.py` 第一版把"评分项找不到落点"判为阻断，实际章节命名是人的决定，改为警告。
6. 头像生成工具输出带"AI生成"水印。本机无 Pillow、无 ImageMagick，`Add-Type` 被安全策略拦截，于是用标准库写了一个 PNG 处理器（`tools/png_tool.py`）做镜像补片去水印 + 裁切 + 缩放。

## 四、技术选择的理由

| 选择 | 理由 |
|---|---|
| 只用标准库 | 用户机器可能无网络、无 pip；商业分发不该要求用户装环境 |
| 脚本本地跑 | 招标文件涉密，不能上传；也不该让用户为分析功能付费调用模型 |
| 脚本拒绝代填判断 | 会自动填默认值的工具，会让人误以为分析做完了 |
| 报告强制写边界 | 评审模拟最常见的误用是把分数当中标概率 |
| 头像用符号不用人物 | 20px 尺寸下人脸会糊成色块；几何符号更清晰，也避开肖像风格争议 |
| 交付体检用退出码 | 防止"报告生成了就算过了" |
