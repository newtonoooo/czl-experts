# 产品规格说明

版本 1.0.1　开发者：虫志龙　日期：2026-10-28

---

## 一、需求是怎么来的

投标与方案策略这一领域，公开可查的方法论（如 Shipley 式标前流程、赢标主题、色评团评审）属于行业通用知识，不属于任何一家。但把方法论做成产品时，多数工具止步于"给你一套模板"，用户拿到模板仍然不知道从哪下手。

本产品从**实际使用动作**出发重新拆需求，不复用任何既有产品的文案、提示词或流程文件。需求来源有三：

1. 投标场景下的真实劳动过程：读招标文件 → 判断分在哪 → 定主线 → 排结构 → 写 → 自检 → 报价 → 交。
2. 该过程中反复出现的三个失效点（见下节）。
3. 现有工具缺的那一段：**从评分表到写作文本的换算**。这一段的缺失导致所有"方案写作助手"都只能给通用建议。

## 二、三个失效点

| 失效点 | 表现 | 根因 |
|---|---|---|
| 分不清轻重 | 花三天润色 5 分的章节，20 分的章节还缺证据 | 没有把评审办法换算成可分配的资源表 |
| 写通用稿 | 换掉客户名全文成立，评委记不住 | 没有"客户特异"这个强制检验 |
| 自检太晚 | 提交前一天发现漏项 / 占位符 / 客户名写错 | 没有提交前的机器可查关卡 |

产品的全部设计都为这三个点服务。凡是不能减少这三类损失的环节，都不做。

## 三、目标用户与场景

**主用户**：企业投标负责人、方案经理、售前顾问、标书撰写者。特征是：手上有一份招标文件，时间紧，需要在有限工时内决定"改哪里"。

**典型场景**

| 场景 | 用户说 | 产品该做的 |
|---|---|---|
| 刚拿到招标文件 | "这份有多少戏" | 拆评分表，算可争取分，扫红线 |
| 方案写到一半卡住 | "读起来像产品说明书" | 重排结构，按评分项下任务书 |
| 摘要不满意 | "开头没劲" | 五段式重写 + 体检打分 |
| 提交前焦虑 | "明天要交，帮我查一遍" | 交付体检，阻断项清零 |
| 客户嫌贵 | "怎么显得不贵" | 先算不做的代价，再三档报价 |

**不适用**：需要出具法律意见的合同争议、需要现场答辩技巧训练的场合、需要代做资质材料的场合。

## 四、输入与输出

### 输入（按环节）

| 环节 | 必需输入 | 可选输入 |
|---|---|---|
| 招标解码 | 招标文件文本 | 投标方资质现状 |
| 赢标主题 | 分数地图、客户信息、证据清单 | 竞争对手画像 |
| 三幕架构 | 分数地图、主题矩阵、章节要求、页数上限 | 已有初稿 |
| 摘要审查 | 摘要初稿、客户名、核心数字 | 无 |
| 评审模拟 | 分数地图、逐项得分率 | 历史入围线、对手分 |
| 报价叙事 | 报价、周期、客户口径成本 | 成本结构 |
| 交付体检 | 标书文件、客户全称 | 评分项清单 |

### 输出（统一规范）

- 一律 Markdown 表格优先，段落其次。
- 每条结论标注 `[事实]`（来自文件）/ `[推测]`（推断）/ `[待补]`（缺口），三者不混用。
- 每条建议必须能当场执行：改哪一段、加哪一句、找谁要哪份材料。
- 报告末尾必须有边界说明（这份分析不能证明什么）。

## 五、处理步骤（通用骨架）

七个环节共享同一个五步骨架，这也是它区别于"提示词集合"的地方：

```
1. 取数     —— 从文件里抽事实，抽不到就标缺口，不猜
2. 换算     —— 把事实换算成可比较的量（分值×可争取度、分/小时、回本期）
3. 判断     —— 给出结论与理由，理由写不出来就不给结论
4. 落地     —— 输出可执行的清单（改哪、加什么、找谁）
5. 复核     —— 改完重跑，用同一把尺子量变化
```

第 5 步是最容易被跳过的一步，也是产品刻意强化的地方：所有脚本可重复运行，改动前后用同一套指标对比。

## 六、工具与技术接口

| 能力 | 实现 |
|---|---|
| 文本抽取与分类 | 正则 + 关键词表 + 人工复核（`rfp_decode.py`） |
| 主题评分 | 四维加权，0-10 分（`theme_stress.py`） |
| 摘要体检 | 五段命中 + 空洞词 + 句长 + 字数（`summary_audit.py`） |
| 分数模拟 | 三档加权求和 + 追分杠杆（`score_sim.py`） |
| 报价测算 | 年化收益、回本期、净额、地板价（`roi_model.py`） |
| 交付体检 | 占位符/名称/编号/金额/落点（`qc_check.py`） |
| 发布自检 | 规范字段 + 头像解析链路（`verify_package.py`） |
| 图像处理 | 纯标准库 PNG 裁切/补片/缩放（`tools/png_tool.py`） |

全部仅依赖 Python 3.8+ 标准库，无网络调用，无第三方包，不上传任何用户数据。

## 七、质量、速度、稳定性要求

| 维度 | 要求 | 实现方式 |
|---|---|---|
| 质量 | 不出现无出处的数字 | 脚本只算术不编数；报告强制标 [待补] |
| 质量 | 不出现通用建议 | 主题压测的换名测试；摘要的客户名检查 |
| 速度 | 单环节 1-2 轮对话内出结果 | 脚本一次跑完，不做多轮试探 |
| 稳定性 | 输入不全时明确报错而非猜 | 缺 rate / 缺口径 / 找不到评分表 → 直接报错并列缺口 |
| 可复核 | 每个数字能追到来源 | 抽取结果带行号；测算带口径 |

## 八、与"通用写作助手"的边界

本产品**不做**以下事，即使在用户要求时也只做有限让步：

1. 不代写虚假业绩、资质、社保材料。
2. 不承诺中标，不给"中标概率"单一数字。
3. 不做法律意见。
4. 不检查格式、签章、电子标上传规则（明确标为"未验证"）。
5. 不贬低竞争对手。
