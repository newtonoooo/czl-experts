## [1.0.0] 2026-10-28

首个可发布版本。

### 新增

**七个工作流**
- 招标解码：从评审办法抽出评分项与分值，区分门槛分/客观分/主观分，给出可争取度与理由；同时抽废标红线与隐性偏好。
- 赢标主题：3-5 条客户专用主题句，四道压力测试（客户特异 / 证据可挂 / 差异成立 / 分数指向），10 分制打分。
- 三幕架构：理解—方案—结果重排，按分值占比分字数，逐章下任务书。
- 摘要审查：五段式（处境/代价/判断/证据/结果）与 0-100 分体检。
- 评审模拟：四类评委视角，三档总分，追分杠杆排序（每小时追回几分），报价类不参与排序。
- 报价叙事：不做的代价 → 收益回本 → 三档配置 → 让价边界 → 缺口清单。
- 交付体检：占位符、客户名、绝对化用语、金额写法、图表编号、评分项落点，阻断/警告/建议三级。

**六个可执行脚本**（Python 标准库，无第三方依赖）
- `rfp_decode.py`：分数地图抽取，支持 `--total` 校验抓取完整性，抓不全时报告差额而不是凑数。
- `theme_stress.py`：主题四维打分，输出改法而不代写。
- `summary_audit.py`：摘要五段结构与空洞词、句长、字数检查。
- `score_sim.py`：缺 rate 时直接报错并列出缺失项，拒绝用默认值糊过去。
- `roi_model.py`：只做算术，缺口径的项进缺口清单，不补成漂亮数字。
- `qc_check.py`：有阻断项时退出码 2，防止"报告生成了就算过了"。

**辅助工具**
- `scripts/verify_package.py`：发布前自检，含"头像能否被客户端解析"的链路式检查。
- `tools/png_tool.py`：纯标准库 PNG 裁切/补片/缩放，零依赖处理头像。

**资料**
- 评分口径手册、空洞词表、四类评委视角、废标风险清单。
- 主题矩阵、章节任务书、三个 JSON schema 模板。

### 设计决定

- **可争取度必须写理由。** 给一个数字不给理由，等于拍脑袋。写不出理由就说明还没读懂评分表。
- **脚本不代填判断。** 得分率、证据、口径全部由人给，脚本只算。这是刻意的：一个会自动填默认值的工具，会让人误以为分析已经做完了。
- **报价类不参与追分排序。** 价格分靠报价决策，改文字追不回来。放进排序会误导用户去改报价页的措辞。
- **报告必须写"不能证明什么"。** 评审模拟常见误用是把分数当成中标概率，所以每份报告末尾都有边界说明。
- **头像用符号而非人物。** 专家图标在列表里只有 20px，人脸在这个尺寸会糊成色块，几何符号反而更清晰，也不涉及肖像风格争议。

### 已知限制

- PC 端与移动端的实际渲染表现未验证（缺测试设备）。
- 招标文件若为扫描件，脚本抽不出文字，需人工提供文字版。
- 评分表跨页断裂时需人工合并，脚本不做跨页推断。
- 格式、签章、电子标上传规则一律不检查，报告中标为"未验证"。
