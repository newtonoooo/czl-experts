# 报价叙事

## 一条铁律

**价格永远出现在价值之后。** 评委/客户看到数字之前，必须先看到一个代价。否则你的报价只是一串字符，唯一能比较的对象是隔壁那家更便宜的。

## 输入

必需：报价或预算区间、实施周期。
必需：客户口径的现状成本或损失（哪怕是估算，也要写清假设）。
可选：成本结构、竞争对手价格区间、付款方式要求。

## 步骤

1. **算不作为的代价**。按客户的口径算：赔付、返工、人工、合规风险、机会损失。每条写口径。算不出来就空着，**不要编**。
2. **算回本**。投入 ÷ 年化收益 → 回本期（月）。超过 24 个月的回本期，客户不会信，回头检查收益口径是否虚高。
3. **排三档**。够用 / 推荐 / 加厚。每档写清少什么、多什么。三档的意义是让客户在"少要点"和"多给点"之间选，而不是在"买"和"不买"之间选。
4. **写价格页**。顺序固定：结果 → 数字 → 付款与验收的绑定。
5. **划边界**。可让的（排期、培训场次、巡检频次、响应时段）与不可让的（核心交付范围、验收口径、数据归属、责任边界）。
6. **备弹药**。每让 3%，换一条范围收缩或一个付款节点前置。无条件让价会引来第二次砍价。

## 判断

| 情况 | 处理 |
|---|---|
| 算不出客户口径收益 | 不写 ROI。改成"范围透明 + 单价拆解 + 验收绑定"的写法 |
| ROI 假设超过两条 | 降级为"情景测算"，给三档情景而不是一个数 |
| 报价高于对手 30% 以上 | 必须有一个结构性理由（交付范围、责任承担、响应等级），否则不要用叙事硬撑 |
| 客户只给总价不给明细 | 内部反推档位，只用于自己判断，不进标书 |
| 要求低于成本报价 | 拒绝。说明低价中标后的履约风险与法律后果 |

## 输出

`报价叙事.md`：不做的代价 → 收益与回本 → 三档表 → 让价边界 → 缺口清单。
缺口清单里每一项都是"不能写进标书"的，要标出来。

## 脚本

```bash
python scripts/roi_model.py price.json --md 报价叙事.md
```

`price.json` 结构见 `templates/price.schema.json`。脚本只做算术：年化收益、回本期、三年净额（未折现）、地板价、三档差额。所有金额与口径由你填，缺口径的项会被列进缺口清单。

## 异常

- 收益全靠"效率提升"这种软指标：换算成钱，或删掉。换算不出来就不写。
- 客户是政府采购、价格分权重高：报价策略优先于价值叙事，直接告诉用户"这个项目里叙事补不回价格分的差距"。
- 涉及付款条件偏离招标文件：提示这是实质性条款，可能构成废标风险，需法务确认。
