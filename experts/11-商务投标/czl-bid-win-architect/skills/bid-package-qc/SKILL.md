# 交付体检

## 态度

这一关的功能不是让标书变好，是**防止低级错误把前面的工作全部作废**。一个"XX 公司"的占位符、一处"保证中标"，足以让评委在心里给你减一档。

因此本环节只有两种结论：**通过**，或**待修清单**。没有"基本没问题"。

## 输入

必需：标书文件或目录（.md / .txt）。
必需：客户全称。
可选：评分项清单（每行一项，用于查落点）、招标文件的格式与密封要求。

## 查什么

| 类别 | 查什么 | 级别 |
|---|---|---|
| 占位符 | TODO、TBD、待补、待确认、【】、{{}}、XX、示例公司 | 阻断 |
| 客户名 | 是否出现、是否只出现在封面 | 阻断 |
| 越界承诺 | 最强、唯一、保证中标、100%、零风险、无条件 | 阻断 |
| 自称 | 我司、本公司（视行业习惯，可放宽） | 警告 |
| 金额 | 同一笔钱是否多种写法、大小写是否一致 | 警告 |
| 工期 | 天/日历天/工作日/月 是否混用 | 警告 |
| 图表 | 编号是否连续、是否重复 | 警告 |
| 评分项落点 | 每个评分项能否在正文找到对应内容 | 警告 |

## 步骤

1. 收集文件，跑脚本出第一版报告。
2. **人工过一遍阻断项**。脚本命中的每一条都要么改、要么明确判定为误报（例如"第一"出现在"第一步"里）。
3. 处理警告项：金额与工期口径必须统一，这是评委最容易抓的地方。
4. 按评分项清单反查落点，找不到的补一段。
5. **脚本查不到的必须人工核**：格式字体字号、页数上限、签章位置、电子标上传格式与大小、资质原件是否需要公证、是否需要授权委托书。这些脚本一律视为"未验证"，不是"通过"。
6. 重跑一次，直到阻断项清零。

## 判断

| 情况 | 处理 |
|---|---|
| 有任一阻断项 | 不出"可提交"结论 |
| 客户名 0 次 | 严重：这份文件可以发给任何客户 |
| 多个章节的金额互相矛盾 | 退回报价叙事环节重算，不要就地改数字 |
| 评分项落点缺失 | 回三幕架构补章，不要硬塞一段 |
| 用户说"来不及了" | 只保证阻断项清零，警告项列出但不改——并明确告知风险 |

## 输出

`交付体检报告.md`：结论（通过/不通过）+ 阻断/警告/提示三级清单 + 未验证事项清单。

报告最后必须写明"不覆盖什么"，避免让用户误以为脚本通过就等于可以投了。

## 脚本

```bash
python qc_check.py ./标书目录 --client 蜀通 --rubric rubric.txt --md 报告.md
```

有阻断项时退出码为 2（`--allow-blocker` 可关掉）。用退出码是为了防止"报告生成了就算过了"。

## 异常

- 目录里混了草稿与终稿：先让用户确认哪份是终稿，不要一起查。
- 文件是 docx/pdf：先转文本再查（转换会丢格式，格式项本来就要人工核）。
- 评分项清单没给：只做通用检查，并在报告里注明"未做评分项落点检查"。

## 依赖与上下游

上游：全部环节。下游：提交。发现问题时按类别回退：结构问题回三幕架构，数字问题回报价叙事，措辞问题回摘要/正文。
