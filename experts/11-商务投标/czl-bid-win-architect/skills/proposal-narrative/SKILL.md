# 三幕架构

## 什么时候用

- 章节还不知道怎么排，或按招标文件顺序写完读起来是散的
- 字数分配靠手感（写得多的地方反而分少）
- 需要给多个写手分活，得先把任务书写清楚

## 输入

必需：分数地图、赢标主题矩阵、招标文件要求的章节清单、页数或字数上限。

## 步骤

1. **定三幕**。
   - 第一幕 理解：客户的处境、约束、被考核的指标。这一幕不解决问题，只证明你听懂了。
   - 第二幕 方案：一个评分项一章。章首句直接回答该项问题，再展开机制。
   - 第三幕 结果：交付物、里程碑、验收口径、风险与应对。全部可核。
2. **对齐章节**。把招标文件要求的章节映射到三幕。要求顺序不能动的，顺序不动，在每章开头加"评分点直答"段。
3. **分字数**。按分值占比分，不按写作手感分。20 分的章节拿 30% 篇幅，10 分的章节不要写 40%。
4. **下任务书**。每章一节，见 `templates/chapter-brief.md`。
5. **查空档**。有没有评分项找不到落点？有没有章节不承接任何评分项？前者补章，后者压缩或合并。

## 判断

| 情况 | 处理 |
|---|---|
| 某章承接不到任何评分项 | 压到一页以内，或并入他章 |
| 某评分项无落点 | 补章。不接受"在别处提到过" |
| 招标文件限死页数 | 先砍第三幕的重复陈述，再砍第一幕的行业综述，最后才动第二幕 |
| 一个评分项跨多个章节 | 指定主责章，其余章只做引用，不重复论证 |

## 输出

`章节蓝图.md`：三幕结构 + 章节列表 + 每章承接评分项 + 分值 + 目标字数 + 主/次主题。
`任务书/第X章.md`：按模板逐章填写。

任务书必须能直接交给一个不了解项目的人开写。

## 异常

- 用户只给目录不给正文：先出蓝图，明确说这是结构建议，不含内容。
- 页数上限极紧（如技术标 30 页以内）：改用"评分点直答 + 一图一表"的压缩结构，把论证搬进图表注。
- 招标文件要求"按顺序逐条响应"：改成"响应表 + 方案正文"双轨，响应表保证不漏项，正文保证有论证。

## 依赖与上下游

上游：招标解码、赢标主题。下游：摘要（从蓝图里提炼）、评审模拟（按章打分）、交付体检（按章查缺）。
