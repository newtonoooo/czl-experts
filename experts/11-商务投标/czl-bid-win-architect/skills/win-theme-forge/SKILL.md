# 赢标主题锻造

## 什么时候用

- 分数地图已出，需要决定"这篇标书到底要说服评委相信哪三件事"
- 客户反馈"看完记不住你们想说什么"
- 方案各章各写各的，没有一根主线

## 输入

必需：分数地图（至少要主观项与分值）、客户基本信息。
必需：投标方可用的证据清单——项目名、可公开的指标、方法名、团队构成。**没有证据就先做证据盘点，不要先写主题。**

## 步骤

1. **选格子**。从分数地图里挑权重最高的 3-5 个主观项，一项对一条主题。不允许一条主题覆盖多项，那样等于没有重点。
2. **写初稿**。句式：`客户的什么处境` + `我们用什么做法` + `会变成什么结果`。控制在 25-35 字。
3. **跑四道测试**（脚本自动打分）：
   - 客户特异：换掉客户名还成立吗
   - 证据可挂：有没有数字、项目、可核结果
   - 差异成立：句子里有没有一个能被追问的机制
   - 分数指向：挂到哪个评分项、值几分
4. **淘汰**。低于 5.5 分的直接删。不够 3 条就交 2 条，不要凑。
5. **配证据卡**。每条主题一张：证据名 / 出处 / 能否公开引用 / 缺口。缺口写成待办给客户，不许自己补。
6. **映射章节**。每条主题标出它在哪几章出现。只出现在摘要里的主题等于没有。

## 判断

| 情况 | 处理 |
|---|---|
| 客户画像几乎为零 | 用行业公开信息做假设，全部标 [推断]，并列出"必须向客户确认的 5 个问题" |
| 证据全是"我们做过类似项目" | 逼出一句具体的：哪个项目、多大规模、什么指标、验收怎么写的 |
| 主题之间互相重复 | 合并。三条讲一件事，不如一条讲透 |
| 主题与评分项对不上 | 删掉。感动不了评委的主题不叫主题，叫散文 |

## 输出

`赢标主题矩阵.md`：

| 主题 | 对应评分项 | 分值 | 客户痛点（原话） | 我们的做法 | 证据 | 承载章节 | 压测分 |

加一节"竞争姿态"：只写我方在哪些维度做对了什么，**不写对手哪里不行**。

## 脚本

```bash
python scripts/theme_stress.py themes.json --md 主题压测结果.md
```

`themes.json` 结构见 `templates/themes.schema.json`。脚本对每条主题输出四维得分、结论（保留/改写/删除）与具体改法。

脚本只判断，不改写。改写由你完成，改完再跑一遍直到 ≥8 分。

## 异常

- 主题句超 45 字：拆成主句 + 一句支撑，主句留 30 字内。
- 证据涉及客户保密：主题里用脱敏表述（"某省级冷链客户"），但证据卡里保留真实出处供内部核对。
- 全部主题都过不了测试：说明这份标书目前只有通用能力，先解决"我们凭什么"再谈叙事。

## 依赖与上下游

上游：招标解码。下游：三幕架构（主题决定章节任务）、摘要（主题必须在摘要里出现）、报价叙事（主题要在价值段回响）。
