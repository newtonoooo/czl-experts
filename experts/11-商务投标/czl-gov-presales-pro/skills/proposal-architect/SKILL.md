# 方案骨架（proposal-architect）

写方案最常见的错误是照着需求书目录写。需求书是客户的口袋，评分表才是客户的钱包。
这个技能把评分表翻译成章节结构：分值高的给页数，分值低的砍掉。

## 一、什么时候用

| 用户说的 | 用哪条命令 |
|---|---|
| "帮我搭方案目录" / "这标怎么写" | `plan` |
| "评分项我列好了，帮我分配篇幅" | `plan` |
| "我这份评分表有没有问题" | `check` |
| "给我一个评分表模板" | `template` |

## 二、入口

```bash
python <技能目录>/scripts/proposal_plan.py plan --input scoring.json --out 方案骨架.md
python <技能目录>/scripts/proposal_plan.py plan --input scoring.json --page-limit 80
python <技能目录>/scripts/proposal_plan.py template > scoring.json
python <技能目录>/scripts/proposal_plan.py check --input scoring.json
```

## 三、输入格式

```json
{
  "project": "XX区一网通办升级",
  "page_limit": 60,
  "total_score": 70,
  "items": [
    {"name": "项目理解与需求分析", "points": 8, "type": "商务"},
    {"name": "总体技术架构", "points": 12, "type": "技术"},
    {"name": "数据治理与共享交换", "points": 10, "type": "技术"}
  ]
}
```

- `points` 是评分表里的分值，不是页数。页数由脚本按分值比例算。
- `type` 可填 `技术 / 商务 / 服务 / 价格`，只影响归类，不影响分配。
- `page_limit` 是招标文件给的页数上限；不给则按 60 页估算。

## 四、分配逻辑

1. 页数池 = `page_limit - 固定消耗`（封面、目录、偏离表按 4 页估）。
2. 每项页数 = 页数池 × 该项分值 / 总分，四舍五入，最低 1 页；单章上限 15 页，防止一章吃掉全篇。
3. 若章节含"架构"类要素，额外标注"必须配架构图"；含"实施"要素，标注"必须配里程碑表"。
4. 与必备章节对比，缺哪章提示哪章（项目理解、总体架构、安全合规、实施计划、运维服务、案例业绩）。

## 五、必备要素映射

脚本按章节名关键词挂要素，命中即写进该章"必须出现"栏：

| 关键词 | 必须出现的东西 |
|---|---|
| 架构 / 总体设计 | 总体架构图、部署图、技术选型理由、与现有系统的关系 |
| 数据 / 治理 / 共享 | 数据来源、清洗规则、质量指标、共享交换通道、数据安全分级 |
| 安全 / 等保 / 密码 | 等保级别与控制项、密码算法使用点、日志审计、备份恢复 |
| 信创 / 国产化 | CPU/OS/数据库/中间件型号、兼容证明、迁移路径 |
| 接口 / 对接 | 接口清单、协议、频率、异常处理、对现有系统的影响 |
| 性能 / 并发 | 指标值 + 测算口径 + 压测方法，不写"高并发" |
| 实施 / 计划 | 里程碑、甘特图、人员投入曲线、风险预案 |
| 运维 / 服务 | SLA、响应时限、驻场安排、备件与升级机制 |
| 培训 / 移交 | 培训对象、场次、教材、考核方式 |
| 案例 / 业绩 | 案例名称、规模、与本项目的相似点、可核验材料 |
| 报价 / 商务 | 报价构成、付款节点、让利方式、账期成本 |

## 六、输出格式

markdown，四段：

1. **方案骨架**：章节号、章节名、分值、建议页数、必须出现、写作提示。
2. **篇幅分配表**：一眼看出页数花在哪。
3. **缺章提示**：必备章节缺失清单。
4. **写作提醒**：三条，按当前评分结构定制（例如"数据治理占 10 分但需求书只写了一段，别被需求书带偏"）。

`--json` 输出：`{"items":[{"name","points","pages","must":[...],"tip":"..."}],"warnings":[...],"total_pages":N}`

## 七、异常处理

- 分值合计与 `total_score` 不一致 → 提示差额，按实际分值合计分配（不硬凑）。
- 页数池不足以给每章 1 页 → 提示"章节过多，建议合并同类项"，并给出合并建议（如把三个"子系统"合成一章）。
- 某项分值为 0 → 仍保留章节但标 1 页，提示"0 分项只做形式响应，不投入篇幅"。
- 用户没给评分表就要写方案 → 先要评分表。拿不到就按经验结构出骨架，但必须标注"未按评分表校准，存在结构性失分风险"。

## 八、边界

骨架不等于方案。这个技能解决"写什么、写多少"，不解决"写得好不好"。
方案里的数字必须来自真实测算，架构图必须与实际部署一致——骨架给不了这两样。
