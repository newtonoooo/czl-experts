# 使用说明

## 一、装好之后先做三件事

1. **直接对话**：在专家中心选「标胜」，第一句话就把三样东西给它——哪个单位什么项目、预算多少、招标文件有没有。
2. **跑一次自检**（可选，验证文件完整）：`python tools/selftest.py`，应输出 11 项通过。
3. **看一遍七关**：`agents/czl-gov-presales-pro.md` 里的七道关口，决定你这次走哪几关。只问报价就走第五关，不用全跑。

---

## 二、四个技能怎么用

所有命令在专家目录下执行。Windows 用 `python`，macOS / Linux 用 `python3`。

### 1. 机会打分

```bash
# 先导一份模板
python skills/gov-opportunity-radar/scripts/radar.py template > opp.json

# 改完分再算
python skills/gov-opportunity-radar/scripts/radar.py score --input opp.json
```

输出四段：结论（全力/选择性/放弃）、分数表、短板三条、下一步。

要点：
- `qualification_ok` 填 `false` 就直接出"不建议投标"，不算分。这不是惩罚，是省时间。
- 七维里缺项会自动归一化，但缺 3 项以上结论变"待定"。
- 想说"这个项目很好所以都给 5 分"——先给自己找一个反例，再定分。

### 2. 标书体检

```bash
python skills/tender-clause-audit/scripts/tender_audit.py scan --file 招标文件.txt --out 体检报告.md
python skills/tender-clause-audit/scripts/tender_audit.py scan --file 招标文件.txt --min-level 致命
python skills/tender-clause-audit/scripts/tender_audit.py materials --out 材料清单.md
```

招标文件是 PDF/Word 的，先另存为 txt 或用工具转文本。扫描件（图片）本技能不处理。

输出看三处：致命清单（逐条闭环）、星号条款汇总（逐条进响应表）、时间节点（做倒排）。

改规则：复制 `scripts/rules/tender_rules.json`，加自己的条目，用 `--rules 我的规则.json` 指定。

### 3. 方案骨架

```bash
python skills/proposal-architect/scripts/proposal_plan.py template > scoring.json
python skills/proposal-architect/scripts/proposal_plan.py plan --input scoring.json --out 骨架.md
```

`scoring.json` 里 `points` 填评分表的分值，不是页数。页数由脚本按比例算，单章最多 15 页。

输出会告诉你：每章几页、必须出现什么（架构图、里程碑表、型号清单等）、缺哪章。

### 4. 合规矩阵

```bash
python skills/compliance-matrix/scripts/matrix.py all --level 3 --out 合规三表.md
python skills/compliance-matrix/scripts/matrix.py dengbao --level 3 --format csv --out 等保.csv
```

三张表：等保（按级别）、密评（八个层面）、信创（层次 + 型号 + 验证要点 + 优先级）。
建议导 csv，用 Excel 分给不同的人填。填的时候重点不是"写了什么"，而是"测评时要什么材料，我们有没有"。

## 三、七关怎么走（按你的时间选）

| 你手上的时间 | 走哪几关 |
|---|---|
| 只有一条采购意向 | 第一关（30 分钟出结论） |
| 拿到招标文件，3 天内决定投不投 | 第一 + 第四关 |
| 决定投了，两周内交标 | 第一 → 第二 → 第三 → 第四 → 第五 |
| 已经投了，等答辩 | 第六关 |
| 中标了，明天交接 | 第七关 |

不要每次都跑全流程。全流程是给"大标、有把握、要拿分"的项目用的。

## 四、常见问题

**Q：导入后专家头像变成了一个字，怎么办？**
这是导入端没找到头像文件，退化成名字首字。用自检脚本查：

```bash
python tools/pack_check.py . --zip <你的包>.zip
```

它会检查三件事：plugin.json 里 `avatar` 写的路径在不在包里、图片是不是正方形 PNG/JPG、zip 里路径有没有用反斜杠。哪条不对，它就报哪条。修复后重新打包。

**Q：招标文件扫描不到东西？**
先确认文本能复制。扫描件（图片 PDF）需要先 OCR 再转 txt。另外正文如果是表格排版的参数表，可能存在大量空行，建议另存为纯文本。

**Q：规则库命中太多，全是噪音？**
先跑 `--min-level 致命`，只看会废标的那几条。一般级提示留到装订前再看。

**Q：方案骨架给的页数和我想要的不一样？**
改 `--page-limit` 或调整 `points`。注意单章上限是 15 页，超了会被压回来。

**Q：等保矩阵是几级的标准？**
默认三级（政务系统最常见）。二级用 `--level 2`，四级用 `--level 4`。矩阵是按控制类别归纳的自查提纲，不是标准条文，定稿必须对标准原文和测评机构意见。

## 五、这几件事它不会替你做

- 不会替你决定投不投。它给分数，你给判断。
- 不会替你见客户。需求共创那关，它给提纲，人得你去。
- 不会写假案例、假资质。这是硬红线。
- 不会保证中标。任何说"稳了"的，都在骗你。
