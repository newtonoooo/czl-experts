## 四、需要你本人决定的事项

### 决定 1：参考产品的功能分析是否需要留痕

你在任务中说明"没有现成专家的版权证明或授权文件"。本产品的实现是独立的，不依赖任何授权。但如果平台审核问起"是否参考了某产品"，建议保留本文件的第七节（功能差异表）作为说明材料。**是否需要额外准备一份书面说明，由你决定。**

### 决定 2：合规矩阵的表述尺度

矩阵目前是"按控制类别归纳 + 自有表述"，不复制国家标准条文。这是最稳妥的做法，但带来一个后果：如果客户要求"逐条对应 GB/T 22239 条款号"，矩阵需要补条款编号映射。补编号属于事实性引用（条款号本身不受著作权保护），**可以补，但需要你确认是否要做，以及是否购买了标准正式文本用于核对**。

### 决定 3：定价与许可

`LICENSE` 目前是"专有 + 禁止转售 + 禁止去署名"。如果你打算在平台上按订阅或买断销售，需要确认：
- 是否允许企业客户内部多人使用（当前条款允许"所属组织内部设备使用"）；
- 是否允许客户二次销售基于本产品输出的方案（当前条款允许"输出内容著作权归使用者"，这是行业惯例，但对咨询类产品意味着客户可复用你的方法论产出）。

## 五、内容风险（业务层面，非法律层面）

| 风险 | 说明 | 已做的缓解 |
|---|---|---|
| 用户把结论当承诺 | 有人可能拿"全力投入"去承诺领导"这标稳了" | 提示词与文档三处写明"不承诺中标、不输出中标概率" |
| 合规矩阵被当成合规结论 | 用户直接抄进标书说"满足等保三级" | 矩阵顶部与文档均声明"自查提纲，不替代测评机构结论" |
| 规则库地域差异 | 各地交易中心要求不同，通用规则可能漏项 | SKILL 中明确"通用结构规则"，并给出规则库扩展方法 |
| 政策时效 | 政策与信创目录会变 | 文档注明"以最新文件为准"，信创型号标注"以采购目录为准" |
| 报价模块被误用 | 用户可能用估算值直接投标 | 输出中强制标注"估算，误差 ±X%，需商务复核" |

## 六、发布前建议动作（按优先级）

1. **手动导入实测一次**：在另一个 WorkBuddy 实例导入 zip，确认头像、名称、三个推荐问题均正常显示。这是唯一未做的关键验证。
2. **跑一次真实的招标文件**：拿自己手上一个项目的招标文件跑 `tender_audit.py`，看命中是否符合直觉；误报多的规则考虑调整正则。
3. **校准打分权重**：用 3–5 个历史项目回填分数，看"全力投入"的项目实际中标情况，必要时改 `radar.py` 顶部权重（改完更新 CHANGELOG）。
4. **确认 LICENSE 条款**：见第四节决定 3。
