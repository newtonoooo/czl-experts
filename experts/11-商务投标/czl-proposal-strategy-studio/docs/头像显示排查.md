# 头像显示成文字：原因排查与修复

现象：专家导入新的 WorkBuddy 后，在专家列表里选中它，头像位置显示成一个文字方块（通常是名字首字），而不是图片。

这不是"导入失败"——专家的名称、简介、提示词都正常加载，只是图片没加载到。平台在图片不可用时不会报错，而是静默退化成文字头像，所以看起来像"图标丢了"。

## 一、结论：四类真实原因

以下按实际发生频率排序，每一类都能在本机复现。

### 1. plugin.json 声明的路径下没有文件（最常见）

`plugin.json` 写了 `"avatar": "avatars/expert.png"`，但 `avatars/` 目录是空的，或者文件名不是 `expert.png`。

这类包在结构校验里可能只给一条 warning（"avatar file not found"），很容易被忽略，打包后照常能装，只是头像变文字。

**本机证据**：排查时发现一个同批构建的专家包，`plugin.json` 明确声明 `avatars/expert.png`，而它的 `avatars/` 目录实际为空。这就是典型的"声明了但没放文件"。

### 2. 路径里带反斜杠，命令静默失败，目录最后是空的

在 Git Bash 里写 `cp 原图 "avatars/expert\.png"` 时，反斜杠会进入路径。Windows 的文件名不允许含反斜杠，这条命令会直接报 `No such file or directory` 失败；但报错常被后面的一串输出淹没，于是看起来"已经复制过了"，实际 `avatars/` 里什么都没有。

`plugin.json` 的 `avatar` 字段写成 `avatars\expert.png`（反斜杠）也是同类问题：JSON 里反斜杠还是转义符，路径会解析错。

**本机证据**：排查时运行日志里出现过 `.../avatars/expert\.png` 这样的路径记录，同一批构建里 `avatars/` 目录确实为空。所以这一类的最终表象与第 1 类完全一致：目录空 → 头像 404 → 显示成文字。

### 3. 图片规格不合规

- 体积超过 500 KB；
- 不是 512×512 正方形；
- 扩展名是 `.png` 但实际字节是 JPEG（把 `.jpg` 直接改名成 `.png` 就会这样）。

前两项在部分环境只是加载慢或裁切异常；第三项会直接加载失败。

### 4. 打包时没把 avatars/ 带进去

手工压缩时只选了 `agents/`、`.codebuddy-plugin/`，漏了 `avatars/`；或者压缩工具默认排除了隐藏目录之外的某些文件。检查方法：打开 zip 看内部是否真有 `你的包名/avatars/expert.png`。

## 二、四步自查（两分钟内完成）

```bash
# 1. 看 plugin.json 怎么写的
grep '"avatar"' .codebuddy-plugin/plugin.json

# 2. 看文件是不是真叫这个名字（-b 会显示反斜杠等特殊字符）
ls -b avatars/

# 3. 看尺寸与体积
python -c "import struct;f=open('avatars/expert.png','rb');h=f.read(24);print(struct.unpack('>II',h[16:24]))"
ls -l avatars/expert.png

# 4. 打包后看 zip 里有没有
python -c "import zipfile;print([n for n in zipfile.ZipFile('你的包.zip').namelist() if 'avatar' in n])"
```

## 三、一键检查（本包内置）

```bash
python tools/check_package.py
```

输出示例（全部通过时）：

```
| PASS | 头像 | 体积 479 KB，在 500 KB 以内 |
| PASS | 头像 | 尺寸 512x512 |
**FAIL 0 项 / WARN 0 项**
```

它会专门拦这几件事：字段没写、路径指向不存在的文件、字段含反斜杠或首尾空格、体积超限、非正方形、扩展名与真实格式不符、`avatars/` 里残留未声明文件（容易误引用）。

任何一项 FAIL，都不要打包。

## 四、修复步骤

1. 把原图重新处理成 512×512、PNG、500 KB 以内。
2. 用**正斜杠**路径复制到 `avatars/expert.png`，不要用 `\.` 转义。
3. 确认 `plugin.json` 的 `avatar` 字段与磁盘文件名逐字符一致（含大小写）。
4. 跑一遍 `python tools/check_package.py`。
5. 用平台官方脚本打包（它会保留 `.codebuddy-plugin` 并排除垃圾文件）：
   ```bash
   python <平台技能目录>/scripts/package_expert.py <专家目录> <输出目录>
   ```
6. 重新导入，清一次专家列表缓存（退出重进），头像即恢复。

## 五、本包的状态

本包已按上述要求处理：

- 头像 `avatars/expert.png`：512×512、PNG、约 479 KB；
- `plugin.json` 的 `avatar` 字段与文件名完全一致；
- `tools/check_package.py` 实测 FAIL 0 项；
- 打包后 zip 内确认存在 `czl-proposal-strategy-studio/avatars/expert.png`（见测试报告）。

## 六、如果换了机器还是不显示

那问题不在包，而在导入链路，按顺序看：

1. 目标机器的 WorkBuddy 版本是否过旧（旧版本对 zip 内头像路径的解析不同）。
2. 是否通过"导入 zip"进入，而不是手动解压到别的目录——手动放到非专家目录的包不会被正确解析。
3. 企业版是否限制了自定义头像（部分企业策略只允许平台审核过的头像）。

这三种情况与包内容无关，需要平台侧确认。
