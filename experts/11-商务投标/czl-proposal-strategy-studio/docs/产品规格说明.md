产品：czl-proposal-strategy-studio（标胜）
版本：1.0.0
开发者：虫志龙（47190078@qq.com）

## 一、产品定位

面向**要投一个标、写一份方案、争取一次评审通过**的人，提供一条从判断到交付的完整工作线，而不是一篇代写文章。

一句话：**先把分数拿住，再谈漂亮。**

## 二、需求从哪来

需求不是从某个现成产品的文案里抄来的，而是从这类工作本身的失败模式里倒推出来的。三类高频失败：

| 失败模式 | 可观察的现象 | 对应关卡 |
|---|---|---|
| 判断失误 | 投了明显不该投的标，两周人力打水漂 | 机会关 |
| 得分错位 | 评分表 30 分项，正文只有两页；低分项写得很长 | 读标关、成篇关 |
| 程序性废标 | 技术分第一，因缺章、缺份、逾期被判无效 | 交标关 |

围绕这三类失败，把工作拆成六个有明确通过标准的关卡。每个关卡都必须能回答三个问题：输入是什么、判断依据是什么、不通过怎么办。

## 三、目标用户与场景

| 用户 | 场景 | 主要诉求 |
|---|---|---|
| 中小企业销售负责人 | 第一次投政府/医院/学校标，不熟悉流程 | 判断值不值得投；别在程序上翻车 |
| 售前/方案工程师 | 技术很强，写出来评委看不懂 | 把技术优势翻译成得分点 |
| 投标代理/咨询顾问 | 同时跟 3–5 个标，需要一致的检查标准 | 可复用的矩阵、清单与体检脚本 |
| 创业者/自由职业者 | 写商业提案、合作方案、服务建议书 | 在报价页把价值讲清楚，而不是比价格 |

不适用：纯文案润色、纯排版、纯翻译；也不适用于需要法定资质的造价、法务意见出具。

## 四、输入与输出

### 输入（按重要性）

1. 招标/需求文件（评分办法、资格条件、技术需求、商务条款）。
2. 客户与项目背景（预算、决策链、既往合作、痛点原话）。
3. 可动用证据（案例、资质、团队、数据）。
4. 竞争情报（对手名单与强项）。
5. 商务约束（底线价格、付款条件、工期）。

输入不完整时：缺 1–2 项可标注后推进；缺评分办法或招标文件，必须先出《要件缺口清单》，不得凭想象写正文。

### 输出

| 产物 | 形式 | 用途 |
|---|---|---|
| 机会关评分记录 | Markdown 表格 | 内部决策留痕 |
| 得分点矩阵 | Markdown + CSV | 写作分工与进度跟踪 |
| 否决项清单 | Markdown 清单 | 交标前逐条核对 |
| 主题卡 | Markdown 卡 + 体检表 | 立意对齐，防止写成能力说明书 |
| 执行摘要 | Markdown，≤700 字 | 单独可发的第一页 |
| 证据账本 | Markdown 表 + 体检表 | 应对评委追问 |
| 价格叙事底稿 | Markdown | 内部测算；对外只留结论 |
| 红队记录 + 交标清单 | Markdown 表 | 交标前最后一道闸 |

## 五、处理步骤（六关）

1. **机会关**：五维打分（资格/客户/差异/交付/商务），加权总分 → 结论 + 拖分项 + 必须项。
2. **读标关**：评分表 → 得分点矩阵（分值、证据、落章、责任人），按分值排写作顺序；否决项与硬性要求单独成单。
3. **立意关**：3–5 条主题，每条过"三问"（只对这家成立 / 有证据 / 对手照抄会露馅），产出主题卡。
4. **成篇关**：先写五段式执行摘要（处境/张力/主张/证据/终局），再按矩阵顺序搭正文骨架，最后展开。
5. **报价关**：不做的代价 → TCO → ROI/回本 → 三档报价（保底/推荐/进取）→ 让价换条件。
6. **交标关**：评委视角自评 + 三类对手假设 → 丢分三项 + 可捞分项；交标六项核查。

每关的产物是下一关的输入。任何一关不通过，回到上一关，而不是硬着头皮往下写。

## 七、质量、速度、稳定性要求

| 维度 | 要求 | 现状 |
|---|---|---|
| 结果质量 | 每个结论必须能追到输入；禁止无证据断言 | 用证据分级（E1–E4）与脚本体检约束 |
| 速度 | 单关脚本执行 < 2 秒（万行内文本） | 实测均在 1 秒内 |
| 稳定性 | 输入缺失或格式错误时给出明确报错，不静默产生错误结果 | 全部脚本对缺参/坏 JSON/坏 CSV 有显式错误分支 |
| 可移植 | Windows / macOS / Linux 一致 | 仅用标准库；路径用 os.sep 拼接；输出强制 UTF-8 |
| 可审计 | 每关留记录，含输入、判断、结论、未决项 | 关卡记录模板 + 脚本产出的表格 |

## 八、与参考产品的差异（经验继承与改进）

参考对象是一个同类"提案/方案策划"助手。本产品在功能层面**独立重写**，不复制其文案、提示词或代码。经验层面的继承与新增如下：

**继承的通用做法**：赢标主题（win theme）概念、执行摘要优先、按评分表组织正文、以价值论证支撑价格、以红队/模拟评审做终检——这些是行业通用方法，不属于任何单一产品的专有表达。

**本产品的补充**：

1. **加了入口关卡**：机会关（Go/No-Go）与必须项机制。多数同类工具从"怎么写"开始，本产品从"要不要写"开始。
2. **把方法做成可运行脚本**：矩阵覆盖率、摘要七项、主张标注率、回本周期、红队分差，全部可复算，而不是只靠提示词约束。
3. **证据分级制度**：E1–E4 四级，并规定 E1/E2 拿不出原始材料必须降级为 E4。
4. **否决项单列**：把"会直接死"的条款从评分逻辑里剥离，优先处理。
5. **异常分支写进流程**：时间不足转"最小可交版"；证据不足降级表述；对手未知做三类假设。
6. **包体自检**：针对"头像不显示"这类发布期问题提供检查脚本。

## 九、非目标

- 不做自动投标、不代签、不代替法务与造价资质。
- 不承诺中标率，不提供"评分内幕"。
- 不生成虚假业绩、虚假检测报告、虚假客户评价。
- 不做行业垄断性数据库（案例库由用户自备）。
