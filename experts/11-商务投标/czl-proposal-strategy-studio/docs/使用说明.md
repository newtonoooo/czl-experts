# 使用说明

适用版本：1.0.0　开发者：虫志龙（47190078@qq.com）

## 一、安装

1. 打开 WorkBuddy，进入「专家」→「我的专家」→ 导入，选择 `czl-proposal-strategy-studio.zip`。
2. 导入后在专家列表选择「标胜」，头像应显示为暖金色背景的插画人物。
   - 如果显示成一个文字方块，见文末「头像显示成文字怎么办」。
3. 首次对话会自动带出引导语，直接替换成你的项目信息即可。

本地开发者也可以把整个目录放进
`~/.workbuddy/plugins/marketplaces/my-experts/plugins/`，再运行注册脚本使其出现在专家中心。

## 二、第一次对话怎么开口

不用先分类，把手上有的东西丢进来就行。三种最常见的开场：

**只有招标文件**
> 这是某某项目的招标文件（贴在下面）。先告诉我值不值得投，再帮我拆评分表。

**已经决定投，要写方案**
> 项目是某某医院机房改造，评分表在附件里，我们有三个同类案例。帮我定主题，再写执行摘要。

**稿子写完了要体检**
> 方案初稿在下面，评分表也发你，帮我按评委视角打分，指出会被废标的地方。

## 三、六关怎么走

| 关 | 你提供 | 你拿到 | 大概耗时 |
|---|---|---|---|
| 机会关 | 资质、关系、对手、工期、价格空间 | 投/条件投/不投 + 必须项 | 10 分钟 |
| 读标关 | 评分办法、投标人须知 | 得分点矩阵 + 否决项清单 | 20–40 分钟 |
| 立意关 | 客户痛点原话、我们的做法、案例 | 3–5 张主题卡 + 体检结果 | 30 分钟 |
| 成篇关 | 矩阵、主题卡 | 执行摘要 + 章节骨架 | 1–2 小时 |
| 报价关 | 年损失、投入、运营成本、三档配置 | 代价/TCO/ROI/三档表 | 30 分钟 |
| 交标关 | 全文初稿、评分表、核查项 | 自评分 + 丢分三项 + 交标清单 | 30 分钟 |

时间紧的时候可以跳关，但不能跳**读标关**和**交标关**——这两关决定生死，其余决定分数。

## 四、能直接复制的提问模板

**机会关**
> 帮我做机会关打分：资格=？客户基础=？方案差异=？交付风险=？商务空间=？（0–5 分，不确定就说不确定）另外这三件事我现在拿不到：__、__、__。

**读标关**
> 这是评分办法原文：__。帮我拆成得分点矩阵，标出哪些项我们没证据，哪些条款会直接废标。

**立意关**
> 客户最在意的是"__"（原话）。我们能做到"__"，有案例：__。帮我出三条主题，每条都要能过三问。

**成篇关**
> 按这个矩阵写执行摘要，700 字内，第一段必须出现客户全称和项目名。

**报价关**
> 不做这件事每年损失约 __ 万（算法是 __），投入 __ 万，年运营 __ 万。帮我算回本周期，并给三档报价的配置差。

**交标关**
> 初稿在下面，评分表在附件。按评委视角打分，再假设一个低价对手和一个关系对手，各写一句他们的攻击点和我们的回应。

## 五、脚本可以单独跑

专家会自己调用，你也可以在本地直接跑（Python 3.8+，无需安装依赖）：

```bash
cd skills/rfp-decode
python scripts/rfp_matrix.py matrix samples/items.csv
python scripts/rfp_matrix.py scan samples/rfp.txt
```

每个技能的 `samples/` 里都有可直接运行的样例，其中 `themes-bad.json`、`summary-draft.md` 是故意写坏的反例，用来观察脚本能抓到什么问题。

## 六、常见问题

**Q：能不能直接给我一份能投的完整标书？**
可以产出全文骨架与关键章节，但业绩、资质、报价必须由你提供真实材料。编造内容会带来废标与法律风险，本专家不会做。

**Q：评分办法没有分值怎么办？**
按通用假设（技术 40 / 商务 30 / 价格 30）推进，产物第一行标注"假设"，并要求你向招标代理确认。

**Q：只剩两天怎么办？**
直接说"只剩两天"，会转成最小可交版：资格文件、否决项、技术响应表、报价表、执行摘要五件，其余放弃。

**Q：能不能保证中标？**
不能。能保证的是：评分表每一项都有回应、每条主张都有证据等级、交标六项都核对过。这能提高得分概率，但不能决定评委和对手。

**Q：客户案例涉密怎么办？**
用"同城某三甲医院"这类去标识写法，真实名称只留在内部证据账本，对外版本删除。

## 七、头像显示成文字怎么办

专家列表里显示成一个字母方块，说明平台没有加载到头像图片，自动退化成了文字头像。按顺序查四项：

1. `plugin.json` 里的 `avatar` 字段是否指向真实存在的文件（区分大小写）。
2. 头像文件是否真的复制进了 `avatars/`：在 Git Bash 里写 `"avatars/expert\.png"` 这类带反斜杠的路径会直接复制失败，目录看着存在、里面是空的。
3. 图片是否超过 500 KB、是否 512×512、扩展名与实际格式是否一致（把 JPEG 改名成 .png 会加载失败）。
4. 打包时 `avatars/` 目录是否真的进了 zip。

本包内置检查脚本，一步定位：

```bash
python tools/check_package.py
```

它会逐项报告并通过颜色区分 FAIL / WARN；有 FAIL 就不要打包。详见 `docs/头像显示排查.md`。

## 八、卸载

从专家中心移除即可，不写入系统目录、不驻留后台进程、不修改注册表。本地文件位于
`~/.workbuddy/plugins/marketplaces/my-experts/plugins/czl-proposal-strategy-studio/`，删除该目录即彻底清除。
