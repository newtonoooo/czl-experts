# 产品规格 · 简锋（czl-resume-gate）

版本 1.0.0 ｜ 开发者 虫志龙 ｜ 2026-10-26

---

## 0. 这份规格怎么来的

先对一个同类产品（WorkBuddy 专家中心的简历类专家）做**只读功能分析**：看它能做什么、输出什么、边界在哪。分析结论只用于确定"要解决哪些问题"，不复用它的文案、提示词结构、评分分项或工作流定义。本规格中所有模型、分项、流程与阈值均为独立设计，见第 5 节的差异说明。

## 1. 目标用户

| 用户 | 场景 | 他真实的处境 |
|---|---|---|
| 应届生 / 毕业 1-2 年 | 第一次系统写简历，投了几十份没回音 | 不知道自己哪里不对，只知道自己"不够优秀" |
| 工作 3-8 年的在职者 | 想跳槽，简历还是三年前那版 | 做过的事很多，写出来像岗位说明书 |
| 转行者 | 经验相关但行业术语不对 | 不知道怎么把旧经历翻译成新行业的话 |
| 被裁 / 空窗期 | 时间紧，需要快速出一版能投的 | 情绪压力大，需要的是可执行的下一步而不是安慰 |
| 帮人看简历的人（HR 朋友、学长、家长） | 被求助"帮我看看" | 只能凭感觉说"再突出一下亮点" |

**共同点**：他们不缺"要写好简历"的道理，缺的是**具体改哪一句、改成什么、为什么**。

## 2. 要解决的问题

按发生顺序排：

1. **不知道卡在哪一关。** 简历先被机器解析，再被人六秒扫，再被面试官追问。三关的失败原因不同，笼统的"不够突出"无法指导修改。
2. **写成了岗位说明书。** "负责 X""参与 Y"只说明了岗位存在，没说明这个人做出了什么。
3. **没有数字，或者数字没有口径。** 前者让简历失去说服力，后者在面试里会被问穿。
4. **同一份简历投所有岗位。** 相关经历埋在后面，关键词对不上，投递成本几乎为零但转化率也几乎为零。
5. **内容对但交付形态错。** 表格排版、图片承载文字、PDF 是扫描件，导致解析失败。
6. **想要"包装"，但不知道边界在哪。** 需要有人明确告诉他：能改表达，不能改事实。

## 3. 输入与输出

### 输入

| 输入 | 必填 | 形式 | 缺失时 |
|---|---|---|---|
| 简历正文 | 是 | md / txt / docx 文本 / 粘贴正文 | 追问，或按用户口述建档 |
| 目标岗位 / JD | 否 | 文本 | 跳过定制，只做体检与重写 |
| 投递市场 | 否 | 中文/英文、民企/外企/国企 | 默认中文、民企，写入"本次假设" |
| 工作年限与时间线 | 否 | 数字 | 从简历日期推断，标注为推断 |

### 输出

| 输出 | 触发 | 形态 |
|---|---|---|
| 三闸门评分卡 + 致命项清单 | "能不能过""为什么没回音" | Markdown 报告（≤6 条问题，每条含证据与改法） |
| 要点改写对照表 + 待补清单 | "帮我改""润色" | Markdown 表格（一次 3-5 条） |
| JD 四栏拆解 + 覆盖矩阵 | 贴了 JD | Markdown 报告 + 匹配度结论 |
| 交付文件 | "导出""打印" | .docx / A4 HTML（可打印为 PDF）/ .txt |

## 4. 处理步骤（产品级流程）

```
S1 建档    判断意图 → 缺什么问什么（≤4 个问题）→ 记录假设
S2 体检    脚本算机械指标 + 模型判判断性指标 → 定位最致命的一关
S3 重写    逐条标 A/O/R/E 四格 → 出 Before→After → 列待补
S4 定制    有 JD 才做：四栏拆解 → 覆盖矩阵 → 三类缺口分流
S5 交付    三种格式导出 → 六项自查 → 规范命名
S6 复检    重跑体检，对比致命项数量（不是对比分数）
```

**判定分支**

- 致命项 > 0 且集中在 A 闸门 → 先修版式，不要动文案。
- 致命项集中在 B 闸门 → 进 S3 重写。
- 有 JD 且必备项覆盖 < 50% → 先判"要不要投"，再决定改不改。
- 用户要"从零写" → S3 先出骨架（章节 + 每段要什么），确认后再填内容。

## 5. 与同类产品的设计差异（独立实现说明）

| 维度 | 常见做法 | 本产品做法 | 为什么 |
|---|---|---|---|
| 评分模型 | 五维百分制（内容/结构/语言/ATS/影响力） | 三闸门（机器解析 30 / 六秒扫描 40 / 追问耐受 30） | 按"谁在筛"分，而不是按"简历的组成"分；直接对应失败原因 |
| 分数用途 | 前后对比提升幅度 | 只用于排优先级，明确禁止承诺分差 | 两次评分都是模型打的，分差没有客观意义 |
| 重写框架 | STAR / 强动词替换 | AORE 四格（动作-对象-结果-证据） | 增加"证据"格，专门治"数字没口径"和"团队成果写成个人成果" |
| 数据缺口 | 提示用户补充 | 三级分级：事实／推演／待补；推演只允许结构量 | 效果量推演必然在面试或背调时爆掉 |
| JD 定制 | 关键词覆盖率 | 四栏拆解 + 覆盖状态三分（已覆盖/可迁移/缺失） | "可迁移"单列能把用户低估的相邻经验捞回来 |
| 清单式检查 | 40+ 项逐条打勾 | 不逐条打勾，直接给 ≤6 条致命优先项 | 40 条清单用户改不动 |
| 交付 | 主张多格式（含 LaTeX 等） | 三种真实可交付格式，脚本实测可生成 | 不列没实现的能力 |

## 6. 工具能力需求

| 能力 | 实现方式 | 依赖 |
|---|---|---|
| 读文件 | 内置多编码尝试（UTF-8-SIG / UTF-8 / GB18030） | 标准库 |
| 机械指标计算 | `resume_audit.py` | 标准库（re/unicodedata/json） |
| JD 词表匹配 | `jd_match.py`（内置约 60 类技能词表） | 标准库 |
| Word 生成 | `md2docx.py` 直写 OOXML | 标准库（zipfile/xml） |
| 打印版 HTML | `md2html.py` | 标准库 |
| 纯文本导出 | `md2txt.py` | 标准库 |
| 判断性分析（层级是否错位、成果是否值钱、故事是否自洽） | 模型按 SKILL 指令执行 | 平台模型 |
| 包自检 | `selfcheck.py`（34 项） | 标准库 |

**明确不依赖**：python-docx、pandoc、jieba、Pillow、任何网络 API、任何字体文件。

## 7. 质量、性能、稳定性要求

| 维度 | 要求 | 现状 |
|---|---|---|
| 单份简历体检耗时 | < 2 秒（1000 字以内） | 实测 < 0.5 秒 |
| 导出耗时 | < 3 秒 | 实测 < 0.5 秒 / 文件 |
| 大文件 | 10000 字以内正常；超出提示精简 | 未做硬截断，超长会变慢 |
| 编码容错 | UTF-8 / GB18030 均可读 | 已测 |
| 异常退出码 | 文件不存在 = 2；参数错误 = 2；成功 = 0 | 已测 |
| 不编造 | 输出中不得出现用户未提供的数字 | 由提示词铁律约束 + 待补占位机制 |
| 结论可核对 | 每条判断必须能指回原文 | 输出契约强制要求"证据"字段 |

## 8. 验收标准

1. 专家包通过 `validate_expert.py` 校验且注册成功。
2. `selfcheck.py` 34 项全部 PASS。
3. 26 项功能测试全部 PASS，日志落盘。
4. 弱样例与强样例的体检分差 ≥ 20（区分度）。
5. 导出文件可被 XML 解析器完整解析，Word 包结构齐全。
6. 文档齐全：规格、使用说明、测试报告、风险清单、展示文案、文件清单、开发记录、更新日志。

## 9. 不在范围内

- 代写工作经历、伪造证书学历。
- 面试模拟、薪资谈判（可作为后续版本的独立能力）。
- 简历投递渠道推荐、内推资源撮合。
- 自动投递（涉及第三方平台条款与账号安全）。
- 人像照片美化（与"证据链"定位无关）。
