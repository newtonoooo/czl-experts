# AORE 框架与例句库

## 四格定义

| 格 | 名称 | 判断标准 | 缺失后果 |
|---|---|---|---|
| A | 动作 Action | 一个具体的、可验证的动作动词 | 读者不知道你干了什么 |
| O | 对象 Object | 动作落在什么上：系统、人群、金额、区域、流程 | 读者不知道事情有多大 |
| R | 结果 Result | 前后变化，最好带数 | 读者不知道有没有用 |
| E | 证据 Evidence | 归属（独立/主导/参与哪段）+ 口径（怎么算、什么周期） | 面试被追问时撑不住 |

## 完整句与残缺句对照

**完整（A+O+R+E）**
> 重构 4 张核心宽表（A+O），把看板刷新时间从 8 分钟降到 40 秒（R），独立完成建模与调度改造，数据取自 2023 年 Q2 生产监控（E）。

**缺 E**
> 重构 4 张核心宽表，把看板刷新时间从 8 分钟降到 40 秒。
> —— 能用，但面试会问"你改的是哪几张""别人有没有参与"。

**缺 R**
> 负责核心宽表的建模与调度优化。
> —— 等于没写。这是最常见的问题。

**缺 O**
> 主导优化，效率提升 40%。
> —— 优化了什么？40% 是谁的口径？不可信。

## 句式模板（按场景取用）

| 场景 | 模板 |
|---|---|
| 效率提升 | {动作} {什么系统/流程}，把 {指标} 从 {X} 降到 {Y}，{范围或周期} |
| 规模支撑 | {动作} {什么东西}，支撑 {多少用户/多少单/多少门店} 的 {什么需求} |
| 从 0 到 1 | 从零{搭建/设计} {什么}，{上线时间} 上线，{首期覆盖范围}，{当前状态} |
| 问题排查 | 定位 {什么异常}，拆出 {几类原因}，推动 {谁} 修复，{指标} 从 {X} 回到 {Y} |
| 成本节约 | {动作} {什么流程}，{周期} 内节省 {多少人力/多少钱}，{折算方式} |
| 团队与带教 | {带/培养} {几人}，{多长时间} 内 {产出什么}，{留存或晋升结果} |
| 跨部门推动 | 推动 {几个部门} 就 {什么事} 达成一致，{落地了什么机制}，{减少多少返工/争议} |

## 三个常见误改

1. **把"负责"换成"主导"就交差。**
   换词不改事实，面试一问就露。要么补出你主导的范围，要么老实写"负责其中 X 模块"。

2. **一句话塞五个指标。**
   读者记不住，还会怀疑真实性。一条一个主指标，其他放括号里。

3. **为了显得高级，用行业黑话。**
   "赋能业务全链路闭环"没人知道是什么。招聘方要的是"你让哪个数变了"。

## 长度控制

- 40-80 字：正常。
- 20-40 字：只够写"动作+对象"，适合次要条目。
- 80-120 字：只给最重要的 1-2 条，多了页面撑不住。
- 超过 120 字：拆成两条，或删掉修饰。

## 自检三问（写完每条都过一遍）

1. 这句话能不能换到别人的简历上？能，说明太泛。
2. 面试官问"这个数怎么来的"，我能不能当场答？不能，删数或补口径。
3. 删掉这条，我的简历会变弱吗？不会，就删。
