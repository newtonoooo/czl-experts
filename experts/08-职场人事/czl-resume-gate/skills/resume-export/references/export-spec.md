# 导出规范

## 为什么导出要单独一个技能

大部分简历死在导出这一步，不是内容问题：Word 里排得好看，系统读出来是乱的；PDF 是扫描件，文字提不出来；页边距太窄，打印被裁掉。**内容改完只是半成品，交付形态才算完成。**

## 三种交付形态与用途

| 形态 | 用途 | 不能用来 |
|---|---|---|
| `.docx` | 官网投递、内推发 HR、需要对方批注 | 自己打印（字体可能替换） |
| A4 HTML → 打印 PDF | 自己发邮件、需要固定版式 | 直接上传招聘系统（多数不收 HTML） |
| 纯文本 `.txt` | 招聘平台在线填写、系统只收文本 | 给人看（没有层级） |

**给用户的默认交付**：`简历.docx` + `简历.pdf`（由 HTML 打印）+ 一份 `简历.txt`（自查用）。

## 页面规格

| 项目 | 值 | 理由 |
|---|---|---|
| 纸张 | A4（210×297mm） | 国内与欧洲通用；投北美用 Letter 需单独说明 |
| 边距 | 上下 14mm、左右 16mm | 再窄打印会被裁，再宽一页装不下 |
| 正文 | 10.5pt（五号），行距 1.55-1.65 | 小于 10pt 打印发虚，大于 11pt 一页塞不下 |
| 姓名 | 18-20pt，加粗 | 唯一需要突出的元素 |
| 章节标题 | 11-12pt，加粗，带细分隔线 | 建立扫读锚点 |
| 页数 | 3 年以内 1 页；5 年以上最多 2 页 | 超过就是冗余 |
| 颜色 | 正文纯黑，最多一个强调色 | 彩色打印会变灰，且显得花 |

中文字体栈：`Microsoft YaHei → PingFang SC → Noto Sans SC → Source Han Sans SC`。英文简历用 `Calibri / Georgia`。

## 文件命名

```
姓名-岗位-年限-版本.扩展名
王小明-数据分析师-3年-20261026.docx
```

不要用 `简历.pdf`、`我的简历最终版3.pdf`。HR 一天收两百份，文件名是第一个筛选信号。

## 导出前必须过的六项自查

1. **纯文本粘贴测试**：把 docx 全选复制到记事本，顺序对不对、有没有乱码、公司职位时间能不能对上。
2. **页数**：打开 PDF 看实际页数，不是看编辑器的"第 1 页 / 共 1 页"。
3. **链接可点**：邮箱和作品集链接在 PDF 里能点开（不能点也无所谓，但必须能看清）。
4. **无图片承载信息**：所有文字都是真文字，不是图片。
5. **日期格式统一**：全文一种写法。
6. **文件名规范**：按上面的格式。

## 各形态的已知限制

**`.docx`（本技能自带生成器）**
- 用 OOXML 直接生成，不依赖 Word 或 python-docx。
- 支持：标题、段落、项目符号、编号列表、加粗、行内代码、引用、分割线。
- 不支持：图片、表格（表格会被拍平成单列文本，这是有意的）、页眉页脚、自动目录、脚注。
- 字体依赖阅读端：`微软雅黑` 缺失时回退 Calibri，版式会轻微变化。要绝对固定版式，导 PDF。

**A4 HTML**
- 打印用浏览器（Chrome/Edge）的 Ctrl+P，纸张选 A4，缩放 100%，勾选"背景图形"。
- 不要用"另存为 PDF"的打印驱动缩放，会导致边距变化。

**纯文本**
- 项目符号用 `•`，不用 `-`（部分平台会把 `-` 当分隔符）。
- 章节名全大写，方便解析器识别。

## 异常处理

- 用户要 PDF 但环境里没有浏览器打印能力：交付 HTML 并给出三步打印说明，不要谎称已生成 PDF。
- 用户要 Word 但需要图片/头像：说明本生成器不含图片；建议用 Word 手动加，或改走打印版 HTML。
- 导出后发现文字溢出到第二页一两行：优先删内容，不要压字号（压到 10pt 以下打印会糊）。
- 用户要求"两页压成一页"：先看能不能删，不能删就接受两页——挤成一页的代价通常比两页大。
