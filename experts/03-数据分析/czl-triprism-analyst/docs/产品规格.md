# 三棱镜 · 专业数据分析专家 —— 产品规格

版本 1.0.0 · 开发者 虫志龙 · 47190078@qq.com
本文档定义产品要做什么、不做什么、做到什么程度算合格。

---

## 1. 目标用户与实际使用场景

### 1.1 目标用户

| 用户类型 | 特征 | 他们真正缺的 |
|---|---|---|
| 一人公司 / 超级个体 | 自己是老板、财务、分析师、汇报人 | 没时间做系统性分析，但必须拿数据说话 |
| 中小企业经营者 | 有表但没数据团队 | 需要能问出问题的人，不是画图工具 |
| 部门负责人 | 要向老板/董事会汇报 | 结论要经得起追问"这个数怎么来的" |
| 财务/运营复核者 | 需要核对别人的分析 | 要能复现，而不是听结论 |

### 1.2 三个典型场景

**场景 A：月度经营会诊**
12 个月分区域分产品线销售表，30 分钟内要产出能开会的材料。
痛点：不知从哪看起；看到下跌不敢下结论；图老板看不懂。

**场景 B：数据可信度存疑时的初筛**
下属交来一张表，数字看着不对。先判断：业务真变了，还是数据有问题。
痛点：没有工具能快速判断"这张表能不能用"。

**场景 C：汇报前的自我质证**
已有一个结论，要在会上讲。需要先替老板问一遍："这 43% 怎么算的？分母是什么？"
痛点：自己检查自己，永远检查不出来。

## 2. 要解决的问题

| # | 问题 | 现状 | 解法 |
|---|---|---|---|
| P1 | 拿到表不知道从哪下手 | 凭经验挑几个指标看 | 强制体检：先摸清结构、时间轴、可分析性 |
| P2 | 数据不可用却硬分析 | 分析完才发现缺失 30% | 闸门机制：不可用直接拦停 |
| P3 | 多视角看数据时口径打架 | 趋势说涨、结构说跌，无法调和 | 口径冻结：同一分母、同一粒度、同一过滤 |
| P4 | 数字靠模型心算，不可靠 | 大模型算术易错 | 全部数字由本地确定性工具算出 |
| P5 | 结论无法验证 | 写完没人复核 | 证据链：每条结论附复算规格，自动重算 PASS/FAIL |
| P6 | 报告冗长，重点被埋 | 20 页找不到一句话 | 一页纸 + 分层交付 |
| P7 | 敏感数据不敢上传 | 只能手工做 | 全程本地，零外发 |

## 3. 必要的输入

### 3.1 文件

| 项 | 要求 |
|---|---|
| 格式 | `.csv` / `.tsv` / `.xlsx` / `.xlsm`（`.xls` 不支持，给转换提示） |
| 编码 | UTF-8 / UTF-8-BOM / GB18030 / GBK 自动识别 |
| 结构 | 首行表头，至少 2 行数据、2 列 |
| 大小 | 实测 5 万行 / 2.4MB 约 2.6 秒；建议单表 ≤ 20 万行 |
| 工作表 | 多表需指定主表，不指定取第一张并在报告注明 |

### 3.2 用户需提供的信息

| 信息 | 必需 | 缺省处理 |
|---|---|---|
| 分析目标（走势/结构/异常/全要） | 否 | 默认全要 |
| 核心指标 | 否 | 按"金额类优先 + 波动性"自动排序 |
| 拆解维度 | 否 | 取基数合适的前两个文本列 |
| 时间粒度 | 否 | 由日期列中位间隔推断 |
| 受众 | 否 | 默认"自己决策"，四件套全给 |
| 业务规则（如单笔上限） | 否 | 无规则则跳过规则扫描 |

## 4. 预期输出

### 4.1 四件套

| 文件 | 内容 | 用途 |
|---|---|---|
| `report.html` | 7 节完整报告，内联 SVG，单文件离线可看 | 复核、归档、打印 PDF |
| `onepager.md` | 三句话 + 关键数字 + 下一步 | 群消息、周报 |
| `deck.html` | 16:9 幻灯片网页版，含图表 | 投屏汇报 |
| `deck_spec.json` | 每页标题 + 要点 | 交给 PPT 能力生成 .pptx |
| `workbook.xlsx` | 6 个工作表 | 财务复核、二次加工 |

### 4.2 过程产物（可审计）

| 文件 | 内容 |
|---|---|
| `profile.json` | 体检：每列类型、缺失、分布、时间轴、评级 |
| `contract.json` | 冻结的口径 |
| `bundle.json` / `bundle.verified.json` | 三视原始结论 / 打上复算标记后的结论 |
| `verify.json` | 每条结论的复算结果 |
| `run.json` | 运行清单：输入哈希、耗时、输出文件与大小 |

### 4.3 每条结论的结构

```json
{
  "id": "C1",
  "claim": "销售额从 2025-01 的 971,614 变到 2025-12 的 1,392,924，整体上行，累计增长 43.36%",
  "value": 43.36,
  "unit": "%",
  "grade": "B",
  "recheck": { "op": "delta_pct", "field": "销售额", "agg": "sum", "grain": "month" },
  "verified": true
}
```

`recheck` 是硬要求：没有它，结论会被标 SKIP。

## 5. 通用处理步骤（六道工序）

| 工序 | 动作 | 判定 | 失败处理 |
|---|---|---|---|
| **S0 接料** | 问清表是什么、要解决什么、给谁看 | 三项至少答出两项 | 按默认假设推进并声明 |
| **S1 体检** | 解析、类型推断、缺失、重复、时间轴、评级 | `gate = pass/warn/block` | block 直接停，产出 `blocked.md` |
| **S2 冻口径** | 起草/校验口径 JSON | 字段存在、类型匹配、分母非零 | 校验失败退出码 2，不进入分析 |
| **S3 三视** | 走势 / 拆解 / 验伤 依次计算 | 各视产出 findings + recheck | 单视失败不影响其余两视 |
| **S4 复算** | 逐条复算 | PASS / FAIL / SKIP | FAIL 作废，SKIP 标注，整体 FAIL 拒绝交付 |
| **S5 交付** | 渲染四件套 + 运行清单 | 文件完整、大小非零 | 缺件即报错 |

## 6. 工具能力与技术接口

| 能力 | 实现 | 接口 |
|---|---|---|
| 表格读取 | `tools/triad_io.py` | `read_table(path, sheet)` |
| 类型推断 | 同上 | 数字/日期/文本/空，阈值 95% / 80% |
| 体检评级 | `tools/triad_profile.py` | `profile_table()` → A/B/C/D + 闸门 |
| 口径校验 | `tools/triad_contract.py` | `check_contract()` |
| 走势分析 | `tools/triad_analyze.py` | `analyze_course()` |
| 结构分析 | 同上 | `analyze_composition()` |
| 异常检测 | 同上 | `analyze_integrity()` |
| 复算 | `tools/triad_verify.py` | `verify_findings()` / `recompute()` |
| 渲染 | `tools/triad_render.py` | `build_html()` / `deck_html()` / `onepager_md()` |
| XLSX 写出 | `tools/triad_xlsx.py` | `write_workbook()` |
| 统一入口 | `tools/triad_cli.py` | `profile / analyze / verify / run` |
| 发布自检 | `tools/verify_package.py` | 字段一致性、引用、头像、语法、依赖、品牌词 |
| 打包 | `tools/build_release.py` | zip + sha256 + 文件清单 |

平台侧：仅使用文件读写与命令执行，不依赖多 agent 协作接口。

## 7. 质量、速度、稳定性要求

### 7.1 质量指标（实测）

| 指标 | 目标 | 实测 |
|---|---|---|
| 结论可复算率 | 100% 的 finding 带 recheck | 7/7、8/8 |
| 复算一致率 | ≥ 99% | 100%（所有复算用例 PASS） |
| 篡改检出 | 100% | 1/1 检出并作废 |
| 数字来源 | 100% 来自工具 | 渲染层不做计算，只格式化 |

### 7.2 速度（实测，Windows / Python 3.13）

| 数据规模 | 端到端耗时 |
|---|---|
| 108 行 CSV | 0.03 秒 |
| 5 万行 / 2.4MB CSV | 2.62 秒（含四件套渲染） |

### 7.3 稳定性

| 项 | 要求 | 现状 |
|---|---|---|
| 依赖 | 零第三方包 | 仅标准库 |
| 崩溃 | 输入异常必须给可读错误 | 全部入口 try/except，返回 JSON 错误 |
| 幂等 | 同输入同口径 → 同输出 | 无随机数 |
| 可追溯 | 每次运行产出 `run.json` | 已实现 |

## 8. 边界（明确不做）

1. 不做预测建模（只做保守线性外推，带区间与置信度）
2. 不做因果推断（只陈述"同期发生"）
3. 不做数据清洗改写（只标记问题，不改用户文件）
4. 不接入外部数据（不查行情、竞品、政策）
5. 不做实时/流式分析
6. 不生成 .pptx / .docx 本体
7. 不处理图片、音频、纯文本、PDF 表格
8. **不做多角色独立质证**（那是专家团版的能力）

## 9. 验收标准

- [ ] 体检评级与闸门结论出现在报告首页
- [ ] 三个视角各至少 1 条有效结论（或说明为何没有）
- [ ] 每条结论有等级（A/B/C/D）与复算状态
- [ ] 复算整体 PASS；有 FAIL 则正文不出现该结论
- [ ] 报告含口径全文与使用限制
- [ ] 四件套齐全且非空
- [ ] `run.json` 记录输入哈希与耗时
- [ ] 全程无网络请求
