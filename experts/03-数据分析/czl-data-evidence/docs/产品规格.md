## 一、为什么做这个产品

### 1.1 目标用户

| 用户 | 典型处境 | 他们真正要的东西 |
|---|---|---|
| 中小商家老板 / 店长 | 有一份订单或流水导出表，感觉"这个月不行"，但说不出哪不行 | 掉在哪、能不能救、先动哪一处 |
| 运营 / 增长岗 | 每周要出数据日报、活动复盘，被追问"为什么" | 一句能站住的归因，加一个可执行动作 |
| 产品经理 | 手里有漏斗、有 A/B 结果，要向决策层解释 | 这个差异是真的还是噪声，能不能上 |
| 分析师（初阶） | 会跑数，不敢下结论；或下了结论被质疑 | 结论分级、证据链、反例检查 |
| 个体创业者 | 没有 BI 团队，Excel 就是全部工具 | 不用装环境，把表丢进去就能得到判断 |

**不服务**：需要建模预测未来销量的人（本产品明确不做预测生意）、需要出具审计或法律意见的人、要求把结论"做得好看"的人。

### 1.2 要解决的问题

不是"不会算数"，是三类具体的判断失误：

1. **口径不明就开算**：GMV 含不含退款、活跃是登录还是下单、新客按首单还是按首登，口径不同结论可以相反。
2. **把噪声当信号**：几百单的波动被说成"趋势"，看一周数据就改策略，改完发现是自然波动。
3. **归因停在现象**：说"转化率低"，不说哪一步低、低多少、和谁比低、低了值多少钱。

产品的全部设计，都是为堵这三个洞。

### 1.3 输入与输出

**输入**（任何一种都行，不齐也能开工）：

- 一份或多份表格：CSV / TSV / Excel 导出的 CSV；
- 一组后台截图里抄下来的数字（手抄也行，只要说清是哪几项）；
- 一句业务问题 + 时间范围 + 一个目标（如"六月销售掉了 18%，要不要改价"）。

**输出**（按交付形态分三档）：

| 档 | 内容 | 用在什么时候 |
|---|---|---|
| 一页纸 | 一个结论句 + 三条证据 + 一个动作 + 一句"什么情况下这个结论会翻" | 周会、汇报、给老板看 |
| 完整报告 | 口径账、质量账、分析过程、证据账、局限与反例 | 复盘归档、跨部门对齐 |
| 看板规格 | 指标树、维度、刷新频率、告警线、口径卡 | 交给做看板的人落地 |

所有交付物落盘 Markdown，可一键导出 docx / html。

## 二、产品的核心方法：三账五验

这是本产品与"会跑数的 AI"的分界线。三账是过程留痕，五验是出门前的检查。

### 2.1 三账

| 账 | 记什么 | 什么时候必须建 |
|---|---|---|
| **口径账** | 每个指标的：业务含义、分子、分母、时间窗、排除项、边界情况 | 开工第一件事，没有它不许算 |
| **质量账** | 行数、字段类型、缺失率、重复、异常值、口径冲突、可用性评级 | 拿到数据第二件事 |
| **证据账** | 每条结论 → 用了哪份数据 → 什么方法 → 效应量与区间 → 反例检查结果 | 写结论的同时逐条填 |

### 2.2 五验（结论出门前的五道关）

| # | 验证 | 问的问题 | 不过怎么办 |
|---|---|---|---|
| 1 | 口径验 | 这个数算的是不是提问人以为的那个东西 | 改口径重算，或把两种口径并列给出 |
| 2 | 分布验 | 结论是不是被少数样本或极端值带偏 | 看中位数/分位数/去极值后重算 |
| 3 | 对照验 | 有没有基线？自然波动、季节、大促能否解释 | 补对照组或历史基线；补不了就降级为"待观察" |
| 4 | 效应验 | 差多少？区间多宽？值不值得动 | 给区间；效应太小直接说"不值得改" |
| 5 | 反例验 | 什么样的数据会推翻我 | 主动去找，找到就改结论 |

五验全过 → 结论标 **A 可直接决策**；缺对照或缺区间的 → **B 有条件可用**（写清条件）；只有一段数据、无基线的 → **C 仅供观察**；五验中任一明确不过 → **D 不成立**，重做。

这个分级是本产品的核心交付物。用户拿到的不只是"结论"，还有"这句话能拿去做多大的决定"。

## 三、功能需求（编号即实现依据）

### FR-1 提问转任务书

把"帮我看看数据"转成可执行的分析任务：决策问题、判定标准、口径、时间范围、产出形态、不做什么。

- 判断条件：决策问题不明确时，先给 2–3 个候选问法让用户点选，不做开放式追问。
- 输出：任务书（含假设登记）。

### FR-2 数据体检

读表后先给可用性评级，再谈分析。

- 检查项：行列数、字段类型识别、缺失率、重复行、单值列、异常值、日期连续性、口径冲突线索（如状态字段里有"退款"但金额未冲销）。
- 输出：质量账 + A/B/C/D 可用性评级 + 三条"这会怎么影响结论"的提示。
- 判断条件：D 级必须停下来先问用户"补数据还是降级继续"。

### FR-3 探索与假设

先看形状，再看关系，最后给假设清单。

- 必做：目标指标的时间趋势、分布形态（均值 vs 中位数偏离）、按主要维度拆开看。
- 输出：假设清单，每条写明"如果这个假设成立，应该看到什么"。

### FR-4 归因五法

按问题类型选方法，不混用。

| 问题形态 | 方法 | 判据 |
|---|---|---|
| 总量变了，想知道是哪块变的 | 结构分解（量/价/结构） | 各因子贡献之和 ≈ 总变化 |
| 转化链路卡住 | 漏斗 | 找出"跌幅显著大于其他步"的那一步 |
| 用户留存变差 | 同期群 | 新老群对比，排除结构变化 |
| 整体与分群结论相反 | 分群对比 | 检查辛普森悖论 |
| 改了东西之后变了 | 实验/准实验 | 有对照组才谈因果，没有只谈相关 |

### FR-5 结论分级与举证

- 五验逐条过，结论标 A/B/C/D。
- 每条结论必须写"什么会推翻它"。
- 输出：证据账。

### FR-6 交付与落地

- 一页纸：结论句（≤40 字）+ 三条证据 + 一个动作 + 翻盘条件。
- 报告：三级结构（给老板 / 给团队 / 给行家）。
- 看板规格：指标树 + 维度 + 刷新 + 告警线。
- 导出：Markdown → docx / html。

### FR-7 工具能力与接口

全部脚本纯标准库、零第三方依赖、可离线，命令行调用，输出 Markdown 便于归档。

| 能力 | 接口 | 约束 |
|---|---|---|
| 表体检 | `profile_table.py <csv>` | 支持 UTF-8/GBK 自动识别 |
| 两期对比与分解 | `period_compare.py` | 支持量/价/结构三因子 |
| 漏斗 | `funnel_steps.py` | 支持计数串或事件表 |
| 同期群 | `cohort_retention.py` | 按首期分组，按周期回看 |
| 分层 | `segment_abc.py` | ABC 与分位分层，含 RFM 三档 |
| 实验检验 | `ab_test.py` | 比例检验、均值检验、bootstrap 区间、MDE |
| 导出 | `doc_export.py` | docx（真实 OOXML）/ html |

### FR-8 质量、速度、稳定性要求

- **质量**：每个数字可复算（给出命令与参数）；每个结论有分级；不确定就写不确定。
- **速度**：10 万行以内的 CSV，单脚本 30 秒内出结果（实测见测试报告）。
- **稳定**：脚本对缺列、空文件、非数字、日期格式混乱必须给出中文错误提示，不抛堆栈吓人。
- **可离线**：不联网也能完成全部计算与出具报告。

## 四、与同类产品的差异（设计取向，不是文案）

1. **先立口径再算数**：多数工具直接出图，本产品拒绝在口径未定时计算，把口径账作为一等交付物。
2. **结论分级**：交付物里最有价值的一行，是"这个结论能拿去做多大的决定"，而不是分析过程多长。
3. **反例检查写进流程**：每条结论必须自带"什么会推翻它"，且要主动去找。
4. **不做预测**：明确拒绝销量预测、股价预测一类需求，避免用相关冒充因果、用拟合冒充判断。
5. **手抄数据也算输入**：不强制有数据库或 BI，只要数字说得清来源。

## 五、明确不做的范围

| 不做 | 原因 |
|---|---|
| 销量/流量/股价预测 | 无法保证，且容易让用户据此压货压钱 |
| 出具审计、税务、法律意见 | 需持牌专业机构 |
| 处理含个人身份信息的明细（手机号、身份证、住址） | 最小必要原则，只接受聚合数据或已脱敏数据 |
| 替用户"美化"结论 | 与产品立场冲突 |
| 抓取第三方平台数据 | 合规风险，只处理用户提供的数据 |
