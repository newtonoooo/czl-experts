## 一、为什么这样测

一般"能跑就行"的测试看不出问题。这份测试的设计原则是：

1. **真值独立**：期望值全部手算后硬编码在测试里，不从被测代码取。被测代码改了却"自己算对了自己"，测不出来。
2. **只测行为不测实现**：断言命令行输出里的具体数字与措辞，不检查内部函数，保证重构后测试仍有效。
3. **异常路径与正常路径同权重**：参数错误、文件缺失、列名不存在都必须给出中文提示并退出码 2，不能抛堆栈。
4. **产物可验证**：docx 不仅检查"文件存在"，还校验 zip 结构、XML 合法性、是否含表格、中文是否丢失。

## 五、未验证事项（不宣称通过）

| 项 | 原因 | 影响 |
|---|---|---|
| docx 在 Microsoft Word / WPS 中的**视觉**呈现 | 本机无法启动 Office 做目视检查，只做了结构与 XML 校验 | 排版观感（字号、行距、表宽）未验证；结构合法不代表好看 |
| Excel `.xlsx` 直读 | 产品不支持，需另存 CSV | 属已知限制，非缺陷 |
| 10 万行以上大文件的性能 | 未做压测，只测了 680–2000 行 | 速度承诺未验证 |
| macOS / Linux 运行 | 仅 Windows 验证 | 路径与编码在其它系统可能需微调（代码已用 `os.path`，风险低） |
| 在 WorkBuddy 对话中真实召唤专家跑完整工序 | 需重启客户端并人工发起会话 | 提示词的指令遵循度、语气是否符合预期，未经真实对话检验 |
| 平台审核本身 | 需提交后台 | 审核结论未知 |
| 统计实现与权威库的逐位比对 | 采用手算真值验证，未与 R/Python statsmodels 交叉验证 | 极端参数（极小样本、极端比例）可能有偏差；已在文档标注 t 分位数为二分近似 |

## 六、复现方法

```bash
# 1. 重新生成样例数据（会打印手算真值）
python skills/czl-evidence-playbook/samples/make_demo_data.py skills/czl-evidence-playbook/samples

# 2. 跑全部测试（测试器需在包外，例如放构建目录）
python run_functional_tests.py <本包目录> <日志路径>

# 3. 单点验证某一项
cd skills/czl-evidence-playbook/scripts
python period_compare.py ../samples/orders_demo.csv --date 支付日期 --value 金额 \
    --qty 件数 --period 2026-05:2026-06 --by 渠道
```
