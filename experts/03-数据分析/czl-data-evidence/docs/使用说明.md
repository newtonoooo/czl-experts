# 使用说明

面向两类人：要用它的分析师和老板；要审它的平台审核人员。分开写。

---

## 一、给使用者

### 1. 安装

**方式 A · 本地目录**

把 `czl-data-evidence/` 整个目录放到：

```
~/.workbuddy/plugins/marketplaces/my-experts/plugins/czl-data-evidence/
```

重启 WorkBuddy，在专家中心「我的专家」里出现 **数证台**。

**方式 B · 导入 zip**

用专家中心的导入功能选择 `czl-data-evidence.zip`。zip 内顶层目录名必须保持 `czl-data-evidence`，不要解压后改名再压——目录名要和 `plugin.json` 里的 `name` 一致，否则识别不到。

### 2. 运行要求

| 项 | 要求 |
|---|---|
| WorkBuddy | 支持专家包 |
| Python（仅脚本功能） | 3.8 及以上，**纯标准库，不用装任何包** |
| 网络 | 全程可离线，不做联网请求 |
| 数据格式 | CSV / TSV（Excel 请先另存为 CSV，UTF-8 或 GBK 都行） |
| 磁盘 | 整包约 300 KB |

没有 Python 也能用：脚本里的判据在提示词和参考文档里都有对应检查表，只是要人工算，且必须在交付里注明「未跑脚本，结果为手算」。

### 3. 怎么开口

三种最省事的说法：

1. **报现象**：「六月销售额掉了 18%，帮我看掉在哪。」→ W1 → W2 → W3 → W4
2. **报数据**：「这是漏斗，访问 1 万、加购 3200、下单 1500、支付 980，哪步最该动？」→ W4 漏斗
3. **要判断**：「A/B：对照 1 万人转化 512，实验 1 万人转化 583，能上吗？」→ W5 定级

缺什么它会自己补，补的东西写在「假设登记」里，你看一眼就能推翻。

### 4. 一次完整交付长什么样

以销售下滑为例：

| 次 | 你拿到 | 对应记录单 |
|---|---|---|
| 1 | 任务书 + 口径账（含假设登记） | T1、T2 |
| 2 | 质量账 + 可用性评级 + 三条影响提示 | T3 |
| 3 | 假设清单（每条带可验证预测） | T4 |
| 4 | 归因结论 + 证据账（五验逐条）+ 定级 | T5 |
| 5 | 一页纸（结论+三条证据+一个动作+翻盘条件） | T6 |

报告和看板规格按需另出。

### 5. 交付物在哪

- 默认落盘 Markdown，路径会在回复里写明；
- 要 Word / 网页：`python doc_export.py 报告.md --to docx,html`，生成在 Markdown 同级的 `导出/` 下；
- 命名约定：`<主题>-<形态>-<日期>.md`，如 `六月下线下滑-复盘-20261026.md`。

### 6. 四个用得顺手的习惯

- **先给决策场景**。说清"这个结论拿去干什么"，比多给十列数据有用。
- **数据能给几项给几项**。只有汇总数字也能做，但最高只能给 B 级。
- **不信结论就改假设**。它的判断建立在假设栏那几行上，改假设比争论结论有效。
- **别让它保证准确**。它不会承诺"一定对""一定涨"，只会给级别、区间和翻盘条件。

### 7. 脚本速查

```bash
# 体检
python profile_table.py 订单.csv --by 渠道 --key 订单号

# 两期对比 + 量价拆解
python period_compare.py 订单.csv --date 支付日期 --value 金额 --qty 件数 \
    --period 2026-05:2026-06 --by 渠道

# 漏斗（可带基期）
python funnel_steps.py 访问=10000,加购=3200,下单=1500,支付=980 --aov 120
python funnel_steps.py 访问=10000,加购=3200,下单=1500,支付=980 \
    --baseline 访问=9800,加购=3600,下单=1700,支付=1050

# 同期群
python cohort_retention.py 事件.csv --user 用户ID --date 日期 --period month

# 分层
python segment_abc.py 订单.csv --key 客户ID --value 金额 --rfm --date 支付日期

# 检验
python ab_test.py --control 512/10000 --treat 583/10000
python ab_test.py --file ab.csv --group 组别 --metric 是否转化

# 导出
python doc_export.py 报告.md --to docx,html
```

每个脚本都可加 `--help`。退出码：0 成功，2 参数或数据有问题（会给出中文提示，不抛堆栈）。

## 二、给审核人员

### 1. 平台规范符合性

| 规范项 | 本包实现 |
|---|---|
| 入口清单 | `.codebuddy-plugin/plugin.json` |
| 类型 | `expertType: "agent"`，单角色 |
| agentName 与文件 | `czl-data-evidence` ↔ `agents/czl-data-evidence.md`，同名 |
| 展示字段 | `displayName` / `profession` / `displayDescription` / `defaultInitPrompt` / `tags`(3) / `quickPrompts`(3)，均含 en/zh |
| 头像 | `avatars/expert.png`，512×512，150.7 KB，PNG |
| 分类 | `04-DataAI`（数据智能） |
| 禁止项 | 无 `hooks/`、`commands/`、`.lsp.json`；`agents/skills/avatars` 均在包根 |
| Agent MD frontmatter | 含 `name`/`description`/`displayName`/`profession`/`maxTurns`，**不含 `tools`** |

### 2. 目录职责

```
workflows/   流程层：六道工序，含输入、步骤、判断、输出、异常、依赖、衔接
templates/   表单层：六张记录单，与工序一一对应
references/  方法层：八份方法参考，通用统计知识，自行表述
scripts/     工具层：八个纯标准库脚本，全部手写
samples/     样例层：四份合成数据 + 生成器，真值可手算
```

### 3. 引用关系

- 提示词按「工作流第 01–06 号文件」「记录单 T1–T6」引用，文件名变更需同步提示词与 `SKILL.md`（本包已对齐，实测 12/12 可达）；
- 脚本之间只有 `import czl_core`，无绝对路径、无外部依赖；
- 样例数据用相对路径 `../samples/` 访问，与脚本同包。

### 4. 可复现的自检命令

```bash
# 结构校验（须在专家目录内执行）
python <专家包管理工具目录>/validate_expert.py <专家目录>

# 全部脚本可编译
cd skills/czl-evidence-playbook/scripts && for f in *.py; do python -c "import py_compile;py_compile.compile('$f',doraise=True)" || echo "FAIL $f"; done

# 功能测试（真值断言 + 异常路径）
python run_functional_tests.py <expert-dir> <日志路径>

# 敏感信息扫描
grep -rInE "sk-[A-Za-z0-9]{16,}|api[_-]?key|password|secret|token" . --include=*.py --include=*.json
```

### 5. 已知边界

- 不含联网能力，也不做任何外发请求；
- 只读 CSV/TSV，不读 `.xlsx`；
- `doc_export.py` 支持有限的 Markdown 子集，复杂排版（脚注、公式、图表）不支持；
- 知识库是通用方法论，不含任何平台的实时规则或内部数据。

## 三、常见问题

**Q：和直接把表丢给 AI 有什么区别？**
它会先问口径、先体检数据、给结论定级。多数 AI 直接开始算，算出来的数你不知道能信几分。

**Q：能不能只让它出图/做 PPT？**
不做。它出的是判断和记录，图请用专门的工具。看板规格里有该画哪些指标的建议。

**Q：为什么不给我预测？**
预测需要假设未来与历史同分布，商业场景经常不成立。它宁可给你"现在的结构哪里脆"，也不给一个看起来精确的假数字。

**Q：数据里有客户手机号怎么办？**
拒绝处理明细。改成聚合数据，或给我脱敏编号表。

**Q：结论和我预期相反，能改得乐观些吗？**
不改数字。可以给"要达成目标需要哪一项指标改善多少"的反向测算，这是两回事。
