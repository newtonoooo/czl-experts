# 样例数据说明

这四份数据是**手工设计的**，每份的真值都能口算核对。用途有两个：验证脚本算得对；给使用者一个可以直接上手的例子。

**都不含任何真实业务数据或个人信息。**

---

## 1. `orders_demo.csv` — 订单表（680 行）

| 列 | 含义 |
|---|---|
| 订单号 | 唯一订单号 |
| 客户ID | 20 个客户循环出现 |
| 支付日期 | 2026-05-01 至 2026-06-30，每天都有 |
| 渠道 | 线上 / 门店 |
| 品类 | 日用品 / 食品 |
| 件数 | 每单 1 件 |
| 金额 | 单价 × 1 |
| 状态 | 已完成 / 已退款（每 17 单有一单标记退款，但金额未冲销，用于演示口径冲突） |

**设计真值**

| 项 | 2026-05 | 2026-06 | 变化 |
|---|---|---|---|
| 线上 | 240 单 × 100 = 24,000 | 120 单 × 100 = 12,000 | -12,000 |
| 门店 | 160 单 × 100 = 16,000 | 160 单 × 150 = 24,000 | +8,000 |
| **合计** | **40,000（400 单）** | **36,000（280 单）** | **-4,000（-10.00%）** |

三因子分解（可手算核对）：

- 量：Δ量(-120) × 基期价(100) = **-12,000**
- 价：基期量(400) × Δ价(28.5714) = **+11,428.57**
- 交互：Δ量 × Δ价 = **-3,428.57**
- 合计：-12,000 + 11,428.57 - 3,428.57 = **-4,000.00** ✓

**故意留的坑**

- 状态列有「已退款」但金额未冲销 → 演示口径账与一致性检查；
- 单价从 100 变 150 只发生在门店 → 演示"整体跌、某组涨"的结构变化。

## 2. `events_demo.csv` — 漏斗事件表（1568 行）

列：用户ID、日期、步骤。

**设计真值（按用户去重）**

| 步骤 | 人数 | 单步转化率 |
|---|---|---|
| 访问 | 1000 | — |
| 加购 | 320 | 32.00% |
| 下单 | 150 | 46.875% |
| 支付 | 98 | 65.333% |

带客单价 120 元时，「访问→加购」提升 1 个百分点 ≈ 10 人 ≈ 1,200 元。

## 3. `cohort_demo.csv` — 同期群（90 行）

列：用户ID、日期、访问次数。

| 同期群 | 人数 | 第 1 期 | 第 2 期 |
|---|---|---|---|
| 2026-07 | 20 | 12 → 60.0% | 8 → 40.0% |
| 2026-08 | 20 | 10 → 50.0% | 数据未到，显示 — |
| 2026-09 | 20 | 数据未到，显示 — | — |

第 2 期留存均值（只算可观测的两个群）= (60.0% + 50.0%) / 2 = **55.0%**。

> 用于检验一个常见错误：把"观测不到"当成"留存为 0"。正确做法是标「—」并从均值里剔除。

## 4. `ab_demo.csv` — A/B 明细（2000 行）

列：组别（control / treat）、是否转化（0/1）、客单价。

**设计真值**

| 组 | 样本 | 转化 | 比例 |
|---|---|---|---|
| 对照 | 1000 | 51 | 5.10% |
| 实验 | 1000 | 78 | 7.80% |

差异 +2.70 个百分点；两比例 z 检验 z≈2.458，双侧 p≈0.0140；95% 区间约 [+0.55, +4.85] 个百分点。

## 5. 怎么用

```bash
cd scripts
python profile_table.py ../samples/orders_demo.csv --by 渠道 --key 订单号
python period_compare.py ../samples/orders_demo.csv --date 支付日期 --value 金额 --qty 件数 --period 2026-05:2026-06 --by 渠道
python funnel_steps.py --file ../samples/events_demo.csv --user 用户ID --step 步骤 --order 访问,加购,下单,支付 --aov 120
python cohort_retention.py ../samples/cohort_demo.csv --user 用户ID --date 日期 --period month
python segment_abc.py ../samples/orders_demo.csv --key 客户ID --value 金额 --rfm --date 支付日期
python ab_test.py --control 51/1000 --treat 78/1000
python ab_test.py --file ../samples/ab_demo.csv --group 组别 --metric 是否转化
```

跑出来的数应与上面各表一致。不一致，说明脚本或参数有问题，先别用它的结论。
