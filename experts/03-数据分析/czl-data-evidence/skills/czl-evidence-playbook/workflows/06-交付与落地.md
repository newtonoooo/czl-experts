# W6 · 交付与落地

## 职责

把证据账变成三种人能看的东西：老板看的一页、团队执行用的正文、行家复核用的附录。同时给出落地动作与复盘埋点。

结论写不完的，不要靠篇幅补，靠删。

## 输入参数

| 参数 | 是否必需 | 说明 | 缺失时怎么办 |
|---|---|---|---|
| 证据账 | 必需 | W5 产出 | 无 → 回 W5 |
| 交付形态 | 必需 | 一页纸 / 报告 / 看板规格 | 默认一页纸 |
| 读者身份 | 强烈建议 | 老板 / 业务负责人 / 分析师 | 不知道 → 按"老板+业务"双读者写 |
| 行动成本约束 | 建议 | 预算、人力、时间上限 | 无 → 给动作按成本从低到高排序 |

## 执行步骤

1. **先定动作，再写报告。** 一页纸的核心是一个动作，不是一段分析。写不出动作，说明证据不足，回 W5。
2. **写一页纸四件套。**
   - 结论句（≤40 字，带级别）
   - 三条证据（每条一句话 + 一个数字）
   - 一个动作（谁、做什么、什么时候、预期动多少）
   - 翻盘条件（什么数据出现就推翻这个结论）
3. **写正文。** 结构：问题 → 口径与数据 → 定位 → 归因 → 动作与预期 → 局限。
4. **写附录。** 口径账、质量账、方法参数、复现命令、已排除的解释（D 级）。
5. **需要看板时写规格。** 指标树（北极星 → 一级 → 二级）、维度、刷新频率、告警线、每个指标的口径卡路径。
6. **落盘并导出。** Markdown 存档；需要 Word 或网页时用 `doc_export.py`。

## 判断条件

| 判断点 | 条件 | 动作 |
|---|---|---|
| 最高级别 | A | 一页纸给明确动作与预期增量 |
| 最高级别 | B | 动作写成"建议先小范围试"，并写清验证条件 |
| 最高级别 | C | 不给动作，只给"建议继续观察的 2 个指标 + 观察多久" |
| 全部 D | 是 | 交付"排除了什么"，这本身有价值，别硬凑结论 |
| 读者要做预算决策 | 是 | 必须给区间，不给点估计 |

## 输出格式

**一页纸（`T6-结论一页纸.md`）**

```
结论：<一句话，≤40 字>　[级别 A/B/C/D]
证据：① …（数字）　② …（数字）　③ …（数字）
动作：<谁> 在 <何时> 做 <什么>，预期 <指标> 变动 <区间>
翻盘：若出现 <具体数据现象>，本结论作废，改用 <备选解释>
```

**报告**：三级标题结构，正文不超过 3 页（不含附录）。

**看板规格**：指标树表格 + 告警线 + 口径卡引用。

## 异常处理

- **用户要"结论再乐观一点"**：拒绝改数字。可以提供"若要达成目标，需要哪一项指标改善多少"的反向测算，这是两回事。
- **用户要求删掉限制条件**：不删。可以把局限放附录，但附录必须在交付里。
- **结论涉及跨部门责任**：只写数据与事实，不写"某部门失职"。归因到流程与环节，不归因到人。
- **导出失败**：交付 Markdown 原文并说明失败原因，不谎报已导出。

## 必要依赖

`scripts/doc_export.py`、`templates/T6-结论一页纸.md`、`references/06-图表与汇报结构.md`。

## 与其他工作流的关系

- **上游**：W5 证据账。
- **下游**：本工序是终点。附"复盘埋点"：下次同类分析应该在上线后第 N 天回看哪两个指标。
- **回流**：若在写动作时发现"证据撑不起动作"，回 W5 复核定级，不要为了有动作而拔高级别。
