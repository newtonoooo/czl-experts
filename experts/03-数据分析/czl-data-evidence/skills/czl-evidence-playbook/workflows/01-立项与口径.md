# W1 · 立项与口径

## 职责

把"帮我看看数据"变成一份能执行、能验收的分析任务；同时把每个指标的口径钉死。这一步不产出任何结论，只产出两个东西：**任务书**和**口径账**。

## 输入参数

| 参数 | 是否必需 | 说明 | 缺失时怎么补 |
|---|---|---|---|
| 决策问题 | 必需 | 拿到结论要做什么决定 | 从用户原话里提炼；提炼不出，给 2–3 个候选问法让他点选 |
| 现象描述 | 必需 | 用户看到什么、什么时候开始的 | 让用户给一句"哪天开始觉得不对" |
| 判定标准 | 建议 | 什么算"好"、什么算"该动手" | 默认用历史同期 ±10% 作为参考带，写进假设 |
| 时间范围 | 建议 | 数据起止 | 默认最近两个完整月，写明"按最近两个月推断" |
| 指标口径 | 强烈建议 | 分子分母、排除项 | 按行业惯例补，并标注为假设 |
| 交付形态 | 建议 | 一页纸 / 报告 / 看板规格 | 默认一页纸 |

> 手上没有任何数据时也能立项：把"需要哪几项数据、在哪拿"写进任务书，作为交付物之一。

## 执行步骤

1. **还原决策场景。** 问清"这个结论会被用来做什么"。改价、换渠道、加投放、砍 SKU、还是只想知道——四种目标对应四种分析深度。
2. **写下判定标准。** 什么样算"掉得有问题"。没有标准，后面所有显著性都无处落地。
3. **拆指标。** 用户嘴里的"销售""业绩""单量"落到具体字段上。一个词对应一个指标卡。
4. **立口径账。** 逐项填 `templates/T2-口径账.md`：业务含义、分子、分母、时间窗、排除项、边界情况。
5. **暴露冲突。** 如果两份数据的口径不一致，不合并，在任务书里列为"待裁定项"。
6. **列假设。** 推断出来的东西全部进「假设登记」：补了什么、依据什么、影响哪一步结论。
7. **定交付。** 一页纸 / 报告 / 看板规格，三选一，写清交付时间和依赖项。

## 判断条件

| 判断点 | 条件 | 动作 |
|---|---|---|
| 决策问题是否明确 | 说得出"用在哪" | 直接进 W2；说不出 → 给候选问法，选完再进 |
| 口径是否可确定 | 用户能说清或数据字典有 | 填口径账；不能 → 并列两种口径，写"影响待评估" |
| 是否需要立即体检 | 有原始表格 | 进 W2 |
| 是否只有汇总数字 | 无表、手抄数据 | 跳过 W2，直接 W3，且全程最高只能给 B 级 |
| 是否有多个互斥目标 | 既想降本又想增长 | 拆成两次分析，一次只答一个 |

## 输出格式

`T1-分析任务书.md` 一份，必须含：

- 一句话问题（谁、在什么决策上、需要知道什么）
- 判定标准（数字化的）
- 口径账（T2，可引用附页）
- 假设登记（表格：假设 | 依据 | 影响 | 可否被推翻）
- 不做什么（明确划掉的相邻问题）
- 交付形态与依赖

## 异常处理

- **用户拒绝说口径**：按行业默认口径算，报告开头用一行黑体标明"口径为默认假设，若贵司口径不同，结论可能反转"。不因用户不配合就不标注。
- **指标名与实际字段对不上**（如"销售额"实为"应付金额"）：以字段为准，指名字段名，别顺着用户的词走。
- **时间字段有多个**（下单/支付/发货）：默认用业务确认口径最常用的那个（电商用支付时间），并在口径账写明，附一句"若按发货时间口径，结果会差 ×%"（若可算）。
- **用户要的结论与数据能支持的不匹配**：在任务书"不做什么"里写明，提前管理预期。

## 必要依赖

无脚本依赖。用到 `templates/T1`、`templates/T2`。

## 与其他工作流的关系

- **上游**：无。这是入口。
- **下游**：有表格 → W2；无表格 → W3。
- **回流**：W5 若判定"口径错误"导致结论不成立，退回本工序重立口径。
