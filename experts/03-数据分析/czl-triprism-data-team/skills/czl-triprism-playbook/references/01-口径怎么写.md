# 口径怎么写

口径没写清，后面所有数字都是废的。这一份讲怎么把一句模糊的业务话，变成一段能复算的定义。

---

## 一、一个指标必须回答的六个问题

| 问题 | 写错的后果 | 正确写法示例 |
|---|---|---|
| **算什么** | 名字对不上字段 | 销售额 = 订单金额合计 |
| **怎么算** | 用平均值代替合计 | `agg: sum` |
| **单位** | 万元和元混着说 | `unit: 元`（报告里统一换算成万元再说） |
| **分母是谁** | 成本率算成 120% | 成本率 = 成本 / 销售额 |
| **按什么切** | 日数据和月数据比 | `grain: month` |
| **排除什么** | 把测试单算进营收 | 过滤：`订单状态 != 已取消` |

六个里缺任何一个，报告里就不许出现这个指标的百分比。

## 二、合同 JSON 的最小形态

```json
{
  "contract_version": 1,
  "table": "sales_2025.xlsx",
  "sheet": "明细",
  "grain": "month",
  "time_field": "月份",
  "metrics": [
    { "id": "M1", "name": "销售额", "field": "销售额", "agg": "sum", "unit": "元",
      "definition": "含税订单金额合计，不含运费与退款" }
  ],
  "ratios": [
    { "id": "R1", "name": "成本率", "numerator": "成本", "denominator": "销售额" }
  ],
  "dimensions": ["区域", "产品线"],
  "filters": [
    { "field": "订单状态", "op": "not_in", "value": ["已取消", "测试单"] }
  ],
  "rules": [
    { "id": "RULE1", "type": "max_single", "field": "销售额", "threshold": 500000,
      "message": "单笔超 50 万需二次审批" }
  ],
  "comparison": { "mode": "mom" }
}
```

字段含义不用背，跑一次 `check` 就知道哪里不对：

```bash
python tools/triad_cli.py run --path data.xlsx --contract contract.json --outdir out
```

## 三、四个最容易出事的写法

### 1. 用「平均」代替「合计」

「客单价」不是 `mean(订单金额)`，是 `sum(订单金额) / count(distinct 订单号)`。
后者在本工具里要用 `ratios` 写，不能塞进 `metrics` 的 `agg: mean`。

### 2. 分母会变

「转化率 = 成交数 / 访问数」——如果访问数里有机器人流量，分母虚高，转化率就假性偏低。
**分母要单独定义，并且和分子用同一批过滤条件。**

### 3. 时间粒度混用

月度报告里出现「本周环比」，一定是错的。`grain` 只能有一个值，全流程统一。

### 4. 同名不同义

「收入」在财务口径是确认收入，在运营口径是流水。**表里两列都叫"收入"时，必须先问清是哪一列**，不要自己挑。

---

## 四、口径需要用户确认的三个时刻

1. **指标有歧义时**（同名不同义、含税不含税、是否含退款）
2. **需要排除异常行时**（取消单、测试单、内部单）
3. **跨期对比基期不一致时**（去年有 12 个月，今年只有 9 个月）

这三个时刻不问，后面一定返工。

---

## 五、口径变更的处理

用户中途改口径 → **旧结论全部作废**，从 P2 重跑。
不允许"新口径算出来的数"和"旧口径算出来的数"混在同一份报告里——哪怕只差 0.3%。
