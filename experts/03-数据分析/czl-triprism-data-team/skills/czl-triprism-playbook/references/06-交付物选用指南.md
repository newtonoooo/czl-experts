# 交付物选用指南

四件套不是每次都要全给。给错了，等于让人在会议室里翻 20 页找一句话。

---

## 一、按场景选

| 场景 | 给什么 | 不给什么 |
|---|---|---|
| 微信/企微群里同步一句结论 | `onepager.md` | 完整报告、Excel |
| 周报/月报里插一段 | `onepager.md` + 一张图 | 全套 |
| 部门内部复盘会 | `report.html` + `deck.html` | 明细 Excel |
| 向上汇报（10 分钟） | `deck.html` 或 `deck_spec.json` 转 PPT | 完整报告 |
| 财务/审计要核对 | `workbook.xlsx` + `report.html` 的证据链章节 | 幻灯片 |
| 自己深挖 | `workbook.xlsx` + `bundle.verified.json` | 排版好的成品 |
| 存档留痕 | `run.json` + 全套 | — |

---

## 二、四件套各自解决什么

### `report.html` — 完整报告

- 结构：结论 → 体检 → 三线 → 证据链 → 口径
- 用途：需要别人**复核你的判断过程**时
- 特点：单文件、离线可看、可直接打印成 PDF
- 不要用它：投屏（太长）、发群（太重）

### `onepager.md` — 一页纸

- 内容：三句话 + 关键数字 + 下一步
- 用途：**已经在开会/已经在写周报**，只需要结论
- 不要用它：需要论证过程时

### `deck.html` / `deck_spec.json` — 幻灯片

- `deck.html`：浏览器直接投屏，方向键翻页，可打印成 PDF
- `deck_spec.json`：每页标题 + 要点，交给平台的 PPT 能力生成 `.pptx`
- 用途：10 分钟汇报
- 不要用它：需要精确复现某页排版时（此时用 PPT 工具手工调）

### `workbook.xlsx` — 数据底稿

- 六个表：概览 / 走势 / 结构 / 异常清单 / 证据链 / 体检明细
- 用途：财务复核、二次加工、留档
- 不要用它：直接发领导（他们要的是结论不是表）

---

## 三、一页纸的写法（最容易写坏）

一页纸只允许三句话，每句必须满足：

1. **有数字**（"销售额增长 43%" 而不是 "销售额增长明显"）
2. **有方向**（增/减/集中/分散）
3. **有边界**（"在样本 108 行、12 个月的口径下"）

写不出来，说明分析还没到位，别硬凑。

---

## 四、什么时候必须补一份"口头摘要"

交付时在对话里给不超过 5 行：

```
结论：<一句话>
风险：<一句话>
下一步：<一句话>
证据：<复算 PASS 数/总数>，报告见 <文件名>
```

**不要让用户自己从文件里找重点。**
