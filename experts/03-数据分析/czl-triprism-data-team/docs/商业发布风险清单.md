## R1 · 原创性

**判断依据**

- 提示词、技能包、代码、文档均为本次独立撰写/编写，未复制目标产品的句子或结构命名
- 继承的仅是"多视角并行分析 + 多格式交付"这类通用方法论，属思想层面，不受版权保护
- 角色命名、五阶段流水线、信封结构、复算算子、证据分级均为本项目自定

**残余风险**

- 若目标产品的作者主张"分析工作流"整体构成受保护的表达，存在争议可能。目前无证据表明其已就该工作流申请著作权登记。
- 建议：保留本项目的开发记录（`docs/开发记录.md`）与提交历史，作为独立创作的时间证据。

**需要你做的**：确认你未在开发前把目标产品的提示词原文交给他人"改写"，也未复制其文件内容到本项目。若有，需替换。

## R2 · 第三方代码

**结论：无风险。**

全部 Python 代码仅使用标准库（argparse/csv/datetime/hashlib/html/io/json/math/os/re/statistics/struct/sys/tempfile/time/traceback/zipfile/zlib/xml）。
标准库适用 PSF License，允许商业使用、修改、再分发，无需开源本方代码。

无 npm 包、无字体文件、无图标库、无 CDN 引用（HTML 图表为内联 SVG，字体用系统字体）。

## R3 · 头像商业使用权（**需你确认**）

**事实**：5 张头像由 AI 图像生成工具产出，原始图右下角带"AI生成 WORKBUDDY"水印，
已通过裁剪去除，并缩放至 512×512。

**风险点**

1. AI 生成内容的可版权性：多数法域（含中国）对"纯 AI 生成、无人类独创性投入"的内容不给予著作权保护。本产品的头像经过**人工设定视觉概念 + 裁剪 + 缩放 + 统一体系**，有一定独创性投入，但保护力度弱于手绘。
2. 生成工具的**服务条款**是否允许将产出用于商业销售：需查阅你所使用工具的用户协议。
3. 平台是否要求上传头像具备"原创证明"：需查阅 WorkBuddy 专家中心的上架规则。

**替代方案（若上述任一项不成立）**

- 方案 A：用矢量工具（Illustrator/Figma）按现有视觉概念重绘 5 个几何图标，产出 SVG 后导出 PNG。几何图形（三角形、折线、盾形、放大镜）本身不构成他人作品，重绘后版权清晰。
- 方案 B：改为纯文字标识（单字 + 色块），放弃图形。
- 方案 C：委托设计师绘制并签署著作权转让协议。

**建议**：方案 A 成本最低（半天），且能彻底消除争议。当前头像可先用于内测。

## R4 · 头像显示（**未实测**）

**已知机制**（详见 `docs/开发记录.md` 第四节）

- 自定义专家通道（`my-experts`）：本地相对路径 → `local-file://` → 正常显示
- 插件市场通道（`experts`）：`avatar` 被丢弃或拼成远程 CDN → 404 → 显示首字

**已做的规避**：投放到 `my-experts` 并登记、路径不带前缀、团长 `role: lead`、体积远低于 5MB。
（原用于兜底的 `leader` / `icon` 字段经上传校验确认为平台非标准字段，已在 v1.0.1 移除。）

**残余风险**：若平台版本变更解析逻辑，或用户从"插件市场"入口安装，仍可能不显示。

**需要你做的**：在目标实例按 `docs/开发记录.md` 4.5 的三步验证。

## R7 · 平台规则（**需你查阅**）

本机文档（workbuddy.cn/docs）未检索到专家中心关于**原创性审核标准**与**商业分成比例**的条款。

**需要你做的**

1. 查阅专家中心上架协议：是否要求独家、是否要求著作权声明、分成比例、结算方式
2. 确认是否允许 MIT 许可的包上架（部分平台要求专有许可）
3. 确认是否允许包内包含可执行 Python 脚本（本包会在本地运行脚本，需确认平台政策）

**若平台不允许本地脚本**：降级方案是纯提示词版（去掉 `tools/`，模型自行计算），
但这会**丧失本产品最核心的"可复算"能力**，不建议。

## R8 · 结论误用

**风险**：用户把 B/C 级结论当作 A 级写进决策材料，或把外推当预测。

**已做的控制**

- 每条结论强制带等级与复算状态
- 报告"口径与免责"章节声明"不构成审计、税务或投资意见"
- 外推强制带区间与置信度，R²<0.5 标"低"
- 使用说明与规格中明确"不替客户做业务决策"

**需要你确认**：免责措辞是否足够（如需更强表述，可在 `triad_render.py` 的 `footer_note` 中调整）。

## R11 · 平台上传校验规则不公开（**已部分解决**）

**事实**：上传被拒两次。

- 第一次：`tags 须固定 3 个`、`defaultInitPrompt` 必须与 `quickPrompts[0]` 一致
- 第二次：`settings.json 不存在或无法读取（Team 型专家必须在 plugin root 下提供 settings.json）`

这些规则在本地 `app.asar` 中搜不到，说明校验在服务端，且平台未公开完整规则清单。

**已做**：
- 统计本机 24 个专家包的字段规格，反推出「能通过校验」的共同特征
  （tags=3、quickPrompts=3、default 与首条快捷提示一致、displayDescription ≤60 字、无非标准字段）
- `settings.json` 形态取自平台内置插件与客户端 `readGeneratedAgentOverride()` 的解析规则
- 以上全部写入 `tools/verify_package.py` 的自动检查

**残余风险**：可能还存在未暴露的规则（字段长度上限、分类白名单、成员数量上限、脚本执行政策）。
下次上传若再报错，把报错原文贴出来，按同样方法反推修正。

**已通过的本地自检**：`python tools/verify_package.py` → 全部检查通过。
