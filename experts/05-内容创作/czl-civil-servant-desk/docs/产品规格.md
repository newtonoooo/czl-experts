**产品**：案头 · 公务员工作助理（`czl-civil-servant-desk`）

**定稿**：2026-10-30

---

## 一、目标用户与场景

办公室／综合科／业务科室要交件的科员到中层。四个高频场景：

1. **布置活**：写通知，要有任务、责任单位、时限、报送要求。
2. **要钱要人**：写请示，要有一文一事、依据、拟办意见。
3. **报情况**：写报告／总结，要有数、有问题、有下一步。
4. **接上级**：上级文件下来，写本级落实稿，不能漏项、不能加码。

共同点：**没有时间学方法，只要一份能交的稿。**

## 二、要解决的问题

| 问题 | 做法 |
|---|---|
| 通用模型先反问、先讲方法 | 首字即标题，不许先提问；信息不足先写，缺口标【待补】 |
| 数据前后不一、口径缺失 | 同一指标全文一个数；数带单位带口径；不换算、不约 |
| 上级文件落不全 | 拆条目→承接/配合/不适用→逐条落正文；报送三要素必须在正文出现 |
| 写完不知哪有毛病 | 十条致命项自查，改完再交（不外抛清单） |
| 被领导问住 | 可另出答问准备（六块），不进附件 |
| 格式返工 | 可选 docx 导出（GB/T 9704-2012 版式）＋结构校验 |

## 三、输入与输出

**输入**：文种／事由（必需）；单位、对象、时限、数据、依据（有则更准）；上级文件或本单位模板（可选）。

**输出**（一次回复）：

```
稿件全文（标题 → 主送 → 正文 → 署名 → 日期）
——
核校备忘（≤4 行：怎么写的、哪几处待补、哪处要你确认）
```

可选追加：Word 文件（有 Python 时）、答问准备（用户要时）。

**不产出**：提纲（除非用户要）、问题问卷、方法讲解、长篇说明。

## 四、处理流程

```
判文种 → 搭骨架 → 填事实（上级文件先拆条目）→ 落书面语 → 十条自查并修改 → 交稿
                                                              ↓
                                          可选：docx 导出 + 结构校验（退出码 0 才算成功）
```

无中间停顿、无确认环节。仅涉密触发停止。

## 五、接口

| 组件 | 作用 | 是否必需 |
|---|---|---|
| `agents/czl-civil-servant-desk.md` | 角色层：三条铁律、文种速查、八条语言规矩、十条自检、交稿形态 | 必需 |
| `skills/doc-craft/SKILL.md` | 深材料：22 文种骨架、审校二十条、版式参数、承接五列、答问六块、词表 | 按需读取 |
| `bin/docx_export.py` | 稿面格式 → docx（GB/T 9704 版式） | 可选 |
| `bin/docx_check.py` | docx 结构与页面几何校验 | 可选 |
| `bin/selftest.py` | 15 项一键自检 | 打包/交付前 |

稿面格式：`[文号] [标题] [主送] [正文] [附件] [署名] [日期] [抄送] [印发机关] [印发日期]`，一行一段。

## 六、质量与稳定性要求

| 维度 | 要求 | 保障 |
|---|---|---|
| 首轮可用 | 第一条回复即成品 | 角色层铁律 + 交稿形态约束 |
| 真实性 | 不出现用户没给过的数、名、文号 | 【待补】机制 + 三条铁律 |
| 可核查 | 每条任务对应上级一条；报送三要素齐 | 承接五列 |
| 环境适应 | 无 Python、无写权限也能交稿 | 降级路径（稿面格式＋版式参数） |
| 启动开销 | 注入指令 ≤16KB | selftest 自动核对 |
| 不谎报 | 文件/校验状态如实 | 只有"文件存在且校验 0"才说已生成 |

## 七、非目标

不做红头件、印章、密级与发文字号认定；不代签发；不联网核政策；不做行业专属术语库；不处理涉密件；不做 PDF 互转。

## 八、与通用模型的差别（可验证的三点）

1. **上级文件承接表**：通用模型给"综合稿"，本产品给"逐条对应上级要求"的稿，并明确不适用项。
2. **口径规则**：同一指标一个数、数带口径、不换算——写进角色层，每次生效。
3. **答问准备**：多出一册以"领导会问什么"为线索的资料，明确不进附件。
