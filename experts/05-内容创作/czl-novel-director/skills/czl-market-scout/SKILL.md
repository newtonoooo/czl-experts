# 侦察：赛道、卖点、书名

## 职责边界

只做三件事：判断这条路能不能走、把卖点压成一句话、把书名压到能点开。

**不做**：不做世界观、不写正文、不做详细大纲。那些是 `czl-story-architect` 的活。用户如果在这一步就要正文，直接用 `czl-chapter-forge`。

## 输入

必需：一个方向或一个脑洞。
有用但可缺省：平台、题材、目标读者、篇幅、禁忌。

缺省取值（写进 `01-定位.md` 的"当前假设"，一句话告知用户）：

| 缺项 | 默认假设 |
|---|---|
| 平台 | 按"免费流量平台"考虑（前三章权重最高） |
| 篇幅 | 80—120 万字 |
| 读者 | 该赛道的主力读者，不做跨性别假设 |
| 禁忌 | 无（不主动添加感情线或后宫） |

## 步骤

### 第 1 步：赛道判定（三问）

不看榜单，先判断这个方向本身的结构：

1. **期待明确吗？** 读者能不能在三十个字内说出"这本书在等什么"。（升级？复仇？翻身？找真相？）
2. **压力可持续吗？** 主角每往上走一步，会不会自动冒出新的对手/新的限制？如果变强就没事干了，这书活不过二十章。
3. **有复利吗？** 前面的投入（人脉、资源、能力、名声）能不能在后面变现？没有复利的赛道写不长。

三问里有两个"否"，直接说这条路不适合长篇，并给替代：
- 期待不明确 → 换一个"读者已经在等"的期待
- 压力不可持续 → 加一层"能力有代价"或"对手会升级"
- 无复利 → 把成长换成可积累的东西（人、地、物、名）

### 第 2 步：卖点命题（三个，必须互斥）

一个卖点命题的格式固定：

> 别人都在写 **X**，这本写的是 **Y**，所以读者读它是在等 **Z**。

三条硬标准，任何一条不满足就废掉重写：
- **不能通用**：把 Y 换到任何同类书上还成立，就是废的。检验法：这句话能不能贴到三本以上的书上？能，删。
- **必须具体**：Y 里得有一个人、一个动作或一个数字。"更爽""更燃""节奏更快"不算。
- **必须能兑现**：Z 是读者能"等"到的东西，不是氛围。

### 第 3 步：书名候选（三个，各走一条路）

三条不同路线各出一个，不要三个同款：

| 路线 | 做法 | 适合 |
|---|---|---|
| 反差留白 | 给一个读者原以为成立的前提，再当场打碎它 | 有钩子型卖点的书 |
| 动作悬念 | 一个越界的具体动作，读者想知道"他怎么敢" | 强冲突型 |
| 尺度压迫 | 一个可比的数字或身份落差 | 数据型、身份型 |

**书名硬规则**
- 主标第一句必须回答"这是什么事"，并至少含一个读者认识的锚（地名、职业、一个能被拍出来的动作）。
- 不在标题里写结论。结论写进标题，点开动机就没了。
- 不用自带歧义的词，尤其是正文里要专门澄清的那个词。
- 副标给指向，不给泛化承诺（"这几个办法比讲道理好使"是泛化，"有一条线得守死"是指向）。
- 不含空格、特殊符号；中文书名不超过 14 字为宜。

每本书名后面附一行判定：**读者会先想到什么？这句话留的空位在哪？**

### 第 4 步：简介骨架

三段，每段一句到两句：
1. 处境（读者能立刻对号入座的具体场景）
2. 裂口（哪件事不对了）
3. 承诺（读者将看到他做什么，注意是"看他在做什么"，不是"他将获得什么"）

**禁止**：在简介里列设定、列境界、列人物关系图。

## 判断条件

| 情况 | 处理 |
|---|---|
| 三问全过 + 三个卖点里有一个能一句话说清 | 放行到 `czl-story-architect` |
| 卖点全部通用 | 停下来，先问用户"你最想让读者记住的一件事是什么"，以此重写 |
| 用户已有书名，判断不合格 | 指出哪条规则不过，给两个替代，不强推 |
| 用户要"照着某本爆款写" | 转为独立设计，说明理由，不复制 |

## 输出

写入 `01-定位.md`：

```
# 定位
## 当前假设
（缺省项与取值）
## 赛道判定
三问逐条结论 + 一句"能不能写长篇"
## 卖点命题
A/B/C 三条，各附"是否通用"的检验结论
## 书名候选
三个，各附路线、判定、留白位置
## 简介骨架
三段式
## 下一步
交给 czl-story-architect 的三个必答项
```

## 异常处理

- **用户给的方向自相矛盾**（如"不要感情线但感情线为主"）：只问这一个，其余照常推进。
- **平台规则类问题**（签约、分成、审核红线）：可联网则查现行来源并注明日期；不可联网则明确说"未核实，以平台当前公示为准"，不给旧数据当结论。
- **用户要求判断"能不能火"**：不给概率，给结构性判断（期待是否明确、压力是否可持续、复利是否有），并说明这不等于结果。

## 依赖

无脚本。仅在需要平台现行规则时用宿主联网能力。

## 与其他工作流的关系

上游：无（入口）。
下游：`czl-story-architect` 接收卖点命题与书名，作为设定与大纲的约束。

## 脚本

`scripts/pitch.py` —— 把这一步原来靠人judge的两件事变成可算：

```bash
# 卖点命题体检：三段齐不齐、Y 段具体不具体、有没有通用词
python scripts/pitch.py proposition "别人都在写X，这本写的是Y，所以读者在等Z"

# 书名体检：长度、具体锚、结论前置、留白、歧义词
python scripts/pitch.py title "一个主任，两本账，三百户人家"
python scripts/pitch.py title --file titles.txt          # 批量，一行一个
python scripts/pitch.py title "书名" --ambiguity 学区,划片  # 指定本赛道歧义词
```

退出码 0 通过 / 1 不通过。判据写死在脚本头部注释里，改判据就改脚本。

**它不能替代判断**：锚点词表是闭集，遇到表外的职业会漏判（开发中"主任"就漏过一次）。脚本说不过，大概率真不过；脚本说通过，仍要自己读一遍。
