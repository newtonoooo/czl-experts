# 铸造：写作包与正文

## 职责边界

一章一章地写。**核心纪律：先出写作包，再写正文。** 没有写作包直接写，写到中段必跑偏。

**不做**：不在这一环改设定（发现设定问题回 `czl-story-architect`）、不在这一环做全篇体检（交给 `czl-voice-tune`）。

## 输入

必需：本章目标（来自大纲，或用户口述）。
必需：前情（来自 `czl-continuity-keeper` 的状态，或用户贴的上一章）。
可选：字数要求、视角、禁忌。

**缺前情时不许假装记得。** 明确说"我没有前文，先按以下假设写，你确认或纠正"，把假设列出来。

## 步骤

### 第 1 步：出写作包

写作包是本章施工图，七格，一格不许空。模板见 `templates/writing-packet.md`。

| 格 | 内容 | 常见错误 |
|---|---|---|
| 本章目标 | 一句话，主角要拿到/改变什么 | 写成"发生了一些事" |
| 阻碍 | 谁或什么在挡，必须具体 | 写成"内心的挣扎" |
| 转折点 | 本章中段那个让局面变了的动作 | 没有转折，从头平到尾 |
| 结果 | 达成 / 失败 / 达成但有代价 | 每次都达成，读者会麻 |
| 章末钩子 | 类型 + 具体那句 | 写成"欲知后事如何" |
| 要用的伏笔 | 埋哪条、收哪条 | 埋了不记 |
| 不许出现 | 本章明确不写的东西 | 不填，写到哪算哪 |

**章末钩子四种，选一种，不要混**

1. **信息缺口**：刚露出一个答案的边，但不说全。（他翻到最后一页，落款是他自己的名字。）
2. **倒计时**：给一个明确期限。（三天后开审。）
3. **越界动作**：主角做了不该做的事，读者想知道后果。（他把刀递给了对方。）
4. **身份反转**：某人的身份被重新定义。（"我不是你哥。"）

### 第 2 步：写正文

**开场**：直接落在动作或对话里，不落在环境和心情里。第一句不许是天气、不许是"某某醒来"、不许是"这个世界"。

**中段**：转折点必须由人物的选择造成，不由巧合造成。巧合可以制造麻烦，不能解决问题。

**对话**：每段对话里至少有一句是"没用的"——绕开的、重复的、答非所问的。全是有效信息的对话读起来像会议纪要。

**描写**：一个场景最多一两个比喻。比喻之后不许跟上解释。

**结尾**：落在钩子上，不落在总结上。写完钩子就停，不许再补一段"他知道，从今天起……"。

**字数**：按正文字数写，写到区间内。写完由脚本实数，不自报。

### 第 3 步：自检（写完立刻做，不留给下一环）

五问，逐条答，不许跳：

1. 本章目标达成了吗？用一句话说结果。
2. 转折点是谁的选择造成的？如果是巧合，改。
3. 钩子是四种里的哪一种？把那一句抄出来。
4. 有没有铺垫不够就发生的爽点？有就补铺垫，不许靠形容词抬高。
5. 有没有出现"人物精准解释自己的情绪"？有就删。

五问里 2、3 不合格，就地重写，不进 `czl-voice-tune`。

### 第 4 步：落盘

- 正文：`chapters/ch-XXX.md`，只放正文，不加标题以外的任何东西
- 写作包：`chapters/ch-XXX.packet.md`
- 然后交给 `czl-voice-tune` 体检，过了再交 `czl-continuity-keeper` 入档

## 判断条件

| 情况 | 处理 |
|---|---|
| 本章目标写不出"一句话" | 说明大纲这一章是空的，回 `czl-story-architect` |
| 转折点只能靠巧合 | 改人物动机，不改巧合 |
| 用户要"多写点，凑够字数" | 不给注水。说明注水会掉完读率，改为"加一个场景"或"把这段拆细" |
| 用户要求一次写十章 | 先写一章给用户定调，确认后再继续。批量出字必崩 |
| 用户要照某作者风格写 | 转为语感参数（句长、对话占比、描写密度），照参数写 |

## 输出

```
chapters/ch-001.md          正文（纯正文）
chapters/ch-001.packet.md   写作包（含五问自检答案）
```

## 异常处理

- **写到一半发现与前文冲突**：立即停，记录冲突点，交 `czl-continuity-keeper` 判定以哪个为准，不许自行圆过去。
- **上下文不足**（用户只给一句话就要写三万字）：先写写作包给用户看，写作包确认后才写正文。
- **用户要求写违规内容**：直接说明不能写，给替代方向。

## 依赖

`templates/writing-packet.md`。入档依赖 `czl-continuity-keeper` 的 `nproj.py`。

## 与其他工作流的关系

上游：`czl-story-architect`（大纲）、`czl-continuity-keeper`（前情与待办）。
下游：`czl-voice-tune`（体检）→ `czl-continuity-keeper`（入档）。
回边：`czl-data-doctor` 的工单回到本环节执行。

## 脚本

`scripts/pacing.py` —— 章级节奏、章末钩子星级、爽点密度：

```bash
python scripts/pacing.py chapters/
python scripts/pacing.py chapters/ --json qc/pacing.json
python scripts/pacing.py chapters/ --min-hook 3 --window 2
```

三条红线：H1 章末钩子低于指定星级；H2 连续 N 章无爽点信号；H3 整章没有对话。

**两条自我限制**
1. 张力是启发式估算（冲突词密度 + 时间压力词 + 对话占比 + 段长起伏 + 句长参差），衡量的是"文字里的事件密度"，不等于好看。
2. 全书都没有爽点信号时只给提示、不给红线——那更可能是题材不属于爽点型（生活流、文学向），而不是稿子有病。

写完一章先跑一次，比写完十章再回头看便宜得多。
