# 架构：规则、人物、大纲、开篇

## 职责边界

把"感觉"变成"可判定"。产出三样东西：能被判定真假的规则、会犯错的人物、有到期章的大纲。

**不做**：不写正文、不起书名、不写简介。正文交给 `czl-chapter-forge`。

## 输入

- 卖点命题（来自 `czl-market-scout`，或用户口述）
- 篇幅与平台
- 用户已有的设定（若有，只增不改，改动需用户确认）

## 步骤

### 第 1 步：世界规则表（可判定优先）

一条规则要能写进表，必须满足：**有主语、有触发条件、有可见后果、有边界**。

反例（不可判定，写了等于没写）：
> 灵气复苏后，世界秩序彻底崩塌。

正例（可判定，且天生带冲突）：
> 觉醒者每日可用能力三次，第四次动用会导致经脉逆冲，轻则吐血三日，重则修为倒退一层。这条限制对所有人成立，包括反派。

规则表固定四列：**规则 / 触发 / 后果 / 谁能例外**。至少 5 条，其中必须有两条是"限制主角的"。

**能力体系必须带代价。** 没有代价的体系写不出压力，只能靠不断加敌人硬撑，二十章后必崩。

### 第 2 步：人物卡（每人一张）

```
姓名 / 常用称号（只准一个主称号，别名单列）
他想要什么（具体、可达成、有期限）
他怕什么（具体的事，不是"怕失去"）
他会做错什么（一处，必须具体到某个情境下他会选错）
他自己的逻辑（他为什么认为自己是合理的）
说话特征（句子长短、口头习惯、绝不说什么）
```

**硬要求**
- 主要人物必须有"会做错事"的一格。没有这一格的人物是工具，不是人。
- 主称号只准一个。称号漂移是长篇最高频的错误，必须在建档时就锁死，别名放 `bible.json` 的 `aliases`。
- 反派要有自己的合理性。写不出反派的合理性，说明这个反派只是障碍物。

### 第 3 步：大纲（卷—章两级）

- **卷**：一卷一个"局面变化"。卷末的局面必须和卷首不同，且变化不可逆。
- **章**：每章一行，格式固定：

```
第 N 章 | 本章目标（一句话） | 阻碍 | 结果（达成/失败/达成但有代价） | 章末钩子 | 涉及伏笔
```

排章大纲时同时做两件事：
1. **标伏笔**：每埋一条，立刻写到期章。不写到期章的，标"弃"。
2. **查因果链**：每章的"本章目标"必须能由上一章的"结果"推出来。推不出来就是凑章，删或改。

### 第 4 步：开篇三章设计

三章各有唯一任务，不许串岗：

| 章 | 唯一任务 | 必须出现 | 明确禁止 |
|---|---|---|---|
| 第 1 章 | 让读者决定不划走 | 一个具体异常 + 一个小胜或一个强钩子 | 铺设定、交代家族史、主角起床、天气 |
| 第 2 章 | 让读者相信这事会持续 | 规则的第一次生效（让读者看懂"这世界怎么运转"） | 换个场景重复第一章 |
| 第 3 章 | 让读者产生"我要看他怎么办" | 主角做出一个主动选择，且这个选择有代价 | 被人推着走、被动接受任务 |

第一章的异常必须是**具体的物理事实**，不是感受。写"空气里有股铁锈味"可以，写"他感到一阵莫名的不安"不行。

## 判断条件

| 检查项 | 不合格的表现 | 处理 |
|---|---|---|
| 规则可判定 | 一条规则说不出"怎么算违反" | 重写该条，或删 |
| 代价存在 | 能力只有收益没有成本 | 必须补一条限制，否则不进下一章 |
| 人物有弱点 | 主要人物从不出错 | 补一格"会做错什么" |
| 因果链完整 | 某章的本章目标推不出来 | 改大纲，不许在正文里硬圆 |
| 伏笔有到期 | 存在无到期章的伏笔 | 补到期章或标弃 |
| 开篇分工 | 第一章在铺设定 | 重排，不许"再忍两章就好" |

六项里有两项不合格，退回重做；一项不合格，就地修完再放行。

## 输出

- `02-架构.md`：规则表、人物卡、卷章大纲、开篇三章设计
- `bible.json`：结构化版本，供 `czl-continuity-keeper` 读取

`bible.json` 结构：

```json
{
  "title": "",
  "rules": [{"id": "r1", "rule": "", "trigger": "", "cost": "", "exception": ""}],
  "characters": [{
    "id": "c-lead", "name": "", "title": "", "aliases": [],
    "want": "", "fear": "", "flaw": "", "logic": "", "voice": ""
  }],
  "volumes": [{"id": "v1", "turn": "卷末局面变化", "chapters": [1, 30]}]
}
```

## 异常处理

- **用户已有大量设定**：只记录不推翻。发现自相矛盾时列出冲突点，让用户选保留哪一条，不替用户决定。
- **用户拒绝写代价**（"我主角就是要无敌"）：说明后果（二十章后无压力、只能靠加敌人），给一个折中（无敌但受限：如"只能在自己认定的规则内无敌"），然后按用户选择执行，并在档案里标注这是用户选择。
- **用户要照搬某本书的体系**：转为"同类机制 + 你自己的代价设计"，明确说明不改写他人具体表达。

## 依赖

无脚本。产物 `bible.json` 被 `czl-continuity-keeper` 的 `nproj.py` 与 `lint_project.py` 使用。

## 与其他工作流的关系

上游：`czl-market-scout`（卖点命题）。
下游：`czl-chapter-forge`（读大纲与写作包）、`czl-continuity-keeper`（读 bible.json 建档）。
