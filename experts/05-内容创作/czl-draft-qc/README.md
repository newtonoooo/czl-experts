## 四个环节，四个技能

| 环节 | 你给什么 | 它给什么 | 脚本 |
|---|---|---|---|
| **选题** | 一个关键词 | 5 张选题卡片（角度互斥、脚本查重） | `topic_score.py` |
| **成稿** | 选定的题 | 骨架（可校验）→ 初稿 | `outline_check.py` |
| **质检** | 一篇稿子 | 八项指标打分 + 硬伤定位到句 + 改前改后对照 | `quality_gate.py`、`title_score.py` |
| **排版** | 定稿 | 能直接粘进公众号后台的 HTML + 合规自检 | `render_wechat.py`、`check_wx_html.py` |
| **配图** | 图片地址 | 下载到本地 + 图片上传清单 | `fetch_images.py` |

七个脚本，除下载图片外不联网、不上传稿件。

## 选题：怎么保证 5 个真的是 5 个

```
给关键词 → 联网搜（官方口径 / 民间讨论 / 数据变化 三组查询）
        → 分成热点与常销两堆
        → 用五种角度各出一个（事实 / 影响 / 反常识 / 方法 / 判断）
        → 脚本查重，相似度 ≥0.45 判重复，exit 1 必须换掉重出
        → 给你 5 张卡片
```

**为什么要有查重这一步**：模型一口气生成 5 个选题，往往 3 个是同一个选题的不同说法。用户看着有 5 个选项，实际只有 1 个。`topic_score.py` 用字面相似度把它抓出来——脚本比人眼可靠，因为它不算"我觉得不一样"。

**热点必须真联网搜**。搜不到就直说搜不到，改出常销题，绝不把记忆里的旧闻包装成"最近"。

## 配图：为什么必须下载到本地

公众号**不接受外链图片**。在你自己的浏览器里能看到，粘到后台就是裂图。所以这条路只有一种走法：

```
下载到本地 → HTML 用相对路径引用（本地预览正常）→ 发布时在后台逐张上传插入
```

```bash
# 1. 下载（urls.txt 每行一个地址，可用 | 分隔说明）
python skills/publish-kit/scripts/fetch_images.py --file urls.txt --dir images --markdown

# 2. 把输出的标记贴进 Markdown
#    ![初三教室全景](images/01_1.jpg "图注：图片下方的小字")

# 3. 渲染时自动生成图片上传清单
python skills/publish-kit/scripts/render_wechat.py 定稿.md
```

渲染完会多一个 **`图片上传清单.md`**：

| # | 文件 | 尺寸 | 体积 | 插在哪 | 说明 |
|---|---|---|---|---|---|
| 1 | `images/01_1.jpg` | 1200×800 | 240 KB | 第一节 | 初三教室全景 |

发布时照着这张表逐张上传、插到对应章节。不用再回去找"这张图该放哪"。

清单还会单独列出：**文件缺失**、**外链图片**（粘过去必裂）、**体积超标**、**版权提醒**。

**图片版权这件事必须说清**：下载来的图不等于能用。只用自制、明确可商用或已获授权的；来源不明的宁可不用——公众号图片侵权投诉处理很快。

## 质检：八项指标

| 指标 | 满分 | 量什么 |
|---|---|---|
| 节奏变化 | 20 | 句长变异系数（句子长短有没有起伏） |
| 套话控制 | 20 | 每千字几个"赋能/闭环/首先其次最后" |
| 元叙述 | 15 | 作者跳出来指挥读者怎么读的地方 |
| 句式变化 | 15 | 三句以上一样长的短句 |
| 段落功能 | 10 | 每段是不是都被过渡句占满 |
| 比喻密度 | 5 | 一段几个比喻 |
| 生活痕迹 | 10 | 有没有具体时刻、原话、动作 |
| 具体信息 | 5 | 数字、量词、专名密度 |

**六类硬伤单独列出，任一命中直接判"需修"，不看总分。**

## 排版：为什么单独做一套

公众号有个特殊的坎：**浏览器里写好的样式，粘到后台会掉一半**。编辑器只保留内联样式，丢弃 class，过滤 grid / flex / 定位 / 伪元素。

所以排版不是"调好看"，是"调到最后还能站住"。按一份实战规范实现：

- **容器** 680px 居中，手机自适应
- **配色** 五套可选，默认每次随机抽一套（整篇级别，不会一章一个色）

| key | 名称 | 适合 | 主色 / 强调 / 点缀 |
|---|---|---|---|
| `a-ink` | 墨绿书卷 | 硬新闻、盘点、深度；拿不准用它 | `#1F5A50` / `#9E3B2E` / `#C29A4B` |
| `b-navy` | 藏青学术 | 政策、规则、数据解读 | `#23395B` / `#C5673F` / `#B8924E` |
| `c-dai` | 黛蓝烟雨 | 随笔、教育理念、慢话题 | `#2F5D62` / `#A85A6A` / `#C9A86A` |
| `d-chestnut` | 栗棕暖陶 | 亲子、情感、成长故事 | `#7A5230` / `#B5573D` / `#C9A24B` |
| `e-graphite` | 石墨青 | 观点、评论、年轻化表达 | `#264653` / `#E76F51` / `#E9C46A` |

  想固定：`--theme c-dai`，或在 frontmatter 写 `theme: c-dai`。想看全套：`--list-themes`。
- **布局** 只用块级 + `table` + `inline-block`
- **九个组件** 胶囊标签、章节条、白卡片、数据表、时间轴、编号圆牌、提示块、字内高亮、落款

## 已知限制

- 八项指标与选题打分都是**启发式**：词表与正则只能捕捉机械特征，误判漏判都会发生，最终以人工复读为准。
- **选题质量取决于搜索结果**。搜不到近期内容时只能出常销题，这不是偷懒，是没有可核实的新进展。
- 选题查重靠字面相似度，抓得住"换词不换意"，抓不住"字面不同但本质相同"——后者仍需人判断。
- 脚本判断不了三件事：**歧义**、**真伪**、**信息量**。这三件事靠模型判断补。
- 不做"是不是 AI 写的"判定。脚本量的是特征，不是生成来源。
- 排版自检能抓**结构性问题**，抓不了**视觉效果**。
- 未对真实稿件做大规模第三方评测，样本为自写回归样本。
