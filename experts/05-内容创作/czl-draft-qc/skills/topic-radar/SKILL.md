# 选题雷达（topic-radar）

## 这个技能解决什么

用户给一个词，比如"通勤"。真正难的不是想不出选题，是**想出的 5 个选题其实是同一个选题的 5 种说法**。用户看着有 5 个选项，实际只有 1 个。

这个技能做两件事：
1. **真的去外面看**——搜当前热点，不是凭记忆编。
2. **保证 5 个角度互斥**——用五种不同角度生成，再用脚本查重，重复的当场淘汰重出。

## 什么时候用

| 用户说 | 是否走这条 |
|---|---|
| "给我个关键词，出几个选题" | ✅ 主场景 |
| "最近 XX 有什么可写的" | ✅ |
| "这个政策能不能写一篇" | ✅（先判断能不能写，再出选题） |
| "帮我写一篇关于 XX 的" | ⚠️ 先确认角度，再出 3 个选题让他选，不要直接写 |
| "这篇稿子怎么改" | ❌ 走质量闸门 |

## 输入

**必须**：一个关键词（越具体越好："早高峰通勤"好过"生活"），以及**这个号写什么方向**。方向缺失就先问，不许默认。

**尽量要到**（缺了会让选题跑偏）：

| 项 | 为什么需要 | 缺了怎么办 |
|---|---|---|
| 目标读者 | 决定选题的落点 | 按"对该关键词最焦虑的那群人"假设，并声明假设 |
| 账号定位 | 排除不该碰的角度 | 只做通用判断，声明可能不合账号调性 |
| 已发过的内容 | 避免重复 | 跳过查重，提醒用户可能有重复 |
| 不能碰的领域 | 合规与专业边界 | 默认排除医疗、法律、投资建议 |

## 执行步骤

### 第一步：先搜，不要先想

用 **WebSearch** 联网搜索，至少 3 组查询，覆盖三个方向：

```
1. 政策/事件：  <关键词> 2026 政策 最新
2. 争议/讨论：  <关键词> 争议 讨论 真实体验
3. 数据/变化：  <关键词> 数据 变化 下降 上涨
```

**判断什么是真热点**，五条标准见 `references/hotspot-playbook.md`。核心一条：**能指出来源和时间**，指不出来就不算热点，只能算"常见话题"。

### 第二步：分两类

把搜到的东西分成两堆：

- **热点堆**：有时间窗，两周后没人看（政策发布、事件、季节节点）
- **常销堆**：随时有人搜，三年后仍成立（做法、清单、避坑、名词解释）

两类都要有。全是热点 → 这个号没有沉淀；全是常销 → 没有传播。

### 第三步：用五种角度生成 5 个选题

**关键约束：5 个选题必须各用一种角度**，不能两个都用"事实层"。

| # | 角度 | 问什么 | 适合 |
|---|---|---|---|
| 1 | **事实层** | 到底发生了什么？变了多少？ | 热点首发 |
| 2 | **影响层** | 对谁有影响？影响多大？ | 政策解读 |
| 3 | **反常识层** | 大家以为 X，其实 Y？ | 传播力最强 |
| 4 | **方法层** | 具体该怎么做？ | 常销、收藏 |
| 5 | **判断层** | 两种做法选哪个？分水岭在哪？ | 争议、评论 |

详细问法与示例见 `references/angles.md`。

### 第四步：打分与查重（必须跑）

把 5 个选题写成 JSON，跑脚本：

```bash
python scripts/topic_score.py topics.json
```

它检查三件事：
- **重复**：两两算相似度，≥0.45 判定重复，exit 1，必须换掉重出
- **短板**：每个选题最弱的那一维（具体性/角度张力/时机/可写性/受众贴合）
- **类型集中**：5 个全是一个类型会提示

**exit 1 不许交付。** 换掉重复的那个，重新生成一次，再跑。

### 第五步：交付 5 张选题卡片

按下面的格式给用户，一次给全，不要一个一个问。

```markdown
## 关键词「早高峰通勤」· 5 个选题

**① 事实层 · 热点（82 分）**
标题：这条地铁线加密了班次，但早高峰的站台反而更挤
角度：班次变密，进站速度没变，人全堆在闸机口——瓶颈不在车上
素材：运营方 2026-09 公告（已核实）+ 连续三天早高峰实测
预计：1800 字，2 天

**② 反常识层 · 常销（81 分）**
...
```

每张卡片必须有：**角度标签、分数、标题、一句话角度、素材情况、预计成本**。

最后加一句：

> 选一个（说编号就行），或者告诉我"换一批"，我按你偏的方向重出 5 个。

### 第六步：用户选择后移交

- **用户选了** → 进入 `draft-foundry`：先出骨架，骨架过了再写初稿。
- **用户说"换一批"** → 问一句"是角度不对还是题材不对"，然后换角度重出 5 个，不要原样重生成。
- **用户说"就这个，直接写"** → 仍然先给骨架（5—8 行），让他看一眼结构再动笔。跳过骨架的稿子八成要重写。

## 判断条件

| 情况 | 处理 |
|---|---|
| 搜不到任何近期内容 | 直说"这个关键词近期没有可核实的新进展"，改出 5 个常销选题，不编造热点 |
| 搜到的全是三个月前的旧闻 | 标注"已过窗口"，只作为背景，不当热点卖 |
| 5 个选题查重 exit 1 | 换掉重复项重出，最多两轮；两轮仍重复说明关键词太窄，建议换词 |
| 用户给的词太宽（"生活"） | 要求收窄到"人群 + 场景"，例如"一线城市上班族 + 通勤" |
| 某选题素材明显不够 | 在卡片上标"素材待补：需要什么"，不假装能写 |

## 输出规范

- 5 个选题的**角度标签必须不同**，一眼能看出差别。
- 分数只作排序参考，**不等于好坏**——要说明"分数低的是因为缺具体锚点，不是不能写"。
- 热点题必须标时间窗（3 天 / 7 天 / 30 天），过期就作废。
- 不承诺"这个选题会爆"。选题只解决"写什么"，不解决"有没有人看"。

## 依赖

- **WebSearch**（联网搜索，必须真实调用，禁止凭记忆编造热点）
- Python 3.8+，仅标准库
- 下游：`draft-foundry`（成稿）、`quality-gate`（质检）

## 异常处理

| 错误 | 处理 |
|---|---|
| 搜索结果互相矛盾 | 以官方来源为准，并在卡片上注明"存在不同说法" |
| 搜到的是营销号编的政策 | 只认政府/学校/官方媒体来源；营销号内容只能当"民间关注点" |
| 用户要求写不能碰的领域 | 说明边界，改为"从普通读者视角写怎么判断真假"，不做专业结论 |
| 关键词涉及具体未成年学生 | 一律不写 |
