# 粘贴与发布前核对清单

## 一、粘贴流程（六步，别跳）

1. 用 Chrome 或 Edge 打开生成的 `.html` 文件（手机预览用同一份文件即可）。
2. 点击正文**最开头**的位置，`Ctrl+A` 全选，`Ctrl+C` 复制。
3. 进公众号后台 → 新建图文 → 点正文编辑区 → `Ctrl+V` 粘贴。
4. 逐项核对下面第二节的五个检查点。
5. 后台单独填写：**标题、作者、摘要、封面图**（正文里不重复写标题）。
6. 点「预览」扫码到手机，确认表格不挤、圆点对齐、颜色正常，再发。

## 二、粘贴后的五个检查点

| # | 看什么 | 掉了会怎样 | 原因 |
|---|---|---|---|
| 1 | 章节编号方块有没有底色（主色） | 变成黑字白底，整篇失去结构 | 用了 class 或外部 CSS |
| 2 | 白卡片有没有边框和圆角 | 卡片消失，正文糊成一片 | 同上 |
| 3 | 表格列宽是否正常 | 中文被挤成一字一行 | 缺 `table-layout:fixed` 或 `colgroup` |
| 4 | 圆点是否还是圆的 | 变成方块或消失 | 用了伪元素，或缺宽高 |
| 5 | 重点高亮还在不在 | 重点词变普通文字 | 同上 |

四处里任何一处不对，回 `check_wx_html.py` 看它报了哪一项。

## 三、手机预览必看

桌面正常不代表手机正常。扫码后在手机上确认：

- [ ] 表格没有横向溢出，没有被压缩到一字一行
- [ ] 时间轴的圆点和文字在同一水平线上
- [ ] 段落不超过 5 行视觉高度（超过就要拆段，回内容层改）
- [ ] 主标题没有换行成三行以上
- [ ] 落款区没有贴到屏幕最底部

## 三半、图片上传流程（正文粘好之后做）

粘过去以后，图片位置是**空的**——这是正常的，不是出错。公众号不接受外链图，也不吃 base64 的中大图。

1. 打开同目录的 `图片上传清单.md`，看这一篇有几张图、分别插在哪一节。
2. 在后台编辑器里把光标放到对应位置。
3. 点工具栏「图片」→ 上传本地 `images/` 里对应文件 → 插入。
4. 图片宽度默认撑满正文宽度即可，不用手动调。
5. 全部插完，手机预览一遍，确认图片没有把段落挤断。

**顺序错了会怎样**：图插到不对的段落里，读者看到的是"这张图和上面这段没关系"。清单里标了"插在哪"，照着来。

## 三之四、配色核对（五套里只能出现一套）

| # | 查什么 | 出错会怎样 |
|---|---|---|
| 1 | 全篇只有一套配色（不要一章一个色） | 读者看得出是拼接的，系列识别度归零 |
| 2 | 主色出现的都是结构件（章节编号块、表头、编号圆牌） | 主色到处用会显得闷 |
| 3 | 强调色只用于时间、重点词、大数字 | 满篇强调等于没有强调 |
| 4 | 点缀色全篇不超过 1—2 处 | 点缀色用多了会抢主色 |
| 5 | 正文没被某个主题改浅（深色底深字） | 读不出来 |

抽到不喜欢的配色就换一套重跑，**不要手动改 HTML 里的色值**——下次渲染又会被覆盖，而且容易漏一处。

## 四、发布前内容侧核对（与排版无关，但别忘）

- [ ] 标题 ≤ 64 字（建议 ≤ 24 字，列表页显示更完整）
- [ ] 摘要自己写了，不是让系统抓前几句
- [ ] 封面图已上传（2.35:1 或 900×383）
- [ ] 文中的数字、日期、机构名已核对来源
- [ ] 图片来源已确认（自制 / 明确可商用 / 已授权），没有外链
- [ ] 图片已按清单逐张上传插入，位置对得上
- [ ] 单图 < 500KB（后台允许更大，但加载慢）

## 五、常见翻车与处理

| 现象 | 处理 |
|---|---|
| 整篇样式全掉 | 检查是否粘成了"纯文本"；改用浏览器打开源文件再复制 |
| 只有部分段落掉样式 | 那段大概是手动在后台改过；删除重粘 |
| 表格某些列特别窄 | 回 Markdown 调整第一列内容长度，或改成两列 |
| 时间轴堆成一坨 | 检查时间轴块的 `:::` 定界是否成对 |
| 背景色变成深色/变色 | 用了渐变；改纯色 |
| 图片裂了 | 用了外链；上传素材库后重新插入 |
