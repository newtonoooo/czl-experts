# 输入语法（Markdown 方言）

> `render_wechat.py` 只认这一套语法。写错不会报错，会静默按普通段落渲染——所以对照着写。

## 一、头部（frontmatter）

```markdown
---
tag: 小店观察
tag2: 城市样本
title: 开了九年的文具店，最赚钱的不是文具
subtitle: 一本账翻出来的三件事
footer_name: 你的公众号名
footer_slogan: 一句话说清你写什么 / 用斜杠可以换行
theme: c-dai
---
```

> **`footer_name` 只能是用户自己的账号名。** 不知道就整块不写（落款不输出），
> 不许填"示例公众号"以外的任何名字，更不许编一个像真的号名——读者会照着去搜。

| 键 | 是否必填 | 渲染成 |
|---|---|---|
| `tag` | 否 | 左上第一个胶囊标签（**主色**实心、白字） |
| `tag2` | 否 | 第二个胶囊标签（白底、**主色**描边） |
| `title` | 是 | 主标题（衬线 28px / 900 / 主色，左对齐） |
| `subtitle` | 否 | 副标题（衬线 18px / 700 / **强调色**） |
| `footer_name` | 否 | 落款区账号名（衬线 20px / 900 / 主色）；**必须由用户提供**，不填则整块落款不输出 |
| `footer_slogan` | 否 | 落款区 slogan；用 `/` 分隔会**换行** |
| `theme` | 否 | 锁定配色。不写则每次随机一套 |

**配色优先级**：命令行 `--theme` > frontmatter `theme:` > 随机。

**同一篇必须只用一套配色。** 随机发生在整篇级别，不会一章一个色。想固定就写 `theme:`。

**注意**：frontmatter 之后**不要再写 `# 一级标题`**。写了也会被忽略——主标题由 `title` 承担，重复会导致公众号显示两次。

## 二、章节

```markdown
## 最赚钱的一栏，不在货架上
## ! 要是你也想开一家
```

`## ` 开头 → **编号方块（01、02…）+ 章节标题**。编号自动累加，不用手写。

标题前加一个 `!` → 编号方块换成**强调色**，用于重点 / 警示章节。`!` 不会显示出来。

章节下的内容直接排在奶油底上，**不再套白卡片**（新规范 §5 的结构：区块自己就是 `tr>td`）。

第一个 `##` 之前的内容是**导语**，跟在标题区下方。

## 三、块级元素

| 写法 | 渲染成 |
|---|---|
| 普通段落（连续几行，中间不空行 = 一段） | 正文 17px / 行高 1.95，段间 14px |
| `- 项目` | 项目符号列表 |
| `1. 项目` | 圆牌编号清单（主色圆点 + 序号） |
| 表格（见下） | 数据表，`table-layout:fixed` + colgroup |
| `> 提示内容` | 浅底提示块（左侧**点缀色**竖线） |
| `::: timeline` 块 | 时间轴（三列：时间 / 圆点 / 标题+说明） |
| `::: stats` 块 | 数据卡片（2—4 列，浅底细边，大数字用强调色） |
| `::: quote` 块 | 金句卡片（**主色**底 + 浅色字，重难点缀色） |
| `::: source` 块 | 白底来源框 |
| `---` | 忽略（仅作视觉分隔，不输出） |

### 表格

```markdown
| 科目 | 分值 | 构成 |
| --- | --- | --- |
| 语文 | 150 | A 卷 100 + B 卷 50 |
```

- 第二行必须是 `| --- | --- |` 形式的分隔行，否则识别为普通段落
- 列宽自动：2 列 → 32/68；≥3 列 → 首列 22%，其余均分（总和 100%）
- 首列深色加粗、其余次要色——所以**第一列放主信息**（科目名、日期、名称）

### 时间轴

```markdown
::: timeline
2月!! | 春季开学 | 一周流水顶平时半个月
6月 | 毕业季 | 同学录、礼物包装纸
9月!! | 秋季开学 | 全年第二高峰
12月! | 年末 | 贺卡台历，量小但毛利高
:::
```

三列：**时间 | 标题 | 说明**（第三列可省略）。

时间列后缀控制圆点：

| 后缀 | 圆点 | 用途 |
|---|---|---|
| 无 | 主色 12px | 普通节点 |
| `!` | 点缀色 12px | 关键节点（点缀色只点 1—2 处） |
| `!!` | 强调色 13px | 全年最关键的 1—2 个节点，多了就不关键 |

### 数据卡片

```markdown
::: stats
5 个|关键节点
3 次|全市统考
120 分|理化合计
:::
```

一行一格，`|` 前是大数字、后是说明。**2—4 格**，多了会挤成一条。数字写短（"120 分"而不是"合计 120 分"）。

### 金句卡片

```markdown
::: quote
文具是流量，复印是利润。==卖得最多的，从来不是最赚钱的==。
:::
```

主色底、浅色字。里面用 `==...==` 标的地方会变成**点缀色加粗**（不是高亮底色）。

**一篇最多一两个。** 满篇金句等于没有金句。

### 来源框

```markdown
::: source
素材来源
运营方 2026-09 公告（官网可查）
连续三天的现场记录
本文为公开信息整理与个人观察。
:::
```

第一行是标题，后面每行一条。放在文末。

## 三半、图片

```markdown
![图片说明](images/01_1.jpg)
![图片说明](images/01_1.jpg "图注：会显示在图片下方的居中灰色小字")
```

- 图片必须**单独占一行**，前后留空行，否则会被当成普通段落
- `[...]` 里是 alt（读屏用，也写进上传清单）
- `"..."` 里是图注，可省略；写了会渲染成图片下方的小字
- 路径用**相对路径**，相对 Markdown 文件所在目录。Windows 下也写 `/`，不要写 `\`
- **不要写 http 外链**。预览能看到，粘到公众号必裂。先下载到本地

渲染时会自动生成 `图片上传清单.md`，发布时按清单上传插入。

## 四、行内标记

| 写法 | 渲染成 |
|---|---|
| `==重点词==` | 浅底 + **强调色**加粗的字内高亮 |
| `**强调**` | **主色**加粗 |
| `` `代码` `` | 浅底等宽（少用，公众号里不好看） |
| `[文字](链接)` | 只保留强调色文字，**不生成超链接**（公众号正文外链会被拦） |

> 行内标记**不要嵌套**。`==**重点**==` 这种会渲染错。

## 五、写作时的排版意识（给写手的三条）

1. **一段不超过 5 行**（手机屏）。超过就拆，或改成列表。
2. **每个 `##` 下不超过 4 段**。多了读着闷，加个 `##` 或把中间那段改成清单。
3. **能用表格就别用文字罗列**。"三个科目、三种分值、三种构成"写成表，读者三秒看完；写成段落，读者划走。

## 六、不支持的东西（别写，写了会被当普通文字）

- 引用块的多层嵌套
- 脚注、目录、代码块高亮
- 任何 HTML 标签（会被转义成文字显示）
- grid / flex 之类的布局意图
- 自定义颜色（想换色只能整套换，见规范 §4）

需要图片时：**先下载到本地（`fetch_images.py`），用相对路径引用，发布时在后台手动上传插入**。不要在 HTML 里留外链。
