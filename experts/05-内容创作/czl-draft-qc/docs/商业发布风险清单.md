> **本清单不构成法律意见。涉及商标、著作权归属的最终判断，上架前建议咨询专业律师。**

## 二、R10 已处置说明（本轮主要变化）

**原风险**：1.x 承诺定位、选题、成稿、质检、标题、排版、发布七件事，而开放平台质量检测首维度是"每个专家只承诺一件具体、可交付的事"，存在被判"不够聚焦"的实质风险。

**处置**：
1. 产品重新定位为"给已写完的稿件做质检并改到能发"，只承诺一件事。
2. 四个技能迁出本包，Agent 提示词里列出六类不处理的需求并说明"这不是我的活"。
3. `displayDescription` 改为只讲质检（44 字）。

**结论**：R10 由"中低"降为"低"。剩余风险来自审核方对"改稿"这件事本身是否算"一件可交付的事"的理解，属于主观判断，无法完全消除。

### 2.1.0 补充评估：加入排版后是否又变成两件事

**变化**：新增 `publish-kit` 技能（排版渲染 + 合规自检）。

**判断**：仍是一件事，但需要说明理由，因为表面看是"质检 + 排版"两个功能。

**理由**：公众号的发布形态决定了排版不是附加服务——不发 HTML 就发不出去。"改到能发"必然包含"排成能发出去的样子"。已在主 Agent 中明确写成"这是同一件事的两头，不是两件事"。

**同步收紧的边界**：排版只套用固定规范，不做原创视觉设计；要新风格必须先改规范文件，不在本专家范围内。这条写进了 Agent 边界表。

**残余风险**：审核方可能仍按"包含两个技能 = 做两件事"判断。若被质疑，处置方案与 R10 相同——把 `displayDescription` 收回到纯质检表述，排版降级为"交付附件"（不改包体，只改文案）。

### 3.0.0 再评估：现在是真的三件事了

**变化**：新增选题（联网搜索 + 5 选 1）与成稿（骨架 + 初稿），共 4 个技能。

**必须承认**：这次不是"一件事的两头"，而是**一篇稿子的三个连续阶段**。口径确实变宽了。

**为什么仍可接受**：
1. 三个阶段服务的是**同一篇稿子**，用户不会拿了选题就走——他会继续要稿，拿了稿会要继续改。
2. 卡片的表述仍限定在"单篇文章"：编辑介绍写的是"搜热点、出选题、搭骨架、写成稿、去AI味、排版发布"，没有承诺排期、文风建模、数据复盘，这三项在 Agent 边界表里明确拒绝。
3. 有 4 个可跑脚本支撑，每个环节都能拿出输入输出，不是纯话术。

**风险等级调整为：中**（原"低"）。理由是审核方对"任务完成度"的判断可能从严——一个 Agent 覆盖三个环节，会被问"到底哪件事做得最好"。

**若被驳回的处置，按优先级**：
1. 把 editor 的编辑介绍收回到"选题 → 成稿 → 质检 → 排版中的'质检'环节"，把选题与成稿降级为"辅助"（只改文案）
2. 拆成两个包：`czl-topic`（选题）+ `czl-draft-qc`（成稿质检排版）
3. 拆成三个包：选题 / 成稿 / 质检+排版

**注意**：`name` 已定为 `czl-draft-qc`，若被要求拆包，第二三个包另起标识即可，第一个不用改。

## 三、逐项说明

### R1 商标风险（等级：中）

**事实**：花名「朱笔」，系列名「尺素」，标识符 `czl-draft-qc`。
**风险**：
- 「朱笔」是通用词（红色批改笔），作为未注册商标单独主张保护较弱，但**他人可能已在第 9 类（软件）或第 41 类（教育娱乐）注册了"朱笔"组合商标**，使用同名仍可能构成侵权。
- 「尺素」文气重，已被多个文创、教育类品牌使用，需重点检索。
**处置**：
- 上架前在中国商标网做近似检索：第 9 类（计算机软件）、第 41 类（在线出版、教育）、第 42 类（软件设计）。**两个名字都要查**。
- 若命中，优先改系列名（影响面小，只需改文档叙述），花名最后改（要重建包）。
**替代名**（已做初步语义检查，仍需检索）：系列——「案头」「纸上」；花名——「墨裁」「校书」「点墨」。

### R2 同质化风险（等级：中低）

**变化**：1.x 与公众号运营类专家大面积重叠；收窄为"稿件质检"后，重叠面显著减少。
**残余风险**：市面上有通用"AI 味检测"类工具，功能相近但方法不同（它们给概率，本产品给可指认的特征与改法）。
**处置**：详情页讲清差异——**不判定生成来源，只描述可修改的特征**。这个差异既是卖点，也规避了"AI 检测不准"的投诉。

### R3 头像著作权（等级：中低）

**事实**：生成式图像工具产出，经裁剪、缩放、6 bit 量化处理（1024 → 945 方形裁切 → 512）。
**处置**：
- 1024 原图已另存本地（`dev-tools/avatar_master_1024.png`），作为创作过程证据，**不随包分发**。
- 头像不含第三方素材、真实人物肖像、他人商标。
**若平台要求披露 AI 参与**：以 `docs/开发记录.md` 第四节为准。

### R4 质检分数被误当权威认定（等级：中）

**风险**：用户可能把"44 分"当成"这篇稿子很差"的客观结论，或把"98.9 分"当成"可以发"的保证。实际上打分是启发式文本特征测量，会被词表覆盖度、文体差异影响。
**处置**：
- LICENSE 第 4.5 条：明确分数为启发式测量结果，不是质量、真实性或生成来源的权威认定。
- Agent 边界条款：脚本是启发式、会误判，每一处命中都要人工复读确认；不得把脚本当判决书。
- 报告页脚固定提示"样本偏小/分数波动"。

### R5 用户产出内容责任（等级：中）

**处置**：主 Agent 禁止编造数据与引用；W1 强制产出"事实待核清单"；LICENSE 4.2 免责。

### R6 平台规则（等级：中，已核实）

**已核实**（`open.workbuddy.cn/docs` 系列，2026-10-26）：

| 项 | 实际 |
|---|---|
| 入驻 | 个人认证（身份证 + 手机号 + 邮箱 + 人脸） |
| 上架路径 | 发布管理 → 专家 → 创建 → 上传 zip；解析后补分类与头像 |
| 包体 | 首层须为专家目录；≤20MB；头像 512×512、≤500KB |
| 审核 | 机器审（基础安全/内容安全/质量检测）+ 人工审（类目资质），官方口径 7 工作日 |
| 质量检测 | 任务完成度、指令遵从性、事实辨别性、规则遵从性 |
| 付费发布 | 需勾「原创声明」；一次性买断或按月订阅；**付费方式发布后不可改** |

**仍未确认**：平台服务费比例。官方文档未写明；第三方测评称内测期 1%，**未经官方确认**，以微信签约页与《付费服务开发者规则》为准。

### R7 方法论可保护性弱（等级：低）

通用编辑经验（删句子优于换词、段落要承重）不主张独占。可主张且已形成壁垒的是：八项指标定义、权重公式、脚本实现、样本与测试记录。
**对外表述**：说"我们的做法是……"，不说"只有我们会……"。

### R8 测试样本中的机构信息（等级：低）

样本含"打印店老板姓周""479""成都"等，均为虚构或已泛化，不含真实学生信息，不对外宣传为案例。

### R9 AI 生成标识（等级：中，需你决定）

**事实**：原图右下角有生成工具自动附加的"AI生成"角标，为符合 512×512 规格并避免"WORKBUDDY"字样造成合作关系误解，本次裁去了该区域。

**相关条款**：《腾讯云 WorkBuddy 软件许可及服务协议》9.2(5) 禁止对"已标注的人工智能生成内容标识"进行删除、篡改或隐匿。

**当前缓解**：README、LICENSE 第 3.3/3.4 条、平台展示文案三处明示"头像为 AI 生成内容"。实质上未隐匿，但形式上仍有瑕疵。

**三个方案**（你上一轮选择"暂不更换"，此处保留以备审核方质询）：

| 方案 | 做法 | 代价 |
|---|---|---|
| A | 换成程序化绘制的纯几何标识（尺 + 栏线），脚本生成、可复现 | 丢掉人物插画，但条款风险归零、权属最清晰 |
| B（当前） | 保持现状 + 三处披露 | 审核方严格认定时可能被要求更换 |
| C | 换回带角标原图 | 出现"WORKBUDDY"字样，易误解为官方合作 |

### R11 详情页写了未发布的系列成员（等级：中，待注意）

**风险**：为讲"系列感"而在详情页列出墨裁、题眼、砚台等未发布成员，可能被判虚假宣传或"承诺未交付功能"。
**处置**：`docs/平台展示文案.md` 第十节的系列表已标注"仅供内部规划，不对外"。**上架时只写朱笔一个，不写系列其他成员**（可在文案里说"尺素系列第一支笔"，这是事实陈述，不是功能承诺）。

### R12 配图版权（等级：中高，新增）

**事实**：v3.1.0 新增 `fetch_images.py`，可以从网上把图片下载到本地嵌进文章。

**风险**：这是本次迭代引入的**最大法律风险**。网络图片绝大多数有著作权，直接用于商业公众号可能构成侵权。国内图片维权（视觉中国类）投诉与索赔都很成熟，处理速度很快。

**已做的处置**：
1. 脚本把每张图的来源 URL 写进 `images/SOURCES.txt`，可追溯。
2. 图片上传清单里单列「版权提醒」段落，明确写"下载来的图片不等于可以用"。
3. Agent 注意事项写明：只用自制 / 明确可商用 / 已获授权三类；来源不明的宁可不用；交付时说清哪几张需用户自行确认授权。
4. 排版规范本身主张"能不用图就不用"，表格、时间轴、色块可以替代大部分配图需求。

**残余风险**：工具无法判断一张图的授权状态。**最终责任在发布者**。这一点必须在产品里持续说清，不能包装成"自动配图无版权风险"。

**包内素材核查（上架前已做）**：全包只有 3 个位图，均为自制——`avatars/expert.png`（AI 生成后处理）、
`samples/images/01_cover.png`（头像派生）、`samples/images/02_photo.png`（纯标准库脚本绘制的占位图）。
原先那张从测试站点下载的示例图已替换掉。所以**专家包本体不含任何第三方图片素材**，
R12 对审核的影响为：不触发——工具风险在使用端，不在包体。

**如果平台审核对图片能力有顾虑**：可以把 `fetch_images.py` 从技能里移除，只保留"用户自己提供本地图片"的路径——渲染与清单逻辑不受影响。

## 五、明确不做的事
