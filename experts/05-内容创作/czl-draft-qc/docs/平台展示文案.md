## 四、详细介绍（详情页长文案）

### 朱笔是什么

尺素系列的第一支笔。管一条链：**说清你账号的方向，再给一个关键词，一篇能发的稿子出来。**

```
你的账号方向 + 关键词 → 搜热点 → 5 个选题 → 你选 1 个 → 骨架 → 初稿 → 去AI味 → 排版 → 能粘的 HTML
```

也可以从中间任何一环插进来：你有稿子就直接给稿子。

**账号是你说，不是它猜。** 公众号名称、写给谁看、写什么领域，全部由你提供。它不预设行业、不预设城市、不预设读者类型，**也不会替你编一个账号名**——读者会照着去搜，搜不到就是骗人。没给账号名，落款就空着，它会在交付时说一句"把号名给我，我补上"。

它不做的事同样明确：不替你定账号人设、不做排期、不做文风建模、不做数据复盘。

### 它解决的那个说不清的问题

"这篇稿子到底哪儿不对"——这个问题从来没被认真回答过。

朋友看完说"挺好的"，老板说"读着有点飘"，你自己读第八遍已经麻木。朱笔把这个感觉翻译成八个数字，再指到具体第几句。

### 先说选题：5 个是真的 5 个

给一个关键词，它真的去网上搜——官方口径、民间讨论、数据变化，三组查询。然后分两堆：热点（有时间窗）和常销（三年后仍成立）。

接着用**五种互斥的角度**各出一个：事实层（发生了什么）、影响层（对谁有用）、反常识层（你以为的不是这样）、方法层（怎么做）、判断层（该选哪个）。

最后跑一遍**查重**：五个选题两两比相似度，≥0.45 判重复，必须换掉重出。

为什么要有这一步——模型一口气生成 5 个选题，往往 3 个是同一个说法的变体。你看着有 5 个选项，实际只有 1 个。

### 八项指标，每一项都能指到句子

| 指标 | 量什么 |
|---|---|
| 节奏变化 | 句子长短有没有起伏 |
| 套话控制 | 每千字几个"赋能/闭环/首先其次最后" |
| 元叙述 | 作者跳出来指挥读者怎么读的地方 |
| 句式变化 | 三句以上一样长的短句 |
| 段落功能 | 每段是不是都被过渡句占满 |
| 比喻密度 | 一段几个比喻 |
| 生活痕迹 | 有没有具体时刻、原话、动作 |
| 具体信息 | 数字、量词、专名密度 |

**六类硬伤单独列出，任一命中直接判"需修"，不看总分。** 因为一篇 85 分但有三处"这才是最要紧的一段"的稿子，比 78 分没有元叙述的更需要改。

### 四条工作流

1. **体检**：先跑脚本拿数字，不凭感觉。
2. **分诊**：判断这篇是局部手术、保留重写，还是推倒重来，并给理由。
3. **定点重写**：只改被标记的句子，不做整篇润色。每处给"改前 / 改后 / 为什么"。
4. **复检**：改完必须重跑，两次分数并排给你看。没有第二次数字的交付不算完成。

### 排版：不是调好看，是调到最后还能站住

公众号有个特殊的坎——浏览器里写好的样式，粘到后台会掉一半。编辑器只保留内联样式，丢弃 class，过滤 grid / flex / 定位 / 伪元素。

所以这里用一套实战规范套版：680px 容器、**五套低饱和配色**（每次随机一套，也可按文章气质指定）、章节编号块、数据表、时间轴、金句卡、数据卡、来源框，布局只用 table + inline-block。

五套配色按气质分：墨绿书卷（通用）、藏青学术（政策数据）、黛蓝烟雨（随笔理念）、栗棕暖陶（亲子情感）、石墨青（观点评论）。同一套里只用 1 主色 + 1 强调色 + 1 点缀色，多了会花。

生成完还要跑一遍**合规自检**：把规范的黑名单反过来查——grid、flex、定位、伪元素、负 margin、外链、字体缺 fallback、表格缺列宽、圆点缺宽高。全部通过才交付。

**只套版，不做设计。** 要新风格得先改规范。

### 配图：下载到本地，生成上传清单

公众号不收外链图片，粘到后台必裂。所以配图只能：下载到本地 → HTML 相对路径引用（本地预览正常）→ 发布时你在后台逐张上传。

排完会自动生成一张 **图片上传清单**：哪张图、多大、插在哪一节。照着传就行，不用回头找。

清单还会单独标出：图片文件缺失、外链图片、体积超标、版权提醒。

### 两条硬规矩

- **能整句删掉的，不要换词。** 绝大多数问题删掉就没了，逐词替换只会得到另一句套话。
- **连续两轮改不好的，不是语言问题，是骨架问题。** 停下来重做结构，不要在错的骨架上继续打磨。

### 适合谁

- 已有自己的号，需要一个稳定的成稿与排版流水线的人
- 有素材但"不知道今天写什么"的人
- 一个人写号、没人给把关的自媒体作者
- 稿子被说"读着有点飘"但不知道改哪儿的人
- 代运营多个号、需要一套客观标准的团队
- 需要向上解释"为什么这稿要改"的内容负责人

### 不适合谁

- 想一键出爆款的人（不承诺任何传播效果）
- 想让它一次生成 20 篇的人（它一次只做一篇，且要先选题）
- 想让它判断"这段是不是 AI 生成的"（只描述特征，不判定来源）
- 需要医疗、法律、金融投资专业结论的场景

## 六、推荐提示词（3 个，第一条为首屏引导语）

> 排版不再需要单独提示词——内容定稿后专家会直接排版，用户不需要说"帮我排成 HTML"。配图不是自动的：你说要图，它才去找、下载到本地、并给你一张上传清单；图的授权仍需你自己确认。

1. **（首屏）** 我的号写的是 ___。关键词是「___」，帮我搜搜最近有什么热点，出 5 个选题让我选。
2. 我手上有篇公众号稿子，帮我按标准体检一遍，哪里读着像 AI 写的，直接给我改法。
3. 我想写「___」，先给我看看骨架，确认了再写，写完排成能粘的版式。

## 八、卖点提炼

| 卖点 | 支撑 |
|---|---|
| 选题不重复 | 五角度生成 + 脚本查重；重复样本 5 选 1 被抓出 |
| 热点不瞎编 | 联网三组查询；搜不到就说搜不到，改出常销题 |
| 有数字，不靠感觉 | 八项指标 + 阈值表；样本对照 44 vs 98.9 |
| 指到句，不打哑谜 | 硬伤清单带句序与原文片段 |
| 改稿给对照 | "改前/改后/为什么"三列是硬性格式 |
| 能闭环 | 改完必须重跑，两次数字并排 |
| 排完能直接粘 | 全内联 + 680px + table 布局，自带合规 linter |
| 配图不用自己找位置 | 下载到本地 + 自动生成图片上传清单 |
| 不越界 | 明确列出不处理的需求；排版只套版不做设计 |
| 账号由你定 | 名称、方向、读者、语气都来自用户；不预设领域，不代起号名 |

## 十一、审核四维度自查

| 维度 | 审核方会问 | 本包的答卷 |
|---|---|---|
| 任务完成度 | 能不能稳定交付一个完整结果 | 只承诺一件事（改稿）；四条工作流各有明确产出；脚本可跑；12 项测试通过 |
| 指令遵从性 | 同一指令跑十次稳不稳 | 阈值为固定数值，同一稿件输出一致（T2/T3 可复现） |
| 事实辨别性 | 会不会编造 | 明令禁止编造；W1 含"事实待核清单"；缺数据要求用户补 |
| 规则遵从性 | 格式与合规声明有没有写进规则 | 不承诺流量、不判定 AI 来源、不碰他人作品、质检分数非权威认定，均写入 Agent 与 LICENSE |
