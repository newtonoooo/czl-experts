## [3.3.0] — 2026-10-26

**账号信息改为用户自填，清除全部预设账号与预设领域。职业名补上「成稿」「排版」。**

### 一、清除的预设是两类，不是一类

用户的要求是"把某个具体账号名及其相关内容全部去掉"。但只删账号名不够——样本文章写的是升学，
同样会把使用者带到一个不属于他的领域。所以清了两类：

| 类型 | 原状 | 现状 |
|---|---|---|
| 账号名 | 落款固定写成某一个真实账号名 | 全部改为 `示例公众号` / `你的公众号名` 占位 |
| 领域内容 | 样本稿是中考升学、家长读者、成都本地 | 改为中性的「小店观察」题材，与任何领域无关 |
| 领域示例 | 选题技能的例子是"中考体育" | 改为"早高峰通勤"，只作方法示例 |
| 落款 slogan | 固定为某账号的一句话定位 | 改为"换成你自己的一句话定位" |

涉及 13 处、11 个文件，含 `typography-spec.md` 里的溯源说明与 §8 语气要求——后者原本直接写着某个账号的语气规则，
现在改为"语气由使用者提供"，原句降级为"填写示例"。

### 二、新增一道开工关卡：先拿到账号的两件事

主 Agent 里加了一节「开工前，先拿到账号的两件事」：

| 要什么 | 用来干什么 | 没给怎么办 |
|---|---|---|
| 公众号名称 | 落款显示 | 落款整块不输出，交付时提醒补上 |
| 账号方向 | 写给谁看、写什么领域、举什么例子 | 先问一句，不猜 |

并写死一条：**没有任何默认值**——不许默认教育、不许默认升学、不许默认家长读者、不许默认某个城市、不许默认任何具体账号名。

**为什么不能让 AI 编一个账号名**：读者会照着去搜，搜不到就是骗人。所以规则是"不知道就留空，落款不出，比编一个强"。

同步落到三个技能：
- `draft-foundry` 新增「第零步：先确认账号，再接选题」（后续步骤顺延编号）
- `publish-kit` 新增「落款的硬规矩」三条
- `markdown-dialect` 的 `footer_name` 说明补上"必须由用户提供"

### 三、职业名补「成稿」「排版」

| 字段 | 旧 | 新 |
|---|---|---|
| `profession.zh` | 公众号图文创作与质检专家 | **公众号成稿质检与排版专家** |
| `profession.en` | Draft Writing & Quality Expert | **Drafting, QC & Typography Expert** |
| `displayDescription.zh` | 45 字，从关键词讲起 | 42 字，按账号方向 → 成稿 → 去AI味 → 排版 |

`displayDescription` 从"从一个关键词出发…"改掉，是因为原来那句**默认了用户会从关键词起步**。
现在改成"按你账号的方向…"，先讲账号、再讲动作。

### 四、首屏提示词也改了

原来首屏是"我有个关键词「中考体育」…"——既是预设领域，也是预设起点。改成：

> 我的号写的是 ___（说个方向，比如美食/职场/育儿）。关键词是「___」，帮我搜搜最近有什么热点，出 5 个选题让我选。

留了两个空让用户填，括号里给了三个不同领域的例子——**三个都列，等于不预设任何一个**。

### 六、包内位图全部改为自制

上架前核查素材时发现：`samples/images/02_photo.png` 是从测试站点下载来的示例图，属于第三方素材。

虽然它只是一张 100×100 的占位图，但**商业分发的包里不该出现任何非自制的位图**——这跟图有多小无关。
已用纯标准库脚本重绘为 600×400 占位图（浅底 + 描边 + 三条占位文本条 + 主色标记）。

同时把 `images/SOURCES.txt` 从"测试下载留下的记录"改成真实说明：包内两个位图分别来自哪里、授权如何，
以及 `fetch_images.py` 本身不预置、不缓存、不分发任何图片。

**结论**：专家包本体不含第三方图片素材，配图版权风险只存在于使用者调用下载脚本时。

顺带改掉一处过度承诺：平台展示文案原写"定稿后专家会自动排版并配图"，容易被读成"它保证配图可用"。
已改为"会直接排版；配图不是自动的，你说要图它才找，授权仍需你确认"。

### 五、上架前补的两份样本说明

`quality-gate/samples/` 与 `topic-radar/samples/` 里的回归样本仍沿用最早标定阈值时的题材。
换题材就要重新标定（44 / 98.9 两个分数锚点、0.45 查重线），容易把已验证的区分度弄丢，所以没动。

为了不让审核方或使用者误读成"产品预设了这个领域"，在这两个目录各加了一份 `README.md`，说明：

- 这些文件是回归样本，不是产品模板
- 题材为什么保留（阈值标定）
- 本专家不预设任何行业、地区、读者类型（附主 Agent 的"无默认值"规则）

根目录 README 的「已知限制」也加了一条同样的说明。

- 全包旧账号名命中数：**0**（含样本 HTML、规范副本、脚本注释）
- 用户可见文案里 `中考/成都/家长` 命中数：**0**

### 为什么是这个名字

驳回原因不是名字不好，是**撞名**。所以新名字要同时满足三件事：唯一、一眼看懂、不虚构能力。

「内容运营」「公众号运营」「新媒体运营」这类通用词基本都被占了，必须带一个不常见的组合。选的组合是**「创作 + 质检」**：

- **创作** 对应选题与成稿（`topic-radar` + `draft-foundry`）
- **质检** 是这个产品最不可能被替代的那一段：八项指标、六类硬伤定位到句子、去 AI 味（`quality-gate`）
- 两个字并列在同类资产里很少见，撞名概率低；同时两句都是**真做过的**，不含"运营增长""涨粉"这类不承诺的能力

没选的两个方向及原因：

- **「公众号稿件质检与排版专家」**：最稳，但把成稿能力藏了。产品确实能写，藏起来等于少一半客源。
- **「公众号单篇图文创作专家」**：覆盖全链，但"创作专家"太通用——同名的工具一抓一把，很可能再被驳回一次。

### 只改了名字，没改别的

能力、技能、脚本、行为、边界一概未动。`displayDescription` 也不需要改——"搜热点、出选题、搭骨架、写成稿、去AI味、排版发布"里，"选题/成稿"落在**创作**上，"去AI味/排版"落在**质检**上，与职业名对得上。

### 如果这个名字也被驳回

按优先级换下一个，只改 `profession`、不动包结构：

1. `公众号图文质检与排版专家` — 最稳，藏掉成稿
2. `公众号单篇图文创作专家` — 覆盖全链，但通用词多
3. `公众号文章审校专家` — 最短，最不可能撞名，但"审校"偏书面

换名后必须重新打包（`package_expert.py`），并同步 `agents/*.md` 的 frontmatter，否则卡片标题与内部身份会不一致。

## [3.2.0] — 2026-10-26

**排版规范升版：新增 5 套配色，布局改用全 table 骨架。**

用户更新了《公众号 HTML 排版规范》，这一版有两处结构变化，不只是加配色。

### 一、5 套配色，默认随机

| key | 名称 | 适合 | 主色 / 强调 / 点缀 |
|---|---|---|---|
| `a-ink` | 墨绿书卷 | 硬新闻、盘点、深度 | `#1F5A50` / `#9E3B2E` / `#C29A4B` |
| `b-navy` | 藏青学术 | 政策、规则、数据解读 | `#23395B` / `#C5673F` / `#B8924E` |
| `c-dai` | 黛蓝烟雨 | 随笔、教育理念、慢话题 | `#2F5D62` / `#A85A6A` / `#C9A86A` |
| `d-chestnut` | 栗棕暖陶 | 亲子、情感、成长故事 | `#7A5230` / `#B5573D` / `#C9A24B` |
| `e-graphite` | 石墨青 | 观点、评论、年轻化表达 | `#264653` / `#E76F51` / `#E9C46A` |

- **默认随机**：每篇抽一套，整篇级别，不会一章一个色
- **优先级**：`--theme` > frontmatter `theme:` > 随机
- `--seed 42` 可复现同一套；`--list-themes` 列出全部
- 渲染日志会打印抽到哪套、三个色值，以及"想固定就加 `--theme xxx`"

随机这一步的必要性在于：一套配色用久了，读者会在信息流里先认出颜色再认出内容；五套轮换能缓解视觉疲劳，但**同一篇必须只用一套**——规范里写死了这条。

### 二、布局从 div 改成全 table 骨架

上一版规范写的是"普通块级 + table + inline-block"，这一版改成 **外层 table + 容器 table + 每个区块一个 `tr>td`**。所以渲染器整体重写：

| 项 | 旧 | 新 |
|---|---|---|
| 骨架 | `div` + `max-width:680px` | 外层 table > 容器 table > 区块 `tr>td` |
| 章节 | 整条主色色条 | **编号方块（01/02）+ 标题**，重点章节换强调色 |
| 正文 | 14.5px / 行高 1.95 | **17px / 行高 1.95**（规范 §4 的舒展版） |
| 左右留白 | 24px | **32px** |
| 章节内 | 套白卡片 | 直接排，不套卡片 |
| 落款 | 强调色色块 | 顶边线 + 居中衬线名 + 次要色 slogan（可 `/` 换行） |

### 三、补齐规范里缺的三个组件

旧渲染器只有「时间轴 / 数据表 / 编号清单 / 提示块」，规范 §6 里的金句卡、数据卡、来源框一直没实现。这一版补上：

```markdown
::: stats          # 数据卡（2—4 列，浅底细边，大数字用强调色）
5 个|关键节点
:::

::: quote          # 金句卡（主色底，里面 ==这样写== 变成点缀色）
一句必须被看见的话。
:::

::: source         # 来源框（白底细边）
素材来源
文件名、日期、单位
:::
```

另加两个小功能：frontmatter 的 `tag2`（第二个描边标签）、`## ! 标题`（重点章节换强调色方块）。

### 四、修掉一个换配色必踩的坑

旧渲染器有两处**写死的色值**：主标题 `#222`、提示块 `#5a564c`。加配色后这两处不会跟着变——`e-graphite`（石墨青）主题下标题会是纯黑，提示块会发灰。已全部改为走 token。

这条加进了测试 T31：渲染产物里不允许出现这三个写死色值。

### 五、顺带修掉一个 table 拼接 bug

`full_table()` 自带闭合标签，我在表格与时间轴两处又追加了行和 `</table>`，结果是「空 table + 多余闭合」。校验方法：对渲染产物做标签配平统计（table/tr/td/div/p 各自 open == close）。修完 15 table 对 15 table。

### 验证

31 组功能测试、41 项断言全部通过（新增 T24—T31 配色用例），详见 `docs/测试报告.md`。
五套配色各自的样张：`skills/publish-kit/samples/preview_{a-ink,b-navy,c-dai,d-chestnut,e-graphite}.html`。

## [3.1.0] — 2026-10-26

**排版改为自动执行，新增配图能力。**

### 行为变更（重要）

- **定稿即排版，不再询问。** 原流程是"内容定稿 → 问用户要不要排成 HTML"，现改为**直接排**。
  理由：用户拿到一堆 Markdown 发不出去，排版不是可选项，是交付物的一部分。
  Agent 的 W5 已写明「禁止问"要不要排成 HTML"」，输出规范里也加了"定稿即排版"一条。
  同时补了一条判断标准：**这件事是不是把成果交付出去所必需的？是，就做，不问。**

### 新增

- **配图全流程**（`publish-kit` v1.1.0）
  - `scripts/fetch_images.py`（约 220 行）— 批量下载图片到本地：校验图片魔数（PNG/JPEG/GIF/WEBP）、读尺寸、限体积（12MB）、记录来源、输出可直接粘贴的 Markdown 标记、生成 `SOURCES.txt` 用于版权追溯
  - `render_wechat.py` 支持图片块：`![说明](路径 "图注")`，渲染为居中圆角图 + 灰色图注
  - **自动生成 `图片上传清单.md`**：哪张图、什么尺寸、多大、插在哪一节，并单列"文件缺失""外链""体积超标""版权提醒"
  - `--embed` 参数：把本地图转 base64 内嵌（可选，HTML 会变大，后台不一定认）

### 为什么图片必须下载到本地

公众号**不接受外链图片**。浏览器预览能看到，粘到后台就是裂图。所以流程只能是：
下载到本地 → HTML 用相对路径引用（预览正常）→ 用户发布时在后台逐张上传插入。

清单就是为最后这一步准备的：用户按顺序传，不用再回去找哪张图该放哪。

### 文档

- `publish-kit/SKILL.md` 新增「第四步半：配图」
- `references/markdown-dialect.md` 新增图片语法节
- `references/preflight-checklist.md` 新增「三半、图片上传流程」
- Agent 新增两条注意事项：不用外链图片、不忽略图片版权

- `tags`：改为 选题策划 / 去AI味质检 / 公众号排版
- `quickPrompts`：首屏改为"给关键词出选题"（原先的首屏是"体检稿子"，与新主场景不符）
- `version`：2.1.3 → 3.0.0（MAJOR：产品从单点工具变为链路）

### 关于定位扩张的判断

2.0 时把七件事收窄成一件事，3.0 又扩成一条链。这不是反复，是**换了一种收窄方式**：

- 2.0 的收窄是"砍功能"——不做选题、不做成稿，只做质检
- 3.0 的扩张是"接链路"——选题和成稿不是新增的独立服务，是同一篇文章的三个阶段

区别在于：用户不会拿了选题就走（他会继续要稿），也不会拿了稿就走（他会要改）。三个环节服务的是**同一篇稿子**，所以仍算一件事，只是这件事从头做到了尾。

**但必须承认口径变宽了**：卡片上写"内容运营专家"，实际做的仍是"单篇文章"，不做排期、文风建模、数据复盘。这条边界没动。
