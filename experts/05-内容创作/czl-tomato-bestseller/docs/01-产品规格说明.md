## 一、目标用户与实际使用场景

### 用户画像

| 类型 | 特征 | 最痛的点 |
|---|---|---|
| **在写的人（主力）** | 已开书，日更或周更，有后台数据 | 完读率掉了不知道崩在哪，舍不得弃又不知道该怎么救 |
| **准备开的人** | 有题材想法，还没动笔 | 凭感觉选题，写到三十万字才发现方向错了 |
| **多本并行的人** | 同时在写两本以上 | 精力分配靠感觉，哪本该保、哪本该弃说不清 |
| **想变现的人** | 已经写完一两本 | 不知道自己的书有没有改编价值，签约时看不懂条款 |

### 真实使用场景

1. **深夜看后台**：留存曲线突然下坠，想知道从第几章开始崩的。
2. **开书前一周**：手里有三个题材，选不出来。
3. **写到八十章**：主线越写越空，每天靠加新设定续命。
4. **拿到推荐**：流量进来但次日就掉，不知道是内容问题还是运营问题。
5. **准备签约**：合同里一堆条款，不知道哪几条该问清楚。

## 二、要解决的问题

**核心问题**：网文作者缺少"止损判断"，只有"写作建议"。

具体拆成四个子问题：

| 子问题 | 现状 | 本产品怎么做 |
|---|---|---|
| 选题凭感觉 | 没有可对照的标准 | 五维打分 + 弃题清单 |
| 掉量归因靠猜 | "感觉前面几章有点拖" | 拐点定位到具体章，原因在拐点之前 |
| 不敢停 | 沉没成本绑住人 | 三种退出条件，把"停"变成专业操作 |
| 变现靠运气 | 写完才发现拍不了 | 改编适配度五维评分 + 埋点标准 |

## 三、输入与预期输出

### 输入（四种，任一种都能开工）

| 输入 | 例子 | 对应闸门 |
|---|---|---|
| 一句话题材 | "都市脑洞，主角是外卖员" | G1 |
| 正文片段 | 前三章 / 某几章 | G2 / G3 |
| 后台数据 | 逐章留存、曝光、评论 | G3 / G4 |
| 合同条款 / 收益截图 | 六个字段的原文 | G6 |

### 输出（固定为「结论卡」）

```
【闸门】第 N 道 · XX闸
【结论】过 / 抢救 / 退出
【依据】最多三条，每条带位置
【最弱一环】一句话
【抢救动作】3–5 条，按优先级，可当天执行
【退出条件】什么信号出现就该停
【本次假设】推断信息逐条列出
```

**硬约束**：结论只能三选一，不接受"再观察"。

## 四、通用处理步骤

```
接单 → 定位闸门 → 取证 → 判定 → 落盘 → 指出下一道闸
```

| 步骤 | 做什么 | 失败处理 |
|---|---|---|
| 接单 | 从用户话里提取闸门、材料、诉求 | 信息不足则用行业通例补，写进「本次假设」 |
| 定位闸门 | 按用户处境映射到 G1–G6 | 无法判断男频女频时，一次问清并给选项 |
| 取证 | 有正文取钩子/增量/情绪；有数据对齐章号；只有想法走评分表 | 数据不足时明确说明"需要什么才能判断" |
| 判定 | 按结论卡输出 | 不能三选一就不许输出 |
| 落盘 | 写成 Markdown | 需要 docx/html/txt 用 `draft_exporter.py` |
| 指路 | 说明下一步该过哪道闸，不自动往下做 | —— |

## 五、工具能力与技术接口

### 依赖要求

- Python 3.8 及以上；
- **零第三方依赖**，仅标准库（argparse / json / re / os / sys / html）；
- 无网络请求，无外部 API，不上传任何用户数据。

### 16 个 CLI 工具

| 分组 | 工具 | 输入 | 输出 |
|---|---|---|---|
| G1 | `gate1_topic_scan.py` | 五个维度分数 | 判定 + 最弱维 |
| G1 | `gate1_rival_read.py` | 同类样本表 | 趋势 + 建议 |
| G2 | `gate2_pressure.py` | 第一章文本 | 压强初筛结果 |
| G2 | `gate2_goal_visibility.py` | 目标/阻碍/代价 | 三问通过情况 |
| G3 | `gate3_hook_audit.py` | 整本稿件 | 等级分布 + 不达标章号 |
| G3 | `gate3_info_gain.py` | 逐章增量标注 | 低增量章列表 |
| G3 | `gate3_drop_autopsy.py` | 逐章留存序列 | 拐点 + 回看范围 |
| G4 | `gate4_surge_prep.py` | 四项目状态 | 就位判定 |
| G4 | `gate4_sentiment.py` | 评论文本 | 归类统计 + 极性 |
| G5 | `gate5_tension.py` | 承诺台账 | 余额 + 过期项 |
| G5 | `gate5_thread_close.py` | 支线状态表 | 回收率 |
| G5 | `gate5_consistency.py` | 战力记录 | 无解释跳变 |
| G6 | `gate6_revenue.py` | 收益分项 | 结构判断 |
| G6 | `gate6_adapt_score.py` | 五维分数 | 总分 + 短板 |
| G6 | `gate6_contract_check.py` | 六字段 | 未约定项 |

**统一约定**：所有工具 `--help` 可用；数据错误返回码 2；判定不合格返回码 1；正常返回 0。

## 六、质量、速度、稳定性要求

| 维度 | 要求 | 现状 |
|---|---|---|
| **判断质量** | 每个结论必须能定位到章/段；不许出现无落点建议 | 由结论卡格式强制 |
| **响应速度** | 单次判定在对话内完成，不排队；脚本单次运行 < 1 秒 | 实测均为秒级 |
| **稳定性** | 空文件、字段缺失、参数越界必须给错误提示且不崩溃 | 已测三类边界用例 |
| **可解释性** | 每个数字标注来源与是否为经验值 | 所有输出带"经验参考"注脚 |
| **数据安全** | 不联网、不上传、不落盘用户原文（仅读写本地文件） | 全部脚本无网络调用 |

## 七、明确不做什么

1. 不代写正文、不写人设、不写关键转折；
2. 不承诺上榜、不承诺收入；
3. 不提供平台官方数据接口（无授权）；
4. 不做 AI 检测规避（合规红线）；
5. 不评价无法取证的事（如"这本能不能爆"这类无输入判断）。
