# 完结止损判定

> 闸门：第五道 · 续航闸　｜　模块编号：G5-07　｜　适用：纠结该继续写、压缩收尾，还是直接完结时

## 一、这个模块解决什么

这是整个产品里最反直觉的模块：教你在什么情况下应该结束一本书。写得下去和写得值得，是两件事。

## 二、判断标准

四种处置，按三个信号组合判断：

| 信号 | 检查 |
|---|---|
| 张力余额见底 | G5-01 判定为“见底” |
| 干预无效 | 连续 10 章做 G3-01/G3-05 干预，留存无改善 |
| 设定崩坏 | G5-03 出现 3 处以上无法解释的矛盾 |

| 组合 | 处置 |
|---|---|
| 仅余额见底 | 压缩收尾（3 卷压 2 卷） |
| 余额见底 + 干预无效 | 加速完结（10–15 章内收完） |
| 三项全中 | 立即完结，写一个完整结局 |

**底线**：无论如何给一个结局。烂尾的伤害大于短。

## 三、操作步骤

1. 跑三个信号检查；
2. 按组合表定处置方式；
3. 写一份收尾清单：必须交代的 5 件事；
4. 按清单写完，不再开新线。

## 四、输出模板

```
信号：余额 <充足/偏薄/见底>；干预 <有效/无效>；设定 <自洽/崩坏 <n> 处>
处置：继续 / 压缩收尾 / 加速完结 / 立即完结
收尾必交代：1.<...> 2.<...> 3.<...> 4.<...> 5.<...>
预计完结章：第 <N> 章
```

## 五、三个常见误判

- **因为投入太多而不敢停**：沉没成本不参与决策。
- **直接断更了事**：没有结局的书会污染你所有后续作品的读者信任。
- **加速完结时砍掉所有支线**：主线要完整，支线可作废但要交代一句。

判定后如需重开新书，回 G1 选题闸。
