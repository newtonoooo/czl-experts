# 掉量解剖：从数据到章号

> 闸门：第三道 · 留存闸　｜　模块编号：G3-08　｜　适用：后台数据在掉，但不知道从哪一章开始掉时

## 一、这个模块解决什么

把“完读率掉了”这种笼统描述，定位到具体章与具体段落。方法是对齐曲线找拐点，再从拐点往回找病灶。

## 二、判断标准

四步定位法：

| 步骤 | 做什么 | 产出 |
|---|---|---|
| 对齐 | 把每章的留存率按章号排列 | 一条曲线 |
| 找拐点 | 找斜率突然变陡的 2–3 个点 | 可疑章号 |
| 回看 | 只读拐点前 3 章的最后一段 | 病灶候选 |
| 归因 | 对照四类病灶：钩子弱 / 增量低 / 情绪断供 / 设定混乱 | 结论 |

**原则**：掉量的原因永远在**拐点之前**，不在拐点之后。

## 三、操作步骤

1. 导出逐章留存数据（无后台数据则用章节阅读量衰减代替）；
2. 标出三个最大跌幅点；
3. 每个点往前推 1–3 章，读章末；
4. 按四类病灶归因，写出改法。

## 四、输出模板

```
拐点：第 <A>、<B>、<C> 章
跌幅：<x>%、<y>%、<z>%
回看范围：第 <A-3>–<A> 章
归因：钩子弱 <n> 处 / 增量低 <n> 处 / 情绪断供 <n> 处 / 设定混乱 <n> 处
优先处理：第 <N> 章（原因：<...>）
```

## 五、三个常见误判

- **在跌幅点那一章找原因**：原因在前面。
- **把掉量归因于“平台不给量”**：留存是内容指标，推荐是流量指标，两件事。
- **一次改十处**：改完就不知道是哪一处生效了，一次改一到两处。
