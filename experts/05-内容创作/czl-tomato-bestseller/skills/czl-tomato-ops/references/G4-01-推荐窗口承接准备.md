# 推荐窗口承接准备

> 闸门：第四道 · 爆发闸　｜　模块编号：G4-01　｜　适用：拿到推荐位或流量要来了，不知道怎么接时

## 一、这个模块解决什么

推荐位的本质是一次“高流量、低耐心”的考试。窗口期读者停留时间更短，承接准备必须在窗口前完成，窗口内只做微调。

## 二、判断标准

窗口前必须就位的四件事：

| 项目 | 标准 |
|---|---|
| 前三章 | 已过 G2 全部 8 项自检 |
| 存稿 | 至少 5 章，保证窗口内不断更 |
| 首章标题 | 能独立成立，不依赖上下文 |
| 简介 | 一句话说清“谁、想要什么、被什么挡”，不超过三句 |

## 三、操作步骤

1. 窗口前 48 小时：跑一遍 G2-07 自检表，任一项不过就延期；
2. 备够 5 章存稿，锁定加更节奏；
3. 重写简介，删掉所有形容词，只留事实；
4. 窗口期内不再改开篇，改稿会破坏已产生的数据基线。

## 四、输出模板

```
窗口预计：<日期>
自检结果：<N>/8
存稿：<N> 章
简介版本：v<N>
风险项：<...>
是否就位：是 / 否（缺什么）
```

## 五、三个常见误判

- **窗口期还在改前三章**：数据基线被破坏，看不清真实承接率。
- **把推荐当终点**：推荐只是流量，留存才决定它有没有第二次。
- **简介写成剧情简介**：简介是筛选器，不是内容摘要。

## 六、关联模块

窗口后进 G4-05（流量异常归因）判断承接质量。
