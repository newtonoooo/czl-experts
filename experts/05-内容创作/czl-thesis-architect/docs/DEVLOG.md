## 一、为什么重做

1.0.0 交付后，用户的第一句话是：**"我不要框架，我就要论文写作功能，要全部论文写作功能，要全流程功能。"**

这句话点中了 1.0.0 的真实问题：那一版的核心是**过程管控**——八阶段闸门、状态文件、证据台账、
修订追踪表。用户拿到的是"你现在在哪个阶段""产物齐不齐"，而不是"帮我把这段摘要写出来"。
对一个要交论文的人来说，前者是负担，后者才是需求。

所以 2.0.0 换了组织方式：

| | 1.0.0 | 2.0.0 |
|---|---|---|
| 组织单位 | 八阶段闸门 | 十二个写作模块 |
| 默认输出 | 状态、清单、任务书 | 正文段落、改后稿、排好格式的文献表 |
| 工具 | 管流程（gate / ledger / track） | 管写作（字数 / 摘要 / 语言 / 引用 / 重复 / 图表） |
| 用户第一步 | 建项目、填状态 | 直接说"写第三章" |

1.0.0 的闸门与台账**整套删除**，不是改名保留。同时新增 15 份写作手册、13 份模板、
6 个写作工具，全部围绕"写出东西"。

## 三、写作手册怎么写的（这是产品的主体）

每份手册固定四段结构，目的是让"我"（模型）读完就能落笔，而不是读完只记住一堆原则：

1. **段落配方**：这一章分几节、每节干什么、每段什么段型、字数占比。
2. **句式库**：按功能分类的可取材句式（起段、分歧、评价、收口、过渡、报数据、解释、限制）。
3. **示范段落**：一段真实长度的完整示例（如摘要 300 字、引言 700 字、讨论机制段 200 字）。
4. **常见错误对照**：左边错例、右边改法，逐条说清为什么。

举例：`04-abstract-and-keywords.md` 给了中文摘要五槽位、300 字示范段、英文摘要改写对照
（把"本研究以……为对象"改成"Drawing on …"），以及六个常见错误（写成导语、无数字、结论空泛等）。

## 四、测试驱动的修正记录

第一轮 54 个用例跑出 11 个失败，逐条修（这部分是真实的，不是事后补写的）：

1. **`dup_scan.py` 语法错误**：`*table if segments else [...]` 不能用条件表达式直接解包。
   → 先算出 `table_lines` 再解包。
2. **`abstract_check.py` 抓不到英文摘要**：`## Abstract` 带井号，正则只匹配裸词，且大小写敏感。
   → 剥掉井号再判，加 `re.IGNORECASE`。
3. **`abstract_check.py` 中文摘要被英文标题截断**：把标题行也当正文收进去了。
   → 遇到其他标题即关闭当前摘要区，标题行不入正文。
4. **`wordstat.py` 认不出章**：正则只认中文数字（第一章），实际写作多用"第 1 章"；
   而且标题带 `#` 前缀。
   → 正则允许阿拉伯数字与可选井号，标题去掉井号后再展示。
5. **`wordstat.py` 缺"前置部分"统计**：题目与摘要落在第一章之前的空档里，字数丢失。
   → 第一章之前若有内容，生成"（前置：题目/摘要）"伪章。
6. **`wordstat.py` 两章文档不报失衡**：阈值写成章数 ≥3。
   → 改为 ≥2。
7. **`style_lint.py` 英文被动比率为 0**：英文按中文句号切句，切不开。
   → 英文单独按 `[.!?]` 切句。
8. **`style_lint.py` 把关键词行当连续短句**：`关键词：A；B；C` 被切成五句。
   → 关键词行、表格行、标题行不参与连续短句判定。
9. **`style_lint.py` 密度显示成 4.199475…**：消息里用了未舍入的原值。
   → 改用已舍入的指标。
10. **`cite_format.py` 把整篇文档吃成一条文献**：整篇输入时，第一条编号之前的正文
    被当作第 0 条，然后所有正文都拼进去，输出长达数千字。
    → 若存在编号条目，从第一条编号开始解析；没有编号时只保留含类型标识的段落。
11. **`figtable.py` 提示语对表不适用**：只说"如图 X 所示"。
    → 改成"如图 X 所示"或"见表 X"。

修完复跑，54/54 通过；再把六个工具在夹具上实跑一遍，确认输出可读、能指回行号。

## 五、设计取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| 组织方式 | 12 模块并列，不串联 | 用户常常只卡一章，不该被迫从选题开始 |
| 默认输出 | 直接给正文 | "先给建议再让你写"是用户明确否掉的做法 |
| 占位符 | `〔待补：缺什么｜从哪拿〕` | 允许在材料不全时继续写，同时不编造 |
| 推断标注 | `〔核验：…〕` | 我推出来的数字必须让用户回原始材料核 |
| 工具定位 | 只查机械问题 | 论证质量靠人读，工具给线索不给判决 |
| 句子库 | 给骨架不给整段 | 整段套模板比 AI 味更容易被看出来 |
| 中文病句对照 | 30 组 | 润色最容易见效的地方，宁可多给 |
| 删除闸门 | 完全移除 | 用户明确说不要框架；保留会稀释"能写"的定位 |

## 六、原创性说明

- 全部文本（提示词、15 份手册、13 份模板、README、文档）为本项目编写，未从其他专家包复制。
- 6 个工具、1 个公共模块、7 个测试文件为本项目编写，仅用 Python 标准库，无第三方代码。
- 头像沿用 1.0.0 时生成的原创符号标识（页面网格 + 垂线 + 标尺梁），本次未更换。
- 参考的公共知识：GB/T 7714-2015 的著录要素、APA/MLA/IEEE 的通行样式、学术写作通识方法
  （IMRaD、三线表、hedging、漏斗式引言）。这些属领域常识与公开规范，未复制标准正文或他人教程。
