# 文衡 · 论文写作全流程导师（Paperwright）

> 包名：`czl-thesis-architect`　版本：2.0.0　开发者：虫志龙（47190078@qq.com）
> 类型：Agent 型专家　分类：06-ContentCreative

文衡是**写手型导师**。你说"写第三章方法"，它给你三千字方法章；你说"这段摘要太像总结"，
它给你中英两版改后摘要。不是给你一堆建议让你自己凑。

覆盖从选题到答辩的十二个环节，每个环节都有专属写作手册（段落配方 + 句式库 + 示范段落 + 错误对照），
配六个本地工具做字数、引用、摘要、语言、重复、图表的机械核对。

## 一、十二个写作模块

| 模块 | 你说什么 | 它给你什么 |
|---|---|---|
| W1 选题与开题 | "题目没定""帮我开题" | 3—5 个题目候选（带评估）→ 收敛题目 → 研究问题 → 开题报告全稿 |
| W2 文献与综述 | "写文献综述" | 中英文检索式 + 文献矩阵 + 综述正文（按争议组织）+ 衔接句式 |
| W3 结构与提纲 | "列提纲" | 三级提纲 + 字数预算 + 每章任务与出口 + 论证骨架 |
| W4 摘要与关键词 | "写摘要" | 中文摘要 + 英文摘要 + 关键词 + 五要素核对 |
| W5 引言 | "写引言" | 四段式引言正文（背景—缺口—问题—贡献与结构） |
| W6 方法章 | "写研究方法" | 方法章正文：设计、样本、工具、程序、分析、效度威胁、伦理 |
| W7 结果与图表 | "写结果" | 结果叙述句 + 三线表 + 图注 + 统计报告模板 |
| W8 讨论与结论 | "写讨论""写结论" | 讨论四段（发现—对话—机制—边界）+ 结论 + 分层建议 |
| W9 语言润色 | "润色""改得像论文" | 改后全文 + 改动对照表（中文 30 组、英文 15 组高频病句） |
| W10 降重与查重 | "查重 30%" | 报告解读 + 逐段改写（换骨架）+ 引用补标 |
| W11 引用与格式 | "参考文献格式" | GB/T 7714 ↔ APA ↔ MLA ↔ IEEE 互转 + 缺项检查 + 格式清单 |
| W12 答辩与投稿 | "答辩 PPT""投稿信" | 逐页 PPT + 讲稿 + 问答预测 + 期刊矩阵 + cover letter + 回复信 |

附属文本（致谢、附录、个人陈述、研究计划）在 W12 末节。
文体差异（人文 / 质性 / 量化 / 实验 / 工程 / 算法 / 综述）见 `references/14-genre-methods.md`。

## 二、怎么用

### 装进 WorkBuddy

专家包放到：

```
%WORKBUDDY_CONFIG_DIR%\plugins\marketplaces\my-experts\plugins\czl-thesis-architect\
```

（未设环境变量即 `C:\Users\<你>\.workbuddy\plugins\marketplaces\my-experts\plugins\`）

或用脚本注册：

```bash
python <expert-manager>/scripts/register_expert.py <专家包目录>
```

### 直接说要写什么

- 「帮我写第三章的研究方法：问卷设计、样本说明和数据分析方法，大约三千字。」
- 「我的题目还没定，只有大概方向，帮我把题目定下来，并给出开题报告的完整框架。」
- 「这段摘要写成了总结，帮我改成规范的学术摘要，中英文各一版。」
- 「这几段查重标红了，帮我按换骨架的方式改写，保留引用。」
- 「帮我做答辩 PPT，十页，每页给讲稿。」

### 用工具（可选）

```bash
cd skills/thesis-architect

python scripts/wordstat.py 正文.md --target 12000       # 字数与章节配比
python scripts/abstract_check.py 正文.md               # 摘要与关键词
python scripts/style_lint.py 正文.md                   # 套话、长句、连续短句
python scripts/cite_format.py 参考文献.md --to apa     # 引用转换与检查
python scripts/dup_scan.py 正文.md --sources 文献/      # 与源文本重合比对
python scripts/figtable.py 正文.md                     # 图表编号与引用
```

全部支持 `--json`；退出码 `0` 正常、`1` 有严重问题、`2` 参数或文件错误。

## 三、六个工具各管什么

| 工具 | 检查项 | 什么时候跑 |
|---|---|---|
| `wordstat.py` | 按章统计中英文字数、段落数、图表数，对比目标字数，标失衡章节 | 写完一章核对字数；定稿前查配比 |
| `abstract_check.py` | 摘要字数、五要素（目的/方法/结果/结论/边界）、关键词数量与质量、中英文数字一致性 | 写完摘要自查 |
| `style_lint.py` | 套话密度、长句比例、连续短句、连接词连用、段首雷同、英文被动、高频重复词 | 润色前定位问题段；改完复查 |
| `cite_format.py` | 编号连续、类型标识、年卷期页、出版项、访问日期、重复条目；四种格式互转 | 交稿前统一格式；投稿换刊 |
| `dup_scan.py` | 与给定源文本的 n-gram 重合，标出疑似未标注重复的段落与行号 | 降重前定位；交稿前自查 |
| `figtable.py` | 图表编号重复/跳号/风格混用、题注未被引用、正文引用悬挂 | 定稿前 |

## 五、写作规矩（它一定会守）

1. **先给文字，再给说明。** 默认输出是可粘贴的正文，不是建议清单。
2. **不编造。** 文献、数据、问卷结果、访谈引语、学校规定一律不造；缺材料用 `〔待补：缺什么｜从哪拿〕`。
3. **推断要标。** 根据你的口径推出来的数字标 `〔核验：…〕`，提醒你回原始材料核对。
4. **不承诺。** 不承诺通过、录用、查重率；不提供规避查重或 AI 检测的做法。
5. **不改你的结论。** 润色只调语体和结构，核心判断由你定。

## 六、脚本的已知局限

- `figtable.py` 的题注识别是启发式，依赖"行首为 图/表/Figure/Table + 编号"，模板写法特殊时可能漏识别。
- `cite_format.py` 只做结构与标点重排；中文姓名转拼音、刊名缩写需人工处理（输出会逐条标注）。
- `dup_scan.py` 按字符 n-gram 比对，纯英文短片段（<40 字符）不报；它不判断引用是否正当。
- `abstract_check.py` 的五要素判定是关键词启发式，只作提示。
- 所有工具都不联网，不判断文献是否真实存在。
