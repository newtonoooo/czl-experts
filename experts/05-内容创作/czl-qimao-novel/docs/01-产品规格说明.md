## 一、目标用户与使用场景

### 用户

1. **准备在七猫开新书的作者**：有想法，不确定题材能不能过、开篇该怎么写。
2. **正在投稿的作者**：稿子写了两万字，投出去没回音，不知道为什么。
3. **已签约、卡在数据上的作者**：均留在 8% 左右，知道不好但不知道差在哪一档、该改哪一章。
4. **算不清收入的兼职作者**：想知道日更 6000 到底比 4000 多赚多少、断更一次损失多大。

### 场景

- 动笔前：判断题材与壳，避免写完 20 万字才发现方向不对。
- 投稿前：把材料整理成编辑能五分钟看完的形态。
- 上架前：确认分类、标签、简介、存稿四件事。
- 上架后：把均留和 UV 换算成档位与缺口，再翻译成具体章号的修改动作。
- 签约谈判前：算清保底与全勤的现金流，判断自己的产能撑不撑得住。

### 不适用

- 不想写、只想让 AI 整本代写的：本产品明确要求人工实质创作，代写路径不做。
- 需要平台代运营、代投稿、代签约的：不提供。
- 其他平台（番茄、起点、晋江）的规则咨询：本产品的分档表与规则口径是七猫的，跨平台会算错。

---

## 二、要解决的问题

七猫这条链路上，作者真正会卡住的不是"不会写"，是四个具体的坑：

| 问题 | 现状 | 本产品怎么解 |
|---|---|---|
| 投稿没回音 | 作者不知道编辑在挑什么，反复改文笔 | 把编辑的关注点拆成十条红笔，先改结构再改字 |
| 均留不好但不知差多少 | 只知道"低"，不知道落在哪一档、差几个点 | 按官方分档表定位档位、单价、缺口、UV 门槛 |
| 收入算不清 | 只知道"日更越多越好"，不知道 20 万字上限与档位跳变 | 现金流模型，四个日更档位对比 |
| 断更一次损失多少没概念 | 以为只是少一天的钱 | 算出整月全勤归零的代价，倒推排产天数 |

## 三、输入与输出

### 必要输入（缺一项就只做能做的部分）

1. 频道与题材（男频/女频 + 一句话题材）
2. 核心爽点（读者追的是哪一种情绪）
3. 更新能力（每天稳定能写多少字）
4. 当前阶段（没动笔 / 有稿没投 / 已签约 / 已上架）

### 可选输入

对标书、计划字数、签约模式、千字单价、均留、日阅读 UV、现有章节文件。

### 输出

- 七类**工单**（Q1–Q7），每张含：站号、日期、输入摘要、判定（放行/返工/止损）、依据、交付物、下一站进入条件。
- 正文类交付：书名候选、简介、大纲、样章、章节。
- 数值类交付：五维评分、档位定位、现金流表、断更风险。
- 全部为 Markdown，可另行导出 docx/pdf。

## 四、通用处理步骤（七站流水线）

```
Q1 选品 → Q2 包装 → Q3 结构 → Q4 样章 → Q5 上架 → Q6 档位 → Q7 现金流
```

| 站 | 任务 | 判定 | 短路规则 |
|---|---|---|---|
| Q1 | 题材对主收盘、五维打分 | 放行/返工/止损 | 已有签约书只问后续 → 直接 Q6 |
| Q2 | 书名、简介、标签、封面 brief | 放行/返工 | 已有强书名 → 只做简介与标签 |
| Q3 | 大纲六段式 | 放行/返工 | 已有大纲 → 只做体检 |
| Q4 | 两万字样章，前 200 字压强 | 放行/返工 | 只想要建议 → 出自检表并声明未读稿 |
| Q5 | 三万字上架前检查 | 放行/暂缓 | 已上架 → 转"改分类代价评估" |
| Q6 | 均留/UV → 档位与缺口 | 守档/抢救/止损 | 无 UV → 只做均留定位并标注未验证 |
| Q7 | 全勤与保底现金流 | 放行/返工 | 无单价 → 用区间做敏感性分析 |

**站间纪律**：不许跳站；每站产物必须落成工单；判定只有三种，没有"基本可以"。

## 七、与目标专家的功能边界

本产品参考了同类网文生成工具的通用思路（一句话扩写、大纲规划、逐章生成、连贯性台账），并做了三处实质性重构：

1. **顺序重构**：同类工具通常"先写后看数据"。本产品把七猫的人工签约前置为第一道门槛，先解决"能不能签"，再解决"写得好不好"。
2. **财务层新增**：原类型工具普遍没有收入模型。本产品把全勤档位、20 万字上限、请假额度、断更代价做成可计算模块（Q7），这是七猫"保底 + 全勤"模式下的必需品。
3. **诊断口径重构**：把"留存掉了"改成"落在哪一档、差几个点、缺多少 UV"，并给出档位跃迁路径，而不是泛泛的"提升追读"。

未继承的部分：原类型的英文摘要输出、Mermaid 关系图、`init-novel.sh` 脚本与 `.learnings/` 目录结构——这些属于原产品的具体实现，本产品用独立的工单体系与台账体系替代。
