# 工序 00 · 收料

## 名称

收料（Intake）—— 把散乱素材收成一张能开工的素材卡。

## 职责

判断用户手上的东西**够不够写**、能写成**多长**、缺什么。这道工序不产出文案，只产出判断和清单。

收料做错的代价最大：料不够硬写，后面四道工序全白做。

## 输入参数

| 参数 | 必填 | 说明 |
|---|---|---|
| `raw_material` | 是 | 用户给的任何东西：文字描述、产品资料、聊天记录、图片描述、链接内容、价格 |
| `subject` | 是 | 写的是谁：自己的体验、自家产品、别人的东西、还是一个知识点 |
| `goal` | 否 | 涨粉 / 转化 / 品牌 / 纯记录。缺省按"涨粉"处理 |
| `account_state` | 否 | 新号 / 有粉但不动 / 稳定产出。缺省按"新号"处理 |

## 执行步骤

**第 1 步：抽事实清单。** 把素材里所有信息拆成两列。

- 可核实事实：价格、克数、成分、时长、地址、人数、日期、用户原话
- 不可核实表述：好用、高级、舒服、性价比高、绝了、爱了

事实清单只留左列。右列单独存一栏，标为"待替换"。

**第 2 步：素材三问打分。**

| 问 | 通过标准 | 不通过的样子 |
|---|---|---|
| 有具体物吗 | 至少一个数字 / 价格 / 时间 / 地名 / 可拍动作 | 全是形容词，没有一个能被拍出来 |
| 有对照组吗 | 之前之后 / 别家我家 / 买前买后 / 换前换后 | 只有单点描述，没有参照 |
| 有代价吗 | 花了多少钱、等多久、踩了什么坑、放弃了什么 | 一切都很顺利、都很好 |

**第 3 步：定产能。** 按命中数决定这条素材能撑多长。

| 命中 | 产能 | 处理 |
|---|---|---|
| 0 | 不能写 | 只出取材清单，不出稿 |
| 1 | 短笔记（300 字内，一条信息） | 单点说透，不硬凑结构 |
| 2 | 正式笔记（400–700 字） | 正常进 03 |
| 3 | 可拆多篇（同素材不同角） | 进 02 做矩阵，一条料出 2–4 篇 |

**第 4 步：建素材卡。** 用 `templates/T1-material-card.md`。字段：素材原文摘要、事实清单、三问打分、可切角度预判、风险项（哪些话不能说）。

**第 5 步：出缺口清单。** 缺什么就写什么，写成可执行动作，不写"建议补充更多细节"。

- ✅ `补 1 个数字：这支手霜你用了多久（天数）`
- ✅ `补 1 张图：涂前手背裂口的位置，自然光，别开美颜`
- ❌ `建议提供更详细的素材`

## 判断条件

- 三问全空 **且** 用户不肯补 → 停在 00，只交付"取材清单 + 10 个占位选题方向"，说明为什么不开工。
- 素材是别人的内容（截图、竞品笔记）→ 只能用于**结构分析**，不能改写。明确告知。
- 素材含未证实的功效或数据 → 标红进 `data/compliance_terms.json` 检查，能删则删，能换则换。

## 输出格式

```
【素材卡】T1
事实清单：n 条（列出）
三问打分：具体物 ✓ / 对照 ✗ / 代价 ✓ → 产能：正式笔记
可切角度：亲历、对照（拆解暂缺，缺成分信息）
风险项：'修复'一词涉及功效暗示，建议改'第二天不那么紧'
缺口清单：3 条（附拍摄/记录动作）
```

## 异常处理

| 异常 | 处理 |
|---|---|
| 用户只发一句"我想做小红书" | 不追问三轮。直接给取材清单：拍哪 8 张、记哪 5 个数字、问哪 3 个人 |
| 素材是 PDF/长文档 | 先压缩成 15 条以内的事实清单，回读给用户确认，再往下走 |
| 素材里有大量用户好评截图 | 好评不是素材，是证据。要问：这些好评里有没有**具体场景**？没有就不能用 |
| 用户拒绝补料但坚持要稿 | 出稿，但每处空缺标 `〔待补：…〕`，并在交付开头写明"本稿有 n 处待补，补齐前不建议发布" |

## 依赖

无前置工序。需要读 `references/05-material-angles.md` 做角度预判，读 `references/07-compliance.md` 做风险标注。

## 与其他工序的关系

- 产出直接进 `01 定位`（新号）或 `02 选题`（有定位）。
- 缺口清单里的补料动作，若用户当场能补，回到第 1 步重跑，不必重开工序。
