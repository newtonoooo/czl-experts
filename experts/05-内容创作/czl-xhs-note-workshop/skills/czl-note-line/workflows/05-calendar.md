# 工序 05 · 排期

## 名称

排期（Scheduling）—— 把通过质检的卡片排成一张能执行的日历。

## 职责

决定哪天发哪篇、什么时段发、哪几天留白、哪几篇是同素材不同角需要拉开距离。

排期的核心不是填满，是**节奏**：连续同质内容会让账号看起来像机器。

## 输入参数

| 参数 | 必填 | 说明 |
|---|---|---|
| `approved_notes` | 是 | 通过 04 的笔记卡集合（CSV 或逐张卡片） |
| `per_week` | 是 | 每周产能：2 / 3 / 5 篇 |
| `start_date` | 是 | 起始日期 |
| `days` | 否 | 周期长度：7 / 14 / 30，缺省 30 |
| `best_time` | 否 | 用户历史数据里表现好的时段；没有就用经验默认值 |

## 执行步骤

**第 1 步：分类。** 把卡片按三个标签打标：

- 角度（亲历/对照/拆解/清单/避坑…）
- 骨架（亲历型/清单型/对照型/拆解型）
- 素材来源（哪条原始素材）

**第 2 步：拉距离。** 同一素材衍生的多篇，间隔 ≥5 天。同角度内容不排在前一周两次。

**第 3 步：排节拍。** 按"强—中—弱"交替：

| 位次 | 放什么 |
|---|---|
| 周首篇 | 强选题（P0，搜索意图明确） |
| 周中 | 中等（清单/对照，好读不费脑） |
| 周末 | 弱一点（个人向、生活向，养人味） |

连续三篇都是"干货清单"会让账号像资料库；连续三篇都是生活流又立不住专业度。

**第 4 步：留白。** 每周至少留 1 天空位，用途写清楚：

- 追热点
- 补拍素材
- 数据好的那篇做续集

留白不是偷懒，是给不可预知的机会让路。填满 30 天等于放弃了 30 天里的所有热点。

**第 5 步：定时段。** 没有历史数据时用经验默认值，并且**必须标注这是经验值**：

| 时段 | 适合 |
|---|---|
| 07:30–09:00 | 通勤刷手机，适合短平快 |
| 12:00–13:30 | 午休，适合清单和轻松内容 |
| 19:00–22:30 | 主时段，适合长文与干货 |
| 周末上午 | 生活向、探店、居家 |

有历史数据就用历史数据，不要用默认值覆盖用户的真实表现。

**第 6 步：生成日历。**

```bash
python scripts/build_calendar.py 选题.csv --start 2026-11-01 --per-week 3 --days 30 --out 日历.csv
```

脚本会做三件事：按产能铺日期、同素材自动拉开间隔、跳过留白日。生成后人工检查一遍节拍是否符合第 3 步。

## 判断条件

- 通过质检的卡片数 < 日历所需篇数 → 不注水。宁可 30 天只排 12 篇，把空位标成"待生产"，并给补料动作。
- 同一素材的篇数占比 > 40% → 提示：素材复用过度，账号会显得单薄。
- 用户要求的频率超过实际产能 → 按产能排，说明"日更断更比不日更伤害更大"。

## 输出格式

`templates/T5-calendar.csv`：

```
日期,星期,时段,标题,选题,角度,骨架,素材来源,状态,备注
```

交付时附三条说明：哪几篇需要补拍、哪几天留白及用途、第一周最该盯哪一篇的数据。

## 异常处理

| 异常 | 处理 |
|---|---|
| 用户没有足够卡片 | 排已通过的，其余写"待生产"，附补料清单 |
| 用户要求"每天都发" | 按能力给建议，但不硬拦。给"7 天日更 + 观察"的小步方案 |
| 用户有固定活动日（如每周三直播） | 活动前一天排预告，活动当天不排笔记，避免自己抢流量 |
| 跨节日/大促 | 标注出来，但不自动塞节日选题。节日选题是否合适要看账号定位 |

## 依赖

- `scripts/build_calendar.py`
- `templates/T5-calendar.csv`

## 与其他工序的关系

- 前置：`04 质检`（只排通过的）。
- 后继：发布 → `06 复盘`。
- 日历里的留白日，在复盘后可以回填 `02 选题` 的新条目。
