# 笔记产线（czl-note-line）

这是一条线，不是一个知识库。物料从 `00` 进，成品从 `06` 出。每道工序有明确的输入检查，检查不过就停在那道工序，不带着缺陷往下流。

## 全局约束（先读这一节，再看具体工序）

1. **先读后做。** 进哪道工序，先读对应文件。不许凭印象跳过输入检查。
2. **素材不编。** 用户没给的事实不进入稿件。占位符写 `〔待补：…〕`，并在交付末尾列成清单。
3. **不写亲历未亲历之事。** 用户没做过的，不能写成做过。这是合规问题，不是文风问题。
4. **双闸硬过。** `04-qc-gate` 是硬闸，任何笔记交付前必过。用户催也得过。
5. **结论先行。** 每个判断先给结论，再给依据。不写"建议可以尝试"。
6. **一次一个动作。** 复盘、优化、整改，每次只给一个最该动的动作。给五个等于没给。
7. **规则不猜。** 平台限流、违规判定、算法权重这类拿不准的，明说是经验判断，给自查动作，不编造内部机制。

## 工序总表

| # | 工序 | 文件 | 输入 | 输出 | 硬判据 |
|---|---|---|---|---|---|
| 0 | 收料 | `workflows/00-intake.md` | 用户散乱素材 | 素材卡 T1 + 缺口清单 | 素材三问至少中一问 |
| 1 | 定位 | `workflows/01-positioning.md` | 素材卡 + 账号现状 | 定位卡 T2（3 个备选角） | 一句话能同时说清「对谁·给什么·凭什么」 |
| 2 | 选题 | `workflows/02-topic-matrix.md` | 定位卡 + 赛道词 | 选题矩阵 T3（≥20 行） | 每个选题都能对上素材三问之一 |
| 3 | 成稿 | `workflows/03-note-draft.md` | 选题 + 素材 | 笔记卡 T4 | 5 标题、3 行封面、正文、首评、3+3+2 标签齐全 |
| 4 | 质检 | `workflows/04-qc-gate.md` | 笔记卡 | 通过 / 打回清单 | 两闸全过 + 脚本零高危命中 |
| 5 | 排期 | `workflows/05-calendar.md` | 通过质检的卡片组 | 日历 T5 | 同素材不同角不相邻；每周留白 ≥1 天 |
| 6 | 复盘 | `workflows/06-review.md` | 已发布数据 | 诊断表 T6 + 下一步 | 能指出断在哪一级 + 只给 1 个动作 |

## 依赖关系

```
00 收料 ──→ 01 定位 ──→ 02 选题 ──┬──→ 03 成稿 ──→ 04 质检 ──┬──→ 05 排期
                                  │                        │
                                  └──(批量)───────────────┘
                                                            └──→ 发布 ──→ 06 复盘 ──┐
                                                                                     │
                                                        （下一轮选题从这里回流）──────┘
```

- `04` 打回时，回到 `03` 改稿，不回 `02`。选题没问题不必重来。
- `06` 的结论回流到 `02`，形成选题假设，不是回流到 `03` 改旧稿。
- `01` 只在起号、转型、内容不聚拢时进。已经稳定产出的账号跳过。

## 可执行工具

脚本均为 Python 3 标准库实现，无需安装依赖。

| 脚本 | 用途 | 用法 |
|---|---|---|
| `scripts/note_lint.py` | 笔记体检，40+ 条规则 | `python scripts/note_lint.py <笔记文件.md|.txt> [--json]` |
| `scripts/build_calendar.py` | 生成发布日历 | `python scripts/build_calendar.py <选题.csv> --start 2026-11-01 --per-week 3 --out 日历.csv` |
| `scripts/selftest.py` | 整链自测，产出测试报告 | `python scripts/selftest.py` |

`note_lint.py` 的退出码：`0` 通过，`1` 有高危命中，`2` 输入错误。可直接串进流水线判断。

## 什么时候不该用这条线

- 用户要的是投放计划、达人合作报价、账号代运营 —— 那些不是内容制作，说清楚不在范围内。
- 用户要的是刷量、养号、批量搬运他人内容 —— 直接拒绝，给合规替代。
- 用户要写的是医疗诊断、投资建议、未成年人带货 —— 拒绝并说明原因。
