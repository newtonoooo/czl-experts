# 使用说明

这份说明按"你会遇到的顺序"写，不按功能列表写。

---

## 一、第一次用，先给它三样东西

它不会凭空写。开工前先想清楚这三样，能省掉一半来回：

1. **你手上有什么真实的东西。** 产品资料、一次真实经历、店里拍的照片、课程大纲、客服原话、用户反馈。越具体越好。
2. **这篇想达到什么。** 涨粉、带货、引流、记录。不同目标选不同的选题和 CTA。
3. **你做不到什么。** 不能出镜、只有手机、每周只能发 2 篇、这个东西不能提价格。说清约束，它才不会给你写不了的方案。

一句话就能开始：

> 我手上有一款护手霜和二十几条用户反馈，想在小红书起号。帮我把素材切成选题，先写 5 篇能直接发的笔记。

---

## 二、它会先给你一张素材卡，不要跳过

如果素材很散，第一步是**收料**，出来的是一张素材卡：事实清单（能核实的）、待替换表述（不能进正文的）、三问打分、缺口清单。

三问是：

- 有具体物吗（数字、价格、时间、地点、能拍出来的动作）
- 有对照组吗（之前/之后、别家/我家、买前/买后）
- 有代价吗（花了多少钱、等多久、踩了什么坑）

**命中 0 条，它不会给你写稿**，只给取材清单——拍哪 8 张图、记哪 5 个数字、问哪 3 个人。这不是推诿，是料不够硬写出来一定是广告。

想跳过也可以，但每处空缺会标 `〔待补：…〕`，并且不建议带占位符发布。

---

## 三、拿到笔记卡，先改这一处

笔记卡有六块：标题候选 5 个、封面三行、正文、首评、标签、可选微调。

**先看 5 个标题，选一个。** 每个标题后面标了结构类型和它赌的人群。选完之后，正文的钩子要对得上标题——标题承诺什么，前三行就得交什么。

正文区是干净的，可以整段选中复制。批注都在卡片最下面的"可选微调"里。

封面的三行字：

| 行 | 字数 | 干什么 |
|---|---|---|
| 主标 | ≤9 字 | 这篇讲什么，要有一个具体的量或动作 |
| 副标 | ≤14 字 | 凭什么信，放一个数字 |
| 角标 | ≤10 字 | 谁该看，身份或处境 |

## 四、发布前，让它跑一遍体检

这一步别省。跟它说"过一下质检"，或者自己跑：

```bash
python skills/czl-note-line/scripts/note_lint.py 我的笔记卡.md
```

输出长这样：

```
笔记体检 v1.0.0 · 规则 41 条
结构识别：标题 5 · 封面 3 行 · 正文 352 字 · 标签 8 个 · 首评 有
命中：高危 0 · 中危 0 · 低危 0
结论：☑ 放行
```

命中会这样列：

```
[高危] K01 绝对化用语 · 命中 1 个词
       证据：最好（1 次）
       改法：换成一个可核对的比较……
```

**高危项不清零，不要发。** 高危包括：绝对化用语、功效与医疗暗示、站外导流、承诺性表述、占位符未填、标题超长。

加 `--json 报告.json` 可以拿到机器可读的完整报告；加 `--strict` 让中危项也阻断。

## 五、要一个月的内容，走这条线

选题 → 成稿 → 质检 → 排期，四道连走。

选题矩阵出来是一张 CSV，≥20 行，每行带搜索词、角度、骨架、素材命中、优先级。P0 是"先写"的，控制在 5–7 条——全是 P0 等于没有优先级。

排期：

```bash
python skills/czl-note-line/scripts/build_calendar.py 选题.csv --start 2026-11-01 --per-week 3 --days 30 --out 日历.csv
```

它会做三件事：按产能铺日期、同素材自动拉开 ≥5 天、留出空白位。素材不够 5 天间隔时会**明确告警**，不会静默硬排。

留白日不是偷懒，是给热点让路。填满 30 天等于放弃了这 30 天里的所有意外机会。

## 六、数据不好，怎么问

带上这四个数字再问，否则只能得到"无法定位"：

- 曝光
- 点击（阅读）
- 点赞 / 收藏 / 评论
- 涨粉

还要带上**封面和标题的截图**——不然它没法判断是不是封面问题。

它会做的事：算三个率 → 和你自己最近 10 篇的中位数比（不用行业平均值）→ 从上游往下游找**第一个**断掉的环节 → 只给 **1 个**动作 → 要求写清 48 小时后看哪个数字验证。

为什么要用你自己的中位数：不同类目、不同粉丝量级的基准差几倍，行业均值对单篇没有判断力。

## 七、三个脚本的完整参数

### note_lint.py

```bash
python note_lint.py <文件> [--json 报告.json] [--strict] [--quiet]
```

| 参数 | 说明 |
|---|---|
| `--json FILE` | 输出完整 JSON 报告（含每条命中的证据与改法） |
| `--strict` | 中危项也阻断（默认只有高危阻断） |
| `--quiet` | 只输出一行：`PASS/BLOCKED high=… mid=… low=…` |

退出码：`0` 通过 · `1` 阻断 · `2` 输入错误。

支持两种输入：按 `templates/T4-note-card.md` 结构的笔记卡（推荐），或任意纯文本（会退化为只查正文相关规则）。

### build_calendar.py

```bash
python build_calendar.py <选题.csv> --start YYYY-MM-DD [--per-week 1-7] [--days N] [--out 日历.csv] [--md 日历.md] [--rest-day 0-6]
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--per-week` | 3 | 每周产能 |
| `--days` | 30 | 周期长度 |
| `--rest-day` | 无 | 固定不发的星期（0=周一 … 6=周日） |
| `--md` | 无 | 同时输出 Markdown 表格 |

CSV 至少要有「选题」或「标题」列；可识别「角度 / 骨架 / 素材来源（或素材命中）/ 优先级 / 时段 / 备注」。输出为 UTF-8 BOM，Excel 直接打开不乱码。

### selftest.py

```bash
python selftest.py [--out 测试记录.md]
```

跑 18 项检查：环境、规则表、文件完整性、放行与阻断、异常退出码、排期间隔。你要验证"这东西现在还能不能用"，跑这一条就够。

## 八、常见问题

**它写的东西感觉像广告。**
回看素材三问。三问命中一条以下，写出来必然是广告——不是写法问题，是料的问题。让它先出取材清单。

**标题都不够炸。**
"炸"不是形容词密度。"标题里必须有读者能自己核对的量"这一条守住了，点击率才有基础。让它把 5 个标题里的量逐个标出来，你自己判断哪个是你真有的。

**它不肯写"亲测"。**
因为你没说这东西你真用过。没亲历写亲测属虚假宣传，不是文风问题。你可以给它一个可核实的替代：翻了这个链接下的评论、问了几个用过的朋友——数据真实就行。

**体检报了误判。**
有可能。比如家居内容里"修复旧家具"，会被 K02R（功效类需人工复核）命中。人工复核后放行，并在报告里注明"误判，已复核"。不要因为一次误判就关掉整条规则。

**能不能帮我把笔记发出去。**
不能。不代发布、不养号、不刷量。发布行为代表你的公开身份，必须你自己确认。

**平台为什么给我限流。**
这类问题它会给经验判断和自查动作，不会编造算法内部机制。平台规则以你自己后台的提示为准。
