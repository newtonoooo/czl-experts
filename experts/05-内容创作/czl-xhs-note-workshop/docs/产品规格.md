# 产品规格 · 爆款笔记车间

版本 1.0.0 · 2026-10-27 · 虫志龙

---

## 一、产品定位

**一句话**：把素材变成能直接发布的小红书笔记，并在发布前过两道闸。

**边界**：只做内容制作。不做投放、不做达人合作报价、不做代运营、不代发布。

**不做成什么**：不做"账号运营顾问"。顾问给建议，车间出成品。这个区别决定了所有设计：输出必须是文件、必须有格式、必须能过判定。

---

## 二、目标用户

| 群体 | 具体处境 | 最痛的一点 |
|---|---|---|
| **起号中的个人博主** | 有真实经验或产品，写不出笔记；一周能出 2–3 篇 | 不知道写什么，写了没人点 |
| **小商家 / 品牌执行** | 老板要求"每周发 3 条"，一个人兼着做 | 素材一堆，串不成笔记；怕违规 |
| **内容代运营 / 编导** | 同时带 3–5 个账号 | 量大，质量不稳，交付靠手感 |
| **有一技之长的专业人士** | 医生、教师、设计师、律师的合规内容 | 专业内容写出来像论文，不像笔记 |

**不服务的用户**：要投放方案的人、要刷量的人、要把别人的笔记改写一遍的人。

---

## 三、要解决的问题（按发生频率排）

1. **选题靠灵感**，断更，或写出来的题没人搜。
2. **标题点不开**：给的是品类名，不是让人想点的那句话。
3. **正文像广告**：全是形容词，没有具体物、没有对照、没有代价。
4. **封面在缩略图里看不清**：字太多、太小、没有信息层级。
5. **写了不敢发**：不确定有没有踩违规词、有没有把"听说"写成了"亲测"。
6. **发完不知道好坏**：只有点赞数，不知道是封面问题还是内容问题。
7. **一个人做不到日更**：素材复用没规划，同一条料写两篇就撞车。

---

## 四、输入与输出

### 输入（按提供方式）

| 输入 | 必需性 | 说明 |
|---|---|---|
| 素材原文 | 必需 | 文字、图片描述、聊天记录、链接内容、价格 |
| 主体的身份 | 必需 | 自己的经历 / 自家产品 / 别人的东西 / 一个知识点 |
| 目标 | 建议 | 涨粉 / 带货 / 引流 / 记录 |
| 账号现状 | 建议 | 新号 / 有粉不动 / 稳定产出；粉丝量级 |
| 产能约束 | 建议 | 每周几篇、能否出镜、拍摄条件 |
| 已发布数据 | 复盘时必需 | 曝光、点击、点赞、收藏、评论、涨粉 |

### 输出（按工序）

| 工序 | 输出物 | 形态 |
|---|---|---|
| 收料 | 素材卡 + 缺口清单 | Markdown（T1） |
| 定位 | 定位卡（3 个互斥角） | Markdown（T2） |
| 选题 | 选题矩阵（≥20 行） | CSV（T3） |
| 成稿 | 笔记卡（6 块齐全） | Markdown（T4） |
| 质检 | 通过 / 打回清单 | 文本 + JSON 报告 |
| 排期 | 发布日历 | CSV（T5）+ Markdown |
| 复盘 | 诊断表 + 唯一动作 | Markdown（T6） |

## 五、方法内核

### 五段两闸

```
料 → 角 → 题 → 稿 → 测
        ↑         ↓
     合规闸    人味闸
```

### 四个判断器（可当场使用，不依赖工具）

| 判断器 | 判据 | 不通过怎么办 |
|---|---|---|
| 素材能不能写 | 三问：具体物 / 对照组 / 代价 | 0 问：只出取材清单 |
| 标题有没有自答 | 是否已把结论说进标题 | 重写，改成留空型 |
| 前 3 行值不值得展开 | 是否交出具体承诺 | 换开头：结论/代价/场景 |
| 有没有可回答的问题 | 问题是否指向具体对象 | 换成能被具体回答的问句 |

### 两闸的判据来源

- 合规闸：公开法规的类别归纳 + 平台通行规则，落成 6 组词表
- 人味闸：中文笔记语境的 12 种机器味特征，落成 12 条正则与结构规则

## 六、工具能力

| 能力 | 实现 | 依赖 |
|---|---|---|
| 笔记体检（41 条规则） | `note_lint.py` | 无（标准库） |
| 发布日历（含间隔约束） | `build_calendar.py` | 无（标准库） |
| 整链自测（18 项） | `selftest.py` | 无（标准库） |
| 平台数据获取 | **不提供** | 用户手抄/截图 |
| 笔记发布 | **不提供** | 用户自行发布 |

设计取舍：**宁可少一个自动化，不引入一个不可控的依赖。** 原目标专家依赖的 MCP 服务在未连接时会导致整条链路不可用，这是本产品刻意避开的失败模式。

---

## 七、质量要求

| 维度 | 要求 | 怎么保证 |
|---|---|---|
| 事实 | 稿件里的每个数字都能在素材卡找到出处 | 质检第 2 步逐句核对；脚本查占位符残留 |
| 合规 | 高危项零命中才放行 | 6 组词表 + 明确"给替换写法"而不是"删掉" |
| 人味 | 12 条机器味特征不超标 | 脚本初筛 + 人工逐句过 |
| 可执行 | 用户拿到卡片能直接复制发布 | 正文区不夹批注；六块结构强制齐全 |
| 可判定 | 判断有依据，不是"我觉得" | 41 条规则给出证据句；复盘必须写验证方式 |

---

## 八、速度与稳定性

| 场景 | 指标 | 现状 |
|---|---|---|
| 单篇成稿 | 一轮对话内给出完整笔记卡 | 满足（无外部调用） |
| 批量 5 篇 | 索引 + 5 张卡片 | 满足，受模型上下文限制，建议一次不超过 8 篇 |
| 体检 1 篇 | < 1 秒 | 满足（本地脚本） |
| 排期 30 天 | < 1 秒 | 满足 |
| 断网可用 | 全部工序可跑（除模型本身） | 满足，脚本零外部依赖 |

---

## 九、与原目标专家的差异

详见 `开发记录.md` 第一节。核心差异三句：

1. 它依赖外部 MCP 才能动手，**本产品零外部依赖**。
2. 它的质检是文字建议，**本产品有可复现的 41 条判定**。
3. 它的复盘给 KPI 目标值，**本产品用账号自身中位数做基线、定位断点、只给一个动作**。

---

## 十、范围外（明确不做）

- 投放计划、信息流出价、达人报价与议价
- 账号代运营、养号、刷量、批量搬运
- 代发布（涉及用户公开身份，必须用户自己确认）
- 医疗诊断、投资建议、未成年人带货
- 平台算法内部机制的推测与"内部规则"披露
