## 一、安装

### 方式 A：导入压缩包（推荐给分发场景）

1. 拿到 `czl-uae-public-affairs-pro.zip`。
2. 打开 WorkBuddy → 「专家」→「我的专家」→ 右上角「导入专家」。
3. 选择 zip，确认后即可在列表看到「阿联酋公共事务权威顾问」。

> 压缩包内已确保顶层目录唯一（`czl-uae-public-affairs-pro/`），导入后不会出现双层目录。

### 方式 B：直接放目录（推荐给自用与调试）

把整个 `czl-uae-public-affairs-pro/` 目录放到：

```
~/.workbuddy-ai/plugins/marketplaces/my-experts/plugins/
```

Windows 实际路径：
```
C:\Users\<用户名>\.workbuddy-ai\plugins\marketplaces\my-experts\plugins\
```

放好后重启客户端。

### 方式 C：重新注册（改了内容之后）

```bash
python <expert-manager>/scripts/validate_expert.py <专家目录>
python <expert-manager>/scripts/register_expert.py <专家目录>
```

## 二、第一次对话

选中专家后，直接说你的处境，不用写得很规整。三种典型开场：

**1）选址类**
> 我们要在阿联酋设区域总部，做储能系统集成，团队 30 人，2027 年 Q1 前落地，帮我看看放哪个酋长国。

专家会先给「任务简报卡」，列出已确认信息与缺口（如主体类型、是否有敏感面、交付形态），一次问完，然后走 W0→W1→W2→W3→W5。

**2）政策类**
> 阿联酋最近对 XX 出了新规，我们还按原计划进口会不会有问题？

走 W0→W1→W5，输出规则清单（含主管机构与来源等级）+ 影响判断 + 风险分。

**3）舆情类**
> 有人在 Instagram 上说我们的工地欠薪，已经被本地媒体转发了。

直接进 W6，输出分级（T0–T3）、0–6 小时动作表、三段式声明（中英）、监管是否报备的建议。

## 三、怎么让它输出得更准

| 你想得到 | 你就这样说 |
|---|---|
| 一页纸给老板 | "给我一页纸，老板要看" |
| 上会用 | "要上投委会，给我决策备忘，含方案对比和风险分" |
| 监管回函 | "监管来函了，帮我起个回函框架"（附上来函要点） |
| 只要结论 | "直接说结论，别写背景" |
| 要英文对外件 | "对外版本要英文，内部说明用中文" |
| 换权重算风险 | "按政府采购场景重新打分"（会切到 `gov-contract` 预设） |

**会显著提高质量的三个信息**：目标酋长国（或"未定"）、业务动作的具体形态、是否有敏感面（政府股东、制裁名单、负面舆情）。

## 四、输出怎么读

标准作业模式的六段，各有用途：

| 段落 | 你该怎么用 |
|---|---|
| 【结论】 | 直接抄进汇报的第一页 |
| 【关键判断】 | 每条后面括号里是来源等级，A/B 可直接用，C 要补证，D 是推断 |
| 【酋长国分列】 | 拿去做选址会的对比表；"待核实"的格子就是你的尽调清单 |
| 【行动清单】 | 直接变成项目计划，责任方与时点已经写好 |
| 【风险与红线】 | 分数≥65 时会附停止条件，这是给决策层的"刹车" |
| 【信息截止日】 | 三条待复核项就是下次更新前必须确认的事 |

## 五、常见问题

### Q1：选中专家后，小图标没了，显示成一个字？

这是客户端的**头像回退机制**：当 `avatar` 指向的图片无法被解析时，界面会退化成显示名称首字。本产品已在打包环节做了三重防护：

1. `avatar` 写作 `./avatars/expert.png`（带 `./`，避免相对路径歧义）；
2. 打包脚本强制 zip **顶层目录唯一且等于 `plugin.name`**；
3. 打包后自动**回读验证**头像条目可被命中。

自检命令：

```bash
python tools/build_package.py verify ./dist/czl-uae-public-affairs-pro.zip
```

若你手上的旧包出现该问题，按顺序排查：

| 排查项 | 检查方法 | 修复 |
|---|---|---|
| 双层嵌套目录 | 解压后是否看到 `czl-uae-public-affairs-pro/czl-uae-public-affairs-pro/` | 删除外层，只保留一层 |
| 头像文件缺失 | `avatars/expert.png` 是否存在 | 从 zip 重新解压完整包 |
| 头像过大 | 文件是否 > 500KB | 压缩到 512×512、≤500KB |
| 路径写法 | `plugin.json` 的 `avatar` 是否为 `avatars/expert.png` 或 `./avatars/expert.png` | 改为带 `./` 的形式 |
| 客户端缓存 | 换版本号后重启客户端 | 修改 `version` 后重新导入 |

### Q2：为什么它总说"待核实"？

因为阿联酋法规与费率变动快，产品策略是**不编数字**。给"待核实"是为了让你去拿书面依据，而不是给你一个看起来很专业的错数。

### Q3：它能直接帮我写回函发给监管机构吗？

能起草框架与中英文版本，但**不能直接发**。回函必须经：法务复核 → 阿语母语终校 → 授权签署人签字 → 留档。

### Q4：能查具体某位官员的联系方式吗？

不能。只给机构与公开渠道。这是产品的硬边界。

### Q5：政策变了怎么更新？

改 `skills/czl-uae-pa-toolkit/references/` 里对应手册，**不用改提示词结构**。改完把 `plugin.json` 的 `version` 升一位，重新 `validate` → `register` → `build`。

## 六、维护手册（给开发者自己）

```bash
# 1. 改内容（提示词 / 手册 / 模板 / 脚本）
# 2. 结构体检
python tools/build_package.py check .

# 3. 官方校验（需先把目录放到 my-experts/plugins 下）
python validate_expert.py <专家目录>

# 4. 重新注册
python register_expert.py <专家目录>

# 5. 打包 + 回读验证
python tools/build_package.py build . ./dist

# 6. 更新 CHANGELOG.md 与 plugin.json 的 version
```

**版本号规则**：改错别字/措辞 → PATCH；加手册/加模板/加脚本 → MINOR；改工作流结构或删功能 → MAJOR。

## 七、边界提醒（请在使用前读一遍）

1. 输出是**公共事务咨询建议**，不是法律意见。
2. 审批结果不做任何承诺，只给概率性判断与备选路径。
3. 涉及政府机构署名、联合发布、官方标识使用，必须先取得书面许可。
4. 对外件涉及阿语发布时，务必由母语者终校。
5. 涉及制裁、出口管制、反腐败的结论，必须另行完成名单筛查与内部合规审批。
