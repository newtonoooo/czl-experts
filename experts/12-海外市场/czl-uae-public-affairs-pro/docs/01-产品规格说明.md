## 一、需求从哪里来

### 1.1 目标用户

| 用户 | 规模/形态 | 真实处境 |
|---|---|---|
| 拟落地阿联酋的中资企业 | 制造、贸易、新能源、科技，50–5000 人 | 有海外扩张决策，但缺本地政府事务能力，靠中介口头信息做判断 |
| 已落地企业的政府事务/法务负责人 | 1–3 人小团队 | 同时对接多个酋长国多个机构，缺结构化作业方法 |
| 投资机构与家族办公室 | 跨境配置 | 需要政策连续性与合规风险的快速量化判断 |
| 跨境品牌与市场团队 | 电商、消费品 | 内容能不能发、代言能不能用，靠猜 |
| 央国企与工程承包商 | 投标主体 | 本地化含量、反腐败合规、PPP 规则复杂 |

### 1.2 他们要解决的问题（按频次）

1. **"这事归谁管"**——机构名称对不上、联邦/酋长国/自由区三层分不清。
2. **"在哪个酋长国做"**——只听到"迪拜"和"阿布扎比"，不知道还有五个酋长国各有独立政策。
3. **"要多久、卡在哪"**——没有决策路径，不知道先找谁后找谁。
4. **"这话能不能说"**——宗教、政治、劳工、主权表述的红线不熟，一次失误代价很高。
5. **"风险到底多大"**——只有定性描述，上不了会、排不了序。
6. **"出了事怎么办"**——舆情来了没有节奏表，第一份声明写错就收不回来。

### 1.3 现有做法的不足（产品机会）

| 现有做法 | 不足 | 本产品的处理 |
|---|---|---|
| 通用大模型直接问 | 把阿联酋当整体，忽略酋长国差异；给不出机构与路径；数字张口就来 | 强制七酋长国分列 + 三层机构定位 + 数字带口径 |
| 中介/代理口头咨询 | 信息不可核、无留痕、利益相关 | 四级来源标注 + 交付物留痕 |
| 律所意见 | 准确但慢、贵，且只回答法律问题不回答公共事务问题 | 定位为"律所之前的第一层作业"，明确不替代法律意见 |
| 法规知识库类工具 | 给条文，不给判断与路径 | 给方法论、矩阵、路径、模板与打分 |

## 二、产品定义

**一句话**：把一件阿联酋公共事务的模糊需求，在**一次对话内**压成"结论 + 依据 + 酋长国分列 + 行动清单 + 风险分 + 红线"六件套。

**不做**：法律意见书、审批结果承诺、规避监管方案、内政与皇室评价、具体官员个人联系方式。

## 三、功能需求（FR）

| 编号 | 功能 | 说明 | 验收标准 |
|---|---|---|---|
| FR-1 | 任务受理与缺口识别 | 12 项简报字段，按必问/可推/可略分级，一次问全 | 缺失必问项时输出缺口清单与假设声明 |
| FR-2 | 监管域定位 | 把业务动作翻译成 12 个监管域之一或多个，定位联邦/酋长国/自由区三层机构 | 每个域给出机构、规则方向、所需动作 |
| FR-3 | 七酋长国分层评估 | 8 维矩阵 + 按业务动作加权 + 推荐序 + 取舍 | 至少阿布扎比与迪拜两列；不确定填"待核实" |
| FR-4 | 决策路径映射 | 审批层/影响层/监督层三层链 + 推进表 + 反腐败检查 | 输出顺序、渠道、时点、成功信号 |
| FR-5 | 沟通红线校验 | 14 项体检 + 违规表达改写对照 | 任一项"禁止"未清除则不得输出"可发布" |
| FR-6 | 风险量化 | 五维打分 0–100 + 等级 + 主导维度 + 缓释动作 | 高分（≥65）必须附停止条件与升级路径 |
| FR-7 | 交付物装配 | 一页纸/决策备忘/回函框架/危机声明 | 形态与用户诉求匹配，篇幅符合上限 |
| FR-8 | 危机快车道 | 分级 T0–T3 + 0–6h/6–24h/24–72h 动作表 | T0/T1 必须建议引入本地持牌律师与专业公关 |
| FR-9 | 来源与时效标注 | 四级来源 + 日期 + 待核实项 | 每条关键判断带来源等级；D 级标注"推断" |
| FR-10 | 自检闸门 | Q1–Q4 四道闸门 | 输出前逐项过闸 |

## 四、输入 / 输出规范

### 4.1 输入

**最小可用输入**（能给出有价值回答的下限）：
```
行业 + 业务动作 + 目标酋长国（可"未定"）+ 是否有敏感面
```

**完整输入**（12 项，见 `skills/czl-uae-pa-toolkit/scripts/brief_check.py`）：
主体类型、行业与产品、目标酋长国、业务动作、时间窗、已有资质、涉及监管域、敏感面、交付形态、语言、保密级别、决策人。

### 4.2 输出

三种模式：

| 模式 | 触发 | 长度 | 结构 |
|---|---|---|---|
| 速答 | 单点问题 | ≤1 屏 | 结论 → 3–5 条关键判断（带依据）→ 下一步 |
| 作业 | "方案/报告/评估" | 1–3 页 | 结论 / 关键判断 / 酋长国分列 / 行动清单 / 风险与红线 / 信息截止日 |
| 交付物 | "上会/发声明/回函" | 按模板上限 | 调用 `templates/` |

**强制尾栏**：信息截止日 + 三条待复核项 + 合规声明。

## 五、通用处理步骤（与工作流对应）

```
受理(W0) → 情报(W1) → 分列(W2) → 路径(W3) → 沟通(W4) → 量化与装配(W5)
                    ↘ 危机时：直接进 W6，24h 内补 W1/W4
```

每一步都有：输入参数、执行步骤、判断条件（G0–G6）、输出格式、异常处理、依赖关系，详见 `agents/czl-uae-public-affairs-pro.md` 第五节。

## 六、工具能力与技术接口

| 能力 | 实现 | 依赖 |
|---|---|---|
| 结构化推理与写作 | 主 Agent 提示词（7 工作流 + 4 闸门 + 异常表） | 无外部依赖 |
| 方法论与矩阵 | 7 份 reference 手册 | 无 |

## 七、质量 / 速度 / 稳定性要求

| 维度 | 要求 | 落地手段 |
|---|---|---|
| 质量 | 每条关键判断可追溯到来源等级；数字必须带口径；涉及选址必须分列酋长国 | Q1–Q4 闸门 + 输出模板固定尾栏 |
| 一致性 | 同一问题多次回答结构一致、结论方向不漂移 | 固定工作流与模板，不自由发挥结构 |
| 速度 | 速答模式一次响应完成；作业模式不额外追问超过 1 轮 | W0 一次问全；缺 3 项以上先带假设作答 |
| 稳定性 | 信息缺失、规则查不到、用户要求违规时都有明确降级路径 | 异常处理总表（8 类） |
| 可维护 | 法规更新只需改 reference，不改提示词结构 | 方法论与事实分离：手册写方法，事实标注"待核实" |

## 八、与"同类产品"的定位差异

| 维度 | 常见做法 | 本产品 |
|---|---|---|
| 地理颗粒度 | "阿联酋" | 七酋长国 + 同国四层辖区 |
| 输出形态 | 分析文章 | 可上会的作业件（含行动项与验收标准） |
| 风险表达 | 定性（高/中/低） | 五维打分 + 主导维度 + 缓释动作的分数变化 |
| 来源 | 不标注或笼统"据公开资料" | 四级来源 + 日期 + 待核实项 |
| 合规边界 | 模糊 | 明确拒绝清单（规避监管、内政评价、个人联系方式） |
| 时效处理 | 隐含假设最新 | 每份输出固定"信息截止日 + 三条待复核" |

## 九、不适用范围

1. 需要出具法律意见、税务意见、审计意见的正式场合。
2. 需要代理申报、代为沟通的委托事项。
3. 需要实时行情、实时政策推送的场景（本产品不含数据订阅）。
4. 阿联酋以外的国别事务（另有对应产品）。
