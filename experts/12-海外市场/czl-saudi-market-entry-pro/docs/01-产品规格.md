## 1. 目标用户

| 用户 | 处境 | 最急的问题 |
|---|---|---|
| 中国制造商的产品/海外负责人 | 产品有竞争力，沙特零基础 | 要不要设公司、先找谁、要花多少钱 |
| 贸易公司与品牌方 | 有零散询盘，不敢承诺 | 认证怎么过、回款怎么保、代理能不能签 |
| 工程与系统集成商 | 想投政府与总包项目 | 资格够不够、缺什么、多久能补上 |
| 投资与投后团队 | 看项目要判断准入是否成立 | 股权结构与许可路径是否可行 |
| 已落地企业的属地负责人 | 公司开了但业务没起来 | 沙特化、投标资格、渠道效率 |

## 2. 使用场景

1. **首次进入评估**：从零判断这个品类能不能进、以什么结构进。
2. **渠道决策**：三家代理候选，需要统一标准打分并指出不能签的那家。
3. **路径比选**：独资 vs 合资 vs 代理，需要一个能向老板交代的三年账。
4. **投标资格判断**：某个 Etimad 项目该不该投，缺口多久能补。
5. **落地排期**：把决定变成带责任人与有效商务周的时间表。
6. **风险复核**：已有计划，需要有人指出哪一步会死、止损线在哪。

## 3. 要解决的问题（按优先级）

1. **判定缺失**：大量方案停在「沙特机会很大」，没有 GO / NO-GO 结论。
2. **口径混乱**：成本、税负、周期各说各话，无法比较。
3. **伙伴误判**：凭印象签约，独家条款无业绩约束，第一年就被绑死。
4. **时间失真**：按中国节奏排期，忽略斋月、节日、夏季与决策链。
5. **合规盲区**：认证、沙特化、发票在签约后才发现，代价最高。
6. **风险无止损**：知道有风险，但没写触发条件与退出动作。

## 4. 必要输入

**最小输入集（缺则只问 3 个问题）**

| 输入 | 用途 | 缺失后果 |
|---|---|---|
| 产品/服务描述 | 定活动代码与监管线 | 无法判定准入 |
| 买方类型 | 决定资格与路径 | 路径比选失真 |
| 进入意图（出口/代理/设点/设厂/合资） | 决定 G2 候选集 | 只能给全路径对比 |
| 股权意向 | 判定结构是否成立 | 无法判定 |
| 预算量级与首单时间窗 | 约束方案可行性 | 三年账无法收敛 |

**进阶输入（有则显著提升质量）**

现有客户与伙伴、已持证照、产品认证状态、目标客户名单、竞品与中标记录、可接受账期、决策链信息。

## 5. 预期输出

| 层级 | 产物 | 形态 |
|---|---|---|
| 即时 | 一页作战简报（结论 / 判定 / 关键数字 / 下一步三件事 / 待核实 / 风险） | Markdown |
| 阶段 | 立案卡、准入判定书、路径决策备忘、伙伴评分卡、投标资格核对表、落地清单 + 风险台账 | Markdown 表格 |
| 计算 | 准入规则结果、三年账、评分与排序 | JSON / Markdown 表格 |

## 6. 通用处理步骤

```
G0 立案 → G1 准入 → G2 路径 → G3 渠道 → G4 投标 → G5 落地与风险
   ↓ 任一闸门 BLOCKED：停止推进，只给替代路径
   ↓ 任一闸门 CONDITIONAL：列前置条件（谁/向谁/交什么/多久），可带条件进入下一门
```

每门的通用内部步骤：收料 → 判定 → 出产物 → 标注待核实 → 记录假设。

## 7. 工具与技术接口

| 能力 | 实现 | 依赖 |
|---|---|---|
| 准入规则匹配 | `entry_gate.py`（9 类规则，可替换敏感清单） | 标准库 |

无 MCP、无外部 API、无登录、无数据库。离线可用。

## 8. 质量、速度、稳定性要求

| 维度 | 要求 | 当前实现 |
|---|---|---|
| 质量 | 每个结论可追溯到依据；数字三态（有来源/区间估计/待核实） | 写入人设「数字纪律」章节，作为硬约束 |
| 质量 | 阻断结论必须给替代路径，不能只说不行 | G1/G2/G4 均定义「不通过怎么办」 |
| 速度 | 首次响应不问超过 3 个问题；常规咨询一屏内给结论 | 开场行为与默认输出规范固定 |
| 稳定性 | 脚本在任何输入下不崩溃，非法输入返回结构化错误 | 全部参数做区间校验，异常统一捕获 |
| 可维护 | 卡片与脚本解耦，政策变化只改卡片 | references 与 scripts 分离 |
