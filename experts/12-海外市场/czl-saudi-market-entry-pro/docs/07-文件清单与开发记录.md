## 三、关键设计决策

### D1 用闸门制替代能力清单

原产品是「七项能力 + 四步流程」，能力之间没有强制顺序。本产品改为六道闸门，每门必须有判定与产物，`BLOCKED` 不得纵向推进。

**理由**：沙特市场的高频失败是「准入没解决就谈渠道」，能力清单结构无法阻止这种跳步。

### D2 三态判定（GO / CONDITIONAL / BLOCKED）

不采用「可行 / 不可行」二态。**理由**：真实业务中大多数情况是「有条件可行」，二态会逼迫顾问给出过度确定的结论。

### D3 不使用任何第三方语料库

原产品自带 91 个语料文件并指向外部存储桶。本产品完全不引用，改为 9 张自写判定卡片 + 官方核对路径。

**理由**：语料的汇编权利状态不明，且静态语料会过期。改为「维度 + 核对路径」更可持续，也避免版权风险。

### D4 名称用「旗舰版」而非「最强」

需求建议使用「最强」类形容词。未采用，改用「旗舰版」。

**理由**：《广告法》禁止绝对化用语；「最强」不可举证，商业宣传中有处罚风险。已在 `docs/06` R-03 说明，并给出可举证的替代方案。

### D5 脚本零依赖

五个脚本只用 Python 标准库。

**理由**：专家包会被分发到未知环境，任何 pip 依赖都会变成安装失败点。实测在 Python 3.13 下 43 条断言全部通过。

### D6 头像风格

三十岁上下、无胡须、细框眼镜、炭灰西装、金色胸针、琥珀金几何底纹。

**理由**：需求要求「干练、专业、不要像老登」；同时要与同类产品的头像（蓄须、领带、手持平板、暖黄背景）形成明显区分。

**处理**：原始生成图右下角带平台水印，已用纯 Python PNG 工具裁切 150px 并中心裁方后缩放至 512，水印无残留（已目视复核）。

### D7 安装通道写进文档

`docs/03` 与 `README.md` 均明确要求安装到 `my-experts` 通道。

**理由**：官方市场通道会把相对头像路径拼成 CDN 地址并 404，这是实测结论，不写进文档用户必然踩坑。
