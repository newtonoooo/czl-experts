# 使用说明

## 一、安装

### 方式 A：导入 zip（推荐）

1. 打开 WorkBuddy → 左侧「专家」→「我的专家」；
2. 点「导入专家」，选择 `czl-saudi-market-entry-pro.zip`；
3. 导入完成后重启客户端，在「我的专家」中可见。

### 方式 B：手动放置

把解压后的目录整体放到：

```
<配置目录>/plugins/marketplaces/my-experts/plugins/czl-saudi-market-entry-pro/
```

Windows 下配置目录通常为 `C:\Users\<用户名>\.workbuddy-ai`（旧版本为 `.workbuddy`）。放好后重启客户端。

### 不要放进官方市场目录

不要放到 `plugins/marketplaces/experts/plugins/` 下。原因见第四节。

## 二、怎么用

### 1. 第一次对话

直接说清楚三件事即可，不需要准备材料：

> 我们做工业自动化设备，想卖给沙特的工厂和部委项目，目前没有本地客户，预算 100 万人民币级别，希望明年上半年有第一单。

专家会先给你一页作战简报，然后按闸门推进。**它不会一次问十个问题**，最多问三个。

### 2. 常见用法

| 你想做的事 | 怎么说 |
|---|---|
| 判断能不能进 | 「帮我判定这个品类在沙特的准入，需要哪些许可」 |
| 选路径 | 「比较独资、代理、合资三条路，给我一个推荐」 |
| 筛代理 | 「这三个代理商候选帮我打分，指出哪家不能签」 |
| 判投标 | 「这个 Etimad 项目我该不该投，缺什么资格」 |
| 排落地 | 「把方案排成时间表，标出哪些周不会有进展」 |
| 查风险 | 「帮我找这个计划最可能死在哪一步」 |

### 3. 要它出文件

默认给一页简报。需要正式交付物时说：

> 出一份准入判定书 / 路径决策备忘 / 伙伴评分卡 / 落地清单和风险台账

会按 `skills/saudi-entry-playbook/templates/` 的结构输出，可直接贴进周报或投资备忘录。

### 4. 用脚本自己算

脚本可以脱离对话单独运行，方便你把参数换成自己的：

```bash
cd skills/saudi-entry-playbook/scripts

# 准入判定（先复制 fixtures 里的样例改成自己的）
python entry_gate.py --input fixtures/entry_gate_case.json --format md

# 三年账
python route_cost.py --input fixtures/route_cost_case.json --format md

# 伙伴评分
python partner_score.py --input fixtures/partner_score_case.json --format md

# 商机排序
python pipeline_rank.py --input fixtures/pipeline_case.json --format md

# 自检
python selftest.py
```

脚本输出 JSON 或 Markdown，可直接粘进报告。参数含义见各脚本头部注释与 `--help`。

## 三、读结果时注意什么

1. **`待核实` 不是废话，是提示你去核对**。沙特政策更新快，凡是标了这个标签的，签约前必须确认。
2. **`CONDITIONAL` 是常态**，不是坏消息。它意味着路径存在，但有前置条件；条件清单就是你的待办。
3. **`BLOCKED` 时不要绕过**。换路径、换品类、换结构，不要试图用关系解决结构问题。
4. **评分不能覆盖否决**。红旗项触发时，分数再高也是 D。
5. **时间表按有效商务周看**，不是按日历周。斋月、两个节日、夏季各扣一段。

## 四、头像为什么显示成文字（故障说明）

### 现象

把专家包导入到新的 WorkBuddy 后，在专家列表或对话头部，小图标没有显示，变成了专家名称的第一个字。

### 原因（已实测确认）

WorkBuddy 有两条加载专家的通道，头像解析方式不同：

| 通道 | 目录 | 头像解析 |
|---|---|---|
| 我的专家（my-experts） | `plugins/marketplaces/my-experts/plugins/` | 从本地读取 `plugin.json` 的 `avatar` 路径，文件存在且 ≤5MB 就内联显示 |
| 官方市场（experts） | `plugins/marketplaces/experts/plugins/` | 把 `avatar` 当成 **CDN 相对路径**，拼成 `https://acc-1258344699.cos.accelerate.myqcloud.com/workbuddy/expert-marketplace/<avatar>` |

官方市场的 429 个专家，头像在清单里一律写成 `/avatars/<专家ID>.png`，由 CDN 托管。而本地开发的包写的是 `avatars/expert.png`，拼出来的地址是：

```
https://acc-1258344699.cos.accelerate.myqcloud.com/workbuddy/expert-marketplace/avatars/expert.png
```

该地址**返回 404**（已用 HTTP 请求验证）。取不到图，界面就回退显示名称首字——也就是你看到的「成字」。

所以问题不在图片本身：这个包的头像是 512×512、PNG、368KB，完全符合规范。

### 三种解法

**解法 1（推荐）：装到「我的专家」通道**
按第一节方式 A 导入，不要手动放进 `marketplaces/experts/`。这是本地开发包的正确通道。

**解法 2：把头像内联进 plugin.json**
用 `tools/make_inline_avatar.py` 生成 data URI 版本，替换 `plugin.json` 的 `avatar` 字段。data URI 不参与路径拼接，两条通道都能显示：

```bash
python tools/make_inline_avatar.py --avatar avatars/expert.png --size 256
# 输出可直接粘贴的 JSON 片段，替换 plugin.json 中 "avatar" 的值
```

代价是 `plugin.json` 变大（256px 版本约 80–120KB 文本），且部分平台的包体检查可能不欢迎内联大字段，上架官方市场前建议改回相对路径。

**解法 3：走官方市场上架流程**
如果最终要上架官方市场，头像需要按平台流程上传到 CDN，并在市场清单中登记为 `/avatars/<你的专家ID>.png`。这一步在提审环节完成，不由包内文件决定。

### 自查清单

- [ ] 目录在 `my-experts/plugins/` 下，不是 `experts/plugins/` 下
- [ ] `plugin.json` 的 `avatar` 指向的文件真实存在，大小写一致
- [ ] 图片为 PNG/JPG，≤5MB（平台规范建议 ≤500KB）
- [ ] 路径没有 `../`（越界会被判空）
- [ ] 改完后重启客户端（有 DTO 缓存）

## 五、卸载与更新

- **卸载**：在「我的专家」中删除，或直接删除该目录后重启。
- **更新**：覆盖目录后重启；版本变化见 `CHANGELOG.md`。
- **自定义**：可以改 `agents/saudi-market-entry-pro.md` 的语气与闸门，但不要改 `plugin.json` 的 `name`、`agentName` 与文件名——它们是唯一标识，改了专家会丢失。
