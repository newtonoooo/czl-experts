# 工作流说明

本文逐门说明六道工作流：名称、职责、输入、步骤、判断条件、输出、异常处理、依赖与上下游关系。

---

## G0 立案

| 项 | 内容 |
|---|---|
| **名称** | 立案（Case Intake） |
| **职责** | 把模糊诉求压缩成可判定的立案卡，固定边界与成功标准 |
| **输入** | 产品/服务、买方类型、进入意图、股权意向、预算、时间窗、已有资源 |
| **步骤** | ① 抽取六要素 ② 识别缺口 ③ 只问最关键的 3 个问题 ④ 固化显式假设 ⑤ 出卡 |
| **判断条件** | 六要素齐 → 立案；缺 1–3 项 → 问一轮后按假设推进；缺产品与买方类型 → 拒绝判定，给补料清单 |
| **输出** | `templates/01-intake-card.md` 填好的立案卡 |
| **异常** | 用户拒绝提供预算 → 用区间并标注「客户未确认」；用户只想要结论 → 给一页简报并声明假设风险 |
| **依赖** | 无 |
| **下游** | G1 准入 |

---

## G1 准入闸门

| 项 | 内容 |
|---|---|
| **名称** | 准入判定（Entry Gate） |
| **职责** | 判断能否做、以什么条件做；三条线并行（外资准入 / 行业许可 / 产品准入） |
| **输入** | 立案卡 + 活动代码、股权比例、是否本地伙伴、所需与已持许可、是否面向政府、是否进口、是否受管制产品、是否雇工、是否特区/RHQ |
| **步骤** | ① 跑 `entry_gate.py` ② 对照 `references/01-entry-gate.md` 复核三线 ③ 标注待核实 ④ 出判定书 |
| **判断条件** | 无阻断且无前置条件 → `GO`；有前置条件 → `CONDITIONAL`；有结构性阻断 → `BLOCKED` |
| **输出** | `templates/02-entry-verdict.md` + 脚本 JSON |
| **异常** | 活动代码缺失 → 阻断并要求补全；股权比例越界 → 阻断；清单可能过期 → 强制标注检索日期 |
| **依赖** | `entry_gate.py`、`references/01`、`references/06` |
| **下游** | `GO`/`CONDITIONAL` → G2；`BLOCKED` → 只给替代路径，终止主线 |

**硬规则**：`BLOCKED` 时不得输出渠道方案。这是本产品与原同类产品最容易拉开差距的一条——很多人会在准入没解决时就开始谈代理。

---

## G2 路径闸门

| 项 | 内容 |
|---|---|
| **名称** | 路径比选（Entity & Route） |
| **职责** | 在六条路径中给出唯一推荐 + 一个备选 + 明确的放弃理由 |
| **输入** | G1 结论、买方类型、资产需求（工厂/仓库/实验室）、时间窗、控制权敏感项、各路径成本参数 |
| **步骤** | ① 用 G1 结论砍掉不可行路径 ② 按买方/资产/时间/控制权四问收敛 ③ 跑 `route_cost.py` ④ 写放弃项 ⑤ 出备忘 |
| **判断条件** | 推荐必须同时满足：准入可行、时间窗可行、控制权可接受；三者有一项不满足 → 换路径或改时间窗 |
| **输出** | 路径决策备忘（推荐/备选/三年账/放弃项） |
| **异常** | 参数缺失 → 给区间与敏感性，不用点值伪装确定性；用户坚持不可行路径 → 书面写出风险与放弃条件 |
| **依赖** | `route_cost.py`、`references/03`、`references/05` |
| **下游** | G3 渠道（若走代理/合资）或 G4 投标（若走实体直投） |

---

## G3 渠道与伙伴闸门

| 项 | 内容 |
|---|---|
| **名称** | 渠道与伙伴（Channel & Partner） |
| **职责** | 建长名单、统一标准评分、识别不能签的那家、准备尽调与谈判 |
| **输入** | 目标客户画像、候选伙伴信息、八维评分、红旗项 |
| **步骤** | ① 按来源地图建 ≥6 家长名单 ② 收敛到 ≥3 家 ③ 跑 `partner_score.py` ④ 红旗否决 ⑤ 尽调清单 ⑥ 谈判要点（先谈退出） |
| **判断条件** | ≥80 → A 可签；65–79 → B 有条件；50–64 → C 观察；<50 → D 不可签；红旗 → 直接 D |
| **输出** | `templates/03-partner-scorecard.md` + 脚本结果 |
| **异常** | 候选 <3 家 → 只出「候选来源地图」，不硬凑评分；信息不足 → 标 `待核实` 并在尽调清单里列为缺口 |
| **依赖** | `partner_score.py`、`references/07`、`references/08` |
| **下游** | G5 落地（签约与考核机制） |

---

## G4 商机与投标闸门

| 项 | 内容 |
|---|---|
| **名称** | 投标适配（Tender Fit） |
| **职责** | 判断该不该投、缺什么资格、在手商机怎么排 |
| **输入** | 招标公告要点、主体资格状态、专业资格、保函能力、商机清单（金额/毛利/胜率/周期/可及性/匹配度/竞争） |
| **步骤** | ① 对照 `references/04` 逐项打勾 ② 跑 `pipeline_rank.py` 排序 ③ 缺口与补齐时间 ④ 出结论 |
| **判断条件** | 资格齐备 → 可投；缺口可在窗口内补齐 → 补格后可投；无法补齐 → 不投 |
| **输出** | 投标资格核对表 + 商机优先级表 |
| **异常** | 招标文件未拿到 → 只给通用资格框架，不出结论；技术规格指向特定厂商 → 建议不投并说明 |
| **依赖** | `pipeline_rank.py`、`references/04` |
| **下游** | G5 落地（中标后的履约准备） |

**注意**：「不投」是合法且常见的交付结论。劝退比陪跑一次废标更有价值。

---

## G5 落地与风险闸门

| 项 | 内容 |
|---|---|
| **名称** | 落地与风险（Mobilization & Exit） |
| **职责** | 把决定变成带责任人、带有效商务周的时间表；把风险变成带止损线的台账 |
| **输入** | 前五门结论、编制计划、许可与认证计划、预算、账期、伙伴条款 |
| **步骤** | ① 步骤链（许可→注册→开户→用工→税务→认证→首单） ② 有效商务周折算 ③ 沙特化编制表 ④ 风险台账 ⑤ 退出预案 ⑥ 90 天检查点 |
| **判断条件** | 关键风险无止损线 → 暂缓；关键岗位无到岗计划 → 带条件启动；其余 → 可启动 |
| **输出** | `templates/04-mobilization-checklist.md` |
| **异常** | 时间窗过紧 → 给并行方案（如代理先拿单 + 实体并行设立）；预算不足 → 缩小首期范围，不虚报可行性 |
| **依赖** | `references/02`、`05`、`06`、`08`、`09` |
| **下游** | 无（闭环），可回流至 G3/G4 做季度复核 |

## 工作流之间的关系

```
            ┌──────────── G0 立案 ────────────┐
            │                                  │
            ▼                                  │
        G1 准入 ──BLOCKED──► 替代路径（回到 G2 的候选集重排）
            │ GO / CONDITIONAL
            ▼
        G2 路径 ──► 代理/合资 ──► G3 渠道 ──┐
            │                              │
            └──► 实体直投 ──► G4 投标 ─────┤
                                           ▼
                                       G5 落地与风险
                                           │
                                           └──► 季度复核回流 G3/G4
```

**三条编排铁律**

1. 上一门无结论，不进入下一门。
2. `BLOCKED` 只允许横向移动（换路径），不允许纵向推进。
3. 每个交付物必须能被下一门直接引用，不允许「另行整理」。
