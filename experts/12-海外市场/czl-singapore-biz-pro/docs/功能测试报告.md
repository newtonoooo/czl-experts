## 一、专项：专家图标不显示（显示为文字）的原因定位

### 1.1 平台的两条解析路径（读自应用主程序）

| 场景 | 函数 | 行为 |
|------|------|------|
| 本地已安装专家 | `resolveAvatarUrl(avatar, expertRootDir)` | 拼接 `root + avatar` → 若越出根目录 / 文件不存在 / 文件 > 5,242,880 字节 → 返回空字符串 |
| zip 导入预览 | `resolveAvatarFromExpertZip(zip, rootDir, avatar)` | 取 `rootDir + "/" + avatar` 与 `avatar` 两个候选，在 zip 条目中做**精确字符串匹配**；命中则转 base64 data URI，未命中则**原样返回相对路径** |

两条路径任一返回空或无效路径，前端就回退为首字文字头像——即"小图标没了、变成字"。

### 1.2 五个真实成因（按出现概率排序）

| # | 成因 | 为什么难发现 |
|---|------|-------------|
| 1 | `avatar` 路径大小写与文件实际名不一致（如 `avatars/Expert.png` vs `expert.png`） | Windows 文件系统大小写不敏感，本地开发正常；zip 条目匹配区分大小写，换机导入即失败 |
| 2 | `plugin.json` 未写 `avatar` 字段或值为空 | 本地无报错，界面直接显示文字 |
| 3 | 路径含反斜杠（`avatars\expert.png`）或用 `Path` 拼接后打包 | 在 Windows 上用 `str(Path(a)/b)` 生成 zip 条目名会写成反斜杠，条目匹配失败 |
| 4 | 头像文件没被打进 zip | 被打包工具忽略、或位于平台跳过的目录（`cache`/`tmp`/`logs`/`storage`/`temp`）、或扩展名为 `.tmp`/`.zip`/`.log` |
| 5 | 头像超 5MB 或文件损坏（改扩展名、0 字节、非真实图片） | 界面无提示，仅日志有 `avatar file is too large` |

### 1.3 本包的处置

| 措施 | 实现位置 |
|------|---------|
| 路径统一小写、正斜杠、相对路径 `avatars/expert.png` | `plugin.json` |
| 打包时强制正斜杠、单一顶层目录、回读校验 | `scripts/build_zip.py` |
| 体检脚本模拟平台匹配算法（含大小写一致性、反斜杠、条目存在性） | `scripts/pack_check.py` |
| 头像控制为 512×512、486.9 KB、真实 PNG（< 5MB 上限） | `avatars/expert.png` |

**验证结果**：T8 通过（见下表）。
