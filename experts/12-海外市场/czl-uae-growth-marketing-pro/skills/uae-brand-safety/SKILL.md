# 文化合规与双语文案

## 何时用

- W5 Safety & script 全段。
- 用户给了一段现成文案，问"能不能发"。
- 需要产出阿语版本，或判断现有阿语是否可用。
- 投放窗口撞上宗教或国家节点。

## 扫描脚本

`bin/uae_compliance.py`（专家包根目录）

```bash
# 直接扫文本
python bin/uae_compliance.py --text "限时秒杀，100% 保证有效" --sector beauty

# 扫文件
python bin/uae_compliance.py --file copy.md --sector fintech

# 机器可读
python bin/uae_compliance.py --text "..." --format json
```

**退出码就是判断条件**：`1` = 存在 High 风险，禁止交付；`0` = 无 High，可交付（Medium 需置顶提示）。

## 严重度处理规则

| 等级 | 处理 | 交付状态 |
|------|------|---------|
| **High** | 必须改写，给替代表达，等用户确认 | 阻断，不出终稿 |
| **Medium** | 保留但置顶风险提示 + 修改建议 | 可交付，附风险 |
| **Low** | 建议优化，不阻断 | 可交付 |

## 脚本覆盖不到的，你必须人工判断

关键词只能抓显性表达。以下四类必须靠人读：

1. **语境**：同一个词在玩笑、对比、赞美中的风险完全不同。
2. **视觉**：构图、镜头、手势、着装、男女同框距离。文字干净不代表画面安全。
3. **方言**：阿语方言差异大（海湾 / 埃及 / 黎凡特），一个词在某些方言里是俚语。
4. **暗示**：隐喻、双关、竞品影射、政策影射。

## 双语文案六条硬规则

1. **阿语不是翻译，是同目标重写。** 语序、敬语层级、修辞习惯都不同。逐句直译一定读起来像机器。
2. **RTL 排版**：阿语版必须右对齐、标点镜像；数字与英文混排时注意方向隔离，否则会出现 `AED 100` 被拆开的观感。
3. **品牌名保留原拼写**，不做阿语化音译，除非客户明确要求。
4. **敬语与称呼**：面向家庭与本地客群时用正式语体；面向年轻外籍可用轻量语体，但不要在同一素材里混用。
5. **数字与折扣**：阿拉伯语用阿拉伯-印度数字（٠١٢٣）或西阿拉伯数字（0123）需与投放平台一致，同一素材内不得混用。
6. **母语终审**：交付时附一句"建议由阿语母语者终审"。这是诚实，不是推责。

## 标准交付结构

```markdown
## 合规结论
{通过 / 需复核 / 阻断}：High X · Medium Y · Low Z

## 风险清单
| 等级 | 命中 | 问题 | 替代方案 |

## 阿语版
{正文}

## 英语版
{正文}

## 视觉注意事项
{构图、着装、手势、场景的四条具体约束}

> 扫描为辅助手段，不构成法律意见。牌照、审批与内容审查的最终结论由主管机构与本地法律顾问确认。
```

## 节点相关的额外规则

| 节点 | 额外约束 |
|------|---------|
| 斋月 | 日间不做餐饮诱惑型内容；避免"白天狂欢"类表达；慈善与家庭叙事优先 |
| 开斋节 | 祝福语与促销必须分开成段，不做"宗教祝福 + 打折"绑定 |
| 宰牲节 | 涉及屠宰、动物影像需谨慎；慈善与分享是安全叙事 |
| 国庆日 | 国旗、地图、领导人形象一律走官方素材；不做创意化改编 |
| 先知诞辰 | 仅品牌问候，禁止任何促销绑定 |

## 异常处理

| 情况 | 处理 |
|------|------|
| 用户坚持保留 High 风险表达 | 记录"已提示未采纳"，交付物保留风险提示，不删不改用户决定 |
| 用户要求"帮我把这段直译成阿语" | 说明直译风险，仍可给直译版，但必须同时给一份"建议改写版" |
| 扫描全过但内容明显擦边 | 以人工判断为准，脚本通过不等于安全 |
| 涉及牌照/审批 | 直接指出需主管机构确认，不代替法律意见 |
