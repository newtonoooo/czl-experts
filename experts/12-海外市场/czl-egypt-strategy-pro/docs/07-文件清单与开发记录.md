## 二、开发过程记录

### 阶段 1：需求分析（只读）

- 逐文件阅读对标专家的目录结构、manifest、Agent 提示词、技能索引、脚本清单。
- 记录其**功能构成**：宏观、行业、选址、进入模式、风险、情景、汇率、劳动力、税务、海关、融资、文化。
- 记录其**工作方式**：按问题类型路由到不同语料文件，检索后合成结论。
- **未复制**任何文本、代码、数据文件；分析结论只用于确定"需要覆盖哪些功能"。

### 阶段 2：功能转化

把"它覆盖哪些主题"转化为"用户需要哪些决策"：

| 原功能视角 | 本产品视角 |
|---|---|
| 宏观经济分析 | G1 环境体检：给我一个该不该进的判定 |
| 行业分析 | G2 赛道筛选：给五维分和切入角度 |
| 选址对比 | G3 落点打分：给排序 + 敏感性 + 待核实项 |
| 进入模式 | G4 路径比选：先过滤硬约束，再排序，附退出成本 |
| 税务/海关/劳动力 | G5 成本栈：折算成单位成本与回本期 |
| 风险/情景 | G6 风险台账：触发信号 + 责任人 + 止损线 |

### 阶段 3：独立实现

- 提示词：按"闸门 + 判定红线 + 证据分级"重写，不沿用原有的"模式 0–7"框架。
- 卡片：12 张，按"方法 → 分领域 → 模板"重新组织，内容为自述式写作。
- 工具：8 个标准库脚本，全部为本次新写；每个工具都是 `compute()` 纯函数 + CLI，可被 selftest 断言。
- 头像：AI 生成埃及女性顾问形象 → `avatar_prep.py` 按实测白边（57px）裁掉画框 → 降采样 512×512 → 通道量化（step 4）把体积从 507 KB 压到 230 KB。
- 目录：`agents / skills / tools / examples / variants / docs`，与对标包的 `Reference_Texts / Databases / scripts` 结构不同。

### 阶段 4：测试与打包

| 步骤 | 命令 | 结果 |
|---|---|---|
| 工具回归 | `python tools/selftest.py` | 11/11 通过，退出码 0 |
| 清单校验 | `validate_expert.py .` | `✅ Expert package is valid!`（无 error，无 warning） |
| 注册 | `register_expert.py .` | 已写入 `marketplace.json` |
| 打包 | `package_expert.py . <dist>` | 42 个文件，约 311 KB |

### 阶段 5：问题诊断

针对"导入后图标变成汉字"做了宿主端代码静态检查，定位到 `ExpertAvatar` 的 `onError` 回退逻辑与 `resolveAvatarUrl` 的 5 MB / 路径越界 / 文件缺失三类失败分支，并据此内置了内联头像开关。详见 `docs/08`。
