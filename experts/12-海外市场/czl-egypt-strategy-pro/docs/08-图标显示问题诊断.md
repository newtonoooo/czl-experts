# 08 · 专家图标变成文字：原因诊断与修复

> 现象：专家导入到新 WorkBuddy 后，在专家列表/输入框的专家标签里，小图标不见了，位置显示成一个汉字（专家名首字）。

## 一、结论先说

**这不是"头像没打包进去"，而是头像 URL 解析成功、但图片加载失败，界面按设计回退成了"专家名首字"。**

回退逻辑是产品既定行为，不是 bug：

- 组件在有 `avatarUrl` 时渲染 `<img>`，一旦 `onError` 触发，就把状态置为失败，转而渲染 fallback seed（名字首字）。
- 所以"看到字"= `avatarUrl` 存在但请求失败；"看到空白"才是 `avatarUrl` 为空。

## 二、代码层面的证据

以下结论来自对 WorkBuddy 桌面端安装包的静态检查（`resources/app.asar` 与 `resources/app.asar.unpacked/renderer/assets/*.js`），不是猜测。

### 1. 渲染层：加载失败即回退首字

`ExpertAvatar` 组件的结构（简化）：

```js
function ExpertAvatar({ expert, prefixCls }) {
  const seed = resolveAvatarFallbackSeed(expert);
  const [failed, setFailed] = useState(false);
  useEffect(() => { setFailed(false); }, [expert.avatarUrl]);
  if (expert.avatarUrl && !failed) {
    return <span><img src={expert.avatarUrl} onError={() => setFailed(true)} /></span>;
  }
  return <FallbackSeed value={seed} />;   // 名字首字
}
```

### 2. 主进程：解析失败会返回空字符串

`ExpertPluginService.resolveAvatarUrl(avatar, expertRootDir)` 的关键分支：

| 条件 | 结果 |
|---|---|
| `avatar` 为空 | 返回 `""` |
| 以 `http(s):` 或 `data:` 开头 | 原样返回 |
| 解析后路径跳出插件根目录 | 返回 `""` |
| 文件不存在 | 返回 `""` |
| **文件大于 5,242,880 字节（5 MB）** | 返回 `""`，并打日志 `[ExpertPluginService] resolveAvatarUrl: avatar file is too large` |
| 其他 | 转成 `local-file://` URL |

注意阈值是 **5 MB**，不是文档里建议的 500 KB。500 KB 是市场展示的建议值，不是硬限制。

### 3. 渲染层：相对路径会被当成"专家根目录下的路径"重新拼

`resolveExpertAvatarUrl` 的逻辑：

```js
if (/^(https?|file|data|blob|local-file):/i.test(v)) return v;   // 直接放行
return buildExpertUrl(v.startsWith('/') ? v : '/' + v);           // 否则按路径拼
```

也就是说：`avatar: "avatars/expert.png"` 这种相对路径，最终要靠自定义协议 + 专家根目录映射才能取到文件。**只要这条映射在当前渲染上下文里不成立，图片就会 404，然后回退成首字。**

### 4. CSP：不同渲染上下文放行的图片协议不一样

安装包里存在多套 CSP，其中至少一套的图片策略是：

```
img-src 'self' blob: data: https:
```

**不含 `local-file:`**。另一套（主窗口）才含 `local-file:`。所以同一张头像，在不同面板里可能出现"这里能显示、那里显示成字"。

### 5. 市场通道：头像字段来源不同

从市场条目映射时用的是服务端字段：

```js
avatar: e.icon || ''
```

即：**走市场通道的专家，头像来自服务端 `icon` 字段，而不是 plugin.json 的 `avatar`**。如果导入路径把它当成了市场条目、而 `icon` 为空，头像就是空 → 直接回退首字。

## 三、对目标专家包（egypt-strategic-advisory）的具体判断

检查结果：

| 检查项 | 实测 | 是否触发回退 |
|---|---|---|
| 头像文件存在 | `avatars/egypt-strategic-advisory.png` 存在 | 否 |
| 格式 | PNG，magic 正确 | 否 |
| 尺寸 | 512 × 512 | 否 |
| 体积 | 316,591 字节（0.3 MB） | 否（阈值 5 MB） |
| manifest 路径 | `.codebuddy-plugin/plugin.json`，`avatar` 为相对路径 | — |
| 路径字符集 | 含中文用户名 `C:\Users\丛自龙\...` | **可疑** |
| 通道 | 位于 `marketplaces/experts/plugins/`（市场下载目录） | **可疑** |

**判断**：文件本身完全合规，问题出在"相对路径 → 实际 URL"这一步。两个最可能的触发点：

1. **路径含非 ASCII 字符**：`C:\Users\丛自龙\...`。`local-file://` URL 的编码方式在不同构造点不一致（一处逐段 `encodeURIComponent`，另一处直接拼字符串），含中文的路径在未编码分支上容易被渲染层拒绝。
2. **走了市场通道**：此时头像取自服务端 `icon` 字段，本地 manifest 的 `avatar` 不参与，`icon` 为空即回退。

> 说明：这两条是对代码路径的推断（E4），不是运行时复现结论。验证方法见第五节。

## 四、修复方案（按可靠性排序）

### 方案 A：头像改成内联 data URI（最稳，推荐先做）

`data:image/...` 在解析阶段就被原样返回，不参与任何路径拼接，也不依赖文件系统权限；所有 CSP 的 `img-src` 都放行 `data:`。

本产品已内置开关：

```bash
python tools/apply_inline_avatar.py --apply            # 切到内联（默认 256px）
python tools/apply_inline_avatar.py --apply --size 160 # 更省体积：约 30KB 文本
python tools/apply_inline_avatar.py --status           # 查看当前状态
python tools/apply_inline_avatar.py --revert           # 上架官方市场前切回相对路径
```

实测体积：256px → data URI 约 71.8 KB；160px → 约 29.5 KB（`plugin.json` 从 3.4 KB 增至约 34 KB）。图标在标签里只有 20–32 px，160px 足够。

**注意**：上架官方市场时应切回相对路径（审核要求 `avatar` 是路径），内联值只用于"本地导入后先让图标显示出来"。

### 方案 B：把路径与文件名都做成纯 ASCII

- 头像放插件根目录下的 `avatars/`，文件名只用小写字母、数字、连字符。
- 避免把专家包放在含中文的目录层级里（这一点在 Windows 中文用户名下无法完全避免，所以方案 A 更可靠）。

### 方案 C：确认走的是哪条通道

- 如果是"从市场下载"的专家 → 头像由服务端 `icon` 决定，本地改 `avatar` 无效，需要在发布侧补 `icon`。
- 如果是"本地导入 zip"的专家 → 头像由本地 manifest 的 `avatar` 决定，按方案 A 处理。

### 方案 D：看日志定位

- 主进程日志里搜 `resolveAvatarUrl`，若有 `avatar file is too large` → 体积问题；若无任何输出但界面仍是首字 → 属于加载失败，按方案 A。
- 渲染层开发者工具 Console 里会有一条图片请求失败（`net::ERR_FILE_NOT_FOUND` / `ERR_UNKNOWN_URL_SCHEME` / CSP 拒绝），这条错误直接指明是"路径没找到"还是"协议被拦"。

## 五、怎么验证修好了

1. 重新选中该专家，看标签里是否出现图案而不是汉字。
2. 若仍是汉字，打开开发者工具看 `<img>` 的 `src` 值：
   - `src` 为空 → 解析阶段就失败了（查体积/路径越界/文件缺失）。
   - `src` 是 `local-file://...` → 文件协议被拦或路径错。
   - `src` 是 `data:image/...` 却仍失败 → 图片数据本身损坏。
3. 换一个纯英文用户名的账户再试一次，可快速区分"中文路径"与"通道"两类原因。

## 六、对目标专家包的处理建议

- 本机调试：可以对 `marketplaces/experts/plugins/egypt-strategic-advisory` 的 `plugin.json` 手动把 `avatar` 换成 data URI，仅用于自己看效果。
- **不要**把这个改过的包再打包分发——它仍然是他人作品，改字段不改变权属。
- 若需要对外分发，请使用本产品（`czl-egypt-strategy-pro`），它的头像、提示词、卡片、脚本均为独立实现，且已内置上述开关。
