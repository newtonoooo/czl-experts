## 一、这个产品解决什么问题

中国企业去埃及，卡点几乎从不在"不了解埃及"，而在**决策链条断了**：

- 调研报告写了一百页，没人敢签字；
- 选址凭感觉，理由是"朋友在那个园区"；
- 报价用的是 FOB，落地发现关税、清关、滞港、在途资金全没算；
- 合资协议签完才发现没有退出条款；
- 汇率一变，原本 30% 的毛利变成负数，但合同里没有调价机制。

这些问题的共同点是：**缺一个把选择变成参数、把参数变成数字、把数字变成判定的人**。

本产品把自己定位成这个角色：不是百科，是**七道闸门的作战台**。每道闸门必须给出 PASS / CONDITIONAL / STOP，并留下一份可以拿去开会、交给财务和法务的文件。

## 二、目标用户与使用场景

| 用户 | 典型场景 | 他真正想要的 |
|---|---|---|
| 制造业出海负责人 | 董事会问"埃及能不能去"，两周内要一版判断 | 一个有红线的结论，不是一个国家简介 |
| 外贸公司老板 | 想从纯出口转成本地组装，怕踩坑 | 进口 vs 本地组装的成本差、以及最短验证路径 |
| 工程/基建投资方 | 要投一个园区或产线，需要可研的骨架 | 成本模型、许可顺序、风险台账 |
| 产业园区招商方 | 要向国内企业解释"为什么来我们这个园区" | 可对比的选址打分与差异化理由 |
| 已在埃及的中资企业 | 项目卡在审批或亏损，需要复盘 | 回退到具体闸门重做，而不是空泛建议 |

## 三、必要的输入

G0 案头立档的六项（缺 3 项以上会拦停）：

1. 做什么（产品/服务/工程）
2. 卖给谁（本地 / 出口 / 两者，比例）
3. 体量（年产能或年营业额）
4. 资本开支区间
5. 时间窗（多久要出货或开工）
6. 风险偏好（能否承受首年亏损）

进阶输入（有则更准）：币种结构、进口件占比、用工规模与岗位结构、电力负荷、目标客户的结算币种、现有订单或意向书。

## 五、通用处理步骤

1. **定框**：六项参数 + 目的反推（出口基地 / 本地市场 / 原产地规避）。
2. **体检**：宏观与汇率敞口，先判断"这个时点该不该进"。
3. **筛赛道**：五维打分，判断是顺风还是逆风。
4. **选落点**：加权打分 + 权重敏感性，防止"排名靠权重撑着"。
5. **定路径**：硬约束过滤在前，四维排序在后。
6. **算账**：到岸成本 + 全口径人工 + 三档情景，算出回本期与最致命项。
7. **排期与风险**：许可顺序、12 个月里程碑、风险台账与止损线。

## 七、质量、速度、稳定性要求

| 维度 | 要求 | 落地方式 |
|---|---|---|
| 质量 | 每个数字带口径与时点；每个判断带翻转条件 | 证据分级 E1–E4 + 数据台账卡 |
| 质量 | 不许编数据 | 取不到就写"待核实 + 复核渠道" |
| 速度 | 简单问题一轮答完，不启动全流程 | 七道闸门按需触发，不强制全跑 |
| 稳定性 | 工具可复算、可回归 | `selftest.py` 11 条断言，退出码即结论 |
| 一致性 | 同一输入复算结果一致 | 纯函数 `compute()`，无随机、无网络 |

## 八、与"通用型埃及问答顾问"的差异

| 维度 | 通用问答型 | 本产品 |
|---|---|---|
| 交互形态 | 问什么答什么 | 七道闸门推进，带判定与产物 |
| 输出 | 分析文字 | 判定 + 文件 + 可复算参数 |
| 数字 | 引用结论 | 用脚本算出来，参数可改 |
| 风险 | 列举风险类别 | 触发信号 + 责任人 + 止损线 |
| 可追责性 | 低 | 每步有 PASS/CONDITIONAL/STOP，可回溯 |

## 九、不做什么（边界）

- 不出具法律意见、税务裁定、审计结论。
- 不预测汇率点位、不承诺审批结果、不承诺补贴额度。
- 不替代实地调研；所有结论都要标注"需现场核实"的项。
- 不做埃及政治、宗教、军方角色的评价性判断。
