# 使用指南

本仓库有 61 个专家包和 176 个技能。它们的关系是：**专家 = 一个角色 + 一组技能 + 一套提示词**，技能可以脱离专家单独用。

先决定你要哪一层：

| 你的需求 | 用哪一层 | 怎么做 |
|---|---|---|
| 想要一个能持续对话、按固定流程办事的角色 | **专家包** | [装专家](#一装一个专家包) |
| 只想要某个具体能力，自己组合 | **技能** | [装技能](#二只装一个技能) |
| 已有专家，想补一个它没有的能力 | **技能 + 现有专家** | [组合使用](#三组合使用) |
| 想改提示词、改流程、二次开发 | **源码** | [开发说明](02-开发说明.md) |

## 一、装一个专家包

### 1. 挑一个

打开 [专家目录](../CATALOG.md)，按分类或直接看「全表速览」。每个条目都写了它做什么、可以怎么问它、挂了哪些技能。

### 2. 下载

两种方式任选：

```bash
# 方式 A：直接下 zip（推荐，不用 clone）
# 在 CATALOG.md 里点「下载 zip」，或用命令行
curl -L -o expert.zip \
  https://raw.githubusercontent.com/newtonoooo/czl-experts/main/dist/experts/01-产品设计/czl-product-decision-audit.zip

# 方式 B：clone 整个仓库
git clone https://github.com/newtonoooo/czl-experts.git
```

### 3. 放进专家目录

WorkBuddy 的专家目录由环境变量 `WORKBUDDY_CONFIG_DIR` 决定，默认是 `~/.workbuddy-ai`。完整路径是：

```
$WORKBUDDY_CONFIG_DIR/plugins/marketplaces/my-experts/plugins/<包标识>/
```

```bash
# 解开 zip（zip 内已带 <包标识>/ 这一层，直接解到 plugins 下即可）
unzip expert.zip -d "$WORKBUDDY_CONFIG_DIR/plugins/marketplaces/my-experts/plugins/"
```

用 clone 方式的话，直接复制源码目录：

```bash
cp -r czl-experts/experts/01-产品设计/czl-product-decision-audit \
      "$WORKBUDDY_CONFIG_DIR/plugins/marketplaces/my-experts/plugins/"
```

### 4. 注册

专家必须在 `marketplace.json` 里登记才会出现在专家中心。如果你装了 WorkBuddy 的专家管理能力，执行：

```bash
python scripts/register_expert.py \
  "$WORKBUDDY_CONFIG_DIR/plugins/marketplaces/my-experts/plugins/czl-product-decision-audit"
```

或者手工在 `$WORKBUDDY_CONFIG_DIR/plugins/marketplaces/my-experts/.codebuddy-plugin/marketplace.json` 的 `plugins` 数组里加一条：

```json
{
  "name": "czl-product-decision-audit",
  "source": "./plugins/czl-product-decision-audit",
  "description": "从 plugin.json 里复制 description 字段"
}
```

### 5. 验证

重启 WorkBuddy，在左侧「专家」里应该能看到它。看不到时按顺序查：

1. 目录名是否等于 `plugin.json` 的 `name` 字段
2. `.codebuddy-plugin/plugin.json` 是否随 zip 一起解出来了（这是隐藏目录，有些解压工具会漏）
3. `marketplace.json` 里的 `source` 是否指向 `./plugins/<包标识>`
4. 重启客户端（专家列表在启动时加载）

## 二、只装一个技能

技能目录是 `~/.workbuddy-ai/skills/`（或 `$WORKBUDDY_CONFIG_DIR/skills/`）。

```bash
# 从仓库里挑一个技能
unzip dist/skills/01-产品设计/evidence-ledger.zip -d /tmp/skill-unpack
cp -r /tmp/skill-unpack/evidence-ledger ~/.workbuddy-ai/skills/
```

或者直接用源码目录：

```bash
cp -r czl-experts/skills/evidence-ledger ~/.workbuddy-ai/skills/
```

技能的触发完全靠 `SKILL.md` 里 frontmatter 的 `description`。它写得越具体（做什么、什么时候用），被正确调用概率越高；写得含糊就会该触发时不触发、不该触发时乱触发。

## 三、组合使用

技能和专家不是绑死的。常见做法：

- **给通用专家补专项能力**：专家已经在跑，把它缺的那一步用技能补上。例如产品决策类的活儿，主体用「定盘」，指标口径那一段单独挂 `metric-integrity`。
- **同一套技能换角色**：`czl-product-strategy-solo` 和 `czl-product-strategy-warroom` 用的是同一批技能，差别只在角色数量和调度方式。想省事用 solo，想模拟多人评审用 warroom。
- **注意同名技能会互相覆盖**：如果两个包里有同名技能（例如 `evidence-ledger` 在 4 个包里都出现过），装到同一个技能目录下只会保留一份。取舍依据见 [重名技能取舍说明](../skills-conflicts.md)。

## 四、常见问题

**Q：装完专家，对话里它没按预期流程走。**
先看 `agents/<包标识>.md`，这是它的系统提示词。多数偏差是提示词里对触发条件的描述太宽或太窄。

**Q：技能装进去了，但从来不触发。**
`description` 里没有写清「什么时候用」。对照 `skills/` 下任意一个成熟技能（如 `adversarial-review`），它的 description 后半段专门有一句 `Use before any approval meeting, or when a decision already feels obvious.`，这类句子是触发率的关键。

**Q：专家团（Team 型）和普通专家有什么区别？**
专家团有多个角色，主理人负责调度，成员各自输出专业结论，再汇总。它更适合需要多视角交叉验证的任务，代价是慢、token 消耗高。单角色专家是同一套流程压在一个角色里。

**Q：能不能商用？**
可以。本仓库以 MIT 开源，见 [LICENSE](../LICENSE)。

**Q：包内自带的 LICENSE 写着「All rights reserved」，和 MIT 冲突吗？**
那些是历史文件。仓库级的 MIT 优先。
